## 来源

ADR-0019 §5（Q9=A）。现状核查：`ErrorBoundary|componentDidCatch` 全仓 0 命中，`window.onerror` / `unhandledrejection` 0 命中——一个渲染错误即白屏，且无任何记录。

## 范围与落点

- **三层 boundary**：App 顶层 + 每页面 route-level + canvas 渲染区单独 boundary（错误态 + 「重试」按钮，不白屏）。canvas 是渲染密度 / 大数据谱面的高危区（ADR-0017 的不变量就崩在画布上），值得单独兜。
- **全局兜底**：`window.onerror` / `unhandledrejection` 接入 logger（错误日志轨）。
- **联动**：boundary 触发时把 ring buffer 轨迹刷盘（票 02 的 flush 入口之一）；错误态界面提供「导出诊断包」入口（票 04）。
- 用户可见文案口径不变：原始技术错误不拼进界面（沿用 `useVideoExport` 既有政策）。

## 锁测

- 组件测试：抛错的子组件被 boundary 接住 → 显示错误态而非白屏；点「重试」后重置。canvas boundary 同例。
- jsdom 可派发 `error` / `unhandledrejection` 事件 → 断言 logger 各收到一条 error 记录。
- 手工验收：dev 态临时注入 throw，验证三层各自的兜底表现与日志落盘。
