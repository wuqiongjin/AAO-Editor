## Findings

### #1 脱敏键名表漏 `password`，渲染 / 主进程两份不一致

- 症状：`src/diagnostics/sanitizeSettings.ts` 的 `SENSITIVE_KEY` 缺 `password`；主进程 `electron/diagnosticsExport.cjs` 那份有。票 04 口径与 ADR-0019 §4 要求凭据类字段一律剔除，渲染侧第一道防线漏底。
- 根因：两边各写一份正则（渲染进程不能 import electron/），无锁测钉一致。
- 修法：补齐 `password`；新增静态锁测断言两份正则逐字一致；`chart` 载荷进包前也过同一把筛（渲染 + 主进程两道）；函数改名 `sanitizeForDiagnostics`、文件改名 `sanitizeDiagnosticsPayload.ts`（不再只管 settings）。
- Status: resolved

### #2 `trail.flush()` 即发即忘，导出诊断包时主进程可能读到不完整轨迹

- 症状：`exportDiagnostics` 调 `trail.flush()` 后立刻 `bridge.export()`；`logger.trail.append` 是 `void` 掉的 IPC，最多 500 条不等回包，主进程随即读 logs 目录。正确性依赖未成文的 IPC 保序。
- 根因：flush 无等待语义；logger 的桥调用被 void。
- 修法：`flush()` 返回 Promise——收集每条 persist 的 IPC Promise，全部落盘才 resolve；单条失败不拖垮整批、不外溢 rejection；并发 flush 挂同一条尾巴。`exportDiagnostics` 改为 `await trail.flush()` 后再导出；`logger.trail.append` / `warn` 回传桥调用结果，谱面读取失败的 warn 也 await。CrashBoundary 同步上下文 `void trail.flush()`（尽力落盘）。
- Status: resolved

### #3 `appLog` 每条写入都重扫 logs 目录

- 症状：一次 flush 500 条轨迹 = 500 次 `readdirSync` + 逐文件 `statSync`。
- 根因：`appendLine` 无状态，轮转前必现扫。
- 修法：扫描结果按 UTC 天缓存，同一天的连续写入只扫一次；文件大小随 append / 删除增量更新，5MB / 7 天 / 50MB 判定仍准确。边界：unlink 失败不滑出缓存（50MB 预算不少算）、append 失败作废缓存等下次重扫（判定不少算）；单实例口径写进注释。
- Status: resolved

### #4 诊断包 zip 非原子写，崩溃留半截

- 症状：`fs.promises.writeFile` 直接写用户选定路径。
- 根因：仓里 `writeFileAtomic` 已有同形实现（main / projectStore / communitySession / appState 各一份），诊断包又抄了第五份，且失败不清理临时文件。
- 修法：抽 `electron/atomicWrite.cjs`（异步 + 同步两个口径，tmp + rename，失败清理 `.tmp-*`），五处全部迁移；`assetCache.cjs` 的三处内联原子写语义不同（吞错返回 false/null），本票不动。
- Status: resolved

### #5 `chart` 载荷原样进包

- 症状：主进程只对 `settings` 过脱敏，`body.chart` 原样写 `chart/project.json`。
- 修法：chart 与 settings 过同一把键名筛（见 #1），渲染侧同样先脱敏再过桥。
- Status: resolved

### #6 `installGlobalErrorHandlers` 重复 install 丢 logger；旧 dispose 污染在任世代

- 症状：二次 install 直接返回旧 dispose——新 logger 被静默丢弃；持有旧 dispose 的调用方事后调用会把模块级 dispose 置空，在任世代失去卸载入口，监听泄漏。
- 修法：install 先拆旧再挂新（不叠监听）；dispose 加 `removed` 标志做到幂等——重复调用不二次摘监听，换代后的旧世代调用也不动模块状态。
- Status: resolved

### #7 文件命名与职责不符

- 症状：`sanitizeSettings.ts` 现在也脱敏 chart，名字撒谎。
- 修法：改名 `sanitizeDiagnosticsPayload.ts`（含测试文件），引用同步更新。
- Status: resolved

### #8 修复本身缺锁测

- 症状：第一轮修复（原子写、扫描缓存、flush 保序）没有测试看守，复审确认坏掉也发现不了。
- 修法：补 `tests/platform/electron/AtomicWrite.test.ts`（成功 / 覆盖 / rename 失败清 tmp / 目录不存在）；`AppLog.test.ts` 补同日连续写入体积累积（跨 5MB 才开 -2）；`exportDiagnostics.test.ts`（jsdom 假桥）锁「flush 落盘后才导出」「warn 先于导出」；`trail.test.ts` 补 flush 异步保序 + 并发链式 + 失败吞噬；`logger.test.ts` 补桥 Promise 透传；`globalErrorHandlers.test.ts` 补换 logger / 旧 dispose 不污染。
- Status: resolved
