## 来源

ADR-0019（2026-10-13 用户拍板：纯本地可观测性）。发布前评估确认：打包态用户看不见 `console.*`、无任何落盘——用户出问题无法定位。本票建地基，其余票挂在它上面。

## 范围与落点（2026-10-19 收口）

Bestdori 已合入当前线；IPC 约定已成型。本票只建机制与 API，不迁旧 `console.*`（归票 05）、不埋轨迹事件（归票 02）。

- **渲染进程 logger**（`src/` 新模块，建议 `src/diagnostics/logger.ts`）：`error / warn / info(module, message, extra?)`。行格式 = ISO 时间戳 + 级别 + 模块前缀 + 消息。模块前缀沿用现有命名（`[chart-project]`、`[preview]`、`[i18n]` 等）；社区失败用 `[community]`。
- **主进程落盘 sink**：新文件 `electron/appLog.cjs`，用现有 `registerXxxIpc(ipcMain, …)` 模式注册；`electron/main.cjs` 里调用注册；`electron/preload.js` 白名单暴露。通道名建议 `log:write`（实现期可跟现有冒号命名对齐）。渲染进程无 fs，日志经 IPC 汇聚主进程落盘。
- **双轨**（`userData/logs/`，跟数据根走、不进谱面工程）：
  - `errors-YYYYMMDD.log` 纯文本（人读，用户可直接贴 Issue）——本票 logger 的 error/warn/info 写这条。
  - `trail-YYYYMMDD.jsonl` 结构化——本票只建文件 / 轮转 / `trail.append` API；真正埋点归票 02。
- **轮转**：按天切文件；单文件 5MB 封顶；保留 7 天 / 总量 50MB。策略做成纯函数（输入：当前文件状态 + 新条目 → 写哪个 / 删哪些），便于单测。
- 主进程自己的失败（`projectStore` 解析、网关、更新）也应能直接调同一套 sink，不要只收渲染进程 IPC。

## 锁测

- 单测：行格式（时间戳 / 级别 / 模块前缀）；轮转策略纯函数——按天边界、5MB 封顶、7 天 / 50MB 保留的删旧逻辑，各至少一条。
- 静态源码断言：`electron/main.cjs` 注册 log handler 且 preload 白名单含该通道；`src/` 无直接 fs 访问（照 `tests/static/` 惯例）。IPC 形态照 `tests/platform/electron/CommunityNetWiring.test.ts`：假 ipcMain 跑真 handler。
- 手工验收：dev 态与打包态各跑一次，确认 `userData/logs/` 双文件能生成、内容格式正确；跨天与超限轮转符合预期（可临时调小阈值验证）。

### 2026-10-19 实现口径（grill 全同意推荐）

- `trail.append` 立刻写 jsonl；票 02 的 ring 是调用方。
- 50MB 是 `userData/logs/` 整目录（含非日志文件计入，但不删它们）。
- 超 5MB 开同日 `-2`；空文件 + 超大条目仍写入该空文件。
- 先删满 7 个 UTC 日（`age >= 7`），再按最旧删到 ≤50MB；不删即将写入的那份。
- extra 进纯文本行；Error 只 `message`/`stack`。
- logger 双写 console + IPC；无桥不抛。
- 文件名与行时间戳都用 UTC；切文件用墙钟，行内 `ts` 只进文本。
- 通道：`log:write` / `log:trail`；preload `electronAPI.log`。
