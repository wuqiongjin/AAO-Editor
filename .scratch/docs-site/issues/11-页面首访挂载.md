# 11 · 应用页面改为首访挂载

Type: chore
Status: open

## 来源

票 10 收口时（2026-10-25）顺着根因多问了一句：票 10 只掐掉了最贵的那一个症状（素材页缩略图），
真正让首屏白付流量的是 `AppShell` 的「7 个页面启动即全部 mount」——保活挂载把「保状态」和
「未访问也挂」混成了一件事。

## 症状

`PageRegistry` 里 7 个页面全是 `lazy()`，但 `PageSlot` 无条件渲染 ⇒ 7 个 chunk 首屏全部取回，
其中 `AssetsPage` chunk 连带整份 `noteSkinRegistry.gen.ts`（七包全套精灵矩形，约 4600 行）。
用户只是打开工程列表，却把工作台 / 预览 / 素材 / 设置 / 快捷键的代码都下了一遍。

## 修法

`PageSlot` 加首访 latch：`active` 首次为真后永久为真，未访问过的页面**不渲染**（连带不取 chunk）。
保活语义不变——一旦访问过就始终挂着，切走切回仍然零重挂。

## 风险 / 待查

- 首访切页会有一帧 `Suspense fallback={null}`（目前所有页面启动就已就绪，感知不到）。
- 需逐个确认没有页面依赖「未访问也 mount」做后台工作（`PreviewPage` 的后台上传 /
  `WorkspacePage` 的快捷键注册等）。
- 与 ADR-0007 / CONTEXT「5 页注册 + 保活挂载」的措辞要对齐（保活 = 访问过的页面不卸载）。

## 锁测

`tests/dom/` 渲染 `AppShell`（或直接 `PageSlot`）：未激活页不出现在 DOM、chunk 不取；
首次激活后渲染，切走再切回节点身份不变（不重挂）。一次性 Chromium 复测首屏 chunk 数与字节。
