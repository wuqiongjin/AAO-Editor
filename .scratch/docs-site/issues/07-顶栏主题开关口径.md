# 07 · 顶栏主题开关口径

Type: grilling
Status: resolved（2026-10-24 用户拍板 B；实现落地，待用户目检顶栏原生开关）

## 来源

评审 i18n / 顶栏开关批次（2026-10-24）时发现：map 2026-10-23 用户拍板「默认深色 +
支持亮色，落地页顶栏与文档导航右侧都带开关，两边共用 `vitepress-theme-appearance`、
切换后全站一致」——即**两个开关并存且互相同步**是本轮实现的验收点（票 01  Comments
亦按「两个开关互相同步」验收过）。

## 症状

`site-chrome.css` 用 `.VPNavBarAppearance.appearance { display: none !important }`
直接藏掉了 VitePress 内置的文档页外观开关，顶栏只剩自建圆形按钮 + 语言胶囊。
「两个开关互相同步」的验收失去对象。

## 根因

代码注释给的理由：「不用 VitePress 内置滑条式外观开关（与落地页圆形按钮不一致，
强行缩放会变形）」——这是**实现口径，未经用户拍板**，且与 map 定案冲突。

## 定案（用户 2026-10-24 拍板 B）

- **A. 单一自建开关**（未选）：维持隐藏原生开关，放弃「两个开关」表述。
- **B. 两个开关并存（已选）**：恢复 VitePress 原生开关可见，只把样式对齐站点
  chrome；状态经 `vitepress-theme-appearance` + StorageEvent 同步
  （`useSiteChrome.ts` 的合成 StorageEvent 派发即为此而存在）。

拍板理由：B 不需要改 2026-10-23 既有定案（原文就含「文档页原生开关」），A 才需要；
且 `display:none` 藏框架控件在 VitePress 升级时会静默失效（类名一改就冒出两个开关），
改样式失败的最坏结果只是「长得不太一样」。

## 实现落点（2026-10-24 已落地）

- `theme/style.css`：删 `.VPNavBarAppearance` 的 `display:none`；把 40x22 滑条
  重置为 30px 圆形（`--aao-chrome-*` 同款边框 / 面板底，把手抹平为图标层并居中）；
  补画菜单链接与工具区之间的竖线（VitePress 自带的 `.menu + .appearance` 分隔线
  因 translations 被隐藏而失效）；≥768px 一律内联原生开关，并藏掉 `⋯` 浮动菜单
  （`VPNavBarExtra`，768–1280 间会塞重复的翻译下拉）。
- `theme/Layout.vue`：文档导航槽去掉自建 `NavThemeToggle` 与分隔线，只留语言胶囊；
  原生开关在 DOM 上排在语言胶囊之前。`NavThemeToggle.vue` 组件本身不删——落地页在用。
- `useSiteChrome.ts` 不动：StorageEvent 同步逻辑保留，B 之后重新有了对面。

## 锁测

手工验收（仓内无 Playwright 基建，照 issue 01 的目检口径）：中 / 英 × 深 / 浅
四象限，切换后 `<html>.dark` 类、`localStorage['vitepress-theme-appearance']`、
原生开关与落地页圆形按钮的高亮态一致；刷新后保持；控制台无报错。
另核三档宽度顶栏不溢出、不出现两个开关：1440 / 1024（内联原生开关）/
820（曾收进浮动菜单的档位，现已内联）/ 375（走汉堡屏，屏内自带开关）。
