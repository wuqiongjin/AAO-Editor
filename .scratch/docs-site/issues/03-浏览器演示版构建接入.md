## 来源

map 2026-10-23：`/demo/` 复用现有 `vite build`、不做人为功能限制。运行时的降级分支已由代码提供，本票只解决「把产物塞进静态站」。

## 已核实（不需改造）

- `ChartProject.ts` 的 `autoDetectBackend()` 无 `window.electronAPI` 即走 IndexedDB；设置走 localStorage。
- 导出三条都有 `a[download]` fallback（`exportChartCode.ts`、`preview/static/saveBinary.ts`）。
- 视频导出 WebCodecs + muxer，**不需要 COOP/COEP**，Pages 静态托管即可；缺 WebCodecs 时 `probeContainer` 报不可用不崩。
- 无 react-router、单入口，`base: './'` 相对路径 ⇒ `/demo/` 子路径直接可用，不需要 SPA fallback。

## 做什么

1. 构建产物落 `site-dist/demo/`（票 02 的合并步骤）。
2. 验证素材路径：`SIM_ASSET_BASE` 用 `import.meta.env.BASE_URL` 拼接，在 `/demo/` 下必须解析到 `/AAO-Editor/demo/assets/sim/...`（不是站点根）。这是本票唯一有回归风险的改动面。
3. 首屏体积实测：记录 `dist` 首包大小、最大单文件、以及 sim/skins 素材是否被误预加载（素材应保持运行时按需 fetch）。
4. 素材取件失败必须让构建红（`ci-assets.sh` 已 `set -euo pipefail`）；**不允许**降级成「空态站」：缺 `*.gen.ts` 时 `tsc -b` 会直接失败，缺二进制则是画布空白，后者需要一条构建期断言或人工验收兜住。

## 锁测

- 构建期：`npm run assets:check`（票 02 可选加在 build job 末尾）。
- 手工验收：`/demo/` 打开后画布有音符皮肤、键音能响、仿真场能出图、能导出谱面图与视频（Chromium）。

**实现后的落点**（逐条展开见下方 Comments「2026-10-25 实现」）：

- 常驻有锁：`tests/static/DocsSiteDemoBuild.test.ts`（新增 5 条，四条做过变异验证）看守 workflow 的两条构建期断言、`base: './'`、单入口无 `react-router`、落地页 CTA 落点；`tests/static/DocsSiteDeploy.test.ts` 那条负锁按用户拍板拆开（`assets:check` 不再锁在「不许跑」里）。

#### 第二轮：用户验收反馈（2026-10-25）

**① 点「在线试用」是 VitePress 的 404，刷新才正常；回退键失效（真 bug，是我引入的）**

- 根因：VitePress 的客户端路由会把**同源同前缀**的站内 `<a>` 一律拦成 SPA 跳转。它那只点监听挂在 `window` 的 **capture 阶段**（`dist/client/app/router.js` 末尾 `{ capture: true }`），比元素上的 `@click` 更早执行——所以「`@click` + `preventDefault()`」抢不过它（我第一版就是这么修的，实测无效，已回退）。
- `/demo/` 不是 VitePress 的一页 → 找不到路由 → 渲染它自己的 404，而且**一个文档请求都不发**（Playwright 抓到的 document 请求数是 0，这是判定这条路的铁证）；历史里那条是 pushState 出来的假条目，所以回退键跟着失效。这在真 Pages 上同样会犯。
- 修法：给它自己的 bail 条件之一——**`target="_self"`**（同标签真导航，保住「internal navigation」语义，不新开标签）。另一条可行路是 `target="_blank"`，但你在 /demo/ 上用了回退键——说明期望的是同标签跳转，所以没采纳。
- 加了回归锁 `DocsSiteDemoBuild.test.ts`「『在线试用』必须绕开 VitePress 客户端路由」，并注明别再试 `@click` 那套。
- 复验：点击 → 发出 1 次文档请求 → title 变成 app 的、root 挂载、不是 404；回退 → 回到落地页、CTA 两个按钮都在。

**② CTA 位置返工**（见上，「在线试用」初版是 `[主按钮][平台徽标][次按钮]` 同排同距，层级散了）

**③ 顺手修：1024 档主标题断字**

票 01 说过「主标题在各档都单行」，但 1024 档实测会断成「桌面级谱面编 / 辑器」——`--fs-h1: clamp(32px,5vw,60px)` 在 1024 是 51.2px，8 个汉字要 410px，而 hero 文案列只有 392px。改成 **`4.6vw`**（1024 档 47.1px，留 15px 余量）；≥1280 档本来就被 60px 上限夹住，**1920 / 1440 观感分毫未变**。实测 1920 / 1440 / 1280 / 1024 / 900 / 768 / 414 / 375 / 320 九档全部单行，无横向溢出。

**④ `docs-dev.sh` 加 `--demo` 模式（先走了弯路）**

用户提问「`docs-dev.sh` 部署的网址能访问 /demo/ 吗」——**不能**：默认模式起的是纯 VitePress 开发服务器，只服务 `docs-site/` 自己那一套页面；demo 是另一个静态应用，不在它的根目录里，那个路径会被 VitePress 的 SPA 兜底接住（HTTP 200，但客户端渲染出的是它自己的 404 页）。

我第一反应是**另起一个 `scripts/site-preview.sh`**，被用户否了：「demo 既然融进 docs 了，为什么还要单独一个脚本」。说得对——一个站就该一个入口。最终把能力折进 **`bash scripts/docs-dev.sh --demo`**（独立脚本已删）：

- 该模式按 `deploy-site.yml` 的 build job **逐句相同的命令**构建两边 + 合并成单一 `site-dist/`，再在一个临时目录里按项目站路径（`DOCS_BASE`，该模式下默认 `/AAO-Editor/`）建一条指向 `site-dist/` 的软链当服务根——页面里全是「base + 绝对路径」的链接，没有这一层目录它们落不到文件上——然后静态起服务并打印 CNB 对外 URL。`--skip-build` 复用已有 `site-dist/` 只重启服务。
- **默认模式不开它是有意的**（写进脚本头注释）：写文档不该被 app 那一整套工具链（依赖 + 素材取件 + 7MB 构建）绑架；而且 VitePress dev 有热更新，静态预览没有。
- 端口解析与占用清理仍复用 `scripts/lib/dev-server.sh`。

踩到两个坑都已绕开：清理大目录用 `find -delete` 而不是 `rm -rf`（本环境的 rm 安全钩子删 500+ 文件要确认，会把本地复现 CI 的步骤卡住）；`pkill -f <脚本名>` 会连发起它的 shell 一起杀，排查时别踩。

实测：`--demo` 模式下 `/AAO-Editor/`、`/AAO-Editor/demo/`、`/AAO-Editor/guide/` 全 200；默认模式 VitePress dev 正常起、`/demo/` 如预告只有客户端 404。
