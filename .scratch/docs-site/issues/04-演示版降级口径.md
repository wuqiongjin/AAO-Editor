# 04 · 演示版降级口径与提示

Type: feature
Status: resolved
Blocked by: 03

## 来源

map 2026-10-23：demo「不做人为功能限制」，能跑的全上。缺的都是**平台边界**（CORS / Electron 专有概念），不是被砍的功能。

## 缺口清单（无桥即缺）

| 能力 | 现状 | 处置 |
| --- | --- | --- |
| 社区曲库浏览 / 登录 / 上传发布 | `communityNet` 桥独占，浏览器抛 `unsupported`，入口自动隐藏 | 入口保留可见 + 点开一张说明卡（一句话原因 + 下载桌面版按钮） |
| 社区会话持久化 | 恒 false | 随上一条，不单独提示 |
| 应用更新 / 自动检查 | 无桥只显示应用版本 | 沿用现有分支，不回潮 |
| 数据根 | 无桥整块隐藏 | 保持隐藏（Electron 专有概念） |
| 窗体标题栏 | `windowChrome` 可选调用 | 不动 |
| 诊断包导出 | `exportDiagnostics.ts` 直接 `{unavailable:true}`，**无 fallback** | 本票暂不补（jszip 已在依赖，后续可单开票） |

## 做什么

1. 首次进入 `/demo/` 一条可关闭横幅：数据只存本机浏览器、清缓存即丢；社区与自动更新仅桌面版可用。
2. 社区入口的说明卡（**本轮实现口径，待验收**：选「可见 + 说明」而非「消失」，理由是消失看起来像坏了，说明卡能转成下载）。
3. 文案纪律：不写「阉割 / 演示版限制」，写平台原因；不承诺未发布功能（沿用 2026-10-11 口径）。

## 锁测

- DOM 测试：无 transport 时社区入口仍渲染、点开是说明卡而非空面板。
- 静态断言：`AppUpdateWiring.test.ts` 既有断言不得回潮（关于页在浏览器分支下不出现检查更新）。
- 手工验收：隐身窗口首次进入，横幅与说明卡各出现一次、文案与桌面版现状一致。

## Comments

### 2026-10-25 定案（用户逐条拍板，**取代正文第 1 / 2 条**）

正文「首次进入一条可关闭横幅」「社区入口可见 + 说明卡」两条**均被取代**。新口径：

1. **命名**：这是**在线版**（英文 Web version），不是「演示版」。它基本可以投入正式谱面创作，缺的只是依赖桌面端的能力。界面上不出现「演示版 / 阉割 / 限制」；`/demo/` 作为路径名同样不作数，改 `/app/`。
2. **首访提示 = 模态弹窗，不是横幅**：挂在 app 内（不是文档站拦截点击），只在线版出现，每个浏览器一次（`aao.webNotice.v1`），关掉即记账（按钮 / Esc / 遮罩同一出口）。
3. **关于页常驻一段话**：**不列功能清单**——今天列三条，明天加了第四条没人回来改，而且清单本身把产品说矮了。写法 = **一句总则 + 举例**（「依赖桌面端的能力不可用（如社区曲库、应用更新）」），新能力天然被总则兜住。弹窗与关于页取**同一个 i18n key**（`web.body`），不复制文案。
4. **社区入口维持隐藏**：`ProjectHub` / `AccountBar` / `ProjectsPage.importSources` / `ProjectDialogs` 四处条件渲染**一律不动**。正文那条的动机（「消失看起来像坏了」）已由首访弹窗 + 关于页承担；再放开入口要把四处条件反转、另造说明卡形态，面积与风险翻倍，且与「在线版可正式使用」的定位自相矛盾（最显眼的两格里有两格点了不能用）。验收后仍觉得缺，再单开票。
5. **不给「下载桌面版」外链**：app 在 `/app/` 下、`base: './'` 且不知道站点根，从应用里算相对路径在 Electron / 本地 dev 下是死链；文案写「完整功能请使用桌面版」即可。
6. **判定信号**：全仓无构建期 demo 标志，在线版 / 本地 `npm run dev` / 未打包 Electron 共用同一份 `dist` ⇒ 运行期唯一信号是 `window.electronAPI` 在不在（`hasDesktopRuntime()`，口径同 `community/electronTransport.ts`）。**不加 `import.meta.env.PROD` 门禁**：本地 dev 每个浏览器弹一次、点掉永久消失，换来改文案能立刻看到真东西。

文案定稿（`src/i18n/messages/{zh-CN,en}.json`，弹窗与关于页渲染 `src/app/WebVersionNote.tsx` 这一份）：

> · 部分功能仅在桌面版支持，例如曲库浏览、谱面导入。
> · 工程数据仅保存在本浏览器，清除站点数据后将一并丢失。
> · 完整功能请使用桌面版。
>
> 底栏小字：可在 设置 › 关于 再次查看　主按钮：我已知晓

### 2026-10-25 二轮验收回修（用户）

1. **原文案一整段没人读**（原话「一堆文字堆叠，阅读成本太高」）：拆成**三条短句**，指路小字从标题下挪到底栏、与主按钮同行。结构抽成 `WebVersionNote`，弹窗与关于页共用（关于页走 `compact` 档），**文案仍然只有一份**。
2. 弹窗主按钮 `开始试用` → **`我已知晓`**（点它是"我看过了"，不是"我要开始用"）。
3. 静态锁跟着改成钉「共用组件 + 组件里不出现中文句子」，比原来钉同一个 key 更贴近意图。

### 2026-10-25 三轮验收回修（用户）

1. **不许口语化**：「用不了」→「不可用」、「比如」→「例如」、「跑在浏览器里」整句删掉。
2. **导语取消**：原话「在线版和桌面版是同一个应用，只是跑在浏览器里 —— 谁懂啊，对用户没意义」。用户知道自己开的是浏览器；三条短句各自已带落点，不需要开场白。
3. **关于页那段并入身份卡**：原来它作为独立一段悬在卡片下方，用户判断「非常丑」。改成身份卡的下半段（一道 hairline 隔开 + 小标题「在线版说明」）。紧凑档的图标**保留**（同轮验收：少了图标，三条看着像一坨）——图标是并列条目的分行锚点，只是缩到 14px。
4. **「完整说明」的前缀去掉**：弹窗本身就是完整的那份，改成「可在 设置 › 关于 再次查看」。
5. **举例改「曲库浏览、谱面导入」**，去掉「应用更新」：在线版随站点发布，刷新即新版，把它当"缺失能力"说给用户只会让人以为它不会更新。写完先试过更精确的「导入官方或社区谱面」——在 440px 弹窗里正好折出「面。」两个字单独一行，很难看，退回用户原话（一行放得下）。指南页保留精确版（曲库浏览与登录 / 从官方或社区导入谱面、上传发布），并单开一节说明「在线版不需要手动更新」。
6. 关于页紧凑档的图标**恢复**（同轮验收「图标好像没了」）：图标是并列条目的分行锚点，缩到 14px 保留。
7. **「依赖桌面版的功能不可用」→「部分功能仅在桌面版支持」**：用户判断前者是自造术语——「依赖桌面版」不是用户会说的话，而后者直接陈述事实、也不暗示因果。指南页小节跟着改名「仅在桌面版可用的功能」。
