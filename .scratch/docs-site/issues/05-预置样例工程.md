# 05 · 预置样例工程

Type: feature
Status: closed
Blocked by: 03

## 来源

`/demo/` 首次进入会落在空启动台——没有工程就没有可看的东西，演示感为零。本票把它变成「打开就有东西可玩」。

## 做什么

1. 示例谱面代码 + 封面放 app 侧静态资源（建议 `public/demo/samples/`，随 `/demo/` 一起发布；体量几 KB，进 Electron 包也可接受）。
2. 首次进入时写入 IndexedDB（`aao.chartproject`）：1–2 个工程，含工程信息、1–2 张谱面（难度 / 等级）、谱面时长。
3. **不带 BGM**（版权 + 体积），播放走合成时间线——这点要在样例工程名或横幅里不误导用户。
4. 只写一次：localStorage 标记；用户删光后不反复重建（是否给「恢复示例」入口：待验收）。
5. 与 Electron 版隔离：示例注入只在无 `electronAPI` 时生效，桌面版永远不注入。

## 锁测

- DOM / 集成测试：首次进入后工程列表非空；二次进入不重复写入（数量不变）。
- 手工验收：清空 IndexedDB → 重进仍恢复 1 个样例；桌面版启动台不受影响。

## Comments

### 2026-10-25 关票：不实现（用户拍板）

**结论**：本票不做。立票理由（「`/demo/` 首次进入落在空启动台、演示感为零」）的前提已被票 04 取代——在线版不是 Demo，而是可以正式创作的**网页版**，缺的只是依赖桌面端的能力、推荐路径是下载本地版。真实产品首访为空属正常，不需要预置内容来营造「有东西可玩」。

否决理由：

1. **与定位冲突**：在线版对用户的说法是「工程数据仅保存在本浏览器」。首访自动写入 1–2 个不是用户建的工程（还要靠 localStorage 标记只写一次），是 Demo 手法；用户会把样例当成自己的工程编辑、导出。
2. **票内验收自相矛盾**：正文第 4 条「用户删光后不反复重建」vs 锁测「清空 IndexedDB → 重进仍恢复 1 个样例」——删光即清空，两条不可能同时成立，锁测只会把含混行为固化下来。
3. **样例本身是半成品**：不带 BGM（版权 + 体积）、播放走合成时间线。给「能正式创作」的在线版塞一个没声音、时长也不真的谱面，比空启动台更容易被读成「产品坏了」；否则又得在工程名 / 横幅里解释，等于自认是道具。
4. **维护面被低估**：样例 JSON 要随谱面格式演进（解析失败即坏样例），另加一条「无 `electronAPI` 才注入」的常驻分支与一串锁测，而桌面版永远走不到。
5. **同一问题已有更便宜的答案**：0 工程时 `ProjectHub` 本来就有引导（`projects.guide.*` 横幅 + `projects.empty.*` 空态带「创建第一个工程」），新建弹窗也支持粘贴谱面 JSON（`projects.chartCodePlaceholder`）。「首访有东西可看」交给票 06「快速上手」里一段**可复制的样例谱面 JSON**：用户主动、零注入、零持久化标记、零平台分支。

**若日后仍要 app 内入口**：做成新建面板里的显式一格（「从示例工程开始」），点了才创建、复用空白新建那条创建路径——届时另开票，不复用本票。

原正文保留作事实存档（其中 `/demo/` 路径名已由票 04 改为 `/app/`）。
