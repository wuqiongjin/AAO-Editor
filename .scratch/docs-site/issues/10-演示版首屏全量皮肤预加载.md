# 10 · 演示版首屏全量皮肤预加载

Type: bug
Status: resolved

## 来源

票 03（2026-10-25）接 `/demo/` 时的首屏体积实测发现。票 03 第 3 点写的是「sim/skins 素材应保持运行时按需 fetch」，`sim` 做到了，**`skins` 没做到**——已违背这条既有口径，故按 `bug` 记。

用户追问后补的根因说明（2026-10-25）：不是"启动时预加载 1.75 MB 常驻"这句话本身，而是——**AAO Editor 一启动就把七个页面全部一次性挂载**（无论桌面版还是网页版），其中素材页会为 7 个音符皮肤包各渲一张整包缩略图，每张缩略图都要把它那个包的图集 + 连接带 + SP 带 + 同时线 + 方向键图集拉下来。合计 33 张 PNG ≈ 1.75 MB。桌面版是 `file://` 本地读，几乎无感；网页版就是首屏白打 1.75 MB 网络请求，且这些图进 `CanvasSpriteIcon.imageCache` 后**常驻内存到进程结束**（网络请求只发生一次）。

## 症状

浏览器演示版打开 `/demo/`，还没进任何页面，首屏就发起 33 个皮肤图集请求（1.75 MB）。这笔流量与用户当前操作无关：用户可能只是想看一眼工程列表。

## 根因

`src/layouts/AppShell.tsx` 的**保活挂载**：

```
// 保活挂载：所有 page 始终渲染，仅激活页可见
{PAGE_IDS.map((id) => <PageSlot key={id} id={id} active={activePage === id} />)}
```

七个页面在应用启动时全部 mount。其中 `AssetsPage` 的整包预设列表（`NoteSkinPresetThumbnail`）给每个 note 包各渲一张缩略图，每张在 `useEffect` 里 `CanvasSpriteIcon.ensureImagesLoaded(icons.preloadSrcs())`——`preloadSrcs()` 返回的是**该包自己的**一组图（atlas / band / bandSp / simultaneous / 配对方向包 atlas），于是 7 个包 × 4~5 张 + 5 个方向包图集 = 33 张，全部在启动时并行下载。

`sim` 素材不中招：`loadSimAssets` 只在 `PreviewVideoStage` 挂载**并且**切到动态预览时才调用。

## 修法候选（待拍板，不在本票实现）

1. **缩略图按需加载**：非激活页的 `PageSlot` 不渲染 `AssetsPage` 的预设缩略图（或延迟到首次切到素材页再加载）。不动保活挂载这条架构，改动面最小。
2. **列表虚拟化 / 懒加载**：preset 用 `IntersectionObserver` 或滚动懒渲染，只加载视口内的几张。
3. **共享一张缩略图资源**：让取件侧产出一张小尺寸预览图取代"用整张图集现画"，同时省网络与 canvas 绘制成本。
4. **不动**：桌面版无感，只追究网页版的话，可以接受（但要先把票面口径改掉，别留不一致）。

倾向 1 或 3：1 最直接，3 顺带把"缩略图为什么要用整张原生图集现画"这件事一起理了。要用户拍。

## 锁测

1. **Playwright 网络实测**（照票 03 的验收路径）：`/AAO-Editor/demo/` 首屏 `assets/skins/` 的请求数 ≤ 选中包所需的那几张（现为 33 → 期望 ≤ 6），且总字节 ≤ 当前包的量级；切到素材页后剩余缩略图再加载。为什么不用单测：这是浏览器网络行为 + React 挂载时序，jsdom 里既发不出请求也复现不了保活挂载。
2. **DOM 测试**：激活 / 失活切换后皮肤预设缩略图仍能正常绘制（不出现"切过去空白"回归）。
3. **反向锁**：改完务必复测「切进素材页 → 切走 → 再切回」——保活挂载的初衷是"激活页可见 + 失活页保留状态"，别为了省流量把状态丢了。
4. 静态锁（可选）：`AppShell` 里 `PAGE_IDS.map` 那条「保活挂载」注释若一并改了，同步更新与之相关的一概说明，别留下过期口径。

#### 拍板（grilling 一轮即闭）

1. **修法 = 候选 1**（缩略图延迟到首次进素材页）。候选 3 被否在事实上：`src/rendering/skin/gen/` 与

   （`scripts/README.md` §运行时资源包）——要「取件侧出小预览图」得先改快照仓，不属本仓可闭环范围。
   候选 2 只在 1 之上省「首次进素材页那一下」的并发，候选 4 与票 03「skins 应保持运行时按需 fetch」冲突。
2. **latch 语义 = 首次激活后常驻**（不是离页就卸）：保住保活挂载的初衷（切走切回零重挂、不丢状态）。
3. **平台 = 全部统一**：`/app/` 与桌面版跑同一份构建，不为此引入构建标记；桌面版本地读、无感，但行为一致。
4. **锁测 = 永久 DOM 锁 + 一次性 Chromium 实测**（见下）。
5. **另开票 11**：真正的根因是「7 页启动全 mount」，本票只掐最贵的症状；改 `PageSlot` 为「首访挂载」单独立票，不动保活架构。

#### 实现

- `src/pages/assets/AssetsPage.tsx`：接住 `PageSlot` 早已传下的 `active`，新增只升不降的 `visited` latch
  （`useState(active)` + `active` 时置真），正文 `AppPageShell.Body` 里的两个面板都挂在这个闸门下。
  `visited || active` 使首访那一帧就出内容，不会闪一帧空白。`PageSlot` / `AppShell` 一行未动——
  「保活挂载」那条注释与本轮事实仍相符（访问过的页面始终渲染），无需改口径。
- 素材页身兼两类开销的入口（7 张整包缩略图 + 综合预览），一起被挡在首次访问之后。

#### 锁测

`tests/dom/pages/AssetsSkinDeferredLoad.test.tsx`（新增 5 条，jsdom）——把 `CanvasSpriteIcon` 整体替身化，
锁的是**取图闸**而不是像素；页面/正文的有无仍按 role 查（`region` + 分区 aria-label）：

1. 没进过素材页：正文不挂载（场景分区查不到），`ensureImagesLoaded` 0 次（含反复失活重渲）；
2. 首次激活：分区出现、每个包的图集都进了请求清单，且 `render` 真的落笔（不是空卡）；
3. 首访即素材页（直接开在本页）：不因 latch 初始值漏画；
4. 反向锁：切走再切回，取图次数与绘制次数都**一毫不变**（重取 = latch 没常驻；重画 = 组件被卸载重挂）；
5. **接线锁**：渲染真 `PageSlot`（不是测试里手工摆 `active`），锁住「闸门吃的是应用壳传下来的 `active`」。

变异验证（两条）：① 把 `bodyMounted` 改回 `active`（离页即卸）→ 第 4 条转红；② 把 `PageSlot` 的
`<Component active={active} />` 改成 `<Component />` → 第 5 条转红。还原后全绿。

顺带：注册表替身抽到 `tests/support/noteSkinStub.ts`（原本与票 49 那份 fixture 逐字重复四十行），
`AssetsPageNoteSkin.test.tsx` 改为共用（它守护的「显示名不回落 label」断言原样保留）。
