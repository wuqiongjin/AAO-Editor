# 07-工程id白名单非字符串漏判

Type: bug
Status: resolved

**来源**：[06](./06-工程记录单映射与单写入口.md)（架构评审候选 2）加跨进程同口径锁测时暴露（2026-09-29）。

**症状**：渲染侧 `assertValidProjectId` 只跑正则，非字符串会被正则**强制转串**后放行——`123` 判成合法 id，一路走到主进程；主进程 `safeProjectId` 有 `typeof` 检查、直接拒。双保险（渲染侧先拦 / 主进程再拦）对这类输入判决不一致：渲染侧那道形同虚设，抛出时机与来源都落到主进程。

**根因**：`/^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/.test(id)` 对非字符串先做 `ToString`；`typeof` 这层只写在 `electron/dataRoot.cjs`。

**修法**：`src/project/ChartProjectRecord.ts` 的 `assertValidProjectId` 补 `typeof id !== 'string' ||`，与主进程逐条对齐，错误文案不变（`非法的谱面工程 id: …`）；正则提成 `PROJECT_ID_PATTERN` 常量。类型上不可能出现的输入不再有分歧。

**锁测**：`tests/platform/electron/ProjectRecordCrossProcess.test.ts` —— 同一 id 语料（含 `123` / `null` / 超长 / 路径穿越 / 非 ASCII）在两侧判决必须一致；`tests/platform/electron/ChartProject.test.ts` 的「非法工程 id 在渲染侧即拒绝」原样看守后端接线（该用例在修前只覆盖字符串语料，故漏判未被发现）。
