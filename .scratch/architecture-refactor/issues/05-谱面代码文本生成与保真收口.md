## 来源与目标

- **来源**：`notes → 文本` 今天有两份实现（导出与弹窗各一份）；`appliedChartCodeText` / `chartCodePristine` 是两个独立 `useState`，「改音符即作废」这条规则手写在四个入口里。
- **目标**：
  1. 一份序列化器 + **两个具名入口**（画布投影 / 源数据优先），口径不变：**弹窗显示投影，另存为走源数据优先**；
  2. 保真 = state 的一个字段，与 notes **同一次 `setState`** 写（原子、无法绕过），**不进快照栈**；四个手写作废点收成一个 commit；
  3. 不碰 `ProjectChart` 记录形状、不引入 `chart → project` 反向依赖。

## 落点

1. **序列化（`ChartConverter.ts`，与 04 同一 module）**：一份实现出两个具名入口——
   - 投影文本：画布音符 → 紧凑 JSON（弹窗显示用）；
   - 导出文本：保真 pristine 且有源文本时**原文返回**，否则回退投影（另存为，以及将来 Bestdori 上传同一个口）。
   `exportChartCode.ts` 与 `ChartCodeEditorModal.currentViewText` 都改走它们，仓库里不再有第二份 `convertNotesToChartCode` + `chartCodeToCompactJSON` 组合。
2. **保真收成一个 commit**（Q2=b + Q1=B 定案）：
   - `{ text, pristine }` 作为 EditingProvider 状态对象的**一个字段**，与 notes 在**同一次 `setState`** 里改——原子、任何改 notes 的路径都无法绕过；
   - **不进历史快照栈**：撤销 / 重做照旧**作废** `pristine`（今天语义），但**不还原旧值**（没有"撤销回退到 pristine=true"这回事）；只有 Apply 置回 `(text, true)`、切工程从记录恢复；
   - 类型定义放 chart 域（与序列化 module 同处），`ProjectChart` 保持两个扁平字段不变，映射发生在 EditingProvider 边界——**不引入 `chart → project` 反向依赖**。
3. **口径不变**：弹窗显示的是画布投影；未应用的草稿照旧不导出（`exportChartCode.ts:55` 定案）；已上传只读闸门（`useChartProjectPersistence.ts:114-118`）不属本票。

## 锁测要求

- **新增行为单测**（`tests/unit/`，覆盖保真语义，不只覆盖函数）：
  - Apply → `pristine = true` 且文本 = 源文本；
