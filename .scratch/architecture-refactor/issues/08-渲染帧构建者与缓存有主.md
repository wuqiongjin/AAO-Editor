# 08-渲染帧构建者与缓存有主

Type: chore
Status: resolved

> **来源**：一次架构评审（2026-09-29）候选 3「一帧只有一个构建者，缓存有主」（dir 2 谱面预览，评 Strong）。
> 候选 1（[04](./04-谱面代码解析侧收口.md) / [05](./05-谱面代码文本生成与保真收口.md)）与候选 2（[06](./06-工程记录单映射与单写入口.md)）已收口，本轮编号自本票续。

## 来源与目标

- **来源（逐条读码核对，2026-09-29）**：
  1. **没有一帧的构建者**：`FinalVirtualCanvas.renderCanvas`（`src/chart/components/canvas/FinalVirtualCanvas.tsx:503-584`）从 5 个 provider（`useEditing` / `useUI` / `usePlayback` / `useConfig` / `useChartCodeEditor`）现攒 `RenderCtx`（32 字段）再调 `renderChart(ctx, canvas, rc)`——"任意秒一帧"没有任何单一入口，预览只能复制这份装配。
  2. **两层离屏缓存没有所有者**：`pipeline/staticLayerCache.ts:14-15,37-38`（`screenCanvas` / `stripCanvas` / `screenBasis` / `stripMeta`）与 `pipeline/noteLayerCache.ts:65-70`（`tiles` / `basis` / 播放瓦片队列 / 计时器）都是**模块级单例**——第二个渲染目标（离屏导出 / 预览）一渲染就会与工作台互相顶掉缓存。
  3. **dpr / 尺寸解析散在 5 处**：组件（`FinalVirtualCanvas.tsx:535` dpr 策略：`min(devicePixelRatio, 1/2.5/3)`）、`renderChart`（主缓冲 `round(surface×dpr)`）、静态层屏幕层与 pos 条带（`ensureBitmap`）、音符瓦片（`round(css×tileDpr)`）各自算一遍。
- **目标**：
  1. **缓存有主**：新增 `RenderTarget` = 一次绘制「画到哪」的全部归属（画布 + surface + dpr + 两层离屏缓存实例）；工作台画布是 target 之一，离屏导出 / 未来预览各建自己的 target，互不顶掉（issue 36 F2/F3 的失效语义逐条不变）。
  2. **一帧的构建者**：`frameFor(target, view) → RenderCtx`（view = 现 `RenderCtx` 去掉 target 拥有的 `surface`/`dpr`）+ `target.renderFrame(view)` 一次调用出帧；组件只组装 view。
  3. **dpr / 尺寸解析收成 1 处**：新增 `resolveCanvasDpr`（策略）与 `bufferSizeFor`（缓冲尺寸），四处位图尺寸共用。
  4. **零行为变化**：dpr 取值策略（issue 39/40 定案 1×/2.5×/3×，上限 `devicePixelRatio`）原样保留、只搬位置（与 ADR-0006 §1 不冲突，ADR 保留"上限 2"的历史表述，现口径以 issue 39/40 为准）；渲染结果、缓存失效依据、skip 策略逐条不变。

## 本轮口径（用户 2026-09-29 拍板）

- **`renderFrameAt(target, chart, T)` 不落本票**：它唯一的产品调用者（`chart-preview/01` 谱面预览）还没开工，照 04 定案⑤ / 06 落点 5 先例——无调用者的接缝不预埋；`frameFor`/`renderFrame` 已是一站式出帧入口，预览票按真需求再定 `renderFrameAt`。
- **view 边界取最小面**：view = 现 `RenderCtx` 去掉 `surface`/`dpr`（target 拥有）；组件仍组装其余字段，渲染域接口变成 `(target, view)`。不把 `frozenCursor` / `display` 归一化 / `spriteIcon` 等派生计算一并搬进构建者（审查面更大，且与"行为不变"无冲突收益）。

## 落点

1. **新增 `src/rendering/rasterScale.ts`**（栅格尺度解析唯一处，叶子模块）：
   - `resolveCanvasDpr(imageQuality, devicePixelRatio?)`：dpr 策略（流畅 1× / 标准 2.5× / 高清 3×，上限 `devicePixelRatio`）；
   - `bufferSizeFor(surface, dpr)`：`round(css × dpr)` 位图尺寸（主画布 / 静态层屏幕层 / pos 条带 / 音符瓦片共用）。
2. **两层缓存实例化**（模块级可变单例删除）：
   - `pipeline/staticLayerCache.ts` → `createStaticLayerCache()`（屏幕层 + 条带 + basis；`draw` / `reset` / `__setCanvasFactoryForTests` 收进实例）；
   - `pipeline/noteLayerCache.ts` → `createNoteLayerCache()`（tiles / basis / 播放瓦片队列与计时器 / stats 收进实例）；
   - 纯函数与常量（`computeBackgroundDrawRect`、`normalizeBackgroundOpacity`、`TILE_PX`、`diffNotes`、`posRangeOf`、`tileIndexRange`、`tileBlitRect`、`clipTileDrawRect`）仍在模块级导出。
3. **新增 `src/rendering/RenderTarget.ts`**：
   - `createRenderTarget({ canvas, surface, dpr })` → `RenderTarget`：拥有 `canvas` / `context()` / `surface` / `dpr` / `staticLayer` / `noteLayer`，`configure({ surface?, dpr? })` 原地更新（缓存续用/失效由各层既有 basis 决定）；
   - `frameFor(target, view) → RenderCtx`（把 target 的 surface/dpr 注入 view）；
   - `target.renderFrame(view)` = `renderChart(target, frameFor(target, view))` 一次调用出帧。
4. **`render.ts` 绘制编排改走 target**：`renderChart(target, rc)`——主缓冲尺寸走 `bufferSizeFor(target.surface, target.dpr)`，ctx 走 `target.context()`，`drawStaticLayer` / `drawNotesLayer` 改经 `target.staticLayer` / `target.noteLayer`。
5. **工作台画布成为 target 之一**（`FinalVirtualCanvas.tsx`）：组件持 `targetRef`（懒建 + 每帧 `configure`），每帧只组装 `view`（不再算 dpr / 不再拼 surface）；dpr 经 `resolveCanvasDpr(display.imageQuality)`。构造/失效逻辑、marker DOM 更新、useLayoutEffect 时序逐条不变。
6. **`src/rendering/index.ts`** 出口补 `createRenderTarget` / `frameFor` / `resolveCanvasDpr` / `bufferSizeFor` / `FrameView` / `RenderTarget` / 两层缓存的工厂与类型（唯一绘制入口，预览的地基）。

## 锁测要求

- **净值网**：`npm test`（开工前基线见 Comments）+ `npx tsc -b` 全绿；既有断言只换入口（模块级函数 → 实例方法 / `renderChart(ctx, canvas, rc)` → `renderChart(target, rc)`），断言语义逐条不动。
- **新增 `tests/unit/rendering/cache/TargetIsolation.test.ts`**（本票的核心行为锁）：
  - 两个 target 各自持有静态层缓存：对 target A 渲染一帧后渲染 target B，A 的屏幕层/条带不失效（同 scrollY 再渲染 A 时静态重绘数不增）——即"离屏导出不再顶掉编辑器缓存"；
  - 两个 target 各自持有音符瓦片表：A 的瓦片身份在 B 渲染后不变，B 有自己的一份；
  - target 的 `configure({ surface })` 原地生效、缓存续用（不重建 target）。
- **新增 `tests/unit/rendering/FrameBuilder.test.ts`**：
  - `frameFor(target, view)` 产出的 `rc.surface` / `rc.dpr` 来自 target，其余字段逐条透传（view 里同引用）；
  - `renderFrame(view)` 一次调用完成：主画布缓冲 = `surface×dpr`（整数）、`setTransform(dpr,…)`、静态层与音符层各画一次。
- **`resolveCanvasDpr` 策略锁**（同文件或 `tests/unit/rendering/RasterScale.test.ts`）：smooth→1 / standard→2.5 / hd→3，上限 `devicePixelRatio`（含 1 档 devicePixelRatio=1、3 档 devicePixelRatio=4 等边界）。
- **新增 `tests/static/RenderTargetWiring.test.ts`**（防回潮接线锁）：
  - 工作台画布经 `createRenderTarget` / `renderFrame` 绘制，不再出现 `renderChart(ctx, canvas, rc)` 旧签名与 `Math.min(window.devicePixelRatio` 内联策略；
  - 两层缓存文件不再出现模块级可变单例（`let screenCanvas` / `const tiles = new Map` 形态）；`renderChart(` 只出现在渲染域内。
- **替代验证说明**：本票不改变任何像素语义，不新增 Playwright 像素实测；缓存复用/失效的数字断言（重绘计数、瓦片身份）由上述单测与既有 cache/perf 套件覆盖——它们本来就是"行为不变"的证据。

## 不在本票范围

- **`renderFrameAt(target, chart, T)`**（任意秒一帧）与任何预览 / 导出代码（见"本轮口径"；随 `chart-preview` 票）；
- 组件侧派生计算搬迁（`frozenCursor` 现算、`display` 归一化、`spriteIcon` 单例、`zoomGesture`/`playing` 合并）——留待有真实收益时再动；
- dpr 策略本身的取值调整（1/2.5/3 与 ADR-0006 §1 的关系：口径以 issue 39/40 为准，本票只搬不改）；
- `perf` 诊断（`chart/perf.ts`）与 `perf.info` 的归属——仍是模块级诊断单例。
