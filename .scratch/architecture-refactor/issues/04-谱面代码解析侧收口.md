# 04-谱面代码解析侧收口

Type: chore
Status: resolved

> **来源**：一次架构评审（2026-09-29）候选 1「谱面代码只从一个口进出」，本轮 grill 定案（见 map「候选 1 grill 定案」）。
> **本票只做解析侧**：文本 → 已校验 code 收成一个入口。序列化侧与保真在 [05](./05-谱面代码文本生成与保真收口.md)，`Blocked by` 关系反向（05 依赖本票）。

## 来源与目标

- **来源**：四类调用点各自拼「校验 → 解析 → 转换」，同一段谱面代码文本被 `JSON.parse` **两遍**；根因不是调用方偷懒，是 `validateChartCodeJSON` 把解析出的数组丢了。
- **目标**：
  1. `ChartConverter.ts` 出唯一入口 `parseCodeText(text) → { code, errors }`——**只 parse 一次**，结构校验照旧「一次收全部错误」（`Apply 硬拒绝` 口径不变）；
  2. **校验与转换分离**：只要错误的路径（弹窗 250ms 防抖校验）不付 `convertChartCodeToNotes` 的成本；要画布音符的调用方自己调它（保持纯函数、可单测）；
  3. 删掉两个肇事 API，消掉仓库里全部三处二次 parse。

## 现状核对（2026-09-29，逐条 grep 所得）

- `ChartConverter.ts:586-597` `validateChartCodeJSON(text)`：内部 `JSON.parse` 后**只返回 `{ valid, errors }`，数组被丢弃**——调用方要 notes 只能自己再 parse。
- 二次 parse 的三处：
  - `src/project/projectCatalog.ts:123`（`validateChartCodeJSON`）+ `:125`（`JSON.parse`）→ `:126` `hasBeat0Bpm` → `:129` `convertChartCodeToNotes`；
  - `src/chart/components/code-editor/ChartCodeEditorModal.tsx:302`（`validateCode` → `validateChartCodeJSON`）+ `:325`（`parseChartCodeFromJSON`）→ `:328` `hasBeat0Bpm` → `:341` `commitApply`；
  - `scripts/analyze-stress-test-charts.ts:341` / `:362`（同一文本两次 `validateChartCodeJSON`）。
- `ChartConverter.ts:222-229` `parseChartCodeFromJSON`：失败 `console.error` + 返回 `[]`——弹窗 `:193-194` 的注释明确记载这就是「JSON 语法错误被误报成缺第 0 拍 BPM」的肇事者。
- 对象视图 dialect 已在复用整份谱面的校验与转换：`NoteCodeOps.ts:264-279` `coerceNoteViewCode`（容错裸对象 / 单元素数组）→ `:141` / `:178` `validateChartCode(fragment)` → `:185` / `:234` `convertChartCodeToNotes`。
- **策略性判定散在调用方，本票不动**：空文本保底 120 BPM（弹窗 `:206-209`、`:235-242`）、`hasBeat0Bpm` 硬要求（`projectCatalog.ts:126-128`、弹窗 `:328`）。
- 全仓无第二套 notes↔code 转换实现；`ChartConverter.ts` 是唯一真相源。

## 落点

1. **新增** `ChartConverter.ts` → `parseCodeText(text: string): { code: ChartCodeNote[] | null; errors: ValidationError[] }`：内部 `JSON.parse` **一次** + 调 `validateChartCode`；JSON 非法 / 根不是数组时 `code = null`，错误文案照今天。**原地改，不搬文件、不拆文件**（Q1=a）。
2. **删除** `validateChartCodeJSON`、`parseChartCodeFromJSON`（Q4=a）。三个调用点改打新入口：
   - `projectCatalog.addChartToProject`：一次 `parseCodeText`，`errors` 非空即拒，`code` 用于 `hasBeat0Bpm` + `convertChartCodeToNotes`；
   - `ChartCodeEditorModal`：`validateCode` 与 `handleApply` 共用同一次解析结果（`handleApply:300-302` 的 `validationTask.cancel()` + 即时结算口径不变）；
   - `scripts/analyze-stress-test-charts.ts` 两处同步改（第三处二次 parse，顺手收掉）。
3. **对象视图只共享解析原语**（Q5=a）：`coerceNoteViewCode` 的 `JSON.parse` 改调 `parseCodeText`；**容错（裸对象 → 包成单元素数组）留在对象视图**——不让裸对象变成整份谱面入口也悄悄接受的形态。
4. **零行为变化**：toast 文案、`ValidationError` 结构（`noteIndex` / `connIndex` / `field` / `reason` / `expected`）、`formatValidationError`、`Apply 硬拒绝` 口径（CONTEXT.md）逐条不变。

## 锁测要求

- **净值网**：`npm test`（2026-09-29 基线 **167 文件 / 1933 用例**）+ `npx tsc -b` 全绿；除上述调用点外无 diff。
- **新增单测**（`tests/unit/chart/code/`，与既有 `ChartConverter.test.ts` 同域）：
  - 合法数组 → `code` 与空 `errors` 一次给出（**同一份文本只 parse 一次**）；
  - JSON 语法错 → `errors` 非空且 `code === null`（今天「误报成缺第 0 拍 BPM」的回归网）；
  - 根不是数组（对象 / 字符串 / null）→ 拒；
  - 顶层无 `type` / `type` 不在 ADR-0014 白名单 → 拒，报错明示下标。
- **改写既有断言**：`tests/unit/chart/code/{ChartConverter,ChartCodeSourceFidelity}.test.ts` 中对两个被删函数的调用改打 `parseCodeText`（**只改入口，断言语义逐条不动**）；用 `validateChartCode`（数组口径）的测试保持不动。
- **「parse 一次」的静态看守**（照 `tests/static/` 惯例新增）：`projectCatalog.ts` 与 `ChartCodeEditorModal.tsx` 源码中不再出现对谱面代码文本的 `JSON.parse(`；`ChartConverter.ts` 里 `JSON.parse` 只允许出现在 `parseCodeText` 与 `normalizeChartCodeText`。
- **本票不应顶红** `tests/static/ChartCodeModalResponsiveness.test.ts` 与 `tests/platform/electron/ChartCodeExportSaveAs.test.ts`——弹窗的文本生成与导出 gate 不属本票；若红了，说明动了不该动的行。
