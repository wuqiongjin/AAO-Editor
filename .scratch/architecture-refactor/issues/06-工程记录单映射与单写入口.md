## 来源与目标

- **来源**：谱面工程记录（`ChartProject` ↔ 存储形状）的**字段映射手写了三遍**（Electron wire / IndexedDB 存储 / 主进程收尾各一遍），加字段要同步多处；而整记录的**读-改-写有五条路径 + 会话的 open**，其中最贵的一条（音频提交）的次序约束只写在注解里。
- **目标**：
  1. **一份映射**：新增 `src/project/ChartProjectRecord.ts` 拥有记录形状与映射，两个后端（IndexedDB / 文件）共用同一组转换函数与同一套测试；加字段只动一处（字段表 + `satisfies` 编译期看守）。
  2. **一条写入口**：`mutateProject(deps, projectId, fn)` = `flush → get → fn → save → notify`，五处现存读-改-写路径 + `CurrentProjectSession.open` 全部改走它；上传记录的落笔点就是同一个 `mutateProject`（本票不造上传流程）。
  3. **零行为变化**：存储形状、`schemaVersion`、旧记录「不读不删」口径、封面 Blob 身份稳定化、防抖落盘时序逐条不变（**唯一例外**＝ id 白名单的非字符串漏判，拆 [07](./07-工程id白名单非字符串漏判.md) 记账）。

## 落点

1. **新增 `src/project/ChartProjectRecord.ts`**：记录形状与映射的唯一拥有者。
   - 类型与常量迁入：`PROJECT_SCHEMA_VERSION`、`ProjectRecordDoc`、`ProjectPutWire`、`ProjectGetWire`、`ProjectListItem`、`BinaryIntent`、`ElectronProjectBridge`（`ChartProject.ts` 只留工程/谱面实体与 store 门面，改 import 打本模块；两个测试文件的 import 同步改，不留转发别名）。
   - 转换函数（一份字段表驱动两个方向；加字段只动 `RECORD_FIELDS` 一张表）：
     - `recordFromProject(project, audioIntent, coverIntent)`（原 `toPutDoc`，charts 仍 `cloneJson`）；
     - `projectFromRecord(id, doc, audio, cover)`（原 `projectFromDoc`，`??` 兜底原样）；
     - `storedFromProject(project)` / `projectFromStored(record)`（IndexedDB 形状，原 `{ ...project, schemaVersion }` / `fromStored`）；
     - `isCurrentProjectRecord` / `canReplaceStoredProject`（原闸门，语义不动）。
   - **存储形状不变**：IndexedDB 记录仍是 `ChartProject & { schemaVersion }`（Blob 内联），wire doc 仍带 `audioPresent/coverPresent` —— 不做数据迁移，旧记录照旧可读。
2. **新增 `mutateProject(deps, projectId, fn)`**（同模块导出）：
   - `deps = { store, flush?, notify? }`；次序固定为 `flush → get → fn → save → notify`；`fn` 返回 `ChartProject | null`，`null` = 调用方取消（不写、不通知）；
   - 返回 `{ status: 'saved', project } | { status: 'missing' } | { status: 'cancelled' }`；**取消原因留在调用点**（音频锁判定、`decode` 失败都是音频语义，不属记录模块）；
   - `save` 失败不回滚、不 notify、错误上抛（与今天各调用点一致）。
3. **五个调用点改走它**（调用点自己的下一步动作留在原地）：
   - `projectAudio.ts`：`loadWritable/commit` 的 `flush → get → save → notify` 收进 `mutateProject`，锁判定与解码仍在 `fn` 里（锁判定先于解码的口径不变；「无需落盘」用 `skip` 表达）；
   - `ProjectsPage.mutate`：函数体换成 `mutateProject`，`reload()` 留在调用点；
   - `ProjectsPage` 新建谱面 `onAdd`：同前，校验失败的 toast 留在 `fn` 里、`setChartForm(null)` + `reload()` 留在调用点；

   - `WorkspacePage.handleCopyCurrentChart`：同前，`open(projectId, copyId)` 留在调用点（该路径今天不 flush，本票只换入口不改口径）。
4. **跨进程同口径锁测**（新增 `tests/platform/electron/ProjectRecordCrossProcess.test.ts`）：同一 id 语料在渲染侧 `assertValidProjectId` 与主进程 `safeProjectId` 判决一致（**含非字符串**）；同一 doc 语料在 `isCurrentProjectSchema` 与 `projectStore.cjs` 的 `isCurrentDoc`（经 `getProject` 实读）判决一致；写侧闸门（空位可写 / 旧记录拒覆盖）两侧一致；`PROJECT_SCHEMA_VERSION === projectStore.SCHEMA_VERSION`。**不合并双份实现**（无共享构建通道），只让漂移必红。
