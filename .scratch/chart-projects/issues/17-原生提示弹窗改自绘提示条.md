# 17 · 原生提示弹窗（window.alert）改自绘提示条

Type: feature
Status: resolved

**来源**：用户 2026-09-28（16 票样式验收通过后）反馈「谱面代码编辑器点『应用』时仍弹原始 windows 弹窗」，
并问还有没有同类遗留。

**症状**：全站 11 处 `window.alert` —— `ChartCodeEditorModal` 8 处（应用成功 / 应用失败 /
校验不过 ×2 / 缺第 0 拍 BPM / 复制成功 / 复制失败 / 另存失败）、`ProjectsPage` 2 处
（不能删最后一张谱面 / 新增谱面被拒）、`ChartSwitcher` 1 处（新增谱面被拒）。
`window.confirm` 已在 13 票清零；`window.prompt` 全站没有。Electron 侧的原生 dialog 只剩
文件选择器（选数据根 / 另存为），那是系统集成，不算提示弹窗。

**根因**：13 票只把「二选一确认」收进自绘弹窗；**单向下达的提示**（成没成、为什么不行）
一直没有落点，于是各处随手 `alert`。16 票明确把这件事排除在外（另开票）。

**修法**（本轮实现口径，待验收）：
- `src/ui/Toast.tsx`：`showToast(message, tone)` + `<ToastHost/>`（挂在 `AppShell` 一次，
  portal 到 body）。模块级函数而非 Context —— 调用点散在深层回调里，提示不该穿 props 转手。
- 形状沿用工作台「已上传只读」浮条（chart-projects 06）：顶部居中、可手动关、胶囊。
  语气四档 info / success / warn / danger；底色 = 语气色 14% 混 `--bg-elevated`（**不透明**，
  浮在画布上不能透底），文字用对应的 `--*-text`；色全走 token。
- 停留：成功类 2600ms、警告/失败 5000ms；同一时刻只留一条（后来的顶掉前一条）；
  warn/danger 走 `role="alert"`，其余 `role="status"`；层高 `calc(var(--z-modal) + 10)`，压在弹窗之上。
- 「不能删最后一张谱面」是拦住动作不是出错 —— 走 warn 不走 danger。

**锁测**：
- `tests/static/NoWindowAlert.test.ts`（新）：src/** 无 alert / confirm / prompt 调用；
  三个文件的 showToast 接线数（8 / 2 / 1）；宿主挂载恰好一次；提示条层高在弹窗之上。
- `tests/dom/ui/Toast.test.tsx`（新）：弹一条 / 按时消失 / 失败类停留更久 / 顶掉前一条 /
  手动关 / 挂载前发出去的提示不丢 / 语气即 role。
- 视觉（胶囊形状、四档配色、压不压得住弹窗）jsdom 无布局引擎 → headless 出图 + 小窗 hit test。

## Comments

**2026-09-28 实现 + 自查**

- 11 处调用点全部改接 `showToast`（成功类 success、出错类 danger、拦住动作 warn），
  三个文件的 import 与调用点同步；i18n 只新增 `ui.dismiss`（关闭提示按钮的无障碍名，zh + en）。
- 出图自查（headless Chromium 走真实 UI）：成功（应用更改）与失败（改坏代码后立刻点应用，
  走防抖窗口内那条 `alertErrorsApply`）两条提示都上屏、语气色正确；暗色未单独出图但底/字色
  走的是 token 混色，与弹窗色带同源。
- 一处实现细节按实机修正：最初用 `--*-soft` 直接当底色，浮在页面/画布上会**透出背景**
  （暗色主题下那几档 soft 本身就是半透明），改成 `color-mix(语气色 14%, --bg-elevated)` 不透明底。
- 小窗（1280×720）hit test：提示条矩形（y 16–54）与弹窗顶部（y 49）重叠时，
  中心点命中的是提示条 —— 层高压得住。
- 全量 1718 条测试通过（新增 13 条：提示条 DOM 6 条 + 原生弹窗清零 7 条）。
- 另报（本票未动，等用户定）：`src/layouts/AppShell.css` 的 `.readonly-toast__copy-btn`
  用了 **`--accent-contrast` 这个不存在的 token**（tokens.css 里没有），文字色实际走继承 ——
  在暗色主题下是浅底浅字。一行可修（改 `--text-on-accent` 或 `--accent-btn-text`），
  但它属于「只读浮条」那套历史样式，与本票的提示条是两回事。
