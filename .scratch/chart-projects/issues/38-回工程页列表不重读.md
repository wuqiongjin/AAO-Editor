# 38 · 回工程页时列表不重读

Type: bug
Status: resolved
Blocked by: —

## 来源

issue 36 验收现场（用户 2026-10-15）：工作台编辑谱面后回到工程管理页，卡片 / 详情谱面行的音符数还是上次编辑后的数量，不是本次编辑后的。

## 症状与根因

工程页保活挂载（PageSlot 只切可见性、不卸载），列表只在 catalogEpoch 变化时 reload；工作台的音符编辑走 800ms 防抖落盘、防抖那笔落地**不通知目录**，切页也不 flush / 不重读。唯一会把工作台编辑刷进工程页的是 `setCurrent → notifyCatalogChanged()`——发生在**点进工作台那一刻**，于是回来看见的是上次的快照，下次再进工作台才刷出来，正好晚一次导航。预览页踩过同一坑（2026-10-05 验收：重置谱面后切预览仍见旧音符）并已在 `usePreviewScope` 修掉：激活时重读 + 读前先 `flushPersist`；工程页只在**写前** flush，缺「激活时重读」这一条。

## 修法

照 `usePreviewScope` 范式：ProjectsPage 收 `active` prop，加激活 effect（`false→true` 时先 `flushPersist()` 再 `reload()`）。hub 卡片与详情谱面行的音符数同源（都出自 `projects` state），一处修两边好。

## 锁测

1. `tests/dom/pages/`：active 切换锁行为——disk 换上工作台刚落盘的记录（音符数变了），激活工程页后文案即时更新；不激活不更新。
2. 静态断言（照 35/36 惯例）：激活 effect 内先 `flushPersist` 再 `reload`——顺序锁死，防只重读不 flush、读到防抖窗口前的旧记录。

## Comments

- 2026-10-15 实现（resolved）：`ProjectsPage` 收壳层 `active` prop（PageSlot 早在传，页面此前不接），加激活 effect——`false→true` 边沿（`wasActiveRef` 守卫，照 `usePreviewScope` / `useAudioScope` 同形）时先 `flushPersist()` 再 `reload()`。挂载时的那次读仍走原来的 `catalogEpoch` effect，不 flush（启动时工作台未挂，无在飞防抖笔）。hub 卡片与详情谱面行同出 `projects` state，一处修两边。
- 锁测：DOM 两条（`tests/dom/pages/ProjectsActiveReload.test.tsx`）——① 防抖笔在飞（flush 回调模拟 `persistNow`，只在 flush 时写盘、不通知目录）：激活后音符数 2→3 即时更新；② 盘上记录已换（不通知目录）：不激活纹丝不动、激活即重读 2→5。静态五条（`tests/static/ProjectsActiveReload.test.ts`）：active prop 形态、effect 形状一段正则、`flushPersist` 严格先于 `reload`、依赖 `[active, flushPersist, reload]`、`catalogEpoch` 那条不受影响。撤修复 / 换序 / 删 flush 三种破坏均验过红。
- 验证：`tsc -b` 净；相关测试域 137 条 + 全量 3108 条（265 文件）全绿；存量 `test:types` 72 错不涉及本次文件。
- 2026-10-15 复验（用户反馈首修**没解决问题**：工作台编辑后回工程页，谱面行音符仍是上次编辑后的；但 39 的「切目录后回工程页刷新」被顺带修掉了）：激活 effect 本身没错，错在它的 `flushPersist()` 打到**空注册柄**上。链路复现（xvfb + CDP 驱动真 Electron，谱面代码弹窗 Apply 后立即离开）：日志显示导航那一提交里 `workspace UNregistering persistFlush` → `projects activation effect fired` → `workspace registering persistFlush`——**cleanup 先于激活 effect，重新注册又晚于它**。根因 = React 一个 commit 内先跑完整个 cleanup 阶段再跑 setup 阶段，且 setup 按树序（`PAGE_REGISTRY` 里 projects 在 workspace **之前**）；而 `WorkspacePage` 每次渲染都产生新 `persistNow` 闭包（`useChartProjectPersistence` 返回值每渲染新建），注册 effect `[persistNow, registerPersistFlush]` 随之每次重渲染都 cleanup（`registerPersistFlush(null)`）→ setup。于是防抖窗口内离开时 flush 是 no-op，reload 读到编辑前的旧记录。预览/音频页同套 flush 没踩到，只因它们树序排在工作台**之后**、setup 时注册已恢复（这解释了 2026-10-05 预览页修法为何当时有效）。
- 二修（根因侧，两层）：① `useChartProjectPersistence` 的 `saveNow` 提为稳定 `useCallback`、返回值经 `useMemo` 求稳——句柄 churn 是注册竞态的根因；② `WorkspacePage` 注册改 ref 包装 + 依赖只剩 `[registerPersistFlush]`（挂载一次，与 `registerRestoreWaiter` 的稳定注册同范式）——注册侧确定性契约，不依赖上游句柄稳定性。
- 锁测补强：DOM 增第三条「生产接线」（`tests/dom/pages/ProjectsActiveReload.test.tsx`）——假工作台树序排在工程页之后、随 active 翻转重渲染、照生产旧接线注册，内部用**真** persistence hook；防抖窗口内离开也必须即时更新。静态增四条（WorkspacePage 注册形状 + hook 稳定句柄）。破坏验证：撤 ① → DOM 第三条红；撤 ② → 静态两条红。
- 复验验收：Electron 真机（xvfb + CDP，谱面代码 Apply 编辑）四轮——防抖已落地 ×3 + 防抖窗口内立即离开 ×1，全部即时更新（修复前第四轮读旧值 7/期望 9）；`tsc -b` 净；全量 3308 条（284 文件）全绿；eslint 净。
