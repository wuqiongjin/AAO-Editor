# 38 · 回工程页时列表不重读

Type: bug
Status: resolved
Blocked by: —

## 来源

issue 36 验收现场（用户 2026-10-15）：工作台编辑谱面后回到工程管理页，卡片 / 详情谱面行的音符数还是上次编辑后的数量，不是本次编辑后的。

## 症状与根因

工程页保活挂载（PageSlot 只切可见性、不卸载），列表只在 catalogEpoch 变化时 reload；工作台的音符编辑走 800ms 防抖落盘、防抖那笔落地**不通知目录**，切页也不 flush / 不重读。唯一会把工作台编辑刷进工程页的是 `setCurrent → notifyCatalogChanged()`——发生在**点进工作台那一刻**，于是回来看见的是上次的快照，下次再进工作台才刷出来，正好晚一次导航。预览页踩过同一坑（2026-10-05 验收：重置谱面后切预览仍见旧音符）并已在 `usePreviewScope` 修掉：激活时重读 + 读前先 `flushPersist`；工程页只在**写前** flush，缺「激活时重读」这一条。

## 修法

照 `usePreviewScope` 范式：ProjectsPage 收 `active` prop，加激活 effect（`false→true` 时先 `flushPersist()` 再 `reload()`）。hub 卡片与详情谱面行的音符数同源（都出自 `projects` state），一处修两边好。

## 锁测

1. `tests/dom/pages/`：active 切换锁行为——disk 换上工作台刚落盘的记录（音符数变了），激活工程页后文案即时更新；不激活不更新。
2. 静态断言（照 35/36 惯例）：激活 effect 内先 `flushPersist` 再 `reload`——顺序锁死，防只重读不 flush、读到防抖窗口前的旧记录。

## Comments

- 2026-10-15 实现（resolved）：`ProjectsPage` 收壳层 `active` prop（PageSlot 早在传，页面此前不接），加激活 effect——`false→true` 边沿（`wasActiveRef` 守卫，照 `usePreviewScope` / `useAudioScope` 同形）时先 `flushPersist()` 再 `reload()`。挂载时的那次读仍走原来的 `catalogEpoch` effect，不 flush（启动时工作台未挂，无在飞防抖笔）。hub 卡片与详情谱面行同出 `projects` state，一处修两边。
- 锁测：DOM 两条（`tests/dom/pages/ProjectsActiveReload.test.tsx`）——① 防抖笔在飞（flush 回调模拟 `persistNow`，只在 flush 时写盘、不通知目录）：激活后音符数 2→3 即时更新；② 盘上记录已换（不通知目录）：不激活纹丝不动、激活即重读 2→5。静态五条（`tests/static/ProjectsActiveReload.test.ts`）：active prop 形态、effect 形状一段正则、`flushPersist` 严格先于 `reload`、依赖 `[active, flushPersist, reload]`、`catalogEpoch` 那条不受影响。撤修复 / 换序 / 删 flush 三种破坏均验过红。
