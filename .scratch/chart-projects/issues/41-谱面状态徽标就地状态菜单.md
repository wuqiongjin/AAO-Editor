# 41 · 谱面状态徽标就地状态菜单

Type: grilling
Status: resolved（2026-10-18 实现落地；真机验收待补）
Blocked by: —

## 来源

用户 2026-10-18 提问：「标为完成」这个按钮，真的有必要单独存在吗？（使用频率可能不高吧？）更好的做法是不是将标识状态的组件，直接变成可以操作状态的？还是有其他更好的方案？

## 症状 / 现状

- 工程详情页谱面行（`ProjectDetail.tsx`）：`DiffLevelBadge`（可点）/ 标题 / `StatusBadge`（只读）/ 动作组 **7 个**（打开 / 预览 / 发布 / 标为完成 / 编辑 / 复制 / 删除）。
- 状态展示与状态操作被拆成两个组件：徽标负责「是什么」，文字按钮负责「改成什么」，用户读了徽标还要去找按钮。
- 「标为完成」是行内唯一的文字按钮（约 84px，全组最宽），使用频率却是每张谱面一辈子一次（完工时声明一下），却与「打开 / 预览」这类每次都用动作并排。
- 工作台切换器下拉另有「当前谱面标为完成」菜单项（票 06 定的两处入口之一）。

## 根因

票 06 需求（"完成标记：工作台与工程管理页都能手动标 / 撤"）的直接落地形态：**低频声明性动作以高成本形态（独立文字按钮）占高频位，且状态展示与状态操作物理分离**。同行本就存在「徽标即控件」的既有范式（`DiffLevelBadge`，issue 19 #2）——本不需要新交互模式，只是没有把状态操作归位到状态本身。

## 定案（用户 2026-10-18，三轮 grill 拍板）

1. **详情页撤掉独立「标为完成」文字按钮；`StatusBadge` 点开垂直小菜单就地切状态**——复用 `ProjectBits` 现成的 `Menu` + `ProjectMenuItem`（portal + scrim + 垂直列表，当前态打 ✓），与卡片 ⋯ 菜单、切换器下拉同一套视觉语言。
2. **菜单只列「未完成 / 已完成」两项**，不列派生的「已上传」（上传记录由发布链路写入、用户选不了，列进选项是对模型的谎言；徽标本身已会显示它）。触发键 `title` 新增 `projects.statusEdit`「点击改状态」，照 `projects.diffLevelEdit`（"点击改难度 / 等级"）口径。
3. **已上传徽标 inert**：不加 pointer 手型、不挂 handler，视觉上就不可点。浮层对上传态天然不成立（无可选项），不弹 toast——toast 是给「长得像按钮其实不能点」兜底的，素色徽标不假装能点。
4. **其余徽标一律只读**：`StatusBadge` 组件加 `interactive` 参数默认 `false`，仅详情页谱面行传 `true`；hub hero 谱面快捷钮（`ProjectHub.tsx:199`）、切换器下拉行（`ChartSwitcher.tsx:144`）、预览页切换器行（`PreviewChartSwitcher.tsx:161`）都是行内徽标、不挂交互（前者还嵌在「打开谱面」的 `<button>` 里，点按语义冲突且 button 嵌 button 不合法）。
5. **工作台切换器菜单项「当前谱面标为完成」删除**——全局唯一入口收敛到详情页徽标菜单。这是对票 06「两处都能标 / 撤」的**显式覆盖**：标完成是每张谱面一次的声明性动作，不该占干活现场的常用菜单位；且完成态的展示语境在详情页（徽标 + 左栏完成比例 `doneRatio` + 进度条），控件放在状态被观看的地方。工作台保留**看**状态（下拉行徽标），不再提供**改**状态。
6. **切换不加确认**（可逆操作、无副作用，对齐 issue 16 定的「不可逆=实底红确认，可逆=点到为止」）。

## 实现落点

- `src/pages/projects/components/ProjectBits.tsx`：`StatusBadge` 加 `interactive?: boolean`；为 true 时渲染为 `<button>` 作 `Menu` 触发器，面板内两条 `ProjectMenuItem`（未完成 / 已完成，当前态 ✓），选中调 `toggleChartCompleted`（经消费方既有 mutate 通道）。
- `src/pages/projects/components/ProjectDetail.tsx`：删行尾文字按钮整块（现 204–211 行，含 `disabled={up}`）；`StatusBadge` 传 `interactive` 与 mutate。
- `src/pages/workspace/ChartSwitcher.tsx`：删「当前谱面标为完成」`ProjectMenuItem`（现 151–156 行）；清理随之无消费者的 import（`Check`、`toggleChartCompleted`）。
- i18n：新增 `projects.statusEdit`（zh-CN / en 双语）；删 `projects.markComplete` / `projects.unmarkComplete` / `workspace.switcher.markComplete` / `workspace.switcher.unmarkComplete` 四组 key。
- CSS：`.pp-badge` 作触发器时的手型 / hover / focus-visible 新规则（现有 `.pp-badge` 是纯展示样式）。

## 锁测

- **DOM**（新增 `tests/dom/pages/ChartStatusBadgeMenu.test.tsx`，4 条）：徽标点击出垂直菜单；选中「已完成」提交 toggle 且徽标 / 左栏完成比例（1/2↔2/2，上传态计入完成数）即时跟变；选回「未完成」可逆；**已上传谱面徽标 inert**（连按钮都不是，点了不出菜单、记录不变）；点当前态 no-op 只收菜单；每行状态图标（`pp-st--unfinished` ○ / `pp-st--completed` ✓）+ 当前态 is-active 标活，不列「已上传」。
- **静态装配**（新增 `tests/static/ChartStatusEntryWiring.test.ts`，照 `ReadonlyGateWiring` 惯例，5 条）：详情页谱面行无独立「标为完成」文字按钮；`StatusBadge` 默认只读、仅详情页传 interactive（hub / 切换器 / 预览页三处源码零 `interactive`）；切换器下拉无标完成菜单项、不引用 `toggleChartCompleted`；四组 i18n key 全清 + `statusEdit` 双语俱全——防回潮总闸。
- **单测**（`unit/project/projectCatalog.test.ts` 新增 3 条）：`toggleChartCompleted` 的 `!c.upload` 守卫**原本 0 覆盖**（本票原记「已有覆盖面，确认即可」系误判，实现时核查 grep 为 0 命中后补齐）——已上传谱面原样返回（completed / lastModified / upload 不动）、正常路径三态切换、同工程其它谱面不受影响。
