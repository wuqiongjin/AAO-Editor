# 20 · 当前工程跨刷新存活

Type: grilling
Status: resolved

**来源**：用户 2026-09-28 #7——刷新页面后工程启动台「当前」角标消失，必须进一次工作台才回来；「这是合理的吗？」

## 症状

刷新后启动台没有任何卡片带「当前」角标；进一次工作台（或音频页）后角标才出现。

## 根因

`CurrentProjectSession` 的 projectId / chartId 只活在内存（`CurrentProjectSession.ts:29-30`）；只有进工作台 / 音频页才 `ensure()`（`AppShell.tsx:45-48`）。刷新 = 新会话 → projectId 为 null → 无角标。按 ADR-0015 §3 的现行字面口径这算"预期行为"，但与用户直觉冲突。

## 定案（用户 2026-09-28，Q6=B）

当前工程**跨刷新存活**：

1. `{ projectId, chartId }` 落盘到本机独立存储（不进设置对象、不随配置导入 / 导出走）；
2. 启动即恢复 → 角标立即可见；进工作台**直接回到它**（即使已完成 / 只读，不再套用"最近未完成"）；
3. 指针指向的工程不存在时清指针，回落既有规则（最近未完成 → 新建未命名）；
4. 删除当前工程（`reset()`）→ 清指针。

**连带修订**（本票落地时一并改）：ADR-0015 §3 补一句优先级——「有记住的当前工程时优先恢复它；只有没有可恢复项时才走最近未完成 / 新建」。

## 实现落点

- 新模块（`src/chart/project/currentProjectPointer.ts`）：load / save / clear，storage 可注入（测试用内存实现），损坏 JSON / 缺字段 / storage 异常一律静默回 null。
- `CurrentProjectSession`：构造时恢复；`open` / `ensure` / 新建成功 → save；恢复的工程已不存在 → clear 并回落；`reset()` → clear。
- Provider 初始 state 取自 session（`CurrentProjectProvider.tsx:51-52` 已是此形态）→ 启动台首帧即带角标。

## 锁测

`CurrentProjectSession.test.ts` 扩：
1. 有指针 → 首次 `ensure()` 直接返回该工程（不新建、不选"最近未完成"）；
2. 指针指向已删工程 → 清指针 + 回落既有规则；
3. `open` / `ensure` 成功后指针被写；
4. `reset()` 后指针被清。

指针模块单测：损坏 JSON / 缺字段 / storage 抛错全回 null；save 后 load 往返一致。
