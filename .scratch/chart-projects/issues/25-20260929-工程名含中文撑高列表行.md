# 25 · 工程名含中文把详情页列表行撑高 1px（行高跟着字体回落走）

Type: bug
Status: resolved

**来源**：用户 2026-09-29 报障（diagnosing-bugs）：「谱面工程的名字携不携带中文，会导致谱面列表（pc-chart）的高度发生变化」。

**症状**：同一窗口、同一字体档下，**工程名含中文时每行高 1px**，并顺着列表盒传给其后所有区块。headless 实测（1576×908，zh-CN + 出厂字体栈）：谱面行 56→57、列表盒 115→116、其后区块 top 371→372；左栏工程行（`.pc-item`）同为 57/58。头部恒 96px（封面钉死），不受影响。

**根因**：名字行无显式行高 → `line-height: normal` 的行盒高度取**这一行实际命中的字体**的度量：同一字体栈下拉丁命中 Geist（`--text-sm` 13px → 17px 行盒），中文回落 Microsoft YaHei（13px → 18px 行盒），同字号差 1px。名字行是行内最高项（标题列 36/37 > 封面 36），这 1px 就一路传下去。工程名能进谱面行，是因为谱面标题未填时**动态跟随工程名**（`effectiveTitle`）。

**修法**：口径 = **布局判据不许依赖文字内容**（与 issue 23 #4 同源，那边是宽度、这边是高度）。`.pc-chart__title b/small` + `.pc-item__text b/small` 由同一条规则钉 `line-height: 1.3`：unitless 随 `--ui-type-scale` 缩放（写 px 会在字号档被钉死），1.3 = 出厂拉丁字体的自然行高比 —— 纯拉丁名观感不变，中文名不再撑高。

**锁测**：
- `tests/static/ProjectDetailHeadLayout.test.ts` 新增 `issue 25` 两条：①四条名字行同由一条规则钉显式行高；②任一声明不许退回 `line-height: normal`。**已验证可捕获回潮**（把 `1.3` 改回 `normal` → 两条变红，恢复即绿）。
- 几何（jsdom 无布局引擎，测不了）：`shots/measure-detail-row-height.mjs`（临时脚本，`shots/` 不入库）—— headless Edge + CDP 灌 3 个工程（纯 ASCII / 纯中文 / 混合）量行高。**修复前** 谱面行 56/57/57、左栏 57/58/58；**修复后** 逐项同值（54.48 ×3、左栏 56 ×3）。
