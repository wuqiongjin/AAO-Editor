# 44 · 多工程启动慢与工程启动台滚动掉帧

Type: chore
Status: resolved

## 来源与症状

用户 2026-11-22 反馈：

1. 当本地项目工程数量较多时，打开软件（启动加载工程列表）速度明显变慢；
2. 工程刚加载出来后，停留在工程管理页主页面（工程启动台 `ProjectHub`）时掉帧严重、非常卡，尤其是滚动封面墙的时候；
3. 过一小段时间（或滚过一遍后）流畅度会明显好转。

## 根因分析

### A. 启动读目录慢（随工程数 N 线性恶化）

1. **`project:list` 串行读盘 + 读取全量谱面正文**：[projectStore.cjs](../../../electron/storage/projectStore.cjs) 的 `listProjects` 用 `for...of` 逐个工程串行读取 `project.json` 与 `cover.bin`（`2N` 次串行磁盘 IO），并完整 `JSON.parse` 全部谱面的 `notes[]` 与 `appliedChartCodeText`。而工程启动台与详情页列表根本不消费 `notes` 正文（详情页仅需单张谱面的 `noteCount` 整数）。
2. **全量嵌套对象 + 原图字节经 `contextBridge` 同步深拷贝**：issue 232 仅将 `project:put` 改为 JSON 文本跨桥，`project:list` 仍跨 IPC 返回庞大的嵌套 JS 对象数组与原始 `cover.bin` `Buffer`，经 `contextBridge` 同步克隆进渲染主世界阻塞渲染主线程；随后 [ChartProjectRecord.ts](../../../src/project/ChartProjectRecord.ts) 的 `blobFromBytes` 又对每张封面额外拷贝一次 `Uint8Array` 再包成 `Blob`。
3. **工程封面无缩略图，直接传原图**：社区/官方选曲弹窗已走 `aao-asset://thumb/` 提供 96×96 缩略图，但本地工程封面每次 `list()` 都搬运原分辨率 `cover.bin`。

### B. 刚加载出首页掉帧/滚动极卡、过一会好转

1. **全量卡片一次挂载 + 原图走 CSS `background-image` 无法懒加载**：
   - [ProjectHub.tsx](../../../src/pages/projects/components/ProjectHub.tsx) 一次性渲染全部 N 张 `.pb-card`，无 `content-visibility: auto`（对比选曲行 `.off-row` 已有）也无虚拟列表。
   - [ProjectBits.tsx](../../../src/pages/projects/components/ProjectBits.tsx) 的 `Cover` 使用 `<div style={{ backgroundImage: 'url(blob:...)' }}>`，无法使用浏览器原生的 `loading="lazy"` 与 `decoding="async"`，首屏挂载与首次滚动会触发大量原分辨率封面的冷解码、缩放重采样与 GPU 纹理上传；待解码进入 Chromium `ImageDecodeCache` 后滚动即明显变顺。
2. **启动瞬间后台保活页同时抢占 CPU / 磁盘 / IPC**：
   - `AppShell` 保活挂载全部 7 页，`CurrentProjectSession` 构造时同步恢复上次 `projectId`，导致用户尚停在工程管理页时：
     - 隐藏的 `WorkspacePage` 立刻执行 `store.get(projectId)`（读整份 `audio.bin` + 谱面）→ `AudioEngine.load` 全曲 `decodeAudioData` + `touchAudioBuffer`（issue 238 实测单曲约 1.15–1.62s，含主线程收尾长任务）+ 键音包预解码 + 画布初始化；
     - 隐藏的 `ChartSwitcher` 再次调用 `store.get(projectId)`（第 2 次读整份 `audio.bin` 过 IPC）；
     - 隐藏的 `AudioPage`（[useAudioScope.ts](../../../src/audio/useAudioScope.ts) 未判断 `active`）启动时立刻调用 `store.list()` + `store.get(projectId)`（第 3 次读整份 `audio.bin`，且可能触发第 2 轮全量 `project:list`）。
   - 这些后台重活恰好叠在“首页刚出来准备滚动”的 1.5~3 秒窗口内，结束后卡顿明显缓解。

## 定案（用户 2026-11-22）

- **Q1（冷启动后台预热策略）= 选项 A**：冷启动停留在工程管理页时，工作台延迟到工程启动台首屏就绪后的短暂空闲窗口再后台预热上次工程与 BGM（启动与首页滚动零争抢，稍后进上次工程仍秒开）；若用户在预热开始前主动切进工作台，则立即启动恢复（由 `ws-preparing` 兜底）。
- **Q2（派生缓存存放位置）= 选项 A**：落在 `<数据根>/cache/` 下（与既有 `cache/community/` 并列新建 `cache/projects/`），不污染 `projects/<id>/` 既有三文件结构，全量可删可自愈重建。

## 最终方案

### 1. 存储与传输层：整体索引 `cache/projects/index.json` + 目录摘要接口 + 并发校验

1. **缓存目录结构（`<数据根>/cache/projects/`，与既有 `cache/community/` 隔离）**：
   ```text
   <数据根>/cache/
   ├── community/          # 既有：社区素材缓存（assetCache 管辖，清除素材缓存只清这里）
   └── projects/           # 新增：本地工程派生缓存（全量可删可重建，不改 projects/<id>/ 三文件结构）
       ├── index.json      # 单个整体索引文件：projectId → { projectMtimeMs, projectSize, coverMtimeMs, summary }
       └── thumbs/         # 扁平封面缩略图目录（仅渲染时经 aao-asset:// 按需读取）
           └── <id>.png    # 384×384 居中裁方缩略图
   ```
   - **为什么用单个 `index.json` 而不是每工程一个 `meta.json`**：启动读全部工程摘要只需 **1 次文件读取**（几十 KB）+ 受控并发 `stat(project.json)`（不打开、不读正文，NTFS 上百个工程仅数毫秒）；命中指纹直接复用缓存摘要，避免打开/读取 N 个小文件与 Windows Defender 逐文件扫描开销。
   - **真源与自愈**：`projects/<id>/{project.json, audio.bin, cover.bin}` 仍是唯一真相源。仅当某工程在 `index.json` 中缺失、或 `project.json` 的 `mtimeMs/size` 变化（含外部手动改动、首次升级、缓存被删）时，才按需解析该工程的 `project.json` 并刷新索引；已删除的工程条目与孤儿缩略图在扫描或 `deleteProject` 时清理。
   - **`noteCount` 口径严格互锁**：主进程计算 `noteCount` 必须与渲染侧 [NoteEditing.ts](../../../src/chart/editing/NoteEditing.ts) `countChartNotes`（issue 84 口径）逐条一致——排除 `BPM` / `System` / `Opaque`，`Slide` / `Long` 按非 `hidden` 结点数计（负 beat 非 hidden 仍计入），其余音符计 1；严禁简化成 `notes.length`。
   - **写入一致性**：`putProject` / `touchLastOpened` / `deleteProject` 经单写队列 + `writeFileAtomic` 同步更新 `index.json`；切换/搬家数据根时，`cache/projects/` 随数据根隔离，无跨根污染。
2. **新增目录摘要类型 `ProjectSummary`（与 `ChartSummary`）**：
   - 工程级：`id, name, artist, source, durationSeconds, lastOpened, audioName, coverName, coverPresent, coverVersion`（Electron 走封面协议 URL + `${coverMtimeMs}-${coverSize}` 版本戳；Web/IndexedDB 仍兼容 `coverBlob`）。
   - 谱面级：`id, title, diff, level, completed, upload, lastModified, noteCount`——**彻底剥离 `notes[]`、`appliedChartCodeText`、`publishDraft`、`tags`**。
   - 消费方盘点（全量无遗漏）：
     - `ProjectHub` / `ProjectDetail` / `NewProjectDialog` / `ChartInfoDialog` / `useAudioScope` / `usePreviewScope` / `SettingsPage` / `CurrentProjectSession.ensureOnce` 全部只消费 `ProjectSummary`；
     - **`EditInfoDialog`（[ProjectDialogs.tsx](../../../src/pages/projects/components/ProjectDialogs.tsx)）**：当前直读 `useCoverUrl(project.coverBlob)`，改为复用统一 `useProjectCoverUrl(project)`（Electron 优先走协议 URL、Web 降级走 `coverBlob`），确保编辑弹窗封面预览不回退；
     - **`usePublishEntry.open` & `PublishDialog`**：点击「发布/更新」时按 `projectId` 按需 `store.get(projectId)` 拿到完整 `ChartProject`（含 `notes` 与 `coverBlob`），因此 `PublishDialog` 内 `convertNotesToChartCode(chart.notes)` 与自定义曲目 `hasCover = !!project.coverBlob` 校验均完整保真，不因摘要化劣化。
3. **JSON 文本跨桥**：`project:list`（或 `project:listSummaries`）跨 IPC/contextBridge 返回单条 JSON 字符串（同 issue 232 `project:put` 思路），避免 `contextBridge` 同步深拷贝嵌套对象数组。

### 2. 封面缩略图与懒加载渲染（解决滚动掉帧核心）

1. **Electron 侧复用 `aao-asset://` 协议提供工程封面缩略图（零封面字节进 IPC）**：
   - 新增只读路由 `aao-asset://project-cover/?id=<projectId>&v=<mtimeMs>-<size>`（严格复用 `safeProjectId` 与 `currentDataRoot()` 校验，禁止路径穿越；版本参数同时带 `mtimeMs` 与 `size`，避免 Windows 快速连续覆盖同毫秒命中浏览器旧缓存）；
   - 主进程使用 `nativeImage` 将 `cover.bin` 居中裁方并缩放到 **384×384**（覆盖 172px 流式卡片 @2x 与 120px hero @3x，清晰度无损）缓存为 `<数据根>/cache/projects/thumbs/<id>.png`；在 `putProject` 替换/清除封面或 `deleteProject` 时**主动删除旧缩略图**；
   - **解码降级防回退**：若 `cover.bin` 是 `nativeImage.createFromBuffer` 无法解码但 Chromium `<img>` 能显示的图片格式（如部分特殊编码/格式），协议路由必须**回退返回原始 `cover.bin` 字节**，绝不静默返回 404 导致原本可见的封面消失；
   - `list` 响应不再携带 `cover.bin` 字节；Web / IndexedDB 环境保持现有 `coverBlob` + `useCoverUrl` 降级路径。
2. **`Cover` 组件改原生 `<img>` + 懒加载异步解码**：
   - [ProjectBits.tsx](../../../src/pages/projects/components/ProjectBits.tsx) 的 `Cover` 在有图时改为 `<img src={url} loading="lazy" decoding="async" draggable={false} />`（CSS `object-fit: cover; width: 100%; height: 100%`），配合占位背景色/渐变防加载闪烁；
   - Hero 首屏封面走 `loading="eager"`，网格墙卡片走 `loading="lazy"`。
3. **启动台网格渲染隔离与防裁切约束（自检修正）**：
   - **重要防回退**：不可直接对 `.pb-card` 裸加 `content-visibility: auto`——该属性隐含 `contain: paint`，会直接裁掉 `.pb-card.is-selected` 外伸 7px 的 `outline: 2px solid var(--accent); outline-offset: 5px` 与 `.pb-card:hover .pb-card__cover` 的 `transform: translateY(-2px)`！
   - 修正口径：① 将卡片拆为 `React.memo` 子组件隔离 `selectedId` 变化，避免方向键移动焦点时重渲全部 N 张卡片；卡片 `⋯` 菜单保持闭合态零多余子节点构造；② 若需对超长列表启用 `content-visibility: auto`，必须通过预留 ≥8px 溢出的外层包裹盒（`padding: 8px; margin: -8px`）确保选中描边与悬停抬升全部留在 paint 边界内，并通过 DOM/视觉核验无裁切。

### 3. 消除启动阶段后台保活页的并发争抢

1. **`useAudioScope`（`AudioPage`）补齐 `active` 门控**：与 `usePreviewScope` / `AssetsPage` 同口径——未激活时不发起 `store.list()` 和 `store.get(scopeId)`，首次激活或激活期间依赖变化时才加载。
2. **`ChartSwitcher` 不再调用整工程 `store.get(projectId)`**：改为只读轻元信息（或直接消费工作台已恢复的工程元信息），彻底消除隐藏态重复读取 `audio.bin`。
3. **冷启动后台工作台延迟预热（定案 Q1=A，含防竞态约束）**：
   - 仅在 `active === false`（启动停在非工作台页）时启用延迟预热；若挂载时 `active === true`（含直接挂载工作台的测试），**零延迟立即恢复**；
   - 延迟预热必须等「工程目录就绪 + 无近期滚动/交互（如 `requestIdleCallback` 且避开首页刚加载后的活跃滚动窗口）」，避免用户正在滚动首页时突然起跑 BGM `decodeAudioData`；
   - 延迟期间 `boundProjectIdRef` 保持 `null`、`restoreSettledRef` 保持 `false`：① 若用户在此期间于工程页删/改工程或于音频页换音频，`flushPersist()` 安全短路，绝不把空编辑态写回覆盖磁盘；② 若用户在此之前主动切进工作台（点击导航「工作台」或「直接进工作台」），立刻取消延迟开始恢复，且 `WorkspacePage` 首帧同步进入 `ws-preparing`，零旧画布/空白闪烁。

## 预期锁测与验证

1. **后端与协议单测**：`projectStore` `index.json` 单索引命中/自愈（缺失、损坏、外部篡改 `project.json` 自动回退重建、删工程清条目与缩略图）、主进程与渲染侧 `countChartNotes` 口径互锁单测、`aao-asset://project-cover/` 路径穿越拦截 / 缩略图生成 / 换图版本戳与删旧缩略图 / `nativeImage` 不可解码时回退原图；
2. **渲染与交互 DOM 锁测**：`Cover` 渲染 `<img loading="lazy" decoding="async">`、无图回退渐变、`EditInfoDialog` 与 `PublishDialog` 封面预览/校验不回退、选中态外框与悬停抬升不被裁切、`useAudioScope` 隐藏态不发 `store.list`/`store.get`、`PublishDialog` 按需 `store.get` 仍能完整导出 `chartCode`、冷启动工作台延迟预热及竞态守卫（提前切入立刻恢复、预热前删除/改工程不回写空数据）；
3. **Electron 真机性能对照**：构造 50–100 个含真实大谱面与高清封面的测试工程副本，对比优化前后：① 冷启动到工程列表就绪耗时；② 列表刚出后立即快速滚动的 LongTask 与 rAF 间隔分布。
