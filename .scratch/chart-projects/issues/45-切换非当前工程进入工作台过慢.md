# 45 · 切换非当前工程进入工作台过慢

Type: chore
Status: resolved

## 来源与症状

用户 2026-11-22 反馈：

- 在工程管理页主页面（工程启动台），点击**非当前工程**的「直接进工作台」按钮触发切换工程时，切换速度太慢，会先卡半天才进入新工程的谱面画布；
- 要求：**修复时绝不能影响既有画布性能**（并询问是否原本就是为了性能才这么慢）。

## 根因分析

### 1. 刻意为性能保留的部分（issue 238，不得退化）

- 在提交 `9258be7e`（[basic-editor 238](../../basic-editor/issues/238-首次滚动条拖动GPU贴图停顿修复.md)）中，为消除首次进入画布拖动滚动条时 BGM `decodeAudioData` 收尾占用渲染主线程 50–64ms 的卡顿：
  - [WorkspacePage.tsx](../../../src/pages/workspace/WorkspacePage.tsx) 的 `handleProjectRestore` 改为 `await audioReady`（等待完整 `decodeAudioData` + `touchAudioBuffer`）；
  - 工作台新增 `preparing` 遮罩（`ws-preparing`「正在准备谱面…」），在首次恢复或切换 `projectId` 期间隐藏 `.ws-shell` 并禁用交互。
- 因此，切到非当前工程时存在**真实 BGM 解码开销**（单曲约 0.5–1.6s），而点当前工程不重解码所以很快。

### 2. 把切换拖成“卡半天”的非预期放大器（4 处叠加）

1. **两套等待门控撞车（issue 26 × issue 238 冲突）**：
   - [ProjectsPage.tsx](../../../src/pages/projects/ProjectsPage.tsx) 的 `enterWorkspace` 仍保留着 issue 26 时期（当时 `onRestore` 不等音频解码，仅 ~10ms）写的 `await setCurrent(id, chartId); await waitForRestore(id, chartId); setActivePage('workspace');`。
   - issue 238 让 `handleProjectRestore` `await audioReady` 后，`notifySettle()` 被推迟到整曲解码结束，导致 `enterWorkspace` **先死卡在工程管理页最多 1500ms（`waitUntilSettled` 超时兜底）且无任何反馈**，切到工作台后若解码仍未完又继续卡在 `ws-preparing` 遮罩。
2. **单次切换引发“多余写盘 + 最多 4 次读整份 `audio.bin` + 全量 `store.list()` 风暴”**：
   - `flushPersist()`（[useChartProjectPersistence.ts](../../../src/project/useChartProjectPersistence.ts) `saveNow`）不判脏，旧工程 A 未编辑也无条件整份序列化写盘；且 `open(B)` 的 `setProjectId(B)` 与随后的 `notifyCatalogChanged()` 若分两次 React commit，第 1 次 commit（`epochChanged = false`）会再 flush 一次 A、紧接着第 2 次 commit 又作废第 1 轮加载重来（顺带埋下同 `audioName` 时 `restoreAudio` 误判 `false` 的隐患）。
   - [CurrentProjectSession.ts](../../../src/project/CurrentProjectSession.ts) 的 `open(B)` 仅为改一个 `lastOpened` 时间戳，走了 `mutateProject`：**第 1 次 `store.get(B)`（把整份 `audio.bin` 和 `notes` 跨 IPC 读进来）→ `store.save(B)` 整份写回 → 丢弃已读对象**。
   - `notifyCatalogChanged()` 紧接着在切换最关键的瞬间引爆：
     - `ProjectsPage` 立刻执行全量 `store.list()`（工程多时串行读盘 + `contextBridge` 同步深拷贝把主进程与渲染主线程全部堵死）；
     - 隐藏的 `AudioPage`（`useAudioScope`）触发 `store.list()` + **第 2 次 `store.get(B)`（含 `audio.bin`）**；
     - `ChartSwitcher` 触发 **第 3 次 `store.get(B)`（含 `audio.bin`）**；
     - `useChartProjectPersistence` 触发 **第 4 次 `store.get(B)`（含 `audio.bin`）**。
   - 此外 `project:get` 仍以嵌套 JS 对象跨 `contextBridge` 传输 `doc`，且 `audio.bin` 历经主进程 `Buffer` → `blobFromBytes` `new Uint8Array` → `new Blob` → `new File` → `arrayBuffer()` 多轮拷贝。
3. **`<ChartCodeEditorProvider key={projectId ?? 'none'}>` 强制销毁重建整页工作台与 Canvas**：
   - [WorkspacePage.tsx](../../../src/pages/workspace/WorkspacePage.tsx) 把 `key={projectId ?? 'none'}` 挂在包裹整棵 `.ws-shell` / `FinalVirtualCanvas` / `WorkspaceTopBar` / `ChartSwitcher` / `PatternLibraryDrawer` 的外层 Provider 上；
   - 而 [ChartCodeEditorProvider.tsx](../../../src/chart/components/code-editor/ChartCodeEditorProvider.tsx) 在 issue 169 时早已实现 `useEffect([projectId])` 重置弹窗状态（不需要外层 `key` 破坏性 remount），只是旧静态测试 `workspaceProject.test.ts` 仍正则锁着 `key={projectId`。每次切工程因此白白销毁重建 `<canvas>`、`RenderTarget` 瓦片缓存、`ResizeObserver` 和顶栏（触发额外一次 `store.get(B)`）。

## 守住的既有性能与语义红线

1. **issue 238 首次滚动零停顿**：新工程首次可操作前，BGM `decodeAudioData` + `touchAudioBuffer` 仍必须结算完成，不得把 50–64ms 解码收尾放回首次滚动窗口；同工程切谱、普通切页保活仍 0 次重新解码、0 次出现准备遮罩。
2. **issue 26 零旧画布残留 / 零播错旧音频**：切换到新工程或新谱面时，绝不允许露出旧工程的音符画面或允许空格起播旧工程。
3. **ADR-0015 §3 / `WorkspaceEntrySingle`**：`setActivePage('workspace')` 仍全仓唯一落在 `enterWorkspace`，`setCurrent` 绝不跳页；切工程保留剪贴板、清空撤销栈与谱面代码弹窗。
4. **issue 38 回工程页数据新鲜**：从工作台切回工程管理页（`active: false → true`）仍保证先 `flushPersist` 再刷新目录。

## 定案（用户 2026-11-22）

- **Q1（音频解码缓存）= 选项 A**：不做多工程解码 `AudioBuffer` LRU，保持 ADR-0015 §3 单曲内存占用口径；通过消除冗余 IO/IPC/整页重挂载与减少 `ArrayBuffer` 多余拷贝，把切工程耗时压到纯单曲解码水平。
- **Q2（跨工程切页过渡交互）= OK**：点击非当前工程「直接进工作台」后，立即切到工作台并显示「正在准备谱面…」遮罩（`.ws-shell` 隐藏 + `inert`），BGM 解码结算后立刻亮出新画布；不破坏 issue 26（零旧画布残留）与 issue 238（首次滚动零停顿）。

## 最终方案

### 1. 消除切换路径的全部冗余 IO 与 IPC 风暴（最大降时项）

1. **`flushPersist` / `saveNow` 脏检查短路（自检防吞写修正）**：
   - 严禁只凭 `merger.hasPendingTimer()` 判脏——`AudioSession.importAudio` / `clearAudio` 会直接调用 `persistNow()`（不经防抖 `schedule()`）！
   - 正确判脏口径：`hasPendingTimer || hasProjectContentChanged(lastSavedRef.current, next)`，同时给 `hasProjectContentChanged` 补上 **`prev.audioBlob !== next.audioBlob`**（防止重导同名新音频被误判未变更）；真正落盘成功（或初始恢复完）后同步更新 `lastSavedRef.current`；确无改动时 `flushPersist()` 立即 `Promise.resolve()`，**0 序列化、0 IPC、0 写盘**。
   - `setCurrent` / `open` 将 `projectId`、`chartId` 与目录变更的提交合并为一次状态更新，彻底消除“两次 commit → 二次 flush 旧工程 + 作废首轮加载”；同时修正 `restoreAudio` 判定，使其不再受 `epochChanged` 干扰（只要 `projectChanged || audioMismatch` 即恢复音频）。
2. **轻量化 `touchLastOpened` + 单次读取复用（4 次 `store.get(B)` → 1 次）**：
   - Electron 后端新增轻量 `project:touchLastOpened(id, now)`（严格经过 `safeProjectId` + `isCurrentDoc` 旧 schema 闸门，仅更新 `project.json` 与 `cache/projects/index.json` 中的 `lastOpened` 及新文件指纹，**不读取 `audio.bin`/`cover.bin`**，也不跨 IPC 传输谱面正文；工程不存在返回 `false` 供 `CurrentProjectSession.open` 照常抛错）；
   - `ChartProjectStore.touchLastOpened` 必须同步推进内存里的 **`lastOpenedFloor.set(id, now)`**，防止后续任何防抖写回把 `lastOpened` 倒退；IndexedDB 侧同样走轻量更新；
   - `project:get` 改用 **JSON 文本跨桥**传 `doc`（同 issue 232 `project:put`），彻底消除 `contextBridge` 对整谱 `notes` 的同步深拷贝；同时减少 `audio.bin` 到 `decodeAudioData` 之间的多余 `Uint8Array`/`File` 拷贝。
   - 配合 [issue 44](./44-多工程启动慢与工程启动台滚动掉帧.md)：
     - 隐藏的 `AudioPage`（`useAudioScope`）未激活时不发 `store.list()` 与 `store.get(B)`；
     - `ChartSwitcher` 改为消费轻量工程元信息（不读 `audio.bin`）；
     - 一次切工程对磁盘与 IPC 的全量读取严格收敛为 **仅工作台恢复时的 1 次 `store.get(B)`**。
3. **非激活态不触发工程管理页目录重读**：
   - 当 `ProjectsPage` 已切走（`active === false`）或正在执行 `enterWorkspace` 离开本页时，不立即发起目录重读，仅记脏标记；等用户切回工程管理页（含从设置页切换数据根后切回）时由既有 `active: false → true` 流程刷新（同步更新 `ProjectsActiveReload.test.ts` 中对原无条件 `catalogEpoch` effect 的静态正则锁，保留 `flushPersist` 先于 `reload` 的核心次序锁）。

### 2. 拆除破坏性整页重挂载（保留 Canvas 与缓存壳，并显式清理瞬态编辑态）

- 移除 [WorkspacePage.tsx](../../../src/pages/workspace/WorkspacePage.tsx) 中 `<ChartCodeEditorProvider key={projectId ?? 'none'}>` 的 `key` 属性，直接使用其已实现的 `projectId={projectId}` 重置弹窗机制（`SurfaceSizeTracking.test.tsx` 已验证）；
- **自检防泄漏必做项**：此前依赖整页卸载自动归零的子组件瞬态状态，在拆除 `key` 后必须随 `projectId` 变化显式重置：
  - `FinalVirtualCanvas`：`slideBuffer`（滑条待连锚点）、`curveDraft`（曲线草稿）、`bpmEdit`（就地 BPM 输入框）、`expandedBpmGroupKey`（展开重合 BPM 组）、进行中手势 `GestureSession`、`lastBpmRef`（复位 120）；
  - `ChartSwitcher`：`openMenu`（下拉菜单）与 `chartInfo`（新增/编辑谱面弹窗）；
  - 保留 `<FinalVirtualCanvas>` DOM、GPU 上下文、`ResizeObserver`、工具轨、顶栏与片段库抽屉，只令旧谱面瓦片缓存自然失效重建。
- 同步更新 `tests/unit/project/workspaceProject.test.ts` 的历史正则断言为行为锁测（验证切工程时关闭谱面代码弹窗、清空上述瞬态编辑态且不卸载 Canvas）。

### 3. 解耦 `enterWorkspace` 切页与音频解码等待（消除 1500ms 双重卡顿）

- **切换非当前工程（`id !== currentProjectId`）**：
  - `enterWorkspace` 在完成轻量 `flushPersist`（脏才写）+ `open` 切换 `projectId` 后，**立即调用 `setActivePage('workspace')`**，不再在工程管理页上死等 `waitForRestore`（最高 1500ms）把 `ws-preparing` 遮罩藏在后台；
  - 进入工作台的第一帧，`WorkspacePage` 同步进入 `preparing = true`（`.ws-shell` `visibility: hidden` + `inert`，显示 `ws-preparing`「正在准备谱面…」），**零旧谱面残留（满足 issue 26）、零误播旧音频、点击即响应**；
  - 后台单次 `store.get(B)` + `decodeAudioData` + `touchAudioBuffer` 完成后立即解除遮罩进入画布（**完全保留 issue 238 的首次滚动零卡顿**）。
- **同工程切谱面（`id === currentProjectId && chartId !== currentChartId`）**：
  - 无需重新解码音频（`restoreAudio = false`），`waitForRestore` 仅等待毫秒级 `resetNotes` 结算后即切换，零遮罩闪烁、零旧谱面残留。
