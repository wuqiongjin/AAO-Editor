# 12 · 编辑工程信息的封面上传改版

Type: feature
Status: resolved
Blocked by: 08

**来源**：用户 2026-09-26 #4（未上传/已上传两张截图）；2026-09-27 Q4=A。

**症状**：`EditInfoDialog` 里的封面就是一枚原生 `<input type="file">`（浏览器默认「选择文件 | 未选择文件」控件）+ 一枚「清除封面」按钮 + 一段 hint 文案，与整页自绘风格割裂。

**根因**：`src/pages/ProjectsPage.tsx` L253-268 直接放原生 file input，没包成自绘上传区。

**定案（用户 2026-09-27 Q4=A）**：
- 未上传：一个**点击式虚线上传区**（图标 + 主文案 + 「拖到这里也可以」，拖拽作为可选增强）；
- 已上传：**方块缩略图预览**（object-fit: cover）+「更换」「清除」两个文字按钮替代现在的两行；
- **不做裁剪 / 不做比例校验**，显示保持 cover；文件类型仍限 `image/*`。

**修法**：把封面字段抽成 `src/ui/CoverField.tsx`（受控：`previewUrl | 'clear' | File`），`EditInfoDialog` 与未来其它地方复用；原生 input 藏进 `visually-hidden-input`（沿用音频页做法），由自绘区域代触发。patch 出参不变（`coverName` / `coverBlob` / `clearCover`），**不动 `updateProjectInfo`**。样式进 `src/ui/ui.css`，文案进 i18n。

**锁测**：
- `tests/dom/ui/CoverField.test.tsx`（依赖 08）：无图 → 上传区可见且有 accessible name；`fireEvent.change` 给 File → 预览图 + 更换/清除按钮出现；点清除 → 预览消失、`onChange` 回 clear 语义；已有关联封面时也渲染预览。
- `tests/static/EditInfoDialogNoRawInput.test.ts`：静态断言 `EditInfoDialog` 内不再直接出现未隐藏的 `<input type="file"` 字面。
- 视觉（虚线框尺寸、缩略图比例）走人工截图门票。
