# 29 · 工程管理页启动先闪 0 工程空态、再被真实列表替换

Type: bug
Status: resolved
Blocked by: —

**来源**：用户 2026-10-13 真机反馈 #1 —— 打开软件后，谱面工程页初始必定显示「从零开始」的空态，过一会才刷新出既有工程（肉眼可见刷新过程）。已与用户确认症状 = `projects.guide.*` 引导横幅 + `projects.empty.*` 空态（非幽灵未命名工程卡）。

**症状**：启动 → 工程页首帧渲染 0 工程空态（「从第一个工程开始」横幅 + 「还没有工程 / 从空白新建开始…」）→ `store.list()` resolve 后整页翻成真实卡片网格，中间无遮罩，错误帧可见。

**根因**：`ProjectsPage` 把「列表未就绪」与「真的没有工程」混用同一 state 值 `[]`，且**没有加载态**。`ProjectsPage.tsx:56` 初值 `[]` → `:80-87` 挂载 effect 异步 `store.list()` 后 `setProjects`；`ProjectHub.tsx:50` 只按 `list.length === 0` 判空，`:123` / `:191-201` 据此渲染引导横幅 + EmptyState；全页无 `isLoading` 之类状态量 ⇒ 首帧必落空态分支。等待之所以可见另有两个放大因素：(a) 列表在**页面挂载后**才拉（`PageRegistry.tsx:10` lazy chunk 先加载）；(b) `store.list()` 不轻 —— Electron 后端对每个工程目录**串行**读 `project.json` + `cover.bin`（`electron/projectStore.cjs:123-145`），工程越多 / 封面越大越慢，再叠 IPC 往返。

## 修法（本轮实现口径，待验收）

1. **必须**：区分「未就绪」与「空」——`projects` 改 `ChartProject[] | null`（`null` = 未就绪）；未就绪时不渲染空态，`isEmpty` 只在确认为空时成立。
2. **同票**：启动预载目录 —— Provider 层发起一次 `store.list()`，`ProjectsPage` 消费同一（进行中）Promise（去重），消掉「页面挂载后才发请求」的窗口。
3. **可选**（实测仍慢再开性能票）：`listProjects` 的封面读取并发化。

不追求「零闪烁 / 秒开」：那需本地缓存上次目录 + 首帧乐观渲染 + 与真实列表对账，属更大设计决策，不在本票范围。

## 锁测

1. `tests/dom/pages/ProjectsPageEmptyState.test.tsx`（既有，本票的行为守卫）：新增「列表 Promise 未 resolve 时**不渲染** `projects.empty.*` 与引导横幅、resolve 为空才渲染、resolve 有数据直接出网格」3 条。既有 2 条（`findBy*` 等待）应保持绿。
2. 需给 `tests/support/providers.tsx` 的 `makeMemoryProjectBackend` 补一个「`list()` 返回手动可控 deferred」的开关（照 issue 21 扩展该文件的惯例），否则测不到「未就绪」这一帧。
3. 预载去重：同一次启动只发一次 `store.list()`（假后端计数断言）。
4. 真机验收：冷启动进工程页，空态不出现，直接骨架 → 列表（jsdom 测不到首帧时序与真实 I/O 时长，故需人工）。

**验证**：`npx tsc -b` 0 错误；`npm test` 238 文件 / 2759 用例全绿；改动文件 eslint 无**新增**问题（`ChartProject.ts:187` 的 `_audio` 报错在 HEAD 上已存在，已用 `git show HEAD:... | eslint --stdin` 核对，不属本票）。

**已知限界（对应审查意见）**：

- 只做 in-flight 合并、**不留结果缓存**：快盘（预载已 settle 后才挂页面）下页面仍会重读一次全量 —— 预载收益在慢盘 / 页面挂载早于 settle 时兑现。要"零重读"须引入目录缓存 + 失效，属更大决策（本票明确不做）。
- 骨架占位是**新增视觉**：票面「修法」一节未写它（锁测 #4 写了"直接骨架 → 列表"），属本轮实现口径的一部分，待用户验收；不要骨架可只保留"未就绪不渲染空态"。
- 两处审查判为判断题、本轮**保留**：① 用 `null` 哨兵 + `ready` 布尔而非判别联合表达三态（离 React 惯例近、改动面小）；② 预载挂在 `CurrentProjectProvider`（它是唯一的 app 级 `store` 持有者，且 DOM 测试经 `TestProviders` 也覆盖得到它）。
