# 11 · 无封面工程的封面背景色丢失（浏览器 / IndexedDB）

Type: bug
Status: resolved
Blocked by: 08

**来源**：用户 2026-09-26 #3（截图：主页面与详情左侧列表无背景色，点进条目后又有）；2026-09-27 确认**运行环境 = 浏览器**（走 `IndexedDbProjectBackend`）。

**症状**：同为无封面工程，有的条目是一片空白（无占位色），选中/进入详情后又出现背景色；「Fire Bird（副本）」尤其明显。

**已查事实**：`Cover`（`src/pages/ProjectsPage.tsx` L94-114）无条件给 `linear-gradient(135deg, hsl(hue 70% 55%), hsl((hue+40)%360 65% 35%))`，色相由 `projectCoverHue(id)` 从工程 id 派生，**与选中态无关**——所以「选中就有色」不是分支差异，只可能是背景被**后续声明覆盖**或 `backgroundImage` 被设成无效值。

---

## 根因（2026-09-27 实测确认）

**`Cover` 把 `background` 简写与 `backgroundImage` 长手写在同一个 style 对象里，React 按对象键序逐个赋值，后写的空长手把简写刚设好的渐变整条抹掉。**

```jsx
background: url ? undefined : `linear-gradient(...)`,   // ① 先落地
backgroundImage: url ? `url(${url})` : undefined,       // ② 无 url 时 → '' → 抹掉 ①
```

React 19 的 `setValueForStyles`（`node_modules/react-dom/cjs/react-dom-client.development.js` L2745）在**挂载**时对 style 对象的每个键逐个 `node[key] = dangerousStyleValue(...)`，`undefined` 归一成 `''`。于是真实浏览器里的 DOM 操作是：

```js
el.style.background = 'linear-gradient(...)';  // background-image 变成这条渐变
el.style.backgroundImage = '';                 // 移除 background-image → 回退 none
```

**Chromium（headless Edge）实测**：

| 写法 | `getComputedStyle().backgroundImage` |
| --- | --- |
| 只写 `background = 渐变` | `linear-gradient(135deg, rgb(60,135,221), rgb(54,31,147))` |
| `background = 渐变` 后紧跟 `backgroundImage = ''` | **`none`** ← 本 bug |
| 只写 `backgroundImage = 渐变` | `linear-gradient(...)` ✅ |

因此**所有无 `coverBlob` 的工程一律没有占位色**（不是「有的」）。「选中/进入详情后又有背景色」是另一处视觉：`.pc-item.is-selected { background: var(--accent-soft) }` 给选中行铺了浅色底、`.pb-hero` 自身也有渐变横幅，看着像封面恢复了。

**三个原假设的裁决**：
1. ~~`coverBlob` 是空 Blob / url 被 revoke → `url('')` 压掉 gradient~~ —— **不是本 bug 主因**（`url` 为空时那条 `backgroundImage` 是 `undefined` 而非 `url('')`），但空 Blob 确实**没有渐变兜底**，作为加固一并修（见下）。
2. ~~`projectCoverHue` 得 NaN~~ —— **排除**。`h = (h * 33 + charCodeAt) >>> 0` 恒为 32 位无符号，`% 360` 必为 `0..359` 有限整数；实跑覆盖空串/非 ASCII/代理对/4KB 超长 id 均无异常。已补护栏测试锁住取值域。
3. ~~CSS 里 `.pb-cover` 某条规则 `background: none` 覆盖~~ —— **排除**。`.pp-cover`（`ProjectsPage.css` L15-26）只声明 `background-size` / `background-position`，不含 `background` / `background-image` 简写；inline 也无从被它覆盖。

**次要问题（同一次修掉）**：有 `coverBlob` 时首帧仍是「渐变 → 被抹掉 → effect 建好 objectURL 再设上」，多一次闪烁与多余的样式写入；空 Blob（0 字节）会建出一个只能画出破图的 objectURL，且完全没有渐变兜底。

## 修法（已落地）

`src/pages/ProjectsPage.tsx`：

1. `Cover` **只用 `backgroundImage` 长手**，永不混写 `background` 简写；无 url 时该长手直接就是渐变。
   ```jsx
   backgroundImage: url
     ? `url(${url})`
     : `linear-gradient(135deg, hsl(${hue} 70% 55%), hsl(${(hue + 40) % 360} 65% 35%))`,
   ```
2. `useCoverUrl` 把**空 Blob（`size === 0`）视为无封面**，返回 `null`、不建 objectURL → 回退占位渐变。

## 锁测

- ✅ `tests/dom/pages/ProjectCoverFallback.test.tsx`：无 `coverBlob` → `style.backgroundImage` 含 `linear-gradient` + 工程名首字母；有 `coverBlob` → 用该 Blob 的 objectURL；**空 Blob → 回退 gradient 且不建 objectURL**；另加一条「style 里不许再出现 `background` 简写」。
  - 判据口径：断言打在 **`backgroundImage` 长手**上，**不打 `style` 属性字符串**——jsdom 的 cssstyle 在「简写后跟空长手」时仍把渐变留在 cssText 里，断言属性串会得到**假绿**；长手在 jsdom 与真实浏览器两边一致（都变 `''`）。
  - 在改动前的代码上跑：**4/5 红**（「有 Blob」那条本来就工作，前后都绿）；改后 5/5 绿。
- ✅ `tests/unit/chart/project/ProjectCoverHue.test.ts`：对所有 id 返回 `0..359` 有限整数（NaN 护栏）。
- ✅ 视觉门票（截图）已过：用 headless Chromium 渲染与源码等价的 `.pp-cover`，上行「修复前」4 个封面全白且 `computed background-image: none`，下行「修复后」渐变正常。截图仅作诊断取证，**未入库、已清理**。
