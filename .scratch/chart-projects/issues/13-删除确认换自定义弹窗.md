# 13 · 删除/覆盖确认统一为自定义确认弹窗

Type: feature
Status: open
Blocked by: 08

**来源**：用户 2026-09-26 #5（「还是系统弹窗的样式？」）；2026-09-27 Q5 = B（同意推荐，并要求能复用尽量复用）。

**症状**：delete / overwrite 类确认仍是浏览器原生 `window.confirm`，与自绘 UI 风格不一致、无法自定义按钮文案与危险色、也不受主题/i18n 控制。

**根因**：无 Dialog 基建。`src/ui/` 现有 `EmptyState / IconButton / ActionBtn / CanvasSpriteIcon`；各家自绘的 `.pp-dialog__scrim`（`ProjectsPage.tsx` L232）仅靠 scrim 的 `onMouseDown` 关闭，无 Esc / 焦点 / aria；`ChartCodeEditorModal` 又一套。

**范围（用户 Q5=B）**：替换全部 **4 处 `window.confirm`** —— 删除谱面工程（`ProjectsPage.tsx:333`）、删除单张谱面（`ProjectsPage.tsx:554`）、覆盖导入谱面代码（`ChartCodeEditorModal.tsx:303`）、未保存改动关闭代码编辑器（`ChartCodeEditorModal.tsx:210`）。**`window.alert`（4 处报错提示）不动**（全局提示体系另开票）。

**修法**：新建 `src/ui/ConfirmDialog.tsx` —— scrim + 面板 + 标题/正文 + 取消 + **危险确认**按钮、Esc 关闭、点击遮罩关闭、打开时焦点落在确认键、`aria-modal` + `aria-labelledby`，样式进 `src/ui/ui.css`。`.pp-dialog` 收编到同一 Dialog 壳属行为等价重构 → 另开 chore，不混在本票。

**锁测**：
- `tests/dom/ui/ConfirmDialog.test.tsx`（依赖 08）：确认 → onConfirm 触发；取消 / Esc / 点遮罩 → onCancel 且**不**回调；`title` 与 `aria-labelledby`/`role="alertdialog"` 对得上；危险按钮默认聚焦。
- `tests/dom/pages/ProjectDeleteConfirm.test.tsx`：删除工程按钮 → 弹出自定义确认（非 `window.confirm`），确认后 `store.delete` 被调用。
- `tests/static/NoWindowConfirm.test.ts`：静态断言 `src/**` 内不再出现 `window.confirm`（历史ionis 例外清单写进票 Comments）——这是防止未来偷偷加回系统弹窗的总闸。
- Electron 主进程 / preload 不在范围内（本仑 electron 侧无 confirm）。
