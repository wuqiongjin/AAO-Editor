# 39 · 切换数据目录后工程管理页未即时刷新

Type: bug
Status: resolved
Blocked by: —

**来源**：用户 2026-10-14 反馈 #1 —— 设置中“谱面与素材”→“使用已有数据目录”（或“更改数据目录位置”）切换数据目录后，回到工程管理页面列表未更新，必须重新启动软件才能更新。

**症状**：在设置页通过 `claimDataRoot`（或 `changeDataRoot`）切换至包含不同谱面工程的数据目录后，切换回工程管理页（`ProjectsPage`），卡片网格仍展示切目录前的旧工程列表；仅当退出重开软件后才显示新目录下的工程。

**根因**：
1. **渲染进程无通知**：`SettingsPage.tsx` 的 `applyDataRootResult` 调用 Electron API 成功后，仅通过 `setDataRootPath(r.path)` 更新了本组件内显示的路径字符串，未通知 `CurrentProjectProvider`，也没有更新 `catalogEpoch`。
2. **保活挂载阻断组件重载**：`AppShell` 对五大页面采用 `display: none` / `opacity: 0` 的保活挂载（keep-alive）。`ProjectsPage` 切页时并不重新挂载，其拉取列表仅依赖 `useEffect(() => { void reload(); }, [reload, catalogEpoch])`。因 `catalogEpoch` 未变动，切回工程页时完全不会触发 `store.list()`。
3. **伴随隐患**：`CurrentProjectSession` 内存指针仍保留旧目录的 `projectId`，若该 ID 在新目录不存在，工作台状态会悬空；`backgroundSkinStore` 与 `cacheStats` 等也需与数据根联动刷新。

## 修法（本轮实现口径，待验收）

1. **通知目录变更**：`SettingsPage` 成功切换/认领数据根后，调用 `CurrentProjectProvider` 的通知机制（递增 `catalogEpoch`），促使 `ProjectsPage` 重新触发 `reload()` 读盘。
2. **会话校验与重置**：切换数据根时校验当前工程会话；若旧工程在新目录下不存在，调用 `reset()` 清理当前会话指针，防止残留游离 ID。
3. **单例缓存失效**：重新拉取背景皮肤（`backgroundSkinStore` 重新装载）及素材缓存统计（`cacheStats`）。

## 锁测

1. DOM 测试：模拟设置页执行 `claimDataRoot` 成功，断言 `CurrentProjectProvider` 触发重新列盘，`ProjectsPage` 展示新目录下的工程。
2. 异常隔离单测：当前工程在切换后的目录不存在时，当前指针安全回落（不抛异常、不白屏）。
