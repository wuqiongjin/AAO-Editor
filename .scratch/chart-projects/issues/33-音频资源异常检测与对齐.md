# 33 · 音频资源异常的检测与对齐（被替换 / 被删除）

Type: feature
Status: resolved
Blocked by: —

## 来源

用户 2026-10-14：「用户偷偷更换了音频怎么办？我们怎么处理？需要检测吗？」
追加 1（同日）：「偷偷换音频和点『更换音频』的处理要一致——原曲是官方歌曲，偷偷在本地磁盘上换掉对应资源，也应该自动变成『自定义曲目』。」
追加 2（同日）：「如果本地资源被删除了，我们也能检测得到吗？此时会变成什么情况？」→ 定案：并进本票，同族横幅 + 双动作。

## 症状与根因

工程记录与音频字节**零完整性绑定**：`project.json` 只有 `audioName`（纯展示名）、`durationSeconds`、`source`、`audioPresent`，无字节数 / 哈希 / 音频时长（字段表见 `ChartProjectRecord.ts:94`）；`electron/projectStore.cjs:96` 读取原样吞字节。两类外部异常今天的表现：

### A. 字节被替换（audio.bin 被换成另一份音频）

应用内换音频已完整处理（`projectAudio.ts:149`：重探时长 + `source→custom` + 上传锁定）；应用外替换的缺口：

1. **全程无提示**——应用 silently 呈现一个"看似有效"的工程，谱面与新歌脱节；
2. **`source` 不翻 custom**（用户追加点 1）——官方曲宣称失真，与「换音频即改归属」（06 Q12）口径双标；
3. **锁定工程记录时长永久陈旧**——`buildProject` 锁定时保留旧 `durationSeconds`；
4. 未锁定工程的时长其实会经「hydrate 自纠 → bridge 同步 → 防抖落盘」**静默自愈**，但用户无感知，且 ①② 照样发生。

### B. 字节被删除（audio.bin 被删，audioPresent 仍 true）

代码路径逐段推演：

1. 主进程 `readBinIfPresent`（`projectStore.cjs:43`）读失败 → `console.warn('…按无数据处理')` → 返回 null 字节；**doc 原地不动**（`audioName` 旧名、`audioPresent: true`）；
2. `projectFromRecord` → **半态记录**：`audioName != null` 且 `audioBlob == null`；
3. 工作台 `hydrateFromProject`（`AudioSession.ts:214`）→ 清引擎、audioName 置 null → **音频静默消失**，零提示；时长保留旧值；
4. 音频页 `hasAudio = audioName != null`（`projectAudio.ts:77`）→ **幽灵卡片**（旧文件名 +「已导入」+ 更换/清除按钮）；详情页头部音频行、编辑弹窗音频条同样显示幽灵；
5. 未锁定工程下一次防抖落盘 → `binaryIntent` 得 `'cleared'`（`ChartProject.ts:107`）→ 记录**静默自愈**为无音频（时长保留），但 **`source` 不翻 custom**；
6. **锁定工程永久不自愈**：`buildProject` 锁定时保留 `audioName` → 落出 `audioName + audioPresent:false` 的不一致记录，每次 get 重新制造半态；
7. 运行中删除不重启：内存 blob 照常播，下次加载才现形（与替换同边界）。

注：基本期（basic-editor 25）"缺失降级 + 下次保存自然修复"是刻意决定，但 `tests/platform/electron/ProjectStoreFs.test.ts` 没锁这条路径——自愈是无测试护航的静默行为。

## 定案（用户 2026-10-14）

- **检测 = 两个信号，都不上哈希**：
  - 替换：hydrate 解码后 `engine.duration` 与记录 `durationSeconds` 差 > **0.5s**（沿用 `useChartProjectPersistence` 现容差）。同时长替换 / 重编码检测不到——明确记录此缺口（将来要补，最便宜是记录字节数，不必上哈希）；
  - 丢失：**半态判定** `audioName != null && audioBlob == null`——加载即可判，零解码、零 IPC 改动，比替换信号更早。
- **对齐口径 = 与「更换音频」一致**：修复写把 `durationSeconds` 改为音频实际时长、`source` 置 `custom`（音频已不是官方那首，同 06 Q12 理由）。`audioName` 在替换场景保持旧名（外部替换拿不到新文件名；纯展示字段，横幅文案说明音频已变）——与 import 路径唯一的刻意分歧。
- **丢失场景 = 同族横幅 + 双动作**：「去音频页重新导入」/「清除音频记录」；清除走 `clearProjectAudio`（它本来就翻 `source→custom`），补上静默自愈路径不翻 source 的洞。
- 两类检测都落**工作台 hydrate 路径**（替换要等解码；丢失在加载记录上就能判）；工程管理页不解码、不检测；音频页的幽灵由本票的清除动作收敛。

## 修法

1. `projectAudio.ts`：
   - 纯函数 `audioDurationMismatch(recordSeconds, actualSeconds, tolerance = 0.5)`（替换信号）；
   - 纯函数 `audioBytesLost(project)`（丢失信号：`audioName != null && audioBlob == null`）；
   - 新写路径 `realignProjectAudio(deps, projectId, seconds)`（替换修复：时长 ← 入参、source ← custom、audioName 不动）；
   - 丢失的清除复用 `clearProjectAudio`，加 `force` 参（横幅传 true 绕过锁闸；音频页不传，UI 禁用不变）。
   - `realignProjectAudio` 与 `force` 清除**不走 `mutateWritable` 的锁闸**——修复是记录与字节对齐、不是换音频；已上传谱面发布物不可变且按 song id 引用，本地修复不影响社区（此为本次实现口径，待验收）。
2. 工作台（`WorkspacePage.tsx`）：`handleProjectRestore` 收记录进 ref；恢复时先判丢失（半态，挂在 `restoreAudio` 为真的恢复上——切谱面不重判），再在 `audioSnap.audioDuration` 解码完成后判替换。同一枚横幅组件（样式族照 `.audio-locked-banner`，不新造壳）按当前信号出文案与动作：
   - 丢失：「音频文件丢失（原文件：{{name}}）」+「去音频页重新导入」/「清除音频记录」；
   - 替换：「音频文件与工程记录不一致」+「按音频重新对齐（时长与曲目归属将更新）」/「暂不处理」；
   - 「暂不处理」仅本会话不再提示（不落盘）；动作成功即清横幅。重新导入 = 带作用域跳音频页（票 22 既有机制）。
3. i18n 两语言补横幅文案；官方曲场景补一句与音频页清除官方音频同口径的后果说明（转自定义、本地照常播）。
4. 静默自愈（未锁定工程的下次落盘）保留为兜底，但不再"静默"——横幅先于它出现。

## 锁测

1. 单测（扩 `tests/unit/audio/ProjectAudioScope.test.ts`）：
   - `audioDurationMismatch` 边界（0.4s 不触发 / 0.6s 触发 / 无音频不触发）；
   - `audioBytesLost` 三态（有字节不触发 / 无音频不触发 / 半态触发）；
   - `realignProjectAudio` 写入形状（时长变、source 变 custom、audioName 不变、**锁定工程也写得进**——与 `importProjectAudio` 的锁闸刻意相反）；
   - 半态工程 `clearProjectAudio(force)`：audioName 清、source 翻 custom、锁定工程也写得进。
2. DOM（`tests/dom/workspace/` 新增，照 `ChartSwitcherAudioEntry.test.tsx` 注入假 store/引擎）：丢失横幅出现 / 清除动作调写路径 / 重新导入跳音频页（带作用域）；替换横幅出现 / 对齐动作 / 暂不处理不再出现。
3. 平台层（`tests/platform/electron/ProjectStoreFs.test.ts` 补）：`audioPresent:true` 但 `audio.bin` 缺失 → `getProject` 返回 doc + null 字节（锁"降级不炸、doc 不动"——基本期唯一无测试护航的一条）。
4. 边界说明：`cover.bin` 同样零绑定，但无时长这类廉价信号，检测需哈希，本票不做（一类问题不混票）；本票不构成"第二个音频管理面"（管理 = 导入/清除/改时长三动作，修复 = 记录对齐），写路径仍收口 `projectAudio` 接缝——`AudioManagementSingleSurface.test.ts` 的 `AUDIO_WRITES` 清单若扩，把新函数名一起列进去防双写路径。

### 2026-10-27 复验记录（修完又出的误报：音频页换音频/清除音频）

**症状**：本会话里工作台先恢复过某工程，再从**音频页**给当前工程更换音频 → 工作台弹「音频文件与工程记录不一致」，记录时长与音频实际时长相符也弹（截图：相差约 2 秒）；清除音频则旧横幅赖着不走。刷新页面 / 切工程后复现不出来。

**根因**：检测记住的那份记录（`useAudioAnomaly.recordRef`）只在**恢复路径**（`noteRestoredProject` ← `handleProjectRestore`）刷新。音频页写当前工程音频走的是票 15 定案 8 那条路——写记录 → `notifyCatalogChanged` → `catalogEpoch` 递增 → 持久化 hook 判 `audioMismatch` → `onRecordAudioChanged`（`handleRecordAudioChanged`）→ `hydrateFromProject`——**不经过 `onRestore`**。于是新文件解码落地（`audioLoadGeneration +1`）时，替换信号拿的是**换音频之前那份记录**的时长去比新音频的实际时长：误报；清除音频时，记录记忆与横幅都停在旧记录上：横幅不撤。

**修法**（与定案「两类检测都落工作台 hydrate 路径」一致，检测面从"恢复路径"扩到"记录侧音频变更路径"）
- `useAudioAnomaly` 加 `noteRecordAudioChanged(project)`：刷新记录记忆 + 按新记录重判——半态照旧报丢失，一致即静默，真不一致交给落定后的替换信号。
- 加**落定代数基线** `notedGenRef`：记录记下后要有**新的**负载落定才判替换。没有它会在解码还没落地时先拿旧 buffer 的时长比一轮（一闪而过的误报）。
- 两条入口共用一个内部 `remember(project)`（记记录 + 记基线），避免两处同形逻辑。
- `WorkspacePage.handleRecordAudioChanged` 调该入口。

**锁测**（`tests/dom/workspace/WorkspaceAudioAnomaly.test.tsx` 8 例 → **12 例**，新增 4 例）
- 音频页更换音频：记录与解码一致 → 不出替换横幅，记录落为新时长 + source→custom；
- 音频页清除音频：不出横幅，且已有横幅即清；
- 记录侧交出半态记录 → 丢失横幅照出（补上记录侧路径此前不判丢失的洞）；
- 记录侧变更后记录仍与解码不符（外部换文件）→ 替换横幅照出（防修完把真异常也一起压掉）。

**验收数字**：全量 `vitest run` 333 文件 / 3664 测试通过；`eslint` 干净；`tsc -p tsconfig.test.json` 错误数与改动前基线一致（77，既有债务，不在本票改动面）。
