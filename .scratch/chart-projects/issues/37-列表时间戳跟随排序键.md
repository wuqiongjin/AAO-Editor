# 37 · 列表时间戳跟随排序键

Type: feature
Status: resolved
Blocked by: —

## 来源

issue 35 验收后（用户 2026-10-14）：hub 切「最近修改」排序，卡片副行的时间仍是 lastOpened——顺序按 max(charts.lastModified) 排、眼睛看到的是「上次打开」，二者对不上；用户报「非常奇怪、让人产生疑惑」，并提了三个方向（删「最近修改」/ 删「最近打开」/ 让时间跟着排序变）。

## 症状与根因

时间显示与排序键是两个独立口径：卡片副行 `relTime(p.lastOpened)`（`ProjectHub.tsx:266`）与 hero 标签（`:171`）写死 lastOpened，排序键却可以是 `lastModified`（`projectSort.ts:26-32` 派生）。非时间键（数量 / 名称）下错位不显眼——顺序本就不像时间序；唯「最近修改」下顺序像时间序、显示的时间却不是它，错位显形。

## 定案（用户 2026-10-14）

两个时间键都保留，**列表时间戳跟随排序键，且必须贴短标签**：

- `lastModified` 键 → 卡片 / hero / 详情左栏显示 `projectLastModified(p)`；`lastOpened`（默认）/ `chartCount` / `name` → 显示 `lastOpened`。
- 贴标签的原因：卡片时间是裸「N 分钟前」，不贴标签就静默换语义，用户会看到「2 分钟前才打开过，怎么显示 5 小时前」——把一个疑惑换成另一个疑惑。卡片副行加短标签（打开 / 修改）；hero 标签从写死「上次打开」改为跟随。
- 详情页左栏同样跟随：它没有排序控件，但顺序是全局排序键驱动的（`ProjectsPage.tsx:268-270`：导航顺序必须用展示序），不跟则错位在详情页复发；且标签是那里唯一能告诉用户「在看哪个时间」的口径。
- hero 默认选中锚不动（仍 = 最近打开，issue 19 #4）。
- 死键 `projects.header.description`（"按最近打开排序。…"）当前无任何组件渲染：删掉，或改成不写死排序口径的文案。

## 修法

1. `projectSort.ts` 加纯函数 `projectTimeAt(project, key)`：时间键返回该键时间，其余返回 `lastOpened`（模型保证工程恒有 ≥1 谱面，`projectLastModified` 不回落 0）。
2. `ProjectHub.tsx`：卡片副行 / hero 改读 `projectTimeAt(p, sort)`；hero 标签按 sort 切 `projects.lastOpened` / 新增 `projects.lastModified`。
3. `ProjectDetail.tsx`：左栏 `doneRatio` 行（:74）跟随；`sort` prop 由 `ProjectsPage` 传入（与 hub 同源 `settings.projects.sort`）。
4. i18n zh/en：`projects.lastModified`（「上次修改 {{time}}」）+ 短标签两键（打开 / 修改）。
5. 新增 `relTime` 调用点的 `now` 注入形态随 36 落地结果对齐（36 若先行，直接按 ticker 形态写）。

## 锁测

1. `tests/unit/project/projectSort.test.ts`：`projectTimeAt` 四键各自取哪个时间戳（撤分支应红）。
2. `tests/dom/pages/ProjectsPageSort.test.tsx`：seed「最近修改」→ 卡片显示修改时间且带「修改」标签；默认「最近打开」→ 带「打开」标签；hero 标签随排序切换。
3. 静态断言（照 35 惯例）：两视图的工程时间显示必经 `projectTimeAt`，防回溜写死 `p.lastOpened`。
