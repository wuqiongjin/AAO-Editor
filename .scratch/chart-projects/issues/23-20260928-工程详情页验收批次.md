## #1 创建工程后应落工程详情页，而不是直接进工作台（feature）

**Status**: open

**症状**：空白新建点「创建并打开」→ 直接跳进工作台（空谱面，歌曲/等级/封面都还没填），谱师"还在懵逼着"就被推进去作谱。

**根因**：`createBlank`（`ProjectsPage.tsx:463-479`）末尾 `await open(...)` + `setActivePage('workspace')` 两件事绑死；文案 `projects.createOpen`（"创建并打开"）把跳页写进了承诺。

**定案（用户 2026-09-28，Q2=a / Q9=a / Q11）**——创建 / 复制完成后统一口径：

1. **留在工程详情页**（不跳工作台）；
2. **新工程成为当前工程**（`setCurrent(newId)`）；
3. **详情视图切到新工程**（`setDetailId(newId)`，`goDetail` 之外直接改 state —— 走 `goDetail` 会置 `navDir='forward'` 播一次滑入，而"详情内换工程"本就不该重放动画，见票 19 #1 的锁测）；
4. 若新工程不在左栏视口内 → `scrollIntoView`（Q12）。

**修法**：

- `openWorkspace`（`ProjectsPage.tsx:435-440`）拆成两个：
  - `setCurrent(id, chartId?)`：`flushPersist` → `open` → `notifyCatalogChanged`（**不**跳页）；
  - `enterWorkspace(id, chartId?)`：`setCurrent` + `setActivePage('workspace')`。
  - 现有 5 个"要跳页"的入口（hub hero / 卡片播放 / 详情「在工作台打开」/ 谱面行「打开」/ 列表双击）**全部改走 `enterWorkspace`**；只有 `createBlank` / `copyProject` 末尾走 `setCurrent`。
- 文案 `projects.createOpen`（zh"创建并打开"）**改成"创建"**（en "Create"），因为不再"打开"工作台；`projects.newBlankDesc` / `projects.guide.description`（写着"创建后会直接进入工作台"）同步改。
- **锁测**：
  - DOM：空白新建 → 仍在工程管理页（`activePage === 'projects'`）、`detailId` == 新工程 id、当前工程 == 新工程；复制工程 → 同上（**现在还完全没切**，见 #3）。
  - DOM：现有 5 个跳页入口逐个断言 `activePage === 'workspace'`（防止拆分时漏改一个）。
  - **静态断言**（新 `tests/static/WorkspaceEntrySingle.test.ts`，照 `NoWindowConfirm.test.ts` 惯例）：`setActivePage('workspace')` 全仓**只出现在 `enterWorkspace` 一处** —— 这是本票最重要的一条，防止后人把 `setCurrent` 又和跳页绑回去。

## #2 详情页左栏可拖拽分栏 + 宽度记忆（feature）

**Status**: open

**症状**：详情页左栏写死 `300px`（`ProjectsPage.css:156` `grid-template-columns: 300px minmax(0,1fr)`），不可调、不记忆。

**定案（Q3=a / Q6=a / Q7=a / Q8=a）**：

- 分隔条 **6px、`cursor: col-resize`**、`hover`/拖动中高亮 `var(--accent)` —— 形状照工作台的 `.ws-panel__resizer`（`AppShell.css:2484-2510`）。
- 宽度 **`clamp(220, 300, 420)`**，默认 300（沿用现值），**双击复位**。
- 落 **`settings.layout.projectList.width`**（additive、不 bump schemaVersion，照 `uiLanguage` / `projects.sort` / `curve` 先例）。
- 右栏 `minmax(0, 1fr)` 等量变窄（Q8=a）——**前提是 #4 修好后头部不再对右栏宽度敏感**。
- **不抽公共抽象**：工作台那套绑在 `UIProvider`（Provider 级 state + Provider 里的全局 mousemove effect + 内联 CSS 变量），详情页是 CSS Grid；抽公共 hook 等于动工作台那条被 ADR-0003 收编的稳定路径。**另**：两者夹取范围本质不同（工作台左右对称 `min(160, 20vw)` / `50vw`；详情页是导航列表，上限不该是半屏）。**出现第三个可拖拽分栏时再开 `chore` 抽**。
- **锁测**：
  - `AppSettings`：新增 `layout.projectList.width` 的 default / merge 归一化（缺字段 → 300；`0` / 负数 / 字符串 → 300；合法值沿用）→ 单元测试。
  - DOM：拖动分隔条 → 宽度写入 `settings.layout.projectList.width`；双击 → 复位 300。
  - 静态：夹取上下限常量在 CSS 与 JS 两侧同源（避免 CSS `clamp` 与 JS 夹取分叉）。
  - 像素（jsdom 测不了）：拖动观感、末态宽度 → 人工门票 / headless Edge 实渲染。

## #3 复制工程后视图与当前工程都不切到副本（bug）

**Status**: open

**症状**：复制工程后，人还站在**老工程**的详情页，当前工程也还是老工程；副本只是静默出现在左栏（且因 `lastOpened=now` 排到列表首位，但眼前内容不变）。

**根因**：`copyProject`（`ProjectsPage.tsx:481-497`）末尾只有 `reload()`，**既没 `open()` 也没 `setDetailId()`**。对比 `createBlank` 有 `open()`（但也因此跳了工作台）。`reload` 里的 `setDetailId(id => 已存在 ? id : 最近打开)`（`:419`）只在**目标被删**时才纠正，新增副本不触发。

**修法**：按 #1 的统一口径 —— `setCurrent(copy.id)` + `setDetailId(copy.id)` + 必要时 `scrollIntoView`，留在详情页。

**锁测**：DOM：复制工程 → `detailId` == 副本 id、当前工程 == 副本、`activePage === 'projects'`、左栏出现副本且「当前」徽标在副本上。

## #4 详情页左栏 ↑↓ 键盘导航（feature）

**Status**: open

**症状**：详情页左栏 `<button>`（`ProjectsPage.tsx:629-645`）**零键盘处理** —— 只有 `onClick`（切视图）/ `onDoubleClick`（进工作台）。同一页面的 hub 网格却有完整方向键导航，从 hub 进详情**能力突然断裂**。

**定案（Q4=c / Q13）**：

- ↑↓（以及 ←→，列数传 1 退化为"到边界无动作"）移动**查看焦点**，走 `goDetail`（= 只切视图），**永不碰当前工程**。
- **Enter / 双击仍 = 进工作台**（`enterWorkspace`），保持不变。
- 复用纯函数 `moveGridSelection`（`projectGridSelection.ts`，`columns = 1`），**不抽 hook**（两个调用点不值得；出现第三个再说）。
- 守卫条件照抄 hub 那份（`ProjectsPage.tsx:840-871`）：① 仅 `activePage === 'projects'` 时响应；② 弹窗/菜单开着（`.dialog__scrim, .pp-menu__scrim`）不响应；③ 焦点在 INPUT/TEXTAREA/SELECT/contentEditable 放行；④ **到边界不吞键**（`next === current` 直接 `return`，放行原生滚页）。
- 切换后 `scrollIntoView({ block: 'nearest', behavior: 'smooth' })`（Q13，照 hub `:874-879`）。
- **两份 keydown 不得同时响应**：hub 那份只在 hub 视图渲染时挂载，详情那份只在详情视图挂载（条件渲染天然做到），实现时把"哪个视图"作为分流条件并写锁测。
- **锁测**：DOM：详情页按 ↓ → `detailId` 变、当前工程**不变**；到末项按 ↓ 仍停原地；进详情后按 ↓ **不**移动 hub 的 `selectedId`（两视图互斥）；弹窗开着按 ↓ 不动；输入框（等级框等）里按 ↓ 不动。

## 被否决方案（记录理由，防回潮）

- **抽公共「可拖拽面板宽」hook，工作台与详情页共用**（Q3 候选 b）：见 #2 定案段的两条理由（绑 `UIProvider` / 夹取范围本质不同）。
- **宽度落 `settings.projects.listWidth`**（Q6 候选 b）：`projects` 段在票 19 刚被定成"工程页的**数据视图**偏好"（`sort`），纯视觉宽度塞进去会让它变杂物间。
- **宽度落 `userData/app-state.json`**（Q6 候选 c）：会与工作台面板宽度**分家**（后者随配置导入导出一带走），同一个"拖过面板"的概念两套命运。
- **`settings.layout` 借这次改成按"面板"而非"左/右"形状**：全站重构（工作台热路径 + ADR-0003 §6），收益不匹配本票，不做。
- **↑↓ 直接改「当前工程」**（Q4 候选 b）：属 `当前工程` 的交互模型问题，**归票 24**（见下），不在键盘导航里顺手加。
- **A2 变体（窄窗口把音频/时长/来源摆成右侧信息列）**：利用右侧空间更彻底，但会把"信息位置随宽度变"这条引入进来，与用户报障 #4 的诉求方向相反；且本仓零 `@container` 使用，要单独决策基建。取 A。
- **B 变体（按钮组永远独立一行）**：位置最稳，但多占一行且把主行动"在工作台打开"推离标题。取 A。
- **Q10 候选 b（创建/复制后给 toast 说明"已设为当前工程"）**：一条 toast 解释一个尚未定清的机制，只会把困惑提前；「当前」语义归票 24。

## Q5 定案细节（头部布局，A 变体）

**根因**：`.pc-detail__head { flex-wrap: wrap }` + `.pc-detail__actions { margin-left: auto }`（`ProjectsPage.css:168/171`）—— `margin-left:auto` 让按钮组的锚点从"标题块"漂成"整行最右"，于是同一组按钮在宽/窄窗口下有两个完全不同的位置。窄窗口更糟：按钮组与文字**抢同一行**，文字列被压到 ~90px（标题断两行、「设置音频」竖排成单字），而折行后按钮独占一行、右半屏空着。

**修法（A 变体）**：

- `.pc-detail__actions` 去掉"飘"的根源：宽窗口下由 `.pc-detail__head__body { flex: 1 1 340px }` 把它顶到**标题块右缘**；
- 给按钮组 `min-width`（约 430px，随按钮文案派生）—— flex 项不会缩到 min-width 以下，故窄窗口下**整组折行**，文字列因此拿到整行宽度；
- 折行后 `margin-left: auto` **右对齐**，把那一行的右半空间用上；
- `.pc-audio-jump { white-space: nowrap }`（它是不可断行的 pill，竖排是纯 bug）。

**锁测**：jsdom 测不了折行 → DOM 锁 class 接线 + **静态断言**（`min-width` / `nowrap` 在位、`margin-left:auto` 仍在但被 `min-width` 约束住）；观感与折行阈值走**原型**（`?prototype=project-detail-head`，变体 A 窄/默认/宽三列并排）+ 人工门票。

**原型**：`src/prototypes/ProjectDetailHeadPrototype.tsx` / `.css` + `App.tsx` 的 `?prototype=project-detail-head` 门。变体 A（定案）/ A2 / B / C（现状对照），三列窗宽并排缩放，带"按钮组定位辅助框"开关。**定案落地后原型代码删除**（照 `PageShellPrototype` 先例）；截图属临时文件、仅本地留存不入库。
