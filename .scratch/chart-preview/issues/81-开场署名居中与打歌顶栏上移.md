# 81 · 开场署名居中与打歌顶栏上移

Type: grilling
Status: resolved（2026-11-22：署名 / HUD / 装饰 C 三项均落地并锁测；随附的顶栏离屏合成白线回修见 Comments）
Blocked by: —

## 来源

用户针对动态预览提三点：① 开场曲目信息希望居中而非左对齐；② 开头星星 / 音符装饰中间没连上、间隔不规整；③ 打歌界面的分数条 / 生命条 / AUTO LIVE 距离上边缘再短一点，用户本地已把整组 Y 减 8。

## 症状

1. 开场 4 行署名（作词 / 作曲 / 编曲 / 谱师）首字对齐成一块、整块居中，视觉重心偏右（截图红框中心偏右）。
2. 装饰链中段两对与左右簇间隔不规整，看起来「没连上」；此前误做的「装饰压到白条上」改错了层级。
3. 打歌顶栏（分数 / 生命 / 暂停 / AUTO LIVE / `+增量`）距上边缘偏大，用户本地已把整组 Y 减 8。

## 根因

1. 票 39 定的是方案 B（首字对齐块居中），各行共用同一 `blockLeft` 起笔 ⇒ 行长不同则墨迹中心不齐。
2. 票 30 实测表的中段两对 x/y 是实测值，与左右簇不等距；不是漏画配对星，而是间距口径问题。
3. `SIM_HUD` 五项 Y 原为 38/38/38/150/119，与用户实机 JSON 差 8；实时预览与导出共用同一常量，必须一起改、不拆配置。

## 定案（用户 2026-11-22 逐项确认）

1. **署名块**：4 行署名（作词 / 作曲 / 编曲 / 谱师）改**逐行墨迹居中**，推翻票 39 方案 B（首字对齐块居中）；歌名 / 艺人保持现状（本来就是墨迹居中）。
2. **装饰链**：先看 A/B/C 三版预览再定，暂不落默认。
   - A = 只调匀间距，保留票 30 的「中段两对沉在白条后」；
   - B = x/y 全线性均分，**不改绘制层级**；用户反馈右侧显稀（右簇 y 被抬进白条更深 + x 间距变大）。上一轮误做的「装饰压到白条上」方案已作废。
   - C = 左右两簇 x/y 完全保留现状，只把中间两对在 `x=0.2806 → 0.714` 间插值；右簇密度回到原样。用户认可 C 的效果（实现口径见下节）。
   - 预览走**既有** `public/proto/scenes.html`（不另开原型页）：
     - 拍板时的 A / B / C：`/proto/scenes.html?scene=opening&t=2.2`（A）/ `?decor=even`（B）/ `?decor=middle`（C）。
     - C 落默认后：无 `decor` 参数 = C（与生产一致）；A / B 用 `?decor=current` / `?decor=even` 对照。
     - 三版都保持票 30 的「装饰在白条之下」层级，只改 x/y 间距。
3. **HUD**：按用户 JSON 的**五项** Y 整体 −8（组件一体）：`boxY 38→30` / `lifeY 38→30` / `pauseY 38→30` / `autoY 150→142` / `plusY 119→111`；实时仿真预览与导出视频共用 `SIM_HUD`，两边一起生效，不拆配置。其余参数不按 JSON 全量覆盖。

## 实现口径（2026-11-22 用户认可 C 后定，非用户拍板的数值）

- 中间两对按 x 在 `DECOR_PAIRS[3].x=0.2806 → [6].x=0.714` 间三等分落位，y 同法插值；用户反馈第二对星露出白条下缘 ⇒ y 上限取 `0.035H`，整对留在白条后（票 30 口径）。
- 最终布点写成常量 `MIDDLE_PAIR_POSITIONS`：`4 = (0.425067, 0.0242)` / `5 = (0.569533, 0.035)`；`current` / `even` 只留作原型 A/B 对照，生产与原型缺省都是 `middle`。
