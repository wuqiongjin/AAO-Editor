# 07-视频导出

Type: feature
Status: open
Blocked by: 05, 06

**来源**：chart-preview/01 定案 3（用户 2026-09-30）：**离线逐帧 + 含音频**。无对标实现——Bestdori 前端 0 处编码 / 录制代码（research 笔记 §1.2），这条路要自己走通。

## 链路

```
任意秒出帧（05 的同一函数，固定 surface / dpr）
  → 逐帧离屏出帧（t = k / fps，k = 0..ceil(duration × fps)）
  → VideoEncoder（WebCodecs；codec 由 06 实测定）
  → 封装（mp4 / webm；库由 06 实测定）
音轨：OfflineAudioContext 渲染 BGM + 键音 → AudioEncoder → 同一容器
  → 二进制另存（Electron 通道，复用 03 建的；浏览器降级 <a download>）
```

## 规格默认（本轮实现口径，待验收）

- **1920×1080 / 60fps**；**mp4（H.264 + AAC）优先，webm（VP9 + Opus）兜底**（以 06 的 `isConfigSupported` 实测结论为准，实现时定死并在 UI 说明）。
- 时长 = 谱面长度（有音频 = 音频时长，ADR-0005）。
- 音量口径与播放一致（BGM + `settings.audio.seVolume`），提供**静音导出**。
- 导出耗时 ≥ 歌曲时长（离线逐帧）：UI 必须给**进度 + 取消 + 失败态**；长谱导出不得阻塞页面交互（worker / 分片 + 让出主线程）。

## 离线音轨的接缝（本票最深的一处）

- 现状：`AudioEngine` 的 `buffer` / `sampleCache` / `loadSample` 全 private，仓库无任何对外交出 `AudioBuffer` 的接口（`probeAudioDuration.ts` 只回 `duration`）。
- 口径：**同一份事件表**（`AudioTiming.buildKeyEvents`）+ **同一份采样加载**（现 engine 内的 `loadSample`）→ 用 `OfflineAudioContext` 渲染成一条音轨；**不新建第二套音量 / 调度口径**。接缝形态实现时定（engine 只读访问器 vs 抽出独立的采样加载模块 + 离线渲染器），但**不得**让导出绕开既有键音口径。
- 持久化：不落中间音轨文件（内存里直接喂 `AudioEncoder`）。

## 落点

- `src/preview/video/encode/frameDriver.ts`（固定尺寸逐帧出帧 + 进度 / 取消）
- `src/preview/video/encode/muxer.ts`（编码 + 封装）
- `src/preview/video/encode/renderAudioTrack.ts`（离线音轨）

- `electron/`：沿用 03 的二进制另存通道（大文件走同一通道；若需分块 / 流式，同票扩展）
- `package.json`：按 06 结论引入封装库（**新增依赖要在 Comments 记账体积**）
- CONTEXT.md：补词条（**视频导出** / **离线音轨**）

## 锁测

- `tests/unit/preview/video/ExportTimeline.test.ts`：帧数 = `ceil(duration × fps)`、帧时间戳与 `pts` 单调、音轨长度与视频对齐（不早停 / 不重复末帧）；倒流区与 `beat < 0` 的口径与画布播放一致。
- `tests/dom/preview/VideoExportFlow.test.tsx`：进度 / 取消 / 编码器不可用时的降级提示（`isConfigSupported` 为 false → 明确文案，不静默失败）。
- `tests/static/VideoExportWiring.test.ts`：导出只经 05 的出帧函数（**不开第二份渲染真相**）、落盘只走既有二进制通道、新增依赖在 `package.json` 可见。
- **端到端**（单测测不到编码与音画同步）：导出一次 30 秒谱 → 文件可播 / 音画同步 / 无掉帧；人工验收清单，产出文件存本地（不入库）。
