# 78 · 动态预览滑条按住帽经过中间结点不换款

## 来源与症状

用户 2026-11-15：动态预览里滑条按住时判定线上那枚音符（「按住帽」）全程是滑条端点款 `note_long`；游戏里**经过滑条中间结点后**，按住帽应换成中间结点款 `note_slide_among`。「按住」= 播放时滑条持续被触发、判定线上一直显示音符；这套显示本身已实现（`connectionRing` + 对转双环 + 端帽），问题只在经过中间结点后不换款。

## 根因

- `simField.ts:1106` `drawHoldEffects` ① 无条件取 `noteIcons.slideEndpointFor(lane)`；按住判定只看时间窗 `(min(t0,t1), max(t0,t1)]`（`:1091-1096`），**没有中间结点分支**。票 25 #2 补这枚端帽、票 77 收成全轨扁平，两次都只处理「端帽用哪张图」，没处理「当前被按住的是哪枚结点」。
- 结构性原因：`SimBand`（`:187-201`）只有 `slide/t0/lane0/t1/lane1/sp`，构建期（`:392-405`）也只存几何 ⇒ 按住分支反查不到「刚过线的结点是端点还是中间结点」。而普通接近中的结点选款是对的（`buildSimChartSteps:386` → `render.ts:298-312` 的 `slideNodeIconConfig`，中间款取 `slideAmongFor`）；`prepareSimNoteSprites.ts:9` 已预热 `note_slide_among`，两张图同为 308×120 ⇒ **素材与音符盒子都不用动**。
- 漏测：`SimEffects.test.ts:290-333` 连按用例只造两点滑条、只断言环，没锁住按住帽取哪张图。
- 影响面：`drawSimFrameAt` 同时服务实时预览 / 视频导出（`frameDriver.ts:204`）/ 结尾舞台（`endingFrame.ts:711`），三处同病。

## 定案（用户 2026-11-15 逐条拍板）

- ① 按**播放时间上刚经过的可见结点**选款：A(头端点) → B(中间) → C(尾端点) 时，`A→B` 端点款、`B→C` 中间款；最后一段一路保持中间款到尾端点，尾端点自身仍由 `drawElements` 落下。
- 只换按住帽那张图，`connectionRing` + 对转双环照旧；「中间结点按住」不是另一套特效，也不是缺素材。
- hidden（SP 曲线采样点）**不触发**换款；中间结点忽略 `flick`/`skill`（issue 145 #3），按住帽为普通中间款。
- 倒流区（负 BPM，`t0 > t1`）按**玩家游玩的时间顺序**判定 = 取播放秒更小的那一端，不用投影数组序。
- 导出的视频必须一起变；编辑器画布 / 静态预览不在本票范围。

## 修法

- `SimBand` 补「本段按住帽是否为中间款」；`buildSimChartSteps` 按 `slideSpans`（hidden 对逻辑段透明）划段，段内取播放秒更小的那枚可见结点定款式（端点身份 = 投影下标 `0` / `lastIdx`），一个逻辑段里的小段共用同值。
- `drawHoldEffects` 用该字段在 `slideEndpointFor` / `slideAmongFor` 间取图；两环、`bandLaneAt` 落点、`globalAlpha=1`（票 36）、画序全不动。

- 单测只看到源格 id 看不出观感 ⇒ **手工验收**：动态预览里按住一条带中间结点的滑条，确认过结点那一帧换图、两环不变、SP 绿条（多 hidden）全程不闪；再导一段视频复核同一帧。
