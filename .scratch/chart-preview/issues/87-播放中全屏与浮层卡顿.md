## 来源与症状

用户 2026-11-23：动态预览播放中**进 / 出全屏**会顿一下、掉帧；播放中打开**设置 / 导出**更严重。谱面画布播放时打开**设置 / 切谱下拉**也有同类顿挫。要求先分析根因，不要急着改代码。允许用附件素材复现。

两条症状**不是同一条热路径**。全屏是仿真场 `setFrame` 同步重建；浮层是合成器 + React 挂载（导出另加 WebCodecs 探测）。票 85 已经拿掉加载文案和 `prepareSimRendering` 热路径，**没有**拿掉全屏这条同步重建。

## 根因 A · 全屏 = 播放中同步重建场地

1. `PreviewPage` 对 `.preview-stage` 调 `requestFullscreen`；`{!fullscreen && toolbar}` 把工具条卸掉，舞台几何再变一截。
2. `PreviewVideoStage` 对 `.pv-field` 挂 `ResizeObserver`，`clientWidth/Height` 一变就 `setHostSize` → `fitDesignSurface` **新 metrics 对象**。
3. 票 85 的热更新 effect 故意走 `pb.setFrame(input)`，且 `prepareSimRendering` 的 warmup key **不含** CSS 尺寸。探针窗口内 0 次 `getImageData`，这条已经成立。
4. `createSimPlayback.prepareFrame` 用 `frame.metrics !== input.metrics`（对象身份）决定是否重建底图。全屏每次都是新对象 ⇒ `prepareSimFieldBitmap`：`OffscreenCanvas(metrics.w × density)` 重画背景 / 相框 / 场地 / 判定线，再 `transferToImageBitmap`。进全屏 1600×900，出全屏 1304×733。
5. 同一次 `prepareFrame` **无条件** `prepareSimLifeGauge`（每次 `document.createElement('canvas')`）和 `prepareSimComboSprites`。combo 几何 `labelH = metrics.h * 0.05`，阴影缓存键 `` `${labelH}|${density}` `` 且 `WeakMap` 只留最近一档。进全屏 `shadowBlur = 15.75`（900×0.05×0.35），出全屏 `12.83`（733×0.05×0.35），必 miss。进全屏还 miss 了数字 `apTile` / `glowTile`（38 次匿名 canvas 从默认 300×150 改到字形尺寸）；出全屏数字瓦片命中，只剩生命条 + 阴影 + 底图，longtask 照样 401ms。
6. `render()` 发现 backing store 对不上就写 `canvas.width/height`，清掉 GPU 资源。紧接着无 class 的同尺寸 canvas（WebGL 带体 scratch，`simBandGpu.drawGlBands`）同样从 1304×733 ↔ 1600×900。进全屏时这条 `canvas.height` 晚了约 300ms 才赋上，落在 330ms longtask 的尾巴上——绘制缓冲重分配很可能就是这笔账的大头。

这直接打票 80 红线 2（「播放期不做一次性工作：新建画布 / createImageBitmap」）和红线 1 的精神（底图本该预烘；全屏把它又烘了一遍，还拦在 rAF 上）。

进全屏事件顺序（t≈15249–15592，节选）：

`.pv-field` resize 1600×900 → `transferToImageBitmap` 1600×900 → ~38 次 scratch canvas → `shadowBlur` 15.75 ×2 → `.pv-field__canvas` 1304×733→1600×900 → WebGL canvas 同尺寸（height 延迟到 15562）→ longtask 330ms start 15252.5。

## 根因 B · 浮层 = 合成 + 挂载（导出另加探测）

设置 / 切谱共用 `createPortal(..., document.body)` + `.pp-menu__scrim { position: fixed; inset: 0 }`。合成层一变，正在播的 2D/WebGL canvas 要重新提升。合成对照：

- 透明全视口层盖在动态预览上：maxDt 166.6ms。
- `backdrop-filter: blur(12px)` 全视口：maxDt **449.9ms**（最毒）。
- 动态预览设置面板本身没有 backdrop-filter；工作台 `.wdp__panel` 有，且面板压在谱面画布附近。

导出面板无 scrim，但 `VideoExportControl` 打开即 `onProbe()` → `useVideoExport.probe` 在 **PreviewPage** 上 `setProbing(true)` 再 `probeVideoExportSupport`（按档位几何跑 `resolveTarget` / WebCodecs）。两次 longtask 65ms + 106ms 对得上「state 提交 + 编码器探测」。这与全屏的 bitmap 链无关。

工作台 overlay 窗口里反复出现新建 canvas `300×150 → 1470×512`。`1470` = 当时谱面 surface 宽，`512` = `noteLayerCache.TILE_PX`。这不是主画布 backing store 被清掉，是浮层引起的布局 / 合成连带分配了一块音符瓦片。单独不够解释 116ms（透明 scrim 同样分配瓦片，只有 33ms）；它是加重项。`useSurfaceSize` 的 `flushSync` 只在 surface 真变时提交，本次主画布 1470×806 未改。

## 放大器

保活页用 `opacity: 0; visibility: hidden`，canvas 仍留在文档。探针结束时同时存在：工作台 `1470×806`、六张静态预览 `578×1526`、动态预览 `1304×733`。全视口 scrim / 全屏几何变化要和这么多 GPU 层一起合成。

## 建议修法（调研时的顺序，已落地）

1. **全屏**：尺寸变化期间 CSS 拉伸已有位图，等 `ResizeObserver` 停稳再异步 `prepareSimFieldBitmap` / combo 阴影；`render()` 在新 bitmap 就绪前不要写 `canvas.width`。阴影缓存按量化后的 `labelH` 留多档，不要只留最近一档。生命条按尺寸键缓存。WebGL 带体缓冲延迟到同一帧、或用 `drawingBuffer` 不动、blit 时缩放。
2. **设置 / 切谱**：scrim 不要做成会提升整页 canvas 的全视口层；工作台设置去掉盖在播放画布上的 `backdrop-filter`。
3. **导出**：探测推迟到 `requestIdleCallback` / 面板打开后下一帧；`probing` 不要抬到 PreviewPage；打开前已探过且规格没变就复用。
4. **保活**：隐藏页 `content-visibility: hidden`。

## 修法（2026-11-23 落地）

按建议顺序四条都做了：

1. **全屏**：`prepareFrame` 不再用 metrics 对象身份同步烘底图。尺寸变了先继续用旧底图（CSS 拉伸），`queueSizeBake` 按帧让出后再烘；同一套素材下留最近两档底图，退出全屏走缓存。主画布 / WebGL 带体缓冲只涨不缩。combo 阴影与生命条按场地尺寸各留 4 档。
2. **设置 / 切谱**：全视口 `.pp-menu__scrim` 换成 `useDismissOnOutside`（捕获阶段 pointerdown）。工作台设置去掉 `backdrop-filter`。
3. **导出**：`VideoExportControl` 打开后下一帧再 `requestIdleCallback` 探测；`probing` 不再抬到 PreviewPage；规格没变复用上次结论。
4. **保活**：失活 `.app-page` 加 `content-visibility: hidden`。

## 锁测（实现票再写死；本票只定口径）

1. 静态源码锁：`prepareFrame` 不得仅因 metrics **身份**在播放中同步 `transferToImageBitmap`；`prepareSimRendering` 的 warmup key 继续不含 CSS 尺寸（票 85 不得回退）。
2. Playwright 探针复跑本表：全屏进出窗口不得再出现 `transferToImageBitmap` 与 `.pv-field__canvas` 同一次 rAF 连发；导出打开不得在 100ms 内连续两次 longtask。
3. 真机：票 80 PresentMon 口径，60Hz 进 / 出全屏与打开设置 / 导出 / 切谱，无可见停格。headless 数字不作通过线。

## Answer

两条独立链，都已按上面修法落地。全屏进出不再在 ResizeObserver 当帧同步烘底图 / 改 backing store；退出全屏走尺寸缓存且画布只涨不缩。设置 / 切谱不再铺全视口 scrim，工作台设置不再 `backdrop-filter`。导出探测离开 PreviewPage，idle 后再跑。失活页 `content-visibility: hidden`。

headless 复测（对比调研表）：进全屏 `transferToImageBitmap` 与 `.pv-field__canvas` 不再同一次 rAF（间隔约 37ms）；出全屏 0 次 bitmap / 0 次主画布回缩 / 0 次 longtask（调研 401ms）；设置打开 0 次 longtask（调研 51ms，maxDt 283→100）；导出打开 1 次 longtask、无 100ms 内双发（调研 65+106ms）；工作台基线仍约 60fps；工作台设置 maxDt 116.7→33.4。进全屏仍有一次延后的 GPU 涨尺寸 longtask（headless ~250ms），那是第一次把 backing store 拉到全屏分辨率，不挡 ResizeObserver 当帧。
