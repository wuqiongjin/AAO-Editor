### #1 作用域条下拉贴边（左 / 右对齐 + 最大化跟随）— Status: resolved（2026-10-05 验收通过；五轮回修，末版口径见 v5）

- 症状：点作用域条，弹出面板不贴触发钮左缘；同一行的谱面切换器（`PreviewChartSwitcher`）却是左对齐，两个下拉两种口径。
- 根因：`src/ui/ScopePicker.tsx` L57-66 是**故意右缘对齐**（`left: Math.max(8, r.right - 288)`，288 = `.scope-panel` 的 `min-width` 硬编码），源自"控件住区块头右侧"的旧语境；两处使用者语境不同——预览页在工具栏左簇（该左对齐），音频页在区块头右侧（贴右缘才不漂浮）。
- 修法（第三版，2026-10-05）：**纯左对齐**（`panelLayoutFor`：`left = max(8, r.left)`，只钳视口左缘）；右侧放不下时**收窄面板宽度**到可用空间（下限 160px），不翻转、不钳平位置。内联 `width` + `minWidth:0` + `boxSizing:border-box` 覆盖 CSS（`.pp-menu__panel{min-width:200;padding:4px}` 因注入顺序压过 `.scope-panel{min-width:288;padding:0}`，曾让面板实测只有 237px、且宽度不含 padding/border）。
  - 演进：v1「左对齐 + 钳平」→ 音频页"两边都不贴"（被否）；v2「左对齐优先 + 右侧放不下翻转右缘」→ 用户仍要左对齐（被否）；v3「钉死左缘 + 宽度自适应」→ **v4（用户定案变更，2026-10-05）：贴边按落点分置——音频页改右对齐（面板右缘贴触发钮右缘），预览页保持左对齐**。`ScopePicker` 新增 `align?: 'left' | 'right'`（默认 `left`），`panelLayoutFor(rect, align)` 按边分支（贴边一侧钉死不动，另一侧放不下收窄宽度）；`AudioPage` 传 `align="right"`，`PreviewPage` 吃默认。
- 伸缩跟随：面板开着时挂 `window resize` → 重新量触发钮并重算（验收报截图 2：面板停在旧位置不跟随）。
- 最大化不跟随回修（第五轮，2026-10-05 验收报「最大化窗口时仍不跟随」）：根因 = 触发钮位置**不由 resize 事件当帧定**——`AppPageShell` 的内容壳几何（`--aps-*`）由 `ResizeObserver` 在布局落定后**异步**写，`window.resize` 先派发；拖拽伸缩 resize 连发、下一发自动纠偏（慢一拍肉眼无感），**最大化是单发 resize**，量旧后无人再量 → 面板永久停在旧位。修法：开着期间的 resize 处理改「当帧快测（拖拽跟手）+ 双层 `requestAnimationFrame` 补测（等壳几何落定，双帧兜底极端再落定）」，`computePos` 加**等值守卫**（几何没变不重渲）。锁测新增「布局晚一拍：resize 当帧量旧位、后续帧补测跟上」（旧写法必红）。真机（Playwright，916→1900 单发）：修复前 `AFTER600` 面板停旧坐标、MISALIGNED；修复后 `AFTER600` panel.right=触发钮 right（右对齐跟随 ✓）。
- 锁测：`tests/dom/ui/ScopePicker.test.tsx` 6 条 —— 默认左对齐（有空间 `left` = 触发钮 `left`、宽 288）/ 贴左缘留 8px / 右侧放不下仍左对齐且宽度收窄到可用空间（视口 1200、触发钮 950 → left=950、width=242、右缘不溢出）/ resize 后跟随新矩形（含 top）；右对齐 2 条（左侧空间够时右缘 = 触发钮右缘、宽 288；不足时收窄且右缘仍贴合）。接线与结构：`tests/static/ScopePickerPortal.test.ts`（portal + token + **音频页显式 `align="right"`、预览页不吃 right**）。
- 真机验证：第三轮（纯左对齐版）innerWidth 916、音频触发钮 left 745.8 → 面板 left 745.8、width 162.2、right 908 ≤ 916。**第四轮（v4）**：音频页 panel.right = 触发钮 right = 864.8（右对齐 ✓，≤ 916）；预览页 panel.left = 触发钮 left = 76、宽 288（左对齐 ✓）。

### #2 切页后画面与数据不同步（残留旧音符 / 丢新音符）— Status: resolved（2026-10-05）

- 症状 a：工作台重置谱面 → 切到预览 → 横滚时能看到上一版的音符，随后很快被刷掉。
- 症状 b：工作台新增音符后切预览，**有时**看不到刚加的音符。
- 根因（两条独立，均待实证）：
  - **数据陈旧**：预览读的是**落盘记录**却不调 `flushPersist`（对照：音频页 / 工程页写前都先 flush），工作台 800ms 防抖未落地时读到旧记录，且防抖落地不通知目录 → 整次访问停在旧数据（`usePreviewScope` L65-90）。
  - **位图陈旧**：`StaticPreviewView` 只重画**可见区间**（`paintedRef` 记账），未进视口的画布保留旧画家的位图，滚进视口才重画（L192-207）→ 旧音符可见一瞬。
- 修法：① `usePreviewScope` 读前 `await flushPersist()`；② 画家换代时作废视口外的旧位图（删 canvas / 标脏），滚动进场不出旧图。
- 锁测：① `tests/dom/preview/PreviewPageScope.test.tsx` 注入假 flush + 假 store，断言"读之前先 flush"的顺序；② `tests/dom/preview/StaticPreview.test.tsx` 换 scene 后断言视口外不保留旧位图（滚回必须重画）。

### #3 缩放时横向滚动条弹跳 — Status: resolved 实现（2026-10-05，观感待验收）

- 症状：滑杆 / Ctrl+滚轮缩放时，横向滚动条来回跳。
- 根因（三条候选，待实证）：① 滚轮分支在**布局换代前**抢写 `host.scrollLeft`（`StaticPreviewView` L136-159），浏览器按旧内容宽先钳一次；② 连发滚轮事件用的是上一帧闭包里的 `zoom` / `layout`（state 滞后），重复写同一个值；③ `scrollLeft` 双真相（DOM + state，`onScroll` 回写）互相回声。
- 修法：先复现量测（Playwright 逐步 zoom，记录 scrollLeft 轨迹）再定；方向 = 锚点改在布局换代后于 layout effect 一次性对齐，不在换代前抢写。
- 锁测：jsdom 无滚动布局 → **Playwright 实测**（缩放全过程 scrollLeft 单调、滚动条无回跳）或手工验收清单，并说明单测为何不行。
  - **实际落地**：环境无 Playwright 浏览器二进制（`~/.cache/ms-playwright` 缺席），真机轨迹未采；退到① jsdom **协议锁**（`StaticPreview.test.tsx`：换代前不写 / 换代后按新面板宽写一次 / 连发不重复同一档 / 锚点只落一次——旧写法必红）+ ② 手工验收清单（见 Comments）。
  - 为什么 jsdom 测不了"回跳"本身：它没有滚动布局，`scrollLeft` 是纯存值、内容宽不参与钳制，"换代前抢写被旧宽钳住"这一幕复现不出来；能锁的只有**写盘时机与算式**（协议），这也正是根因候选①的落点。
