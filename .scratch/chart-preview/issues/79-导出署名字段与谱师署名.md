# 79 · 导出署名字段与谱师署名

Type: grilling
Status: resolved（用户 2026-11-15 逐问拍板 Q1–Q18；**已实现**，Canvas 成片待用户验收）
Blocked by: none

## 来源与诉求

2026-11-15 用户提需求（附游戏内夹克画面截图：`Pastel＊Palettes` / `作詞：miwa` / `作曲：miwa` / `編曲：堀川大翼（Elements Garden）`）：

> 「我想完善一下动态预览的导出信息。基于这个信息的基础上，可能还会加上『谱师』的名称这条信息。除了动态预览，静态预览中最好也能支持加上『谱师』名称的这条信息。然后针对上面的这些信息，在哪里填写，可能需要讨论一下。（这些信息和现有的『乐队』一样，保持可以控制开和关的配置项。）」

后续追加：「谱师，默认跟随已经登录的账号名称，但是可以支持修改。（因为存在联合创作的这种情况，有多个谱师参与）」

## 症状与根因

- 票 39 已在**绘制层**做好 4 行附加字段（`OpeningCredits` = 作词 / 作曲 / 编曲 / 谱师，方案 B 首字对齐、0~4 项、空项不占位，`OPENING_CREDIT_FONT = 0.022H` / 行高 1.4），并留了编排接口 `OpeningInput.credits`。
- 但工程 / 谱面**数据层零字段**：`src/project/ChartProject.ts` 与 `ChartProjectRecord.ts` 搜 credits 零命中；`PreviewPage.tsx:280-282` 用 `(project as { credits })?.credits ?? null` 强转兜底 ⇒ 运行时 `credits` 恒 `null` ⇒ 4 行永不出现。`CONTEXT.md` 写的「数据层预留 4 个可选附加字段」只在绘制 / 编排接口，不在工程结构。
- 绘制层 `extractCreditLines` **完全不看开关**：只要有 `credits` 就 4 行全画；`OPENING_ITEM_IDS` 只有难度 / 歌曲标题 / 乐队三项。
- 静态侧：只有「导出谱面图」头带有信息区，`EXPORT_FIELD_KEYS` 7 项全是谱面统计（连乐队都没有）；票 14 写「谱师姓名**本票不做**，后续票再谈」，该后续票一直没开。静态预览舞台本身没有任何文字层。
- 已有「谱师」三处都不是手填：社区谱导入会话 `PostCandidate.charter`（不落盘，票 32 定案）、发布描述里的账号昵称、发布记录 `chart.upload.username`。官方曲库单曲详情只映射 `bgmId` / 曲长，没有 credits。
- 账号名 `getCommunityAccount().getSession().account`（`nickname ?? username`）**不是常驻**：未登录 / 会话失效 / 离线校验没过 / 启动 `user/me` 未返回（`verifying`）时都是 `null`，登出会清。

## 定案（用户 2026-11-15）

1. **术语**：词汇表新增「曲目署名」与「谱师署名」；既有「谱师」（= Bestdori 社区帖作者 / 账号）词义不动，界面标签仍写「谱师」。拆词是**文档 / 代码命名**的事，不是新增一个叫「曲目署名」的配置项。
2. **命名**：词汇表与「编辑工程信息」弹窗的分区标题都用「曲目署名」（不用「曲目信息」—— 那词已被曲目信息片头 / 歌曲元数据 / 曲目来源占满）。导出面板不新增分组标题。
3. **层级**：乐队 / 作词 / 作曲 / 编曲 = **工程级**，在「编辑工程信息」弹窗填；谱师署名 = **谱面级**，在「谱面信息」弹窗填。官方曲导入的本地工程署自己名，不算与「官方曲只有歌手，不讲谱师」冲突。
4. **默认值**：优先级只有三档 —— **手动填写 > 登录账号名 > 空**。账号名取 `nickname ?? username`，**只在新建谱面那一刻落值**；换账号 / 登出 / 未登录都不改已有值；未登录留空（不画）；**老谱面不补默认值，只能手动填写**；导出阶段绝不现取账号名。
5. **导入**：社区谱导入**不带入**导入帖 `charter`，票 32「谱师名称同理不落盘」定案保留。用户原话：「我导入社区谱面，就是为了我自己要重新创作，那么谱师名称自然应该是我」。发布描述 / `chart.upload.username` 本次不动。
6. **联合创作**：谱师署名 = **一个自由文本框**，作者自己写分隔符（「A、B」）；绘制层原样输出、不解析、不拆行，超长沿用既有截断。
7. **静态范围**：只在「导出谱面图」头带信息区加**一枚「谱师」chip**（第 8 个开关）；静态预览舞台 / 全屏画面不加文字层；作词 / 作曲 / 编曲不进静态图。
8. **动态范围**：只改曲目信息片头；结尾结算卡、实时预览舞台不加署名。
9. **开关**：每字段一枚布尔 —— 动态 4 枚并入 `opening.items`（共 7 项），静态 1 枚并入 `EXPORT_FIELD_KEYS`（共 8 项）；两组继续互不跟随，不加总开关；`settings.export` additive、不 bump `schemaVersion`；每枚开关必须真正 gate 自己那一行。
10. **默认值 / 空值**：动态 4 枚默认全开 + 缺字段回落 `true`；静态 1 枚默认关；开关开但值为空 ⇒ 不画、不占位。
11. **文案**：片头 4 行 / 长图 chip / 两处开关标签**全部走 i18n**（导出物文字随界面语言变）。zh-CN = 作词 / 作曲 / 编曲 / 谱师 + 全角「：」；en = `Lyricist` / `Composer` / `Arranger` / `Charter` + 半角「: 」。乐队行维持只有名字、无标签。
12. **静态 chip**：排 chips 行末位，只对这枚做文本截断加省略号保证不超 `textW`（`packChipRows` 现在会把超宽 chip 整枚跳过），不改通用打包策略；两行满沿用既有截尾。
13. **数据**：additive 扩容（`ChartProject` 3 个可选字符串、`ProjectChart` 1 个），缺字段回落空，`PROJECT_SCHEMA_VERSION` 不 bump、不写迁移；复制谱面 / 复制工程带走署名；署名不进 `settings`、不随设置 JSON 导入导出；**已上传谱面的谱师署名可改**（元数据，与难度 / 等级 / 标签同档，不碰音符）。

决策记录见 [ADR-0024](../../../docs/adr/0024-曲目署名与谱师署名的字段边界.md)。
