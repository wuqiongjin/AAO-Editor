# 42 · 自定义表演背景图（仿真场）

Type: grilling
Status: open（2026-10-11 开票；grill 完成 · 已定案见 ADR-0018 · 待实现）
Blocked by: 41

## 来源与诉求

2026-10-11 用户提需求：「动态预览，要支持自定义背景图」（与 41 的"更多种类"并列；
本票 = 用户**自己带图**，41 = 内置素材更多）。

## 现状（实测）

- 仿真场背景层 = 内置 `liveBG*.png`（`src/preview/video/sim/simField.ts` 的 `drawField`），
  图层矩形由 `simGeometry.ts` 的 `BACKGROUND_RATIO = { w: 1.32, h: 1.0065 }` 固定取景。
- 已有一套**画布**用的「谱面背景皮肤」（`settings.visual.backgroundSkin`）：单张本地图 +
  启用开关 + `opacity` / `fit`(cover|contain) / `scope`(outsideTrack|fullCanvas)；
  浏览器存 IndexedDB `bangdream.assets`，Electron 存 `<数据根>/assets/background-skin.bin`。
  它**不进仿真场、不进静态预览**（ADR-0003 已定不做预置背景包）。
- 视频开场第③段（入场过渡）画的就是这张表演背景（`openingFrame.drawOpeningFieldBackground`）
  ⇒ 自定义背景换了，开场段要不要跟着换是需要一起定的口径。

## 待拍板（grilling）

1. **与画布「谱面背景皮肤」的关系**：复用同一张图（一处上传两处生效）/ 各自独立一份 /
   独立但默认跟随？
2. **存储与作用域**：沿用应用级单张（现状通道）vs 多张库 vs 工程级（随工程走、导出分享带得走）。
3. **取景**：内置背景有固定的 `BACKGROUND_RATIO` 取景，自定义图沿用同一取景裁切，
   还是另给 `fit`（cover / contain / 拉伸铺满）？
4. **适用范围**：仅实时预览 / 含视频导出 / 含视频开场第③段 / 含静态预览与谱面图。
5. **格式与体积上限**：沿用画布那套（PNG/JPEG/WebP，20 MiB）还是另定。
6. **UI 落点**：视觉素材页「背景皮肤」子 tab vs 预览页「设置」面板。

## 定案（用户 2026-10-11 · grill 第 1 轮）

1. **独立一份**：仿真场的表演背景 ≠ 画布的「谱面背景皮肤」，两套数据、两处上传，
   不复用同一张图（复用的话"调画布背景、动态预览跟着变"是意外行为，且 `scope` / `fit`
   两套语义要强行统一）。
2. **统一生效**：换成自定义图时，实时预览 / 视频导出 / 视频开场第③段一起换
   （"导出物应当和我在预览里看到的一致"）。
3. **混合归属**（用户 2026-10-11 定案，推翻"全都工程级"的推荐）：
   > 用户原话：「在选内置包的时候，是应用级的。然后在为某个工程专门设置自定义图时，
   > 这个图属于这个工程本身的。如果再创建新的工程时，此时新的工程会默认使用上一次选择的内置包背景图。」
   - 内置包选择 = **应用级**（`settings.preview`；"我的默认口味"，新工程默认沿用上次选的包）；
   - 自定义图 / 视频 = **工程级**（随谱面工程走、复制工程带走）；
   - **优先级**：工程有自定义 → 用它；否则 → 应用级内置包。
   对比：画布「谱面背景皮肤」= 应用级（"放一张自己喜欢的"观看偏好），与工程无关。
   二者层级语义相反，勿统一。
4. **取景 = 沿用内置同一取景矩形**：`cover`（默认，铺满裁切）/ `contain`（完整显示，
   两侧露 `SIM_FALLBACK_BG` 兜底底色）两档，与画布那套 `fit` 同名词同语义；不做"拉伸铺满"。
5. **UI 关系 = 自定义图是缩略图网格的第一格**：未上传 = 「+ 自定义」上传入口，
   上传后 = 可点选的缩略（可"清除"回到内置包）。"背景来源"只有一个选择器，
   不存在"选了内置包却被自定义图盖住"的隐式优先级。
6. **存储 = 照封面 / 音频加第 4 个工程二进制**（用户 2026-10-11 同意推荐）：浏览器内联 Blob
   （IDB `bangdream.chartproject`）、Electron 落 `projects/<id>/` 下固定文件名；`xxxName` 记原始
   文件名供 UI 显示；**复制工程带走**（与封面同口径，`projectCatalog.test.ts` 已有锁测可照抄）；
   **清除 = 从工程删除**（不留空壳字段）；无工程 / 作用域失效时上传入口不可用（对齐音频页空态），
   入口复用预览页已有的 `ScopePicker`。**体积上限沿用 20 MiB**（工程级后体积只落本机，防误导入）。
7. 新增一个工程级二进制要动 6 处：`ChartProject` 字段 / `RECORD_FIELDS` / Blob+Present+Intent /
   wire payload / Electron backend / `electron/projectStore.cjs` —— 不是加一个字段的事。
8. **选中内置包 = 停用但保留**（用户 2026-10-11 采纳推荐）：该工程切回内置包
   （`useCustom = false`），自定义图**留在工程里**，再点第一格即切回、**不用重传**；
   真正从工程删除只由「清除」触发。
9. **图片与视频共用同一个「自定义」槽位**（一格只放一个，换格式 = 替换）—— 两个槽位会再引出
   一次"谁优先"的隐式优先级，而 41 的定案刚把它消灭掉。
10. 全量定案见 **ADR-0018**。

  新增第 4 个工程二进制（自定义表演背景）+ `useCustom` / `fit` / 原始文件名，六处同步。

- 上传入口：预览页「设置」面板网格第一格 + `ScopePicker`（无工程 / 作用域失效时不可用）。
- `src/preview/video/sim/simAssets.ts` + `simField.ts`：工程二进制 → 图像，按
  `BACKGROUND_RATIO` 目标矩形做 `cover` / `contain`。
- 开场第③段（`openingFrame.drawOpeningFieldBackground`）与视频导出走同一份来源。

## 锁测

- `tests/unit/project/projectCatalog.test.ts`：复制工程带走自定义背景（照抄封面 / 音频那两条断言）。
- `tests/unit/project/ChartProjectRecord.test.ts`：新字段的读写往返 + 缺字段兜底（老工程记录仍可读）。
- 单测覆盖不到的（IDB / Electron 文件落盘、真实图片解码、三处画面一致性）走**手工验收清单**：
  上传 → 预览 → 导出一段视频 → 切到别的工程回落到内置包 → 切回来仍在且不需重传。
