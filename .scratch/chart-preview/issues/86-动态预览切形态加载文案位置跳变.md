# 86 · 动态预览切形态时加载文案先在上、后跳到中间

Type: bug
Status: resolved（2026-11-23 已实现 + 锁测全绿；真机目测待用户验收）
Blocked by: none
Related: [69](./69-动态预览切换时长谱派生阻塞首帧.md)、[85](./85-动态预览调设置误出加载态.md)

## 来源与症状
用户 2026-11-23：动态预览初次加载，「正在读取场地素材…」先出现在舞台上方，下一帧跳到正中。

## 根因
票 69 的 `switchMode` 先 `setPendingMode('video')` → `await waitForPaint()` → `setMode('video')`，过渡帧文案是 `.preview-stage` 的裸 flex 子项。有音符时舞台带 `is-filled`（`align-items: stretch`），而 `.preview-stage__pending` 只有水平 `text-align: center`，无垂直定位 ⇒ 文字贴顶。下一帧文案改由 `.pv-field`（双向居中 flex）渲染 ⇒ 跳到中间。次要因素：`.is-video:has(.is-filled)` 的 8px padding 让居中内容下移 4px，非本次主因。

## 本轮实现口径（待验收，非用户逐字定案）
只改过渡帧那一个节点：加专用绝对定位居中遮罩（`inset: 0` + 双向 flex 居中，复用 `.pv-field__pending` 口径），或仅对 `.preview-stage > .preview-stage__pending` 补居中规则。不改 `switchMode` 时序 / `waitForPaint` / 派生 / 素材 / 播放器，不动 8px padding。影响面：一次文本节点的布局/绘制，无额外帧、无状态与内存开销，加载速度与票 80 性能红线不受影响。

## 锁测
1. `tests/static/PreviewPageWiring.test.ts`：加一条源断言锁过渡帧加载节点的居中定位；现有票 69 时序锁、`.is-filled` 与 `:fullscreen` 源序、8px padding 三条保持绿。
2. `tests/dom/preview/PreviewVideoControls.test.tsx`：文案提交时序与「派生前文案在 DOM」原锁保持绿；按 `getByText` 查询要求两句文案仍互斥，不重复渲染。
3. jsdom 无布局 / paint ⇒ **真机 / Playwright 目测**：点动态那一帧文案居中、不贴顶；空态、全屏、静态↔动态来回切无新位移。

## Answer
**改成什么**：取 spec 的第二种方案——`PreviewPage.css` 给 `.preview-stage.is-filled > .preview-stage__pending` 加 `align-self: center`，抵消父级 `stretch`；不加遮罩、不改 `switchMode` / `waitForPaint` / 派生 / 素材 / 播放器，不动 8px padding。

**验证**：票 86 静态断言先红后绿；`PreviewPageWiring` + `PreviewVideoControls` 两文件 55 例全绿；`npx tsc -b` 与改动测试文件 eslint 干净；全量 447 文件 / 5089 例全绿。锁测 3 的真机 / Playwright 目测**未执行**，jsdom 无布局与 paint，位置观感待用户验收。
