### 问题 5 · 音符只在命中那一瞬出现（几乎等于画不出来）— Status: resolved 实现（待验收）

- **症状**（用户）："播放时，所有音符的材质加载都有问题（大部分音符都显示不出来）"。
- **根因（坐实）**：`simField.drawElements` 的可见窗口**取反**了 —— 元素扫描区间取 `[seconds − T, seconds]`（`simField.ts` L455-456），而 `visibleApproach` 只认 `Δ = seconds − time ∈ [−T, 0]`（音符是**将来**才过线的）。两者交集只剩 `Δ = 0` 一个点 ⇒ 除了"正好压线"的音符，一个都不画（不是素材加载问题）。
- **证据**：页面内直调 `drawSimFrameAt`（真实精灵 + 记录 stub，`.cache/sim-frame2.mjs`）：t=4.25s 时窗口内 7 个元素（lane6 A=0.563 / lane4 A=0.312 / lane2 A=0.184 / …），**绘制调用 0 次**；t=6.0s 恰有 Δ=0 的元素 → 1 次。用户截图里"判定线上那 7 个小图标"是判定线素材自带的轨道标记（见问题 4），不是音符。
- **修法**：`lo = elementBound(elements, seconds, true)`、`hi = elementBound(elements, seconds + T, false)`（Δ=0 在线上要画、Δ=−T 是窗口下界）。`drawEffects` 的 `[seconds − 0.32, seconds]` 是对的，不动。
- **锁测**：新增 `tests/unit/preview/video/SimField.test.ts`（记录型 sprite stub，不碰像素）：① `seconds` 前 0.5s 的音符**要**画（今天必红）；② 已过线（Δ>0）不画；③ Δ=−T 画、Δ=−T−ε 不画；④ 效果层仍只画命中后 0.32s 内。像素侧：`scripts/sim-shot.mjs` 的 `playing` 帧（音符随接近变大、能同时看到多个）。

### 问题 4 · 判定线上的 7 个轨道标记错位（场地图 / 判定线画错比例）— Status: resolved 实现（待验收）

- **症状**（用户）："这 7 个小图标没有在轨道中间，已经是错位的状态了"（附与 Bestdori 的对照图）。
- **根因（坐实）**：那 7 个标记是官方判定线素材 `game_play_line.png`（1800×38）**自带的**（素材里标记间距 = 154px、以图片中心对称，与设计面 lane 间距同尺）。Bestdori 按**设计 px 1:1** 画它：`width = 1.35 × stageWidth`（1334×1.35 = 1800 ✓）、垂直居中于判定线；我们拉成 `width = m.w`（`simField.ts` L355-358）⇒ 标记间距压成 154×(1457/1800) = **124.7** CSS px，而音符 lane 宽 = 154×(1457/1334) = **168.2** CSS px ⇒ 最外侧标记偏 3×43.5 ≈ **130 CSS px**。
- **同因第二处**：场地图 `bg_line_rhythm.png`（1160×610）也被拉满 `0..W × 0..H`。Bestdori 的画法 = `width 0.875 × stageWidth`、`height 0.82 × stageHeight × 0.983`、水平居中、**底边贴判定线**。实测（我方 2914×1638 位图）：场地图车道线在判定线处间距 **317.9** bitmap（应为 336.4）⇒ 最外轨偏 ~55.5 bitmap = **27.8 CSS px**。
- **证据**：素材像素分析（`.cache/img-tool.mjs`、`.cache/lane-lines.mjs`、`.cache/line-marks.mjs`）+ bundle 里两处 `<img>` 的 inline style 与 `laneWidth = 154×canvasWidth/1334`、`laneHeight = 0.82×canvasHeight`。
- **修法**：几何常量进 `simGeometry`（唯一定义处），`drawField` 只消费：
  - `fieldImageRect(m) = { x: m.centerX − 0.4375m.w, y: m.laneHeight − 0.8061m.h, w: 0.875m.w, h: 0.8061m.h }`
  - `playLineRect(m) = { x: m.centerX − 0.675m.w, y: m.laneHeight − h/2, w: 1.35m.w, h: 1.35m.w × 38/1800 }`
  - （`0.875` / `0.983` 是 Bestdori 的实测比例；修完标记与 lane 中心误差 < 1%）
- **锁测**：`SimGeometry.test.ts` 加 `fieldImageRect` / `playLineRect` 字面断言（比例 + 贴线关系）；`SimRendererWiring.test.ts` 守"两处 drawImage 必须走这两个函数"（禁再出现 `drawImage(assets.field, 0, 0, m.w, m.h)`）；像素侧 `sim-shot.mjs` 打印判定线素材 7 个标记 x 与 lane 中心的偏差（应 ≤2 CSS px）。
- **附带观测（本轮不改，登记待判）**：① 音符精灵按 `noteMetrics` 的 36×21.6（比 1.667）绘制，而精灵矩形比例 = 308×120 = **2.567**（Bestdori 按 2.567 画）⇒ 我方音符被纵向拉高约 1.54 倍；② 同时点击线粗细我们 = `0.3×noteSize×laneWidth×A`，Bestdori ≈ `27/308×1.35×…` ≈ 0.118（约 **2.5 倍**粗），且它一根跨全程（`lane..lane+width`）、我们逐 gap 一根；③ 背景图取景与 Bestdori 不同（它 `1.32W × 1.0065W`、上缘锚 −0.176H；我们 cover 居中裁两侧）。

## Answer

2026-10-07 实现（待用户验收）。

**问题 5（可见窗口取反）**

- `src/preview/video/sim/simField.ts`：`drawElements` 的扫描区间 `[seconds − T, seconds]` → **`[seconds, seconds + T]`**（`lo = elementBound(elements, seconds, true)`、`hi = elementBound(elements, seconds + T, false)`；Δ=0 压线要画、Δ=−T 是窗口下界）。

**问题 4（场地图 / 判定线的绘制矩形）**

- `src/preview/video/sim/simGeometry.ts`：新增 `FIELD_IMAGE_RATIO`（`0.875W × 0.82H×0.983`，底边贴判定线）、`PLAY_LINE_RATIO`（`1.35W`）、`PLAY_LINE_ASPECT`（`38/1800`，从 `simField` 搬进来）+ 两个纯函数 `fieldImageRect(m)` / `playLineRect(m)`；「几何只在 simGeometry」这条不变。
- `src/preview/video/sim/simField.ts`：`drawField` 的两处 `drawImage` 改吃这两个矩形（不再 `0, 0, m.w, m.h` 拉满）。

**锁测**

- 新增 `tests/unit/preview/video/SimField.test.ts`（8 例）：接近中的音符每帧都画（**旧写法必红**）、过线不画、Δ = −T / −T−ε 边界、同帧远的近的都在、带体与特效窗口没被改坏、两处 `drawImage` 的目标矩形 = `fieldImageRect` / `playLineRect`、两张素材的轨道标尺 = `laneWidth`（差 < 1%）。
- `tests/unit/preview/video/SimGeometry.test.ts`：+3 例（两张矩形的字面断言 + 贴线关系 + 轨道标尺）。
- `tests/static/SimRendererWiring.test.ts`：+1 例回潮守卫（两处 drawImage 必须走这两个矩形函数；禁 `drawImage(assets.field, 0, 0, m.w…)`）。

**验证**

- `npm test` **208 文件 / 2,288 用例全绿**；`npx tsc -b` 通过；改动文件 eslint 干净。
- 像素（`.cache/sim-frame.mjs` 用真实模块渲染任意秒、`.cache/marker-check.mjs` 量位图）：t=4.25s 修前"窗口内 7 个元素、**0 次绘制**"，修后同一秒画出 3 颗（lane 6 / 4 / 2，伪透视正确）；判定线 7 个标记的暗环中心 = 447 / 783 / 1120 / 1457 / 1793 / 2130 / 2466（bitmap），与 lane 中心（447.8 / 784.2 / 1120.6 / 1457 / 1793.4 / 2129.8 / 2466.2）逐轨偏差 ≤ 1.5 bitmap px（≈0.75 CSS px）——修前标记间距 249.3 vs 车道 336.4、最外偏 261 bitmap px。
