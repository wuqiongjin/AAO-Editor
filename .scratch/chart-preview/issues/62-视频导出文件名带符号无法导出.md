# 62 · 视频导出文件名带符号无法正常导出

Type: bug
Status: resolved（2026-11-11 已实现；Windows 真机验收待做）
Blocked by: none

## 来源与症状

用户反馈：导出动态预览视频时，导出视频文件名称带有符号则无法正常导出。环境 / 具体字符不详 —— 本轮已自行实测定位，无需再问用户。

## 根因（实测确认）

导出文件名由**用户可编辑的工程名 / 谱面标题**拼出，**整条 Electron 落盘链路没有非法字符清洗**：

1. `PreviewPage.tsx:215-219` → `t('preview.video.export.filename', { title, diff })`（`{{title}}-{{diff}}-回放`）；`title = chartEffectiveTitle(...)`（`projectCatalog.ts:36`）。`exportSpec.ts:288-291` `videoExportBasename()` 只拼 `` `${base}.${ext}` ``，**不清洗**；`exportVideo.ts:345-349` 交给 `saveBinaryAs`。
2. `electron/foundation/saveDialog.cjs:16-26` 只 `path.basename(rawName)`（去目录段），再 `showSaveDialog({ defaultPath })`。**实测**（注入假 dialog 直接调产品模块）：`* ? " < > |` 与控制字符**原样进 `defaultPath`**；`/` 被 basename 截掉前缀、名字悄悄变短（如 `曲/名-EZ-回放.mp4` → `名-EZ-回放.mp4`）。平台差异：Linux 的 `path.basename` 只认 `/`（`\` 原样保留）；Windows 的 `win32.basename` 连 `\` 与 `:` 一起截。
3. Windows 下 `fs.promises.writeFile`（`saveDialog.cjs:58`）遇这些非法字符会抛 `EINVAL`；**该函数无 try/catch、无回退清洗** ⇒ 错误经 IPC 回渲染侧 → `saveBinaryAs` reject → `runVideoExport` 的 `catch` 只回 `failure:'unknown'`（`exportVideo.ts:359-364`）。本轮以**模拟**验证这条传导链（注入 `fs.promises.writeFile` 对非法字符抛 `EINVAL`，确认异常无人兜住、直接冒泡），未在真 Windows 实机跑对话框。失败发生在逐帧编码**全部跑完之后**（`exportVideo.ts:345`）⇒ 用户等满全程只看到「导出失败」，拿不到原因。
4. **浏览器降级路径不成立**（实测 Chromium 153，19 组用例）：`<a download>` 会把 `/ \ : * ? " < > |`、控制字符自动替换为 `_`，去掉末尾点、把开头空格换成 `_`，**下载照常触发**；`♪ ★ # & （）`、emoji、中文标点原样保留。⇒ 「无法导出」只在 **Electron（尤其 Windows）** 出现，网页版至多改名。
5. `t()` 是函数式 replace（`src/i18n/t.ts:36-42`），曲名里的 `$&` 之类不会被展开 —— 排除插值陷阱。
6. **对照**：`patterns/shareFile.ts:49-69` `patternExportFilename` / `replaceIllegalFileNameChars` 已有现成清洗口径（非法字符→`_`、去尾点空格、空名回落），这一支没复用。

## 同源影响（同一类问题，仍归本票）

静态宽图导出 `PreviewPage.tsx:294`、谱面代码导出 `project/exportChartCode.ts:60` 走同一 `saveBinaryAs` / `saveAs`，同样未清洗；片段分享那条已清洗。

## 修法方向（本轮不改代码）

落盘前统一复用 `replaceIllegalFileNameChars` 口径（并补 Windows 保留名 CON/PRN/NUL 等、末尾点空格、空名回落）；主进程 `promptSaveDialog` 再兜一层；写盘失败单独成档、前置校验，别等编码跑完才报。**本轮实现口径（待验收）**：清洗放在统一落盘入口，静态图 / 谱面代码同源一并受益 —— 用户只报了症状，此处非「定案」，实现后按验收确认。

## 锁测

- `videoExportBasename` 纯函数单测：`/ \ : * ? " < > |`、控制字符、`♪ ★` / emoji、末尾点空格、空名回落，口径对齐 `PatternFileName.test.ts`。
- `saveBinaryAs` / `saveDialog.cjs` 断言 `defaultPath` 已清洗、写盘抛错时给得出可照做的档位。
- 系统保存对话框真机行为单测覆盖不到 ⇒ 手工验收：Windows 真机用含 `? * : /` 的曲名各导一次。

## 复现脚本（本轮，在 /tmp，未入仓）

`/tmp/probe-save.cjs`（产品模块 + 注入 dialog）、`/tmp/probe2.mjs`（Chromium `<a download>`）、`/tmp/probe2.json`（实测结果）。平台差异另以 `node -e` 对比 `path.basename` 与 `path.win32.basename` 核过。
