# 28 · 倍速触钮：按住（mousedown）时图标与读数位移一下，松开又回来

Type: bug
Status: resolved（**2026-10-09 用户验收通过**，实现见文末 Answer）
Blocked by: —

## 来源

2026-10-09 用户两轮描述（第二轮把现象说准了）：

1. 首报："点击倍速按钮时，倍速图标会移动一下。感觉有点奇怪，正常不应该移动吧？"
2. 复述（第一版修法落地后）："票 28 没有任何变化，估计是改错了…… 在 mouseDown 下，倍速的 icon 会**往斜上移动**，然后 mouseUp 后回到原来的位置。"

## 症状（本机 Playwright 实测复现，`.cache/pv-press-28.mjs` / `pv-press-dpr28.mjs`）

按住触钮 → 图标（含读数）位移，松开复位。逐帧量（DPR 1，按住 500ms，中间那 120ms 是过渡）：

| | 钮 x / y | 钮 宽×高 | 图标 x / y | 钮 transform |
|---|---|---|---|---|
| 静止 | 1709.97 / 1042.50 | 74.03 × 27.00 | 1718.97 / 1048.50 | none |
| 按住 | 1710.71 / 1042.77 | 72.55 × 26.46 | **1719.53 / 1048.65** | `matrix(0.98,0,0,0.98,0,0)` |
| 松开 | 1709.97 / 1042.50 | 74.03 × 27.00 | 1718.97 / 1048.50 | none |

光看盒子是亚像素（图标 +0.56 / +0.15px），**真正看得见的是"整块内容被重采样"**：图标墨迹质心在按住时偏

| 屏 | 墨迹质心 Δ（设备px） | 墨迹 bbox |
|---|---|---|
| DPR 1 | **(0.47, −0.05)** | `[8,10,22,19]` → `[9,10,22,19]` |
| DPR 1.25（用户实机档） | (0.35, 0.03) | 不变 |
| DPR 2 | **(0.92, −0.19)** | `[17,20,44,40]` → `[19,20,44,40]` |

⇒ 横向位移为主、纵向略偏上，用户读成"往斜上移动一下"；松开复位 ✓ 与描述逐条吻合。

## 根因（已实测坐实）

全站的按压反馈：`src/ui/ui.css` L20-23

```css
.action-btn:active,
.icon-btn:active { transform: scale(0.98); }
```

它是"**整块钮连着内容一起缩**"，而触钮里那点内容（15px 仪表图标 + 11px 读数）本来就贴着钮的左边与中线 ——
2% 缩放全落在**亚像素重采样**上：图标只挪 0.5px（盒子层），但它的抗锯齿边被整体重画 ⇒ 肉眼看到的是"跳一下"。
（同一记缩放压在别的钮上不明显：那些钮的内容更大 / 更居中 / 不是需要盯着读的数字；本钮是"盯着读数改倍速"的控件。）

## 修法（本轮实现口径，待验收）

**这一个钮的按压反馈不吃几何**，换成不改盒子的按压色（`src/pages/preview/PreviewPage.css`）：

```css
.pv-rate .icon-btn:active:not(:disabled) {
  transform: none;
  background-color: color-mix(in srgb, var(--bg-hover) 88%, var(--text));
}
```

- 深浅与既有令牌 `--bg-active`（按下 / 选中底色）同档；色值混自 `--bg-hover` / `--text` 两个**当前态** token
  ⇒ 全屏台上态（两者一起换）也跟着变，且不落硬编码色值（本文件既有口径）。
- **全站那记 `scale(0.98)` 保留不动**：它是全站的按压语言（播放钮、工具栏钮…）；本票只摘这一个
  "要盯着读数看"的钮。若用户要的是"全站按压都不许动内容"，那是另一票（全站观感），不在本票里顺手改。

## 锁测

jsdom 既没有布局引擎也没有重采样（`getBoundingClientRect()` 恒 0）⇒ 这条现象**只在真渲染里存在**，
故走静态源码断言 + Playwright 逐帧实测（照票 15 / 26 惯例）。

- 新增 `tests/static/PreviewRatePressNoMove.test.ts`（3 条）：
  1. `.pv-rate .icon-btn:active` 必须把 `transform` 钉成 `none`；
  2. 同一条规则里必须还有 `background-color`，且是 `color-mix(... var(--bg-hover) ... var(--text) ...)`
     —— 防"把几何反馈摘掉后顺手连反馈一起删了"，也防色值硬编码 / 只对一种主题生效；
  3. `src/ui/ui.css` 的全站 `.icon-btn:active { transform: scale(0.98) }` 仍在（本票只摘一个钮）。
- TDD：先落锁测（撤掉实现时 2 条红，恢复后 3 条绿，已跑通红-绿）。
- 几何实测脚本一次性留在 `.cache/`（`pv-press-28.mjs` 逐帧 + 祖先链，`pv-press-ancestors.mjs` 排掉"滚动 / 祖先位移"的可能，`pv-press-dpr28.mjs` DPR 1 / 1.25 / 2 墨迹质心，`pv-verify-28-press.mjs` 修后复验 + 冒烟），不入 git。

## Comments

- 2026-10-09 根因调研（第一版）：量到的现象是**另一个真实但用户没报的问题** —— 触钮在播放条里是**右锚**的
  （`[播放][时间码][进度条 flex:1][倍速][音量]` ⇒ 钮与音量一起贴右缘），钮宽随读数变 ⇒ **改一次倍速、
  读数一变宽，钮连同图标整体左移**（实测 `1×` 钮宽 55 → `1.5×` 64 时移 9.3px、→ `0.25×` 74 时移 19px，
  进度条被顶掉同样宽）。第一版修法（给读数留 `0.25×` 的固定槽位 `min-width: 2.64em`）把这个现象治了，
  但**不是用户报的那一下**：用户复验"没有任何变化"，按用户指示**已整段回退**（读数槽位 + 那份锁测文件）。
  - 该现象的实测数据保留在此备查：`1×`(55) / `1.5×`(64) / `0.5×`(67) / `0.75×`(72) / `1.25×`(71) /
    `0.25×`(74) / `2×`(58)，钮 x 随之 1729 → 1720 / 1717 / 1712 / 1713 / 1710 / 1726；进度条右缘恒为 `钮 x − 10`。
    若日后要治它，取舍是"钮恒宽 74px + 进度条短 19px"换"四者全不动"（备选：把钮挪到进度条左边，
    代价是进度条左端跟着读数走）。
- 2026-10-09 根因调研（第二版，用户把现象说准后）：逐帧 + 祖先链一起量 ⇒ 按住期间**只有钮自己的
  `transform: scale(0.98)` 在变**，没有滚动、没有祖先位移；再按 DPR 1 / 1.25 / 2 量**墨迹质心**，
  坐实"重采样跳一下"的方向与幅度（见症状表）—— 与用户"往斜上、松开复位"的描述一致。
- 顺手核过并**不动**的两条：① 按住时面板在 **mousedown** 就展开（不是 click）—— 实测面板是绝对定位、
  不影响任何几何；② 面板自身的入场动效（`translateY(6px)` 那记）不在本票范围。
- 未动的钮：工具栏「全屏」及同排 / 播放钮仍吃全站 `scale(0.98)`（本票只摘倍速这一枚；要动是全站另一票，
  口径 = `.preview-controls .icon-btn:active` 同款 `transform: none` + 按压色）。
- 全屏台上态（进全屏后再量）同款三态复验通过：盒恒等、按压色随台上 `--bg-hover` / `--text` 变。

**Playwright 复验（`.cache/pv-verify-28-press.mjs`，1600×900）**

| | 钮 x,y / 宽×高 | 图标 x,y | transform | 底色 |
|---|---|---|---|---|
| 静止 | 1409.00,862.50 / 55.00×27.00 | 1418.00,868.50 | none | `rgba(0,0,0,0)` |
| hover | 同上 | 同上 | none | `rgb(238,240,243)` |
| 按住 | **同上** | **同上** | none | `rgb(213,216,220)`（按压色） |
| 松开 | **同上** | **同上** | none | `rgb(238,240,243)` |

- 四态**逐像素同盒**（钮 / 图标 rect 完全相同）；图标墨迹质心按住时 Δ = (0.08, 0.07)（DPR 1）/ (−0.11, 0.03)（DPR 2）
  —— 是"底色变深 ⇒ 抗锯齿边像素归属略变"的量测噪声（墨迹 bbox 不变），修前是 0.47 / 0.92 的**真实位移**。
- 按压反馈还在：三态底色各不相同（透明 → hover → 更深一档），mousedown 仍能看清"按下了"。
- 冒烟：mousedown 仍展开面板、点 `1.5×` 仍改值并收起面板 ✓。

`npm test` **217 文件 / 2,396 例全绿**；`npx tsc -b` 无错。
