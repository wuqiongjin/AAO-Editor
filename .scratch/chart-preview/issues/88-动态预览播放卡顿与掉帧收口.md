## 本轮实现口径（待验收）

> 说明：以下为满足既有定案（[ADR-0016 §5.3](../../../docs/adr/0016-谱面预览与游戏仿真导出.md)、[ADR-0017](../../../docs/adr/0017-预览高DPR位图密度与多级降采样.md)、[票 72](./72-官方HUD顶栏分数生命与暂停.md) `+inc` 不合并、[票 80](./80-动态预览清晰度与播放流畅度整改.md) 清晰度与流畅度目标、[票 85](./85-动态预览调设置误出加载态.md) 进全屏不出加载态、[票 87](./87-播放中全屏与浮层卡顿.md) 全屏当帧不卡主线程）的技术实现方案，**均严格保持画面语义等价，不冒充用户新定案**。

### 阶段 1 · 回退清零与布局隔离（解决 RC4 + RC5）

1. **全屏无关的 `scoreFill` 双端（缩小 + 放大）着色器预热（`prepareSimRendering.ts`）**：
   - 保持票 85 的 `simRenderingWarmupKey(density, assets, gpu)` 不含 CSS 尺寸（进出全屏绝不重跑预热、不弹加载遮罩）。
   - 在 `prepareSimRendering` 内部确保无论当前首进 `input.metrics` 多小，除了按当前尺寸跑代表帧外，对 `scoreFill` + 圆角 `clip()` 显式补齐物理目标宽 `< srcW`（缩小采样）与 `> srcW`（至少按 `1920` 设计宽 × `density` 的放大采样）两档绘制 + 1px 回读落定，彻底消除窗口首进后再切全屏的中途编译卡顿。
2. **退出全屏后的延迟回缩，消除窗口态永久超分渲染（`simPlayback.ts` / `simBandGpu.ts`）**：
   - 保留票 87「`ResizeObserver` 触发当帧不改画布尺寸、不挡当前帧」的机制；当目标尺寸变小且 `queueSizeBake` 让出主线程完成目标尺寸底图准备后，将 `.pv-field__canvas` 与 WebGL 带体画布同步收回当前目标物理像素 `bw × bh`，恢复窗口态 `1:1` 整数像素对位（ADR-0017）与窗口态原始帧耗。
3. **`PlayBar` 布局隔离（`PlayBar.css` / `PreviewPage.css`）**：
   - 给 `.play-bar`（及时间码读数盒）补齐 `contain: layout style`（或在不裁切倍速/音量弹出层的前提下对内部进度与时间码区做 `contain: layout paint` + `font-variant-numeric: tabular-nums` 固定宽度），阻断每 `80ms` `setTick` 标脏 `#document` 271 个节点引起的 `50ms+` Layout 尖峰。

### 阶段 2 · 高密击打段 CPU 与 Skia 命令流减负（解决 RC3，逐像素等价）

1. **隔离 `CanvasSpriteIcon` 采样质量并消除每音符热路径分配（`CanvasSpriteIcon.tsx`）**：
   - 在 `CanvasSpriteIcon.render` 内保存并恢复 `ctx.imageSmoothingQuality`（或仅在音符自身 `drawImage` 期间局部生效），严禁 `'high'` 泄漏到同帧 600+ 次粒子光晕、按住环、顶栏切片与 COMBO 辉光。
   - 移除每颗音符调用 `ctx.getTransform()` 产生 `DOMMatrix` GC 对象的热路径，改由调用方传入有效缩放因子（或仅在未提供时兜底读取）；`decorators` 为空或未传时直接短路跳过两次 `.filter().sort()` 数组分配。
2. **`drawPlus`（`+增量`）离屏字形贴片缓存（`simField.ts`）**：
   - 严守票 72 用户定案（「窗口内每次命中各画一条 `+inc`，不限流合并，两段冲刺+缓移淡出轨迹不变」）。
   - 同一谱面 `inc` 固定、当前场地 `fontPx = SIM_HUD.plusFont * s` 固定：在 `prepareSim*` / 尺寸档缓存中预烘一张带描边与填充的 `+${inc}` 离屏贴片，逐帧百余条命中由 `strokeText + fillText` 改为轻量 `drawImage` + `globalAlpha`，将 `drawPlus` CPU 与 Skia 路径光栅化耗时压降一个数量级。
3. **`drawLaneFlash` 同轨同帧光学等价归并（`simField.ts`）**：
   - 同一帧内落在同一轨道 `lane ∈ [0..6]` 的多次命中，几何路径完全重合且均为纯白 `rgba(255,255,255, a_i)` 到 `0` 的竖向渐变。按 Porter-Duff `source-over` 合成公式 `A(t) = 1 - Π(1 - t·a_i)` 在多段渐变控制点（如 `t = 0, 0.25, 0.5, 0.75, 1`）精确拟合单条渐变，将单帧 `50+` 次全高斜切三角形渐变填充压缩到 **至多 7 次**（每轨至多 1 次），8-bit 像素误差 `≤ 1/255`。
4. **`drawSimultaneousLines` 二分窗口裁剪（`simField.ts`）**：
   - 对已按 `time` 升序排列的 `chart.simultaneous` 改用二分查找定位 `[seconds, seconds + T]`，消除长谱每帧全表扫描。

### 阶段 3 · WebGL 带体缓冲复用与跨上下文同步消减（解决 RC2）

1. **VBO 容量几何扩容 + `gl.bufferSubData` 复用（`simBandGpu.ts`）**：
   - 不再每帧 `gl.bufferData(..., STREAM_DRAW)` 重新申请缓冲；改为追踪 GPU VBO 当前字节容量，仅在容量不足时按几何级数扩容 `gl.bufferData(..., DYNAMIC_DRAW)`，常规帧一律 `gl.bufferSubData(gl.ARRAY_BUFFER, 0, view)` 更新有效区间，消除 D3D11 每帧孤立/分配 staging buffer 的驱动停顿。
   - 空带体帧（当前可见窗口无带体段）直接短路跳过 WebGL 绘制与 `ctx.drawImage(glCanvas)` 跨上下文拷贝（确保离线导出与实时回放行为一致）。
2. **跨上下文同步复测与备选分层评估**：
   - 完成上述 VBO 复用与阶段 4 内存减压后，在双工程整曲复测 `CommandBufferService:PutChanged` 是否清零；若仍有残余跨上下文等待，再评估实时舞台将带体 WebGL 画布作为独立透明合成层夹在「底图 canvas」与「音符/特效/HUD canvas」之间（离线视频导出仍走单画布 `drawSimFrameAt` 合成），不提前引入多余 DOM 层。

### 阶段 4 · 保活显存/内存瘦身与运行入口理顺（解决 RC1）

1. **非活跃画布后备缓冲按需回收与缓存封顶**：
   - 静态预览 / 工作台切离或进入动态预览播放时，在**不破坏票 70「静态↔动态切换体验」与既有锁测**的前提下，梳理并释放非活跃巨幅 Canvas 的 GPU 后备存储（例如未打开静态预览时不预占，或失活页回收可无损瞬时重绘的瓦片缓存如工作台 `noteLayerCache`；动态预览自身在全屏过渡落定后收敛多余尺寸档 `fieldBitmaps` / `lifeGauge` / `comboShadows` 上限），把渲染进程 + GPU 进程常驻显存压回安全水位，避免 8GB 物理内存机器频繁跌破 Windows 内存压力阈值。
2. **`electron:dev` 空跑 Vite 进程问题排查与入口对齐（`package.json` / `electron/main.cjs`）**：
   - 当前 `npm run build && npm run electron:dev` 下 `electron .` 实际加载 `dist/index.html`，却并行挂着整套 `vite` 开发服务器白占数百 MB 内存。实现前与用户确认脚本口径（例如新增纯跑构建产物的 `electron:preview` / `electron:prod`，并修正 `electron:dev` 传入开发态环境变量且遵循 `AGENTS.md` 的 `scripts/dev.sh` 规范）。
