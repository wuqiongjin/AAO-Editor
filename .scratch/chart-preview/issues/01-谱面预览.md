# 01-谱面预览

Type: feature
Status: resolved
Blocked by: architecture-refactor/03（已解：03 + 08 均 resolved）

## 能力目标

谱面作者需要在编辑器画布之外，**看到 / 导出**自己的谱面。重点服务"观赏性谱面"作者，他们对预览的核心要求是：**流畅、可定制、便捷、快速**。

本能力大致有两个方向（具体范围与先后待定，开工时再细化）：

- **静态长图预览**：整首谱面切片分栏，离屏全景导出为长图，用于分享 / 审阅；
- **动态视频预览**：游戏仿真回放 + 时间轴帧录制 + 视频导出。

## 前置事实

- 仓库当前**无任何**预览 / 导出成图代码（`src/preview/` 不存在）。
- `docs/adr/` 尚无预览相关架构约定；静态分栏算法、离屏 Canvas 大图尺寸上限、视频录制方案（WebCodecs / MediaRecorder / Electron）均待实现时定案。
- 依赖 `architecture-refactor/03` 合并后的 `src/rendering/index.ts` 作为唯一绘制入口。

## 落点（待细化）

- 新增 `src/preview/` 顶层域，按子能力划分子目录（如 `static/` 静态长图、`video/` 动态视频），各自立骨架与类型契约；
- 依赖规则：`preview → rendering / chart / audio / playback` 单向；`chart` / `rendering` / `playback` 不得 import `preview`；`preview` 不得 import `pages/`；
- 具体子能力、先后顺序、视频录制方案等，待开工时结合需求细化，不在本票预先写死。

## 锁测要求

- 实现时保证新增骨架通过 `npx tsc -b`，既有 `npm test`（164 文件 / 1919 用例）保持全绿（新目录无存量引用）。
- 具体单测 / 替代验证（Playwright 像素实测、手工验收清单等）随子能力细化时一并定义。

**事实修正（原正文三处过期）**

- 「Blocked by architecture-refactor/03」**已解**：03 + 08 均已 resolved，`src/rendering/index.ts` 是唯一绘制入口，`createRenderTarget` / `frameFor` / `renderFrame` 即"任意片段出帧"的地基（文件头注释本就写着"离屏导出 / 未来预览各建自己的 target"）。
- 「既有 `npm test` 164 文件 / 1919 用例」过期：2026-09-30 实测 **183 文件 / 2028 用例全绿**。
- 「动态视频预览 = 游戏仿真回放 + 帧录制」并**不是**从零开始：自动回放的时钟（`AudioEngine` 双时钟 + 合成时间线）、判定线贴底滚动、键音预调度、视口会话（`useChartViewSession` 头注已写明"将来的预览页 consume 同一 interface"）都已存在。真正从零的是：只读预览页壳、仿真场画面、导出链路。
- Bestdori 参照事实（bundle `CommunityChartsNew.b534f9a9.js`，sha256 `face219f2ca5…7394e4` 与既有 research 笔记同一份）：静态预览 = **时间竖切 → 面板横排 → 横向滚动 + 懒绘制**（不是一次画巨图，也没有任何图片导出）；它的"视频"是实时模拟器，**无导出**（bundle 内 `MediaRecorder` / `captureStream` / `VideoEncoder` / `toBlob` 各 0 处）。

**定案（用户 2026-09-30，七答）**

1. **静态预览形态** = Bestdori 式**面板折行**（时间竖切 → 面板横排 → 横向滚动 + 懒绘制）；**长图导出复用同一份面板模型**，但不是主要目标（谱师要反复看，长图不方便）。
2. **动态预览画面** = **游戏仿真场**（不做"编辑器观感"的过渡档；"把 B 拆成子任务各自实现"获准）。首期对标 Bestdori 模拟器：场地 + 音符 + 带体 + 程序化打击特效 + combo HUD + 键音；**不含**判定文字 / 分数。
3. **视频导出** = **离线逐帧 + 含音频**（固定帧率离屏出帧 → WebCodecs 编码 → 封装；音轨离线渲染合成）。
4. **入口载体** = **独立应用页面**，页面作用域绑「工程 + 谱面」（`chartId` 二级 scope 落地）。
5. **静态面板观感** = **复用编辑器渲染 + 预览显示档**（同一渲染入口 + 一组预览专用 display 覆盖，默认精简网格 / 沟槽细节，可手动开）。
6. **仿真场素材口径** = **扩展归档 + 开发期直读本地归档**（`docs/resource/bestdori/`，不入 git、不进安装包）；打包 / 运行时拉取方案留后票。
7. **未来扩展**（用户："纳入计划、具体做哪些到时候再定"）：判定文字 / 分数 / 技能 / fever 表现、自定义背景图 / 背景视频。

**落点与拆分**：02 预览页壳与入口 · 03 静态预览面板折行 + 长图导出 · 04 仿真场素材归档 · 05 仿真场渲染器 · 06 导出链路与尺寸实测（research）· 07 视频导出。依赖方向沿用本票原定：`src/preview/` 单向依赖 `rendering / chart / audio / playback`，**不 import `pages/`**；页面落 `src/pages/preview/`。

**架构约定**：落 **ADR-0016《谱面预览与游戏仿真导出》**（2026-09-30，用户拍板"适合做就写"）——形态两类、域落点与依赖方向、作用域二级 `chartId`（修订 ADR-0015 §6）、离线导出链路、**素材边界与稳定获取口径**、长图导出与二进制落盘通道。CONTEXT.md 已补对应词条表。
