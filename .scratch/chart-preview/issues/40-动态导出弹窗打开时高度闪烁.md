# 40 · 动态导出弹窗打开时高度闪烁

Type: bug
Status: resolved
Blocked by: none

## 来源与症状

用户反馈：
动态预览的导出按钮，点击一下弹出的弹窗，感觉会先闪一下（可能是先伸长一些然后又收缩的感觉），然后才展示出最终的弹窗形态（肉眼很难观察）。

## 根因

1. **探测状态占位导致高度瞬态突变**：
   - 用户点击动态导出按钮时，`VideoExportControl` 会调用 `onProbe()` 触发 `useVideoExport` 的 `probe()`；
   - `probe()` 同步将 `probing` 设为 `true`，此时弹窗同步打开渲染第一帧；
   - 在 `VideoExportControl.tsx` 的 `outcomeNote` 中，包含逻辑 `if (probing) return t('preview.video.export.note.probing');`；
   - 导致打开弹窗的第一帧内渲染了 `<p className="pvex__note">正在检测这台电脑支持的格式…</p>`，弹窗被纵向撑高约 24.5px；
   - 现代浏览器对 `VideoEncoder.isConfigSupported` 等探测 API 响应极快（通常在 10ms ~ 50ms 内完成）；
   - 探测异步完成后，现代主流浏览器均支持 MP4 + AAC（正常规格），此时 `outcomeNote` 判定无兼容性异常，返回 `null`，且 `probing` 变为 `false`；
   - React 重新渲染，`<p className="pvex__note">` 节点被直接移除，弹窗高度瞬间收缩约 24.5px。
2. **每次打开重复触发探测**：
   - `onClick` 中每次 `!open` 打开面板都会调用 `onProbe()`，`useVideoExport` 每次都会置 `probing: true`，导致每次点击展开弹窗都会经历一次“伸长约 24px -> 几十毫秒后收缩 24px”的视觉闪烁。

## 修法

1. **探测中不占行（静默探测）**：
   - 恪守 Issue 07 原定案「常识不占行，探不出结论不占位；没有结论就不出现这一行：不许再有“尚未检测”这类占位文案」的口径；
   - `outcomeNote` 中将探测中（`probing`）和尚未得出结论（`!support`）统一保持返回 `null`；
   - 仅在探测真正完成且得出非理想结论（不支持、自动降级 WebM、MP4 包含 Opus 兼容警告）时才渲染说明行；
   - 清理中英文语言包中废弃的 `preview.video.export.note.probing` 键。

## 锁测

- `tests/dom/preview/VideoExportFlow.test.tsx`：
  - 断言 `probing` 状态下不应渲染临时占位文案，`.pvex__note` 保持为 null；
  - 模拟真实组件时序：从 `probing` 触发到解析出正常规格（MP4+AAC），全程无说明行挂载与卸载，彻底消除高度跳变。
- `tests/static/VideoExportWiring.test.ts`：
  - 静态断言 `zh['preview.video.export.note.probing']` 为 `undefined`，禁止未来重新引入探测占位文案。
