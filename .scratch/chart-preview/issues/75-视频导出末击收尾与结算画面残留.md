# 75 · 视频导出末击收尾与结算画面残留（含末拍键音）

Type: grilling
Status: open（2026-11-14 定案收口；待实现 + 待用户导出成片验收）
Blocked by: 74
Related: [票 52](./52-谱面结束中央章与结算画面.md), [票 73](./73-结算画面分数与SCORE-RANK适配.md), [票 74](./74-视频导出开头前导补偿.md)

## 来源与症状

用户 2026-11-14 报：末音符落在谱面最后一个 beat 时，导出的 `ALL PERFECT!` / 结算画面下仍残留一整排谱面与绿色打击环；同轮追加「末拍的键音被吞肯定要修的」。

## 根因

- `frameDriver.ts:107` `endingAt = O + D`；`:108-119` `stage.seconds` 钉死为 `D`；`endingFrame.ts:694-700` **每个结尾帧**都按这个固定秒重画 `drawSimFrameAt`（`frameDriver.ts:108`「缓存位图」注释已过时）⇒ 末拍音符（`Δ=0` 仍画）、命中特效（`since=0`）、按住环 / 带体被冻结 7.5s。不是画布未清（每帧全屏 `fillRect`）；`SimFrameLayers`（`simField.ts:550-563`）没有 notes / bands / effects 开关，结尾只淡出轨道与 combo。黑幕只在 `t'≈3–4s` 满黑，抬幕后结算 UI 不铺整屏底色 ⇒ 冻结舞台重新露出。
- `renderAudioTrack.ts:208` 过滤 `evt.time >= req.durationSeconds` ⇒ 末音符恰在 `D`（= 音频时长）时键音被丢，画面却画满强度命中特效。

## 修法（2026-11-14 定案，待实现 / 待成片验收）

1. `lastHit = max(chart.elements 末尾 time, max(band.t0,t1), max(simultaneous.time))`；`tail = ceilToFrame(max(0, lastHit + life − D))`，`life = max(SIM_SPRITE_EFFECT_DURATION 0.6, SIM_JUDGE.life 1.0) = 1.0s`。末音符贴 `D` ⇒ tail ≈1s；谱面比音频短 ⇒ tail = 0。`life` 与公式只在 `exportSpec.ts` 定义一次，验收后可调。
2. `endingAt = simStart(74) + D + tail`；尾段沿用同一条 `seconds = t − simStart`，让最后一击的特效 / 判定字自然播完再切结算（用户口径「所有音符的打击特效都结束后，再真正进入结尾画面」）。`endingSfxCues` 的 `at` 后移到新 `endingAt`，轨长同步。**总长增加 `tail`（末击贴 `D` 时约 1s），`ENDING_SECONDS = 7.5` 与三段结构不动。**
3. 结尾舞台 `stage.seconds` 改为 `D + tail`（或 `lastHit + life + 1/fps`）⇒ 各层按既有窗口自然判空，舞台只剩背景 + 轨道（轨道按 `trackFadeDur: 1` 淡出）；**不给 `SimFrameLayers` 加 notes / effects alpha**，不做逐层淡出。
4. 键音过滤放宽到 `evt.time > D + tail`（至少 `> D`），末拍键音不再被吞；不改 `buildKeyEvents`。
5. 不改实时预览；开场人潮 SE 不动（见票 74 定案 3）。
6. **调参入口单一**：`life` / `tail` 公式一处定义，`endingAt` 与 `stage.seconds` 都由它派生。成片验收后若仍见残留或尾段偏长，只调 `life` 或公式，不动帧循环、`drawSimFrameAt`、结算三段动画与素材；锁测按公式写，改数值只改期望值。

## 锁测

1. `tests/unit/preview/video/EndingFrame.test.ts`（`stage.seconds` / 三段时长）、`ExportTimeline.test.ts`（总长 / 末帧）、`tests/static/VideoExportWiring.test.ts`（`endingAt` 接线）、音轨侧轨外过滤用例需同步；新增「末拍 `evt.time === D` 必发声」「`stage.seconds > lastHit + 0.6`」「tail 随末音符位置变化」「`ENDING_SECONDS` 仍为 7.5」断言。
2. Canvas 像素（结算下是否有残留环）与真实成片单测到不了 ⇒ **手工验收**：末音符贴 `D` 的谱导一条，`ALL PERFECT` 与结算白卡下无音符 / 绿环、末拍键音有声、结尾 SE 落在结算第一帧；再导末音符早于 `D−2s` 的一条确认 tail=0、总长不变；关掉结尾画面的一条确认视频末尾是干净场地。**验收结论回填 `## Comments`；观感不对只调 `life`。**

## Comments

- 2026-11-14 用户原话：「结尾也需不需要太补时长，只要保证不出现当前这种BUG就行了，说白了就是所有音符的打击特效都结束后，再真正进入结尾画面」「末拍的键音被吞肯定要修的」。
- 与票 74 共用 `simStart` / `endingAt` 改造，本票不先行；`life` 取 1.0s 而非 0.6s 是为让 `SIM_JUDGE.life`（判定字）也自然收完，切结算时零突变。
- 2026-11-14 用户复核提问：「结尾的设计也是补偿时间吗？(只针对末音符贴最后beat来判断的?)」
  - 是补时长，但性质与开头不同：开头 lead-in 是让首音符**提前出现**，结尾 tail 是让最后一击的特效 / 判定字**播完**再切结算。尾段画面继续推进（特效在衰减），不是空白，只是 BGM 已结束所以静音；且 tail 可能为 0，不是无条件补。
  - 判据不是「末音符贴最后 beat」这个布尔，而是连续量 `tail = max(0, lastHit + 1.0s − D)`：`lastHit` = 最后可击打物的**绝对秒**（含滑条结点 / 带体端点 / 双押线，不是 beat 序号），`D` = 谱面长度（音频时长），1.0s = `max(SIM_SPRITE_EFFECT_DURATION 0.6, SIM_JUDGE.life 1.0)`。例：末击 = `D` → 1.0s；= `D−0.3` → 0.7s；= `D−1.2` → 0s；> `D` → >1.0s。用户遇到的「贴最后 beat」只是 `D` 恰等于末击时刻的特例。
  - 曾列替代案「把结算 7.5s 的头 1s 让给特效收尾，总长不变、结算动画整体顺延」（会改 ADR-0016 §5.2 三段时长）。**2026-11-14 用户拍板「先按照你的来吧」⇒ 按现行方案：补 tail、保持 7.5s 结算结构，不改 ADR 三段时长；替代案作废。** 本轮未写代码。
