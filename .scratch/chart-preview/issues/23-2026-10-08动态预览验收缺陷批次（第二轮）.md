### #1 · 带体的"播放"感不对：过线一端被钉死在原结点轨位 — Status: 待实现

- **症状**（用户）："当前滑条的播放机制存在问题…它不是在播放滑条，而是感觉像是把滑条的尾部折叠到播放线的后面"。
- **根因（坐实）**：Bestdori 画带体时，**过线那一端会沿着带子继续行进**（轨位按时间插值），只有垂直位置钉在判定线上：

```js
// CommunityChartsNew bundle，动态仿真场 drawCanvas 的带体段
O = e > w.from.time ? 1 : this.approach(e, w.from.time)                  // 过线后 A 钉 1
L = (e > w.from.time
  ? w.from.lane + (w.to.lane - w.from.lane) * (e - w.from.time) / (w.to.time - w.from.time)
  : w.from.lane) * d                                                     // ← 接触点沿带子往未过线端移动
moveTo((L + u / 2) * O, O) … lineTo((N ± u / 2) * P, P)                  // P = approach(e, w.to.time)
```

  我方 `simField.drawBands` + `simGeometry.bandQuad`：过线端只做 `clampApproach`（A 钉 1），**轨位永远是该结点的原始 `lane0`** ⇒ 横向移动的滑条看起来是"整条被折回头部结点那条轨"，而不是"接触点沿带子扫过去"。同一个插值我们其实已经实现过一次 —— `drawHoldEffects` 的按住位就是 `lane0 + (lane1 − lane0)·(seconds − t0)/(t1 − t0)`（照 bundle 的 `y.push(L)`），只是没用在带体几何上。
- **修法**：`drawBands` 在 `seconds > min(t0, t1)` 时，把"已过线的那一端"换成沿带子插值出来的轨位、`a = 1`；`bandQuad` 的接口不变（它只负责把两端 `(lane, A)` 变成四边形）。**边界**：`t1 === t0` 按同轨处理、不除零；倒流 / 折返段按 `min/max` 段判定，与 `drawHoldEffects` 同口径。
- **锁测**：
  - `tests/unit/preview/video/SimField.test.ts` 增三例 —— ① 横向滑条在 `t0 + 0.1s / +0.2s / +0.3s` 三帧，四边形"已过线端"的 x **单调趋近未过线端的 lane**（旧写法原地不动 ⇒ 必红）；② `t1 === t0` 不除零、不出 NaN；③ 同一秒里带体顶点 x 与 `drawHoldEffects` 的按住位置一致（同一个公式，不许两份实现）。
  - 像素：`scripts/sim-shot.mjs` 取同一条跨轨 `Slide` 在过线后的三帧，人工核对"接触点沿线移动"。

### #2 · 音符不贴合舞台倾角（画成了正圆） — Status: 待实现

- **症状**（用户，附 Bestdori 对照图）：Bestdori 的音符是**扁椭圆**（贴着倾斜的舞台），我们是**正圆**。
- **根因（坐实）**：Bestdori 的那次 `setTransform` 是**非等比**的（x 缩 `laneWidth·A`、y 缩 `laneHeight·A`，两者不等），所以音符高度做了反向补偿，屏上纵横比 = 精灵自然比 **308:120 = 2.567**：

```js
var i = this.laneWidth / this.laneHeight,                 // ← 补偿因子
    a = 1.35 * this.styleNoteSize,                        // 音符宽（场地单位）
    s = 120 * a / 308 * i;                                // 音符高 = 宽 × 精灵自然比 × i
this.ctx.setTransform(this.laneWidth * A, 0, 0, this.laneHeight * A, this.canvasWidth / 2, 0);
```

  我方走 `simSpriteScale` + `noteMetrics` 的 `NOTE_ICON_SIZE`(36) × `NOTE_HEIGHT_SCALE`(0.6) = **36 × 21.6（比 1.667）** ⇒ 纵向被拉高约 **1.54 倍**，素材自带"扁椭圆 = 贴合倾角"被拉成了正圆。**这条正是票 18「附带观测 ①」**（当时登记"本轮不改"），用户验收坐实后升格为正式缺陷。
- **修法（本轮口径）**：
  1. 音符：宽 = `1.35 × noteSize × laneWidth × A`（口径不变），**高 = 宽 × 精灵矩形自身的比例**（`icon.out` 的 `h / w`；缺失则回落 `120/308`）。新几何进 `simGeometry`（如 `simNoteRect(m, a, noteSize, spriteRatio)`），`simField` 只消费 —— 延续票 18 定的"几何只在 simGeometry"。
  2. 顺带修票 18 登记的同族两条（用户 2026-10-07 拍板 Q4 = **一起修**）：**② 同时点击线粗细** —— 现为 `0.3 × noteSize × laneWidth × A`（约为 Bestdori 的 2.5 倍粗）且逐 gap 一根，改照 Bestdori 的约 `0.118` 系数量级、**一根跨全程**（`lane..lane+width`）；**③ 背景图取景** —— 现为 cover 居中裁两侧，改照 Bestdori `1.32W × 1.0065W`、上缘锚 `-0.176H`。
- **锁测**：
  - `tests/unit/preview/video/SimGeometry.test.ts` 增例：`simNoteRect` 的字面断言（宽 = `1.35·noteSize·laneWidth·A`；高/宽 = 传入的精灵比例；缺失回落 `120/308`）。
  - `tests/unit/preview/video/SimField.test.ts` 既有 8 例里凡断言旧 36×21.6 高度的要同步更新（同一轮改完必须全绿）。
  - `tests/static/SimRendererWiring.test.ts` 增例：同时点击线的绘制必须走新函数（禁再出现 `0.3 *` 字面量）。
  - 像素：用 `.cache` 里的像素工具量命中帧音符的外接矩形宽高比 ≈ **2.567 ± 0.05**（修前约 1.667）。

### #3 · 全屏后播放条基本不可用（播放钮看不见、倍速控件诡异） — Status: 待实现

- **症状**（用户）："全屏后，还看不见播放按钮了，并且这个倍速的样式也很诡异。说白了全屏后的播放条样式都需要优化。"
- **根因（高置信，源码序 + 配色）**：
  1. 全屏元素是 `.preview-stage`（`PreviewPage.tsx` 的 `stageRef`），`.pv-bar` 在它**内部** ⇒ 播放条没有消失，是**看不见**。
  2. **底色规则被覆盖**：`.preview-stage:fullscreen`（`PreviewPage.css:172`）给了 `background: var(--canvas-bg)`，但排在它**后面**的 `.preview-stage.is-filled { background: none }`（`:442`）特异性相同（都是 0-2-0，`:fullscreen` 不额外加分），按源码序胜出 ⇒ 全屏下画面之外那条播放条区域是"透明 + UA 黑色 backdrop"。
  3. **前景配色跟主题走**：播放条文字 / 图标吃 `--text` / `--text-muted`；亮色主题下这两项是深色 ⇒ 黑底深字 = 看不见。倍速那块是原生 `<select class="select-control">`（亮色表单皮肤 + `max-width: 84px`）⇒ 同一条上又多一块不搭的控件。（倍速控件的本体重做归票 20「验收回修 #2」，本条只管全屏态的壳与配色。）
- **修法（本轮口径）**：
  1. 全屏规则排到 `.is-filled` 之后（或提高一级特异性），让 `:fullscreen` 那条真的生效；全屏态给 `.pv-bar` **自己的一套配色**（深底 + 白字），不随亮 / 暗主题翻。
  2. 全屏下**保留底部播放条**（用户 2026-10-07 拍板 Q3 = OK）—— 与静态预览"全屏控件整排退场"（票 12）是两个形态各自的口径，动态形态记下这条例外。
- **锁测**：
  - `tests/static/PreviewPageWiring.test.ts` 增静态断言：`.preview-stage:fullscreen` 的底色规则必须排在 `.preview-stage.is-filled` 之后；全屏态 `.pv-bar` 的配色类（例：`.pv-bar--onstage`）不依赖主题变量。
  - DOM：`tests/dom/preview/PreviewVideoControls.test.tsx` 增一例 —— 舞台处于全屏（stub `document.fullscreenElement`）时 `.pv-bar` 仍在 DOM 且带全屏配色类。
  - 手工：**亮 / 暗两主题**各进一次全屏复验 —— 这条的根因是"依赖页面底色 + 主题前景"，单测只能钉规则，钉不到观感。
