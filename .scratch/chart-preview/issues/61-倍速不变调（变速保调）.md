## 现状（事实）

- `src/audio/AudioEngine.ts:424-429` 用 `AudioBufferSourceNode.playbackRate` 调速，`:344` / `:493`
  （播放中 load、seek 重建源）与 `:173`（运行中改速率）同样只设这个值。WebAudio 语义下这是
  **重采样**：非 1× 会连带升 / 降调。
- 全仓 `preservesPitch` / `detune` / `timeStretch` / `pitchShift` / 相位声码器 **0 命中**；
  `AudioEngine.ts:82-90,511-523` 的时钟与键音调度已按 rate 换算，音画同步不依赖音高。
- 仓库此前没有这条定案或票：最接近的是 [20](./20-动态预览播放器控件.md):96,132,174 与
  `tests/dom/preview/PreviewVideoControls.test.tsx:7` 把「倍速听感」列为**人工验收项**（未闭环）。
- 视频导出 `src/preview/video/encode/renderAudioTrack.ts` 不吃 rate ⇒ 导出物不变调（本票也不改它）。

## 约束（来自 58 / 59）

修复只能落在 **`src/audio/` 的单一层**（`AudioEngine` 或其下的共享 DSP 模块），
工作台播放条、动态预览播放条、静态/离线链路只持有**倍速数值**，不得各自实现一套补偿；
倍速值的唯一来源见 [59](./59-倍速数值的保存与共用口径.md)，倍速 UI 共用见
[58](./58-谱面画布倍速播放与控件共用.md)。

## 实现前要拍板（不占用本轮 grill）

- 保调手段：WebAudio 原生无 time-stretch，是引第三方 DSP / 自写相位声码器，还是只做
  「BGM 保调、键音不保」的折中；
- 键音采样是否也要保调（`src/audio/keySoundSamples.ts` 的固定包络 0.9 / 0.12）；
- 是否提供「变速同时变调」开关（游戏 / DAW 常见），默认值；
- 延迟与 CPU：实时回放 0.1..4× 范围内是否满足，离线导出是否跟随；
- 与 `PLAYBACK_RATE_RANGE` 的边界（极低 0.1× 的artifacts）。

## 锁测（实现前补齐，当前票仅跟踪）

候选落点：`tests/unit/audio/AudioEnginePlaybackRate.test.ts`（音画同步 / 不跳位置 / rate=1 行为**不回退**）
+ 保调链路的源码接线断言（照 `tests/static/EditorAudioSessionRefactor.test.ts` 惯例）。
**听感 / 音高单测盖不到** ⇒ 实现时用频谱脚本或 Playwright 录音实测（0.5× / 2× 下 BGM 基频不变）
+ 手工验收清单；理由：音高判据是信号域量，不是 DOM / 状态断言。
