# 39 · 曲目信息片头乐队字号与可选附加字段兼容

Type: feature
Status: resolved（用户 2026-10-11 拍板方案 B 并落地）
Blocked by: none

## 来源与诉求

2026-10-11 用户提需求（附游戏内参考截图）：「继续调整一下曲目信息片头的 乐队的文字大小，让大小再小一点。便于后续追加新的字段。后续可能追加的字段有(这些子段的字体要比上面的 乐队文字还要小一点)：作词：xxx、作曲：xxx、编曲：xxx、谱师：xxx。刚才提到的 4 个字段，未来都是"可选"的，每首歌曲不一定会有几个字段。(现在要提前做好兼容)」。

## 定案（用户 2026-10-11 拍板）

1. **采纳方案 B（首字对齐块居中，`left-block`）**：
   - 乐队文字大小：下调至 **`0.030 H`**（相比原 `0.040 H` 下调 25%，为下方腾出空间并拉开层级）；
   - 追加字段文字大小：**`0.022 H`**（比乐队更小，与难度徽章同级，字重 400）；
   - 间距：白条底 → 乐队 `0.022 H`；乐队底 → 附加字段块 `0.016 H`；
   - 附加字段行高倍率：`1.40x`（紧凑行高，确保容纳 4 行仍留白从容）；
   - 排版：整个附加字段区域在中轴居中，内部多行统一左对齐，首字“作词/作曲/编曲/谱师”在一条垂线上严格对齐。
2. **4 个附加字段全可选与空项不占位兼容**：
   - 数据接口提供 `OpeningCredits`（作词 `lyricist` / 作曲 `composer` / 编曲 `arranger` / 谱师 `charter`）；
   - 0 项（未填/无数据）：完全不绘制附加字段，整栈与原先基线 100% 一致，不留空白行；
   - 1~3 项（部分字段）：仅画出有内容的行，未填字段自动剔除，整栈自适应重新垂直居中（上留白严格等于下留白）；
   - 4 项齐全：全部展示，整栈依然舒适居中，两端留白保持充足。
3. **原型定档后清理**：
   - 原型 `OpeningScreenPrototype.*` 经用户拍板确认后删除，常量收口落入 `openingSpec.ts`。

## 锁测

- `tests/unit/preview/video/OpeningLayout.test.ts`：
  - 断言方案 B 常量落值（0.030 / 0.022 / 1.4x / 0.022 / 0.016）；
  - 断言 0 个字段时与基线完全一致；
  - 断言 1~4 个字段时整栈上下留白严格相等（`|topGap - bottomGap| <= 1`）；
  - 断言字段增减时栈高按 `creditLineH` 严格线性自适应。
- `tests/unit/preview/video/OpeningFrame.test.ts`：
  - 断言无 credits 时不产生任何附加文本；
  - 断言部分字段时仅绘制指定项（空项不占位）；
  - 断言方案 B 首字对齐不变量：绘制的多行 credits 的 X 坐标严格相同（`new Set(xPositions).size === 1`）。
