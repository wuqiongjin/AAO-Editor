## 要测什么

1. **画布 / 位图上限**：单边上限、面积上限、分配失败的**行为**（`getImageData` / `toBlob` / `drawImage` 各自何时抛或静默）；一张 5,850 × 537（dpr 1 / 2）的网格图能否正常 `toBlob`。
2. **折行导出实测**：3 分钟 / 5 分钟谱（造谱或用 `docs/resource/SampleChartCode/` 语料）的导出耗时与峰值内存（面板 130×537、`es ≈ 0.3`）。
3. **仿真场单帧成本**（真实 canvas，不是 stub）：1080p / 60fps 目标下每帧耗时 → 离线逐帧能否 ≥ 实时吞吐、要不要降分辨率或抽帧；worker + `OffscreenCanvas` 是否可用（决定导出能否离开主线程）。
4. **编码可用性**：`VideoEncoder.isConfigSupported({ codec: 'avc1.640028' / 'vp09.00.10.08' })`、`AudioEncoder`（opus / aac）、封装库选型（`mp4-muxer` / `webm-muxer` 是否要引依赖、体积多少）——结论直接定 07 的容器 / 编码 / 依赖。
5. **MediaRecorder + `captureStream` 对照**：画质 / 掉帧 / 耗时。本 effort 已选离线逐帧，此条只作对照存档（防以后有人重新拍板时无数据）。

## Answer

2026-10-09 实测（**五节全跑，真渲染 + 真 canvas**，产出 `docs/research/chart-preview-export-limits.md`，
数字已回填 03 / 07）。要点：

   **重心是 3–5（视频链路，07 卡在这）；1–2 是复核性质** —— 票 06 开票时 03 尚未落地，票面把 1–2 当成"选型前的实测"；
   03 / 13 / 14 落地后已按公式复算过（语料 805 张谱面，比本票强），本票**不推翻它的任何结论**。

1. **画布上限（复核）**：单边 **65,535**、面积 **2^28 = 268,435,456**（16,384² 过 / 16,385² 拒）。
   **本票唯一的新东西 = 超限全程静默**：`fillRect` 不抛、`getImageData` 回全 0、`toBlob` 回调 **null**、`drawImage` 画透明
   （03 只按公式算过，没验过失败形态）。5,850 × 537（dpr 1 / 2）都能正常出图。
2. **宽图导出（复核 + 补两个数）**：3 分钟 19 面板 → 缓冲 10,982 × 7,324（307 MB）、端到端 **995 ms**、PNG 12.5 MB；
   5 分钟 31 面板 → 17,918 × 7,324（501 MB）、**2,361 ms**、18.4 MB。**新的是进程 RSS 峰值 +500 MB / +735 MB 与端到端耗时**
   （03 没测，票面「面板位图淘汰口径待 06 压测」指的就是它）。耗时不是问题，内存与体积才是。
3. **仿真场单帧**：1080p 命令录制 0.4 ms + **光栅 45.7 ms** = 46 ms（22 fps）；dpr2 190 ms；720p 16 ms；540p 10 ms ——
   成本按位图像素数走。端到端（+快照+编码）1080p **0.26× 实时**、720p 0.71×、540p 1.14×，**瓶颈是快照不是编码器**。
4. **编码**：`avc1.640028` / vp8 / vp9 / av01 可用（Baseline `avc1.42001f` 不可用）；音频**只有 opus**（AAC 全 false）；
   **H.264 要求偶数边长**（1920×1079 = 不支持）。封装库 `mp4-muxer` 69 KB / `webm-muxer` 65 KB（gzip 14 / 12 KB），0 依赖。
5. **MediaRecorder 对照**：1080p 实时录制只有 19–25 fps，与离线逐帧同一瓶颈（光栅），换录制方式不改变它 —— 存档，主路不动。
6. **worker + OffscreenCanvas 可用**，但 worker 无 `Image`，精灵图集要走 `ImageBitmap`（实测可建）。
