# 46 · 动态预览带体观感缺陷批次（材质 / 叠亮）

Type: bug
Status: resolved 实现（逐条半透明体 + 亮缘 + 自叠加亮；锁测 / 像素 / 性能证据见文末 Comments；**用户已验收通过**）
Blocked by: none

## 来源与症状

用户对比动态预览与谱面画布 / 静态预览，报告两处带体观感不一致：

1. **材质**：动态预览的滑条带体是"单色平涂"——无光泽、无亮边；画布 / 静态预览有贴图剖面（亮边 + 中间光泽）。
2. **交叉 / 自叠**：动态预览多条滑条交叉或自叠时"一色平铺、重叠处毫无变化"；画布 / 静态预览重叠区更亮（叠亮），且后放置者在上。

> 注：05 期票面原口径允许"带体颜色取皮肤带体图或采样中心色"、`simGeometry.ts:387` 也写明"仿真场不做贴图透视变换"。本次用户明确要求与画布观感对齐 ⇒ 该简化口径收回；几何 / 时间行为不动。

## 公共背景：两套完全独立的实现

| | 画布 + 静态预览 | 动态预览 |
| --- | --- | --- |
| 入口 | `renderChart` → `renderNotes`（`src/rendering/render.ts:662`） | `drawSimFrameAt` → `drawBands`（`src/preview/video/sim/simField.ts:346 / 392`） |
| 带体 | `renderSpanBands`（`render.ts:911`）：单 region → `drawBandQuad`（`render.ts:854`）**贴图剪切铺入**；多点段 → `renderSpBandStrip`（`render.ts:1040`）**逐像素剖面光栅** | `fillPolys`（`simField.ts:431`）：同组四边形合并成一条路径，**一次纯色 `fill()`** |
| 材质来源 | 皮肤带体图本身（`noteSkin.slideBand`，`noteSkin.ts:324`） | `sampleCenterColor`（`simAssets.ts:132`）**只读中心 1 像素的 RGB**，图片随即丢弃（`SimAssets` 只留 `bandColor` / `bandColorSp`，`simAssets.ts:83-85`） |
| 叠亮 | 半透明贴图源上叠加；SP 段 `rasterBandRuns` 像素内 `1−(1−a₁)(1−a₂)`（`slideBandGeometry.ts:239`） | 单次不透明填充 ⇒ 无叠加 |
| 上下关系 | 按谱面数组序逐条画（`render.ts:676-681`，`visibleNotes` 的 spans 保持原序，`ChartGeometry.ts:360-370`） | `bands.sort(min(t0,t1))` 按时间重排（`simField.ts:301`），再全部并成一层 |

静态预览是 `directNotes: true` 走同一套 `renderNotes`（`preview/static/panelPainter.ts`），所以"画布 = 静态预览"。

## #1 材质：单色平涂

Status: resolved 实现（体半透明 + 皮肤图剖面采样 + 两侧亮缘；用户验收通过；见 Comments）

- 动态预览只拿到中心像素色 `rgb(75, 227, 113)`（= `#4be371`），然后**不透明** fill 一次；纹理自带的横截面剖面、纵向渐变、边缘高光全部丢失。
- skin00 带体图实测（146×205，逐列 α 全高平均）：
  - `longNoteLine.png`（普通）：中心 0.38 → 体部 0.55 → **亮缘 0.89 / 1.00**；纵向 α 两端 0.75、中段 0.38（"两端实、中间虚"）。
  - `longNoteLine2.png`（SP）：中心 0.38 → 亮缘 0.89 / 1.00，纵向恒定（seamless）。
- 即：画布带体 = 半透明体（38%~55%）+ 89%~100% 亮边；动态预览 = 不透明 100% 单色。除了没有光泽，动态带体还比画布**更挡背景**。
- 补充：取色处 `sampleCenterColor` 只读 RGB、**忽略 α**（`simAssets.ts:143-144`），所以连"中心是半透明的"这一信息都没进渲染层。

## #2 交叉 / 自叠：不叠亮、也没有上下关系

Status: resolved 实现（逐条绘制 + 自叠补层 + 绘制序改谱面数组序；用户验收通过；见 Comments）

- `fillPolys` 把**同组（普通 / SP）全部四边形合成一条路径**一次 `ctx.fill()`（`simField.ts:431-441`，合并本身是为消共享边接缝 / issue 45）。三个后果：
  1. **无逐条合成**：无论一个像素被 1 个还是 N 个四边形覆盖，整个批次只画一次、只用一个颜色 ⇒ 重叠处与单层完全一致。这是"重叠处毫无变化"的直接原因（即使把填充改成半透明，单条路径也只应用一次 α）。
  2. **无 z 序**：同材质带体变成一层，"后放者在上"不存在；画布的半透明高光边会压在前一条上，动态里两条完全同色同层。
  3. **不透明底色**：见 #1，即使拆成逐条 fill 也不会叠亮。
- 次要偏差：`buildSimChart` 按 `min(t0,t1)` 排序（`simField.ts:301`），而画布按谱面数组序（`ChartGeometry.ts:360-370`）；即使逐条绘制，倒流 / 乱序谱的上下关系仍会与画布不同。`chart.bands` 仅 `drawBands`（`simField.ts:399`）与 `drawHoldEffects`（`simField.ts:786`）消费，二者都全表遍历，排序不是窗口查询所需。

## 修法（选型记录；实施见 Comments）

> 实施结果：走 **B 剖面路线**，但亮缘改用**薄四边形填充**（不用 clip + stroke——实测密集谱慢 4 倍）；体 / 亮缘 α 从皮肤带体图**运行时采样**（与 ADR-0009 五轮同口径，不写死）。下面是开票时的候选对照，保留不动。

不动几何与时间：`bandQuad` / `bandLaneAt` / 可见窗口 / 绕向归一保持原样；只换"怎么上色"。

- **逐条绘制 + 保留段内合并**：以**一条滑条**为单位合并路径（保留 issue 45 的绕向归一与防接缝性质），滑条之间各自 fill（半透明 ⇒ 自然叠亮），绘制序改为谱面数组序。
- **材质**：
  - A. 贴图路线——`loadSimAssets` 已把带体图读进来了（`simAssets.ts:176-177`），只是没存；可仿 `drawBandQuad` 的剪切贴图。**难点**：动态带体是梯形（两端 A 不同 ⇒ 上下边宽不同），一次仿射变换铺不满；需要纵向切片，切片接缝又会回到"半透明多笔叠涂"的老问题（见 `renderSpBandStrip` 注释）。
  - B. 剖面路线——复用 `bandStripStyle`（`render.ts:961`）的 17 点 α + 体色采样，逐条画"半透明体 + 贴边亮缘（clip 到四边形内，1~2 笔 stroke 近似剖面）"。O(可见滑条数) draw call，廉价且自适应皮肤；放大看是近似而非逐像素真值。
  - C. 逐像素光栅（`rasterBandRuns` 的变体，半宽随 y 变化）——最忠实，但成本 O(面积)；按可见 30~40 条 × 154×600 px 估算单帧数百万像素 JS 写入，**不建议**在 60fps 实时路径上直接做，除非实测过关。
- 选型以实测为准：A / C 中成本可接受者优先（观感最忠实），否则 B；用 `docs/resource/StressTestChart` 在 1080p / 1440p 下测实时帧与导出一帧（06 基线：1080p 单帧 45.7 ms）。
- 若走 B/C，`fillStyle` 仍用皮肤取色、透明度走 `globalAlpha`，可让现有按 `fillStyle` 识别带体批次的测试与 issue 45 锁测继续生效（stroke 不进 `bandBatches`）。

## 锁测

- 单测（`tests/unit/preview/video/SimField.test.ts`）：
  - 现锁的是**机制**："同组一条路径一次 fill"（`bandBatches` L505-530、issue 45 describe L532-578）与 `fillStyle === SIM_BAND_COLORS.band`（L141-150）。改口径后需同步：一条滑条仍合并（防接缝 + 绕向归一不变）、**滑条数量 = 绘制批次数量**、批次顺序 = 谱面数组序。
  - 新增：同一帧两条交叉滑条 ⇒ 2 个批次；带体材质至少两层（体 + 亮缘），且亮缘 α > 体 α。
  - 顺序陷阱：票 23 #1 的锁测用"帧里最前 4 个 moveTo/lineTo"取四边形顶点 ⇒ 新材质层必须画在**体路径之后**（亮缘走 `stroke`，不进 `bandBatches`），否则顶点断言会取到亮缘路径。
- 像素（记录型 ctx 不光栅化，必须浏览器验）：新增/扩展探针（照 `scripts/verify-backflow-band-fill.mjs`），seek 到已知交叉帧，采样"单层中心 / 两层重叠 / 带体边缘"三点：重叠 > 单层、边缘 > 中心；并与画布同位截图做 A/B。
- 回归清单：
  1. issue 45 倒流区照常显示（绕向归一、同滑条防接缝）；
  2. issue 23 #1 过线端沿线行进（`bandLaneAt`）与三条顶点序锁测不动；
  3. 带体可见窗口（`maxT < seconds` 跳过 / 未进场跳过）不变；
  4. 绘制次序仍为 场地 → 带体 → 双押线 → 元素 → 特效 → combo（结点压在带体上）；
  5. `slideOpacity` 语义不变（0 不画）；
  6. 实时回放（rAF）与导出（`frameDriver.ts:102`）共用同一函数 ⇒ 帧数与确定性不受影响；密集谱实测帧率 / 导出耗时不得回退。

## Comments

- 用户报告两处观感差异，要求先查根因、不急着改，必要时开票。本票为诊断产出：代码零改动；证据 = 源码路径 + 带体图逐列 α 实测（skin00 两张）+ 现有锁测清单。
- 实现闭环（用户拍板「开始修复，确保不影响既有功能」）：
  - **数据**：`SimBand` 增 `slide` 分组号；`buildSimChart` 去掉 `bands.sort(min(t0,t1))`，改回**谱面数组序**（`drawBands` / `drawHoldEffects` 都全表遍历，顺序只影响绘制层级）。
  - **绘制**（`simField.drawBands` → `drawBandGroup`）：
    ① 同一条滑条的四边形仍并成一条路径一次 fill（绕向归一 / 防接缝 = issue 45 原样）；
    ② 材质从皮肤带体图**运行时采样**（`simAssets.sampleBandMaterial`：中心区域列平均 = 体 α、最亮列 = 亮缘 α；与画布 `bandStripStyle` / ADR-0009 五轮同口径），`SimBandMaterial` 放 `simGeometry`；缺 DOM / 缺图走兜底常量。体按 `bodyAlpha × slideOpacity` 半透明填充；
    ③ 亮缘 = 沿两条长边**水平内缩**的薄四边形（宽度 = **该段自己的**半宽 × `rimFrac`，随 A 收缩；左右 + 各段合并一次 fill。与 `drawBandQuad` 的贴图剪切同口径；不用 clip + stroke）；
    ④ 自叠 = 同一条滑条的段真重叠时，按凸多边形交集补一层体色（Sutherland–Hodgman；相邻段只共享边 ⇒ 面积 0 跳过）。**只在存在折返段时扫描**：正向流各段 y 区间首尾相接、互不相交，O(n²) 扫描直接跳过。
