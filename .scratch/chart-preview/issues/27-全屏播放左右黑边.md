# 27 · 全屏播放的左右黑边（= 播放条占的那一行）

Type: grilling
Status: open（2026-10-09 根因实测坐实 + **修法已拍板**：E「播放条浮在画面上」，**且只在全屏态浮**；**待实现**）
Blocked by: —

## 来源

2026-10-09 用户：「**全屏播放下**，左侧和右侧有黑边」。

用户随即澄清两点（同日）：① 说的是**全屏播放态**，不是窗口最大化态；②「全屏下不存在什么满宽还是不满宽」⇒ 本票与票 19 的 contain / 满宽之争**无关**。

## 症状（全屏实测，`.cache/pv-fs-edge.mjs`，DPR 1）

全屏舞台底色 = `--canvas-bg` = **rgb(12, 14, 17)**（`.preview-stage:fullscreen`，`PreviewPage.css` L523-539）⇒ 留白本身就是近黑的，与窗口态那层（露出的其实是页面底色，见文末 Comments）不是一回事。

| 屏幕 | 舞台（=屏幕）比例 | 现状场地 | 左右黑边 |
|---|---|---|---|
| 1920×1080 (16:9) | 1.778 | 1850×1040 | 各 **35px**（占屏宽 3.6%） |
| 2560×1440 (16:9) | 1.778 | 2490×1400 | 各 **35px**（2.7%） |
| 1920×1200 (16:10) | 1.600 | 1920×1079 | 各 **0px** |
| 3440×1440 (21:9) | 2.389 | 2490×1400 | 各 **475px**（27.6%，另一成因，见 F） |

## 根因（已实测坐实）

16:9 屏幕比例 **1.7778** ≈ 设计面 **1.7787** ⇒ **画面只要吃掉整个屏幕高度，宽度就正好铺满**，本不该有黑边。

而全屏下画面**没能吃掉整个屏幕高度**：`.pv-stage` 是 flex column，播放条（`play-bar--preview` `min-height: 32`，票 23 #3 定动态形态留住它）+ `gap: 8` 占掉 **40px**。

⇒ 画面高 `1080 − 40 = 1040` ⇒ 宽 `1040 × 1.7787 = 1850` ⇒ 每侧黑边 `(1920 − 1850) / 2 = 35px`。

**黑边宽度 = 播放条占的那 40px × 1.7787 / 2 = 35.6px**，与实测逐位吻合。**黑边的唯一来源就是播放条占的这一行。**（16:10 屏幕比例 1.6 < 1.7787 ⇒ 宽度受限、本来就 0 黑边，所以只有 16:9 及更扁的屏幕才看得到这条黑边。）

## 修法（**E**，已拍板）

- **E · 播放条浮在画面上（不占独立行）**：画面吃掉整个舞台高度。
  实测 1920×1080：场地 1850×1040 → **1920×1079**，**黑边 0px**，画面面积 **+7.7%**；2560×1440 同理 **+5.7%**。
  - 票 19 §2 已把它列为候选：「让播放条叠在场地底部 —— 再省 38px，但会盖住判定线以下的背景区，实现时按观感定」。
  - 代价：播放条压在画面底部。判定线在 `0.82H`，播放条约 32px 高 ⇒ 只压到 `0.97H` 以下那一小条，**不压判定线本身**。
- **F · 抬 `SIM_FIELD_LIMITS.maxW`（只治 21:9，与本票主因无关）**：3440×1440 下画面被 `maxW = 2560` 钳住 ⇒ 黑边 440px。要不要抬上界另议（dpr 位图预算见票 19 Answer：dpr 2 ≈ 14.7M px）。

## 定案（用户 2026-10-09 拍板：**E，且只在全屏态浮**）

**Q1 = 只全屏浮**（窗口态播放条照旧占独立行）。三条理由：

1. **两态的"留白"根本不是一回事**：全屏态舞台底色是 `--canvas-bg`（近黑）⇒ 留白是**黑边**；窗口态 `.preview-stage.is-filled { background: none }` ⇒ 留白露出的是**页面底色**，与页面其他区域同色，**不构成视觉问题**，没有"要消掉"的对象。
2. **窗口态播放条占一排是票 05 的用户定案**（"播放控件 = 舞台底部一排，照 Bestdori"），不该为这 40px 推翻。
3. **语境不同**：全屏是沉浸观看，画面占满屏幕合理；窗口是工作界面，把播放条压在画面底部反而挡住画面下缘、碍事。

⇒ 改动的面收在 `.preview-stage:fullscreen` 这一段的覆盖里，窗口态行为一字不动。

**Q2 = 21:9 先不管**（= F，与播放条无关，是 `maxW` 的成因；本机非带鱼屏，登记观察项，需要时另开票）。

## 落点（实现时）

- `src/pages/preview/PreviewPage.css`：在「全屏预览」那段（L507-539）里补全屏态对 `.pv-stage` 的覆盖 —— 去掉 `gap`、把 `play-bar--preview` 改成浮在舞台底部（`position: absolute`，`.pv-stage` 给 `position: relative`）⇒ 画面吃掉整个舞台高度。
- 播放条浮在画面上后的**可读性**：票 23 #3 已让全屏舞台走 `--stage-*` 一整套台上配色（深底 + 固定浅前景，不随主题翻），理论上立得住；若实测在画面上读不清，补一层极轻的底衬（渐变 / 半透明），**不要**加不透明胶囊（票 10 已撤过控件外壳一次）。
- 画面底部被压住的那一条 = 判定线（`0.82H`）**以下**的背景区，不挡判定线与音符（票 19 §2「会盖住判定线以下的背景区，实现时按观感定」）。
