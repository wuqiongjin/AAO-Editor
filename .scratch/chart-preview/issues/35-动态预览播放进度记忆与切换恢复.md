# 35 · 动态预览播放进度记忆与切换恢复

Type: bug
Status: resolved
Blocked by: none

## 来源与症状

1. **刷新与记忆策略**：用户要求动态预览切出后保持进度并在切回时继续上次进度，仅在谱面代码改动或重启软件时从 0 开始。
2. **切回动态预览一播放就跳回开头**：从动态预览切到静态预览再切回动态预览，时间码初始显示上次的进度，但是一点击播放就又跳回了 `00:00:0`。
3. **按钮越界**：此前擅自向 `PlayBar` 加回了「回到开头」按钮，违背票 20 定案（票 20 明确撤掉「回开头」与「循环」两钮，播放条只留播放/暂停、时间码、进度、倍速、音量）。

## 根因

1. **切页误判改谱**：
   - `src/pages/preview/PreviewVideoStage.tsx` 中改谱监听使用了引用比较 `prevNotesRef.current !== scene.notes`。切出页面再切回时，存储层反序列化出新的音符数组引用，导致被误判为“改谱”，将进度冲刷回 0。
2. **组件卸载与重建状态丢失**：
   - 切换到静态预览再切回时，`PreviewVideoStage` 卸载重建，内部播放游标丢失。
3. **音频引擎异步解码重置时序竞争**：
   - 动态预览挂载时，`createSimPlayback` 异步调用 `AudioEngine.load(file)` 进行音频解码。
   - `AudioEngine.load` 在解码成功后显式执行了 `this.offsetSeconds = 0`。
   - 外部组件虽然把初始秒数同步给了游标，但几百毫秒后异步解码完成，将内部游标强行覆盖为 0。当用户点击播放时，引擎实际上从 0 开始播放。

## 修法

1. **恪守票 20 定案，坚决撤销「回到开头」按钮**：
   - 彻底移除 `PlayBar.tsx` 中的 `RotateCcw` 按钮及 `onRestart` 回调；
   - 移除关联的 i18n 文案与测试。
2. **音符语义比对**：
   - `PreviewVideoStage.tsx` 改用 `notesEqual` 进行音符内容比较，切页生成新引用时不误判为改谱；仅当音符实质被改动时才重置播放进度为 0。
3. **播放秒数提升至父层保活**：
   - `PreviewPage.tsx` 维护 `videoPlaybackSeconds` 状态，组件切换卸载/重建时透传 `initialSeconds`；
   - 缓存 `videoAudio` 避免同工程下切形态重复构造 Blob。
4. **音频引擎异步解码精准恢复**：
   - `simPlayback.ts` 的 `SimPlaybackOptions` 接收 `initialSeconds`；
   - 内部维护 `targetSeconds`，创建时若 `targetSeconds > 0` 立即 seek 并通知 tick；
   - 在 `engine.load(file)` 异步 Promise 完成之后，再次检查 `targetSeconds > 0`，调用 `engine.seek(targetSeconds)` 重新恢复游标，彻底消除解码完成将游标冲为 0 的时序竞争。

## 锁测

- `tests/unit/preview/video/SimPlayback.test.ts`：
  - 断言 `createSimPlayback` 传入 `initialSeconds` 时首帧正确通知目标秒数；
  - 断言异步音频解码完成后进度依然保持在目标秒数，调用 `play()` 从该秒数继续推进，不跳回 0。
- `tests/dom/preview/PreviewVideoControls.test.tsx`：
  - 守卫票 20 验收定案：播放条无回开头与循环两钮；
  - 断言同音符内容（不同引用）切页不重置进度，实际修改音符时重置为 0。
