# 69 · 动态预览：切到动态形态时长谱同步派生阻塞首帧

Type: bug
Status: resolved（用户 2026-11-13 大致手动验收通过；验收边界见「Answer」；静态形态同源问题另开票 70）
Blocked by: none

## 来源与症状
用户 2026-11-13 报：进预览页正常，点「动态预览」卡住半天才进入，谱面越长越久；觉得「以前先进入页面再加载资源，现在没有加载过程了」。与 [68](./68-动态预览残留随机停顿与切片预热缺口.md)（播放期随机停顿、已 resolved）不是同一信号。

## 根因（Playwright + CDP 已复现，RED）
1. `PreviewPage.tsx:330` 同步 `setMode('video')`；`PreviewVideoStage.tsx:151` 的 `useMemo(buildSimChart)` 与 `getBpmEvents` / `BpmTimeline`、`simPlayback.setChart` 首帧光栅挤在**同一 React render 任务**，O(notes)；该路径没有 `waitForPaint()` / `yieldToMainThread()`（导出侧 `useVideoExport.ts:186`、`exportVideo.ts:264` 有）⇒ loading 文案（`:323`）要等长任务结束才 paint，素材命中缓存时更是一闪而过。
2. 实测（真实谱 `150030.json` 按拍放大注入 IndexedDB）：1,242 / 4,821 / 11,979 音符 → 点击到可交互 115 / 251 / 622 ms，长任务 116 / 251 / 1,000 ms；CPU 热点 `BpmTimeline` / `buildSimChart`。`loadSimAssets`（`PreviewVideoStage.tsx:139-148`）是异步 useEffect、profile 零命中 ⇒ **不是场景资源加载阻塞**。
3. 差分：`6bf125d9`（票 65 之前）同样 RED（114 / 277 / 601 ms、同热点），`a1af7da8` ↔ `37216b2a` 空工程差分均 GREEN ⇒ **不是票 65/66/67 新引入的回归**，是既有同步派生开销；「加载过程消失」为 paint 被推迟 + 缓存命中的观感推测，未在真实缓存 / 网络条件下验证。

## 本轮实现口径（待验收，非用户逐字定案）
- 切 mode 前 `await waitForPaint()`（复用导出侧原语），先让骨架 /「正在读取场地素材…」可见；`buildSimChart` 从同步 useMemo 挪到 effect 分批 `yieldToMainThread()`，并复用 `getBpmEvents`（`simField.ts:240` 与 `AudioTiming.ts:129` 各算一次）。
- 不改素材加载链、`ready` 门禁（票 05 既有）与实时 50% / 导出 100% 光栅口径（票 66 定案）；不引 Worker。

## 锁测
1. `tests/dom/preview/PreviewVideoControls.test.tsx` 增：长谱 scene 下点「动态预览」后 loading 文案先于同步派生可见（现 `:39-77` 把 `loadSimAssets` mock 成立即 resolve，真实加载态零覆盖）；`tests/dom/preview/PreviewPageScope.test.tsx:334` 模式切换用例补时序断言。
2. `tests/perf/` 增长谱 `buildSimChart` 耗时预算（先例 `ChartCodeScale.test.ts`）；`tests/static/PreviewPageWiring.test.ts` 锁动态预览路径含 `waitForPaint` / `yieldToMainThread`。
3. jsdom 无真实布局 / paint，单测量不了首帧可见时刻与长任务 ⇒ **手工验收**：① ≥1 万音符长谱点动态预览先见骨架 / 加载态再出画面，不白屏；② 切换期间导航 / 缩放仍可点；③ 冷缓存（Disable cache）与热缓存各一次都有可见加载态；④ 1×/4×/10× 谱长切换耗时不再线性恶化；⑤ 静态↔动态来回切、窗口缩放后画布正常。原因：可见时序与真实缓存 / 绘制只在浏览器真机成立。

## Answer

**改成什么**：切动态形态先提交加载态 → `await waitForPaint()` → 再 `setMode('video')`；等待那一帧里连点 / 点回静态由令牌作废旧切换。`buildSimChart` 从同步 `useMemo` 挪进 effect 分批 `yieldToMainThread()`，派生表没到齐不顶空白画布、不推过期帧；`AudioTiming.beatSecondsAt` 让整轮派生共用一条 `BpmTimeline`，BPM 事件在实时（舞台 → `SimFrameInput.bpmEvents` → `engine.setChart`）与导出（编排层算一次传两边）各只提取一次。素材加载链、`ready` 门禁、实时 50% / 导出 100% 光栅口径一律未动，未引 Worker。

**验证**：`npx tsc -b` 与改动文件 `npx eslint` 干净；`npm test` 427 文件 / 4698 例，4696 通过，2 条失败为 HEAD 既有、与本票无关的静态锁（`ChartCodeDurationSync.test.ts` / `PreviewPlayBarReuse.test.ts`，应用前已复现）；本票 8 个相关测试文件单跑全绿。12k 音符 / 64 段 BPM 的 `buildSimChart` CPU 最小值 ≈52ms → ≈12.1ms（`tests/perf/SimChartScale.test.ts` 预算 32ms）。

**验收边界（如实记）**：用户 2026-11-13 反馈「大致测试通过」—— 动态形态切换耗时主观已可接受，但「锁测」第 3 条的 5 项手工清单未逐条回报，实现后也没有同口径 Playwright + CDP 的点击→可交互复测（票内 115 / 251 / 622ms 是**实现前** RED 数字），故不宣称逐项全验、也不宣称端到端已量化修复。同日用户另报静态形态有同类卡顿 + 可见陈旧帧，另开票 70（静态预览切换时卡顿与陈旧帧分步可见），不并入本票。
