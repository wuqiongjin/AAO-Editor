# 44 · 视频背景（仿真场）

Type: grilling
Status: open（2026-10-11 开票；grill 主体完成 · 排期在 42/43 之后 · **先做离屏逐帧 seek 可行性实测**，实测后还有 3 问待拍）
Blocked by: 42

## 来源与诉求

2026-10-11 用户提需求：「（自定义背景）甚至可以支持"视频背景"」。

## 现状（实测）

- 仿真场背景层当前只接受一张位图（`assets.background: HTMLImageElement | null`），
  `drawField` 每帧 `drawImage`；没有 `<video>` 通道。
- 实时预览 = RAF 逐帧绘制 ⇒ 视频背景可以"跟着播放时钟走"。
- 视频导出 = **离线逐帧**（`src/preview/video/encode/frameDriver.ts` 按固定帧率推进时间）
  ⇒ 视频背景必须支持"按帧 seek 取画面"（`video.currentTime = t` 后等 `seeked` 再画），
  这是与实时回放完全不同的成本模型，也是本票最大的未知项。
- 现有素材边界：镜像仓只分发游戏素材；用户视频属本地数据，存储要另开通道
  （IndexedDB / Electron 数据根；视频体积远大于图片）。

## 待拍板（grilling）— 以下各条已在下方「定案」逐条拍完，此处仅存档

1. **本期做不做**：先做 42（静态自定义背景）再评估，还是视频背景一并进本期。
2. **时长口径**：视频比谱面短（循环播放？停在末帧？）/ 比谱面长（截断？）怎么处理。
3. **音频**：视频自带的音轨**一律丢弃**（会与 BGM / 键音打架）还是可选混入。
4. **导出可行性**：离线逐帧 seek 的耗时与稳定性（软光栅机器实测）可接受吗？
   不可接受时的退路 = 导出时只用首帧 / 禁止带视频背景导出。
5. **存储与体积上限**：格式白名单、体积上限、是否随工程走（与 42 Q2 同一口径）。
6. **与视频开场的关系**：开场第③段画背景 —— 视频背景时这一屏画什么（首帧 / 黑场）。

## 定案（用户 2026-10-11 · grill 第 1 轮）

- **排期在 42 / 43 之后**；进实现前**先做一次可行性实测**（离屏逐帧 `seek` 的耗时与稳定性，
  30s@720p 量级），实测过关再开票实现。
- 不过关的退路（先记下）：导出时只用视频首帧 / 禁止带视频背景导出。
- **存储 = 入库（工程级）**（用户 2026-10-11 选 A）：与自定义图同口径随工程走；
  **体积上限等实测报告出来再定**（先按 100 MiB 试）。否决"只存本机引用"（浏览器端跨刷新
  必然失效，拿不到 File 句柄）与"仅当前会话有效"（与"工程绑定"诉求直接冲突）。
- **与自定义图共用同一个「自定义」槽位**（一格只放一个，换格式 = 替换）。
- **自带音轨一律丢弃**（用户 2026-10-11 采纳推荐）：视频背景**只取画面**，不给开关。
  理由：导出音轨的来源已固定是 BGM + 键音，混入第三方音轨会和它们打架，而我们只有主音量 /
  SE 音量两个旋钮、没法单独调它；"视频背景"要的本来就是画面。
- **视频开场第③段 = 画视频首帧（静止，不播放）**（用户 2026-10-11 采纳推荐）：到第④段
  （谱面 0 秒）才开始随播放时钟走。理由：开场段是"纯前置、绝不与歌曲前奏重叠"，
  视频在这 1.0s 里动起来等于暗示歌曲已经开始。
- 全量定案见 **ADR-0018**。
