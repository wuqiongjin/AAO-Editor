# 41 · 仿真场素材多种类（表演背景 / 轨道）

Type: grilling
Status: 已实现待验收（2026-10-22 实现；应用侧消费链路完成，**待素材取件侧扩包 + 真机验收**）
Blocked by: none

## 来源与诉求

2026-10-11 用户提需求：「动态预览，背景、轨道 素材应该有更多种类的！(当前只获取了一种好像)」。
**素材由用户提供**：扩展后的素材由用户放到取件位置、同步进来即可；**本票不记录来源地址**
（内部地址不入票、不入文档）。应用仓侧只消费取件产物，不关心它从哪里来。

## 现状（实测，`docs/research/sim-asset-variants.md`）

- 应用侧 `src/preview/video/sim/simAssets.ts` 把包与文件名**写死**：`skin00_rip` +
  `liveBG_normal.png` / `bg_line_rhythm.png` / `game_play_line.png`；唯一选择维度是服务器探测
  `jp → en → tw → cn → kr`。 ⇒ 用户观感「只有一种」的根因是**运行时选择逻辑硬编码**，不只是没取到。
- 上游 Bestdori `jp` 实测：轨道（fieldskin）**33 个包**、表演背景（bgskin）**25 个真包**
  （另有 ~19 个 `*preview` 变体）。镜像仓 `update.sh` 只取 `--package skin00`。
- 主背景图命名**不统一**：`liveBG_normal.png`（skin00/02/03）vs `liveBG.png`（其余主题包）
  ⇒ 不能继续靠硬编码文件名。
- 尺寸体积：场地图 1160×610 / 30–48 KB、判定线 1800×38 / 2 KB、背景 2048×1024 / 280–523 KB。
  轨道全量 ≈2 MB；背景全量**只取主图 ≈10 MB、含 fever ≈20 MB**，且直接进安装包。
- 现有「谱面背景皮肤」（`settings.visual.backgroundSkin`）是**画布**的单张本地图，
  不进仿真场、不进静态预览；与本票不是同一件事。

## 待拍板（grilling）

1. **取件范围**：轨道 / 背景全量 vs 策展子集？特效层（`liveBG_fever`、`liveBG_layer1/2`、
   `equalizer*` / `light_*` / `speaker*`）取不取？
2. **选择模型**：背景与轨道**各自独立**选择，还是**成对整包**（像音符皮肤「整包预设」）？
3. **选择器形态与命名**：33 个轨道包里 15 个是 `skin01`–`skin14` 编号包，用户认不出来 ——
   缩略图网格（照视觉素材页「整包预设缩略」）vs 文字下拉？
4. **注册表形态**：镜像仓生成 `*.gen.ts`（照 `noteSkinRegistry.gen.ts`）vs 应用侧清单常量。
5. **UI 落点**：视觉素材页新增子 tab / 预览页「设置」面板 / 两处都给入口。
6. **默认与回退**：默认保持 `skin00`？选中的包缺失时回落内置还是空态。
7. 应用范围：只服务实时预览，还是**连同视频导出 / 视频开场第③段**一起换。

## 定案（用户 2026-10-11 · grill 第 1 轮，8/8 采纳推荐）

1. **两个独立选择器**（表演背景 / 场地皮肤包），各自默认 `skin00`；**不做**"成对整包预设"
   这层概念（上游两类包只同名配对 20 个，互不配对是常态）。
2. **取件范围**：轨道（fieldskin）**全量 33 包**（≈2 MB，差别全在观感）；背景（bgskin）
   **策展约 20 个真包、每包只取主图**（≈8–10 MB）；**跳过** `liveBG_fever`、
   `equalizer*` / `light_*` / `speaker*` 特效层与 `*preview` 变体。
3. **选择器形态 = 缩略图网格**：轨道缩略取该包 `bg_line_rhythm.png`、背景缩略取 `liveBG*.png`，
   缩略从素材自身缩放生成，不额外抓图。
4. **入口 = 预览页「设置」面板**（挑背景要看着画面挑）；视觉素材页保持"管理 / 上传"场所。
5. **应用范围**：选中的包对**实时预览 + 视频导出 + 视频开场第③段**统一生效。
6. 背景主图命名不统一（`liveBG_normal.png` vs `liveBG.png`）⇒ 应用侧**按包 ID 从注册表取文件名**，
   不再硬编码。
7. **显示名 = 包 ID + 缩略图**，不人工起中文名（与音符皮肤整包预设同一口径，辨识交给缩略图）；
   **只同步 `jp` 一个服务器**（现状；多服 = 体积 ×5，留后）。
8. **列表即真相**：注册表只列**实际取到**的包（取不到的不进列表），运行时加载失败兜底回落
   默认 `skin00`，不弹错误、不做"缺失"占位（常识不占行）。
9. **不拆票**：素材取件扩展与消费**合在 41 一张票里**跟踪；票内 / 文档一律说"素材取件 / 同步"，
   **不点名外部仓**（用户："镜像仓库本来就是内部的，不建议额外单独提这个名字"）。
10. **术语**：内部 = **表演背景**（Live background）/ **场地皮肤包**（Field skin pack）；
    UI 文案 = 「背景」/「轨道」；tooltip 用全称。
11. **场地皮肤包与亮度 = 应用级**（`settings.preview`，等同音符速度 / 镜向）—— Q21 确认。
12. 全量定案见 **ADR-0018**（`docs/adr/0018-表演背景与场地皮肤包的选择模型.md`）。
