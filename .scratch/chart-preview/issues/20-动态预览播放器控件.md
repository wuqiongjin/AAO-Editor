**来源**：票 05 验收问题 2（"播放界面，没有声音、倍速设置。这些应该是作为播放器本身具备的功能"）+ 问题 3（"这个页面是不是也要提供「导出」、「全屏」的按钮。（类似静态预览的）"）。

**对照 Bestdori**（bundle `691780a2`）：播放条 = 播放/暂停 + 时间 + 进度 + **折叠扩展行**（音量 ±5%、倍速在 `[0.5, 0.75, 1, 1.5, 2]` 五档步进、循环开关）+ **全屏**钮；它**没有导出**。我们的播放条只有：播放/暂停 + 当前时间 + 进度（可拖）+ 总时长 + 回开头。

## 定案（用户 2026-10-07）

> 用户原话："我说的是没有「音量调节」、「倍速调节」的功能，不是没有声音。声音本身暂时没听出来问题"；「导出钮」= 按推荐来。

1. **"没有声音" = 缺功能**（不是没声音）：本票 = **音量调节 + 倍速调节**（+ 循环开关：Bestdori 同排一起给，成本一条 UI）。
2. **倍速要做** ⇒ 引擎侧 rate 支持纳入本票（§现状盘点那一段的成本照收）。
3. **导出入口 = 等 07**（推荐案）：本轮动态工具栏只加**全屏**；视频导出的按钮 / 规格 / 进度 / 取消随 07 落地（07 票已含"导出 UI"落点，本票在 07 的 Comments 挂一行指针，避免漏）。
4. **音量落 `settings.audio.volume`（新字段，持久化）**，键音音量沿用 `settings.audio.seVolume`；预期 07 的视频导出按这两档取（"与播放一致"）。工作台那档页面内主音量是既有独立口径，本票不动（登记在 Comments）。

**实现的验收口径（待验收）**：音量 0..1（含静音，步进 5%，照 Bestdori）；倍速五档 `[0.5, 0.75, 1, 1.5, 2]`（照 Bestdori），**只影响回放速度，不改谱面秒数与进度条量程**；循环开关到终点回绕到 0 继续播。

## 现状盘点（代码走读）

- 音频链路本身**没有明显阻塞**：`simPlayback` 自持 `AudioEngine`（BGM = 作用域工程音频；无音频走合成时间线；键音 = `buildKeyEvents` 同一份事件表），`play()` 在用户手势里 `ctx.resume()`；主音量固定 1（工作台那档是页面内 state、不落设置）。**未实测**（自动化环境需要"带音频的工程 + 用户手势"；本轮没做）。
- `AudioEngine` **无 rate 支持**：`getSeconds` 的两条时钟（audio / synthetic）、`tick()` 的 horizon、`playSampledTick` 的 `src.playbackRate`、`seek` 的游标都要按 rate 走；合成时间线的 `performance.now` 也要乘 rate。改动集中在 `src/audio/AudioEngine.ts`（工作台共用，要保证 rate=1 时行为逐位不变）。
- **全屏**：`PreviewPage` 的 `stageRef` + `toggleFullscreen` 是形态无关的（动态形态也在同一块 `.preview-stage` 里）；缺的只是工具栏那枚钮 —— 复用 `PreviewStaticToolbar` 的 `Maximize2` 钮 + 浮层 `PreviewExitFullscreenButton`（票 12 定案的形状）。
- **导出**：视频导出是 07 的整条链路（离线逐帧 + 音轨 + 封装 + 落盘），本票只负责"入口"，不碰 07 的实现。

## Answer

2026-10-07 实现（待用户验收）。

**设置域 / 接缝**

- `AppSettings.audio.volume`（0..1，默认 1，additive 不 bump schemaVersion）+ 归一化；`ConfigProvider.setAudioVolume`（与 `setSeVolume` 同范式：段内浅合并 + 整份写盘）。

**引擎（`src/audio/AudioEngine.ts`）**

- `setPlaybackRate(rate)` + 只读 `playbackRate`：钳制 `PLAYBACK_RATE_RANGE = 0.25..4`。速率**三处一起缩放**才不音画不同步：① 两条时钟的经过时间（`getSeconds` 乘 rate）；② BGM 音源的 `playbackRate`（`load` / `play` / `seek` 三条起音路径都设）；③ 键音调度（`tick` 里 horizon × rate、发声时刻 `Δ/rate`）。**播放中改速率不跳位置**（先按旧速率定住位置再重锚）。
- `setVolume` 改成"暂存 + 建 ctx 时落地"（与 `seVolume` 同范式）：此前 ctx 未建时调用会被丢掉 ⇒ 播放器初值音量会失效。

**回放（`simPlayback`）**

- `SimPlaybackOptions` 增初始 `volume` / `rate` / `loop`；`setOptions` 增 `volume` / `rate` / `loop`（仍**不重建引擎**）。
- 循环：到谱面长度 `engine.seek(0)` 继续（单一真相源，不另起时钟）；关 = 停在末帧（原行为）。
- `SIM_PLAYBACK_RATES = [0.5, 0.75, 1, 1.5, 2]`（照 Bestdori 的 `audioPlaybackRate`），从 barrel 出。

**UI**

- 播放条（`PreviewVideoStage`）：原 播放/暂停 + 时间 + 进度 + 总时长 + 回开头，右侧补 **倍速 select（五档）+ 循环钮 + 主音量（图标 + 滑杆，照工作台播放条那套）**；`.pv-bar` 允许换行（窄窗不压扁进度条）。
- 工具栏：动态形态补 **全屏**（`PreviewEnterFullscreenButton` 从 `PreviewStaticToolbar` 抽出，静态/动态同一枚）；**导出仍不给入口**（归 07）。
- i18n：`preview.video.{volume,rate,loop}`（zh-CN / en）。

**验证**

- `npm test` **209 文件 / 2,295 用例全绿**；`npx tsc -b` 通过；改动文件 eslint 干净。
- 新增 `tests/unit/audio/AudioEnginePlaybackRate.test.ts`（4 例，jsdom + MockAudioContext）：有音频时位置按速率推进 + 音源 `playbackRate` 跟随 + 改速率不跳位置；合成时间线同样按速率推进；键音墙钟换算（1s 处的键音在 2 倍速下 0.5s 发声）；钳制与五档合法性。
- `tests/static/SimRendererWiring.test.ts` +1 例：控件 → `setOptions({density, seVolume, keySetId, volume, rate, loop})`、音量走 `settings.audio.volume`、循环只 `engine.seek(0)`。
- 真机（`scripts/sim-shot.mjs`）：播放条渲染出倍速 / 循环 / 音量三件，工具栏出现「全屏」；场地 1514×851（票 19 生效）。
- **待人工验收**（单测测不到听感）：① 拖音量滑杆听 BGM 与键音一起变化、0 = 静音；② 倍速切 0.5× / 2× 听音画仍同步、进度条按谱面秒走；③ 循环开：到末尾回绕继续播，关：停在末帧。

## 验收回修（用户 2026-10-07，推翻本票 §19 两条实现口径）

> 用户原话："不需要这个回到开头 和 循环 的按钮。然后倍速的这个样式太丑了。。。然后倍速的跨度以 0.25 作为递增吧？最低档为：0.25x，然后支持输入自定义倍速（可以设置个最大值、最小值）。"

### #1 撤掉「回开头」与「循环」两钮 — Status: 待实现

- 源头：本票照 Bestdori bundle 抄了这一排（含 `回开头`钮 + 折叠行里的循环开关）；用户明确不要这两件。
- 修法：`PreviewVideoStage.tsx` 删 `RotateCcw` 钮与 `Repeat` 钮（`pb.restart()` 调用随之删；`SimPlayback.restart` 接口**保留**——工作台语义仍需它，且 ESLint/导出 barrel 不动）；`PVideoStage` 的 `loop` state 一并撤，`setOptions({ loop })` 不再传。
- i18n：`preview.video.restart` / `preview.video.loop` 两个键（zh-CN / en）随之删；播放条手册/文档无引用。
- 连带收益：播放条剩"播放/暂停 + 时间码 + 进度 + 音量 + 倍速"五项，与工作台 `PlayBar` 的差异只剩倍速一项 ⇒ 票 22 的"复用"方案更便宜。

### #2 倍速控件重做（0.25 步进 + 自定义输入） — Status: 待实现

- 源头：现在是 `<select class="select-control pv-bar__rate">`（原生下拉，`max-width: 84px`，字是 `0.5× / 0.75× / …`），塞在一排图标钮里像掉进来的一块表单控件 —— 既是"太丑"，也不是播放器该有的形态。
- **定案（用户 2026-10-07）**：步长 **0.25**、最低档 **0.25×**、**支持手动输入**，自行设定最大值 / 最小值。
- **本轮实现口径（待验收）**：
  1. 形态 = 数值输入 + 步进（±0.25）+ 常用档快捷菜单（`0.25 / 0.5 / 0.75 / 1 / 1.5 / 2 / 3 / 4`），不再用原生 `<select>`；视觉与 `.pv-bar` 一族对齐（尺寸、圆角、hover 态）。
  2. 上下限取**引擎既有钳制** `AudioEngine` 的 `PLAYBACK_RATE_RANGE = 0.25..4`（不为此改引擎，也不新增常量第二来源）；越界输入就地钳回并回显钳后值。
  3. 仍然只影响回放速度，不改进度条量程，播放中改速率不跳位置（票 20 的既有口径不变）。
- 锁测：`tests/dom/preview/PreviewVideoControls.test.tsx`（既有 5 例需要改：倍速五档那条换成"0.25 步进 + 自定义值 + 越界钳制"，并要求它们都走 `setOptions({rate})` 且不重建回放；循环那条随 #1 删）；`tests/unit/audio/AudioEnginePlaybackRate.test.ts` 补一条 0.25 与 4 的边界。**听感仍列人工验收**。
