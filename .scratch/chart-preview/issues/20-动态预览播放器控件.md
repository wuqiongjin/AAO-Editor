**对照 Bestdori**（bundle `691780a2`）：播放条 = 播放/暂停 + 时间 + 进度 + **折叠扩展行**（音量 ±5%、倍速在 `[0.5, 0.75, 1, 1.5, 2]` 五档步进、循环开关）+ **全屏**钮；它**没有导出**。我们的播放条只有：播放/暂停 + 当前时间 + 进度（可拖）+ 总时长 + 回开头。

## 定案（用户 2026-10-07）

> 用户原话："我说的是没有「音量调节」、「倍速调节」的功能，不是没有声音。声音本身暂时没听出来问题"；「导出钮」= 按推荐来。

1. **"没有声音" = 缺功能**（不是没声音）：本票 = **音量调节 + 倍速调节**（+ 循环开关：Bestdori 同排一起给，成本一条 UI）。
2. **倍速要做** ⇒ 引擎侧 rate 支持纳入本票（§现状盘点那一段的成本照收）。
3. **导出入口 = 等 07**（推荐案）：本轮动态工具栏只加**全屏**；视频导出的按钮 / 规格 / 进度 / 取消随 07 落地（07 票已含"导出 UI"落点，本票在 07 的 Comments 挂一行指针，避免漏）。
4. **音量落 `settings.audio.volume`（新字段，持久化）**，键音音量沿用 `settings.audio.seVolume`；预期 07 的视频导出按这两档取（"与播放一致"）。工作台那档页面内主音量是既有独立口径，本票不动（登记在 Comments）。

**实现的验收口径（待验收）**：音量 0..1（含静音，步进 5%，照 Bestdori）；倍速五档 `[0.5, 0.75, 1, 1.5, 2]`（照 Bestdori），**只影响回放速度，不改谱面秒数与进度条量程**；循环开关到终点回绕到 0 继续播。

## 现状盘点（代码走读）

- 音频链路本身**没有明显阻塞**：`simPlayback` 自持 `AudioEngine`（BGM = 作用域工程音频；无音频走合成时间线；键音 = `buildKeyEvents` 同一份事件表），`play()` 在用户手势里 `ctx.resume()`；主音量固定 1（工作台那档是页面内 state、不落设置）。**未实测**（自动化环境需要"带音频的工程 + 用户手势"；本轮没做）。
- `AudioEngine` **无 rate 支持**：`getSeconds` 的两条时钟（audio / synthetic）、`tick()` 的 horizon、`playSampledTick` 的 `src.playbackRate`、`seek` 的游标都要按 rate 走；合成时间线的 `performance.now` 也要乘 rate。改动集中在 `src/audio/AudioEngine.ts`（工作台共用，要保证 rate=1 时行为逐位不变）。
- **全屏**：`PreviewPage` 的 `stageRef` + `toggleFullscreen` 是形态无关的（动态形态也在同一块 `.preview-stage` 里）；缺的只是工具栏那枚钮 —— 复用 `PreviewStaticToolbar` 的 `Maximize2` 钮 + 浮层 `PreviewExitFullscreenButton`（票 12 定案的形状）。
- **导出**：视频导出是 07 的整条链路（离线逐帧 + 音轨 + 封装 + 落盘），本票只负责"入口"，不碰 07 的实现。

### #6 去掉"选中"态 + 手填改成"敲一下就生效"（用户 2026-10-08 第五轮复验） — Status: 已实现（2026-10-08）

> 用户原话：①"为什么处在其他倍速时，会有倍速的这个按钮被选中的效果？真的需要这个选中的效果吗？"；②"自定义倍速输入完后，必须按回车才能起作用吗？操作体验好差啊。帮我设计一套更好的交互效果。"

**① 不需要那个选中态 —— 已撤**。理由：`active` 那一下是"非原速就点亮"，但当前倍速**本来就写在钮上**（`1.5×`），再叠一层高亮既像卡住的开关，又给按钮挂了个假的 `aria-pressed`（它是菜单，不是 toggle）。现在只留 `aria-haspopup` / `aria-expanded`，常态一致；锁测把"没有 `icon-btn--active`、`aria-pressed` 为 null"写成断言。
**② 新交互（本轮设计）**：
1. **手填敲一下就生效**：每敲一下就解析，落在区间内 → **立刻应用到回放**（不用回车、不用失焦；边敲边听得出变化）。这是"更好的交互"的核心 —— 取消"输完按回车"这一步。
2. **半截 / 越界输入不打断**：`1.` 这种解析不出值的不动；`9` 这种越界的也**不即时应用**（否则刚敲下就被拉回 4、字也跟着变），只给输入框一个"越界"提示色，等**失焦或回车确认**时才钳回并回显钳后值。
3. **回车 = 确认，不是"生效"**：越界的值在这里才被拉回上下限；面板**不关**，方便连着试几个值。
4. **聚焦即全选**（`onFocus` → `select()`）：直接覆写，不用手动删。
5. **↑↓ 仍按 0.1 步进**（手填中也生效，输入框跟着走）。
- 实现要点：草稿态加了一个 `editingRef` —— 手填期间不让 `value` 回写冲掉半截输入（否则 `1.50` 会被冲成 `1.5`）；每次打开面板都把输入框回填成当前值。
- 锁测：`PreviewVideoControls.test.tsx` 11 例（新增"没有选中态"、"手填敲一下就生效 + 回车只是确认且不关面板"、"半截/越界不打断、确认才钳回"三条）。
- 验证：`npm test` **212 文件 / 2,332 用例全绿**，`npx tsc -b` 通过，改动文件 eslint 干净。真机：选档 1.5× → `1.5×`；手填 `1.35` **不按回车** → 触钮立刻 `1.35×`；手填 `9` 未确认 → 仍是 `1.35×`（不打断）→ 回车确认 → `4×`；面板 135×248，自定义行未溢出。

## Answer

> **2026-10-08 追加**：下面这一节是 2026-10-07 那一版（倍速五档 select + 循环钮），已被当日用户验收**推翻两条口径**；回修后的实现记录在文末「验收回修」小节里（`#1` / `#2` 各附实现记录与锁测）。这里保留原样存档，不改写。

2026-10-07 实现（待用户验收）。

**设置域 / 接缝**

- `AppSettings.audio.volume`（0..1，默认 1，additive 不 bump schemaVersion）+ 归一化；`ConfigProvider.setAudioVolume`（与 `setSeVolume` 同范式：段内浅合并 + 整份写盘）。

**引擎（`src/audio/AudioEngine.ts`）**

- `setPlaybackRate(rate)` + 只读 `playbackRate`：钳制 `PLAYBACK_RATE_RANGE = 0.25..4`。速率**三处一起缩放**才不音画不同步：① 两条时钟的经过时间（`getSeconds` 乘 rate）；② BGM 音源的 `playbackRate`（`load` / `play` / `seek` 三条起音路径都设）；③ 键音调度（`tick` 里 horizon × rate、发声时刻 `Δ/rate`）。**播放中改速率不跳位置**（先按旧速率定住位置再重锚）。
- `setVolume` 改成"暂存 + 建 ctx 时落地"（与 `seVolume` 同范式）：此前 ctx 未建时调用会被丢掉 ⇒ 播放器初值音量会失效。

**回放（`simPlayback`）**

- `SimPlaybackOptions` 增初始 `volume` / `rate` / `loop`；`setOptions` 增 `volume` / `rate` / `loop`（仍**不重建引擎**）。
