# 22 · 动态预览播放条：与工作台播放器

Type: grilling
Status: resolved（**2026-10-08 已实现 + 用户验收通过**：A 案共用 `PlayBar`（props 化 + 两变体 + 倍速 slot）＋ 空格页面级 ＋ 预览时间码恒可编辑；实现记录与验证见文末 Answer）
Blocked by: 20（要先按票 20 的「验收回修」把 pv-bar 削到最终形态，倍速做成 slot 后再合并过去）

**来源**：2026-10-07 用户对票 20 的问题 2 —— "我理解这个播放条没办法复用工作台的播放器吗？（当前空格也没办法对动态视频的播放器起作用，也没办法双击当前秒数，然后能输入自定义的秒数来跳转）"。

**为什么是 grilling**："能不能复用"是看代码就能答的；"要不要抽共用组件"要动工作台既有的 `PlayBar` 及其数据边界（`PlaybackProvider` 的消费者面），属"两套选项之间的取舍"，不是单点实现细节。拍板结论写进本票，实现落点同票。

## 症状（用户提的两件）

1. 空格对动态预览播放器不起作用（工作台可以）。
2. 不能双击当前秒数 → 输入自定义秒数跳转（工作台确有此能力，见「根因 3」）。

## 根因（代码走读，三处耦合）

- **数据源**：`src/playback/PlayBar.tsx:24` 直读 `usePlayback()`（`PlaybackProvider`：`isPlaying` / `canPlay` / `currentSeconds` / `duration` / `volume`）+ `useAudioSession()`（`audioLocked`）。动态预览的回放是 `createSimPlayback` **自持一个 `AudioEngine`**（票 05 定案 ①），不进 `PlaybackProvider` ⇒ 现在的 pv-bar 不是"另一个 Provider 实例"，而是"接不上那个 Provider"。
- **快捷键**：`play`（绑定 = 空格，`src/chart/config/ShortcutConfig.ts:76`）只在 `src/pages/workspace/WorkspacePage.tsx`（`case 'play'` + `useShortcutDispatch`）被消费；预览页没注册 ⇒ 空格在预览页**没有出口**（不是被抢走，是没人接）。
- **时间码编辑**：`PlayBar` 有双击编辑（`beginEditTime` → `input` → `parseTimeInput`），但被 `canPlay` 门住（`PlayBar.tsx:41`：**有音频 = 时长由音频决定，禁止编辑定位**）；pv-bar 压根没实现这个交互，只是 `<span>{formatTimePrecise(...)}</span>`。

**联动**：票 20 的验收回修已把 pv-bar 削到「播放/暂停 + 时间码 + 进度 + 音量 + 倍速」（回开头 / 循环两钮删除）⇒ 与工作台 `PlayBar`（播放/暂停 + 时间码 + 进度 + 音量）只差**倍速**一项。

## 两个方案

- **A · 共用同一件组件**：把 `PlayBar` 的数据入口 props 化（`isPlaying` / `currentSeconds` / `duration` / `volume` / `audioLocked` / `canEditTime` / `shortcutKey`…），倍速做成**可选 slot**（不传就不渲染）；`WorkspacePage` 接线后行为逐位不变；预览页用同一件 + 一层壳变体。
  - 得：空格 / 双击编辑 / 拖拽 seek（含 `setPointerCapture` 跟手）三处行为只有一个实现，预览自然获得；以后任何一处修正，两边同时受益。
  - 失：要动工作台那份组件与其既有锁测（回归风险由既有测试钉住）；两个外壳不同（工作台是 `--playbar-h` 36px 页底栏、预览是舞台底部一行），壳必须分变体。
- **B · 不复用，把三处行为誊到 pv-bar**：`parseTimeInput` / `formatTime*` 已是 `TimeFormat` 里的公共函数可直接复用；另在预览页挂 `useShortcutDispatch` 的 `play` 分支 + 誊一份 pointer-capture 拖拽 seek。
  - 得：工作台零改动。
  - 失：两份 UI 开始漂移 —— 本 repo 已经为这类重复付过账（`usePreviewScope` / `useAudioScope` 同形、`pp-menu__*` 三份）。

## 待拍板（2026-10-08 已拍板，结论见下一节）

- ~~**Q1 · 复用策略 A / B**~~ → **采纳 A**（两者此刻要的东西几乎相同，只差倍速一项；"行为一份"是本 repo 已记过账的口径；props 化是一次机械改动，风险由工作台既有锁测钉住）。**不推荐的是"连外层壳一起复用"**：壳（底色 / 高度 / 是否贴页底）必须分两个变体，否则预览会被工作台底栏的几何拖住。
- ~~**Q2 · 空格的作用域**~~ → **页面级**（预览页 `active` 时接管 `play`；焦点在 `input` / `textarea` / `select` 内放行原生，与既有 `useShortcutDispatch` 同口径）。
- ~~**Q3 · 有音频时能不能编辑时间码**~~ → **预览允许**（动态预览几乎总是有音频，照 `canPlay` gate 走就等于没有这个功能）；实现为把 `canPlay` 参数化成 `canEditTime` prop，**工作台保持现状不动**。

## 定案（用户 2026-10-08）

> 用户原话："复用还是不复用，有没有推荐？没必要强行复用也可以。" → 采纳推荐案。

1. **Q1 = A**：props 化 `PlayBar` 供两处共用，倍速做**可选 slot**（不传就不渲染）；**外壳必须分两个变体**（工作台 `--playbar-h` 页底栏 / 预览舞台底部一行），不连外层壳一起复用。
2. **Q2 = 页面级**：预览页 `active` 时接管 `play`（空格）；焦点在 `input` / `textarea` / `select` 内放行原生。
3. **Q3 = 预览允许**：有音频也能双击时间码输入秒跳转；实现为把 `canPlay` 参数化成 `canEditTime` prop，**工作台保持现状不动**。
4. **顺序**：先做完票 20 的「验收回修」（pv-bar 最终形态定型），再做本票 —— 这也是 `Blocked by: 20` 的由来。

## 落点（定稿）

- A 案：`src/playback/PlayBar.tsx` / `PlayBar.css`（props 化 + 变体类 + 可选倍速 slot）→ `WorkspacePage.tsx` 接线不变 → `PreviewVideoStage.tsx` 的 `.pv-bar` 改消费这一件（票 20 的倍速控件接到 slot 上）。
- B 案：`PreviewVideoStage.tsx` 加 `useShortcutDispatch` 的 `play` 分支 + 时间码双击编辑（复用 `parseTimeInput`）。
- i18n：倍速走既有 `preview.video.rate`；时间码编辑提示复用工作台的 `play.editTime` / `play.timeInput`（不新造键）。

## 锁测（两案都要）

- DOM：`tests/dom/preview/PreviewVideoControls.test.tsx` 增三例 —— ① 空格 → `toggle()`（焦点在输入框内时不触发）；② 时间码双击 → 输入框出现、回车 = `seek(seconds)`、越界钳到 `[0, duration]`；③ 有音频时（Q3 允许路径）双击仍可编辑。
- A 案额外：`WorkspacePage` 既有播放条断言逐条不变（播放状态 / 时间码 / 拖拽 seek / 音量），props 化前后各跑一次；新增一条静态守卫 —— 预览页不得再自带第二份时间码编辑实现。
- 手工 / 像素：实机按空格能切播放；暂停态双击时间码输入 `12.5` → 立即跳到第 12.5 秒那一帧。

## Answer

**2026-10-08 实现（A 案，待用户验收）**。用户当日追加拍板一项（票面外的悬案）：`SimPlayback` 的 `loop` / `restart`（零 UI 消费方）**随本票收掉**。

**落点**

- `src/playback/PlayBar.tsx` / `PlayBar.css`：**props 化** —— 数据入口（`isPlaying` / `currentSeconds` / `duration` / `volume` / `audioLocked` / `canEditTime` / `seekNoCursor` / `shortcutKey` / `variant` / `rateSlot`）全走 props，不再直读 Playback / AudioSession / Config；外壳拆两变体：`play-bar--workspace`（页底栏，几何照旧）与 `play-bar--preview`（舞台底部一行：可换行 / 无底色 / `--text-2xs`）；倍速是**可选 slot**（不传不渲染）。顺带给音量滑杆补 `aria-label`（预览侧复用前本就有这个名字）。
- `src/pages/workspace/WorkspacePage.tsx`：接线逐条显式传入（`canEditTime={!canPlay}`、`seekNoCursor={!canPlay && isPlaying}` —— 行为逐位不变）。
- `src/pages/preview/PreviewVideoStage.tsx`：删自写 `pv-bar`，改 `<PlayBar variant="preview" …>`；空格由本层 `useShortcutDispatch({ only: ['play'] })` **页面级**接管（Q2）；`canEditTime` 恒真（Q3：有音频也能双击时间码输秒跳转）；票 20 的 `PlaybackRate` 接 `rateSlot`。
- `src/chart/config/useShortcutDispatch.ts`：新增 **`only?: FunctionId[]`** —— 未列出的绑定不 `preventDefault`、不派发（预览页只认 `play`，否则 `Ctrl+D` / `Ctrl+T` 这类浏览器键会被顺带吞掉）。工作台不传 = 全接管，行为不变。
- `docs/adr/0002`：§6 作用域补「**预览页例外**」（用户 2026-10-08 定案）+ 头部修订行。这是与 ADR 的既有冲突点，按 `docs/agents/domain.md` 显式落文。
- 域侧清理：`SimPlayback` 删 `loop` 选项 / 回绕分支 / `setOptions({loop})` / `restart()`；`SimPlayback.test.ts` 三条循环用例删、保留「到谱面长度停在末帧（不再排帧）」；`SimRendererWiring.test.ts` 的锁改守「回放层不再有 loop / restart 残留」。
- i18n：删掉失去消费者的 `preview.video.{play,pause,seek,volume}`（zh/en 成对）——播放钮 tooltip 走 `play.toggle`、时间码编辑提示走 `play.editTime` / `play.timeInput`、进度 / 音量走 `play.progress` / `play.seek` / `play.volume`。
- `scripts/sim-shot.mjs`：选择器钉到 `play-bar--preview`（工作台在保活挂载里也有一件 `.play-bar`，不加作用域会 strict mode 撞车，实跑踩到）；seek 改指针点击自绘条（不再有原生 range 可注入）；新增 6.6（空格 / 时间码编辑）与 8（工作台播放条复核）两节。

**锁测**

- 新增 `tests/dom/playback/PlayBar.test.tsx`（9 例，role/text 查询）：播放状态图标切换 / 点击 / `title` 键位提示、时间码 + 锁定图标、拖拽 seek（跟手 / 抬手停止 / 越界钳制）、aria 量程、音量回调与静音、`canEditTime` 两态（含「提交 / 越界钳制 / Esc 放弃」）、倍速 slot 可选。
- `tests/dom/preview/PreviewVideoControls.test.tsx`（16 例，+5）：空格三条（active 接管 / 焦点在输入框内放行 / 失活不接管）、时间码双击（`0:05` → `seek(5)`；上钳 duration、下钳 0）、有音频仍可编辑（Q3）。既有 11 例的选择器收敛到 role/text + `aria-valuemax`。
- 新增 `tests/static/PreviewPlayBarReuse.test.ts`（4 例）：预览条是同一件 `PlayBar`（`variant="preview"` + `rateSlot`）、预览层不得再出现第二份时间码编辑 / 指针 seek / `pv-bar` 类名；`PlayBar` 不直读 context、不含倍速实现、默认变体 = workspace；**工作台逐条接线**（`isPlaying` / `currentSeconds` / `duration` / `volume` / `audioLocked` / `canEditTime` / `seekNoCursor` / `shortcutKey`）；预览只接管 play。
- 口径同步：`tests/static/PreviewPageWiring.test.ts`（`.play-bar--preview` 的 32px 覆盖）。

**验证**

- `npm test` **214 文件 / 2,350 用例全绿**；`npx tsc -b` 通过；改动文件 eslint 干净。
- 真机（`scripts/sim-shot.mjs`，1680×1000 / dpr 2；先按 04 通道归档 fieldskin+bgskin）：场地 1514×851 / 位图 3028×1702（与票 19 一致）、预览播放条高 **32**（`--preview` 变体生效）；空格 `00:01.0 → 00:02.0 → 再按 00:02.0 → 0.6s 后仍 00:02.0`（先推进、后停住）；暂停态双击时间码输入 `0:12.5` 回车 → `00:12.5`（精确跳帧）；拖拽 seek 到 60% / 95% 两次抓帧正常；切回工作台：播放条在、点播放 `00:00.0 → 00:01.1`（props 化后照常）。
- **票面「手工 / 像素」那条的 `12.5` 要改写**：`parseTimeInput` 的口径是 `mm[:ss[.s]]`，裸 `12.5` = 12 分 0.5 秒（再被钳到谱面长度）；要跳第 12.5 秒请输入 **`0:12.5`**（真机验收即用此值）。若希望裸数字按「秒」解释，那是改工作台既有解析口径的另一张票。

**评审留痕（两轴，2026-10-08）**

- Standards：① 修 —— ADR-0002 §6 未同步（已补例外 + 头部修订）；② 修 —— 新增 DOM 测试违反 `tests/README.md`「只按 role / text 查询」（已重写为 role/text，音量滑杆的 `aria-label` 由此补上）；③ 记录不改 —— 测试文件名以组件命名（与仓内既有风格一致，README 的命名约定是判断项）。
- Spec：① 修 —— 「`WorkspacePage` 既有播放条断言」此前并不存在（props 化前没有 PlayBar 的 DOM 断言），现以组件级 9 例 + 静态逐条接线断言落实；② 澄清 —— 时间码示例口径（见上）；③ 记录不改 —— 删 i18n 死键 / `only` 参数 / 新增两份测试文件，都是落点的必要后果。

**待人工验收**：① 预览页观感（播放钮从 `IconButton` 换成 `PlayBar` 那枚 28px 方块钮、时间码移到进度条左侧、进度条改自绘）；② 空格 / 双击时间码的手感；③ 窄窗下换行是否可接受。

**用户验收**：2026-10-08 **验收通过**（观感 / 空格 / 双击时间码三项）。

**后续维护口径**（用户当日问"以后整改 playbar 是不是两边同时生效"）：**是**——播放条的内部排布与交互（播放钮、时间码双击编辑、拖拽 seek、音量）只有 `src/playback/PlayBar.tsx` 一份实现，任何整改在 工作台 / 预览 两处同时生效；分治的只有三样：**外壳几何**（`play-bar--workspace` 页底栏 / `play-bar--preview` 舞台底部一行）、**数据接线**（工作台接 `PlaybackContext` / `AudioSession`，预览接 `SimPlayback`）、**可选 slot**（倍速只有预览传 `rateSlot`）。要给某一侧单独加控件，走 slot / 变体，不改另一侧。
