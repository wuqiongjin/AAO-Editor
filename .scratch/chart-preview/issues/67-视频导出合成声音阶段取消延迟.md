# 67 · 视频导出：合成声音阶段点「取消」无反应、到下个阶段才生效

Type: bug
Status: open（2026-11-13 已实现 + 锁测全绿；**用户手动验收通过**）
Blocked by: none

## 来源与症状
用户 2026-11-12 报「正在合成声音…」时点取消没反应、跳到下个阶段才生效；2026-11-13 要求先开票、修复后由本人手动验收。

## 根因
静态分析（本工作区无 GPU / WebCodecs，未运行时复现）：① `useVideoExport.cancel()` 只写 ref、不触发重渲 ⇒ 点击零反馈；② `exportVideo.ts` 的 audio 段零检查点、`renderAudioTrack` 无取消通道、`startRendering()` 不可中断；③ 同步派生谱面 + 键音采样缓存命中的微任务循环不让出主线程 ⇒ 输入事件排队，取消落到下个阶段。与票 07 定案「进度 + 取消 / 主线程分片让出」冲突；票 33 已修背压处同类问题。

## 修法（本轮实现口径，非用户逐字定案）
- UI：`useVideoExport` 加 `cancelling`，`cancel()` 当帧置位；进度卡换「正在取消…」、取消钮 disabled；中英 i18n 各补一键。
- 域层：`renderAudioTrack` 收 `isCancelled`，键音循环每 64 条 `yieldToMainThread()`；`raceCancellation`（25ms 轮询）包住首次取键音包 / BGM 解码 / `startRendering()`，取消即丢弃结果返回 `AUDIO_TRACK_CANCELLED`（与静音 `null` 区分）；编排层在探编码器后、audio 上报后、派生 / 解码后、建 sink 后补检查点。不引 Worker / AudioWorklet（票 07 定案）。
- 文档：`docs-site/guide/features.md` 校正阶段顺序为 `audio → frames → audioEncode`。

## 锁测
1. `tests/dom/preview/VideoExportFlow.test.tsx`：点取消→卡片当帧换文案 / 钮禁用（含 hook 与卡片联动）、`cancel → isCancelled` 真实传递；`tests/dom/preview/RenderAudioTrackCancellation.test.ts`（jsdom）：键音循环中途取消、渲染 / 取包等待期间取消、静音 + 取消回哨兵、正常路径不变量。
2. `tests/static/VideoExportWiring.test.ts`：两语言文案、audio 段让出与检查点接线、取消哨兵判定；`tests/static/KeySoundSameInstant.test.ts` 既有「只消费传入事件表」锁继续绿（故循环保留 for-of）。
3. 单测到不了真实 `OfflineAudioContext` 耗时 / 输入事件排队与重绘 ⇒ **手工验收（用户本机，见下）**；本工作区不宣称端到端已验。
