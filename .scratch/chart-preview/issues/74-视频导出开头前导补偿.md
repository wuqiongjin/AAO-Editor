# 74 · 视频导出开头前导补偿（lead-in）

Type: grilling
Status: resolved（2026-11-15 用户成片验收通过，原话「没有任何问题了，效果很好」；低速档淡入定档 0.25s）
Blocked by: none
Related: [ADR-0016 §5/§5.1](../../../docs/adr/0016-谱面预览与游戏仿真导出.md), [票 30](./30-视频开场画面.md), [票 48](./48-动态预览音符速度高档映射偏离游戏.md), [票 75](./75-视频导出末击收尾与结算画面残留.md)

**来源**：用户 2026-11-14 报「谱面第 0 beat 就有音符时，导出视频里音符瞬间出现」，同轮拍板「为了防止开头音符突然闪现，必须补时长；未来做可游玩的模拟器同样要补」，并要求核对 `NonSpicyBurrito/sonolus-bandori-engine` 的开头补偿口径。

## 症状与根因

1. 音符 / 带体 / 双押线的可见窗口是 `Δ = seconds − noteTime ∈ [−T, 0]`（`simGeometry.ts:205-210`、`simField.ts:744-758`），`T = chart.approachS = approachSeconds(noteSpeed)`（默认 9.5 档 1.25s，全档 0.4–5.5s）。`time = 0` 的音符本该在 `[-T, 0)` 逐帧接近。
2. `exportVideo.ts:292-296` 总长 = `OPENING_SECONDS(6.75) + D + ENDING_SECONDS(7.5)`，无 leadIn；`frameDriver.ts:137` 第一根谱面帧就是 `seconds = t − O = 0`，`Δ = 0 → A = 1` 直接压在判定线。
3. 开场 ③④ 段**刻意不进** `drawSimFrameAt`（`frameDriver.ts:141-147`，为保干净场地）；ADR-0016 §5.1 否掉「开场与前奏重叠」的理由正是「会吃掉开头音符的接近窗口」，但没另行补 lead-in ⇒ 接近期整段不存在。
4. 6.75s 开场是纯 UI 前置卡片，音轨整体后移，不构成渲染时间域的补偿。

## 调研：sonolus-bandori-engine 怎么处理（2026-11-14 查证）

- **没有固定 2 秒（或任何固定秒数）的开头补偿常量**。`play/src/engine/playData/note.ts` 的 `note.duration` 是按 `options.noteSpeed` 动态算的 `(12−n)/2` / `(16−n)/10` 秒 —— 正是本仓 `approachSeconds` / ADR-0016 §2 的口径来源；`shared/src/engine/data/note.ts` 的 `approach()` 与本仓 `approachA` 同款。
- 机制是「**时间轴从负值起跑 + 每个音符按 T 提前生成**」：`Note.ts` 的 `shouldSpawn() = time.now >= spawnTime`；`VisibleNote.ts` 的 `visualTime = [targetTime − note.duration, targetTime]`、`spawnTime = min(visualTime.min, inputTime.min)`、`updateParallel` 里 `time.now < visualTime.min` 不画。首音符在 `time.now < 0` 时已生成并下落。
- Sonolus 官方教程 `sonolus.js-guide/play/09` 的示例是 `spawnTime = targetTime − 1`（1 秒示意，不是引擎常量）。`lib/src/bestdori/convert.ts` 的 `offset` 只写 `LevelData.bgmOffset`（默认 0），是谱面整体偏移，不是给开头补时。`engine-specs/play-lifecycle/overview` 只定义 Preparation / Update cycle，也没有固定前导秒数。
- ⇒ 引擎按 T 提前生成，无固定前导常量；本仓补的是 T 里「看得见的那一段」并封顶 2s（见定案 2），不是照抄固定 2s。用户记忆里的「固定 2s」没找到源码级证据，若指平台层准备期需另证。

## 定案（用户 2026-11-14；lead-in 口径同日二轮收口）

1. **补真实时长**，不用音符层 alpha 淡入掩盖：淡入只遮「突然出现在判定线」，音符仍无接近过程，作为谱面预览是失真的。
2. **`leadIn = min(T, LEAD_IN_CAP_SECONDS)`，`LEAD_IN_CAP_SECONDS = 2` 秒，`T = chart.approachS`**；再按 60fps 帧对齐（向上取整到 `1/fps` 整数倍，或多补 1 帧让首音符从窗口边界外起步）。默认 9.5 档 → 1.25s、12 档 → 0.4s、1 档 → 封顶 2s。
   - 理由：`A = 0.05 + 0.95·1.1^(50Δ/T)` 是指数曲线，T 前 ~80% 的 `A < 0.14` 几乎贴着渐近位置不动 ⇒ 慢速档补满 5.5s 只是多约 4s 静态画面；封顶 2s 与用户观察的「每次 1-2s」一致。
   - `simStart = openingSeconds + leadIn`；谱面渲染域统一 `seconds = t − simStart ∈ [−leadIn, …)`，帧循环不新增分支（`openingSegmentAt(t >= 6.75) === 'sim'` 的边界正好接上）。关掉开场时同样生效（第 0 帧即负秒）。
   - 慢速档首音符从 `A ≈ 0.22` 起步（跳过几乎看不见的前 3.5s），不是从渐近位置出现 ⇒ 音符层可在 lead-in 头 1–2 帧做极短淡入收掉「从无到 22%」的突变；**淡入只作边界收味，不替代补时长**。
3. **前导段保持无声**：开场人潮 `SE_RHYTHM_GAYA` 不动（`sfx.ts:57-67` 的 `endAt = OPENING_SECONDS` 不改），票 31 / ADR-0016 §5.1 的人潮定案不变；只把「收在 BGM 起点」的表述改成「收在开场段末尾」（BGM 起点此后是 `simStart`）。默认空档 1.25s，封顶后各档前导静音均 ≤2s。
4. **音画对齐**：BGM `start(simStart)`、键音 `at = evt.time + simStart`、轨长、`endingSfxCues` 的 `at` 同步平移（结尾 cue 的具体值在票 75 收口）；`evt.time >= D` 的键音过滤不在本票改。
5. 本轮**只改导出时间线**；实时回放 `simPlayback` / 播放条时间码 `[0, D)` 不动，等做可玩模拟器时再用统一的 `chartStartSeconds` 抽象接上。
6. 需同步改 ADR-0016 §5 时间线公式与 §5.1「绝不与谱面重叠 / 视频总长 = 6.75 + 谱面时长」等表述、`VideoExportRequest` 注释、`CONTEXT.md`「视频导出」词条。
7. **调参入口单一（为成片验收后调整留口）**：`LEAD_IN_CAP_SECONDS` 与 `leadInSeconds(chart, fps)` 只在 `exportSpec.ts` 定义一次，`exportVideo.ts` 算一次 `simStart` 后下传给 `frameDriver` / `renderAudioTrack` / `sfx`。用户导出视频看完效果后若嫌前导偏长 / 偏短，只改这个常量或公式，**不动帧循环、`drawSimFrameAt`、开场四段与素材**；锁测按公式断言，改数值只改期望值。

## 实现落点

`exportSpec.ts`（新常量 + 一处计算）、`exportVideo.ts`（总长 / offset / 下传 `simStart`）、`frameDriver.ts`（`seconds = t − simStart`）、`renderAudioTrack.ts`（BGM / 键音 / 轨长）、`sfx.ts` 仅注释；`OPENING_SECONDS` 与开场四段本身不动。④ 段末帧与 lead-in 首帧可能有 1 帧场地亮度 / 图层跳变，实现时抓帧对齐。
