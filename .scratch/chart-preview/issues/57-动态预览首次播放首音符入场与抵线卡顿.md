# 57 · 动态预览首次播放首音符入场与抵线卡顿

Type: bug
Status: resolved
Related: [basic-editor/179](../../basic-editor/issues/179-冷启动首次播放首音符与BGM出声同刻卡顿.md), [basic-editor/167](../../basic-editor/issues/167-首个音符抵线卡顿.md), [05](./05-仿真场渲染器.md), [21](./21-动态预览HUD与打击特效对齐Bestdori素材.md)

## 来源与症状

2026-10-29 用户汇报：
- 在**动态预览（仿真场）**中，**首次播放时会在到达第一个音符（同时也是 BGM 真正开始出声）那一刻发生明显卡顿**，后续再次播放则不再卡顿。
- 与工作台谱面画布的首次播放卡顿（[basic-editor/179](../../basic-editor/issues/179-冷启动首次播放首音符与BGM出声同刻卡顿.md)）对外表现高度一致：不是点击播放按钮立刻卡，而是经过前导空白、播放到第一个音符时音画一起卡一下，卡顿结束后音画依然保持同步。

## 根因

动态预览**不使用**工作台画布的 `noteLayerCache` 瓦片缓存，而是每帧由 [`drawSimFrameAt`](../../../src/preview/video/sim/simField.ts) 实时绘制。

当在 `t = 0` 暂停或刚点击播放时（以 `Frame by Frame` 为例，首音符位于 `t_first = 2.857s`，默认下落窗口 `approachS = 1.25s`）：
- 可见时间窗 `[0, 1.25s]` 内**没有任何音符**，所有打击特效 `since < 0`，且 `combo = 0`。
- 因此在暂停期与播放前 `1.6s` 内，音符远端 Mipmap、打击特效精灵与染色离屏缓冲、Combo 数字精灵**全部处于未解码、未构建、未上传 GPU 的冷态**，并在首次播放到达第一个音符时分两步在动画帧（rAF）内同步引爆：

### 1. 阶段一：首音符刚进入轨道顶端那一帧（`t = t_first - T`，约 `1.60s`）—— 同步构建深层 Mipmap

- 首音符在轨道顶端入场时透视缩放比仅 `a = 0.05`（目标绘制尺寸极小）。
- [`CanvasSpriteIcon.drawSingle`](../../../src/ui/CanvasSpriteIcon.tsx) 计算出所需层级为 `mipLevel = 3` 或 `4`。
- 即便工作台此前在 `es = 1.0` 下渲染过该音符皮肤（通常只建到 `level = 1` 或 `2`），此时 [`getMipLevelSource`](../../../src/ui/CanvasSpriteIcon.tsx) 也必须在当前 rAF 帧内**同步创建更深层级的离屏 Canvas 并执行 `imageSmoothingQuality = 'high'` 双三次下采样**。
- 若用户打开软件后直接进入动态预览（尚未在工作台渲染过该皮肤），此处还会触发整张音符皮肤图集 PNG 的**首次同步解码 + 1～4 级全链 Mipmap 构建**。

### 2. 阶段二：首音符到达判定线的精确那一帧（`t = t_first`，如 `2.857s`）—— 三张图集首次同步解码 + 5 张 `256×256` 离屏 Canvas 同步合成与上传

- [`loadSimAssets`](../../../src/preview/video/sim/simAssets.ts) 在加载 `particles.png`（`1024×1024`）、`digits.png`（`720×96`）、`combo.png`（`150×41`）时，仅等待了 `img.onload`，**从未调用 `img.decode()`，也从未将它们绘制到任何 Canvas 上**（Chromium 采取延迟图像解码与延迟 GPU 纹理上传策略，首次 `drawImage` 时才在渲染线程同步解码并上传纹理）。
- 在第一个音符到达判定线的**同一帧**（`0 <= since < EFFECT_DURATION` 且 `combo` 从 `0` 变为 `1`）：
  1. [`drawEffects`](../../../src/preview/video/sim/simField.ts) $\rightarrow$ [`drawSpriteEffect`](../../../src/preview/video/sim/simField.ts) **整场首次执行**：
     - 连续调用 [`radialCircleOf`](../../../src/preview/video/sim/simSprites.ts) 两次（白芯 + 染色外圈），同步分配 **2 张 `256×256` 离屏 Canvas** 并渲染径向渐变写入 `circleCache`；
     - 连续调用 [`particleTile`](../../../src/preview/video/sim/simSprites.ts) 三次（`beam` / `slot` / `ring`），同步分配 **3 张 `256×256` 离屏 Canvas**，**首次同步解码 `1024×1024` 的 `particles.png`**，通过 `source-atop` 混合模式完成染色合成后写入 `tileCache`；
     - 紧接着将该帧新生成的 5 张 `256×256` 离屏 Canvas 通过 `lighter` 加法混合绘制到主画布，触发首次 GPU 纹理上传。
  2. [`drawCombo`](../../../src/preview/video/sim/simField.ts) **整场首次执行**（`combo === 0` 时第 1152 行直接 `return`）：
     - 在同一帧内**首次同步解码并上传 `digits.png`（`720×96`）与 `combo.png`（`150×41`）**。
- **为什么第二次播放不卡？**
  - `tileCache`、`circleCache`（[`simSprites.ts`](../../../src/preview/video/sim/simSprites.ts)）与 `CanvasSpriteIcon.mipChains`（[`CanvasSpriteIcon.tsx`](../../../src/ui/CanvasSpriteIcon.tsx)）均为模块级静态单例缓存；且三张图集解码后的位图与 GPU 纹理已驻留内存。

### 3. 叠加因素：共享音频冷态 + 动态预览播放器生命周期与 60Hz 状态刷新

- **共享音频冷态**：在 `t = t_first` 同一时刻，BGM 结束前导静音首次输出非零样本，且首个打击音效触发 `scheduleKeySample` 混音（详见 [basic-editor/179](../../basic-editor/issues/179-冷启动首次播放首音符与BGM出声同刻卡顿.md) 根因 A）。
- **独立 `AudioEngine` 未关闭 `AudioContext`**：[`PreviewVideoStage.tsx`](../../../src/pages/preview/PreviewVideoStage.tsx) 在 `createSimPlayback` 时新建独立的 `new AudioEngine()`（即第二个 `AudioContext`），而 [`SimPlayback.dispose()`](../../../src/preview/video/sim/simPlayback.ts) 只调了 `engine.clear()`，未关闭 `AudioContext`。
- **播放期每帧无节流触发两层 React 重渲染**：[`PreviewVideoStage.tsx`](../../../src/pages/preview/PreviewVideoStage.tsx) 的 `onTick` 在每个 rAF 帧（60Hz）都直接调用 `setTick((n) => n + 1)` 与 `onSecondsChange?.(ctl.seconds)`（进而触发父组件 [`PreviewPage.tsx`](../../../src/pages/preview/PreviewPage.tsx) 的 `setVideoPlaybackSeconds`），未像工作台 [`usePlaybackCoordinator.ts`](../../../src/playback/usePlaybackCoordinator.ts) 那样按 `PLAYBACK_HUD_PERIOD_MS`（80ms）节流 React HUD 状态更新。

## 修复方案

1. **仿真场资源与离屏缓存预热（[`simAssets.ts`](../../../src/preview/video/sim/simAssets.ts) / [`simSprites.ts`](../../../src/preview/video/sim/simSprites.ts) / [`CanvasSpriteIcon.tsx`](../../../src/ui/CanvasSpriteIcon.tsx)）**：
   - 在 `loadImageElement`（[`simAssets.ts`](../../../src/preview/video/sim/simAssets.ts)）中，`onload` 后主动调用 `img.decode?.().catch(() => undefined)`，确保 `field`、`playLine`、`background`、`digits`、`combo`、`particles` 在返回前已完成位图解码。
   - 在 [`simSprites.ts`](../../../src/preview/video/sim/simSprites.ts) 新增导出 `warmupSimSprites(sprites, stageImages)` 并在 `probeSimServers`（`loadSimAssets`）中调用：
     - 预先为 `SIM_EFFECT_TINTS` 全部 6 种配色（`white` / `tap` / `flick` / `skill` / `directionalL` / `directionalR`）调用 `radialCircleOf`，并为 `SIM_WARMUP_TILE_SPECS` 全部 15 种图块染色组合（含无染色 `connectionRing`）调用 `particleTile`，在资源就绪阶段一次性填满 `circleCache` 和 `tileCache`（且无 DOM / 失败时不将 `null` 写入缓存）；
     - 使用离屏 Canvas 将场地素材、`digits`、`combo`、`particles` 以及预生成的 `circleCache` / `tileCache` 画布各 `drawImage` 一次，把首次位图上传消化在开播前。
   - 在 [`CanvasSpriteIcon`](../../../src/ui/CanvasSpriteIcon.tsx) 新增 `warmupImageMips`，在音符皮肤图片加载完成（`loadImage`）时预先构建 `1..PREWARM_MIP_LEVEL (5)` 全链 Mipmap，消除首音符远端入场帧（`depth ≈ 0.05`）的同步建链开销。
2. **播放器 rAF 键音推进、HUD 状态节流与 `AudioEngine` 生命周期收口（[`simPlayback.ts`](../../../src/preview/video/sim/simPlayback.ts) / [`PreviewVideoStage.tsx`](../../../src/pages/preview/PreviewVideoStage.tsx) / [`AudioEngine.ts`](../../../src/audio/AudioEngine.ts)）**：
   - `simPlayback.ts` 的 rAF `tick()` 主动调用 `engine.tick()`（与工作台 `usePlaybackCoordinator` 同口径），并在 `dispose()` 中调用 `engine.dispose()` 关闭底层 `AudioContext`。
   - `PreviewVideoStage.tsx` 的 `onTick` 在播放进行中按 `PLAYBACK_HUD_PERIOD_MS`（`80ms`）同时节流 `setTick` 与 `onSecondsChange`（驱动父组件 `PreviewPage` 的 `setVideoPlaybackSeconds`）两层 React 状态提交（起停切换与暂停态 `playing === false` 立即提交），避免每帧（60Hz）驱动 `PreviewPage` + `PreviewVideoStage` + `PlayBar` React 组件树重渲染与 Canvas 绘制抢占主线程。
3. **音频冷启动混音与 PCM 页预热**：
   - 与 [basic-editor/179](../../basic-editor/issues/179-冷启动首次播放首音符与BGM出声同刻卡顿.md) 共用同一套 `AudioEngine` / `keySoundSamples` 预热机制。

## 锁测

- **单元与 DOM 测试**：
  - `tests/unit/preview/video/SimEffects.test.ts`：验证调用 `warmupSimSprites(sprites)` 后，`circleCache`（6 项）与 `tileCache`（`SIM_WARMUP_TILE_SPECS.length = 15` 项）全部就位，后续重复采样全部命中缓存，零新建离屏 Canvas。
  - `tests/unit/preview/video/SimAssets.test.ts`：验证 `loadImageElement` 在 `onload` 后等待 `img.decode()` 完成再 resolve。
  - `tests/unit/preview/video/SimPlayback.test.ts`：验证 `simPlayback` 在 rAF `tick()` 中主动调用 `engine.tick()`，且 `dispose()` 调用 `AudioContext.close()`。
  - `tests/dom/preview/PreviewVideoControls.test.tsx`：验证播放期 `onTick` 按 `80ms`（`PLAYBACK_HUD_PERIOD_MS`）同时节流 `PlayBar` HUD 重渲与 `onSecondsChange` 父级状态回调，而起停切换与暂停态立即提交。
