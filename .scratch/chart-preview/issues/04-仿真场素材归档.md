# 04-仿真场素材归档（fieldskin / bgskin）

Type: chore
Status: resolved
Blocked by: —

**来源**：chart-preview/01 定案 6（用户 2026-09-30）。仿真场（05）需要两类素材，仓库现无：

- `ingameskin/fieldskin/*`：`bg_line_rhythm.png`（轨道场地）、`game_play_line.png`（判定线）；
- `ingameskin/bgskin/*`：`liveBG_normal.png`（谱面背景）。

现状证据：`scripts/fetch-bestdori-skins.mjs` 只有四类（`rhythm-note-skin` / `directional-flick-skin` / `rhythm-note-se` / `reference-only/judgeskin`）；`public/assets/skins/` 只有 12 套音符皮肤。**判定资源（judgeskin）在本 effort 用不上**——Bestdori 模拟器根本没有判定文字，HUD 的 digits / combo / particles 是它自绘的 sprite（research 笔记 §1.2）。

## 目标

- 归档脚本增两类：`fieldskin` / `bgskin`，复用现有全套行为（按 `_info.json` 目录树 + `.sprites` 校验 + 断点重跑 + `failures.json` + 非零退出码）。
- 产物仍落 `docs/resource/bestdori/<server>/...`，**不入 git、不进安装包**（`.gitignore` 已收 `docs/resource/bestdori/*/`）。
- **开发期直读口径**（本票的接缝）：仿真场在开发期从该目录读素材。推荐形态 = **Vite dev 中间件**（`apply: 'serve'`，把 `docs/resource/bestdori/` 挂在一个 `/__bestdori-assets/` 前缀下）。
- 硬约束：`public/assets/` 不放、`dist/` 不含、仓库不提交这些二进制。
- 更新 `docs/resource/bestdori/README.md`：资源分类表补两类 + 使用边界（仍为"不得再分发 / 仅供本地研究"）。

## 副作用与稳定获取（用户 2026-09-30 要求标注）

**副作用（刻意取舍）**：素材不进仓库、不进安装包 ⇒ **没跑过归档脚本的机器上，仿真场没有场地 / 背景，只能给空态**（预览页其余部分照常可用）。空态文案必须**直接给出获取命令**，而不是一句"素材缺失"：

```
本地还没有场地 / 背景素材。跑一次（幂等，可重复执行）：
  node scripts/fetch-bestdori-skins.mjs --category fieldskin,bgskin
```

**稳定获取口径**（唯一入口 = 归档脚本，不另造第二套下载器）：

| 层 | 做法 |
| --- | --- |
| 主路 | `node scripts/fetch-bestdori-skins.mjs --category fieldskin,bgskin` —— 幂等、断点重跑、SHA-256 校验、失败写 `failures.json` 且非零退出（沿用既有脚本行为，本票只加类别） |
| 便捷入口 | `package.json` 加一个 script 别名（如 `npm run fetch:preview-assets`），让空态文案与文档都指向同一条命令 |
| 镜像 / 离线 | 完整 `manifest.json` / `failures.json` 照既有约定上传 release 渠道，他人从 release 拉到本地后脚本自动跳过已校验文件 |
| 后路 | 用户自备素材目录 / 运行时拉取（前置 ADR-0011 网络层）——**留后票** |

获取不稳定时（Bestdori 改路径 / 限流）：脚本按清单逐包拉取、失败明细全进 `failures.json`、非零退出，**不静默**——这是本仓库既有口径，本票不降级它。

## 不在本票（留后票）

## 锁测

- `tests/static/BestdoriArchiveCategories.test.ts`：脚本类别表含 `fieldskin` / `bgskin`；`public/assets/**` 不含这两类（防"顺手拷进运行时目录"）；dev 中间件只在 serve 模式挂载。
- `tests/static/PreviewAssetAcquisition.test.ts`（**副作用的看守**）：仿真场空态文案含 `fetch-bestdori-skins.mjs --category fieldskin,bgskin`；`package.json` 的别名 script 指向同一命令；`scripts/README.md` 与 `docs/resource/bestdori/README.md` 都记了这条获取路径——防"空态只说素材缺失、不说怎么拿"。
- 冒烟（有网时，不进 CI）：`node scripts/fetch-bestdori-skins.mjs --dry-run --category fieldskin,bgskin` 能把清单列全且不写盘。

## Answer

2026-10-07 实现（待用户验收）：

**改了什么**

- `scripts/fetch-bestdori-skins.mjs`：类别表增 `fieldskin` / `bgskin`（`ingameskin/fieldskin|bgskin`；产物目录与类别 id 同名：`docs/resource/bestdori/<server>/{fieldskin,bgskin}/<包>_rip/`）；断点重跑 / 校验 / `failures.json` / 非零退出全部沿用既有代码路径。预览包判定 `*sample` → `*sample|*preview`（bgskin 的 `skin_*preview` 只含 `previewBG.png`，标 `packageKind: "sample"`；既有四类没有 `preview` 后缀包，行为不变）。
- `vite.config.ts`：新插件 `bestdori-preview-assets`（`apply: 'serve'`），把归档目录挂在 `/__bestdori-assets/`（GET/HEAD；404/403/405；`no-store`；`.sprites` 按真实格式给 `application/json`；`..` / 编码越界 403；裸前缀也 404，不落 SPA 回退页冒充 200）。
- 获取命令四面同源：`package.json` 别名 `npm run fetch:preview-assets`；空态文案落 i18n（`preview.video.assetsMissing` / `preview.video.assetsCommand`，票 05 消费）；`scripts/README.md` 与 `docs/resource/bestdori/README.md` 记录同一命令（分类表补两类 + 使用边界改为"不接发行构建、仅 dev 直读"）。
- 锁测：`tests/static/BestdoriArchiveCategories.test.ts`、`tests/static/PreviewAssetAcquisition.test.ts`（各 3 用例）。

**验证**

- dev server（`bash scripts/dev.sh`）curl 实测：png 200（返回字节 sha256 = manifest 记录 sha256）、`.sprites` 200 `application/json`、缺失 404、越界 403、裸前缀 / 目录 404、HEAD 正常、普通路径 `/` 不受影响。
- `npm test` 203 文件 / 2226 用例全绿（含新增 6 例）；`npx tsc -b` 通过；改动文件 eslint 干净（全仓 lint 与 `npm run test:types` 有**存量**红，均在本次未触碰的文件，未处理）。

## Comments

### 2026-10-11 定案变更：空态文案不再给获取命令

- 本票定案的「空态文案必须**直接给出获取命令**」**已被用户推翻**（见 release-pipeline 票 03 的遗留）。两条理由：打包后看到空态的是应用使用者，`npm run assets:sync` 是对开发者的话术，摆出来也跑不了；且"本地还没有…"断言了成因，盖不住"素材在包里但 URL 解析不到"这种情况（03 的真实成因）。
- 现状：`preview.video.assetsMissing` 改为中性陈述（加载失败 + 缺什么 + 可能是本地资源缺失或不完整），`preview.video.assetsCommand` 键删除，空态只剩一句话、不再有命令块。
- 本票其余部分（脚本两类 / 别名 / 文档同源）不变；取件路径仍由 `package.json` 与 `scripts/README.md` 看守。
