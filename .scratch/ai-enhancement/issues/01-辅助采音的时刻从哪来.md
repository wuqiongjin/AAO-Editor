# 01 · 辅助采音的时刻从哪来

Type: research
Label: wayfinder:research
Status: resolved
Blocked by:

## Question

辅助采音要在用户圈定的一段音频上，标出「这一时刻有一个音」。标记落在音频时刻（秒，可带小数）上，画在轨道右侧、画布外。同一秒内可以有多处标记。标记不是音符，不进谱面代码，不读当前谱面，也不读倒流区。

只调研、不改产品代码、不拍板用哪一家库。

必须回答：

1. 从音频得到这种时刻，现成的可靠做法有哪些（起音 / 瞬态检测一类）。每种做法的一级来源是什么（库的官方文档、论文原文，不要只引用转述）？
2. 这些做法输出的是时刻，还是必须先有 BPM / 节拍网格？本编辑器的采音标记不读谱面 BPM。
3. 在浏览器里、对已经解码进 `AudioBuffer` 的音频（见 `src/audio/AudioEngine.ts`）能不能跑？需要把整段音频送到进程外吗？
4. 一段几分钟的歌曲、用户只圈其中十几秒时，延迟大概在什么量级？哪些做法明显做不到「过一会儿标出来」？
5. 误检（多标、漏标）在这类任务里通常差在哪里？不要给「准确率百分比」除非一级来源里有、并且说清了测试集。

不要写「因此智能制谱应该 / 不应该依赖采音标记」。那是 [03 · 智能制谱的输入是否包含采音标记](./03-智能制谱的输入是否包含采音标记.md)。

## Answer

起音检测（ODF + 峰拾取，含 SuperFlux；可选 RNN/CNN）直接输出秒级时刻，**不需要 BPM**。已有 `AudioBuffer` 时可在浏览器用 Essentia.js（或自写峰拾取）跑，不必进程外；原生 librosa/aubio/madmom 则通常要。十几秒圈选上，经典/SuperFlux 量级通常可「过一会儿」标出；重 ML 端到端或整曲出站传输则难。误检主因是振音多标、软起音漏标、阈值与 ODF 偏好。
