# 03 · 智能制谱的输入是否包含采音标记

Type: research
Label: wayfinder:research
Status: resolved
Blocked by:

## Question

使用上，智能制谱不要求用户先做辅助采音。一次调用的体验是：圈定一段音频，过一会儿，画布上出现一份 AI 提案。内部会自己做 BPM 自动识别。用户可以不打开谱面代码。

现在不知道的是实现上的输入：智能制谱是直接听这段音频，还是必须先有一批「何时有音」的时刻（也就是采音标记那种数据）才能往下生成谱面？

只调研、不改产品代码。可以给出建议，但建议要标成建议，并写明它依赖哪条一级来源。

必须回答：

1. 已发表的、有作者原文的自动制谱（音游谱面、钢琴卷帘、鼓谱一类）通常吃什么输入？把「只吃音频」「先做起音检测再生成」「还要 BPM / 拍点」分开写。不要把博客转述当成来源。
2. 本编辑器第一刀只需要：范围内的 BPM 音符 + 单键。单键有 beat、lane（0..6）。只靠「何时有音」得不出 lane。一级来源里，lane 或音高是怎么来的？若来源只做到时刻、做不到轨道，明确写这一刀还缺什么。
3. 从第一刀（单键 + BPM）到「合理谱面」（再加滑键、技能键、方向键、滑条）时，输入会不会变多？哪些是音频里没有、只能靠约定或模型的？
4. 若生成器内部自己算时刻，用户就不必先点辅助采音。这和「生成器的输入里有一批时刻」不矛盾。请分开回答：用户要不要先做采音，以及程序要不要一批时刻。
5. 对照本仓库的谱面代码：单键和 BPM 在代码里各是什么（`CONTEXT.md`、谱面代码转换）。提案要能过现有校验、并在画布上画出来，最少要有哪些字段？

本票不决定「因此地图改成制谱被采音挡住」。那要等答案写回之后再看。

## Answer

**用户要不要先做采音：不要。** 使用上已定互不要求先后；一级来源里的制谱入口是音频（常加 BPM/难度），不是用户采音标记。

**程序要不要一批时刻：常见要（内部自算），但不等于读采音标记。** 两段式（DDC / GenéLive onset / TCP）会先有时间戳再选轨；端到端可不暴露为采音对象。只靠时刻不够写单键——还缺 `lane`（0..6）以及秒→`beat`（靠范围内 BPM）。提案最少：`{type:"BPM",beat,bpm}` + `{type:"Single",beat,lane}`。
