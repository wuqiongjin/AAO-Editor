## 来源

用户在播放过程中框选音符并执行缩放操作（Ctrl+滚轮），偶然触发所有音符材质（单键、滑条端点、SP绿条带体、同时点击线等）变得极度模糊（4×2 像素巨大马赛克拉伸），而主画布上的选区框、选区黄色描边、轨道网格线等保持锐利高清。

## 症状

1. **音符层材质极端低清与马赛克化**：
   - 画面中所有音符（Single、Slide 端点、连接线、双押线）整体退化为约 4×2 像素的方块马赛克，边缘严重失真发虚。
   - 音符车道位置与横向布局完全正确，并未越出车道，但材质纹理被强行拉伸数倍。
2. **顶层与底层矢量绘制元素完全正常**：
   - 框选框（蓝色半透明选区框、虚线边框、左右标注文本 `19.43`、`218`）极其清晰锐利。
   - 选中的 3 个音符周围的黄色高亮描边矩形清晰锐利。
   - 轨道背景拍线、小节线、左右沟槽、顶栏与底栏 UI 均为原生高清物理分辨率。
3. **播放中持续死锁**：
   - 只要播放不暂停，即使缩放手势结束或等待数秒，模糊状态绝不自动恢复清晰；仅暂停播放后方可恢复正常渲染。

## 根因

1. **播放状态硬编码拦截了瓦片重建（`noteLayerCache.ts:600`）**：
   - 为保障 60 FPS 播放帧率，`NoteLayerCache.draw` 使用 `if (!rc.playing)` 拦截了同步光栅化分支。
   - 当在播放状态下改变缩放（`viewport.scale`）时，无论处于缩放手势中还是手势停止 250ms 后的 settle 帧，由于 `rc.playing === true`，`pending` 重建列表恒被置空，视口内已有瓦片永远不会被同步更新为当前 scale。
2. **异步预取队列漏检尺度过期（`noteLayerCache.ts:395`）**：
   - 播放时承担瓦片补充的 `enqueuePlayingTiles` 在过滤瓦片时，判断逻辑为 `if (cur && !cur.dirty) continue`。
   - 它只检查瓦片是否存在和是否被打脏，**完全漏掉了尺度过期检查**（即未判断 `Math.abs(es / cur.refScale - 1) > STALE_TOL`）。
   - 导致已存在的 stale 瓦片既进不去同步重建，也进不去异步队列，彻底陷入死锁。
3. **极小尺度烘焙产生 4×2 像素 Mipmap 塌缩**：
   - 当用户在播放中用触控板捏合或滚轮快速缩小时，缩放比例连续下降，瞬态触及极小值（如 `MIN_SCALE = 0.1` 附近）。
   - 此时视口可见拍范围剧增，尚未缓存的瓦片以 `es ≈ 0.1` 被加入异步队列并调用 `renderTile`。
   - 由于单音符屏幕尺寸仅 2~3px，`CanvasSpriteIcon.drawSingle` 的 `mipLevelFor` 匹配到最高级的 Mipmap（Level 5~6），截取的精灵贴图仅 4×2 像素，直接被烘焙进瓦片。
4. **中心缩放 blit 放大 7 倍产生巨大像素马赛克**：
   - 当用户将缩放调整/回弹到当前截图中的 `69%`（`es = 0.69`）时，由于死锁存在，瓦片停留在 `refScale ≈ 0.1`。
   - `tileBlitRect` 按照 $k = es / refScale \approx 6.9$ 倍绕画布中心拉伸 blit（保证车道中心线对齐，音符不飞出车道）。
   - 配合 `ctx.imageSmoothingEnabled = false`（最近邻），原本 4×2 像素的贴图被强行放大 7 倍，呈现为巨大的色块马赛克。
5. **框选操作缺乏打脏机制**：
   - 框选（Marquee）为纯视图交互，不改动谱面数据，不触发 `diffNotes` 将瓦片打脏（`t.dirty` 恒为 false）。
   - 使得在框选手势进行中进行缩放时，无法依赖任何编辑动作打破死锁。

## 修法（已实现）

1. **补全异步预取队列与出队消费的尺度过期检查**：
   - 提取模块级辅助函数 `isTileStale(t: Tile, es: number): boolean`（`!t.empty && Math.abs(es / t.refScale - 1) > STALE_TOL`）。
   - 在 `enqueuePlayingTiles` 中，对于已存在的瓦片增加 `!isTileStale(cur, es)` 判定，stale 瓦片排入 `playTileQueue`，不再被跳过。
   - 在 `drainOnePlayingTile` 中同步放行 stale 瓦片（`!isTileStale(cur, snap.es)`），避免出队时被提前 `return`。
   - 在主渲染循环与同步重建分支中统一接入 `isTileStale`，消除了散落各处的逻辑重复。
2. **播放帧异步平滑换新**：
   - 维持播放期不进行同步光栅化（`if (!rc.playing)`）以保证 60 FPS 绝对不卡顿不掉帧；
   - 视口覆盖块（1~2 块）通过队列在 16~32ms 内无缝完成高清换新，并在暂停时保留当帧同步重建兜底。

## 锁测

- `tests/unit/rendering/cache/PlaybackZoomTileRefresh.test.ts`（4 用例全绿）：
  - 用例 1（播放中变缩放异步排队）：验证在 `rc.playing = true` 下改变 `scale`（从 0.2 到 0.7），已存在瓦片被识别为 stale 并推入 `playTileQueue`，drain 后瓦片 `refScale` 成功更新为 0.7，后续绘制帧消除 stale blit。
  - 用例 2（极小比例缩小后放大回弹）：验证先以 0.1 播放生成瓦片，随后直接放大到 0.69，瓦片成功换新为 0.69，杜绝死锁发糊与拉伸。
  - 用例 3（微小缩放容差）：验证在 `STALE_TOL = 2%` 容差内不触发多余重建，保持原瓦片复用。
  - 用例 4（播放中缩放后暂停）：验证播放中缩放后立即暂停时，暂停帧同步重建视口瓦片，立即恢复清晰。
