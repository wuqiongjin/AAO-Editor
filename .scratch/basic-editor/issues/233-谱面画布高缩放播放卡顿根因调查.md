# 233 · 谱面画布高缩放播放卡顿根因调查

Type: research
Status: resolved

## 来源与范围

用户 2026-11-13：本地 `npm run electron:dev` 播放谱面画布概率卡顿，缩放越高越容易触发；要求先复现、分析，不修改产品代码。
样本为本机工程 `p38526b919a60406c8e225fe1467d0217`，谱面 `c52d1b29e3051438c81d46027ade88577`（Retribution ~ Cycle of Redemption ~），173.335 秒，1268 个顶层音符，含 23 条负 BPM 事件。
**本票 resolved 仅表示调查完成，性能问题尚未修复。**

## 结论

播放期的瓦片预取由 `setTimeout` 调度，但 `drainOnePlayingTile → renderTile → renderNotes → renderSpanBands → renderBandStrip → rasterBandRuns` 仍整块同步执行于渲染器主线程。一块含多臂折返带体的新瓦片需要约 60–100ms；rAF 绘制本身约 1ms，仍会被该任务阻塞。

`rasterBandRuns` 对每个折返 run 的每行、每个横截面像素执行采样与透明度合成。缩放使带宽与瓦片高度同时增加；同一实际输入从 100% 到 300% 的位图面积约增加 8.8 倍，8 个 run 的自叠进一步放大工作量。现有视口裁剪与瓦片缓存有效，但未控制**单块新增瓦片任务**的连续占用时长。

## 调查与复现

- 环境：Windows，本机 Electron 38.8.6，60Hz，DPR 1.25，硬件 Canvas / GPU 合成均启用；工程副本与独立 userData；默认显示设置、原 BGM 与键音，原工程未写入。
- 同 `electron:dev` 当前分支选择方式：未设置 `NODE_ENV`，实际加载 `file://…/dist/index.html`；该命令没有设置 `NODE_ENV=development`（`electron/main.cjs:7` / `electron/window/createWindow.cjs:75`）。另显式使用 development 测试当前 Vite 源码，两者都复现。
- 未替换任何模块的 dist 基线，从 0 秒播放 14 秒：100% 的 rAF 回调实际到达间隔最大 18.9ms，超过 50ms 为 0 次；300% 最大 166.5ms、超过 50ms 为 7 次，6 个 63–75ms LongTask。
- 未替换模块的当前源码基线，300% / 0–14 秒：最大回调到达间隔 104.9ms，6 个 65–102ms LongTask。
- 最后用未替换模块的当前源码执行 `probe.mjs --version=dev --zooms=300 --seconds=12 --tag=assert-repro --assert-smooth`：实际退出码 1；开播第一秒后最大回调到达间隔 75.2ms，6 个 62–72ms LongTask，再次捕获同一症状。
- 源码计时探针，不开 CPU profiler，每档从 0 秒播放 12 秒：

| --- | ---: | ---: | ---: | ---: |
| 100% | 23.5ms | 22.5ms | 0 | 28.7ms |
| 200% | 55.7ms | 53.1ms | 1 | 58.4ms |
| 300% | 108.4ms | 103.9ms | 6 | 111.2ms |

- 瓦片编号依次为 5、6、7…，未重复；每块开始时队列已无剩余项。此复现的主因不是反复淘汰重建或任务积压。
- 因果对照：仅在独立实例的网络响应中令 `rasterBandRuns` 返回 null，音频、滚动、瓦片任务与其余绘制继续。300% / 0–14 秒的单块瓦片降为 0.2–0.4ms，LongTask 从 6 个变为 0 个，超过 50ms 的回调间隔也为 0。该消融改变带体显示，**只用于定位，不是修法或画质验收**。
- CPU profiler 独立复测：`renderTile` 采样累计约 576ms，`rasterBandRuns` 累计约 536ms；dist trace 中主线程长任务均落在瓦片排水的 TimerFire；最大 GC 约 3.7ms。
- 最小化到一个实际捕获的 raster 输入（8 个 run、30 个点），脱离工程、React、Canvas 绘制、音频，仅调用原始 `rasterBandRuns`：每轮暖机 3 次，测量 7 次；首轮 100% / 200% / 300% 中位耗时分别 **7.7 / 30.8 / 72.5ms**，复测 **11.1 / 40.2 / 76.9ms**。位图分别为 269×646 / 530×1286 / 793×1926；`micro.mjs --assert-budget` 已实际返回退出码 1（300% 76.9ms > 16.67ms）。

### 间歇性解释与边界

静止时已有窗口预热，命中缓存后画布主要做 blit；播放进入未预热区域才产生整块同步构建。实际任务时机、缓存命中与帧调度影响可见顿挫，符合“有概率、倍率越高越明显”的报告。首个重块在本次 300% 记录约开播后 2.9 秒开始，随后约每 1.16 秒一块；与 512 pos px / 440 pos px·s⁻¹ 对应。

这里的“间隔”采用 heartbeat 的 `performance.now()` 实际到达时间；另存 rAF timestamp，两者不混用。它不是屏幕 present FPS 的逐帧测量。结论覆盖本次 0–14 秒折返区域；没有把所有时段、所有配置的卡顿统一归因。
