## Question

应用 5 个页面（工作台 / 音频 / 素材 / 快捷键 / 设置）中，**4 个非工作台页面**的布局壳当前不一致：
- **音频**用"侧边次级索引（独立于正文外，3 tab） + 右侧 detail"
- **素材**用"页内类别子 tab（顶部 2 个）+ 单列内容"
- **设置**用"侧边次级索引（**在正文内**，分组） + 右侧 detail"
- **快捷键**用"页顶只读区 + 搜索 + 大表格，整页不动表格自身滚"

4 页在"页面头（`.page-intro`）"已共用，但页面头之后的内容布局形态各异：是否有次级索引、次级索引是顶部还是侧边、侧边是在正文外还是正文内、整页滚还是内嵌滚、容器宽度等 5 个维度都有差异。本轮目标：将这 5 个维度的差异收敛为一个**可复用模板** `<AppPageShell>`，4 页一次性迁移到模板上，并沉淀"未来加新页"用的决策清单。

## 期望

- 新建 `src/components/layout/AppPageShell.tsx`，以 compound component 形式暴露：
  - `<AppPageShell.Header eyebrow title description />`（沿用现有 `.page-intro` class，CSS 不动）
  - `<AppPageShell.Sidebar>` / `<AppPageShell.SidebarGroup title>` / `<AppPageShell.SidebarItem icon label>`（侧边索引；可空、可分组；激活态统一为"主色软底 + 主色文字 + 弱描边"）

**第二轮回炉（2026-08-28 17:00，按 H 原型几何整改）**：

- 用户反馈"当前布局完全没有按照预期来"。**根因**：原实现 Header 走 `width: min(width 档, ...)` + flex 自然流，未与 body 强制同宽同左缘；且 ADR 硬约束的"body 居中"被解释为 main 容器内的水平 auto margin（实际是左对齐到 sidebar 右侧），未实现"整块居中于 main 视口"。
- 整改（`AppPageShell.tsx` + `AppPageShell.css`）：
  - `AppPageShellRoot` 计算 `blockWidth = sidebar(200) + gap(24) + body(<width 档>)`（如 audio/settings 1144 / assets 1264 / shortcuts 920）

- `AppShell.tsx` 保持 `navCollapsed = true`（默认折叠态，nav=52），H 几何前提 main 视口 ≥ blockWidth=1144 → 1228 满足。

**第三轮整改（2026-08-28 18:30，修复 H 几何未生效的时序/宽度 bug）**：

用户目检反馈"布局完全没有对标 H 版原型"。DevTools 探针实测（视口 1920，nav=52）证实第二轮实现未生效：

- **根因 1（时序 bug）**：`AppPageShellRoot` 中 `blockWidth` / `headerLeft` 在第二个 `Children.forEach`（给 `sidebar` 赋值）**之前**计算，计算时 `sidebar` 恒为初始 `null` → `blockWidth` 恒 = body 单宽（920/1040），Header 左缘偏移恒为 0（贴 sidebar 左缘横跨整块，退化成 D 版式）。实测 `main inline: "width: 920px"`（音频页）、`"width: 1040px"`（素材页）均可复现。
- **根因 2（Body 宽度失控）**：Body 只注入 `max-width` 无 `width`，且 CSS 为 `flex: 0 0 auto` → body 塌缩成内容 max-content 宽（音频页实测 343px、素材页 952px 且溢出 main）。**"每页布局都不一样"的直接原因**。
- **根因 3（结构性隐患）**：Header `position: absolute + top: 42px` + main 硬编码 `padding-top: 122px`（`HEADER_HEIGHT=98` 估算值），description 两行的页 Header 实际高度 >98，随时可能重叠；窄视口下 `calc` 偏移算歪。

整改（`AppPageShell.tsx` + `AppPageShell.css`，4 页 JSX / compound API 仍不动）：

- 单次遍历 children，`sidebar` 先赋值再做几何计算（修根因 1）；
- Header 改回**正常文档流**：新增 `app-page-shell__head` 包装层，与 main 同宽（`--aps-block-width`）、同 `margin: 0 auto` 居中；`.page-intro` 在包装层内 `margin-left: var(--aps-header-indent)`（= sidebar 200 + gap 24；无 sidebar 页 = 0）→ Header 与 Body 严格同宽同左缘。删除 `position: absolute`、`HEADER_HEIGHT`、`padding-top: 122px`（修根因 3）；
- Body 改 `flex: 1 1 auto; min-width: 0` + `max-width` 档值：main 满宽时 body = 档值（920/1040），视口收缩时随 main 同步收缩（修根因 2）；
- `.app-page-shell` 改 flex column + `padding: 42px 24px 0`，`__head` / `__main` 均 `max-width: 100%` 优雅降级；展开 app-nav（156px）实测不撑破。

## 第四轮回炉（2026-08-29 00:50，sidebar 自适应 + body fluid 方案）

第三轮 H 几何落地后用户目检 4 页，发现 4 页"body 居中位置明显不一样"：

- ADR-0007 §3 删 width 档；§4 删"Body 居中 + max-width"硬约束；
- 4 个 page 文件**全部移除 `width` prop**；
- 响应式断点 720px：sidebar 收为顶部水平条。

**此方案作废**（被第五轮推翻，详见下）：sidebar 宽自适应 + body fluid 仍不能解决"4 页 body 距 main 视口左缘严格相同"——fluid body 撑满剩余后 body 真实宽跟视口强相关，反而引入新问题（body 贴右、sidebar 跟 app-nav 紧贴看着别扭等）。

## 第五轮最终落地（2026-08-29 01:40，sidebar 紧贴 body + 整块居中 + body 限宽 920）

**用户四次纠正的最终诉求**（按时间顺序）：

1. "body 距 main 视口左缘保持相同距离"——4 页几何统一；
2. "sidebar 贴在 body 左边（依附于 body），不是贴 main 视口 0"——sidebar 是 body 的附属；
3. "body 限宽到一个舒服阅读宽度，不要 fluid 撑满（body 占比稍微大点）"——body 限宽；
4. "body 固定的左侧起始位置再向左偏 5px"——整块左偏微调；
5. "快捷键页（无 sidebar）body 位置不对，header 是正确的"——快捷键页 header 跟 body 同左缘。

**最终几何规则**（4 页共用，ADR-0007 §5 定案）：

```
[app-nav 52px] [---- 内容块 1144px 居中于 main 视口 ----] [留白]
                [sidebar 200] [gap 24] [body 920]
                整块 transform: translateX(-5px) 整体左偏 5px
```

- **整块宽 1144** = sidebar(200) + gap(24) + body(920)，4 页统一；
- **整块 `margin: 0 auto` 居中**于 main 视口（= 视口 - app-nav 52）；
- **4 页整块居中后左缘相同** = 居中偏移 = `(main vp - 1144) / 2`；
- **4 页 body 距 sidebar 左缘 = 24（gap 硬约束）**，4 页 body 距 main 视口左缘相同；
- **sidebar 紧贴 body 左边**（是 body 的附属，不是贴 main 视口 0 的独立元素）；
- **header 跟 body 同左缘同宽 920**（在 `__head` 包装层内 padding-left 224 偏移到 body 左缘）；
- **整块左偏 5px**（`--aps-block-shift: -5px` + `transform: translateX(-5px)`）—— 让 body 起始位置稍微偏左，视觉上更舒服；副作用：sidebar 跟 app-nav 中间自然留 5px 边距（之前担心紧贴，现在反而有自然分隔）；
- **快捷键页（无 sidebar）**：`__head` padding-left 0（避免 header 跟 body 错位 224），header 跟 body 都在 main 0 位置 = 整块居中后左缘 = header/body 严格对齐。

**最终几何预期**（视口 → main vp → 整块居中偏移 → 整块实际左缘 → body left）：

| 视口 | main vp | 居中偏移 | 整块实际左缘 | body left (有 sidebar 3 页) | body left (快捷键) |
|---|---|---|---|---|---|
| 1024 (nav 52) | 972 | 0 (撑破, max-width:100% 截) | -5 | 219 | -5 |
| 1280 (nav 52) | 1228 | 42 | 37 | 261 | 37 |
| 1440 (nav 52) | 1388 | 122 | 117 | 341 | 117 |
| 1920 (nav 52) | 1868 | 362 | 357 | 581 | 357 |

| 元素 | 规则 | 1280 视口 (nav 52) 实测值 |

## 流体几何定案（2026-08-29，取代第五轮 1144 居中）

第五轮"整块 1144 `margin: 0 auto` 居中 + body 限宽 920 + 整块左偏 5px"落地后，用户继续目检，反馈：① 快捷键页 header 与 body 未对齐（差几 px）；② 希望 body 再加宽 ~12px；③ 希望 body 与 sidebar 整体再往右 2–3px（极微）。据此转向**流体几何**（不再整块居中，改 L/R 内边距 + 锚点 body），并修复 header/body 对齐的根因。

**几何规则**（4 页共用，定案在 ADR-0007 §5）：

```
[app-nav 52] | L 51 | [sidebar clamp(140,12.5%,200)] gap 24 [body --aps-body-w] | R 32 |
              └──────────────────────── 相对 main 视口（= 100vw − nav 宽）─────────────────────────┘
```

- **左边距 L** = `--aps-inset-l: 51px`（sidebar 起始位置；含 +3px 右移微调）；
- **右边距 R** = `--aps-inset-r: 32px`；
- **sidebar 宽** = `clamp(140px, 12.5%, 200px)`（12.5% of main 视口，140–200 兜底）；
- **gap** = `24px`（模板硬约束 #2）；
- **body 宽** = `--aps-body-w = max(920px, min(100%, 920px + 12px + (主内容区 − 1440px) × 0.3))`（主内容区 = `100vw` − nav 宽，nav 由 `--nav-width` 提供，折叠 52 / 展开 156）
  - 主内容区 ≤1440：body 恒 **920**（1280 窗不变窄，与历史固定 920 一致）；
  - `+12px`（`--aps-body-bump`）：整体加宽微调（用户诉求 #2）；
  - `>1440` 区间按 `0.3/px` 线性增长；**1920 窗（nav 折叠）≈ 1060**（+128+12）；
  - `min(100%, …)` 窄屏兜底。

**header / body 像素级对齐（修复根因）**：旧实现把"sidebar 占位宽" bake 进 `__main` 的 `padding-left`，其中 `12.5%` 相对**包含块父块宽**解析；而 header 走 `__head` 的 flex 占位槽，`12.5%` 相对**容器内宽（= 父块宽 − L − R）**解析——两个基数差 `L+R = 83px` → `0.125 × 83 ≈ 10px` 偏移（即用户看到的"差几 px"）。**修复**：`__head` 与 `__main` 统一用同款 `.app-page-shell__slot` flex 占位槽（无 sidebar 页由 `__main` 渲染该槽），两者内宽一致 → 槽里 `12.5%` 与 body 的 `--aps-body-w` 百分比相对同一基数解析 → header 与 body 严格同宽同左缘。删除 `data-has-sidebar` 的 padding-left 覆盖。

**实现改动**（`AppPageShell.tsx` + `AppPageShell.css`）：

- 删 `--aps-block-w: 1144px` / `--aps-body-w: 920px` / `--aps-block-shift: -5px` 及整块 `margin: 0 auto` + `transform: translateX(-5px)` 居中/左偏；
- 新增 `--aps-inset-l: 51px` / `--aps-inset-r: 32px` / `--aps-sidebar-w: clamp(140px,12.5%,200px)` / `--aps-body-bump: 12px` / 新 `--aps-body-w` 表达式；
- 新增 `.app-page-shell__slot`（`flex: 0 0 var(--aps-sidebar-w); width: var(--aps-sidebar-w)`），`__head` 恒渲染一个槽、无 sidebar 页 `__main` 也渲染一个槽；
- `__head` / `__main` 均 `padding-left: var(--aps-inset-l); padding-right: var(--aps-inset-r); gap: var(--aps-gap)`（不再 `margin: 0 auto`）；
- sidebar `flex: 0 0 var(--aps-sidebar-w)`；body `flex: 1 1 auto; min-width: 0; max-width: var(--aps-body-w)`；
- 响应式断点 720px：`__slot` 隐藏、L/R 归 16px、sidebar 收顶部水平条。

**验证**（dev server `https://ofwtwe3f6t-5173.cnb.run/`，视口 1920、nav 折叠实测）：

- 快捷键页（无 sidebar）：header `left=327 / width=1060.4`，body `left=327 / width=1060.4`，`__slot left=103 / width=200` → header 与 body 左缘、宽度严格一致（对齐 bug 修复）；
- 设置页（有 sidebar）：header `left=327 / width=1060.4`，body 同，sidebar `left=103 / width=200` → 无回归；
- body 宽 1060（较修复前 ~1048 加宽 +12，满足诉求 #2）；header/body 左缘较前右移（满足诉求 #3）。
- `npx tsc -b` / `vitest` / `npm run build` 绿；`AppPageShell.css` / `AppPageShell.tsx` 无 lint 告警。

**本轮 issue 44 闭环**——4 个非工作台页布局彻底统一为流体几何（sidebar 自适应 + body 锚点 920 + L/R 内边距 + `__slot` 占位槽对齐），取代第五轮 1144 整块居中；定案在 ADR-0007 §5，未来加新页直接套用 ADR-0007 §6 四题决策清单即可。
