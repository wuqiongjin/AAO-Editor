## Question

应用 5 个页面（工作台 / 音频 / 素材 / 快捷键 / 设置）中，**4 个非工作台页面**的布局壳当前不一致：
- **音频**用"侧边次级索引（独立于正文外，3 tab） + 右侧 detail"
- **素材**用"页内类别子 tab（顶部 2 个）+ 单列内容"
- **设置**用"侧边次级索引（**在正文内**，分组） + 右侧 detail"
- **快捷键**用"页顶只读区 + 搜索 + 大表格，整页不动表格自身滚"

4 页在"页面头（`.page-intro`）"已共用，但页面头之后的内容布局形态各异：是否有次级索引、次级索引是顶部还是侧边、侧边是在正文外还是正文内、整页滚还是内嵌滚、容器宽度等 5 个维度都有差异。本轮目标：将这 5 个维度的差异收敛为一个**可复用模板** `<AppPageShell>`，4 页一次性迁移到模板上，并沉淀"未来加新页"用的决策清单。

## 期望

- 新建 `src/components/layout/AppPageShell.tsx`，以 compound component 形式暴露：
  - `<AppPageShell.Header eyebrow title description />`（沿用现有 `.page-intro` class，CSS 不动）
  - `<AppPageShell.Sidebar>` / `<AppPageShell.SidebarGroup title>` / `<AppPageShell.SidebarItem icon label>`（侧边索引；可空、可分组；激活态统一为"主色软底 + 主色文字 + 弱描边"）
  - `<AppPageShell.Body mode="default" | "fill" width="default" | "wide">`（内容模式与宽度档）
- 4 个页面（音频 / 素材 / 快捷键 / 设置）改写为调用上述模板：
  - **设置页**侧边索引从"正文内 168px"搬到"正文外 200px"（detail 区变宽是统一化产物，允许）；
  - **素材页**"页内顶部 2 个类别 tab"改为"侧边索引 2 项"（顶部 tab 本轮废止）；
  - **音频页**沿用"侧边索引"现状；
  - **快捷键页**不写 Sidebar，沿用 `mode="fill"` 整页不动、表格自身滚。
- 模板默认硬约束 4 处：Header 下间距 / Sidebar-Body 横向 gap / Sidebar 内 padding / Body 居中与 max-width；其它由 design tokens + 页面作者自管。
- 侧边宽度定 1 档 **200px**（以音频为准，4 页统一）。
- 切子类别保持 `useState`，**不写 URL/hash**（与"切页不写 URL"心智对称）。
- 视觉零变化（除设置页 detail 变宽这一处统一化产物）。
- 沉淀决策清单到 ADR-0007。
- CONTEXT.md 新增"应用页面壳"通用语言段。

## Answer（结论）

**已实现**（2026-08-28）：

- 新建 `src/components/layout/AppPageShell.tsx`（compound component / namespace 形态，5 个 slot：`Header` / `Sidebar` / `SidebarGroup` / `SidebarItem` / `Body`）；配套 CSS `AppPageShell.css`（BEM 化：`app-page-shell__sidebar` 等；Header 沿用 `.page-intro` class，CSS 不动）。
- 4 个非工作台页一次性迁移到 `AppPageShell`：
  - **音频页** (`AudioPage.tsx`)：平铺 3 项 `SidebarItem`（音频素材 / 键音素材包 / 节奏图示 SE 音量），`mode="default" width="default"`；3 section 继续在 Body 内自管（`surface-section.audio-detail`）。`AudioPage.css` 同步删 `.audio-page` flex 与 `.page-content` 旧覆盖，仅保留 `.audio-detail` 内边距与 `.audio-duration-row` / 3 列网格。
  - **素材页** (`AssetsPage.tsx`)：原 `.assets-tabs`（页顶 2 tab）废止，改为 `Sidebar` 下 2 个 `SidebarItem`（音符皮肤 / 背景皮肤，含 `Music2` / `ImagePlus` 图标）；`mode="default" width="wide"`。
  - **设置页** (`SettingsPage.tsx`)：原 `.settings-index`（正文内 168px）搬出正文外到 `Sidebar`（200px）；按"应用设置 / 功能设置"分两组 `SidebarGroup`（外观 / 布局 / 配置数据 / 画布显示）；`mode="default" width="default"`，detail 区 `.settings-detail` 全宽涨到 920px（Q3.2 统一化产物）。
  - **快捷键页** (`ShortcutsPage.tsx`)：不写 `Sidebar`；`mode="fill" width="default"`（整页不动 + 表格自身滚）。`APP_SHORTCUTS` 只读区保留。
- 模板硬约束 4 处全部命中：Header 下间距 24px（继承 `.page-intro`）/ Sidebar-Body 横向 gap 24px / Sidebar 内 padding `12px 10px` / Body 居中 + `width: min(<width 档>, calc(100% - 64px))`（max-width 由模板内联 style 注入）。
- 侧边宽度统一 200px（4 页一致），激活态统一为"主色软底 + 主色文字 + 弱描边"（与 `.app-nav-item.is-active` 同风）。
- 子类别切换保持 `useState`，不写 URL/hash（与"切页不写 URL"心智对称）。
- 4 项允许的视觉差异（issue §8 视觉差异允许清单）已全部产出：
  1. 设置页 detail 区 752 → 920px（Q3.2）；
  2. 4 页侧边激活态统一（Q23）；
  3. 素材页"页顶 2 tab → 侧边 2 项"（Q3.1）；
  4. 侧边宽度 168/200 → 200（Q22）；
  5. 4 页侧边索引视觉密度统一（Q23）。
- 决策清单与术语沉淀已在 `docs/adr/0007-应用页面壳与内容页壳规范.md` + `CONTEXT.md` 录入（issue 闭环前置条件，本次实施前文档已就位）。
- 兼容性：`AppShell.css` 内 `.page-content.is-fill .*` 旧选择器全部扩展一份匹配 `.app-page-shell__body.is-fill .*`（双轨并存），未删除任何旧选择器以保证 4 页内部 surface-section CSS（`.shortcut-surface`、`.shortcut-table` 等）继续生效。

**第二轮回炉（2026-08-28 17:00，按 H 原型几何整改）**：

- 用户反馈"当前布局完全没有按照预期来"。**根因**：原实现 Header 走 `width: min(width 档, ...)` + flex 自然流，未与 body 强制同宽同左缘；且 ADR 硬约束的"body 居中"被解释为 main 容器内的水平 auto margin（实际是左对齐到 sidebar 右侧），未实现"整块居中于 main 视口"。
- 整改（`AppPageShell.tsx` + `AppPageShell.css`）：
  - `AppPageShellRoot` 计算 `blockWidth = sidebar(200) + gap(24) + body(<width 档>)`（如 audio/settings 1144 / assets 1264 / shortcuts 920）
  - main 容器 `width: ${blockWidth}px; margin: 0 auto` 居中于 `.app-page-shell` 父级（main 视口）
  - Header 走 `position: absolute; top: 42px; left: calc((100% - blockWidth) / 2 + sidebar + gap); width: bodyMaxWidth`（与 body 同宽同左缘，不横跨整块）
  - main `padding-top: 122px`（Header 高 98 + margin-bottom 24）让出 Header 高度避免重叠
  - inline CSS variables `--aps-block-width` / `--aps-body-width` / `--aps-header-left` 注入到 `.app-page-shell` 容器，Header 引用
  - BodyContext.Provider 仅留作未来扩展用（不强制消费）
- 4 个页面 JSX **完全不动**，只走 AppPageShell 新 API 即可。
- `AppShell.tsx` 保持 `navCollapsed = true`（默认折叠态，nav=52），H 几何前提 main 视口 ≥ blockWidth=1144 → 1228 满足。
- 4 个生产页面的几何预期（视口 1280, nav=52 collapsed）：
  - 音频 / 设置：`blockWidth=1144, main 视口=1228, 居中偏移=42, Header left=266, body left=266`
  - 素材（wide 1040）：`blockWidth=1264, main 视口=1228, 略超（max-width:100% 优雅收缩）`
  - 快捷键（无 sidebar, fill）：`blockWidth=920, main 视口=1228, 居中偏移=154, Header left=154, body left=154`

**未做**（按 issue §9 边界登记）：

- 基线截图 + 像素 diff：用户拍板不做（人工目检替代）。
- 顶部 tab 原语：素材页迁移后已无调用方，本轮废止；旧 `.assets-tabs` / `.assets-tab` CSS 保留以备历史回退。
- 旧 `.page-content` / `.is-fill` CSS：保留作为兼容层（无调用方，但删除不在本 issue 范围）。
- 浏览器自动化验证：环境缺少 chromium 系统库（`libglib-2.0.so.0`），Playwright 启动失败；tsc / vitest / build 全部绿，由用户人工目检确认最终视觉。

**第三轮整改（2026-08-28 18:30，修复 H 几何未生效的时序/宽度 bug）**：

用户目检反馈"布局完全没有对标 H 版原型"。DevTools 探针实测（视口 1920，nav=52）证实第二轮实现未生效：

- **根因 1（时序 bug）**：`AppPageShellRoot` 中 `blockWidth` / `headerLeft` 在第二个 `Children.forEach`（给 `sidebar` 赋值）**之前**计算，计算时 `sidebar` 恒为初始 `null` → `blockWidth` 恒 = body 单宽（920/1040），Header 左缘偏移恒为 0（贴 sidebar 左缘横跨整块，退化成 D 版式）。实测 `main inline: "width: 920px"`（音频页）、`"width: 1040px"`（素材页）均可复现。
- **根因 2（Body 宽度失控）**：Body 只注入 `max-width` 无 `width`，且 CSS 为 `flex: 0 0 auto` → body 塌缩成内容 max-content 宽（音频页实测 343px、素材页 952px 且溢出 main）。**"每页布局都不一样"的直接原因**。
- **根因 3（结构性隐患）**：Header `position: absolute + top: 42px` + main 硬编码 `padding-top: 122px`（`HEADER_HEIGHT=98` 估算值），description 两行的页 Header 实际高度 >98，随时可能重叠；窄视口下 `calc` 偏移算歪。

整改（`AppPageShell.tsx` + `AppPageShell.css`，4 页 JSX / compound API 仍不动）：

- 单次遍历 children，`sidebar` 先赋值再做几何计算（修根因 1）；
- Header 改回**正常文档流**：新增 `app-page-shell__head` 包装层，与 main 同宽（`--aps-block-width`）、同 `margin: 0 auto` 居中；`.page-intro` 在包装层内 `margin-left: var(--aps-header-indent)`（= sidebar 200 + gap 24；无 sidebar 页 = 0）→ Header 与 Body 严格同宽同左缘。删除 `position: absolute`、`HEADER_HEIGHT`、`padding-top: 122px`（修根因 3）；
- Body 改 `flex: 1 1 auto; min-width: 0` + `max-width` 档值：main 满宽时 body = 档值（920/1040），视口收缩时随 main 同步收缩（修根因 2）；
- `.app-page-shell` 改 flex column + `padding: 42px 24px 0`，`__head` / `__main` 均 `max-width: 100%` 优雅降级；展开 app-nav（156px）实测不撑破。

验证（全部通过）：

- `npx tsc -b` / `npx vitest run`（300 全绿）/ `npm run build` 通过；
- DevTools 探针 4 页实测（视口 1920，nav=52 与 156 两态）：`intro.dx=0, intro.dw=0, gap=24` 全部满足；
  - 音频 / 设置：`main=1144, body=920, intro 与 body 同左缘`；
  - 素材：`main=1264, body=1040`；
  - 快捷键（无 sidebar）：`main=920, body=920, intro 左缘=main 左缘`。
