# 250 · 冷启动与高倍缩放谱面播放掉帧

Type: chore
Status: resolved

## 来源与症状

用户 2026-11-24 在验证 [249](./249-谱面滚动条往返拖动卡顿.md) 后反馈：滚动条/PlayBar 拖动已明显改善，但在 **《Retribution ~ Cycle of Redemption ~》**（1449 个音符、~4.15 MB 音频、200% 左右缩放、最大化窗口、`hd` 画质）**冷启动或切换工程后正常播放**时，仍能肉眼感受到部分位置掉帧。

## 根因调查与基线对照（2026-11-24 已核实）

在 Electron 正式构建（Windows 11，DPR 1.25）下对紧邻基线 `488bd3b6` 与当前提交 `7849efa4` 做了 5 组冷启动 / 切工程 / 全曲 160 秒对照实测与 Chrome Trace + V8 CPU Profile 采集：

1. **并非 249 引入的回归**：两版全曲 0–160s 均维持 `60.1 fps / P95 18.2 ms`；3 轮无 Trace 冷启动 0–15s `gt20` 均值分别为 `5.7` 次（`current`）与 `6.0` 次（`baseline`）；100% 缩放冷启动 0–10s 分别为 `0` 次与 `1` 次 >20ms 尖峰。
2. **起播 `~0.45–0.65s` 必现 58–70 ms 大停顿（`STATE_DROPPED` 3–5 帧）**：两版在 Chrome Trace 中均出现 `CrGpuMain` `RasterDecoderImpl::DoEndRasterCHROMIUM::Flush` 耗时 **`60.8–62.6 ms`**（高倍缩放冷启动首次集中上传/刷出画布与瓦片纹理到 GPU），紧随其后主线程 `TimerFire`（瓦片后台预建回调与微任务队列）耗时 **`19.6–29.5 ms`**。
3. **固定歌曲时刻与后台建块周期性小掉帧（21–42 ms 尖峰，偶发叠加 GPU/GC 大抖动）**：从其他工程切换至《Retribution》后立即 200% 起播时，两版在**完全一致的时间点**（`~155 ms`、`~270–333 ms`、`~2.59 s`、`~3.75 s`、`~8.37 s`）同步触发尖峰。200% 缩放下单张瓦片像素体积增大、跨瓦片边界触发 `prepareTile` / `commitTile` 上传及 V8 GC（前 10 秒累计约 `100 ms`），偶发叠加 GPU `SwapBuffers` 等停顿时可放大为肉眼可见掉帧。

## 本轮根治定位与实现口径（2026-11-24 已实现并实测）

进一步对 200% 冷启动阶段做分项毫秒级打点（`prepareTile` / `collect` / `draw` / `bandPutMs`）后锁定两大真实热点，并已逐项消除：

1. **后台瓦片带体贴回未分片阻塞（`13.5–20.8 ms` 单微任务尖峰）**：[234](./234-播放瓦片带体光栅计算分片.md) 仅将 `rasterBandRunsSteps`（扫描线计算）切成 2 ms 分片，但计算完成后 `prepared.draw()` 在单个 `.then()` 内同步连续执行全瓦片 10–16 次 `octx.clearRect` + `createImageData` + `putImageData` + `drawImage`（Tile 1 单块 `bandPutMs` 实测达 `18.6 ms` / `drawMs 20.8 ms`），直接穿透 16.67 ms 帧预算。
   - **修复**：在 [render.ts](file:///d:/Company/WorkSpace/MocaCoffee/bangdream-editor/src/rendering/render.ts) 提取 `renderPreNoteLayers`、`isDrawableSlide`、`renderNotesBody` 与分步生成器 `renderNotesSteps`（每画完一条 Slide/Long 连接带 `yield` 一次），并让 [noteLayerCache.ts](file:///d:/Company/WorkSpace/MocaCoffee/bangdream-editor/src/rendering/pipeline/noteLayerCache.ts) 的 `drainOnePlayingTile` 在 `drawSteps` 超过 `budgetMs = Math.min(2, frameInterval * 0.25)` 时 `setTimeout(0)` 让出主线程且支持取消中止；同时精简 `renderBandStrip` 省去冗余 `clearRect` 与 `createImageData` 双份拷贝（在 `ArrayBuffer` 完整视图下直构造 `ImageData`）。
   - **否定方案留档**：实测 `createImageBitmap` + 离屏 `<canvas>` 对象池会令第 7 块首次淘汰复用时触发 GPU 同步长顿挫（44–55 ms 与 140.1 ms），`willReadFrequently: true` 会拖慢 CPU→GPU 贴图上传（35–48 ms），均已弃用。
2. **连续胶囊/快捷键缩放未走 `zoomGesture` 节流（触发 `~0.45s` `57–67 ms` GPU Flush）**：此前仅 `Ctrl+滚轮` 调用 `zoomGesture` 节流，快速连点缩放胶囊 `100%→200%` 会在 10 步中间倍率上同步连建 10 块高倍 `Tile 0` GPU 瓦片并堆积在 `CrGpuMain` 命令队列中，开播半秒触发 `DoEndRasterCHROMIUM::Flush`。
   - **修复**：在 [FinalVirtualCanvas.tsx](file:///d:/Company/WorkSpace/MocaCoffee/bangdream-editor/src/chart/components/canvas/FinalVirtualCanvas.tsx) 提取共用 `armZoomGesture`；单次点击仍立即高清渲染，300 ms 内的连续外部 `scale` 变化与 `Ctrl+滚轮` 共用 240 ms `zoomGesture` 比例缩放 blit 预算并在末次输入 250 ms 后统一高清 settle（同步更新 `prevScalePropRef` 避免滚轮与 effect 重复触发，且每次连续点击均正确续期 settle）。
