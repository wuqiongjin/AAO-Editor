# 154 · 官方与社区谱面兼容性压力测试

Type: research
Status: open
Blocked by: —

## 来源

在实现 [153](./153-宽松谱面代码兼容与画布投影.md) 前，先用真实谱面验证“非法配置”是否确实出现在官方谱面或社区谱面中，避免把 Bestdori 的边界行为未经筛选地扩大为编辑器兼容范围。

仓库当前已有 11 份 JSON 样本：`docs/resource/SampleChartCode/Official/` 下 8 份官方谱面、`Community/` 下 3 份社区谱面；另有 `MocaCoffee/特殊滑条.md` 作为特殊 Slide 结构样本。仓库也已有官方/社区 Bestdori 拉取脚本和 vendored Sonolus/Bestdori 解析源码。

## 研究问题

1. 真实官方/社区谱面实际使用了哪些字段、`type`、数值范围和 Slide 结构？
2. 当前导入/应用链路会拒绝哪些真实配置，错误原因是什么？
3. 当前转换、工程重载、代码弹窗和另存为会丢失哪些字段或结构？
4. 哪些“非法配置”在真实样本中出现，哪些只能作为合成边界测试？
5. 153 的兼容范围、优先级和测试 fixture 是否需要据此调整？

## 测试范围

- 静态盘点全部已提交的官方/社区样本：对象数量、type 分布、字段集合、BPM/beat/lane/width/direction 范围。
- 重点检查：
  - 小数或越界 lane；
  - `beat < 0`、超 END beat；
  - `Directional.width` 小数、`>3`、`<1`、负值及非 Left/Right direction；
  - Slide/Long 的 connection 数量、同拍组、非单调点序、hidden/flick/skill、connection lane；
  - 未知字段、未知 type、字段类型异常。
- 用当前软件的真实代码应用入口逐份尝试导入；同时用纯逻辑链路记录 `validateChartCodeJSON`、`convertChartCodeToNotes` 的结果。
- 对能应用的样本继续验证：画布渲染、工程保存重载、再次打开代码、另存为文本及源字段差异。
- 在线新增样本必须固定来源、ID、服务器和抓取时间；线上数据不直接作为不稳定的 CI fixture。

## 产物

- 研究报告：`docs/research/chart-compatibility-pressure-test.md`。
- 固定样本 manifest：记录来源、版本/ID、抓取时间、文件 hash。
- 按“真实出现 / 当前已支持 / 当前拒绝或丢失 / 仅合成边界”分类的配置清单。
- 给 issue 153 和 ADR-0014 的范围调整建议；若真实样本推翻已有假设，先更新 153/ADR，再开始实现。

## 验收

- 11 份现有样本全部有可复核的盘点结果和导入结论。
- 每个拒绝或字段丢失都有具体文件、对象/字段路径和当前代码入口依据。
- 报告明确区分真实样本证据与合成压力用例，不把“未在样本中出现”误判为“不需要支持”。
- 153 在本票完成前保持 blocked；本票 resolved 后再根据报告决定是否拆分实现票。
