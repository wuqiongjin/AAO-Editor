# 165 · 首次播放卡顿

Type: bug
Status: resolved

## 来源

用户 2026-10-07 反馈：在首次切换谱面后，到新的谱面播放时，会先正常播放大概几百毫秒，然后会卡住一下，然后再过一会就正常继续播放了。（之前在 basic-editor 中可能遇到过类似问题，一直不确定是否已修复，仅首次遇到，难以复现）。

## 症状

1. 首次打开或切换到某谱面后首次播放时；
2. 播放开始后的前几百毫秒正常顺畅推进；
3. 大约推进至数百毫秒时，画面与时钟突然卡顿一下（掉帧或短暂暂停数十到数百毫秒）；
4. 卡顿结束后自动恢复顺畅播放；
5. 在同一谱面上后续再次播放不再复现。

## 根因

排查出三项叠加的冷启动机制：
1. **音频异步解码（`decodeAudioData`）完成对播放时钟的强行打断（主因）**：
   - 切换/加载谱面时，`AudioSession.hydrateFromProject` 发起非阻塞异步音频解码 `AudioEngine.load(file)`（耗时 300~800ms）；
   - 用户在解码完成前开播，`AudioEngine.play()` 发现 `this.buffer === null`，走合成时间线（`clock = 'synthetic'`，`performance.now()` 驱动）；
   - 几百毫秒后后台解码完成，`engine.load` 无条件执行 `this.buffer = decoded; this.offsetSeconds = 0; this.cancelScheduled(); this.state = 'ready';`；
   - 正在运行的播放时钟因 `state` 被篡改为 `'ready'` 导致 `getSeconds()` 瞬间归零冻结，造成画面与时钟卡顿；随后会话重对齐才恢复；第二次播放时由于音频已在内存，不再复现。
2. **瓦片缓存（NoteLayerCache）播放期首个未建瓦片光栅化长任务（次因）**：
   - 切换谱面清空瓦片，静止状态仅预建了 beat 0 视口；
   - 开播滚动几百毫秒后首次触碰未建瓦片，在宏任务中同步执行 `renderTile`（若含复杂长条/SP曲线扫描线光栅化），占用主线程导致短时卡顿。构建后存入缓存，后续播放不再卡。
3. **初次加载误触发 800ms 防抖落盘（次因）**：
   - 初始数据恢复误触发了持久化合并器的 800ms 保存定时器，恰好在开播几百毫秒时进行工程序列化与 IndexedDB 写入。

## 修法

1. **`AudioEngine.load` 解码完成时的状态保护与平滑接入**：
   - 增加 `loadGen` 竞态世代计数，丢弃过期解码结果；
   - 若解码完成时当前已处于 `playing` 态，绝不篡改 `state = 'ready'` 和 `offsetSeconds = 0`，而是平滑创建 `AudioBufferSourceNode` 从当前秒数起播并将 `clock` 重锚至 `audio`，保证时钟持续推进不冻结；
   - 若解码完成时当前处于 `paused` 态，保留当前 `offsetSeconds` 暂停位；
2. **恢复工程时不触发防抖落盘**：
   - 在 `useChartProjectPersistence` 中利用 `justRestoredRef` 标记恢复结算，跳过初次加载时由于状态灌入触发的 800ms 防抖保存；
3. **瓦片静止预热与播放期扩展**：
   - 在 `noteLayerCache` 中静止态即预热视口上方瓦片（`hi + 1`），播放期扩展预热至 `hi + 2`，避免开播滚动首瞬间光栅化卡顿。

## 锁测

1. `tests/unit/audio/AudioEnginePlayingLoadRace.test.ts`：验证在合成时钟播放中途音频解码完成时，不会篡改 `playing` 状态、`getSeconds()` 平滑递增不归零，且验证暂停位保留与多任务竞态保护；
2. `tests/unit/rendering/cache/` 全套缓存与瓦片刷新测试通过。
