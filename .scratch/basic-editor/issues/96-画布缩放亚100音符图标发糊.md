# 96 · 画布缩放 <100% 时音符图标逐级发糊

Type: bug
Status: resolved（2026-09-12 实现 + 锁测，待你在页面验收）
Blocked by:

## 来源

用户 2026-09-12 第五批复报：谱面画布音符图标在不同缩放比例下清晰度不一——50% 一种糊形态、80% 略清晰、100% 完全清晰，>100% 恒定最清晰档。用户已确认指**画布缩放**（工具栏百分比，非浏览器缩放）。

## 症状 / 根因（2026-09-12 页面实测复现）

48% 下结点图标糊成小绿点、78% 明显发软、128% 清晰，与用户描述吻合。根因：音符精灵经 `CanvasSpriteIcon.drawSingle` 用单步 `drawImage` 从高分辨率源图集直接缩到目标 CSS 尺寸（`CanvasSpriteIcon.tsx:137`），画布缩放 <1 时为大幅降采样，无 mipmap/多步插值 → 发糊；≥100% 时源图远大于绘制尺寸、降采样比温和 → 恒定清晰（正对应用户「100% 以后保持不变」）。瓦片 dpr 上限 1.5（`noteLayerCache.ts:38` `TILE_DPR_CAP`，issue 36 内存权衡）与本症状正交，非主因。

## 修法

精灵降采样品质整改：候选 = 绘制前逐步减半的中间位图（mip 链）/ 按缩放档预渲染精灵位图 / `imageSmoothingQuality: 'high'` + 分级缓存，按瓦片重建成本实测择一；不得回退 issue 36 的 `TILE_DPR_CAP` 内存权衡（如需动它须另与用户确认）。

## 锁测

- Canvas 像素质量单测覆盖不到 → **Playwright 像素实测**：多档缩放（48/78/100/128%）音符特写截图对比（验证阶段脚本手法已跑通，`scripts/` 下临时脚本可整理为正式验收脚本）+ 手工验收清单。
- 若实现抽出「缩放 → 采样策略」纯函数（如 mip 档位选择）则配套单测锁行为。

## Comments

- 2026-09-12 实现 + 锁测（tsc 0 / 全套 944 测全绿 / Playwright 像素对比改善确认）：
  - 新增纯函数模块 `src/ui/canvasSpriteMips.ts`：`mipLevelFor`（降采样比 ≤2 用原图；否则取级 L 使
    ratio/2^L ∈ (1, 2]，钳到级位图最小维 ≥1）、`mipDims`（逐级减半、最小钳 1）。
  - `CanvasSpriteIcon`：`mipChains`（WeakMap 弱键，随源图释放）按需增量构建源图集减半位图链；
    `drawSingle` 按 ctx 变换把目标尺寸折算到设备像素（瓦片 tileDpr / 主画布 dpr 同口径）选级，
    从级位图取按比例折算的源矩形（钳边界）+ `imageSmoothingQuality: 'high'` 绘制；
    构建失败（vitest node 环境等）→ 原图直绘兜底，目标矩形不变（既有用例零改动通过）。
  - 锁测：CanvasSpriteIcon.test.ts 新增 issue 96 组 7 例（级选取不变量 4 / node 兜底直绘 1 /
    mipDims 1 / 降级不炸 1）。
  - Playwright 验收（`scripts/verify-issue96-97.mjs`，playwright 首次入 devDependencies）：
    78% 档修复前后 4× 特写对比 —— 音符椭圆边缘灰晕消失、白芯对比恢复；48% 档从无白芯绿点
    变为可辨白芯椭圆（图标仅 ~17 设备像素，白芯像素 0 → 6，为该尺寸下的物理上限）。
  - `TILE_DPR_CAP` 未动（issue 36 权衡保持）。
- 2026-09-12 评审收口补充：锁测档位口径 —— 默认缩放 88%、步进 ±0.1，取不到整百，
  验收脚本实际取 **98%** 为票面"100% 档"的最近可表示档（脚本已注明）。
- 2026-09-12 二轮复报（用户：修改无效果 + 新线索"从糊→清晰切换时音符图标像被替换了一样"）→ 真因改判并同日修复：
  - 一轮的 mip 修的是**精灵降采样质量**（对静止态有效但非主因）；"两档形态 + 替换感"的主因在
    **瓦片缓存的手势策略**：Ctrl+滚轮缩放的 240ms 手势窗口内，stale 瓦片只把**旧位图按比例拉伸** blit（糊），
    停止 250ms settle 后才以最终缩放一次性高清重建 → 就是用户看到的"被替换"突切换。
  - 修复：手势帧带 `GESTURE_REBUILD_BUDGET_MS`(4ms) 时间预算**渐进重建** stale 瓦片（预算内现建、
    超预算才退回比例 blit）；轻谱（可见 2-4 块）1-2 帧内全部转新、无跳变；重谱逐帧锐化、单帧成本有界；
    settle 重渲退化为兜底。`STALE_TOL`(2%) 与 `TILE_DPR_CAP`(1.5) 均未动。
  - 契约改版：`RendererPerf.test.ts` 手势帧断言从"零音符重绘"改为"渐进重建发生 + 帧预算 60fps 内 +
    settle 无集中重建"（5000 音符密集谱 9 帧手势 avg<16ms / max<40ms 保持）。
  - 页面实测：3 连档缩放后手势窗口内与 settle 后的音符特写一致（此前手势内为拉伸旧位图）。
  - 物理极限说明（预期管理）：静止态 <100% 时图标屏幕像素本就少于 100%（如 50% ≈ 一半边长），
    细节量必然更低，本修复保证的是"该尺寸下最好的采样 + 全程无跳变"；若 HiDPI 屏仍觉不锐，
    可另行评估 TILE_DPR_CAP 1.5→2（内存约 +78%，需你拍板）。
