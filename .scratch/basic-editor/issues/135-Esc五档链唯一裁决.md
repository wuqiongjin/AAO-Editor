# 135 · Esc 五档链真正只有一个裁决处

Type: chore
Status: resolved
Blocked by: —

## 来源

2026-09-21 `improve-codebase-architecture` 评审候选 4（Worth exploring）。续作 [109](./109-Esc取消进行中手势.md) / [113](./113-画布手势会话深模块.md)：`resolveEscapeTarget` 自称唯一裁决，但 `GestureSession.cancel` 把 ③–⑤ 钉 `false`，③–⑤ 仍靠 `Editor.onEscape` 的 if 顺序。

## 症状

政策表测了 ②–⑤；运行时只有 ② 走表。改优先级会改表 + 改 Editor。

## 本轮实现口径（用户 2026-09-21 确认 1A+2A）

1. 政策只留 `resolveEscapeTarget`。Editor 组完整快照后问表，再按一档执行。
2. `cancel()` 不再伪造后三档；只取消进行中手势。
3. ③ 仍走 `cancelPendingSlide()`；不搬锚点所有权，不把五档收进 `GestureSession`（维持 113 Q15 的执行拆分）。
4. ① 弹窗 capture 仍不进本函数。行为与 ADR-0008 §7 不变。

## 锁测

- `resolveEscapeTarget`：既有优先级表（`CanvasGesture.test.ts`）继续锁 ②–⑤。
- `GestureSession.cancel`：有手势才消费；源码不再 `anchor: false` / 不再调 `resolveEscapeTarget`。
- 静态：`Editor.onEscape` 调用 `resolveEscapeTarget`；执行 ②/③ 发生在问表之后；`getEscapeFlags` 本体含 `slideBuffer !== null` / `curveDraft !== null`。

## Answer

落地 1A+2A：`Editor.onEscape` 经 `getEscapeFlags` + 选区/工具态问 `resolveEscapeTarget`，只执行一档。`cancel()` 只清进行中手势。③ 仍 `cancelPendingSlide`。ADR-0008 §7 记政策入口。
