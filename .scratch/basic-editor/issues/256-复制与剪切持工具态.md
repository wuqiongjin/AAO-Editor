用户 2026-11-08 / 2026-11-12 诉求："针对复制、剪切。我希望不再局限于，必须先选中了。它们也具备 持工具态，处于复制工具态时，框选时自动复制，剪切也是同理。(再次复制/剪切的会覆盖前面的)"。
经 `/grill-with-docs` 展开两轮设计树，8 项核心决策全面闭环，领域文档 [`CONTEXT.md`](../../../CONTEXT.md) 与 [ADR-0008 工具交互机制](../../../docs/adr/0008-工具交互机制.md) 已就地同步修订。本票记录全部定案与后续实现落点，**暂不动代码**。

## 根因与背景（现状事实）

- **历史取舍**：ADR-0008 §2.1 六轮定案曾裁定"复制/剪切不占工具轴（不 arm）"，理由为"二者必须有选区才有意义（作用于对象而非位置），连续复制无意义、连续剪切有误删风险"，随之摘除了 `switchCopy` / `switchCut`。
- **用户痛点**：既有交互强依赖"先建立选区、再点按钮或按快捷键执行"，连续复制/剪切多个不同段落时操作链路繁琐；引入持工具态后，手持复制/剪切工具即可通过连续框选自动完成复制或剪切（后一次覆盖前一次），极大提升段落搬运与清理效率。
- **架构基础**：
  - 工具轴与持工具态：`UIProvider.tsx` 与 `armedToolState.ts` 维护单轴互斥状态 `ArmedTool`。
  - 框选门控：`CanvasGesture.canStartMarquee` 仅对 `noteCode` 与 `paste` 禁框选，新工具态天然放行左键框选。
  - 快捷键系统：`ShortcutConfig.ts` 中裸键 `C` 与 `X` 目前完全未被占用，与现存 `execCopy`（`Ctrl+C`）、`execCut`（`Ctrl+X`）形成天然对称。
  - 剪贴板底层：`SelectionEditing.copySelection` 与 `cutSelection` 逻辑健全，已完备支持普通音符与滑条子部分提取。

## 定案（用户 2026-11-12 逐轮拍板，两轮 8 问 Frontier 为空）

### 1. 状态模型与快捷键
- **工具轴扩充**：`ArmedTool` 扩充 `'copy' | 'cut'`，所有工具共驻单轴、互斥且默认**驻留**。
- **快捷键体系（Q4=OK）**：
  - 新增切换键（进入持工具态）：`switchCopy: 'c'` 与 `switchCut: 'x'`，对应类别 `copy` 与 `cut`，作用域 `canvas`。
  - 保留执行键（即时执行）：`execCopy: 'ctrl+c'` 与 `execCut: 'ctrl+x'` 保持原样，对当前选区立即执行，不改变持工具态。

### 2. 画布交互（框选、单击与手势）
- **框选完成的选区保留（Q1=A）**：
  - **复制态**：左键框选超过 8px 松开后，框内音符写入剪贴板（覆盖前值），**选区保留为本次框选的音符**（显示选中描边，符合 ADR-0008 原则 4，便于紧接着微调或移位）。
  - **剪切态**：框内音符写入剪贴板（覆盖前值），音符从谱面移除，**选区清空**。
- **单击音符交互（Q2=OK，全面遵循 issue 88 规则）**：
  - 命中 ∈ 当前选区：直接复制 / 剪切整片选区。
  - 命中选区外：清空旧选区，单件复制 / 剪切（复制态同时将其设为单选区，剪切态移除并清空）。
- **点击空白处**：遵循 ADR-0008 原则 6，清空选区，剪贴板保持不变，工具态保持驻留。
- **BPM 隔离（Q5=A）**：BPM 线不参与框选复制与剪切（剪贴板纯净保留音符/滑条，速度语境由片段库承载）。单击已有 BPM 线走 ADR-0008 §2 **镜像档**（受限：无效果、清选区、态驻留），**不走删除档**。
- **手势统一性（Q7=A）**：严守 ADR-0008 §6 全局原则，`Shift + 按住音符拖拽` 保持全局移动逃生口；非 Shift 拖拽一律为框选。
- **退出与 Esc（Q8=OK）**：遵循 ADR-0008 §7 五档链。复制态框选后按第 1 次 Esc 清空选区（第 ④ 档），按第 2 次 Esc 退出复制态落回指针（第 ⑤ 档）。

### 3. 左侧工具轨（WorkspaceToolRail）与视觉
- **对齐动作族（2026-11-25 自检）**：复制/剪切进持工具态后，与删除/镜像同属动作族。原则 3（再点当前高亮按钮 = 落回指针）、原则 6（点空白清选区）、切换键只 `setArmedTool` 不执行、按钮不看有没有选区——**全部套既有规则，不另写 copy/cut 特例**。`switchDelete` 不进 `CHART_EDIT_FUNCTIONS`，`switchCut` 同样只进态；改谱拦在 `execCut` / 画布 `handleNotesChange`。
- **工具轨按钮（Q3=B，2026-11-25 推翻）**：11-12 把「有选区时点按钮 = 先执行再进态」写成 copy/cut 专规，和删除/镜像不一致。改回同构：点按钮只 arm/释放，无选区不置灰。真正拷/剪只走画布框选、画布单击、`Ctrl+C` / `Ctrl+X`。
- **视觉反馈（Q6=A）**：剪切工具态不采用红色危险色（无红底按钮、悬停/选区无红色轮廓），保持中性轮廓与常规工具高亮。
- **既有 BPM 删除框选「整条覆盖」**：本次不改。issue 71 仍有效；若要动删除 / 右键框删，另开票。

## Answer

复制 / 剪切已入动作族持工具态，与删除 / 镜像同构。

- `ArmedTool` / `MatrixTool` 扩充 `'copy' | 'cut'`；`switchCopy: 'c'` / `switchCut: 'x'`；`Ctrl+C` / `Ctrl+X` 仍即时执行、不改态。
- 框选 / 单击走 `boxSelectOps` / `clickOps`：复制写剪贴板并保留选区；剪切写剪贴板、改谱、清选区；BPM 单击走镜像档。
- 工具轨按钮只 arm/释放，无选区不置灰，剪切不套 danger。`switchCut` 不进 `CHART_EDIT_FUNCTIONS`。

锁测：`ShortcutConfig.test.ts`、`ToolActionMatrix.test.ts`、`CanvasGesture.test.ts`、`WorkspaceToolRail.test.tsx`、`CopyCutArmedToolWiring.test.ts`。浏览器：无选区点复制进态、框选复制后粘贴可点、框选剪切后音符消失。
