## Question

导入谱面代码并应用后，滚动条会**自动定位到偏结尾处**，而不是保持在原秒数对应的滚动位置。期望：导入/应用代码后，播放头/滚动位置按**当前秒数**保持不变，不跳尾。

关联：ADR-0005 §7 打开画布定位 beat 0 之外的另一处滚动定位问题（本 bug 是应用代码时的滚动跳跃，与初始打开定位不同）。

## 复现

- 在谱面代码面板导入一段更长的谱面代码并应用；
- 观察滚动条跳到谱面结尾附近，而非维持原有秒数位置。

## 期望

- 应用代码后滚动位置按秒数保持稳定（不因谱面末端变化而跳到结尾）。

## Answer（结论）

- 根因：`chartEndKey` 变化触发按秒重锚时，`onScrollChange → setVirtualHeight → 设置 DOM 高度 → scrollHeight 变化` 尚未在当帧完成，重锚读取的 `maxScroll` 是**过期值**。仅当期谱面/导入代码时长不一致、virtualHeight 变化较大时，`maxScroll` 偏差才明显，表现为跳到偏结尾；播放时 RAF 每帧读最新 `maxScroll`，故播放能回到正确位置。
- 修复（Editor.tsx，三段式「标记待重锚 + 就绪后重锚」）：
  1. `chartEndKey` 变化时（应用谱面代码/改时长/BPM 事件）只把 `pendingAnchorKeyRef` 置位，不立即重锚——因为当帧 `scrollHeight` 仍为旧值。
  2. 重锚移到依赖 `virtualHeight` 的 effect 执行：`virtualHeight` 就绪意味着 `.virtual-content` 高度已写回、`scrollHeight` 为最新，此时才按 `lastScrollSecondsRef`（谱面变更前的秒数）重算 `maxScroll` 并重锚到同一秒数位置。
  3. `handleVirtualScrollChange` 必须用 `useCallback([])` 保持引用稳定：否则每个 Editor 渲染都生成新函数引用 → FinalVirtualCanvas 的 onScrollChange effect 每帧触发 → 在导入代码那次渲染中【早于】Editor 置位 pending 就调用本函数，`pending==null` 会用新几何覆盖旧锚点（SKIP 失效），导致按秒重锚读到漂移值。引用稳定后 onScrollChange 仅在 viewport.scrollY/virtualHeight 真正变化时触发，此时 pending 必已置位，SKIP 才能可靠保护锚点。
  - 播放中仍由 RAF 循环独占滚动，跳过重锚避免抢滚动。
- 验证（浏览器实测，读 PlayBar 时间码）：
  - 将无音频谱面时长设为 15s，滚动到中部（时间码 `00:07 / 00:15`）。
  - 导入更长的谱面代码（末尾 beat 80 @120bpm → 40s）并应用。
  - 结果：时间码保持 `00:07 / 00:40`，即滚动位置**按秒数（7s）稳定**，未跳到结尾（40s）；内部滚动比例由 0.5 变为 ≈0.81，恰为"时长变长后保持同一秒数"的正确比例。
  - 若当前时长与导入代码时长一致，无该路径触发，滚动条自然不动，与用户观察一致。
- 静态检查：`tsc -b` 通过；vitest 139 用例全绿。
