# 67 · 框选按住（未松手）时，矩形内的音符实时高亮

Type: task（**新特性**，非缺陷）
Status: open
Blocked by:

> 自 issue 66（验收缺陷批次）拆出：本条是**新特性**，不该与 BUG 混在同一张票里。
> 66 只留三条真正的缺陷（选中遮罩 / 代码面包屑 / 方向键溢出），本票独立跟踪这条特性。

## 来源

用户 2026-09-09 提出。原话复述（用户重新澄清后的口径）：

> 在左键按住的情况下（**不松手**），此时会出现框选的矩形，矩形区域包含的音符要有**被选中的 hover 状态**。

## 现状（为什么现在没有）

框选手势期间（`mousedown` → 拖动 → 未 `mouseup`）：

- `selectedItems` **还是空的** —— 选区要等 `mouseup` 才由 `applyBoxAction` → `computeItemsInBox` 建立；
- 画面上只有 `renderSelectionBox` 画的那个蓝色虚线矩形在动；
- 框内的音符**完全没有反馈**，用户不知道"松手会选中谁"。

## ⚠️ 首轮实现踩过的坑（务必先看，否则会白写一遍）

2026-09-09 首轮已在 `collectSelectionOutlines` 里加过"框选预览集"（用 `computeItemsInBox`
现算框内音符、未选中的按 hover 档出描边），**结果浏览器上完全没效果**。根因不在预览逻辑，
而在**叠加层压根没被调用** —— `src/visual/noteLayerCache.ts` 的瓦片路径有一道性能门卫：

```typescript
// F1：选中/hover 叠加层（瓦片不含选中态，O(选中∩可见) 逐帧绘制）
if (rc.selectedItems.length > 0 || rc.hoverItem) {     // ← 门卫
  const c = makeCoords(rc.geometry, rc.viewport, rc.beatDisplay, rc.notes);
  renderSelectionOverlay(ctx, c, rc, c.getVisibleNotes());
}
```

框选期间 `selectedItems` 为空、`hoverItem` 常为 null → **门卫不成立 → 叠加层整个跳过** →
预览逻辑一次都没执行。（这是 issue 35 F1 的性能优化：只在"有选中或有 hover"时才画叠加层。）
直渲路径（es > `MAX_CACHE_ES`）无条件调用本该生效，但默认缩放走瓦片路径。

**结论：实现本特性必须同时改这道门卫**，否则在 `collectSelectionOutlines` 里写再多也没用。
该改动已随首轮一并撤回（`git diff` 已回到无预览的状态），本票从零重做。

## 定案（本轮实现口径，待用户确认）

1. **高亮形态 = hover 档**（沿用 issue 56 的 hover 视觉：只画亮面、不画暗底、α 0.85、
   线宽 `hoverLineWidth`），表示"即将入选但尚未入选"；松手后才转为真正的 selected。
   > 用户原话"被选中的 hover 状态"我理解为 **hover 档视觉**（比真实选中轻一档）。
   > 若你要的是"直接按 selected 档（暗底+亮面）显示"，改 `emit` 的模式一处即可。
2. **已选中的音符被框住时不叠第二圈**（避免亮面叠亮面、肉眼无差异），只保留 selected 一圈。
3. **判据与真实框选同源**：直接用 `computeItemsInBox(rc.selectionBox, …)`，
   于是 BPM 的"整线覆盖"判据、hidden 结点跳过等规则自动一致，不另写一套。
4. **门的开启**：瓦片路径门卫加 `|| rc.selectionBox`（有框选手势就画叠加层）。
   需评估密集谱下框选每帧 `computeItemsInBox`（O(音符数)）的开销；若掉帧，
   可把预览集挪到 `FinalVirtualCanvas` 用 `useMemo` 预计算后注入 `RenderCtx`（判据不变）。
5. **段的预览是否给反馈**：鼠标 hover 时段只在删除/音符代码工具下给（段不是可点对象）。
   框选不同——段确实会被选入，倾向**一律给反馈**（所见即所得）。此点待用户确认。

## 实现落点

| 文件 | 改动 |
| --- | --- |
| `src/visual/noteLayerCache.ts` | 瓦片路径门卫加 `|| rc.selectionBox`（**关键，否则无效果**） |
| `src/visual/render.ts` | `collectSelectionOutlines` 增"框选预览集"输入：BPM / Single / Directional / Slide 结点 / Slide 段五处分支按「未选中 → hover」出描边 |
| `tests/unit/SelectionVisual.test.ts` | 新增锁测：框住未选中→hover / 已选中不叠 / 框外无 / BPM 整线→line·hover / 滑条结点+段 / hidden 不预览 |

## 验收

- 左键按住拖出一个框（不松手）：框扫过的音符**即时**亮起 hover 黄边；把框缩小/移开，对应音符**即时**灭掉。
- 松手后：这些音符转为真正的选中态（selected 档），与 `selectedItems` 一致。
- 已选中音符被框住：仍是 selected，不出现第二圈。
- 框住滑条：结点与段都亮；框住 BPM（整线）：整条线亮。
- 密集谱（数千音符）下框选不掉帧。
