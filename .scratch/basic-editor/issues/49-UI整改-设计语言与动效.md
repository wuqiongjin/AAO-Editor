### 阶段 1 经验教训（2026-08-29 用户反馈后回滚）

**问题**：阶段 1 完工后用户截图反馈 2 处视觉事故：
- 图 1（侧边栏 + 键音素材卡选中态）—— 玫红浅底 `#fff0f6` + 白字 `#ffffff`（subagent 改的 `accent-text: #ffffff`），对比度 ≈ 1.1:1，文字几乎不可见
- 图 2（"导入音频"实色按钮）—— 玫红 `#d6336c` 饱和度过高，redesign-skill 也警告过"oversaturated accent"

**根因**：
1. **方向拍板错误**——grill 第 2 轮给出 4 个 accent 选项，subagent 替你选了"玫红调"（应是用户主动选），且设计师视角与终端用户视角偏差大
2. **白字陷阱**——subagent 把 `--accent-text` 从深青蓝 `#075e83` 改为白字，破坏"浅软底 + 主色文字"对比安全模式
3. **没有做目视验收**——沙箱无浏览器时不能只看代码就放行

**回滚（2026-08-29 已执行）**：
- ✅ accent 系列回滚到原青蓝系（亮 `#0d9fd6` / 暗 `#38bdf8`）
- ✅ `accent-text` 恢复深档（亮 `#075e83` / 暗 `#bae6fd`），浅软底+主色文字
- ✅ 阴影色相回滚到原冷蓝黑 `rgba(20, 26, 38, ...)`
- **保留**（用户明确确认无问题）：字体 Geist / 交互态 CSS 化 / 时长 120-200-300 / `prefers-reduced-motion` 兜底 / `--overlay-bg` / `--accent-disabled` / `--warning-text` 新增 token
- tsc 0 错；玫红残留 0 处

**后续流程改进**：
- 任何"设计风格"类决策（颜色 / 字体 / 圆角 / 间距）必须由**用户主动选**，agent 不替选
- 沙箱无浏览器时，每个色系改动必须附"实机目视清单"由用户确认
- 浅底 + 文字组合的 contrast ratio 必须 ≥4.5:1（WCAG AA），列为硬性约束
