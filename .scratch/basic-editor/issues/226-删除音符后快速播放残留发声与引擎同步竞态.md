# 226 · 删除音符后快速播放残留发声与引擎同步竞态

Type: bug
Status: resolved
Blocked by: —

## 来源

用户在工作台排查发现（2026-11-09）：先正常播放一段谱面配置，然后滚动到这段配置开始，删除掉这段配置后继续播放，此时仍然会播放这批已经删除的音符的音效声音，并伴随掉帧感知。

## 症状

1. **删除后快播声音残留**：用户删除一段音符配置后，如果快速按下空格继续播放（<300ms），已被删除的音符仍然会在原时间点发出按键击打音效。
2. **静止等待后正常（时序敏感）**：若删除音符后刻意等待 2~3 秒再按空格播放，则完全不发声（对照测试 1A/1B 确认）。
3. **滚轮回开头时间轴正常**：滚动条滚轮回开头及跳转开头定位准确，`engine.seek(seconds)` 正常联动，无时间轴脱节（对照测试 3A/3B 确认）。
4. **开播瞬态抖动**：开播瞬间偶发轻微瞬态微小掉帧，系 rAF 物理启动与 Web Audio 上下文唤醒的常态微抖（测试 2 确认删前与删后概率一致，与谱面编辑后置任务无关）。

## 根因剖析

问题的技术链路涉及两个核心模块的时序错位与撤销缺失：

1. **编辑态到音频引擎存在 300ms 防抖黑洞（`WorkspacePage.tsx`）**：
   ```ts
   const keysPlayingRef = useRef(isPlaying);
   keysPlayingRef.current = isPlaying;
   useEffect(() => {
     const delay = keysPlayingRef.current ? 0 : 300;
     const t = window.setTimeout(() => engine?.setChart(notes, beatDisplay), delay);
     return () => window.clearTimeout(t);
   }, [notes, beatDisplay, engine]);
   ```
   - 在非播放态下，编辑谱面（如删除音符）走 `delay = 300ms` 的防抖更新；
   - 用户删除音符后快速按下空格播放（<300ms 时差），`isPlaying` 虽翻转为 `true`，但该 `useEffect` 的依赖数组 `[notes, beatDisplay, engine]` 均无变化，因此该 effect 既未重新执行也未清除旧定时器；
   - 播放带着尚未更新的**旧谱面**启动，300ms 定时器仍在后台慢慢排队。

2. **超前 2.0 秒预调度窗口将旧音符锁入声卡（`AudioEngine.ts`）**：
   - 为避免切后台页面定时器被浏览器节流，引擎定义了 `KEY_SCHEDULE_AHEAD = 2.0` 秒超前调度；
   - `play()` 启动并在第一帧执行 `tick()` 时，引擎直接扫描播放头未来 2.0 秒的所有事件；
   - 此时引擎持有的是旧谱面，未来 2 秒内的所有按键音（包括刚被删掉的音符）在开播首帧被一次性全量调度进 Web Audio 硬件时间线（调用了 `source.start(when)`）。

3. **`AudioEngine.setChart` 缺乏取消已调度事件机制（`AudioEngine.ts`）**：
   ```ts
   setChart(notes: ChartNote[], beatDisplay: number): void {
     const bpmEvents = getBpmEvents(notes);
     this.keyEvents = buildKeyEvents(notes, beatDisplay, bpmEvents);
     this.rewindKeyIndex();
   }
   ```
   - 300ms 到期后定时器终于触发并调用 `setChart`，但它仅仅更新了 JS 事件数组，**完全没有调用 `this.cancelScheduled()`**；
   - Web Audio 规范中，一旦 `start(when)` 被调用，声卡线程便独立持有该播放任务，除非显式调用 `node.stop()`，否则声卡必然准时发声；
   - 结果：尽管 JS 层音符已更新，已被提前调度的旧音符仍一个不漏地在声卡中响起。

4. **游标倒回参考基准陈旧（`AudioEngine.ts`）**：
   - `rewindKeyIndex()` 内部直接取 `const playhead = this.offsetSeconds;`，在播放过程中动态调用 `setChart` 时，`offsetSeconds` 仅为开播瞬间的静态时间，未对齐动态流逝的 `this.getSeconds()`，导致游标位置错误重置。

## 本轮修法

严格遵循“不影响既有功能、零性能劣化”原则，实施最小精准靶向闭环：

1. **开播前在途同步强刷（Flush Pending Sync on Play）**：
   - 在 `WorkspacePage.tsx` 中维护在途定时器句柄；
   - 在用户点击播放 / 按空格开播瞬间（`handleTogglePlay` / `startPlayback`），检测若存在在途的 `setChart` 定时器，立刻取消该定时器并**同步执行一次 `engine.setChart(notes, beatDisplay)`**；
   - 若平时无未决编辑（正常播放/暂停），则为零成本 no-op，100% 保护 issue 101 的免重复全谱构建性能收益。

2. **`AudioEngine.setChart` 补全 `cancelScheduled` 与动态游标校准**：
   - 在 `setChart` 重建 `keyEvents` 后立即调用 `this.cancelScheduled()`；
   - 播放态下立即调用所有已调度音频节点的 `osc.stop()` 撤回旧音符，彻底切断声卡发声并由下一次 `tick()` 重建新调度；暂停态下 `scheduled` 为空，开销为 0；
   - 将 `rewindKeyIndex` 中的 `playhead` 从 `this.offsetSeconds` 改为 `this.getSeconds()`，无论播放态还是暂停态均精准对齐真实播放头。
