## Question

现有 `FinalVirtualCanvas` 采用多套坐标系混用、且渲染框架（绘制方式 / rAF 循环 / 网格逐拍绘制 / sprite 渲染）性能差，后续需要重构"整体渲染和显示的框架"。本次先把**坐标模型**定案并已在坐标/命中层落地（这部分是领域逻辑，任何重写都必须保留复用），渲染框架重构推迟到专门的 issue。

## 决策（已定案，坐标/命中层已实现）

统一坐标模型，保证任意缩放下音符与轨道严格对齐：

- **虚拟 X 原点 = 轨道内容左缘 `trackBgX`**（`trackStartX + borderTotalWidth`），轨道整体水平居中。
- 音符 X（lane 中心）= `lane * LANE_WIDTH + LANE_WIDTH / 2`（**不含** `borderTotalWidth`）。
- 画布 X = `trackBgX + (virtualX - scrollX) * scale`；反向 `canvasToVirtual` 同样减去 `trackBgX`。
- 网格轨道线仍按 `trackBgX + lane * LANE_WIDTH * scale` 绘制，故音符中心与网格在任意 `scale` 下对齐。

> 旧实现把 `borderTotalWidth` 在音符里当作"虚拟单位"随 scale 缩放、网格里却当作"画布像素"不缩放，导致 scale=1 恰好对齐、scale≠1 时偏移 `12×(scale-1)` 像素——即下述症状 3/4 的根因。

## 症状（本次协调层已处理，渲染框架层仍待重构）

- 放置音符时，音符位置偏离轨道之外。
- 缩放时，音符位置与轨道位置完全偏离。
- 首次放置的音符不可见，滚动一下才出现（多为坐标/渲染触发时序问题）。

## 渲染框架重构（推迟，另立 issue/并入 issue 10 性能优化）

- 移除 `FinalVirtualCanvas` 内 25 处 `console.log`（**本次已清除**，纯调试噪音 + 性能开销）。
- 渲染性能：rAF 全量重绘、`renderGrid` 每帧遍历 360 拍×每拍子拍数、`getVisibleNotes` 遍历全部音符、`beatToVirtualY` 每次重算 BPM 事件——建议缓存/增量/离屏（见 `10-密集音符性能优化`）。
- 重构时**必须复用本坐标模型**，避免再次引入坐标自相矛盾。

## Answer（结论）

**已完成闭环（2026-08-16）**：本 issue 两部分均已解决。
