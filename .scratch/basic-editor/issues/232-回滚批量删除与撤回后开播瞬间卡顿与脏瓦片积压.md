# 232 · 回滚批量删除与撤回后开播瞬间卡顿与脏瓦片积压

Type: bug
Status: resolved
Blocked by: —

## 来源

用户在工作台编辑时发现（2026-11-11）：
谱面画布在播放一段后，立刻回滚到播放那段的开头处进行批量删除。此时再次按下空格播放，会出现明显的卡顿一下。此时如果再切回播放开头处并使用 Ctrl+Z 回退到删除前，继续播放还会再出现一次明显的卡顿。

## 症状

1. **特定操作序列下的开播卡顿（50ms 级阻塞）**：
   - 只有经历「播放一段（例如 0s~4s）→ 回滚开头（0s）→ 批量删除 / Ctrl+Z → 再次播放」时才会稳定触发；
   - 每次编辑（删除或撤回）后首次按下播放，主线程均出现约 50ms~54ms 的 LongTask 阻塞，动画帧间隔骤增至 45ms~65ms（明显掉帧/画面迟滞约 3~4 帧）；
   - 平时正常的播放、暂停、纯跳转（未在播放过区间执行大批量增删）开播流畅（16~17ms 满帧），无该停顿。
2. **伴随音符瓦片旧位图闪烁与突变替换（Stale Tile Blit）**：
   - 删除后播放时，视口向上滚动进入此前渲染过的脏瓦片区域时，已被删除的音符会在画面上短暂闪现（Blit 旧位图），随后在后台光栅化完成后突变消失；
   - Ctrl+Z 恢复后播放时，由于脏瓦片旧位图为空白，刚恢复的音符会在滚动中短暂缺失，随后突变浮现（Pop-in）。

## 复现证据与实验数据

通过自动化 Playwright 脚本（模拟真实用户行为与 CDP Performance 追踪）观测到确定性数据：

1. **CDP Timeline Trace 证据**：
   - 抓取到播放启动瞬间主线程 `RunTask` 耗时达 **54.03ms**；
   - 浏览器 `PerformanceObserver('longtask')` 捕获到持续 **52.00ms** 的连续阻塞任务；
   - 首个 rAF 动画帧间隔：删除后首播拉长至 **45.2ms**，撤回后首播拉长至 **65.0ms**。
2. **渲染与瓦片管线状态**：
   - 在 0s 暂停并完成删除时，`noteLayerCache` 的 `tiles: Map<number, Tile>` 中积压了此前播放产生的远端脏瓦片（Tile 2~6 等，`dirty === true`）；
   - 暂停帧同步重建仅覆盖当前视口（Tile 0 和 Tile 1），远端脏瓦片全部滞留于缓存中；
   - 开播后（`rc.playing = true`），上方脏瓦片进入前瞻窗口触发 `enqueuePlayingTiles`，通过 `setTimeout(..., 16ms)` 调度 `drainOnePlayingTile` 执行同步 `renderTile`（Canvas 2D 离屏光栅化），与主线程播放 rAF 循环竞争 CPU。

## 根因剖析

问题的发生是由**瓦片缓存机制的脏块滞留**与**开播瞬态的多重同步开销爆发**复合叠加引起的：

1. **`noteLayerCache` 脏瓦片滞留与播放期后台光栅化抢占（核心主因）**：
   - **播放期间累积缓存**：首次播放 0s~4s 期间，视口向上推进，Tile 0~6 被依次光栅化并缓存在 `tiles` 表中；
   - **回滚与编辑打脏**：回到 0s 后执行批量删除（或 Ctrl+Z），`diffNotes` 计算出变更区间，调用 `invalidateTilesForBeatRange` 或 `markAllTilesDirty`，将 Tile 0~6 全部标记为 `dirty = true`；
   - **局部更新导致脏块滞留**：由于此时停留在 0s，`draw()` 仅为当前可见视口（Tile 0~1）同步执行 `renderTile` 重建。离开视口的 Tile 2~6 仍残留在 `tiles` 中，且 `dirty` 依然为 `true`；
   - **开播后定时器密集抢占**：按空格开播后，`rc.playing = true` 使得渲染帧本身不再同步光栅化，而是把脏块塞进 `playTileQueue`，靠 `schedulePlayTileDrain()` 的 `setTimeout` 异步逐块调用 `renderTile()`。这一连串的离屏光栅化任务在播放伊始的数十毫秒内密集占用主线程，导致 rAF 渲染帧排队延迟；
   - **旧位图过渡（Stale Blit）带来视觉撕裂**：在异步重建完成前，`draw()` 会继续 blit 带有旧音符的脏位图，导致被删音符闪现后突然消失（或撤回音符延迟蹦出），放大了用户的“卡顿”体感。

2. **开播瞬时的同步事件与 React 状态级联**：
   - **`setIsPlaying(true)` 引起的主画布同步重绘**：`engine.play().then(...)` 翻转 `isPlaying` 状态，触发 `FinalVirtualCanvas` 重渲染；其 `useLayoutEffect`（依赖项含重建的 `renderCanvas`）在浏览器 Paint 前强制同步调用一次 `renderCanvas()`，与首帧 rAF 产生双重开销；
   - **80ms HUD 更新的第二次整页重渲染**：开播仅 80ms 时，`PLAYBACK_HUD_PERIOD_MS` 到期触发 `setCurrentSeconds`，订阅了 `usePlayback()` 的 `WorkspacePage` 再次整页重渲染（导致包括工具轨、顶栏、抽屉、画布全树重算），恰好与前瞻预取在同一狭窄时间窗口内重叠。

## 实现与定案

本次修复拆分为三个互补的切片：

1. **切片 1（`noteLayerCache.ts` 视口外脏瓦片即时淘汰）**：
   - 在 `invalidateTilesForBeatRange` 与 `markAllTilesDirty(rc)` 中，利用 `tileIntersectsViewport(id, es, anchorY, rc.surface.h)` 识别视口相交性；
   - 当前视口内的瓦片保留 `t.dirty = true`（严格守护 issue 146 的“实时编辑不白屏/位图连续性”不变式）；
   - 离开当前视口的远端失效瓦片，直接执行 `tiles.delete(id)` 并从 `playTileQueue` 移除；
   - 彻底消除了回滚编辑后滞留在 `tiles` Map 中的离屏脏瓦片，开播时不再出现 `playTileQueue` 排水风暴和旧音符残影闪烁。

2. **切片 2（播放头 80ms HUD 刷新与 `WorkspacePage` 根解耦）**：
   - 在 `PlaybackProvider.tsx` 与 `ProviderTree.tsx` 中暴露轻量专用 hook `usePlaybackSeconds()`；
   - 新增 `WorkspacePlayBar.tsx`（以 `memo` 封装 `PlayBar` 并直读 `usePlaybackSeconds()`）；
   - 将 `WorkspacePage.tsx` 的全量订阅 `usePlayback()` 替换为仅读静态控制态的 `usePlaybackState()`；
   - 消除播放期间每 80ms 一次（12.5 Hz）的 `WorkspacePage` 级联重渲染，大幅降低主线程抖动。

3. **切片 3（消除 `FinalVirtualCanvas` 开播时的重复同步重绘）**：
   - 将 `FinalVirtualCanvas.tsx` 中 `renderCanvas` 对 `isPlaying` 的直接依赖改为通过 `isPlayingRef.current || playbackActiveRef.current` 获取；
   - 从 `renderCanvas` 的 `useCallback` 依赖数组中移出 `isPlaying`，避免开播 React state 翻转瞬间生成新闭包、触发 `useLayoutEffect` 执行冗余的同步全量 `renderCanvas()` 调用，交由 rAF 循环平滑渲染。

## 锁测与验证结果

1. **TDD 单元测试 看守**：
   - `tests/unit/rendering/cache/PlaybackRewindEditDirtyTiles.test.ts`：看守回滚编辑后非视口瓦片立即被淘汰而不是滞留为 dirty，视口内瓦片保留打脏；
   - `tests/dom/workspace/WorkspacePlayheadDecoupling.test.tsx`：看守 `usePlaybackState` 不受 `currentSeconds` 刷新影响，看守 `WorkspacePlayBar` 独立响应时间码；
   - 全套回归：全仓 **203 个 unit 测试套件（2849 个测试）**、**86 个 dom 测试套件（740 个测试）** 全部 100% 通过。

2. **真实浏览器端到端测试（Playwright / Chrome）**：
   - 针对 400 音符复杂谱面执行 `播放 4s → 回滚 0s → 框选批量删除 → 播放`：
     - 开播后前 20 帧 delta 稳定在 15~17ms 之间；
     - **大于 18ms 的掉帧数：0 个**（满帧 60 FPS）；
   - 执行 `回滚 0s → Ctrl+Z 撤回恢复 → 播放`：
     - 开播后前 20 帧 delta 稳定在 15~19ms 之间；
     - **最大帧间隔仅 19.8ms**，无卡顿阻塞，无旧音符闪现或延迟蹦出。
