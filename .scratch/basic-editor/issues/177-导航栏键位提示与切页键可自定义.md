# 177 · 导航栏键位提示与切页键可自定义

Type: grilling
Status: resolved

## 来源

2026-10-28 用户报障（附截图）：侧栏每项右侧的 `⇧⌘0..6` 看着乱、怀疑用户看不懂；同时问“切页快捷键为什么不能改，要实现吗”。

## 为什么要改

1. 7 枚 9px 灰色小字常驻，抢同一行的视觉权重；
2. `⇧⌘` 是 macOS 字形，Windows/Linux 无 ⌘；隔壁 tooltip / 快捷键页却写 `Ctrl+X`，一套应用两套写法；
3. 数字只表位次、无语义，中间插一页就全体顺延——用户记的号会失效；
4. **macOS 上 7 个里 4 个按不出来**：`⇧⌘3/4/5` = 系统截图/录屏、`⇧⌘6` = Touch Bar 截图，事件先被系统吃掉；
5. 切页键当时不在 `FunctionId` 注册表里，改键 / 屏蔽 / 冲突检测一律够不着，是三处并行字面量。

## 定案（用户 2026-10-28）

1. **侧栏提示 = 渐进显示**：默认隐藏，hover / focus / 当前页淡入；折叠态不显示；`title` 保留但用平台正确文本。
2. **默认键换掉**：`Alt+1..7`，1 起、与导航位次一一对应。
3. **开放自定义**：切页七功能进 `FUNCTIONS`，`scope: 'app'`，归「系统」桶；与画布功能**同一命名空间**，重复即拒绝（复用 `setFunctionBinding`），**不设优先级**。
4. **屏蔽同样开放**（配置置 `null`）：该页没有键盘入口，侧栏点击照常。
5. **冲突弹窗**：Enter 后若冲突**不关窗**，弹窗内就地报错并保留草稿；否决“只用 toast”（三秒消失、离操作太远）。

## 实现落点

- `ShortcutConfig`：新增 `pageProjects`…`pageSettings`（`scope:'app'`、`category:'navigation'`、`alt+1..7`）；`buildBindingIndex` / `resolveAction` 加 scope 过滤，冲突检测仍遍历全表；`normalizeKeyEvent` 对 `alt+数字` 走 `e.code`（macOS `⌥1` 的 `e.key` 是 `¡`）；`loadConfig` 载入去重。
- `pageNav`：只留 `{ id, functionId }`。
- `AppShell`：`resolveAction(e, settings.shortcuts, 'app')` + `isEditableTarget` 守卫。
- `AppNav`：kbd 从 `settings.shortcuts[functionId]` 派生；`.app-nav-item kbd` 默认 `opacity:0`，`hover / :focus-visible / .is-active` 淡入。
- `ShortcutsPage`：删只读系统行与 `PAGE_SWITCH_ROWS`；`onCommit` 返回 `string | null`，冲突时不关窗、`role="alert"` 就地提示。

## 锁测

- `tests/unit/settings/ShortcutConfig.test.ts`：app 作用域默认键、按作用域分流、`⌥1` 合成字符按 `e.code` 命中、可屏蔽、跨作用域互斥、载入去重。
- `tests/unit/layouts/PageNav.test.ts`：七页 ↔ 七功能、默认 `alt+N`、注册表不再持有键位字面量、AppShell 走 app 作用域。
- `tests/unit/settings/ShortcutIndexFilter.test.ts` + `tests/static/PreviewPageWiring.test.ts`：切页七项归「系统」、预览仍是第 4 项。
- `tests/dom/pages/ShortcutsPageConflict.test.tsx`：切页行可改；冲突不关窗、就地报错、草稿保留；换空闲键后写入并关窗。

## Comments

- 2026-10-28：`Alt+1..7` 的两个副作用已处理——① macOS `⌥1` 会打出 `¡`，故补输入框守卫 + `e.code` 归一；② Web 开发版 Firefox 用 `Alt+1..9` 切标签页，拦不住，接受（桌面端是 Electron/Chromium）。
- 解除屏蔽（启用）与改键同规则：出厂键若已被别的功能占用，拒绝启用并提示占用者。
