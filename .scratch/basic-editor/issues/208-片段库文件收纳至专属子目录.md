# 208 · 片段库文件收纳至专属子目录

Type: chore
Status: resolved

## 来源

片段功能上线后尚未对外公开发布。在架构评估中确认：
1. 数据根（Data Root）顶层原有规划全由子域目录构成（`projects/`、`assets/`、`cache/`），直接裸放 `<数据根>/patterns.json` 破坏了目录布局的正交性；
2. 损坏备份机制（`quarantineBrokenFile`）在文件异常时会就地改名产出 `patterns.json.broken` 等备份文件，导致数据根顶层被杂质文件污染；
3. 片段包含密集的 SP 曲线结点与 BPM 速度语境，体量增长迅速。趁发布前无存量兼容包袱的窗口期，将其收纳进一级专属子目录，可为未来的分片存储、标签索引或本地缩略图缓存提供天然命名空间，免除后续迁移成本。

关于文件名：保持 `patterns.json` 比 `library.json` 更自解释（用户从目录中复制、另存或备份时文件名即明确表意），且最小化跨层常量重命名成本。

## 改动内容

1. **数据根布局（`electron/dataRoot.cjs`）**：
   - 增加 `PATTERNS_DIRNAME = 'patterns'` 常量与 `patternsDir(dataRoot)` 辅助函数；
   - `patternLibraryPath(dataRoot)` 调整为指向 `path.join(dataRoot, PATTERNS_DIRNAME, PATTERNS_FILENAME)`（即 `<数据根>/patterns/patterns.json`）；
   - `ensureDataRootLayoutSync(dataRoot)` 增加 `fs.mkdirSync(patternsDir(dataRoot), { recursive: true })`；
   - `claimDataRoot` 补全目录检查，对齐 `patterns/` 目录的自动补建。
2. **文档与领域上下文同步**：
   - 更新 `docs/adr/0023-片段收藏的载荷与存储边界.md` §3 存储位置口径为 `<数据根>/patterns/patterns.json`；
   - 更新 `CONTEXT.md` §数据根 说明中的固定子目录集合（`projects/`、`assets/`、`cache/`、`patterns/`）。

## 锁测

1. `tests/unit/chart/patterns/PatternStore.test.ts`：
   - 调整路径断言为 `<数据根>/patterns/patterns.json`；
   - 验证无文件不落盘、读写 round-trip；
   - 验证损坏文件生成的 `.broken` 和序号备份文件严格隔离在 `patterns/` 目录内，不污染父级数据根。
2. `tests/static/PatternBackendWiring.test.ts`：
   - 验证 `PATTERNS_FILENAME` 为 `patterns.json` 以及路径函数挂载在数据根布局模块；
   - 验证静态布线与 IPC 注册保持稳定。
