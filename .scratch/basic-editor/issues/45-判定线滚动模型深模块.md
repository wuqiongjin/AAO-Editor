## Question

架构深化评审（2026-08-29，候选 1 / Strong / in-process）指出：「判定线此刻对应第几秒」是播放的命脉，却散在
**2 个组件 + 2 个纯模块**之间，靠 ref 协议互调——理解一个概念要跳 4 个文件，且**无法通过接口测试**
（被 DOM / RAF / ref 协议绑死）。两个最易出 bug 的改动（issue 24 按秒重锚、issue 38 有效缩放钳制）都落在
这条 秒↔scrollY↔滚动条 链上。

本 issue 执行候选 1 的代码整改：**把秒↔scrollY↔滚动条映射 + 按秒重锚状态机 + 有效缩放钳制，收敛进一个
深模块**；`Editor` 只应用 DOM scrollTop，`FinalVirtualCanvas` 只渲染，两者都朝它调用。

## 现状（Before）

- `src/pages/Editor.tsx`
  - 播放 RAF 循环每帧 `virtualCanvasRef.current.getScrollYForPlaybackSeconds(...)`
  - 滚动条 `onScroll` → `chartRangeOf / scrollTopToCanvasY / canvasYToScrollTop`（base/span 映射）
  - 重锚 effect ×2（`[chartEndKey]` 置位 pending + `[virtualHeight]` 就绪后按秒重锚）
  - `lastScrollSecondsRef` / `pendingAnchorKeyRef` / `initialScrollDone` / `lastTargetScrollYRef`（死）
- `src/components/FinalVirtualCanvas.tsx`
  - imperative handle 暴露 6 个秒↔scrollY 方法：
    `getScrollYForPlaybackSeconds / setScrollY / getPlaybackSecondsForScrollY / getChartScrollRange / getScrollY / getVirtualHeight / getMaxScrollY`
  - geometry 缓存 + `getSortedBpmEvents`
- `src/utils/ChartGeometry.ts` — beat↔virtualY、有效缩放钳制（`effectiveScale`）
- `src/utils/AudioTiming.ts` — 秒↔beat（BPM 事件表）

ref 协议这条 seam：Editor 经 `virtualCanvasRef.current.*` 反向调用画布的数学方法。

## 整改（After）

新增深模块 **`src/utils/PlaybackScrollModel.ts`**（纯逻辑，node 环境可单测，脱离 DOM / RAF / ref 协议）：

- **三域互映**：秒 ↔ 画布 scrollY ↔ DOM 滚动条 scrollTop（判定线=画布底边，ADR-0006 §2）
  - `scrollYForSeconds(seconds)` / `secondsForScrollY(scrollY)`
  - `scrollRange()`（谱面实际可滚范围，无空白，ADR-0004 §3 修订）
  - `canvasScrollYToScrollTop / scrollTopToCanvasScrollY`（需 DOM maxScroll）
  - `virtualHeight()` / `maxCanvasScrollY()`
- **按秒重锚状态机**（issue 24 三段式，收敛为纯状态机）：
  - `markInitialized()` / `noteChartEndChange(key)` / `noteScrollObserved(scrollY)` /
    `takePendingReAnchor(maxScroll)`
  - 待重锚期间不得用新几何覆盖旧锚点（SKIP 保护）；重锚后同步锚点
- **有效缩放钳制**：委托 `ChartGeometry.effectiveScale`（ADR-0006 Q4=A）

**Editor**：持 `scrollModel`（ref 单例，每渲染 `configure` 注入 bpmEvents/谱长/surface/scale/纵向比例）；
RAF / 滚动条 / seek / 重锚 effect 全部改朝模型取数学，只把结果应用到 DOM（`container.scrollTop`）与画布
（`canvas.setScrollY`）。删除 `chartRangeOf / scrollTopToCanvasY / canvasYToScrollTop` 与 4 个滚动 ref。

**FinalVirtualCanvas**：imperative handle 收窄为**类型化** `FinalVirtualCanvasHandle`——只留
`setScrollY`（应用）+ 起点标记 5 方法；**删除 6 个秒↔scrollY 数学方法**（迁入模型）。

## 不变量（行为保持，必须逐条单测覆盖）

1. `scrollYForSeconds / secondsForScrollY` 互逆；越界钳制到 `[0, chartEndVirtualY]`。
2. `scrollRange()` = `{ top: 0, bottom: chartEndVirtualY }`（与画布 `getChartScrollRange` 一致）。
3. 滚动条↔画布 映射互逆；`maxScroll<=0` 时不产生越界。
4. **issue 24 核心不变量**：谱面末端（时长/BPM/surface）变化后按秒重锚，判定线处秒数保持不变
   （同几何内 `secondsForScrollY(scrollYForSeconds(s)) === s`；跨几何重锚后仍落在锚点秒）。
5. 重锚状态机：未初始化 / 播放中不置位 pending；待重锚期 `noteScrollObserved` 跳过（SKIP）；
   `maxScroll<=0` 时清 pending 但跳过重锚（与现实现一致）。

## Answer（结论，2026-08-29）

已按候选 1 收敛为深模块，行为保持（浏览器实测 + 单测双验证）：

- **新增 `src/utils/PlaybackScrollModel.ts`（深模块，纯逻辑可单测）**：
  - 三域互映 `scrollYForSeconds / secondsForScrollY / scrollRange / scrollTopToCanvasScrollY /
    canvasScrollYToScrollTop / virtualHeight / maxCanvasScrollY`——判定线=画布底边，数学逐条等价于
    原 FinalVirtualCanvas 的 6 个 ref 方法（用 `AudioTiming` 秒域 `secondsToBeat/beatToSeconds` +
    `ChartGeometry` 像素时间线，二者经 BpmTimeline 严格互逆）。
  - 按秒重锚状态机 `markInitialized / noteChartEndChange / noteScrollObserved / takePendingReAnchor`
    ——吸收 issue 24 的三段式（标记待重锚 → virtualHeight 就绪后按锚点秒重锚 → 同步锚点），
    含 SKIP 保护（待重锚期滚动观察不覆盖旧锚点）与 未初始化/播放中/maxScroll≤0 守卫。
  - 有效缩放钳制 `effectiveScale()` 委托 `ChartGeometry` 单一实现（issue 38 / ADR-0006 Q4=A）。
- **`Editor.tsx`**：持 `scrollModel`（ref 单例，每渲染 `configure(geometry, scale)` 注入最新几何/缩放）；
  RAF 循环 / 滚动条 onScroll / 进度条 seek / 两个重锚 effect 全部改朝模型取数学，Editor 只把结果
  应用到 `container.scrollTop` 与 `canvas.setScrollY`。**删除** `chartRangeOf / scrollTopToCanvasY /
  canvasYToScrollTop` 与 4 个滚动 ref（`lastScrollSecondsRef / pendingAnchorKeyRef /
  lastTargetScrollYRef`；`initialScrollDone` 保留为「初始滚动只执行一次」门控）。
- **`FinalVirtualCanvas.tsx`**：imperative handle 收窄为类型化 `FinalVirtualCanvasHandle`——
  只留 `setScrollY`（应用）+ 起点标记 5 方法；**删除 6 个 秒↔scrollY 数学方法**（`getScrollYForPlaybackSeconds /
    getPlaybackSecondsForScrollY / getChartScrollRange / getScrollY / getVirtualHeight / getMaxScrollY`）
    与随之无用的 `getSortedBpmEvents`/`beatToSeconds` 导入。ref 协议 seam 消除。
- **验证**：
  - `tests/unit/PlaybackScrollModel.test.ts` 15 例（node，无 DOM/RAF）覆盖不变量：秒↔scrollY 互逆+越界钳制、
    与 ChartGeometry 既有语义一致、scrollRange/virtualHeight、滚动条↔画布互逆、有效缩放钳制、
    issue 24 重锚（谱面末端拉长后判定线处秒数保持不变）、SKIP 保护、播放/未初始化/maxScroll≤0 守卫。
  - `tsc -b` 0 错误；vitest 315/315 全绿；`npm run build` 绿；`npm run lint` 错误数 81→77（删掉 2 处 `any`，
    无新增，77 个均为既有其它文件问题）。
  - 浏览器实测（开发服务器）：播放 RAF 滚动跟随（0→30s，scrollTop 13200→~6）、进度条 seek（→00:15.0）正常；
    **issue 24 不变量复现判据**：40s 谱滚动到 20s（00:20.0）→ 谱面时长改 60s → 判定线处秒数**保持 00:20.0**
    （滚动比例 0.5→0.333，即"同秒、更长谱"），未漂移到新末端（~39s），无 console 错误。
- **边界**：未动音频域（候选 3）、未动 Editor 的其它会话流（候选 2）；`settings` 字段位置不动。
  候选 2 的播放协调模块可在此基础上直接复用本深模块（滚动数学已出组件）。
