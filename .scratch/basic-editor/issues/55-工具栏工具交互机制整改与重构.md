# 55 · 工具栏的工具交互机制整改与重构

Type: grilling

## Question

**用户痛点：当前的工具切换、放置不顺手。** 工具交互直接决定谱师的操作效率和手感，是本 effort 中最关键的交互面之一。需系统整改并重构工具栏-画布之间的交互机制。

> 关联既有定案：ADR-0002（工具键 + 执行键双交互，编辑工具态 = Model A 点击即执行）、issue 13（快捷键注册表）、issue 05（多选/圈选/粘贴锚点）、issue 35 F1（选中高亮叠加层）。本票可在其基础上修订，冲突处以本票新定案为准（并同步修订 ADR）。

## 当前实现事实（立案盘点，grill 的前提）

- 工具态 = `UIProvider.selectedTool: string`（自由字符串，无类型约束）。工具栏 `src/pages/WorkspacePage/Toolbar.tsx` 提供 `mouse / bpm / single / flick / skill / ldirectional / rdirectional / slide` 八个常驻工具；`copy / cut / delete / mirror / paste` 不占工具栏按钮、仅经快捷键进入工具态（`FinalVirtualCanvas.handleMouseUp` 内分支处理）。
- **选中态与执行态混在一个 `selectedTool` 上**："鼠标"既是默认态又承载圈选/点选；`mirror` 既是执行动作又是可拖框选的"工具态"；放置类工具（single/flick/…）点击即放置，无"选中工具后等待二次确认执行"与"纯选中态"的清晰分层。
- **区域选择只允许 `mouse` 与 `mirror` 两个工具态**（`handleMouseDown/Move` 里 `selectedTool === "mouse" || "mirror"` 硬编码门控）；其余工具态下拖拽无任何选区语义。
- 放置链路：`handleClick` → snap 到 `beatDisplay` 栅格 → `handleNoteReplacement`（ADR-0001）；BPM 放置走 `prompt()` 弹窗输数值；slide 两击成条（`slideBuffer`）。
- 幽灵预览：`renderToolPreview` 对放置/粘贴/镜像态显示悬停预览（issue 13）。

## 待 grill 议题

**a) 工具的选中态与执行态**
- 什么是"选中态"（选中音符/编辑上下文）、什么是"执行态"（某工具驻留待放置/点击即执行）？两者是否解耦为独立状态轴（如 `selectionMode` × `armedTool`），还是维持单轴 + 默认态？
- 放置类工具执行后：驻留（连续放置）还是回落到选中态（放一个就退出）？各工具族（音符类/BPM/滑条/编辑动作类）分别怎么定？
- 工具态之间切换的手感问题定位：误触、状态可见性（当前处于什么态画布上看不看得出来）、Esc/右键退出手感。

**b) 区域选择的交互逻辑**
- 只允许指针工具才能区域选择吗？还是任何工具态下"按住拖拽 = 圈选、单击 = 执行该工具"（拖拽与点击天然可区分，4px 阈值已存在于现实现）？
- 若放开：放置类工具圈选后拖拽 = 批量移动？批量复制？还是仅建立选区？——与 a 的状态模型联动决策。
- 圈选与既有滚动/中键/平移手势的冲突矩阵。

**c) 探索更好的操作逻辑**
- 用户输入参考：bestdori 使用的是"方案 a 那种"（放置即执行、常驻工具态），但**其部分工具的选中态比较诡异**——吸取其连续放置效率，规避其状态含混。
- 候选模型逐项 grill：单轴互斥（现状）/ 双轴（指针态为底 + 工具可驻留）/ 临时工具（按住修饰键借用、松开回落）/ 模式（mode）与工具（tool）分层。
- BPM `prompt()` 输入这类打断式交互是否纳入本次一并整改。

**d) 来自 issue 09 的硬约束（2026-09-07 补，见 09 关联注）**
- 数据层已就绪：`Slide.connections` 为任意长数组（`render.ts` 按连续点对绘制，`ChartConverter` 仅校验 ≥2），三结点/分叉绿条今天即可解析渲染；09 缺的是**编辑交互**（SP 绿条的 N 结点路径、放置后继续加结点的驻留语义）与**结点属性**（过渡结点缓动的格式字段 + 输入 UI）。
- **约束①**：a) 的工具族矩阵必须把"多击路径类工具"（滑条族）设计为一等公民，而非现状"单击放置 + 滑条两击特例"；矩阵须含 **SP 绿条预留行**（多结点 + 结点参数），否则 09 落地时重开状态轴。
- **约束②**：c) 的 BPM `prompt()` 整改应升格为**统一的"工具内参数输入"模式**定案（画布内嵌小面板/属性条 vs 其他）——过渡结点选缓动函数是同类打断式输入的第二个实例，须直接复用该模式，不再发明第二种。
- 09 自身只拍"范围 + 格式字段 + 缓动算法"；放置交互归本票定案（本票为 09 上游）。

## Answer（定案）

**权威载体 = [ADR-0008 工具交互机制](../../../docs/adr/0008-工具交互机制.md)**（2026-09-07 grill-with-docs 三轮定案，全部细节、语义矩阵、规则表见 ADR 本身；修订波及已同步 ADR-0002/0001/CONTEXT.md）。要点：

1. **状态模型**：持工具态（armedTool，单轴互斥、所有工具共驻、**全工具驻留**、三出口）× 选区（selection，常驻解耦）；"执行"为瞬时动作非态。名词裁决："选中"只指音符进选区。
2. **框选全工具放开**（4px 阈值分流拖/点），按工具族批量应用（键型=逐个走 ADR-0001 替换、动作类=整选区执行、滑条=组合、BPM/粘贴=无效果、镜像=预览+松手执行）；批量后**选区保留**。
3. **Slide 混合制**：两击直放保留（横向禁令仅约束此路径）+ 框选组合（排序=beat+subBeat 升序同拍 lane 升序；**形态归一表**：flick 起点剥标/末尾保留、skill 两端保留、方向键降普通、中间结点统一化、音符消耗为结点、端点重合走 ADR-0001 §3 接合）——**表须逐行单测锁死**（用户点名要求文档+代码双落实）。
4. **执行键矩阵**：Ctrl+E 双档（有选区→组合；无选区→放锚点，与鼠标两击共用 slideBuffer）；Ctrl+` = 放置+BPM 线（沿用上一次值）→就地编辑；Ctrl+C/X/T/Q 作用于选区。
5. **BPM `prompt()` 废除** → **对象就地编辑**模式（沟槽数字自动进编辑态、Enter 应用、随时可改无需持工具；推广到未来结点缓动参数）。与 ADR-0004 沟槽双击起点标记经 stopPropagation 仲裁不冲突。
6. **拖拽移动**引入：仅指针态；按下点分流（音符=移动、空白=框选）；吸附放置栅格；滑条端点延伸/结点整形（补 issue 07 遗留）；hidden 结点/SP 曲线拖拽留 09+56 联动。
7. **Esc 四档链**（弹窗→滑条锚点→清选区→落指针）；**侧栏折叠改绑 `Ctrl+B` toggle** 进快捷键注册表（修复"只能折不能开"）。

实现按 ADR-0008 §8 波及清单逐条核销；验收 = 主观"顺手" + 操作路径回归 + 锁表单测。

## 二轮验收反馈处理（2026-09-07，用户实测 6 项）

1. **测试命名去票号（已做）**：`Issue55ToolMatrix.test.ts`→`ToolActionMatrix.test.ts`；`Issue55EditSeams.test.ts` 按被测模块拆归位：batch 落点/应用 → `NoteReplacementRules.test.ts`、remap → `SelectionEditing.test.ts`、拖拽 → 新建 `NoteDragging.test.ts`。仓库约定 = 测试文件跟随被测模块名（原 526 测 → 现 536）。
2. **两个独立 Slide 框选组合无效（已修，ADR-0008 §4 修订"滑条吸入"）**：根因 = `combineSelectionIntoSlide` 只吸 `kind:'note'` 键型音符，而框选对滑条产出的是 `slideNode/slideRegion` 条目 → 两条滑条全被忽略。修订：完整覆盖（全部结点入框，或 Ctrl+E 下整条选中项）→ 全部结点入链、本体消耗；部分覆盖不参与不消耗（防同位重复）；重合结点合并单点 `hidden:false`、标记按归一表再处置；判据从"键音符≥2"改"**来源对象≥2**"；吸入 Long → 结果 Long。锁表：`SlideCombination.test.ts` 新增 8 测（27）、`ToolActionMatrix.test.ts` 新增 2 行测（45）。
3. **组合成功后"多出的描边辅助线"（已修）**：那是**整条滑条选中态**的黄色虚线包围框（`drawSlideSelection` 旧实现）——框选组合按原则4 把结果滑条留作选区，虚线框恰罩在新滑条上，易误读为框选残留/辅助线。已废除包围框：整条选中 = 全部结点青圈 + 全部连接带青框（贴合物轮廓）。黄圈/青框的整体视觉重做仍归 issue 56-a（已在本票批注衔接）。
4. **拖拽移动触发方式（非 bug，可发现性问题）**：入口 = **指针态（默认底态，无工具高亮）下，在已放置音符上按住、移动 ≥4px、松开**。三处易踩：①其他持工具态下拖拽一律=框选（§6 防误拖设计）；②点音符即松手（<4px）=选中，不是移动；③多选时按住的音符必须已在选区内才会组拖。落点非法（越界/碰撞）= 幽灵消失回弹。可发现性改进（悬停光标/hover 反馈）并入 issue 56-c。
5. **动作类（复制/剪切/删除/镜像/粘贴）持工具态去留 —— 给出方案待拍板**：
   - 现状矛盾根源：矩阵与快捷键**已有**动作族工具态（C/X/T/Q 行：单击音符=选中即执行、框选=批量执行），但 Toolbar 没有对应 arm 入口 → 用户体验不到"连续删除 = T 进删除态后逐条点击、无需框选"，误以为单音符操作必须框选。
   - **推荐方案 A（统一入口）**：Toolbar 编辑区补"删除/镜像"两个 arm 按钮（与键盘 t/q 完全对齐）。连续删除即"T 一下 → 点谁删谁"，比框选快；复制不 arm（后剪覆盖前剪，无意义）；粘贴不 arm（执行键 V 光标处连粘已覆盖）；**剪切不建议 arm**（剪切=复制+删除，源对象已消失，连续剪切无意义）。
   - 方案 B（反向统一）：动作族彻底退出工具轴，删除 `switchCopy/Cut/Delete/Paste/Mirror` 四个切换功能，只留执行键作用于选区——连续删除将退化为"框选/点选 + 执行键"两动，劣于 A。
   - 用户提示的快速手段评估：**右键**最合适做"无工具态单对象快速删除"——现有右键已删滑条部件，建议扩展为"右键 = 删除命中对象本体"（键音符/整条滑条/长条/BPM 线），连续删除零切换；**双击**不建议（先触发两次 click 与选中手势冲突、误删风险；轨道区双击留给未来对象属性就地编辑）；**Ctrl+单击**已被"整条滑条选择"占用（§2）。
6. **"t"仍可进删除态（同 5 的一体问题）**：这是矩阵工具轴的正常入口，不是残留 bug；问题只在 Toolbar 缺入口造成"键盘有、界面无"的错位。采方案 A 则补按钮归位；采方案 B 则删 t/q/c/x/v 的 switch 注册。**待用户选择 A/B（及是否加右键删除）后再动代码**——涉及 ADR-0008 §1/§2 工具轴定义修订。

## 三轮验收反馈处理（2026-09-07，用户实测第二轮 4 项 + 补充 bug）

**#2（重开，语义修正）：框选组合 = 结点级吸入 + 宿主拆条**。用户澄清样例：`A→B`、`C→D` 两独立滑条，**只框 B、C** 也应组合成 `B→C`（残留 A、D 退化独立音符），而非要求全结点入框。ADR-0008 §4 滑条吸入条整体改写：被框到的 `slideNode` 不要求完整覆盖即入链；宿主未覆盖连续段按 ADR-0001 §1.2 拆条同语义保留（≥2 结点 = 子滑条保原 type、结点对象结构共享；=1 结点 = `connectionToNote` 退化保 flick/skill）；来源计数 = 键音符 + 被触碰滑条 ≥2；完整覆盖/整条选中 = 本体消耗无残留；`combineSelectionIntoSlide` 重写。锁表：`SlideCombination.test.ts` 重写 2 测 + 新增 3 测（用户样例 B、C；残段子滑条保 Long；退化保 flick/skill），30 测。

**补充 bug：两击接合不级联**。`A→B` + 以 B 为 buffer 起点两击接 `C`（`C→D` 的头）应一步成 `A→B→C→D`；旧 `handleSlideToSlideCombination` 情况 1/2 各只并一侧即 return，另一半留成重复端点的独立滑条。重写为复用 `mergeChainWithSlides` 双向级联（含端点覆盖移除、同向不合并、途径结点 hidden:false、Long 保型）；合并结果**写回首条被消耗滑条的原下标**（SlideExtendRepro 锁瓦片失效锚定，通过）。该函数与 `connectionToNote` 的模块边界调整：`SlideCombination` 不再依赖 `NoteReplacementRules`，方向反转避免循环。新增级联锁测；接合途径结点 subBeat 归一为 0（既有锁表同步 +1 字段，数据等价）。

**#3（根修）：组合是一次性动作 → 完成后清空选区**。用户明确"组合执行完毕就完事，不应有选中态"。`combineOps`（框选组合 & Ctrl+E 组合档共用）的 `setSelection` 从"结果滑条"改为**空选区**——不再有多余描边（一轮的轮廓高亮渲染修复保留，服务于其他整条选中场景）。ADR-0008 §2 原则 4 增补例外条款。矩阵锁表 3 处同步。
