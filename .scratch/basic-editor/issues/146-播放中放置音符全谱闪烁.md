# 146 · 播放过程中放置音符，画面音符闪一下

Type: bug
Status: resolved（2026-09-22 实现 + 锁测，**用户页面验收通过**）
Blocked by: —

## 来源

用户 2026-09-22 #1：「播放过程中，放置音符，谱面中所有音符会闪一下。（非常诡异）」

## 代码侧事实（2026-09-22 盘点）

- 播放帧的 `scrollY` 只活在 ref：`setScrollY` 在 `playbackActiveRef.current` 时**不进 React state**、直接调 `renderCanvasRef.current()`（`FinalVirtualCanvas.tsx:600-607`）；`renderCanvas` 走 `liveViewport()`（`:235,449`）取 `scrollYRef.current`。→ 放置引发的 React 重渲与播放 RAF **同源**，理论上不该出现「按旧滚动位置重画一帧」的错位帧。
- 播放期瓦片 miss **不同步建**：`drawNotesLayer` 在 `rc.playing` 时对 miss 瓦片 `continue`（`noteLayerCache.ts:422-430`），改由 `playTileQueue` + `setTimeout(…, 0)` 链**逐块**补（`:64-100`，commit `e289e8e`「defer play-time raster」引入）。→ **任何失效在播放期都会先经历若干「这块瓦片没有像素」的帧**。
- 静止（不播放）路径 miss 是同步 `renderTile` → 不闪，与「只有播放中才闪」一致。
- notes 变更的失效粒度是 F3 结构共享 diff（`drawNotesLayer:402-408`）：单次放置通常只删 1 块瓦片（含 `VIEWPORT_PADDING+48` 余量最多 2 块）；`basis` 其余字段（dpr / skinVersion / 显示设置 / chartEndVirtualY / verticalRatio / bpmEvents）都不受放置影响 → **未见全量 `tiles.clear()` 的通路**。这与「所有音符都闪」的描述不符，待浏览器实测确认是「真全清」还是「视口只覆盖 2 块瓦片、丢一块看着像全屏」。

## 用户回答（2026-09-22）

- **Q1 = ② 整屏音符全部消失一瞬**（全_clear 级别）。
- **Q2 = 删除 / 撤销 / 重做 / 拖拽移动 / 粘贴**都会闪 —— 即**任何 notes 变更**在播放中都会触发，不限放置。

## 实测定位（探针，2026-09-22）

单例注入假位图跑 `drawNotesLayer`（750×900、es=1、200 个单键、视口居中 beat 100）：

| 场景 | blitted | blitCssPx | tiles 数 |
| --- | --- | --- | --- |
| 播放稳态（notes 引用不变） | 2 | 675000 | 5 |
| **改一个音符（结构共享）** | **0** | **0** | 3 |
| **整份换新引用（undo/redo 形态）** | **0** | **0** | 0 |

即：**可见的内容瓦片被整批删掉，而播放帧偏不同步补**。删的不止一块 —— 失效余量 `margin = (VIEWPORT_PADDING+48)/es`，`VIEWPORT_PADDING = 200` → 默认缩放下 ±248 pos px，一块瓦片 512 pos px ⇒ 常盖住全部可见内容瓦片 ⇒ 整屏音符同一帧没有像素，直到 `setTimeout` 队列（每 macrotask 一块）把它们补回来。

## 修法（issue 146 落地）

**失效 = 打脏 + 保留旧位图**，不再 `tiles.delete`：

- `Tile` 增 `dirty` 标记；`invalidateTilesForBeatRange` 与 `diff = full` 两条路径都改成置脏（`markAllTilesDirty`）；非空内容的瓦片本帧仍照旧 blit 上一版位图过渡 → **不出现空白帧**，队列异步重建完自然换下（`renderTile` 产出无 `dirty` 的新对象）。
- 静止 / 手势期：脏瓦片仍**同步**重建（放置即看得见，旧行为不回退）；播放期让位给队列，不在 present 帧付光栅成本（保 101 / 139 / 140）。
- `enqueuePlayingTiles` / `drainOnePlayingTile` 的跳过条件从「不存在」改为「不存在**或打脏**」，否则脏瓦片永远进不了队列。
- **basis 级失效**（dpr / skinVersion / 显示设置 / 时间线 / 纵向比例）仍走 `tiles.clear()` —— 那些是全量重建语义，且不在本票症状里；由此产生的播放期空白帧见票末「遗留」。

## 锁测

- 新增 `tests/unit/visual/cache/PlaybackEditTileRefresh.test.ts`（5 例；回退源码实测 **4 红 1 绿**，是真护栏）：
  1. 播放中改一个音符 → 当帧 `blitted` / `blitCssPx` 与稳态同值（**修复前掉到 0**），且 `rebuilt === 0`（播放帧仍不通步光栅）；
  2. 整份换引用（undo/redo 形态）→ 同上；
  3. `__flushPlayingTileQueueForTests()` 后脏瓦片对象被换掉、`dirty` 清除，后续帧 `notes` 引用不变则不再建位图（不引入重复重建）；
  4. 非播放期改音符 → 当帧**同步**重建（旧行为不回退）；
  5. 播放中编辑后停播放 → 脏瓦片被同步补上，旧内容不残留。
- `tests/unit/visual/cache/HighZoomTiles.test.ts`（ issue 140 的播放排队口径）保持全绿 —— 本票没动「播放帧不同步建」这条决策。
- 手工验收：播放中连续放 5 个音符 / 删几个 / Ctrl+Z，画面不应出现任何一帧「音符消失」。注意新内容会晚 1~2 帧才出现（过渡帧是旧位图），这是有意的取舍（下节）。**2026-09-22 用户页面验收通过。**

## 取舍记录：新内容晚 1~2 帧出现（2026-09-22 与用户确认，维持现状）

过渡帧 blit 旧位图 ⇒ 新增/删除的音符不是在编辑那一帧就变样，而要等队列重建完（通常下一帧）。若要「编辑当帧立刻变样」，得在播放帧同步光栅那一两块瓦片。

维持现状的三条理由：

1. 播放帧预算是 138 / 139 / 140 连续三轮明确要保护的东西；**每次编辑仅发生一次**的 16~33ms 观感，不值得用 hover 谱面 SP 带的帧抖动去换。
2. 延迟有界且自愈：队列每 macrotask 补一块，且另有兜底 —— 停止播放（`setPlaybackActive(false)`）会同步把脏瓦片补上。
3. 机制保持单点：失效 = 打脏 + 队列补，不再有「同步 / 异步」两条通路并存。

**回头触发器**：若将来在密集 SP 带谱面上肉眼看到「放置后音符出现慢」，针对 `diff` 命中的少数瓦片加一档同步预算即可（不改其余决策），不必推翻本票结构。
