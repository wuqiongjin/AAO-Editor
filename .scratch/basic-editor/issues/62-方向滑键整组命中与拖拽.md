## 来源

issue 55/56 验收后用户复报的遗留问题 #3（2026-09-09）。关联 [56](./56-谱面画布音符选中状态整改.md)（A4 修订：方向键选中描边 = **整体一个矩形**）、[61](./61-拖拽落点吸附相位修复.md)。

## 症状

长度 2/3 的方向滑键（占多条轨道），**框选**与**拖拽**判定用的永远是**根部那一枚本体**，不是整组：

- 框住它的箭头端（非根轨）→ 不入选区；
- 按住非根轨的本体拖 → 命中不到 → 变成框选；
- hover 描边却是整组一个矩形（issue 56 A4 修订后）→ **所见 ≠ 所中**。

## 根因（已定位）

方向键 = `LDirectional`/`RDirectional` + `length(1..3)`，视觉占 `lane` 与 `lane + sign·k`（L 向左 `sign=−1`、R 向右 `sign=+1`，`k = 0..length−1`），几何由 `noteSkin.dirGroup()` 给出。但命中层三处都只认根：

| 位置 | 现状 |
| --- | --- |
| `hitTest.findItemAt` | 只测 `note.lane` 一个圆 → 拖拽/hover/点选只认根 |
| `hitTest.computeItemsInBox` → `ChartGeometry.noteVirtualPoints` | 方向键只返回 1 个点（根）→ 框选只认根 |
| `NoteDragging.planDragMove` 越界校验 | 只校验 `note.lane` → 整组可以拖出轨道外（右侧溢出） |

## 定案（本轮实现口径）

> 用户 2026-09-09 报的是症状（"判定的永远是根部那个音符，而不是整体"），**未预选方案**；下面把"整体"落成"根轨 + 沿方向再占 length-1 条"，与 56 的整组描边同口径，待验收。

**整组是一个对象**，占用轨道 = 一份共享几何，四个消费点（点选 / hover / 框选 / 拖拽越界）同一口径：

- **框选判据**：框到**任一本体所在轨道**即整体入选（与滑条「任一结点入框即算触碰」同口径；不采用 BPM 那种"完整覆盖"）。
- **单击 / hover 命中**：任一本体轨道中心命中（半径同单键 `noteRadius`，与 `findItemAt` 既有单键口径一致）。箭头挂件超出本体的那一小截不作为命中区——它是装饰，与"箭头不单独可选"一致。
- **拖拽越界**：整组占用轨道必须都留在 `0..LANES−1` 内，越界 = 非法落点回弹。

> 放置时的同一条越界约束**不在本票范围**（现状允许在 lane 6 放 length=3 的右方向键、视觉溢出），若要加强另立票。

| 文件 | 改动 |

## 验收

- length=1/2/3 × L/R：框住**最外侧**本体即入选；按住非根本体能拖起来；hover 描边（整组矩形）与命中范围一致。
- 拖到轨道边缘：整组会溢出时回弹（不改变谱面）。
- 回归：单键 / 滑条结点命中不变；`SelectionVisual.test.ts` 全绿。
