方向滑键**在轨道外面的部分可以点击到、也可以框选到，其它工具对它轨道外的部分也生效**。
有问题的**只有 4a 与 4b 两个场景** —— 故命中层（`hitTest.findItemAt`）与框选层

## §4a · 按在组尾（轨道外）那一截上拖不动

**症状**：放置了一个超出轨道外的方向滑键，拖动时**必须按在轨道内的部分**才拖得动；
按组尾（轨道外）那截 → 拖不动（手势退化成框选）。

**根因**：与命中无关，在**拖拽起手**。

```
beginDragCandidate → snapPos(cx,cy) → laneBeatFromCanvas
   → if (lane >= 0 && lane < LANES && beat >= 0) … else return null   // ← 越界 lane 直接 null
   → `if (!p) return;` → dragRef 建不起来 → 手势变框选
```

组尾溢出那截的 lane ≥ 7 → `laneBeatFromCanvas` 返回 `null` → 拖拽锚点建不了。

**修法**：给 `laneBeatFromCanvas` 加 `allowOutsideLane` 参数（默认 `false`，保持放置语义
"不能往轨道外落子"）；**仅拖拽路径传 `true`** —— lane 允许越界（照实返回越界轨号），
`beat` 范围校验始终保留。越界 lane 只用于算相对位移 `dLane = cur.lane − pressLane`，
落点是否越界交给 `planDragMove` 按 §4b 裁决。

| 文件 | 改动 |
| --- | --- |
| `src/chart/geometry/ChartGeometry.ts` | `laneBeatFromCanvas` 增 `allowOutsideLane = false`；`beat < 0` 恒 null，lane 越界仅在放行时通过 |
| `src/chart/components/canvas/FinalVirtualCanvas.tsx` | `getLaneBeatFromCanvas` / `snapPos` 透传；`beginDragCandidate` 与 `dragDelta` 传 `true`（放置/执行路径仍严格） |

## §4b · 拖到"组尾溢出"的新位置被回弹

**症状**：方向滑键的一部分有能力超出轨道外（视觉与放置都合法），但拖动时**任何**区域超出轨道即回弹。

**根因**：`planDragMove` 对方向键判**整组**都在 `0..6`：
`if (!lanes.every(inLane) …) return fail('out-of-bounds')`。

**修法（用户明确诉求）**：**只判根轨** —— 根轨必须在界内（用户原话"最基础的那个根在轨道内"），
**组尾溢出合法**，与放置链路"允许 lane 6 放 length=3 右方向键"同口径。

| 文件 | 改动 |
| --- | --- |
| `src/chart/editing/NoteDragging.ts` | `isKey(n)` 分支改 `inLane(lane)`（不再 `lanes.every(inLane)`）；移除随之失效的 `directionalLanes` import |

> 放置链路的同款判定不在本票（issue 62 已备注"现状允许溢出"），若要加强另立票。
