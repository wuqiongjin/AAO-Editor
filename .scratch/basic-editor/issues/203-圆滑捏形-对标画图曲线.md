## 来源

2026-11-01 用户提出（/grill-me 两轮）：
1. 拖 SP 段出来的形状"棱角分明"（三角捏形峰值处尖角，见图：拖中点成 V），希望像 Windows 画图曲线工具那样圆滑；
2. 现在是"固定拖拽点"（抓取点按下锁定），画图是按住不放时峰值随光标走、看起来"不固定拖拽点"的丝滑拖拽。

本票**修订** issue 108 的定案（108 已 resolved，不改写）。

## 症状

1. 尖角：拖拽 SP 曲线段或普通滑条段时，形成的形状呈分段线性折线，峰值处有尖角（V 形），不够平滑；
2. 固定点：抓取点在按下时即锁定拍位（`grabBeat = DragAnchor.rawPressBeat`），拖拽过程中峰值无法随光标拍位移动；
3. 一格一格：`GestureSession.dragDelta` 的 `dLane` 采用整数轨道差，捏形幅度按整轨阶梯跳变，手感不够细腻丝滑。

## 根因

1. `SpanCurve.ts` 的 `pinchWeight` 采用分段线性三角权重，峰值处一阶导数不连续导致尖角；
2. `planDragMove` 的 region 分支丢弃了光标拍分量，只接收整数 `dLane`；
3. 画布事件与手势层未透传浮点连续 `lane` 与光标实时拍位，且未支持修饰键动态重算预览。

## 圆滑捏形数学（实现口径）

记段两端可见结点拍 `B0 < B1`，按下时快照的段内点集（普通段 = 弦上补 1/16 点）构成原形 `L(b)`（相邻采样点间线性插值，含两端可见结点）。

- 按下：光标未量化拍 `bp`、**连续** lane `lp`；偏移 `o = lp − L(bp)`（起拖不跳）。
- 每帧：光标 `bc`、`lc`；控制点拍 `c = clamp(bc, B0 + ε·(B1−B0), B1 − ε·(B1−B0))`（ε 建议 0.02，实现时可调，锁测给出）。
- 鼓包（三次贝塞尔，P1=P2=(c,h)）：`x(t) = B0(1−t)³ + 3c·t(1−t) + B1·t³`（c∈[B0,B1] ⇒ x 单调）、`y(t) = 3h·t(1−t)`。对拍 `b` 二分解 `x(t)=b` 得 `t_b`，位移 `d(b) = h·k(b)`，`k(b) = 3t_b(1−t_b)`。
- 穿过光标：`h = (lc − o − L(c)) / k(c)`（光标沿原线移动 ⇒ h=0，线不变）。
- 贴边：`s = max s∈[0,1]` 使所有点 `L(b) + s·h·k(b) ∈ [0,6]`；结果 lane = `L(b) + s·h·k(b)`。
- 两端 `k=0` ⇒ 可见结点不动；直线段 + 鼓包 = 恰为画图贝塞尔（仿射不变）。

三角捏形（Alt）：沿用 `pinchWeight` + 按下锁定的抓取点，`dLane` 改为**连续** `lc − lp`。

## Answer

**resolved**。已按照用户定案支持圆滑捏形与 Alt 实时切换三角捏形：
1. **圆滑贝塞尔鼓包算法**：在 `SpanCurve.ts` 中实现三次贝塞尔鼓包，曲线严格穿过光标，峰值随光标丝滑跟随，整体等比缩小贴边（0..6 轨道内无平顶截断）；
2. **Alt 实时切换旧三角捏形**：拖拽中按下/松开 Alt 即时无缝切换为旧三角捏形（逐点 clamp），并阻止 Alt 夺取 Windows 菜单栏焦点；
3. **全链路连续 lane 与光标拍支持**：`CanvasGesture`、`GestureSession`、`NoteDragging` 贯通连续 float lane 与当前光标拍位，非 region 拖拽仍严格保持整数轨道与原有时序约束；
4. **锁测验证**：`SpanCurve.test.ts`、`NoteDragging.test.ts`、`GestureSession.test.ts`、`CanvasGesture.test.ts` 针对性锁测全部通过，全量图表单元测试通过，`npx tsc -b` 零错误。
