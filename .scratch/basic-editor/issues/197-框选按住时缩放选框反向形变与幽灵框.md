## 来源

用户实测反馈：框选功能，在按住一个区域不动的时候，如果此时缩放，行为会变得很诡异，比较难描述，不符合正常逻辑。

## 症状

1. **不动却凭空起框**：鼠标按下左键（或右键）停留在原地未拖动，此时用 Ctrl+滚轮 / 触控板捏合缩放，画面上立刻从光标处向外炸出一个大面积选框。
2. **选框反向形变、完全脱轨**：
   - 放大时：音符随判定线（底部）向上方延伸移动，但选框起点 $p_1$ 反而向下方（底边判定线方向）狂奔，甚至跌出画布底边。
   - 缩小时：选框起点 $p_1$ 向上方飞窜。
3. **选区高亮音符错乱**：由于选框与谱面实际音符严重脱节，选框内部高亮的音符闪烁、跳变，框住的完全不是按下处附近的音符。
4. **松手误击**：若在原地按住并缩放后松手（意图单击或取消），由于起点虚拟坐标在缩放后转回画布像素，`click` 事件会被派发到数百像素外的荒谬位置。

## 根因

1. **`virtualY` 并非无缩放绝对谱面坐标**：
   - 历史 issue 32（圈选时滚动选区起点未锚定谱面坐标）为了支持"滚动长截图"，在 `session.begin` 记录了 `start = { x, y, vx, vy }`。
   - 但 `ChartGeometry` 中，`baseline(scale) = chartEndVirtualY + surface.h / effectiveScale(scale)` 依赖 `scale`。
   - 实际换算关系中：$pos = \text{baseline} - virtualY$。当仅滚动（`scrollY` 变、`scale` 不变）时，$virtualY$ 是常数，能正确锚定拍位；但**当缩放发生（`scale` 变化）时，$virtualY$ 根本不是拍位的恒定量**！
2. **`marqueeRect` 反解公式在变尺度下的数学崩塌**：
   - 缩放使用判定线（底边）锚定（issue 90），`scrollY` 保持不变。
   - 当 `start.vy` 经 `virtualToCanvas` 在新比例 $es_{new}$ 下求值时：
     $$p_1.y = (start.vy - scrollY) \times es_{new} = \left(\frac{y_{press}}{es_{old}}\right) \times es_{new} = y_{press} \times \frac{es_{new}}{es_{old}}$$
     起点坐标 $p_1.y$ 被简单粗暴地按画布顶部为原点乘上了缩放比！
   - 同理横向 $p_1.x = \text{center} + (x_{press} - \text{center}) \times \frac{es_{new}}{es_{old}}$。
   - 而光标端 $p_2$ 仍锁死在当前屏幕鼠标像素坐标（$pos.y$）。于是原先重合的两点（$p_1=p_2$）在缩放瞬间被硬生生扯开为距离高达数百像素的巨型矩形。
3. **未移动（`!this.moved`）状态下的脏数据残留**：
   - 用户按住未动时 `this.moved === false`，`onViewportChange` 早退未更新快照；一旦用户手微抖超过 8px 阈值，或就地松手 `end()`，之前记录的陈旧 `start.vx, start.vy` 在新 `viewport` 下反解，产生瞬态爆框或远距离误点。

## 修法

1. **`marqueeRect` 起点引入 `pos` 锚定**：
   - `input.start` 支持 `{ vx: number; vy?: number; pos?: number }`。
   - 若提供 `start.pos`，通过 `geometry.virtualYOfPos(start.pos, viewport.scale)` 动态推导当前比例下的真实虚拟 Y，转回画布像素坐标 $p_1$；保持原 `{ vx, vy }` 兜底兼容。
2. **`GestureSession` 记录谱面时间轴 `pos`**：
   - `begin` 时通过 `w.geometry.posOfVirtualY(input.vy, w.viewport.scale)` 记录 `this.start.pos`。
   - `end` 中 `click` 派发也通过 `pos` 动态反解当前 `virtualY`，确保点击位置真实准确。
3. **未移动状态（`!this.moved`）防抖重锚定与防起框**：
   - `onViewportChange` 中，当 `!this.moved` 时不构造 `selectionBox`（维持 `null`），并将 `this.start` 同步对齐到当前光标处的最新坐标，彻底杜绝原地缩放炸出选框与后续移动/抬手突跳。
   - 处于持工具态不可框选（`canStartMarquee === false`）或画笔工具态时，也严密拦截在视口变化时不误触发框选。

## 锁测

- `tests/unit/chart/editing/GestureSession.test.ts`：
  - 用例 1（按住原地不动缩放）：缩放后 `selectionBox` 保持 `null`；原地松手派发点击坐标精确对齐光标。
  - 用例 2（框选拖拽中缩放）：缩放到 1.5 倍，选框起点 $p_1$ 精确对齐按下点音符在新比例下的画布坐标，反向形变与坐标飘移差消除。
- `tests/unit/chart/editing/CanvasGesture.test.ts`：
  - 缩放变尺度下，`marqueeRect` 起点反解回的谱面 `pos` 严格恒等。

## Answer

**resolved**。已通过引入 `pos` 真谱面绝对位置锚定重构 `marqueeRect` 与 `GestureSession` 视口同步逻辑，彻底消除了原地缩放起框、选区反向形变及松手误击。全仓 372 个测试文件 4107 条单测及 `tsc -b` 全部通过。
