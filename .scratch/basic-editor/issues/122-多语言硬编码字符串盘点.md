# 122 · 多语言：硬编码字符串盘点

Type: research
Status: resolved
Blocked by: 125

## Question

产品 **大概率要做多语言**。本票 **只调研、不改代码、不拍是否开工**。

必须回答：

1. 硬编码中文的量级与分层（应用壳 / 内容页 / 工作台 / Electron 菜单 / 错误信息 / 缓动族名这类并列文案）。
2. **可以不引入 i18n 框架吗？** 手搓字典、按语言打两份包、和引入 i18next（或同类）的工程成本差在哪；第一种外语 vs 再加一种的成本（LTR、非 RTL）。
3. issue 114「不引入 i18n」的 **实际范围**：当时否的是「为曲线缓动族名上翻译字典」，**不是**「产品永远单语言」。列出 114 会被迫重看的点（例如 `Sine（正弦）` 并列还是拆键），**本票不决定翻不翻 114**。

不要写「推荐现在就做 / 推荐永久不做」的产品结论（那是后续 grilling）。

## Answer

盘点基线 = **125 落地后的 `src/` + `electron/`**（2026-09-19）。方法：去注释后的字符串/模板字面量含 CJK + TSX 文本节点。`tests/`、`.scratch/`、`src/prototypes/` 不算产品面。数字是**按文件去重后的条数之和**（「单键」会在工具栏 / 快捷键表 / 皮肤预览各计一次）；全局去重后的**用户可见键**大约 **250–350**。不含注释。`AppSettings` 无 locale 字段。`index.html` 现为 `lang="en"`，界面正文是中文——无障碍/浏览器词典已和 UI 语言不一致。

### 1. 量级与分层

| 层 | 约略条数 | 落点 | 备注 |
| --- | ---: | --- | --- |
| **应用壳** | ~15 | `AppNav` / `AppShell` / `AppPageShell` | 五页名、折叠、`aria-label`。无 `document.title` / `lang`。 |
| **内容页** | ~170 | 设置 / 音频 / 素材 / 快捷键四页 | 最大面。125 已改页面头与空态；侧栏专名、滑杆 hint、素材背景三张卡长说明仍硬编码。 |
| **工作台** | ~90 | Toolbar、曲线面板、PlayBar、NoteInfo、代码弹窗、Editor chrome | 工具名与快捷键 `label`/`category` **双份**（`Toolbar.tsx` + `ShortcutConfig.ts`）。 |
| **快捷键注册表** | ~61 | `ShortcutConfig.ts` + `shortcutIndexFilter.ts` | 功能名、类别、索引桶、切页五项。 |
| **错误 / 确认** | ~70 | `ChartConverter` / `NoteCodeOps` / 代码弹窗 / `AudioSession` / 设置导入失败 | 用户可见。另：`window.confirm` 两处（关弹窗 / 覆盖应用）。 |
| **并列文案（缓动族等）** | 14+5+面板 chrome | `EASING_*_LABELS`、`SHAPE_TEMPLATES.label`、`CurveConfigPanel` 标题 | 见 §3。 |
| **Electron「菜单」** | **0 条菜单** | `Menu.setApplicationMenu(null)`（[Menu.setApplicationMenu](https://www.electronjs.org/docs/latest/api/menu)） | **有**系统对话框：选数据根 / 认领 / 导出谱面代码 / 搬家失败 `message`（`electron/main.cjs`、`dataRoot.cjs`）。主进程是 CJS，渲染是 TS——字典必须两边都能读。 |
| **非 UI（勿当产品文案）** | ~40–60 | 覆盖规则 `message`、`console.warn`、`throw`、字体栈里的「思源黑体」 | `NoteReplacementRules.message` 不进界面；`EditingProvider` 只看 `shouldReplace`。 |

画布标线 **START / END / BPM 数字**、时间码 `mm:ss` 是拉丁/数字，不在中文盘点里。issue 124 字体档 **不随界面语言切换**（设置页原文）。

锁中文原文的测试（改字典必改）：`CurveConfigSettings.test.ts`（`Sine（正弦）` / `不使用模板`）、`shortcutIndexFilter.test.ts`（空桶句）、`ChartCodeExportSaveAs.test.ts`（「另存为」）、`NoteCodeOps.test.ts` / `ChartCodeValidation.test.ts` / `NegativeBpm.test.ts`（校验句）。数据根单测锁的是 `code` 不是中文 `message`。

### 2. 可以不引入 i18n 框架吗？

**可以。** 三种做法都能做出第一种外语；差在「运行时切语言、插值/复数、主进程共用、加语种」的工程形状，不是「做不做得出来」。本票不拍选哪条。

| | 手搓字典 | 按语言打两份包 | i18next + react-i18next |
| --- | --- | --- | --- |
| **是什么** | `Record<Locale, Record<Key, string>>` + `t(key, vars)` + React context | 构建时烧进一种语言（Vite define / 两份 `electron-builder` 产物） | `i18next.init` + `t()` / `useTranslation`；[起步](https://www.i18next.com/overview/getting-started)、[react-i18next](https://react.i18next.com/) |
| **第一种外语** | 抽键 + 包一层 + Electron 主进程能 `require` 同一份 JSON。插值自己写。 | 抽键一次，但 **运行时不能切语言**。今日仓库 **没有** `electron-updater`；真上更新后，同一 `appId` 两份包会抢 feed，拆 `appId` 则两份 `userData`（谱面默认根看起来像丢了）。谱面 JSON 无 locale。 | 依赖 + 渲染/主进程各一份 init 或 IPC；[插值 `{{var}}`](https://www.i18next.com/translation-function/interpolation)；[TS 键类型](https://www.i18next.com/overview/typescript)可选。`Trans` 覆盖「一句里夹标签」。 |
| **再加一种 LTR** | 多一份表；`t()` 不动。 | 再打一份安装包 / 再一条更新 feed。若这时才要应用内切换，两份包等于白做，仍要回到运行时字典。 | 多一份 JSON（+ 校对）。 |
| **框架多出来的能力** | 无 CLDR 复数、无官方抽键 CLI、缺 key 要自己约定。中文现状多用「有 N 处错误」绕开复数；**第一门英语会倒逼改句式**（[plurals](https://www.i18next.com/translation-function/plurals) `_one`/`_other`）。 | 同左，且无热切换。 | 复数、嵌套、缺 key、选择器类型；**不管 CSS / `dir` / 画布镜像**。 |
| **RTL（阿语等）** | 与框架无关：[`html dir`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/dir)、逻辑属性、侧栏是否翻。**谱面画布必须保持 LTR**（轨道序）。阿语复数最多六式——手搓要重做这块，i18next 已接 `Intl.PluralRules`。 | 两份包也要各做一套 RTL 布局，否则只翻了字符串。 | 同上，另加资源。 |

**第一种外语 vs 再加一种（均 LTR）**：第一种贵在抽键、插值语序、Electron 对话框、以及「中文绕开的复数」。CLDR 里中/日基数复数只有 `other`，英语是 `one`+`other`（[CLDR plural rules](https://www.unicode.org/cldr/charts/47/supplemental/language_plural_rules.html)）。第二种 LTR 主要是翻译文件。日文可蹭现有 Noto CJK JP 回退。**RTL 不是「再加一份 JSON」**，是布局例外 + 画布不翻。成本对照细表见 [docs/research/i18n-engineering-cost.md](../../../docs/research/i18n-engineering-cost.md)。

### 3. issue 114「不引入 i18n」的实际范围

当时否的是 **「现在为缓动族名上翻译字典」**（114 定案第 5 条 / Q4），不是产品永单语言。`Easing.ts` 注释写「未来多语言只需替换这两张表」——只覆盖族/型 **展示串**，覆盖不了面板标题和模板名。

若日后做多语言，114 **会被迫重看、但本票不拍** 的点：

1. **`Sine（正弦）` 并列还是拆键**：现在是一条展示串。英/日界面是保留双语、只留 `Sine`、还是 `family`/`familyNative` 两键，要另 grill。
2. **缓动型**也是 `In（缓入）` 并列（114 实现记录：定案只写了族，型是后来对齐加上的）。
3. **模板名**纯中文（`S 形` / `心形（双弧近似）` / `不使用模板`）与族名策略可能不一致。
4. **面板 chrome**：`缓动族` / `缓动型` / `采样精度…` / `形状模板…` / `曲线配置` 不在那两张 label 表里。
5. **单测锁原文**：`CurveConfigSettings.test.ts` 断言具体中文；字典化后要么改测语言、要么改断言键。
6. **CONTEXT「缓动」术语**：界面语言变了，术语表是否双语——属 domain，不是本票。
