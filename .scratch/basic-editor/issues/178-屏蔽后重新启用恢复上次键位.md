# 178 · 屏蔽快捷键后重新启用会丢失自定义键位

Type: grilling
Status: resolved（2026-10-28 实现 + 锁测；待用户页面验收）

## 来源

2026-10-28 用户报障（issue 177 收口后实测）：把某功能改成自定义键位 → 关掉「启用」开关（屏蔽）→ 再打开，键位变回出厂默认。并追问：若屏蔽前那个键此刻已被别的功能占走，这次「启用」是否还该成功。

## 症状

1. 自定义 `切换-单键 = H` → 屏蔽 → 启用 → 回到 `F`。自定义配置被**不可逆**丢弃，且面板上没有任何"这是默认值还是我改过的"提示。
2. 若要写回的键已被占用：点开关只弹一条 toast，行保持「已屏蔽」——开关看起来是坏的。而**临时屏蔽以把键让给别的功能**正是屏蔽的主要用法，所以这条分支会经常命中。

## 根因

两层，缺一不可：

1. **数据模型没有"屏蔽前的键位"**：`ShortcutConfig = Record<FunctionId, string | null>`，屏蔽 = 把值写成 `null`，原键位就地覆盖；`loadConfig` 也只区分 `null` / `string`，存档里再没有第二份记录。
2. **启用路径硬编码出厂默认**：`setEnabled` 在启用分支取 `getDefaultConfig()[id]`，而不是"上次的键位"。

归属：`setEnabled` 主体来自 `42b2d014`（2026-08-12），**不是 issue 177 引入的回归**；且 ADR-0002 §5 当时明写「重新启用恢复默认绑定」——实现忠实于文档，本质是**文档语义与用户预期冲突**。issue 177（`d4d6c5b`）给启用侧补了冲突阻断，但没有同步 ADR 那句 → 文档（"恢复默认绑定"=总能成功）与实现（可能失败）已经不一致，本票一并收口。

## 定案（用户 2026-10-28）

- **Q1=A｜恢复上次键位**：重新启用写回**屏蔽前的键位**，不是出厂默认。存量存档里被屏蔽的项没有历史可查 → 首次启用回落出厂默认（一次性；从这版起才开始记）。不做事后追溯、不改写旧存档语义。
- **Q2=C｜冲突时就地改键**：要写回的键已被别的功能占用时，**不静默抢占、也不干留在屏蔽态** —— 直接打开快捷键记录弹窗并**预填该键**，弹窗内立刻报「已被 <功能> 占用」；用户按新组合键 + Enter 即写入并同时完成启用；Esc / 点外部取消 → 保持屏蔽。
- **Q3=保持现状**：屏蔽期间**释放**该键（别的功能可以拿走），不做"占位但停用"。

## 实现

- `ShortcutConfig.ts`：新增 `ShortcutMasks`（`FunctionId → 屏蔽前绑定串`）与三个纯函数 —— `maskFunctionBinding`（记 current 后置 `null`；已屏蔽时保留旧记录）、`bindingToRestore`（`masks[id] ?? 出厂默认`）、`pruneShortcutMasks`（只留 `cfg[id] === null` 的条目）。三者都不进 `buildBindingIndex` / `bindingTakenByOther`。
- `AppSettings.ts`：新增 `shortcutLast`（additive，不 bump `schemaVersion`）+ `normalizeShortcutMasks`（白名单 id、非空字符串、小写）；`defaultSettings` / `mergeSettings` / `updateSettings` 三层归一化。导入走 `loadSettings` 同一条路。
- `ConfigProvider.setShortcutConfig(next, shortcutLast?)`：`shortcuts` 与 `shortcutLast` **同一笔** `updateSettings` 写回；修剪不变量收在这唯一写入口（调用点不各自剪，漏一处就会复活旧键）。
- `ShortcutsPage.setEnabled`：屏蔽 = `maskFunctionBinding`；启用 = `bindingToRestore` + `setFunctionBinding`（冲突检测照旧）；撞键时不 toast，改为 `setEditing({ id, initialBinding, initialConflict })` 打开记录器。记录器新增 `initialBinding` / `initialConflict` 两个 props（预填草稿 + 预置冲突提示）。
- `docs/adr/0002` §5 + 头部修订行、`docs/adr/0003` §6 登记 `shortcutLast`。

**导入语义（有意如此）**：整包设置导入会连 `shortcutLast` 一起替换；只含 `shortcuts` 的导出不带记录 → 导入后被屏蔽项回落出厂默认。记录是"本机上一次的键位"，不跟着别人的配置走。

## 锁测

1. `tests/unit/settings/ShortcutConfig.test.ts`「屏蔽前的键位（issue 178）」5 例：记录、重复屏蔽不覆盖、`bindingToRestore` 优先记录 / 回落默认、记录不进索引与冲突检测、修剪只留屏蔽态。
2. `tests/unit/chart/config/ShortcutLastSettings.test.ts` 5 例：出厂空记录、字段级写回不 bump schema、save→load 往返、脏值（非对象 / 非字符串 / 未知 id / 空串 / 大写）逐条丢弃或归一、读写同一把尺。
3. `tests/dom/pages/ShortcutsPageConflict.test.tsx`（原 issue 177 的第 3 例已按新口径改写，未删除）：
   - 自定义 `Alt+9` → 屏蔽 → 启用 → 仍是 `Alt+9`（不是出厂 `Alt+1`）；
   - 自定义 `Alt+9` → 屏蔽 → 让给别的功能 → 启用 → 记录器打开、预填 `Alt+9`、`role="alert"` 报占用者；换空闲键确认后写入并启用、占用者不动；
   - Esc 与点外部取消两条都保持「已屏蔽」。
