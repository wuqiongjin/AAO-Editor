## 来源

## 症状

1/8 吸附下放一个音符（落在只有 1/8 才有的线上，如 1.875 拍）→ 把吸附切到 1/4 → **Shift+左键**拖这个音符：每次位移量确实是 1/4 的整数倍，但落点恒在 1.875 / 2.125 / 2.375 … 这些 **1/8 相位线**上，永远踩不到当前的 1/4 网格线。

## 根因（已定位）

`FinalVirtualCanvas.dragDelta()` 把位移算成「**光标**的吸附拍位差」：

```
dBeat = snap(cursor_now).beat − snap(cursor_press).beat      // 两者都量化到当前 beatDisplay
```

而 `planDragMove` 把 `dBeat` 加到**音符自己的拍位**上：`note.beat + dBeat`。
按下时光标吸附到 2.0（音符真实在 1.875，被量化吃掉 0.125），于是
落点 = 1.875 + k·(1/4) —— 相位偏移 `snap(按下点) − 音符真实拍位` 被永久带进落点。

> 前提事实：放置链路只写小数 `beat`、`subBeat` 恒 0（`clickOps` → `handleNoteReplacement(beat=preciseBeat, subBeat=0)`），所以 `dBeat` 直接加在 `beat` 上在数值上是安全的。

## 定案（本轮实现口径）

> 用户 2026-09-09 只报了症状（"步长对但踩不到当前网格线"）并要求修复，**未预选方案**；下面的量化口径由本轮拍板，待验收。

**量化对象 = 被拖对象的落点**，起手即吸到当前网格：

- 按下时记录锚点对象的**真实拍位** `anchorBeat`（被按中的那个音符/滑条结点的拍位；组拖 = 被按住的那一件）与按下时光标的**未量化**拍位 `rawPressBeat`。
- 拖拽中：`target = snap(rawCursorBeat − (rawPressBeat − anchorBeat))`（抓取偏移保持手感，落点量化到当前 `beatDisplay`）。
- `dBeat = target − anchorBeat`，其余成员共用同一个 `dBeat`（ADR-0008 §6 组移动：相对位移不变）。

推论（都可接受，写下来免得日后当 bug 查）：

- 音符已在当前网格上时，`grab` 偏移量化后为 0，行为与现在完全一致。
- 音符不在当前网格上时，**一起手就落到最近的当前网格线**——这正是"吸附"的含义。
- `beatDisplay` 改成 8 之类的更细网格时，1/4 的音符照常落在 1/8 线上（细网格包含粗网格）。
- lane 方向不存在该问题（`lane` 恒整数、无子划分），保持现状 `dLane = cursorLane_now − cursorLane_press`。

## 实现落点

| 文件 | 改动 |
| --- | --- |
| `src/chart/geometry/ChartGeometry.ts` | `laneBeatFromCanvas` 额外返回**未量化**的 `rawBeat`（供抓取偏移）；量化单独暴露 `quantizeBeat(beat, beatDisplay)` 纯函数 |
| `src/chart/components/canvas/FinalVirtualCanvas.tsx` | `dragRef` 增记 `anchorBeat` / `rawPressBeat`；`dragDelta` 按上面的式子出 `dBeat` |
| `src/chart/editing/NoteDragging.ts` | 不变（仍吃单一 `DragDelta`）；补注释说明"dBeat 已由画布量化到落点" |

## 验收
