# 179 · 冷启动首次播放首音符与 BGM 出声同刻卡顿

Type: bug
Status: resolved
Related: [101](./101-播放起始卡顿.md), [165](./165-首次播放卡顿.md), [167](./167-首个音符抵线卡顿.md), [chart-preview/57](../../chart-preview/issues/57-动态预览首次播放首音符入场与抵线卡顿.md)

## 来源与症状

2026-10-29 用户复报（在 [167](./167-首个音符抵线卡顿.md) 合入单瓦片预热后）：

1. **工作台谱面画布**与**动态预览（仿真场）**在首次播放时，均会在**播放到第一个音符（也是真实 BGM 声音开始响起的那一刻）**出现明显卡顿；后续再次播放则完全流畅。
2. **不是点击播放按钮后立刻卡顿**，而是走完前导空白、抵达第一个音符 / BGM 真正开始出声时才卡顿。
3. **与冷机状态及真实音频强相关**：复现时均带有真实 BGM 音频；同一天内重启软件有时不再复现，但关机后第二天首次打开软件播放时稳定复现。
4. **音画表现**：卡顿仿佛是音频与画面一起卡一下（至少卡顿结束时音频和画面保持同步，没有音画脱节）。

## 关键事实与机制分析

### 1. 为什么「首个音符抵线」与「BGM 真正开始出声」在同一时刻发生？

- BanG Dream 官方 BGM 音频普遍带有 **2～3 秒的前导静音**（为首个音符留出下落引导时间）。例如测试曲 `Frame by Frame`（BPM 210），前 10 拍为前导静音，**第 1 个音符位于 beat 10 = `2.857s`**，而 **BGM 波形从 0 幅度变为非零声音也是在 `2.857s`**。
- 因此在 `t = 2.857s` 这一刻，**三件事同时发生**：
  1. BGM 的 PCM 样本首次出现非零信号；
  2. 第一个按键打击音效（[`scheduleKeySample`](../../../src/audio/keySoundSamples.ts)）触发混音；
  3. 画面上第一个音符到达判定线（动态预览同时触发首次打击特效与 Combo 渲染，见关联票 [chart-preview/57](../../chart-preview/issues/57-动态预览首次播放首音符入场与抵线卡顿.md)）。
- **前序探针脚本误判修正**：`scripts/first-play-hitch-diag.mjs` 拦截 `decodeAudioData` 时把**第 1 个解码完的 `AudioBuffer`** 当作 BGM 计算 `onsetSec`。但实测日志 `shots/first-play-hitch-diag.json` 显示前 6 个解码完的是短打击音效（时长 `0.74s～1.30s`），**第 7 个（时长 `111.428s`）才是 BGM**。因此前序报告记录的 `onsetSec = 0.005s` 实为打击音效起点，掩盖了 BGM 真正出声时刻与首音符抵线时刻重合的事实。

### 2. 为什么卡顿结束后音频和画面仍然同步？

- 在 [`AudioEngine.getSeconds()`](../../../src/audio/AudioEngine.ts) 中，有 BGM 时（`this.clock === 'audio'`），播放位置完全从属于 WebAudio 硬件时钟：
  `offsetSeconds + (ctx.currentTime - startCtxSecond) * rate`。
- 工作台（[`usePlaybackCoordinator.ts`](../../../src/playback/usePlaybackCoordinator.ts)）与动态预览（[`simPlayback.ts`](../../../src/preview/video/sim/simPlayback.ts)）每帧均直接读取 `engine.getSeconds()` 定位画面。
- 因此：
  - 若**音频线程 / 系统音频管线瞬时停滞**（`ctx.currentTime` 停顿），画面读取到的秒数也停在原地，恢复后两者天然同步；
  - 若**主线程在首音符帧同步阻塞**了 $N\text{ ms}$，恢复后的下一帧立刻读取最新的 `ctx.currentTime` 一步跳到对应位置，卡顿结束后音画同样保持同步。

## 根因拆解

本问题是「动态预览独有的首音符三重同步懒初始化（见 [chart-preview/57](../../chart-preview/issues/57-动态预览首次播放首音符入场与抵线卡顿.md)）」与「工作台及音频层共有的冷启动盲区（本票）」在首音符时刻的交汇：

### 根因 A：音频管线与系统音频冷态（工作台 & 动态预览共有）

1. **WebAudio 音效混音分支在 `t = 0` 未激活，推迟到首音符前 `0.12s` 才首次建图混音**：
   - [`AudioEngine.play()`](../../../src/audio/AudioEngine.ts) 在 `t = 0` 只启动了 `bgmSource -> bgmGain -> destination` 一路节点，且前 2.85 秒输出全为 `0.0` 静音样本；此时 `seGain`（打击音效总线）上没有任何活动输入源。
   - 直到距离首个音符 `LOOKAHEAD_SEC = 0.12s`（[`KeySound.ts`](../../../src/audio/KeySound.ts)）及抵线时刻，[`scheduleKeySample`](../../../src/audio/keySoundSamples.ts) 才首次创建 `AudioBufferSourceNode` + `GainNode` 并接入 `seGain`。
2. **冷机 PCM 内存缺页中断（Page Faults）与 Windows 音频栈首次非零唤醒**：
   - 一首 2 分钟 48kHz 双声道 BGM 解码后占约 `45 MB` 连续 Float32 PCM 内存，各打击音效样本（`note_normal` / `note_flick` / `note_long` 等）另有数 MB PCM 缓冲。
   - 在隔夜关机重启后的冷机状态下，Windows 音频图进程（`audiodg.exe` / WASAPI 混音与驱动 APO 管线）在收到**第一帧非零音频样本**前处于节能/旁路态，且 Chromium 音频渲染线程首次读取非零 BGM 区段与各打击音效 `AudioBuffer` 时会集中触发物理内存缺页（Hard/Soft Page Faults）。
   - 同一天内仅重启软件时，OS Standby 文件缓存与 `audiodg.exe` 已经热化，因此难以复现。

### 根因 B：工作台画布瓦片与材质预热的 3 个残留缺口（[167](./167-首个音符抵线卡顿.md) 未覆盖项）

1. **`firstNonEmptyTileIdOf` 仅预热单个瓦片 `firstTile`，漏掉紧邻的 `firstTile + 1`**：
   - [`noteLayerCache.ts`](../../../src/rendering/pipeline/noteLayerCache.ts) 在暂停态只将 `firstTile` 一个瓦片推入 `idleQueue`。
   - 但播放滚到首个音符附近时，[`enqueuePlayingTiles`](../../../src/rendering/pipeline/noteLayerCache.ts) 会立即请求 `[lo, hi + 2]`。若首个音符位于 `firstTile` 上半部，或紧随其后的 `firstTile + 1` 含密集音符，首音符进入视口时仍会在播放帧中触发 `buildTile(firstTile + 1)`（冷态耗时 15～30ms）。
2. **`bandStripStyle` 首次遇到含 `hidden` 节点的 SP 滑条时同步执行 `getImageData` 读回**：
   - 在 [`render.ts`](../../../src/rendering/render.ts) 中，当整场第一次渲染含 `hidden` 节点的滑条连接带（`renderSpBandStrip`）时，`bandStripStyle` 会同步创建离屏 Canvas、`drawImage` 并调用 **`cx.getImageData(0, 0, w, h)`**（强制 GPU $\rightarrow$ CPU 同步像素读回）以填充 `STRIP_STYLE_CACHE`。若该瓦片在播放途中才构建，这次同步读回会直接阻塞主线程。
3. **`CanvasSpriteIcon` 的 Mipmap 链只按当前请求层级惰性构建**：
   - [`CanvasSpriteIcon.getMipLevelSource`](../../../src/ui/CanvasSpriteIcon.tsx) 仅在请求到某一级 `level` 时才同步创建离屏 Canvas 并做 `imageSmoothingQuality = 'high'` 缩放。若播放中首次遇到更小绘制尺寸的精灵（或动态预览首次绘制远端音符），会在动画帧内同步补建深层 Mipmap。

## 修复方案

1. **音频管线与 PCM 缓冲预热（[`AudioEngine.ts`](../../../src/audio/AudioEngine.ts) / [`keySoundSamples.ts`](../../../src/audio/keySoundSamples.ts)）**：
   - 在音频与打击音效解码完成后，调用 `touchAudioBuffer` 对 `AudioBuffer` 各声道 `getChannelData(ch)` 做一次跨页步进读取（每 1024 个 float32 采样点即 4KB 页步长读取累加），提前触发物理内存页提交，消除播放途中的冷缺页中断。
   - 在 `AudioEngine.play()` 首次启动瞬间调用 `primeAudioGraph`，向 `seBus()`（`seGain -> masterGain -> destination`）挂载一个 64 帧、幅值 `1e-6`（$-120\text{ dBFS}$，人耳不可闻但非 `0.0`）的预热缓冲脉冲，使键音混音分支与 OS 音频驱动在点击播放的 `t = 0` 即刻完成唤醒，不再拖延到 `2.857s` 首音符抵线时刻。
   - `AudioEngine.setKeySetId(id)` 对同 `id` 幂等化（已挂载或同 `id` 正在加载时不重复将 `keySet` 置回 `null`），并新增 `AudioEngine.dispose()` 释放节点与底层 `AudioContext`。
2. **工作台瓦片与材质预热补齐（[`noteLayerCache.ts`](../../../src/rendering/pipeline/noteLayerCache.ts) / [`render.ts`](../../../src/rendering/render.ts) / [`FinalVirtualCanvas.tsx`](../../../src/chart/components/canvas/FinalVirtualCanvas.tsx) / [`CanvasSpriteIcon.tsx`](../../../src/ui/CanvasSpriteIcon.tsx)）**：
   - 扩展 `noteLayerCache.ts` 的静止期预热：视口上方预热对齐播放期的 `[lo, hi + 2]`，并将全谱首个实体音符预热从单块 `firstTile` 扩展为连续窗口 `[firstTile, firstTile + 2]`。
   - 在 `CanvasSpriteIcon` 加载图片完成时（`loadImage`）经 `img.decode?.()` 后调用 `CanvasSpriteIcon.warmupImageMips` 预建 `1..PREWARM_MIP_LEVEL (5)` 级减半位图链；在 `FinalVirtualCanvas` 皮肤加载完成时调用 `warmupBandStripStyles(noteIcons)`（复用 `CanvasSpriteIcon.getCachedImage`）提前填充 `STRIP_STYLE_CACHE`，确保播放帧内零 `getImageData` 读回、零 Mipmap 离屏 Canvas 新建。
3. **动态预览专属预热与生命周期修复**：
   - 见关联票 [chart-preview/57](../../chart-preview/issues/57-动态预览首次播放首音符入场与抵线卡顿.md)。

## 锁测

- **单元与性能测试**：
  - `tests/perf/RendererPerf.test.ts`：验证长前导空白谱面在静止期自动将视口上方 `[lo, hi + 2]` 与首音符连续窗口 `[firstTile, firstTile + 2]` 加入预热队列并建好。
  - `tests/unit/ui/CanvasSpriteIcon.test.ts`：验证 `CanvasSpriteIcon.warmupImageMips` 一次性预建 `1..5` 级 Mipmap 位图且渲染热路径零新建离屏 Canvas。
  - `tests/unit/rendering/render/SlideBandGeometry.test.ts`：验证 `warmupBandStripStyles` 复用已缓存贴图完成预采样且后续调用命中 `STRIP_STYLE_CACHE` 零 `getImageData` 回读。
  - `tests/unit/audio/AudioEnginePlaybackRate.test.ts`：验证 `load()` 解码后调用 `touchAudioBuffer` 预触碰各声道 PCM 页、首次 `play()` 执行 `primeAudioGraph` 微脉冲预热且不干扰 BGM `source`、`setKeySetId` 同 `id` 幂等、以及 `dispose()` 关闭底层 `AudioContext`。
