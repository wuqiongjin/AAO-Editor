## 根因与背景（现状事实，结论而非调研）

- **已有完整快捷键系统**：`src/settings/ShortcutConfig.ts` 的 `FUNCTIONS` 是唯一默认键表；`src/pages/settings/ShortcutsPage.tsx` 提供改键 / 屏蔽 / 恢复默认 / 冲突弹窗（`setFunctionBinding` 撞键拒绝且弹窗不关）。配置是整份全量快照存 `aao.settings.v1`（`AppSettings.ts:457,753`），`schemaVersion` 恒 1、additive 不 bump；**没有「用户显式改过 vs 从未改过」的元数据**。
- **倍速 / 音量零快捷键**：倍速是模块级内存态、明确不落设置（[chart-preview/59](../../chart-preview/issues/59-倍速数值的保存与共用口径.md)），预设 7 档 `[0.25,0.5,0.75,1,1.25,1.5,2]`、范围 `0.1..4`；音量 60 落地后单点 `settings.audio.volume`、滑条 `step=0.05`、clamp `[0,1]`，**无独立静音态**（`muted` 只是 `volume<=0` 的派生显示）。
- **冲突现状分三层**：(i) 用户主动改键撞车 —— 已解决；(iii) 一键多功能 —— 已定案「重复即拒绝」；(ii) **升级时新增内置默认键撞用户既有绑定 —— 未解决**：`dedupeBindings`（`ShortcutConfig.ts:227-236`）按 `FUNCTIONS` **表序**保留第一个、把靠后的静默置 `null`，跨作用域全表算，**不认识谁是新增、谁是用户改的**，只靠 `FUNCTIONS:104` 注释里「新功能追加表尾」的手工默契规避。
- **既有原则**：缩放 / seek 明确不纳入快捷键系统（ADR-0002 §2.2）；[216](./216-节拍吸附快捷键切换与常用档位循环.md) 是「完整度」对标对象，其齿轮弹窗是**自定义循环档位**用的，不是快捷键本身；它没有 toast / OSD，反馈只靠常显的 `1/N` 读数。
- **可复用**：`category: 'play'` 已映射到 `playback` 索引桶（`shortcutIndexFilter.ts:43`），`categoryShortcuts` 只在 `WorkspaceToolRail` 用于工具类别 → 新功能用这个 category 既不用加桶映射、也不会污染 tooltip。预览页 `PLAY_ONLY = ['play']`（`PreviewVideoStage.tsx:37`）是「其余 canvas 绑定放行原生」的白名单。
- **性能基线**：`useShortcutDispatch.ts:35-49` / `AppShell.tsx:81-90` **都不过滤 `e.repeat`**（全仓仅 `Dialog.tsx:70` 的 Esc 有）；音量滑条 `PlayBar.tsx:232` 每个 `step` 就直接写一次 settings、无节流，全量程 21 档，是「播放中连续多次写」的既有行为且无卡顿观测记录。issue 207 曾记录「配置写入 → 全树广播 → 播放中约 100ms 冻结」，已由 `React.memo(PageSlot)` + `InactiveConfigBoundary` 修掉。

## 定案（用户 2026-11-11 逐轮拍板，7 轮 frontier 为空）

### 1. 做不做 / 做到什么程度

- **两个都做**（倍速 + 音量），定位为「播放控制补齐」而非 Bestdori 功能对标；在 ADR-0002 写清选键边界：只给「作用于播放态、可逆、结果即时可见」的动作配键，编辑 / 布局类仍不配键。
- 完整度 = **(a)+(d)**：(a) 只进注册表 + 复用现成的改键 / 屏蔽 / 恢复默认 / 冲突弹窗；(d) ADR 修订 + i18n + 三层锁测。**不做 (b)** 专门配置弹窗（自定义倍速档位 / 音量步长）、**不做 (c)** toast / OSD；反馈只靠播放条常显的 `1×` 读数与音量滑条位置。即「系统级完整、产品级最小」，**零新增 UI**（快捷键页只多 4 行）。

### 2. 四个功能与默认键位

| FunctionId | 默认键 | 动作 |
| --- | --- | --- |
| `rateDown` | `,` | 倍速降一档 |
| `rateUp` | `.` | 倍速升一档 |
| `volumeDown` | `;` | 音量 −0.05 |
| `volumeUp` | `'` | 音量 +0.05 |

- **对齐 Bestdori 键位**（用户提供的口径；仓库与公开资料均无 Bestdori 快捷键表可查）。四键在 `FUNCTIONS` 里全部空闲、与出厂默认表零冲突，均为裸键。
- `category: 'play'`、`scope: 'canvas'`（缺省）。
- **只做 4 个**：不做 `rateCycle`（7 档不像吸附 12 档需要循环）、不做 `rateReset`（播放条点 `1×` 预设即可）、不做 `mute`（会牵出新状态与 schema 争议）。
- 语义：倍速按现有 7 档预设跳、**端点停住**、快捷键封顶 `2×`（>2× 仍靠手填）；音量每次 `0.05`、clamp `[0,1]`、**端点停住**。
- 选键原则写进 ADR：新增默认键必须避开既有出厂默认表；`,`/`.` 已被倍速占用，将来若做逐帧 / 逐拍 seek 须另选键。已知代价：这几个符号键布局相关（部分欧式键盘 `[`/`]` 类符号需 AltGr 会变成 `ctrl+alt+…`），先按仓库现有 `` ` `` 裸键同等标准处理，不引入 `e.code` 映射，真出问题单独开票。

### 3. 作用域与反馈

- 工作台与**动态预览页都能用**：把 4 个 id 加进预览页 `PLAY_ONLY` 并在其 `runFunction` 加 `case`（状态本来就同源，按了没反应会被当成坏掉）。不改 `scope: 'app'`（那是切页键的，且冲突检测本就跨作用域全表算）。
- 焦点在输入控件时由 `isEditableTarget` 放行原生输入；录制快捷键期间由 `isCapturingShortcut` 放行。
- **按住不连发**：给 `useShortcutDispatch` 加 `noRepeat?: readonly FunctionId[]` 选项，只列这 4 个 id，过滤 `e.repeat`（一次按下只调一次）。其它快捷键（含空格播放）的连发行为保持原样，不在这个需求里顺手改。理由：倍速只有 7 档，按住一瞬间就冲到底；不加这个过滤，键盘自动连发约 30 次/秒会把引擎与 React 成本放大 30 倍。

### 4. 冲突（本轮唯一真正的新机制）

- **范围**：只处理 (ii)「升级时新增内置默认键撞用户既有绑定」；(i)(iii) 已有定案，不重开。
- **推翻**先前「新功能一律出厂 `binding: null`」的想法：肯定要给这 4 个功能**出厂默认键**，不能让以后所有新功能都未绑定、开箱不可用。
- **长期契约**：用户设置永远优先 —— 新增内置默认绝不抢占用户已占用的键；冲突时让**新功能退让为 `null`**（用户自己去快捷键页绑定）。
- **判定口径 B**：加载时以用户快照 `parsed.shortcuts` 的 **key 集合**把功能分成两拨 —— 快照里**出现过**的 id = 老功能，没出现过的 = 本次新增（其键必然来自出厂默认）。键位撞车时**老功能保住键，新增功能置 `null`**，**不看用户改没改过**（值恰好等于出厂默认也算老功能）。无需 diff 元数据、无需 bump `schemaVersion`。
  - 反面口径 A（只有值 ≠ 出厂默认才算「用户改过」）否决：会让「从没动过快捷键的用户」在升级后凭空丢键，且系统本来就分不清「改过没有」（`SUPERSEDED_DEFAULTS` 注释自承）。
  - 把 `dedupeBindings` 从「表序优先」改成上述规则，是**本需求的实现前置，同一张票里做**，不是单独不排期的票。
- **两个同时新增的默认键互撞**：不许留到运行时 —— 用 `getDefaultConfig()` 上的 `buildBindingIndex(cfg).size === boundCountOf(cfg)` 单测（`ShortcutConfig.test.ts:45` 已有同款）在开发期锁死；加载逻辑只处理「新 vs 老」。
- **退让之后**：静默、**一次性永久 `null`**（去重结果在下次任意 `commit` 整份写回时固化）、不自动恢复、不引入「因冲突退让」元数据。**撤回**「快捷键页该行常显冲突说明」：现有 `ShortcutsPage.tsx:181-193` 的启用路径已经够用 —— 点「启用」→ `bindingToRestore` 回落出厂默认键 → `setFunctionBinding` 撞车 → 打开录制弹窗**预填该键并显示冲突文案**、弹窗不关、草稿保留，当场就能改绑。受影响用户靠自己逛快捷键页或看文档发现，接受此代价。
- `dedupeBindings` 的静默改写视为**待修行为**，不是可依赖的既定策略；「修表序优先 ≠ 用户优先」的契约写进 ADR-0002。

### 5. 性能 / 文档 / 排期

- **不加限速、不改音频引擎、不新建测帧率工具**：音量滑条拖动已是同等或更高写入频率的既有行为且无问题记录；`setPlaybackRate` 的 `rewindKeyIndex()` O(n) 全谱扫描与预览页整帧 `render()` 也已被「播放条点预设 / 输入框按住 ↑↓」打到。R4 的 `e.repeat` 过滤之后，快捷键最快不超过人手点击。真掉帧了再单独开票重构。
- `tests/perf/` 只断言 CPU 预算 / 调用次数，无浏览器帧率 / longtask 基建；播放中连敲 / 长按是否掉帧走**人工验收清单**（复用票 60 的 Playwright 手工清单），不做 e2e、不引入 `PerformanceObserver`。
- **文档**：ADR-0002 头部加一条修订（4 个新 `FunctionId` + 出厂默认键 + 载入去重规则 + 选键原则 + `play → playback` 桶复用）；`docs-site/guide/features.md:69-76` 与 `README.md:65` 键位表补四键；`src/i18n/messages/` 加 4 个功能名。**不改** `CONTEXT.md:249` 的倍速「不落设置」口径（倍速照旧刷新回 `1×`，音量照旧跨重启记住）。
- **依赖**：票 60 已 resolved，本票无前置；用户要求**先跟踪、暂不写代码**。

## 锁测

1. **unit（`tests/unit/settings/ShortcutConfig.test.ts` 及新文件）**：
   - `getDefaultConfig()` 零冲突：`buildBindingIndex(cfg).size === boundCountOf(cfg)`（锁住「两个同时新增互撞」在开发期即失败）。
   - 载入两种场景：老快照**不含**这 4 个 id → 四键按默认生效；老快照里某个已存在功能占着 `,` / `.` / `;` / `'` 之一（含值恰好等于出厂默认的情形）→ 该功能保键、对应新功能为 `null`。
   - 用户**主动屏蔽**的功能不受新规则影响；`repairStaleBindings` 两条特例不回退。
   - 倍速预设档步进：从 `1×` 升到 `2×` 后端点停住、从 `0.25×` 降档端点停住；音量 `0`/`1` 端点停住。
2. **dom**：工作台 4 键分发（`useShortcutDispatch`）、预览页 `PLAY_ONLY` 生效、输入框焦点放行、录制态放行、启用撞键弹窗（预填键 + 冲突文案）、**`e.repeat: true` 不触发**（锁住「按住不连发」）。
3. **static**：`WorkspacePage` / `PreviewVideoStage` 的 `case` 接线、`noRepeat` 传入（照 `EditorAudioSessionRefactor.test.ts` 惯例）。
4. **人工验收（单测盖不到的部分）**：播放中连敲 / 长按 4 键观察是否掉帧；工作台与动态预览页按键均生效；老存档升级后默认键生效 / 撞键时新功能未绑定且点「启用」能看到占用者；跨页 / 跨重启音量一致（复用票 60 清单）。理由：DOM 时序、浏览器帧率与 localStorage 时序在 jsdom / node 侧测不到，仓库没有 e2e 与 FPS 断言基建。
5. **不做**：FPS / longtask 断言、`PerformanceObserver`、e2e。
