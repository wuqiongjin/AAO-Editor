## 来源

issue 09 验收收口后追加需求 #2（2026-09-15 用户提出）："画笔绘制时（还没结束绘制），Esc 应该取消当前绘制行为（包括已画过的轨迹）。当前 Esc 是直接切回到鼠标工具了。除了画笔，还应支持其它操作过程中的 Esc 取消——如双击放置 Slide 只放了 1 个时、拖拽过程中。" 本票管**统一的取消机制**，跨工具、跨手势。

## 症状（代码级根因，2026-09-15 盘点）

1. **Esc 根本没挂钩"进行中的指针手势"**：现有四档链（① 弹窗 → ② 锚点 → ③ 清选区 → ④ 落指针）只覆盖锚点/选区/工具态三类 state；手势 ref 散在 `FinalVirtualCanvas` 十余处（`dragRef` / `penRef` / `selectionBox` / `marqueeCursorRef` / `rightButtonHeld` / `selectionStartRef`），**没有统一状态机**，`cancelPendingSlide` 只认 `slideBuffer` / `curveDraft` 两个 state。
2. **画笔中按 Esc = 越修越坏**：无锚点时落到④档，`armedTool !== 'curve'` 的副作用（`FinalVirtualCanvas.tsx:1053-1063`）顺带清掉 `penRef`（等于误伤取消整个工具），但**不调 `cancelPenVisual()`** → 画笔光标残留；后续 mousemove 因 `penRef===null` 落到框选分支，而 `canStartMarquee(null)===true` → **这一笔变成框选**，松手 `commitBox` 真的建立选区。`PEN_HOLD_MS` 定时器也没清。
3. **拖拽 / 拖带弯曲 / 框选中按 Esc = 完全不取消**：拖拽走③清选区后 return，`dragRef`/`dragGhost` 全在，松手照常 `commitDrag`（用户感受＝"Esc 没用"）；框选矩形照常结算；右键按住删除预览不受影响。
4. Esc 硬编码在 `useShortcutDispatch.ts:34-37`，不在注册表 → 不可改键、不可屏蔽、不出现在设置页。

## 定案（用户 2026-09-16，两轮逐条拍板）

- **五档链（ADR-0008 §7 改写）**：**① 弹窗自消费（capture）→ ② 进行中手势 → ③ 取消 Slide/曲线锚点 → ④ 清空选区 → ⑤ 持工具态落回指针**。
- **一次 Esc 只取消一层**：有进行中手势就只取消手势（锚点、选区、工具态一律不动），再按才轮到锚点。
- **② 档 = `cancelActiveGesture()`**：清 `dragRef` / `dragGhost` / `dragFrozenRef` / `penRef` / `penPreview` / `penActive`+光标（`cancelPenVisual()`）/ `penHoldTimerRef` / `marqueeCursorRef` / `selectionBox` / `rightButtonHeld` / `selectionStartRef`，并 `detachWindowGesture()`。
- **取消后保持工具态**（Q8=甲）：取消画笔 = 作废这一笔、仍留在曲线工具；取消拖拽 = 音符回原位、工具不变。**Esc 的语义是"撤销这次操作"，不是"退出工具"**。
- **取消后保留选区**（Q9=甲）：手势进行中 Esc 不再顺带清选区；无手势时才走④。
- **作废到 mouseup**（B1=甲）：置 `gestureCancelledRef`，期间 mousemove/mouseup 全部短路（不重新起笔、不变框选、不提交），松手只清标志。**这一条不落地就会出现"取消后手势变形"的老 bug**（同症状 2）。
- **Esc 保持硬编码、不进注册表**（Q10=甲）：取消是安全底线，不可改键、不可屏蔽；ADR-0002 显式记此例外。
- 取消清单覆盖：画笔 / 拖拽移动 / 拖带弯曲 / 框选矩形 / 右键删除预览 / BPM 就地编辑（已有）。

## 实现落点

1. `FinalVirtualCanvas.tsx`：imperative handle 新增 `cancelActiveGesture(): boolean`（有进行中手势才返回 `true`）；新增 `gestureCancelledRef`，在 `handlePointerMove` / `handlePointerUp` 顶部短路；`handleMouseDown` 与 mouseup 清标志。画笔取消必须连带 `cancelPenVisual()` + `clearTimeout(penHoldTimerRef)`。
2. `Editor.tsx` `onEscape`：在 `cancelPendingSlide` **之前**插入新档 `virtualCanvasRef.current?.cancelActiveGesture?.()`。
3. 纯函数层（便于单测）：`CanvasGesture.ts` 新增 `resolveEscapeTarget(snap)`（输入 `{ pen, drag, box, rightHeld, anchor, selection, armedTool }` → `'gesture' | 'anchor' | 'selection' | 'tool' | null`），组件只做执行。
4. 文档：ADR-0008 §7（四档 → 五档，含本次定案）、ADR-0002（Esc 不可配置例外）、`CONTEXT.md`（新增 `进行中手势`）。

## 锁测

- **单测 `CanvasGesture.test.ts`（`resolveEscapeTarget`）**：有画笔 → `gesture`；有拖拽 → `gesture`；有框选矩形 → `gesture`；仅右键删除预览 → `gesture`；**无手势但有锚点** → `anchor`；无手势无锚点有选区 → `selection`；三者皆无但有持工具态 → `tool`；全无 → `null`（一次只吐一档，逐档组合锁表）。
- **Playwright 实测（`scripts/` 脚手架）**：
  1. 画笔绘制中 Esc → **无落子**（notes 数不变）、仍在曲线工具态、光标复原、继续移动不起笔不框选、松手无事发生；
  2. 拖拽中 Esc → 音符拍位/lane 完全回原位、选区仍在、继续移动不再拖、松手无提交；
  3. 框选中 Esc → 无新选区、不执行批量动作；
  4. 两击放置首击后 Esc → 锚点清（既有行为不回归）；
  5. 无手势时 Esc → 仍走 ③④⑤（清选区 / 落指针）。
- **手工验收**：画笔"下→上→下"画到一半按 Esc，页面无任何残留绿像素、`pageerror=0`；拖 SP 带捏到一半 Esc，形状与数据均回到按下前。

### 实现与评审记录（2026-09-16）

- **已实现**（commit `44d5c08`，4 文件 +123/−10）：`resolveEscapeTarget`（档位唯一裁决，一次只吐一档）+ 画布 `cancelActiveGesture`（清画笔/拖拽/拖带/框选/右键删除预览 + `cancelPenVisual` + 光标复位 + `detachWindowGesture`）+ `gestureCancelledRef`（move/up 短路）+ `Editor.onEscape` 插为第②档。
- **口径细化（票正文未写，实现时确定）**：`box` 判据 = **按下后未抬起**（含框选矩形与单击起手），不止"有矩形" —— 否则未过阈值的按下会落到第⑤档把工具态退掉，正是用户报的"Esc 直接切回鼠标工具"。
- **`/code-review` 后修的**：`gestureCancelledRef` 的重置从"左键分支内"移到 `handleMouseDown` **最前** —— `detachWindowGesture()` 之后 window 的 mouseup 不再触发，若用户取消后先按右键（右键分支会提前 return）再按左键，旧位置会让标志残留。
- 验证：`tsc` 0 / **1108 测全绿**；页面实测待用户手工验收（清单见「锁测」）。
- 与 108（捏形）无依赖；108 落地后本票的"取消拖拽/取消拖带"同样生效（同一条 `dragRef` 路径）。
- **验收回归 #1（2026-09-16，用户报）**：SP 绘制中按 Esc → 界面"卡住"——实时显示线停在 Esc 那一刻、光标放置幽灵全不显示，要再点一下才恢复。
  **根因**：`gestureCancelledRef` 的短路写在了 `handlePointerMove` **函数顶部**，把 hover 反馈（`setHoverPos` / 放置幽灵 / hover 描边）一起冻住；而取消态按设计要活到下一次 `mousedown` 才清 → 于是"卡到下次点击"。
  **修法**：短路下移到 `if (!selectionStartRef.current) return;` **之后**（hover 更新完之后才短路）。语义不变——只作废手势、不动 hover。
  **教训（写给未来）**："取消手势"绝不能写成整个 pointer 处理器的早退；hover 反馈与手势是两件事，短路点必须落在两者的分界线之后。
