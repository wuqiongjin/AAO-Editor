## Question（bug 34）

切换音频素材（重新导入/更换音频文件）后，对应的"谱面时长"不能及时更新，**残留上一次音频的时长**。

## 根因

`src/pages/Editor.tsx` 里"有音频 = 用音频时长覆盖谱面时长"的 effect 依赖 `canPlay`：

```
useEffect(() => {
  const audioDuration = engine?.duration;
  if (audioDuration != null) { setCtxDuration(audioDuration); ... }
}, [canPlay, setCtxDuration]);
```

首次导入时 `canPlay` false→true 触发更新；但**换音频时 `canPlay` 已是 true，`setCanPlay(true)` 不产生状态变化**，effect 不重跑 → 新音频 `buffer.duration` 未写回谱面时长，残留旧时长。

## 期望

- 更换音频后谱面时长立即更新为**新音频时长**。

## 方案

把该 effect 依赖补上 `audioName`（换音频必然 `setAudioName(file.name)` 触发 anew；`clearAudio` 置 null 时 `engine.duration` 为 null、不改时长，语义不变），并在 `importAudio` 成功回调里直接按 `engine.duration` 写回 `setCtxDuration`/`durationRef.current` 兜底。

## 验证

- 浏览器：先后导入两段不同时长的音频，谱面时长显示随新音频更新，无残留。
- `tsc -b` 通过。

## Answer

**resolved**。`src/pages/Editor.tsx`：①"有音频=用音频时长覆盖谱面时长"的 effect 依赖补 `audioName`（换音频必然触发 `setAudioName` 状态变化；清除时 `engine.duration` 为 null 不改时长，语义不变）；②`importAudio` 成功回调内按 `engine.duration` 直接 `setCtxDuration`/`durationRef.current` 兜底。换音频时 `canPlay` 已 true 不再导致 effect 不重跑，谱面时长随即更新为新音频时长。`tsc -b`、vitest 161 通过。
