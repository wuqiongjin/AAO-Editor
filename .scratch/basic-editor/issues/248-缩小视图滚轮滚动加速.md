# 248 · 缩小视图滚轮滚动加速

Type: feature
Status: resolved（2026-11-21 用户确认只做本条；已实现并锁测，待页面验收）

## 来源

用户 2026-11-21 提出四点问题，其中第 3 点「缩小滚动时加快速度，提高大量选中时的导航速度」经分析确认可实现；第 4 点「持续缩放时加速缩放」与第 3 点是不同物理量（前者是 `scrollTop`，后者是 `scale`），等比步长本身已是对数域匀速，再加速会依赖滚动频率、易过冲并与判定线锚点/0.1–3.0 钳制冲突，**用户确认不做**。

## 症状与根因

- 画布只有一个原生 wheel 监听器（`passive:false`）。Ctrl+滚轮走缩放；普通滚轮原本完全交给父容器原生滚动，`Shift+滚轮` 与 `invertWheel` 分支都是 `scrollTop ± 原始 delta`，系数恒为 1。
- `scrollTop → scrollY` 按谱面实际范围线性映射，但可滚 DOM 范围含 `h(1/es - 1)` 空白；视觉位移 ≈ DOM 像素 × 生效缩放 `es`，所以缩得越小，每格滚轮的画面推进量越小，感觉「滚不动」。不是显式限速，而是映射副作用。

## 本轮实现口径（待验收，非 ADR 定案）

- 新增纯函数模块 `src/chart/components/canvas/wheelScroll.ts`：`wheelScrollBoost(es) = clamp(1/es, 1, 4)`；非法/零缩放退化为 1，上限 4 防止最小缩放一格跳过整屏。不新增设置项。
- `FinalVirtualCanvas.handleWheel`：普通滚轮与 `Shift+滚轮` 的位移乘 boost；`invertWheel` 只翻方向、不改倍率；`deltaMode` 行/页折算成像素。
- Ctrl+滚轮缩放分支完全不动；缩放 ≥ 1 且非 Shift、非反转时仍走父容器原生滚动；`deltaY === 0` 的横向手势不拦截。
- 不改 `PlaybackScrollModel` 的映射本身，只改每事件推进量，seek / RAF 共用口径不受影响。

## 锁测

- 新增 `tests/unit/chart/canvas/WheelScrollBoost.test.ts`（3 例）：1×/2× 不加速，0.5×→2、0.25×→4、0.1×→封顶 4；非法/零缩放退化；`deltaMode` 行/页折算。
- 更新 `tests/unit/chart/canvas/CanvasWheelInvert.test.ts`（5 例）：保留 `invertWheel` 反转语义锁定，新增 Shift/普通滚轮按 boost、默认原生滚动的静态源码断言；Ctrl 缩放优先顺序不变。
- `npx tsc -b` 通过；上述 8 例 + `PlaybackScrollModel` / `PlaybackDomScrollThrottling` / `CanvasZoomWriteback` 共 33 例回归通过。全量 `vitest` 在本环境多 worker 未跑完，**不声称全量通过**。
- 单测覆盖不到的手感差异（原生滚动被手动赋值替代、触控板惯性）需页面验收：100% 缩放保持原手感；50% 约 2 倍、25% 约 4 倍；`invertWheel` 仍反向；Ctrl+滚轮缩放与判定线锚点不变；Shift+滚轮仍纵向。
