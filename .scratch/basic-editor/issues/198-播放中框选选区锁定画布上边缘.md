# 198 · 播放中框选选区锁定画布上边缘

Type: bug
Status: resolved
Blocked by:

## 来源

用户实测反馈：在播放过程中，如果使用框选功能，鼠标一旦开始移动，此时框选的两个顶点必定会瞬间锁定到画布的上边缘，观感非常奇怪。

## 症状

1. **选框上边缘瞬间吸顶**：在谱面播放过程中（谱面正向上滚动），按住鼠标左键（或右键）移动超过 8px 触发框选时，选框的上边缘（左上角与右上角两个顶点）必定瞬间固定死锁在画布顶边（`y = 0`），而下边缘跟随着鼠标光标移动。
2. **长条形失真**：由于顶边锁死在画布顶部，选框从光标位置一直延伸贯穿到屏幕顶端，无法正常圈选光标邻近区域的音符。
3. **松手结算严重污染**：松手完成框选时，`commitBox` 反解出的选区覆盖了过去数秒内走过的所有历史音符（范围扩大数千像素）。
4. **原地按住无法随谱延伸**：在播放中按住鼠标不移动时，选框不会随谱面滚动而实时拉伸延展。

## 根因

1. **播放双轨视口设计导致状态脱节**：
   - 为保障播放时 60 FPS 流畅度并规避 React 频繁重渲带来的音频卡顿，`usePlaybackCoordinator` 驱动的 RAF 循环直接更新 `scrollYRef.current` 并命令式调用 `renderCanvasRef.current()`，刻意绕过了 React 的 `setViewport`。
   - 这使得 React 状态 `viewport`（尤其是 `viewport.scrollY`）在整个播放期间一直停留在播放开始前的初始值（例如 `20000`）。
2. **`session.bindWorld` 注入了陈旧视口**：
   - `FinalVirtualCanvas.tsx` 在第 448 行 `session.bindWorld` 中传入的是陈旧停滞的 React 状态 `viewport`，而非反映实时滚动的 `liveViewport()`（即 `{ ...viewport, scrollY: scrollYRef.current }`）。
   - 同时，`session.onViewportChange` 仅挂载在 `[viewport, geometry, surf]` 的 React `useEffect` 上，播放期间由于 React `viewport` 不变，该 effect 从未执行；`setScrollY` 在每帧更新 `scrollYRef.current` 时也未通知手势内核。手势会话内核 `GestureSession` 内部记录的视口在整个播放期间完全不知道视口已经向前滚动。
3. **起点物理量与重算反解的视口基准分裂**：
   - 鼠标按下时（`handleMouseDown`），通过调用了 `liveViewport()` 的 `canvasToVirtual` 算得起点的真实虚拟坐标 $vy = pos.y / es + scrollYRef$（如 $500 + 15000 = 15500$），并存入 `this.start.pos`。
   - 鼠标移动超过 8px 时，`session.move` 调用 `marqueeRect`，传入的却是内核持有的陈旧视口 `w.viewport`（`scrollY = 20000`）。
   - 在 `marqueeRect` 内部反解起点画布像素 Y 坐标：
     $$p_1.y = (vy - w.viewport.scrollY) \times es = (15500 - 20000) \times es = -4500 \ll 0$$
     下落式谱面播放中 `scrollY` 单调减小，导致计算出的起点像素坐标 $p_1.y$ 必然为巨大负数。
4. **Canvas 裁切造成吸顶视觉假象**：
   - `renderSelectionBox` 中以 $minY = Math.min(p_1.y, p_2.y) = -4500$、$maxY = p_2.y$（鼠标位置，如 510）绘制矩形。
   - Canvas 可见视口为 $[0, surface.h]$，超出 $y < 0$ 的部分被视口上边缘自然截断，视觉上直接表现为选框两个上顶点死死锁在画布上边缘（$y = 0$）。

## 修法

1. **统一手势视口真相源**：
   - 在 `FinalVirtualCanvas.tsx` 中，`session.bindWorld` 传入 `liveViewport()`，并在视口 `useEffect` 中转发 `liveViewport()`，确保手势内核在任何时刻执行 `move`、`commitBox` 或点击时均基于最新帧视口。
2. **播放帧同步驱动手势重算**：
   - 在 `FinalVirtualCanvas.tsx` 的 `setScrollY` 内部（当 `playbackActiveRef.current === true` 时），实时调用 `session.onViewportChange({ ...viewport, scrollY: newScrollY }, geometry, surf)`，使选框随谱面滚动平滑延伸，且内核基准持续最新。
3. **渲染直读手势最新快照**：
   - `renderCanvas` 组装 view 时直读 `session.getSnapshot()`，消灭命令式绘制帧闭包读取滞后 React state `gestureSnap` 的延迟。

## 锁测

- `tests/unit/chart/editing/GestureSession.test.ts`：
  - 用例 1（滚动推进框选）：模拟播放推进（`scrollY` 减小），验证鼠标移动后选框起点 $p_1.y \ge 0$ 且精确对齐按下点音符当前实时画布坐标，随后滚动再推进时选框自动沿谱面平滑拉伸。
  - 用例 2（滚动推进结算）：验证播放推进后框选松手，`commitBox` 结算反解出的选区仅包含框选区域内的目标音符，不会误选历史音符。
- `tests/static/PlaybackRafHud.test.ts`：
  - 静态架构断言锁定：`setScrollY` 的播放分支必须包含 `session.onViewportChange`，且 `bindWorld` 必须绑定 `liveViewport()`。

## Answer

**resolved**。已修复播放中框选视口脱节导致顶点吸顶的问题：
1. `FinalVirtualCanvas.tsx` 中向 `session.bindWorld` 与视口 `useEffect` 统一注入 `liveViewport()`，使手势会话持有反映真实滚动的视口对象；
2. 在 `setScrollY` 播放活动分支中同步调用 `session.onViewportChange({ ...viewport, scrollY: newScrollY }, geometry, surf)`，保持手势内核中的视口与播放滚动逐帧对齐；
3. `renderCanvas` 绘制层改用 `session.getSnapshot()` 获取最新手势快照，保证在 RAF 命令式帧调度下直接绘制最新的选框尺寸；
4. 静态接线锁测（`PlaybackRafHud.test.ts`）与行为锁测（`GestureSession.test.ts`）全部通过，`npx tsc -b` 零类型错误，全套单测无回归。
