## Answer（结论）

**已实现**（2026-08-27，从 issue 29 迁出；同日三轮实机反馈闭环）：

- **数据层** `src/utils/backgroundSkin.ts` —— IndexedDB 独立库 `bangdream.assets`（kv 表，键 `backgroundSkin`，存 Blob）；BackgroundSkinStore 订阅式快照 + revision；持久化/解码/URL 工厂三端口可注入（node 单测覆盖）。`useBackgroundSkin` hook 桥接 React。
- **设置 schema** `src/utils/AppSettings.ts` —— `settings.visual.backgroundSkin.{enabled, opacity, fit, scope}`，additive 不 bump schemaVersion；`loadSettings` 字段级归一化（旧存档缺字段自动补默认）；setter 字段级 patch 合并。
- **渲染** `src/renderer/staticLayerCache.ts` —— 静态层失效五要素（bgActive/bgRevision/bgOpacity/bgFit/bgScope）参与 basis 比较（**问题1根因修复**：此前漏比较背景字段，缓存命中吞掉换图/调参；详见下方"问题1根因教训"）；图片经 `globalAlpha` 合成于黑底之上，合成后立即还原 alpha 不污染后续网格；按 `fit` 经 `computeBackgroundDrawRect(mode)` 几何计算，cover/contain 走不同 scale；按 `scope` 决定轨道区底色。
- **激活补帧** —— issue 28 表面契约 `active` 自 Editor 透传 `FinalVirtualCanvas`，false→true 时经 ref 取最新渲染函数**强制补绘一帧**（仅激活翻转触发，交互帧零额外成本）。即使缓存层已被"五要素"覆盖，这一层依然是保活挂载时所有视觉变化即时呈现的统一保险。
- **UI** `src/pages/AssetsPage.tsx` —— 背景皮肤面板承载上传/更换/启用/隐藏/清除 + 不透明度滑杆 + 填充方式下拉 + 显示范围下拉，全部走 design tokens，无新增 linter 违规。
- **测试** `tests/unit/BackgroundSkin.test.ts` —— 285 测试全过（追加：cover/contain 几何 5、normalizeBackgroundOpacity 7、BackgroundSkinStore 三原语与降级 7、settings 四字段归一化与 patch 合并 4）。
- **文档** —— ADR-0003 §13（"谱面背景皮肤最小模型" + 修订 + 静态层五要素）；CONTEXT.md 谱面背景皮肤术语行；map.md 待同步。

**问题1根因教训**（重要，登记以防重犯）：

用户三次反馈"上传/调透明度后回工作台需滚一下才出图"。前两轮先后用了"加订阅刷新"、"加激活补帧"，实测**无效**。Playwright 无头探针（/tmp/bge2e/modes.mjs，**不入库**）最终定位：staticLayerCache 缓存命中表达式只比较了 scale/scrollY/beatDisplay/chartEnd/surface/dpr/bpmEvents，**漏比较背景字段**——配置已变但命中判断说"其他都没变"→ blit 旧黑位图（"重绘执行了、内容是旧的"）。滚动能救用户恰因滚轮改 scale 强制 miss。修复就是把背景字段全量入比较。**给缓存加新失效维度时必须同步扩命中比较链，而非只塞进快照结构。** 入册以防后续给瓦片缓存加新字段时再踩。

**待实现（grill 2026-08-27 已拍板）** —— 自由裁剪编辑器：

1. **坐标模型** = **原图坐标系**（用户在上传后的原图上画裁剪框；显示与存储一致，避免与画布缩放/轨道变换耦合）。
2. **状态归属** = **画完即持久化**（无"应用/取消"按钮；用户期望"划完立即看到效果"，与整个素材系统的"选择即生效"惯例一致）。
3. **产物表示** = **IDB 写裁后副本**（decode 原图 → 用 OffscreenCanvas 裁矩形 → toBlob → 写 IDB 替换；与"上传"等价但产物是"裁过的图"）。**不**用 `{srcRect, offsetX, offsetY}` 偏移叠加方案（避免裁后图被反复变换、撤销时回不到原图质量）。
4. **入口与交互** —— 在素材页背景皮肤面板加"裁剪"按钮（上传并启用后出现）→ 进入裁剪模态/侧栏（沿用 sprite-locator 思路：滚轮缩放 / 空格平移 / 拖拽框选 / 选区手柄 + 数值输入微调）→ 取消回原图、确认写回 IDB（替换而非叠加）。
5. **撤销与重置** —— "恢复原图"按钮（从快照或上一次的"裁前原图"缓存中恢复，与上传路径相同入口）。
6. **未做**（登记）—— 预设比例、锁定矩形、批量管理、图片库/预设包（与 issue 29 末项"素材包导入"格式相关联，待 grill 联动）。

**仍登记未做**：

- 预设裁剪比例（4:3 / 16:9 / 自由切换）—— 后续可加，依赖裁剪编辑器先稳。
- 锁定裁剪框（防误操作）—— 后续。
- 批量管理（多张背景切换）—— 后续，存储结构（IDB 单值 blob）需扩为多条目表，会带动渲染层（多源切换）改造。
- 图片库/预设包 —— 与 issue 29 末项"素材包导入"格式相关；待 grill 联动。
- 切换/缩放时无障碍焦点环与键盘裁剪支持 —— 按"先做形态、再做无障碍"惯例留待后续。

#### 跨切片不变量（**新 session 必读**）

1. **缓存失效链优先于任何重绘** —— 即便补帧/订阅全到位，缓存命中比较链漏字段仍会吞掉新内容（问题1根因）。新维度必须同步扩 basis。
2. **覆盖（overwrite）vs 偏移叠加** —— 选择覆盖（裁后重写 IDB）。撤销 = 恢复原图。

4. **三原语扩展性** —— 未来"批量管理"会把 IDB 单值扩为多条目表，本 issue 暂不预动 schema。
