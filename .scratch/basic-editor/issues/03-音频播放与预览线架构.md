## Question

在 Electron + React 19 + Canvas（FinalVirtualCanvas）栈上，如何实现编辑器内**音频播放 + 与音频同步的预览线 + 按键音效**？调研并给出推荐架构：
- Web Audio API 的音频加载/播放/暂停/seek 方式（HTMLAudioElement vs AudioBufferSourceNode），以及与 RAF 动画循环同步预览线的做法。
- 按键音效的触发时机（按音符 beat 换算到音频时间戳）。
- 是否需要在 Electron main 进程做音频解码（Node 原生模块）还是仅 renderer 的 Web Audio 足够。
- 与现有历史/Canvas 渲染如何协作（预览线属于 Canvas 绘制还是 DOM 覆盖层）。

产出：推荐架构 + 可选方案权衡，供后续"音频播放与预览线"实现决策。

## Answer（结论）

research 子代理推荐架构：

- **播放**：用 `AudioContext` + `AudioBufferSourceNode`（而非 HTMLAudioElement），以获得精确 seek 与音频时间轴控制。
- **解码**：在**渲染进程**用 `decodeAudioData`（SongUploader 拿到 File → ArrayBuffer → decode），避免把压力放主进程。
- **预览线同步**：在 `FinalVirtualCanvas` 现有 RAF 循环里读 `audioNode.currentTime`，按 BPM 换算时间→beat→y 坐标，Canvas 绘制一条线。
- **按键音**：RAF 循环里将每个音符 beat 与当前时间比对，**提前 ~100ms 预调度**（`AudioContext` 时间），避免延迟。
- **大谱面性能**：预调度 + 对象池/复用 + 限制并发，避免 3000-5000 音符卡顿。

**含义**：渲染进程 Web Audio 足矣，无需 Electron 主进程解码。预览线与现有 RAF/虚拟画布天然契合。
