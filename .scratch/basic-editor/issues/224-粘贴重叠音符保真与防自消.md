# 224 · 粘贴重叠音符保真与防自消

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户在通过特殊手段（如谱面代码修改、导入等）构造了重叠音符（如同一拍、同一轨度的多个音符），在画布中选中这批重叠音符复制（`Ctrl+C`）或存入片段库后再粘贴时，幽灵预览（Ghost Preview）如实绘制了所有重叠音符，但实际落子执行后，**最终只粘贴出了 1 个音符**（其余重叠音符被内部覆盖替换或删除，即“自动去重”）。

后续实测中进一步发现两处交互体验与预期不一致：
1. **落点覆盖与拆条规则**：当将重叠音符放到已有音符/滑条端点位置，或在已有重叠音符位置放置新音符时，旧规则存在标记融合/未完全替换的问题；
2. **重叠音符框选拖拽**：框选了一组重叠音符后，因落点冲突检测机制（`claimed.has(k)`），无法整组一起拖动（判定为 `collision` 回弹）。

## 核心定案原则（用户 2026-11-08、2026-11-09 拍板）

1. **核心铁律**：**「普通编辑操作不应主动创造重叠情况」**。重叠音符本身属于特殊手段（如代码修改/特型谱面）产生的异常或特例，本 issue 的职责是**兼容重叠音符在剪贴板/片段库中的粘贴操作与整组平移**，绝不能让普通编辑操作能随意凭空产生重叠音符。
2. **剪贴板重叠保真**：**只有剪贴板保存的音符数据中自身存在重叠时，同批次内部才不执行自相覆盖**；尝试将普通 1 个音符粘贴到已有音符位置时，必须执行覆盖替换。
3. **落点覆盖与滑条拆条（对齐 Bestdori 干净完全替换口径）**：
   - **完全替换（Clean Slate）**：当新音符（无论是工具放置单个音符，还是剪贴板粘贴的一组音符）落到已有音符的位置时，若该位置已有音符（包含单个音符或既有多重重叠音符），**彻底清空该位置的所有既有音符**，然后写入新落子音符，不留任何被覆盖的底层旧音符残留。
   - **滑条遇落子直接拆条**：若落点为滑条结点（无论端点还是中间结点），**直接触发拆条（`splitSlideAtNode`）**，不执行端点标记融合或滑条组合，拆条后新音符作为独立音符占据该坐标。
   - **工具点击既有重叠处**：在已有重叠音符位置用工具点击放置新音符时，同样完全清空该位置的重叠组，仅保留当前点击放入的 1 个新音符。
4. **框选一组重叠音符支持整组拖拽（预存重叠冲突豁免）**：
   - 框选包含重叠音符的选区后，若被拖拽的多个音符在**拖拽前本来就处于同一坐标**（预存重叠），它们在拖拽到位后落于同一目标坐标属于合法的同组平移，**豁免 `collision` 冲突判定**，允许整组平移且保持相对重叠状态。
5. **单键单击拖拽维持层级逐个拖动**：在画布上不框选直接按住拖拽时，按层级只拖走最上层音符，底层留在原地，符合人机工程。
6. **批量换型维持最上层替换**：批量换型只替换重叠组的最上层音符，若全部替换会导致失去视觉区分度，维持现状。

## 场景分类与方案设计

### 场景 A：剪贴板自带重叠 [A, B] 粘到空白处
- A、B 均未命中原谱面音符；
- A 正常写入，B 不以 A 为目标，B 亦正常写入；
- 👉 **A、B 完整保留（根治核心缺陷）**。

### 场景 B：普通复制 1 个音符 A，粘到已有音符 X 处
- A 命中原谱面音符 X；
- 触发覆盖规则，X 被完全替换为 A；
- 👉 **保持既有行为，普通复制粘贴不创造重叠音符**。

### 场景 C：粘贴到已有音符位置（对齐 Bestdori 完全替换）
1. **落点为普通音符组 [X1, X2, ...]**：
   - 彻底移除落点处所有的既有普通音符（清除 X1, X2）；
   - 将粘贴批次中该位置的音符（单个或自带重叠 [A, B]）写入；
   - 产物：该坐标仅存新粘贴的音符，无残留旧音符。
2. **落点为滑条结点 S**：
   - 对滑条执行拆条（移除该结点，滑条解构为退化单键/短滑条）；
   - 将粘贴批次中该位置的音符独立写入；
   - 产物：滑条在该处断开，新音符独立存在，不发生标记吞并或滑条合并。

### 场景 D：框选重叠音符拖拽
- 在 `NoteDragging.ts` 的 `planDragMove` 中，计算拖拽落点碰撞时，记录每个拖拽源项的初始坐标 `origPosKey`；
- 当 `claimed.has(destKey)` 发生时，若当前项与已 claim 该落点的项拥有相同的 `origPosKey`，判定为「预存重叠整组平移」，不触发 `fail('collision')`；
- 产物：框选重叠音符后拖动，幽灵正常显示，鼠标释放后整组平移落子。

## 锁测用例规划

1. **粘贴重叠音符保真（已在 Phase 1 落地）**：
   - 剪贴板自带重叠单键 [A, B] 粘贴到空白处，两者均保留；
   - 剪贴板自带重叠 [Single, Slide] 粘贴到空白处，滑条与单键同时保留；
2. **落点完全替换与拆条（Bestdori 对齐）**：
   - 剪贴板音符粘贴到既有多重重叠音符 [X1, X2] 位置，断言 X1 与 X2 均被移除，新音符写入；
   - 剪贴板音符粘贴到滑条端点或中间结点，断言滑条拆条，新音符独立写入，无标记吞并；
   - 工具点击放置到既有多重重叠音符 [X1, X2] 位置，断言 X1 与 X2 均被移除，新键型独占该位置；
3. **整组拖拽预存重叠音符**：
   - 框选 2 个同坐标的重叠音符拖动 `dBeat=1, dLane=1`，断言 `ok: true`，且两者均到达新坐标。

### 2026-11-09 第三阶段修复（拖拽重叠音符到既有音符/滑条端点时的完全替换与拆条）
- **根因分析**：第二阶段只在 `pasteChartNotes`（粘贴路径）和 `applyPlacement`（工具点击路径）落地了 `cleanReplacePosition`，但拖拽路径（`NoteDragging.ts` · `planDragMove`）在落点撞滑条结点时仍沿用 issue 76 的 `placements` 标记变异逻辑，该逻辑：
  1. 组拖多件落滑条结点触发 `p.targetNote === slideTarget.orig` 报错 `collision` 回弹；
  2. 单键落普通滑条端点或中间节点判定为 `shouldReplace: false` 报错 `collision` 回弹；
  3. 未在拖拽落子时对既有滑条结点执行 Bestdori 拆条。
- **修复方案**：
  - 在 `NoteDragging.ts` 中预统计 `incomingByDest`，并在落点检测时综合判定 `isOverlapAtDest = incomingCount > 1 || targets.length > 1`；
  - 若触发重叠判定，将坐标存入 `cleanReplaceCoords`，豁免 `collision` 且不走标记消耗与接合；
  - 应用阶段引入 `cleanReplacePosition(unmovedNotes, ...)` 拆解途径未动滑条结点并清除未动键音符，拖拽音符独立落地；
  - 补充锁测：重叠音符平移至滑条端点拆条、中间节点拆条、以及拖拽单键至既有多重重叠位置完全替换；
- **验收全绿**：406 个测试文件、4489 个测试全部通过，`npx tsc -b` 0 报错。
