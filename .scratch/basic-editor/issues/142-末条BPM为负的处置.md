# 142 · 末条 BPM 为负（负 BPM 后面没跟正 BPM）现在怎么处理

Type: grilling（要拍板「编辑器能不能产出以负 BPM 收尾的谱」；结论会改 ADR-0010 结论 7/8 的落点）
Status: open
Blocked by: —

## 来源

用户 2026-09-21：「插入负 bpm 后，如果负 bpm 后面没有跟着正 bpm 当前的处理是什么？（设计的是否合理？）」

## 现状（代码实测）

**编辑器里可以随手造出来，且全程零提示：**

- BPM 就地编辑只拒 `0` 与 NaN（`FinalVirtualCanvas.tsx:316-321`），负值与「末条」都不判。
- BPM 工具点击 / `Ctrl+\`` 执行键用 `lastBpm` 直接落（`bpmPlaceOps`，`ToolActionMatrix.ts:81-92`），无校验。
- 校验只在**谱面代码弹窗的导入/应用**这条路上跑（`validateChartCode` → `checkBackflowBoundaries`）。

**造出来之后的后果：**

1. 时间轴在末条之后**持续倒扣**（`BpmTimeline` 带符号累加，ADR-0010 结论 3）；`chartEndBeat` 由「最大 beat 解」派生（`ChartGeometry.ts:124-126`），画布上会出现「末端之外还有一段反向铺开」的观感。
2. **导出**的代码末条为负 → 按 ADR-0010 关键事实「谱面以负 BPM 收尾会让 Bestdori OUT_OF_MEMORY 崩溃」，我们**产出了打不开的谱**。
3. **自相矛盾**：同一份代码导回我们自己的编辑器会被**整份拒收**（`checkBackflowBoundaries` ②，`ChartConverter.ts:450-465`，`validate.lastBpmNegative`）。即「能产、不能吃」。

## 待拍板

- **Q1（主）** 要哪条：
  - A **继续全放行，只加提示**：画布/状态区标出「末条 BPM 为负 → Bestdori 打不开」，数据一字不动（与 ADR-0010 结论 6「不拦」同气质，保真优先）。
  - B **放置/编辑时拒绝把末条设为负**（与导入校验对齐）：不能产就不能吃，但会拦住「先插负、稍后再补正 BPM」的正常工作流。
  - C **自动回正**：负 BPM 之后自动补一条正 BPM（改数据、进历史，可能不是用户想要的）。
  - D 放行 + **导出时**警告/二次确认。
- **Q2** 提示落在哪：谱面状态图标 / 报错区（issue 107 的地盘）/ 音频页？——需与 issue 107 划边界，本票不抢。
- **Q3** 「连续多条负 BPM 且末条为负」与「单条末条为负」同口径处理？（现状校验是同一条规则。）

## 定案（用户 2026-09-21）

**Q1 = A：继续全放行 + 明显提示，数据一字不动**（保真优先，与 ADR-0010 结论 6「不拦」同气质）。
即：编辑器**不阻止**你造出末条负 BPM，但要让你**看得见**「这份谱导出后 Bestdori 打不开」。

- **Q2（提示落点）待定**，见下方第二轮；本轮先看候选。
- **Q3 = 同口径**：不论「单条末条为负」还是「连续多条负值收尾」，只要**排序后最后一条 BPM 为负**就报同一条状态（与 `checkBackflowBoundaries` ②同判据）。

## 锁测（定案后填实）

- 纯逻辑，单测可完整覆盖：新增 `tests/unit/chart/editing/BpmTailPolicy.test.ts`（或并入 `NoteEditing.test.ts`）：
  - 末条为负 → 判定函数返回什么（A：只报状态 / B：拒绝写入）；
  - 中途负 BPM（后面有正）→ **不受影响**（回归，别误伤倒流区本体）；
  - `beat 0` 负值仍按 ADR-0010 结论 7 单独处理。
- 若选 A 且提示落在 UI：`tests/static/` 静态源码断言（照 `SlideFlickDecorator.test.ts` 惯例）+ 手工验收清单。
- `tests/unit/chart/editing/ToolActionMatrix.test.ts`：`bpmPlaceOps` 在 B 口径下要新增「末条负值 → 不落线」用例；A 口径下断言不变（护栏）。
