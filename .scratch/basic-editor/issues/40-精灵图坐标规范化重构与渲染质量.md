## Question

设置页指标（issue 39）#4 色觉辅助需要为 tap 音符接入「虚拍款式」图标，未来 issue 29 还要做音符皮肤条目级选择。现有精灵图提取逻辑（`src/components/CanvasSpriteIcon.tsx`）用「负百分比偏移 + 百分比尺寸」坐标系从 2048×1024 大图截取，该坐标当年从 BangDream 官方 CSS sprite 反解，**能用但抽象难懂**（`width/height` 字段非直观百分比、带缩放系数），且**无非皮肤数据模型**（坐标全硬编码在 `BaseSpriteIcons`/`DecoratorIcons`/`CompositeNoteConfigs` 注册表）。同时显示质量存疑：源图缩到音符大小是双线性缩小会模糊、主画布 DPR≤2 / 瓦片 DPR≤1.5、Canvas 版与 DOM 版（`imageRendering:'pixelated'`）平滑策略不一致。

## 期望

1. **坐标系规范化（B）**：`computeSrcRect` 改为直观可读的坐标表示（像素矩形 `{x,y,w,h}` 或直观百分比），把三张注册表一并整理，新增音符款式/皮肤时只加数据不碰换算逻辑。虚拍接入点预留在 `BaseSpriteIcons.tapVirtual`（具体坐标由 Issue-41 定位后填写）。
2. **渲染质量（C）**：统一/提升 Canvas 版与 DOM 版平滑策略（`imageSmoothingEnabled` 等），评估提高瓦片 DPR 上限对质量/内存/重建成本的权衡。
3. 不改变既有音符的渲染视觉（整理是纯重构，未经用户确认不得改默认观感）。

## 边界

- 不引入运行时皮肤数据模型（那是 issue 29 范畴）；本 issue 只做坐标体系规范化 + 虚拍接入点预留 + 质量。
- 与 Issue-41（可视化定位工具）解耦：本 issue 提供「加一款=加一条数据」的形态，Issue-41 负责从图上取坐标生成数据条目。两者可并行/先后，均非阻塞。
