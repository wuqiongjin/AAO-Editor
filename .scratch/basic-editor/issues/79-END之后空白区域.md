## 几何事实（核对结果；**推翻本票上一版"END 以下只有竖线"的错误说法**）

- 屏幕方向：**上 = 更晚的时间，下 = 更早**（`beatToVirtualY = C − positionOfBeat(beat)`，beat 越大 virtualY 越小）；
  判定线 = 画布**底边**（ADR-0006）。
- `virtualY(END) = surf.h / es` 是全谱**最小**的 virtualY → **END 是画面最上方的内容**，
  所以「END 之后的时间域」在 END 的**上方**（不是下方；下方是更早的音符，本来就有东西）。
- `scrollY = 0` → END 正好压在判定线上（`PlaybackScrollModel`:71 注释明文）；
  此时可见窗口 = `[0, surf.h/es]`，**全部早于…不，全部晚于 END** → 整屏空白。
- 空白高度 = `surf.h − scrollY · es`（END 上方那一截），`scrollY = 0` 时 = `surf.h` = **整屏**。
- 于是"一屏空白"与"尾部余量 `surf.h/es`"是同一件事的两种说法：余量恰为一屏虚拟高，
  滚到 `scrollY = 0` 时正好把这一屏全部露出来，而它全是 END 之后的时间。

## 为什么没法做（用户判断成立）

「END 音符能落到判定线」⟺ `scrollY` 允许到 0 ⟺ 那一刻画布上除判定线处的 END 外**整个都是 END 之后的时间**
⟺ **整屏空白**。要消除这块空白，就必须把 `scrollY` 下限抬到 > 0，也就是最后一个音符永远差一点到不了判定线。
**两个诉求是同一个约束的两面，不可兼得。**

## 记录过的部分解（均未采纳，留给将来）

- **a 视觉处理**（竖线在 END 收住 / END 以下降暗 / 斜纹）：不减少长度，只让它不难看。
  用户 2026-09-10 明确：不是这个诉求。
- **b 抬高 scrollY 下限**：判定语义是「音符越过底边即判」（issue 50），严格说最后音符不需要**中心**到线，
  只需越过 → 可把下限从 0 抬到"最后音符刚好越过底边"（约一个音符直径）。
  空白从"一屏"缩到"一屏 − 几十 px"，**收益极小**，却要改滚动不变量与按秒重锚口径 —— 风险与收益不匹配。
- **c 浏览态 / 播放态分离可滚范围**：编辑时不允许滚到整屏空白（可滚下限抬到 `surf.h/es − pad`），
  播放时仍允许 `scrollY → 0`。能真正消除"编辑时看到一整屏空白"，代价是滚动范围随模式变化 +
  `PlaybackScrollModel` 的重锚状态机要跟着分叉。**若将来要做，从这里入手。**

## 结论

保持现状。本票留档（含上面的几何事实与三个部分解），不再排期实现。
