## Question

编辑器内"音频播放 + 预览线 + 按键音"功能**从未实现**（按钮/快捷键/入口均为占位）。按 ticket 03（已结案的架构决策）落实实现。

## 现状证据（2026-08-09 调查）

- 音频文件被丢弃：[Editor.tsx:17](./src/pages/Editor.tsx) `Editor` 未消费 `song` prop（`const Editor: React.FC<EditorProps> = () => {}`）。
- 播放/暂停按钮无 onClick：`Toolbar.tsx` 播放区两个按钮为纯展示。
- 快捷键 `play` 为空桩：`Editor.tsx` `case 'play': /* 播放引擎未实现，占位 */ break;`。
- 渲染层无预览线、无按键音：全 `src/` 无 `AudioContext` / `decodeAudioData` / `createBufferSource`；`FinalVirtualCanvas` 无时间→y 绘制。

## 已定案架构（ticket 03，resolved，直接照做）

- 播放：`AudioContext` + `AudioBufferSourceNode`（精确 seek），不用 HTMLAudioElement。
- 解码：渲染进程 `decodeAudioData`（SongUploader 拿到 File → ArrayBuffer → decode），不动主进程。
- 预览线：在 `FinalVirtualCanvas` 现有 RAF 循环读 `audioNode.currentTime`，BPM 换算 时间→beat→y，Canvas 画线。
- 按键音：RAF 循环比对音符 beat 与当前时间，提前 ~100ms 预调度；大谱面用对象池/复用避免卡顿。

- [x] `play` 具体功能接通（切换播放/暂停）。

## Answer（结论）

按 ticket 03 架构落实实现，`tsc -b` / `vite build` 全绿，vitest 95 测试通过（新增 11 个）。

- 新增 `src/utils/AudioTiming.ts`（纯逻辑，可单测）：`getBpmEvents`（与 FinalVirtualCanvas 语义一致，beat 0 缺省补 120）、`beatToSeconds`/`secondsToBeat`（时间↔beat 分段换算）、`buildKeyEvents`（普通/方向/滑条结点平铺为按键音事件）。FinalVirtualCanvas 的局部 BPM 事件实现收敛到该模块，保证预览线与音频时间轴共用同一事件表。
- 新增 `src/utils/AudioEngine.ts`（渲染进程 Web Audio）：`AudioContext` + `AudioBufferSourceNode` 精确播放/暂停/seek；`decodeAudioData` 解码（不动主进程）；RAF 驱动 `tick()` 提前 ~100ms 预调度按键音（Oscillator 对象池复用，cursor 推进避免全表扫描）；谱面/BPM 变化经 `setChart` 增量更新。
- `FinalVirtualCanvas`：新增 `isPlaying`/`getPlaybackSeconds`/`onPlaybackTick` props；播放时持续 RAF 读秒 → `secondsToBeat` → `beatToVirtualY` 画预览线（虚线 + 秒数标签）；暂停停线、可停留。
- `Toolbar`：播放/暂停按钮绑定 `onTogglePlay`（无音频时禁用，title 随配置显示快捷键）。
- `Editor`：`song: File | null` + 解码 effect；`play` 快捷键接通 `togglePlay`；顶栏新增"换歌/选歌"按钮。
- `App`：支持"跳过（无歌曲模式）"直接进入编辑器（`inEditor` 与 `song` 分离）。
