# 107 · 「规范化」动作（把实机口径写回数据）

Type: feature
Status: open
Blocked by: 106

## 来源

issue 106 二次校正（2026-09-15）：解释侧定为**显示投影**（用户数据一字不动）。用户提出把「规范化」——即把同一套口径**写回数据**——改成**用户显式发起的动作**，另开本票；本期不实现，先立票。

## 目标

在谱面代码编辑器的**谱面状态图标**弹窗里，当状态为「需按实机口径显示」时提供一键「**规范化**」：把当前谱面按实机口径整理成一份干净的代码（此后画布 = 数据 = 导出，不再依赖投影）。

## 口径（显示投影的写回版，复用同一个纯模块）

1. `connections` 按 beat **稳定排序**；
2. 掐掉首尾 hidden；
3. 可见结点 **1 个 → 退化为单键**（保 `flick` / `skill`，与自家先例 `SlideCombination.connectionToNote` 同口径）；
4. 可见结点 **0 个 → 丢弃该音符**（写回时才允许丢弃：不再保留"画布无效果、数据还在"的中间态）；
5. 结果**点序恒单调**（非递减）。

## 交互

- 入口：谱面代码编辑器 → **谱面状态图标** → 弹窗 → 「规范化」（仅「需按实机口径显示」态可见）。
- **必须二次确认**，并把后果逐条列明（排序 N 处 · 裁首尾 hidden x · 退化为单键 y 条 · 丢弃 z 条）——这是**不可逆地改用户代码**；
- 一次操作 = **一个 undo 步**；完成后状态回到「合法」；
- 文案**不出现第三方站名**（沿用 ADR-0009 §2.2 的先例）。

## 实现落点

- `src/chart/editing/SlideNormalize.ts`（与 `displayConnections` 同模块）：写回版 `normalizeChart(notes) → { notes, report }`，`report` 复用状态明细的计数结构；
- 只在**用户动作**处调用（不挂在导入路径上——导入路径按 issue 106 保持只读）；
- 状态图标弹窗加按钮 + 确认框 + 明细复用。

## 锁测

- 单测（锁表）：排序稳定性（同 beat 保输入序）/ 掐首尾 hidden / 可见 1 → 单键（保 flick+skill）/ 可见 0 → 丢弃 / **幂等**（对已规范化的输入零改动）。
- 单测：规范化后 `validateChartCode` 通过、谱面状态回到「合法」。
- 手工验收：规范化 → **一次 undo 完全回退**；导出代码 = 规范化后的形态，画布 / 导出 / 实机三者同形。
