# 188 · 首次播放与长时静置后复播卡顿（谱面画布 & 动态预览）

Status: resolved
Type: bug
Related: [101](./101-播放起始卡顿.md), [165](./165-首次播放卡顿.md), [167](./167-首个音符抵线卡顿.md), [179](./179-冷启动首次播放首音符与BGM出声同刻卡顿.md), [chart-preview/57](../../chart-preview/issues/57-动态预览首次播放首音符入场与抵线卡顿.md)

## 来源
用户反馈（2026-10-31）：工作台谱面画布与动态预览在首次播放及长时间未播音频后复播时仍出现卡顿，179 修复后依旧复现。

## 症状
工作台与动态预览首次点击播放（起播帧及前导静音结束首音符/BGM 同刻）出现顿挫；静置 >30s 后再次播放，即使 JS 缓存已就绪仍复现卡顿。

## 根因
1. **音频管线休眠与预热失效**（`src/audio/AudioEngine.ts`）：暂停后 `AudioContext` 持续输出 `0.0f` 满 30s 触发 Chromium `SilentSinkSuspender` 与 WASAPI 休眠；179 的 `primeAudioGraph` 被单次锁 `audioGraphPrimed` 短路，且 64 样本 `1e-6` 微脉冲低于 16-bit 1 LSB（`3.05e-5`）并紧跟数秒全零前导静音，Sink 直至首音符才唤醒。
2. **播放期 80ms React 整页重渲染**（`PlaybackProvider.tsx` / `FinalVirtualCanvas.tsx` / `PreviewVideoStage.tsx`）：工作台 `currentSeconds` 每 80ms 驱动未 `memo` 的 `Toolbar`、`NoteInfoPanel`、`FinalVirtualCanvas` 等重渲染；动态预览 `PreviewVideoStage` 播放中每 80ms 回调父级 `onSecondsChange` 重渲染整页 `PreviewPage`。
3. **瓦片预热前瞻不足与 FIFO 淘汰**（`src/rendering/pipeline/noteLayerCache.ts`）：静止期仅预热 `[firstTile, firstTile+2]`（首音符抵线帧 `hi+2` 达 `firstTile+4`），且 64MB 预算按插入序 FIFO 淘汰漫游回起点的 `firstTile`。

## 修法
1. `AudioEngine` 改为常驻循环 1024 样本余弦保活源（`1/16384 = 2 LSB @ 16-bit`，直连 `seBus` 与 `destination`），暂停静置 `>=10s` 重建保活源，并在 `pointerdown`/`keydown` 捕获期提前 `resume` 与刷新保活。
2. `PlaybackProvider` 拆出 `usePlaybackState`（不含 `currentSeconds`），`FinalVirtualCanvas` 抽离 `CanvasPlayheadHud` 并与工作台子面板 `memo` 化；`PreviewVideoStage` 仅在非播放态与卸载时回调 `onSecondsChange`。
3. `noteLayerCache` 命中时 `touchTile` 刷新 Map 序实现 LRU 淘汰，并将首音符静止预热窗口扩至 `[firstTile, firstTile+4]`。

## 锁测
`tests/unit/audio/AudioEnginePlaybackRate.test.ts`（循环保活、静置重唤醒与 `pointerdown` 预热）、`tests/dom/preview/PreviewVideoControls.test.tsx`（播放期零回调）、`tests/static/PlaybackRafHud.test.ts`（Context 拆分与 `memo` 隔离）、`tests/perf/RendererPerf.test.ts`（`firstTile+4` 预热与 LRU 顺序）。
