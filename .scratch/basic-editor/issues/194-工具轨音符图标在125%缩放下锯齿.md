# 194 · 工具轨音符图标在 125% / 175% 缩放下锯齿（28px → 26px 回归）

Type: bug
Status: resolved
Blocked by:

**来源**：用户 2026-10-31 对比截图（origin/main vs origin/feature/basic-editor/177-workspace-redesign），指出窄工具轨的音符图标（尤其左右方向滑键）有明显"锯齿边"，质感比 main 差。

**症状**：工作台工具轨的 `NoteIconGlyph` 在 dpr 1.25（用户实机 1920×1080 @125%，与 ADR-0017 背景同环境）与 1.75 下边缘呈台阶状硬锯齿；方向键本体上下亮边、箭头斜边最明显；dpr 1.5 / 2 下不明显。main 的旧工具栏无此现象。

**根因**：

- 字形绘制代码与 main 完全相同（`NoteIconGlyph.tsx` / `noteGlyph.ts` 的 blob 一致，逐文件 diff 为空）。
- 183 换壳把工具轨字形从 `size={28}` 改成 `size={26}`（`WorkspaceToolRail.tsx`；180 原型定稿，见 [183](./183-工作台换壳.md)）。
- `size` 同时是画布 CSS 盒：26（方向键经 `glyphBox` 加宽为 34）。dpr 1.25 时物理盒 = 32.5 / 42.5 px；dpr 1.75 = 45.5 / 59.5 px，均为半像素。backing 按 `dpr×2` 生成（65 / 85），但合成器要把位图放进非整数物理盒 → 目标矩形边界落在半像素上，细特征取样点不均匀 = 台阶锯齿。
- 28 是 4 的倍数：常见 dpr 1 / 1.25 / 1.5 / 1.75 / 2 下 `28×dpr`、方向键盒宽 `36×dpr` 都是整数物理像素，所以 main 在 125% 下干净。
- **ADR-0017 §1 只锁了 `density/dpr` 的整数倍，没有锁「画布 CSS 盒 × dpr 必须是整数」**，26px 正好落在这个盲区；图标同时小 7%，放大了主观差距。

**复现**（worktree `/AAO-Editor-177-toolbar-notes` @ eaf3e20；Playwright chromium，1280×800，深色主题；采样 dirL）：

| 版本 | dpr | 画布 CSS / backing | 物理盒 | 观感 |
| --- | --- | --- | --- | --- |
| main | 1.25 | 36×28 / 90×70 | 45×35 | 平滑 |
| 分支 @26 | 1.25 | 34×26 / 85×65 | 42.5×32.5 | 台阶 |
| 分支临时改 28 | 1.25 | 36×28 / 90×70 | 45×35 | 平滑（≈main） |
| 分支 @26 | 1.5 | 34×26 / 102×78 | 51×39 | 平滑 |
| 分支 @26 | 1.75 | 34×26 / 119×91 | 59.5×45.5 | 台阶 |
| 分支临时改 28 | 1.75 | 36×28 / 126×98 | 63×49 | 平滑 |

像素指标（dpr 1.25 dirL，同等裁片 10× 最近邻放大）：unique colors 226 vs main 270、Laplacian variance 5020 vs 2781 —— 分支硬边更多、抗锯齿过渡更少。复现脚本在会话临时目录，未入库。

**修法（用户 2026-10-31 按推荐选定 A + C）**：

- **A（最小、与 main 对齐）**：工具轨恢复 `size={28}`；40×40 按钮放得下（方向键盒宽 36 < 40）。183 的静态锁测试同步改为 28；183 票面按 tracker 约定不改写。
- **B（保 26px 视觉）**：`NoteIconGlyph` 把 CSS 盒 snap 到物理像素网格（如 `ceil(size×dpr)/dpr`，宽高同法），并处理 dpr 变化的重新计算；代价是尺寸随 dpr 微调（26 → 26.4）与额外的像素验收。
- **C（防回归）**：工具轨 size 改用 4 的倍数，并在测试里锁住；或补一条 `glyphBox(...).w/h` 与 dpr 的整数性断言。

**锁测**：单测 `ToolbarNoteSkin.test.ts` 锁 size 与「字形盒 × 常见 dpr 为整数物理像素」（已落地）；像素级用 Playwright 在 dpr 1.25 / 1.75 断言 `canvas.getBoundingClientRect()` 的物理宽高为整数、且 `canvas.width / (cssW * dpr)` 为整数（本票手工执行；单测覆盖不到合成器重采样，仓内暂无 e2e 基建）。

## Answer

2026-10-31 实现（commit 见本分支）：`WorkspaceToolRail` 字形恢复 `size={28}`（与 main 一致）；`ToolbarNoteSkin.test.ts` 新增「字形盒 × 常见 dpr 必须是整数物理像素」锁测（先红后绿）；ADR-0017 §1/§2 补「画布 CSS 盒 × dpr ∈ ℤ」推论。

**验证**：

- `npx vitest run tests/unit/rendering/skin/ToolbarNoteSkin.test.ts`：32 passed（改测试后 2 条红 → 改实现后绿）。
- `npm test`：368 files / 4042 tests passed。
- `npx tsc -b`：0 error。
- `npm run test:types`：仍有 `tests/unit/settings/ShortcutIndexFilter.test.ts` 的既有类型错误（与本票无关，基线同样复现）。
- Playwright（本机 Chromium，dpr 1.25 / 1.75）：dirL 画布 36×28 CSS，backing 90×70 / 126×98，物理盒 45×35 / 63×49 均为整数；截图与 main 同级平滑。旧 26px 对比：dpr 1.25 unique colors 226→270、Laplacian variance 5020→2781；dpr 1.75 381→464、5621→3083。

## Comments

- 2026-10-31 分析建议（已获用户采纳）：优先 **A**（恢复 `size={28}`，与 main 已验证的配置一致、改动面最小），并用 **C** 锁住 size 为 4 的倍数防回归。若产品上必须保留 183 的 26px 视觉，则选 **B**（把画布 CSS 盒 snap 到物理像素网格）——它是覆盖任意 dpr / 浏览器缩放的通解，但需要额外的像素验收；C 单独不能修当前锯齿。
- 2026-10-31 code review 发现（残余风险，未在本票修）：`glyphBox` 的方向键盒宽由皮肤墨迹推导，非默认方向皮肤 02/03/04 的 dirL 在 `size=28` 下盒宽 35 → dpr 1.25 物理 43.75px，仍会半像素重采样；main 同样存在，不属本票引入的 26px 回归。若要彻底覆盖，需 B（`NoteIconGlyph` snap）或把方向盒宽取整到 4 的倍数（会轻微改变非默认皮肤的构图尺寸）。
