# 143 · BPM 填不了小数（Bestdori 支持）

Type: grilling（输入口径要拍板；结论会改 ADR-0010 结论 8）
Status: resolved（2026-09-21 实现 + 锁测，待验收）
Blocked by: —

## 来源

用户 2026-09-21：「bpm 貌似无法填入小数？（bestdori 支持的）」

## 现状（代码实测）

- 就地编辑提交用 `parseInt(bpmEdit.value, 10)`（`FinalVirtualCanvas.tsx:318`），注释明写「只取十进制整数部分、截断小数（12.7 → 12、-12.7 → -12）」—— 这是 ADR-0010 结论 8 定的口径。
- 但**导入侧不拦小数**：`validateChartCode` 只拒非有限数与 `0`（`ChartConverter.ts:509-521`），带小数的社区谱能原样进画布；`convertBpmNote` 直写 `note.bpm`（`:108-114`），**导出也原样**。
- 净结果：能读、能存、能导出小数，**只有手工输入被截断**。想把 128.5 改成 130.2 改不动，一动就变 130 —— 数据被静默改写（往返不保真）。

## 待拍板

- **Q1** 输入口径：`parseFloat` 收任意小数，还是白名单精度（如最多 3 位小数 / 步进 0.1）？
- **Q2** 就地编辑框的显示：`String(lastBpm)` → `128.5`；要不要固定小数位（120 显示 `120` 还是 `120.0`）？
- **Q3** 外侧装饰文字（BPM 数值，`gutterLabels`）跟着显示小数吗？全显 / 保留 1 位 / 整数才原样？
- **Q4** 实现路径（影响可测性）：`commitBpmEdit` 住在组件里，单测碰不到。
  - 建议：抽纯函数 `parseBpmInput(text): number | null` 到 `src/chart/editing/`（组件只调它）→ 小数/负数/0/空串/「abc」全部可单测；
  - 或保持内联 + 静态源码断言。倾向前者。
- **Q5** 同步改 ADR-0010 结论 8（「接受负整数」→「接受负值与小数」）与 CONTEXT 相关表述。

## 定案（用户 2026-09-21）

**Q1 = A：`parseFloat` 全收任意小数**（对齐 Bestdori；显示与导出原样）。
**Q4 = A：抽纯函数** `parseBpmInput(text): number | null` 到 `src/chart/editing/`，组件只调它 —— 小数/负数/0/空串/非数字全部可单测。

- `0` / `-0` / NaN 仍视为**无效 = 取消编辑**（现有口径不回退）。
- 负值仍收（ADR-0010 结论 8 不回退；与 #142「末条负值放行」一致）。
- **Q2 / Q3（显示格式）待第二轮**，见下方。

## 锁测（定案后填实）

- 选 Q4 抽函数：`tests/unit/chart/editing/BpmInput.test.ts`（新增）—— `128.5` / `-128.5` / `12.7` / `0` / `-0` / `""` / `"abc"` / `"12.7abc"` / 超多位小数 各一条；负值仍收（ADR-0010 结论 8 不回退）。
- 选 Q4 静态断言：照 `tests/static/SlideFlickDecorator.test.ts` 惯例锁源码里不再出现 `parseInt(.*bpm`。
- `tests/unit/chart/editing/ToolActionMatrix.test.ts`：`bpmPlaceOps` 的 `String(lastBpm)` 初值在小数下要能原样带出（新增「lastBpm = 128.5 → 编辑框初值 `128.5`」）。
- `tests/unit/visual/render/GutterLabels.test.ts`：Q3 决定后补 BPM 数值文字的格式用例。
- 手工验收：无音频谱面，插入 `128.5` → 标注显示、导出代码里仍是 `128.5`（往返保真，对照 ADR-0010 结论 9）。
