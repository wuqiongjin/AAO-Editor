## Question

issue 36 二轮诊断确认（2026-08-15）：谱面代码编辑器（`ChartCodeEditor`）是密集谱（3,000-5,000+ 音符）放置/编辑卡顿的**主因**——每次画布编辑（250ms 防抖后）全量 `convertNotesToChartCode + chartCodeToJSON`（O(n)，5000 音符 ≈ 300-500KB 字符串）→ 受控 textarea 重新赋值 → 巨型文本布局失效 → 下一次画布鼠标事件 `getBoundingClientRect` 强制同步重排（单击 CPU 的 57.7%）。用户已实测确认：折叠右面板后卡顿显著好转。

## 目标

1. 代码查看/修改从**常驻面板**改为**按需弹窗**：默认不同步、不渲染任何代码文本；用户主动点击（如"谱面代码"按钮）才弹出独立窗口（Modal/Drawer），在其中查看/编辑/应用代码。
2. 密集谱（5000 音符）下画布编辑路径上**零**代码同步成本：无字符串生成、无 textarea 布局、无因代码面板引起的强制重排。
3. 保留现有能力：代码文本撤销栈、校验、应用（覆盖确认）、复制、重置、用画布刷新、AI 通道注释（ADR-0003 §9）。

## 核心思路

- **触发与懒同步**：右面板原代码编辑器位置换成一个入口按钮（显示"谱面代码"）。弹窗打开时才执行一次「画布 → 代码」构建（构建期间可显示 loading，5000 音符量级 <50ms，无需 Worker；若未来要增量/超大谱再考虑 idle/Worker 生成）。
- **打开期间的双向同步语义**（沿用现有 dirty/stale 语义，ADR-0003 §9）：
  - 弹窗打开时以当前画布重建代码（除非有未应用草稿——沿用 `lastAppliedCode`/`isDirty`/`isStale` 状态，迁移为弹窗内部状态或提升到 context）。
  - 弹窗打开期间画布继续可编辑：沿用「过期提示 + 应用覆盖确认」；弹窗内防抖同步可以保留（弹窗内 textarea 布局成本用户可接受，且 Modal 覆盖画布，无 gBCR 级联受害者——画布鼠标事件在 Modal 打开时不会触发）。
  - 关闭弹窗即卸载 textarea（成本归零）。
- **Modal 形态**：居中大窗（代码需要宽度），Esc/点击遮罩关闭；关闭前若有未应用草稿给确认。复用现有 `ChartCodeEditor` 主体（textarea + 工具栏 + 校验逻辑），只把容器从面板内嵌改为 Modal。
- **不做**：语法高亮、虚拟滚动代码视图（YAGNI——按需打开后已非热点；若未来单文件 1MB+ 再议）。

## 验收

- 5000 音符谱面连续放置 20 个音符：DevTools Performance 无 >50ms longtask 归因到代码同步/textarea 布局（issue 36 诊断回路 `diag36.mjs` 右面板展开场景与收起场景等价）。
- 打开弹窗 → 查看/编辑/应用/覆盖确认/关闭，全流程功能与现有一致（含快捷键撤销栈）。
- 弹窗关闭后无残留状态泄漏（再次打开内容正确）。

## Answer

**已实现（2026-08-16）**：`ChartCodeEditor` 由常驻内嵌面板改为**按需弹窗**。

- **入口移动**：代码编辑器从右面板 `NoteInfoPanel` 迁出，入口按钮 `ChartCodeEditor` 挂到左侧工具栏「编辑」分组（`Toolbar.tsx`），点击才打开弹窗；常驻态不做任何代码同步（`src/components/ChartCodeEditor.tsx` 仅渲染入口按钮，弹窗用 `createPortal` 按需挂载）。
- **单向同步 + 关闭即丢**：打开时 `handleOpen` 以当前画布全量构建一次代码、重置撤销栈与 dirty 基准（`lastAppliedCode`/`appliedNotesCount`）；关闭即卸载 textarea，再次打开从画布全新同步，无残留泄漏。
- **保留能力**：代码文本真实撤销/重做栈（Ctrl+Z/Y）、校验、应用（覆盖确认 + beat0 BPM 保底）、重置、复制、用画布刷新、过期提示，均沿用 issue 08 语义。
- **弹窗交互**：居中大窗；Esc/点击遮罩/关闭按钮关闭；关闭前若有未应用草稿弹确认（复用 `requestClose`）。
- **验收**：`tsc -b` 全绿；180 测试通过。画布编辑路径上的代码同步成本归零（弹窗关闭即无字符串生成/textarea 布局；打开期间 Modal 覆盖画布，画布鼠标事件不触发，无 gBCR 级联受害者）。

**点击遮罩关闭是否符合预期？符合。** 按本 issue 方案「Modal 形态：居中大窗…… Esc/点击遮罩关闭」（见上文「核心思路」），点击模态遮罩关闭弹窗是既定的预期行为；实现上外层遮罩 `onClick={requestClose}`、内层弹窗 `stopPropagation()`（`src/components/ChartCodeEditor.tsx`），且 `requestClose` 内含未应用草稿确认，不会静默丢稿。

### 交互修正（2026-08-16）：拖选文字移出弹窗误关

首版实现用遮罩 `onClick` 关闭：**在弹窗 textarea 内按住左键向上/向下拖选，若鼠标移出弹窗到遮罩上，mouseup 落在遮罩 → click 派发到遮罩 → 误触发 `requestClose` 关闭弹窗**，体验诡异。

修复（`src/components/ChartCodeEditor.tsx`）：关闭判定由遮罩 `onClick` 改为 **`onMouseDown`**，内层弹窗同步新增 `onMouseDown` 的 `stopPropagation()`。这样「点击遮罩关闭」语义不变，但拖选场景的 mousedown 发生在弹窗内部（被拦截），遮罩不触发，仅当我们真正**从遮罩上按下**才关闭。`tsc -b` 全绿。
