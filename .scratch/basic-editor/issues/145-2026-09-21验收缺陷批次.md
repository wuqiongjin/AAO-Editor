## #1 负 BPM 被当成「上次填写值」沿用

Status: resolved（2026-09-21 实现 + 锁测，待验收）

**来源**：用户 2026-09-21 #4（「如果上次写的是负数，很容易触发问题 1 的场景。因此，负 bpm 是不是不要自动保存比较好？」）。用户已给倾向，按此实现，待验收。

**症状**：BPM 工具自动带出上次填的 BPM（ADR-0008 §5）。上次是负数 → 下一次点放置 BPM 默认就是负值，极易误造倒流区（并叠加 #141 的手抖误框选）。

**根因**：`lastBpmRef.current = v` 无条件更新（`FinalVirtualCanvas.tsx:326`），`v` 为负也照记。

**修法**：**负值不进「上次值」** —— 只有 `v > 0` 才更新 `lastBpmRef`；从未有过正值则保持初始 120。（`0` 本来就走「无效 = 取消编辑」分支，不额外处理。）

**锁测**：
- `commitBpmEdit` 住在组件里、单测碰不到 → `tests/static/` 静态源码断言（照 `SlideFlickDecorator.test.ts` 惯例）：锁「`lastBpmRef.current =` 被 `v > 0` 守卫」。
- 若 #143 决定抽 `parseBpmInput`，把「是否记忆」一并收进那个纯函数，改由单测锁（届时本条替换为单测）。
- 手工验收：填 `-120` → 应用 → 再点 BPM 工具 → 就地编辑初值应为 **120**（不是 -120）。

## #2 导入谱面代码自动延长谱面长度后，音频页「谱面时长」不跟着变

Status: resolved（2026-09-21 实现 + 锁测，待验收）

**来源**：用户 2026-09-21 #5。

**症状**：无音频时导入比当前更长的谱面代码 → 画布/播放条按新长度走（ADR-0005 §4.5），但**音频页「谱面时长」数字仍是旧值**；且 session 下次 emit 会把旧值反向覆盖回 PlaybackContext（数字会「弹回」）。

**根因**：`ChartCodeEditorModal.tsx:301-306` 只调 PlaybackContext 的 `setDuration(endSeconds)`，没走 `session.setChartDuration`。而 `AudioSession` 才是谱面时长单一真相源（`AudioSession.ts:10-11` 注释明写），`useAudioBridge.ts:45-49` 是**单向** session → context。播放条只是被同步的下游。

**修法**：弹窗改走 session 的 `setChartDuration`（注入/取 `useAudioSession()`），PlaybackContext 由桥自动同步；弹窗不再直接 `setDuration`。

**锁测**：
- `tests/unit/audio/AudioSession.test.ts`：`setChartDuration` 已有用例（clamp/拒绝非法值）保持不动（护栏）。
- 新增 `tests/static/` 静态源码断言：谱面代码弹窗内**不得**出现来自 `usePlayback()` 的 `setDuration` 调用（照 `tests/static/ChartCodeModalResponsiveness.test.ts` 同目录惯例）。
- 手工验收：无音频 + 时长 30s → 导入结束于 90s 的代码 → 音频页数字变 90、播放条同步、回工作台再切回音频页数字不跳回 30。

## #3 Slide 中间结点的 `flick`/`skill` 被真的渲染出来

Status: resolved（2026-09-21 实现 + 锁测，待验收）

**来源**：用户 2026-09-21 #7 —— **定案（用户 2026-09-21）**：中间结点**不渲染** flick/skill，但**允许**通过谱面代码这么改（数据原样保留、原样导出）。

**症状**：给中间结点加 `flick`/`skill` → 画成滑键/技能键，还补 flick 顶部装饰箭头。

**根因**：
- `slideNodeIconConfig`（`src/visual/render.ts:256-260`）：`isFirst || isLast` 只用来选**基底**（端点款 / 中间款），flick/skill 的**覆盖**不区分端点与中间 → 中间结点也被换成 flick/skill 图。
- `renderSlideBody` 的装饰箭头循环（`render.ts:709-718`）：对所有 `conn.flick` 都补，不判端点。
- 实绘 / 选中描边 / 幽灵 / 待连接锚点四处共用这一个选款函数（issue 65①）→ 四处一起错。

**修法**：`slideNodeIconConfig` 只在**端点**（`isFirst || isLast`）应用 flick/skill 覆盖；装饰箭头同样只给端点补。
**数据、命中、选中、导出一律不动**（仍可经谱面代码改、导出原字节）—— 只改「怎么画」。
端点承载标记的现状（issue 81）不变。

**锁测**：
- 导出 `slideNodeIconConfig`（与 `computeBackgroundDrawRect` 同款：为可测而导出），新增 `tests/unit/visual/render/SlideNodeIcon.test.ts`：
  - 中间结点带 `flick` → 选款 = `slideAmongFor(lane)`（**不**被 flick 覆盖）；
  - 中间结点带 `skill` → 同上；
  - 端点带 `flick`/`skill` → 仍被覆盖（回归，不放松）；
  - 装饰箭头：`tests/static/SlideFlickDecorator.test.ts` 扩一条「箭头只给端点」（该测试现锁的是「存在 renderDecorator 调用」，需加端点守卫，别把它改绿成无断言）。
- 手工验收：谱面代码给 5 结点滑条的 m2 加 `flick` → 画布上 m2 仍是普通中间结点外观、无箭头；导出代码里 `flick: true` 仍在。
