# 213 · 高刷屏120Hz播放卡顿与帧调度优化

Type: bug
Status: open

## 来源

用户在 macOS 环境（Apple Silicon M4 / ProMotion 120Hz 高刷屏）反馈：
谱面画布在播放的时候有点卡，相比 Windows 60Hz 更加迟滞不顺畅。

## 症状与根因

1. **瓦片排空延迟按 60Hz 硬编码（16ms）导致 120Hz 下瓦片严重饥饿（主因）**：
   - **症状**：快速移动或播放密集谱面时出现微卡顿、跳帧。
   - **根因**：
     - 在 [noteLayerCache.ts](file:///d:/Company/WorkSpace/MocaCoffee/bangdream-editor/src/rendering/pipeline/noteLayerCache.ts#L430) 中，播放态瓦片排水延迟写死为 `delay = isPlaying ? 16 : 0`。
     - 在 60Hz 下，16ms 约等于 1 帧；但在 120Hz（8.33ms/帧）下，16ms 跨越了 2 个完整刷新周期。
     - 瓦片光栅化远远跟不上 120Hz 下视口前进速度，主流程频繁发生 Cache Miss 并被迫触发主线程同步渲染（`renderTileSync`），耗时 2~5ms 瞬间打爆 8.33ms 的极限单帧预算，导致肉眼可见的丢帧。
2. **每帧同步写 DOM `scrollTop` 引起 120Hz 合成器与重排颠簸（次因）**：
   - **症状**：高刷屏幕下 GPU/Compositor 负载居高不下。
   - **根因**：
     - 在 [usePlaybackCoordinator.ts](file:///d:/Company/WorkSpace/MocaCoffee/bangdream-editor/src/playback/usePlaybackCoordinator.ts#L182) 中，rAF 每帧均同步修改 `container.scrollTop = targetScrollTop`。
     - 120Hz 下每秒执行 120 次强制 DOM 滚动通知与视口几何更新，触发复杂的图层重排，而在 macOS 配合几百万像素 Retina 画布时，Chromium 合成器发生严重颠簸。

## 修法

1. **帧率自适应瓦片调度与预算控制**：
   - 根据当前实际刷新率（动态采样 rAF delta 或估算 60Hz/120Hz/144Hz）：
     - 将 120Hz 设备下的排水定时器缩短至 `Math.min(4, targetFrameInterval / 2)`，消除跨帧断层；
     - 将单片工作预算 `maxWorkMs` 由固定的 4ms 动态缩放为不超过当前帧预算的 25%（如 120Hz 下约 2.0ms），把主线程留给主画布渲染与音频事件调度。
2. **播放态 DOM 滚动平滑与解耦**：
   - 播放过程中由 Canvas 内部的虚拟滚动位移（Virtual Scroll Offset）承载平滑位移；
   - 外部 DOM 滚动条 `scrollTop` 进行适当降频同步，暂停或拖动时即时吸附同步（对齐 Issue 75 / 134）。

## 锁测与不变量保护

1. **既有功能不变量**：
   - Windows 60Hz、144Hz、240Hz 显示器体验平滑不降级；
   - 保持以音频单调时钟（`AudioEngine.currentTime`）为绝对基准，音画同步毫秒级零漂移；
   - 暂停、停止、跳至起点时滚动条与画布严格 1:1 吸附，不回弹、不跳帧。
2. **锁测**：
   - `tests/unit/noteLayerCache.scheduler.test.ts`：模拟 120Hz (8.33ms) 步长，验证队列排水平滑度与时间片预算边界；
   - 密集音符性能测试：确保连续播放 5 秒内 99th 分位单帧耗时稳定在 8.0ms 预算内。
