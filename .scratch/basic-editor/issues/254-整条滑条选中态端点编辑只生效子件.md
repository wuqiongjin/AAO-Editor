# 254 · Ctrl+左键整条选中后再点端点编辑，只生效该端点

Type: bug
Status: resolved
Blocked by: —
关联: [229](./229-整条滑条选中态Shift拖动只拖光标子件.md)（同根因、只修了拖动）· [88](./88-单击选区内音符应作用于整片选区.md)（命中 ∈ 选区 → 整片执行）

## 来源

用户 2026-11-24：Ctrl+左键点滑条端点后整条（含段）进入选中态，再对该端点做编辑，却只改这个端点本身。先前同一分叉只修过「拖动整条」（229）。期望 = 与**框选整条后再点该端点编辑**一致。

## 症状

- **框选整条** → 再点其中一个端点（删除 / 镜像 / 键型 / 曲线）＝整片生效（issue 88）。
- **Ctrl+左键点端点** → 外观同样是整条选中，再点该端点编辑 → 只改被点的那个结点 / 段（删一端、只翻一端 lane、只改一端标记、曲线误启画笔或只刷一段）。
- 键盘 Delete / Ctrl+C / Ctrl+X 不经命中判定，Ctrl+左键态本来就会整条生效，不在本票范围。拖动已由 229 对齐。

## 根因

两种「整条选中」内部表示不同（229 已写清，ADR-0001 §6.1 保留 Ctrl+左键 = `{kind:'note'}`）：
- 框选 = 多条 `slideNode`+`slideRegion` → `sameSelectionItem(hit, 选区某条)` 成立 → issue 88 整片。
- Ctrl+左键 = 单条 `{kind:'note'}` → 光标命中的 `slideNode`/`slideRegion` 与之 `kind` 永不相等。

229 只在 `resolvePressIntent` 补了 `coveredByWholeNote`。issue 88 入口仍用字面 `sameSelectionItem`：`clickOps.hitInSelection`、`resolveActionTargets`（右键点删）、`curveToolClickOps`、曲线无 Shift 按下「选区内不启画笔」。

## 修法（已实现；待页面验收）

抽出 `hitCoveredByWholeNote` / `selectionCoversHit` / `expandWholeSlideItems`，接到 `clickOps`、`resolveActionTargets`、`curveToolClickOps`、曲线无 Shift 按下。命中覆盖时复用 `boxSelectOps`；整条 `{kind:'note'}` 先展开成可见结点 + 逻辑段。**未改** `pointerClickSelection`。`resolveActionTargets` 的 `notes` 必传（缺了无法展开）。

## 锁测（已落地）

`ToolActionMatrix.test.ts` issue 254：skill/flick/delete/mirror 框选≡Ctrl+左键；skill 两端都改、flick 只尾端、delete 整条消失、mirror 含 hidden 0→6；curve 点端点/点段同源；右键点删整条；未整条选中只改一端；单键不被误伤。`CurveTool.test.ts`：Ctrl+左键整条后点端点不启画笔。回归：229 四例拖动、issue 88 整片用例、`npx vitest run` 452 文件 / 4964 例、`tsc -b` 0 错。

## Answer

**resolved（2026-11-24）**。Ctrl+左键整条选中后再点端点/段，与框选整条后再点同源走 issue 88 整片路径。
