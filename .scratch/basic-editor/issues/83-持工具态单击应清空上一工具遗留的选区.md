# 83 · 持工具态单击后，上一个工具留下的「选中态」应清空（音符代码 / 删除 / 镜像 三处漏网）

Type: bug
Status: resolved（2026-09-11 重新定案 + 实现 + 锁测，待你在页面验收）
Blocked by:

## 来源

用户 2026-09-10 报 → 2026-09-11 **重新定义**（首版我把问题理解成"hover 描边残留"，实现跑偏，已回退）：

> 我重新修改一下 issue 83 的内容吧。当选中音符后，此时音符进入被选中态。此时切换工具，
> 被选中态仍然会保持（这是 OK 的）。但是这个新的工具如果要进行操作（点击也好，哪怕是无效操作，
> 比如点击了轨道外面），此时要清空之前被选中的音符的状态。
> 当前存在问题的工具是「音符代码工具」：现在鼠标指针下选中 1 个音符，此时切换到音符代码工具，
> 音符代码工具点击别的音符时，先前被选中的音符的"被选中态"也没有消失。这是不合理的。

## 定案（用户 2026-09-11）

1. **切工具本身不清选区**（与 ADR-0008 §1「选区常驻、与持工具态解耦」一致，不变）；
2. **新工具在画布上单击 = 一次操作意图 → 清空上一个工具留下的选区**，与操作是否有效无关
   （无效操作如点轨道外 / 谱面末端外，同样清）；
3. 故「音符代码」不再是 §2 原则 6 的例外 —— 它原本被豁免的理由是"唯一不改谱面的工具"，
   但用户点了画布注意力就转移了，与改不改谱面无关。

## 事实基线（改前）

`src/chart/editing/ToolActionMatrix.ts` `clickOps`：

| 工具 | 单击后是否清选区（改前） |
| --- | --- |
| 键型 / BPM / Slide / 粘贴 | ✅ 清（`clearSel`，含落点非法） |
| 删除 / 镜像 | 命中音符 → 执行（删除清空 / 镜像替换为产物）；**点轨道内空白 = 无效果不清选区**；点轨道外 → 清 |
| **音符代码** | ❌ **命中 → 只 `openNoteCode`；空白 → `[]`** —— 即选中态一直挂着（本 issue 的 bug） |

## 实现落点

| 文件 | 改动 |
| --- | --- |
| `src/chart/editing/ToolActionMatrix.ts` | `clickOps` 的 `noteCode` 分支：命中 → `[openNoteCode, clearSel]`；未命中（空白/轨道外）→ `[clearSel]`。`isActionTool` 分支：无命中 → **一律** `[clearSel]`（删掉 `pos === null ? clearSel : []` 的双轨） |
| `docs/adr/0008-工具交互机制.md` §2 原则 6 | 例外 ⑤（音符代码不清选区）**作废**并写明反例；末段「删除/镜像点轨道内空白不清选区」改为一律清 |
| `docs/adr/0008-工具交互机制.md` §2 单击矩阵 | 「音符代码」行两列 + 「删除/镜像」行空白列同步改为"清选区" |

**回退**：首版按"hover 描边残留"实现的一套（`CanvasGesture.hoverSuppress*` 状态机 +
`FinalVirtualCanvas` 用 `armedTool` 变化门控 `hoverItem`）**已整体回退** —— 理解跑偏，
且它会带来真实副作用：切到删除/音符代码工具后，鼠标不动就看不到 hover/danger 预览。

## 扩订（用户 2026-09-11 补充拍板）

**删除 / 镜像态点「轨道内空白」也要清选区** —— 与音符代码是同一类问题，并入本票。
旧口径（ADR-0008 §2 单击矩阵 + 原则 6 末段）：删除/镜像点轨道内空白 = 无效果不清选区（清选区走 Esc
或指针态点空白），只有点**轨道外**才清 → 形成"按落点是否合法"的双轨。现统一为：**无命中即清选区**，
与落点是否合法无关（与原则 6"与落点是否合法、动作是否生效无关"对齐）。

> 未动：**框选**路径（`boxSelectOps`）空框仍无效果不清选区 —— 用户口径只覆盖"点击"，框选另议。
