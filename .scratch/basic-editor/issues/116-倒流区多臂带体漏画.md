# 116 · 倒流区「多臂同高」带体漏画（`splitBandAtFolds` 漏判横跳后的折返）

Type: grilling
Status: resolved（2026-09-18 定位 + 复现 → 修法拍板 + 实现 + 锁测；2026-09-19 用户页面验收通过）
Blocked by: —
Related: 104 / 105（倒流区时间轴与几何）、09 七轮（`splitBandAtFolds` 的来路）

## 来源

用户 2026-09-18：社区谱 150030 在 beat 18 之后的**倒流区**，本编辑器与官方画面不一致。
具体对象 = 该谱 `beat 48 → 290` 那条滑条（24 个连接点：lane `6→4→2→0` 阶梯，末尾另有 288/6、289/5）。

## 数据 / 几何

BPM 每 30 拍在 ±225 之间翻转（`48:-225 / 78:225 / 108:-225 / …`），于是
**beat 48→288 在时间轴上只占同一段 4.8s–12.8s，被来回扫了 8 遍**，且每 30 拍换一次轨：

```
(78,6)y=4.8  → (108,6)y=12.8     下行腿（lane 6）
(108,6)      → (108,4)           零高横跳（Δbeat = 0）
(108,4)y=12.8 → (138,4)y=4.8     上行腿（lane 4）
(138,4)      → (168,4)           再下行腿（lane 4）
(168,4)      → (168,2) 横跳 …    依此类推
```

⇒ 官方画面 = **lane 6/4/2/0 四根竖条叠在同一段高度上**（每根覆盖整个 8s），末尾另有 lane 6、5 的短条。

## 根因（已用真实模块复现）

1. `splitBandAtFolds`（`src/visual/slideBandGeometry.ts`）只在 dy 变号时切分，但横跳段 `dy === 0` 被
   `continue` 跳过、方向状态 `cur` 不更新 ⇒ **"横跳之后再反向"检测不到**：
   复现（真实模块，倒流区几何）= 只切出 **2 个 run**（2 点 / 15 点），run1 的 y 序列
   `128,48,48,128,48,48,128,…` → **不是 y 单调** ✗。
2. `bandRunAtY(run, y)` 对一行**只返回第一条命中的臂**（`return` 在循环内）⇒ 非单调 run 里其余臂被
   静默丢弃。复现：同一行 y=80 实际只画到 `x = [120, 120]`（都是 lane 6），**lane 4/2/0 一根都没有**
   = 用户截图左图（一条 lane 6 的宽带 + 空网格）✗。

带体的"多臂"合成本来靠 `rasterBandRuns` **跨 run** 的像素内 screen 合成（叠亮），前提是
**每个 run 严格 y 单调** —— 这个前提在本形状下不成立。

## 修法（待拍板）

- **主修**：`splitBandAtFolds` 改为按「**非零 dy 的符号变化**」切分 —— `dy === 0` 段对方向透明
  （不重置、不跳过方向判定），保证每个 run 非严格 y 单调（允许 Δy=0 段）。切分点仍与下一 run 共享
  （相邻 run 无缝，既有口径不变）。
- **加固**（与主修二选一，避免两处口径分叉）：给 `bandRunAtY` 加「每 run 只应命中一条臂」的断言；
  或让它收集 run 内全部臂。
- **锁测**：`tests/unit/SlideBandGeometry.test.ts` 新增「倒流区锯齿（多层平行腿 + 横跳）」用例：
  ① `splitBandAtFolds` 产出的每个 run y 单调；② `rasterBandRuns` 在同一行能画到 4 条臂（α>0 的簇数 = 4）。

## 影响面

本谱 112 条滑条里 **14 条跨越 BPM 翻转**；凡跨翻转且中途换轨的滑条都会漏臂（本票这条最长、最明显）。
