# 103 · 负 BPM 校验放行与边界

Type: feature
Status: resolved（2026-09-17 实现 + 锁测，tsc 0 / 1142 测全绿；2026-09-19 用户页面手工验收通过，关闭）
Blocked by:

## 来源

[issue 100 负数 BPM 语义](./100-负数BPM语义.md) 定案（2026-09-14），权威 = [ADR-0010](../../../docs/adr/0010-负数BPM与倒流区.md) 结论 1/7/8/9。

## 症状（现状）

`validateChartCode`（`src/chart/editing/ChartConverter.ts` L403-404）以 `bpm <= 0` 拒绝一切非正 BPM → 含负 BPM 的社区谱**打不开**（如 `docs/resource/SampleChartCode/Community/150030.json`）。就地编辑 `commitBpmEdit`（`src/chart/components/canvas/FinalVirtualCanvas.tsx` L404，`v <= 0` 静默取消）也无法创建负值。

## 根因

校验写于"负 BPM 无意义"的旧假设之上；ADR-0010 已确认它是 Bestdori 的一等语义（时间轴倒流）。

## 修法

1. `validateChartCode` BPM 分支：**放行 `bpm < 0`**；仍拒 `bpm === 0`（含 `-0`）、`NaN`、`±Infinity`。报错文案需区分"必须非零有限数"与"不得为 0"。
2. **新增两条拒绝**（比 Bestdori 严，防无意义/防崩溃）：
   - **beat 0 处的 BPM 不得为负**（会让全谱秒坐标 ≤ 0）；
   - **最后一条 BPM 事件的 `bpm` 必须 `> 0`**（Bestdori 会 `OUT_OF_MEMORY` 崩溃）。
3. `commitBpmEdit`：接受负整数（沿用现有 `parseInt` 口径），拒绝 `0`；明确负数与小数输入规则。
4. 导出往返保真：负值原样写出、不取绝对值、不 clamp、不归一化；`convertNotesToChartCode` 的全局排序改**稳定排序**（同 beat 保持输入顺序）。
5. 术语与文案统一用「倒流区」（`CONTEXT.md`），勿用「倒流段」。
6. **非法结点（用户 2026-09-14 拍板，Q15=B）**：滑条中 beat 非单调的中间结点，**代码保留全量、画布不生效**——渲染与命中按「起点 → 单调中间结点 → 终点」的合法子序列构建（= 实机口径），仅在代码弹窗给出**数量提示**（文案用「非法结点」，**不得出现第三方站名**），一步 undo 可回退。口径见 ADR-0009 §2.2 / ADR-0010 §9，术语入 `CONTEXT.md`。
   - **2026-09-17 实现注（本条已过期，本票跳过）**：该语义已由 [106](./106-SP画笔点序回折废止.md) 落地为**显示投影**（`displayConnections`：稳定排序 + 掐首尾 hidden，数据一字不动，实绘/描边/命中同源，见 `tests/unit/SlideSegments.test.ts`）；**数量提示** 连同谱面状态图标 / 报错区搬迁一并归 [107](./107-非单调点序规范化.md)。术语已由 106 定案改名「非单调点序」并**废除「非法结点」**（`CONTEXT.md` `_Avoid_` 行），故本条不再按原文字面实现。

### 2026-09-17 评审（`/code-review` 双轴：Standards + Spec）

**Spec 轴 · 已修（1 处）**

- `[{beat:0,bpm:-120}]` 这类"全谱唯一一条 BPM、又在 beat 0 为负"的输入会**同时**触发两条边界规则 → 同一条音符列两条同源错误（噪音）。已改为②不报①已报过的同一条（`beatZeroFlagged`），加锁测（`errors` 恰好 1 条）。

**Spec 轴 · 已决策不修（记录理由，非遗漏）**

- **两条边界只在 `validateChartCode`（代码视图 / 导入 / 应用）生效，画布编辑路径不拦**：`commitBpmEdit` 只拒 `0`，`bpmPlaceOps` 沿用 `lastBpm`，故画布上可以做出"beat 0 负值"或"末条为负"的谱面，靠代码视图/应用侧的闸门兜住。理由：
  1. 修法 3 明写就地编辑的口径只有「接受负整数、拒绝 `0`」——两条加严规则写在修法 1/2 的**校验**里；
  2. 编辑器必须允许**瞬时非法态**：正路「先画后折」要在既有滑条两侧插一对 BPM（负 → 正），插完第一条负值那一刻它**就是末条**（谱面原本只有 beat 0 一条 BPM 时必然如此），画布若拦就画不出折返；
  3. 出口闸门 = 代码视图校验 / 应用时整份拒（`ChartCodeEditorModal`）。
  - 若验收后希望画布也拦，**另开票**——「何时拦才不打断先画后折」需要重新拍板语义（建议方向：只在导出/应用时拦，画布最多给提示）。

**Standards 轴**：无硬违规（术语全用「倒流区」、`_Avoid_` 无残留；锁测齐；注释述理由）。两处 judgement call 记录在案：

- `fragment` 用布尔选项（用户 2026-09-17 选定的形态；与"整份默认"组合比两个导出函数更省调用点改动）；
- `NoteCodeOps` 有 5 处需记得传 `{ fragment: true }`——漏传的症状是**该视图误拒中途负值**（不会静默改数据），可接受。
