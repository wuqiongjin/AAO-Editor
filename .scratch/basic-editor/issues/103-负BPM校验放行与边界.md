# 103 · 负 BPM 校验放行与边界

Type: feature
Status: open
Blocked by:

## 来源

[issue 100 负数 BPM 语义](./100-负数BPM语义.md) 定案（2026-09-14），权威 = [ADR-0010](../../../docs/adr/0010-负数BPM与倒流区.md) 结论 1/7/8/9。

## 症状（现状）

`validateChartCode`（`src/chart/editing/ChartConverter.ts` L403-404）以 `bpm <= 0` 拒绝一切非正 BPM → 含负 BPM 的社区谱**打不开**（如 `docs/resource/SampleChartCode/Community/150030.json`）。就地编辑 `commitBpmEdit`（`src/chart/components/canvas/FinalVirtualCanvas.tsx` L404，`v <= 0` 静默取消）也无法创建负值。

## 根因

校验写于"负 BPM 无意义"的旧假设之上；ADR-0010 已确认它是 Bestdori 的一等语义（时间轴倒流）。

## 修法

1. `validateChartCode` BPM 分支：**放行 `bpm < 0`**；仍拒 `bpm === 0`（含 `-0`）、`NaN`、`±Infinity`。报错文案需区分"必须非零有限数"与"不得为 0"。
2. **新增两条拒绝**（比 Bestdori 严，防无意义/防崩溃）：
   - **beat 0 处的 BPM 不得为负**（会让全谱秒坐标 ≤ 0）；
   - **最后一条 BPM 事件的 `bpm` 必须 `> 0`**（Bestdori 会 `OUT_OF_MEMORY` 崩溃）。
3. `commitBpmEdit`：接受负整数（沿用现有 `parseInt` 口径），拒绝 `0`；明确负数与小数输入规则。
4. 导出往返保真：负值原样写出、不取绝对值、不 clamp、不归一化；`convertNotesToChartCode` 的全局排序改**稳定排序**（同 beat 保持输入顺序）。
5. 术语与文案统一用「倒流区」（`CONTEXT.md`），勿用「倒流段」。
6. **非法结点（用户 2026-09-14 拍板，Q15=B）**：滑条中 beat 非单调的中间结点，**代码保留全量、画布不生效**——渲染与命中按「起点 → 单调中间结点 → 终点」的合法子序列构建（= 实机口径），仅在代码弹窗给出**数量提示**（文案用「非法结点」，**不得出现第三方站名**），一步 undo 可回退。口径见 ADR-0009 §2.2 / ADR-0010 §9，术语入 `CONTEXT.md`。

## 锁测

- `tests/unit/ChartConverter.test.ts`：**改写 L210-222**（原断言 `bpm: -1` invalid → 改为通过）；新增 `0` / `-0` / `NaN` / `Infinity` 拒；beat 0 负值拒；末条 BPM 负值拒；负值往返逐元素相等（含同拍多条 + 稳定排序不变序）。
- **真谱回归（谱面文件不入库）**：用 [ADR-0010 附录 A](../../../docs/adr/0010-负数BPM与倒流区.md) 的 **BPM 事件紧凑编码**（49 条）重建时间轴，断言末音符 beat 1160 → 带符号累加 **172.80s**（按 `|bpm|` 应为 309.33s，用作反向哨兵）；另用附录 B 的最小三事件谱做折返带/取解的几何断言。断言只依赖上述编码，不依赖 `docs/resource/SampleChartCode/`（该目录不入库；仓内样本与线上 API 当前版并非同一版本）。
- DOM 输入框（`commitBpmEdit`）→ **静态源码断言**（照 `EditorAudioSessionRefactor.test.ts` 惯例）+ 手工验收。
- 单测（非法结点）：构造含非单调中间结点的滑条 → 断言**代码往返逐元素保留**（含非法结点）、而**渲染/命中用的合法子序列**已剔除它们、提示数量正确、一次 undo 完全回退。
- **Playwright 像素实测**：含非法结点的谱面画布形态 = 按合法子序列重建后的形态。
