# 186 · 片段粘贴与 BPM 模式

Type: feature
Status: resolved
Blocked by: 184, 185

**来源**：[164 片段收藏](./164-片段收藏.md) 定案 §2 / §5；权威 = [ADR-0023](../../../docs/adr/0023-片段收藏的载荷与存储边界.md)。第 3 刀 —— 也是整个功能的价值所在。

**目标**：点卡片能把片段贴进任何**可编辑**谱面，且「带 BPM / 仅音符」当场可切。

**修法**：

- **点卡片 = 进「粘贴」持工具态**，负载来源 = 该片段（**不写剪贴板**）；幽灵预览、单击落点、驻留连续贴、Esc 退出全部**复用**既有 paste 行（`ToolActionMatrix`）。此态下再点工具轨「粘贴」= 回剪贴板来源。退出后剪贴板仍是原来那份。
- **构造粘贴载荷**：`notes` +（带 BPM 时）待写入的 `BpmNote[]`，交给既有 `pasteChartNotes`。ADR-0008 §2.1 已规定 **BPM 不参与锚点计算**，所以直接混进同一数组即可，锚点、lane 夹取、越末端整组拒绝、覆盖/原位替换全走既有规则，**不另写一套**。
- **带 BPM 的写入判定**（目标落点的**生效 BPM** 用 184 抽的公共前驱函数算）：
  - `startBpm` 与目标落点生效 BPM **相同 → 不写**（同速粘贴不长出多余 BPM 横线）；
  - 不同 → 写一条 `BpmNote { beat: anchorBeat, bpm: startBpm }`；
  - `events` 全部按同一 `deltaBeat` 平移写入；同拍已有 BPM 由 `pasteChartNotes` 原位替换；
  - **不缩放数值、不在片段末端补"恢复 BPM"**（尾部负值靠既有末条警示色暴露，ADR-0023 §2）。
- **仅音符**：不发 `BpmNote`，只贴音符。
- **胶囊**：进片段粘贴态时在**画布左上角**出现（照 180 Q15 曲线胶囊）：文案 `含 BPM 变化 · n` / `仅音符`，点开可切，切走工具即消失；**记住上次选择** → `settings.patternPaste.withBpm`（additive，不 bump `schemaVersion`，照 `settings.beatSnap` 先例）。注意：这是**偏好**；片段数据本身仍**不进设置对象**（ADR-0023 §3 只约束后者）。
- **只读谱面**：卡片置灰 + tooltip 说明；点卡片不进态。粘贴执行仍走既有三道闸门（执行键分发 / 画布 imperative / `applyOps`）。

**锁测**：

- `tests/unit/chart/editing/PatternPaste.test.ts`（新增）：同值不写线 / 异值写线、`events` 平移、同拍替换、仅音符一条 BPM 都不写、越末端仍整组拒绝、lane 仍只夹取、锚点结果与剪贴板粘贴**同输入同输出**。
- `tests/unit/chart/patterns/PasteBpmDecision.test.ts`（新增）：目标落点生效 BPM 的取值（同拍多条、落点在首条 BPM 之前）。
- `tests/unit/app/PatternPasteIsolation.test.ts`（新增）：点卡片不改写剪贴板；退出态后工具轨粘贴仍贴剪贴板；片段粘贴可连续两次。
- `tests/dom/workspace/PatternPastePill.test.tsx`（新增）：进态出现 / 切走消失 / 切换后落 settings 且下次沿用。
- `tests/dom/workspace/PatternLibraryDrawer.test.tsx`（改）：只读谱面卡片置灰且点击不进态。
- 幽灵预览与胶囊视觉 → 浏览器手工验收。

## Answer

### 评审修复（2026-10-31 两轴 code-review 后）

两轴评审（Standards / Spec）各挑出几条，已修：

- **真 bug**：幽灵数值的 alpha 被外层工具预览层的 0.35 压暗（`renderBpmGhost` 把 `restore()` 放在了写数字之前）——"同一个位置换个值"直接变成"旧值上浮一层淡影"，也是前几轮反复说"看不见"的另一半原因。现在数值 alpha 归 1。
- 就地编辑中的那条 BPM：幽灵数值也不画（与实线数值同一豁免），避免两个值叠一行。
- 胶囊读屏名带上当前模式（原先 `aria-label` 把 `含 BPM (…)` 整段盖掉，屏幕阅读器只听到"片段粘贴"）——`BpmRange` 里刚写过"别盖父级可读名字"，父级自己又盖了一次。
- CONTEXT 词表未跟着改（`带 BPM / 仅音符` → `含 BPM / 不含 BPM`，胶囊文案改成速度跨度），ADR-0008 同步；`AppSettings` 里一处旧注释、i18n 键 `notesOnly` → `withoutBpm`。
- 删掉没有产品调用方的 `startPatternPaste`（抽屉走 `togglePatternPaste`）。
- 类型收敛：`PatternBpmRange` 命名类型（原先两处内联同形）、`previewGeometry` / `renderBpmGhost` 直接收 `BpmNote[]`（去掉三处 `as` 与一个死守卫）。
- 锁测加强：静态接线锁从 `toContain('pastePattern,')` 收到 `session.bindWorld(…)` 块内；`patternBpmRange` 补并列峰值用例。

**未修（明确记录的取舍）**：幽灵不感知"越末端整组拒绝"（沿用剪贴板粘贴的既有姿态：越界时幽灵照画、点击无反应）；沟槽过窄时数值画不下只剩虚线。

### 六轮（2026-10-31 用户定案：永远对齐，不做让行）

用户明确否掉"对齐 → 上让"的避让机制（跳变副作用大），也否掉"固定偏离线"：

- **数值永远与线同行居中**，且直接复用实线数值那条渲染链（`bpmLabelAnchorY` + `layoutGutterLabel` + `drawGutterLabel`，同字号、同沟槽间距、同配色）—— 于是与既有 BPM 值重叠时"看起来就是同一个位置换了个值"，读得清；不做任何避让。
- 唯一的共用收敛：把数值配色抽成 `bpmLabelColor`（唯一决定处：末条非法负 → 警示 / 负值 → 倒流色 / 其余 → 主题主色），实线数值与幽灵数值都从这里取色 —— 顺手让 issue 105 的"负值取色只有一个消费点"锁更名副其实（原先锁的是 `renderBpmLabels` 内的一处内联三元）。

### 五轮（2026-10-31 用户截图：幽灵 BPM 数值该不该跟线对齐）

结论：**对齐**，撞行才让。理由与规则：

- 数值不跟线走时，两条网格线之间浮着一个数字（行距只有一个字号宽），很容易被读成"上一条线的值" —— 所以默认与线**同一行居中**，与实线 BPM 数值同款。
- 撞行（那一行已经有数字）才让：贴线上方一行。`悬停秒读数` 与 `既有 BPM 值` 都算占用；上方顶到画布外则反向让到线下方。
- **让路只让幽灵**：悬停秒读数是"现在"、幽灵是"将来"，不该被预览挤走；既有 BPM 值也擦不掉。
- 判定收进 `bpmGhostLabelRow`（纯函数，4 例锁测：空行 / 已有 BPM / 悬停读数同行 / 顶到上边缘）。

### 四轮（2026-10-31 用户复测：倒流区幽灵 / 幽灵美观）

1. **倒流区幽灵形状不对**（真 bug，已修）：幽灵的 y 原来按**当前**谱面的 BPM 时间线算，而 BPM 还没写进去 —— 所以永远朝正方向延伸。现在带 BPM 时先用「谱面 BPM + 将写入的 BPM」拼一份**预览几何**（`previewGeometry`，只借它的 timeline；谱面末端由秒数决定、与 BPM 无关，基线不动），幽灵整组按落子后的布局轴画 → 折返形状出得来。开销 = 一次 O(BPM 事件数) 的构建，且只在"确实要写 BPM"的帧发生。
2. **BPM 数字挪进沟槽**：原来贴在轨道内左缘（挤在音符旁边），改为轨道左侧沟槽、右对齐、上移 14px 避开同拍已有数值（与实线数值同一侧，才读得懂"这一拍会写成什么速度"）。
3. **线收敛成幽灵档**：预览亮黄 + 2px 太抢戏（"都叫不上幽灵预览了"），改中性白 `rgba(255,255,255,.86)`、1.5px、虚线 6/4、α .8 —— 看得见但不与选中混淆。
4. **该不该预览 BPM**：该。BPM 决定的是**布局**，不预览 BPM 就没法解释折返（第 1 条就是这个后果）；但只画"会写的那几条"，同速不写线时依旧不画。

锁测：`tests/unit/rendering/render/PatternPasteGhost.test.ts` 扩成 3 例 —— 虚线 + 数值在沟槽、**倒流片段折返**（带 BPM 时第二枚画到锚点下方；不带 BPM 时在上方）、不含 BPM 档一条不画。`tsc -b` 0 / 全量 vitest 365 文件 4012 例全绿 / `vite build` 通过。

### 三轮（2026-10-31 用户复测四条）

1. **幽灵仍看不到 BPM** —— 排查结论与改法：
   - 渲染器侧补了一条锁测（`tests/unit/rendering/render/PatternPasteGhost.test.ts`）：真实 `buildPatternPastePayload` → `shiftGroupToAnchor` → `renderBpmGhost` 这条链在 node 环境**能画出虚线**，说明管线没断。
   - 真问题是**看不见**：原来沿用实线那枚弱紫 + α 0.55 + 1px，且常与既有 BPM 线同 y，等于隐身。改为**预览色**（`SELECTION_COLORS.bright` 亮黄）+ 2px + 虚线 8/5 + **在轨道左内缘写出这条的值**（`-120`），与实线一眼分开。
   - 另注：`含 BPM` 下"与落点同速 → 不写线"是 ADR-0023 §2 的既定规则，此时幽灵**正确地**不画线；`不含 BPM` 档同理。若仍看不到，先看胶囊写的是 `含 BPM (…)` 还是 `不含 BPM`（模式跨会话记住）。

### 二轮（2026-10-31 用户五条反馈）

用户看完第一版后提了五条，逐条定案并改掉：
