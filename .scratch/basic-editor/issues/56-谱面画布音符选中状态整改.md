# 56 · 谱面画布的音符选中状态整改

Type: grilling
Status: open（2026-09-06 用户立案；待本票 grill 定案后作为实现载体）
Blocked by: ~~55~~（**2026-09-07 解除**：55 grill 定案落 ADR-0008，b 项依赖的状态模型已就绪，见文末注释；a/c 本就无阻塞）

## Question

音符"选中"是编辑操作的核心反馈，当前选中态在**视觉**（黄圈丑）、**语义**（选中后工具作用对象不明确）、**悬停反馈**（hover 无选中态近似显示）三层都不到位，需整体整改。

## 当前实现事实（立案盘点）

- **选中特效 = 音符周围画黄圈**：`src/visual/render.ts` `strokeSelectedCircle()`（`strokeStyle: 'yellow'`、`lineWidth 3×scale`、`arc(r = iconSize/2 + 4)`），瓦片内与叠加层 `renderSelectionOverlay`（issue 35 F1）共用同一实现保证逐像素一致；滑条结点另有类似圆环（render.ts L415 附近）。用户判定：**非常丑，需要整改**。
- **选中集合**：`selectedItems`（音符下标/滑条连接/端点集，见 `SelectionEditing`/`computeItemsInBox`）；镜像/复制/剪切/删除等工具态目前是**再点一次目标音符**才执行（`handleMouseUp` 里 `findItemAt` 命中才 `editToolAction`），"已选中的音符"与"工具的作用对象"没有打通。
- **谱面代码编辑器**（issue 37 弹窗）打开时展示全量谱面代码，与画布选区无联动。
- **悬停**：`setHoverPos` 已记录鼠标画布坐标（供放置/粘贴/镜像幽灵预览与 issue 54 实时显示线），但 hover 命中某个已放置音符时，该音符本体**无任何悬停视觉反馈**。

## 整改要求（用户立案原文口径）

**a) 选中态视觉重做**——替换黄圈。候选方向（grill 拍板，可组合）：音符本体提亮/加辉光、按音符轮廓描边（贴合 sprite ink 矩形而非正圆）、四角选择框（transform-box 风格）、配色改主题 token。要求：单键/滑键/技能/方向/长条/滑条结点各类音符形态下都成立；与色觉辅助开关、`noteSize` 缩放兼容；仍在叠加层绘制、不进瓦片缓存键（保持 issue 35 F1 的 0 瓦片重建不变量）。

**b) 选中音符 = 工具的作用对象**——音符被选中后，工具栏各种工具（含谱面代码）直接作用于这组选中音符本身，不再要求逐个点目标；**多选同样成立**。待 grill 细节：类型替换类工具（如选中一组音符点"滑键"= 全部转 flick？走 ADR-0001 覆盖规则吗）；BPM/System 是否可选入此语义；谱面代码的联动形态（打开编辑器滚动/高亮到选中音符 vs 仅显示选中片段）；与 55 的选中态/执行态模型的衔接。

**c) 悬停选中态近似**——鼠标悬浮在已放置的音符上时，该音符显示"选中态的不同透明度版本"：hover 态复用 a 定稿的选中视觉、以较低透明度渲染；与真实选中态、幽灵预览三者视觉层级不混淆。需定：hover 命中判定是否复用 `findItemAt`、多音符重叠时命中顺序、透明度具体数值（可先给默认值后随设置项）。

## 期望产出

grill 定案（视觉规格 + b 的作用对象语义矩阵 + c 的层级规则），随后本票作为实现载体落地；验收含各音符类型 × 缩放 × 明暗主题 × 色觉辅助的目检矩阵。
