# 144 · 画布打开时默认缩放显示 88%（希望是 100%）

Type: grilling（「100%」指数字还是指画面，要先拍板；可能动 ADR-0006 §1 Q4=A）
Status: open
Blocked by: —

## 来源

用户 2026-09-21：「现在谱面画布打开时，默认缩放比例被改成了 88%？希望调成 100%。」

## 现状（代码实测）

- 工具栏数字读的是 UIContext 的 `scale`，**初值就是 1 = 100%**（`UIProvider.tsx:60`）。
- 但 `FinalVirtualCanvas.tsx:778-787` 那条 effect 把**生效值回写**给 `ui.scale`：
  `effective = geometry.effectiveScale(scale)`，而 `effectiveScale = min(scale, surface.w / 228)`
  （`ChartGeometry.ts:144-147`；`228 = LANES(7)×LANE_WIDTH(30) + 2×TRACK_CHROME_TOTAL(9)`，ADR-0006 §1 Q4=A：轨道不超出画布宽）。
- 于是渲染面窄（`surface.w < 228`，例如系统/浏览器缩放 150% 的 1280 窗 + 两侧面板各 300 → 画布约 200px）时，
  打开画布数字**自己从 100% 跳到 88%**（= `w/228`）。
- 这条回写不能整条删：它是 2026-09-10 为修「数字虚高 + 死行程」加的（用户复现过：显示 300%、画面停在 263%，点「−」要先吃掉虚高那截）。

## 附带发现（实测，先记下来）

`effectiveScale = min(scale, surface.w/228)` 在**窄画布**下的副作用不止「数字难看」：
若 `fitWidth < 1`（你的场景 ≈0.88），则请求 1.0~3.0 **全部**被钳到 0.88 ⇒ **点「+」数字不动、画面不动，整个放大功能失效**，
只能缩小。也就是说「88%」不只是显示问题，它还意味着**到不了 100%**。这决定了 Q1 怎么选。

## 我的推荐：A′（A 的完整版）

**把「100%」重新定义为「轨道刚好铺满画布宽」**（基准从「1 虚拟单位 = 1 CSS px」改成 `fitWidth`，几何一行不动、ADR-0006 §1 Q4=A 的钳制语义不变）。

- 默认打开 = **100%**（你想要的），且数字与画面严格 1:1 —— **没有死行程**（点 − 立刻变小）；
- 不裁轨道、不加横向滚动、不动 ADR；
- 代价：放大上限仍是 `fitWidth`（窄画布下**点 + 仍然无效**）—— 见上方附带发现，**这一条不随 A′ 解决**。

**不推荐 B**：允许画面突破 `fitWidth` 到真 100%，窄画布上轨道（210+18=228 虚拟宽 > 200px 画布）会被裁掉约 1/3 条轨道 —— 边上的轨道看不见也点不到，除非再补横向滚动（`ViewportState.scrollX` 有字段、UI 未接）= 大活 + 翻 ADR-0006 §1 Q4=A。收益/代价不成比例。

若你的真实诉求是「我要**画面**更大、点 + 得有用」而不是「数字别显示 88%」→ 那要的是 B，请明说，我另开一条（含横向滚动）。

## 待拍板

- **Q1（主）** 「调成 100%」的诉求是哪一种：
  - A **只要数字显示 100%**：画面仍是 fit 钳制后的大小（轨道随画布宽），只让工具栏别把 88% 回写上去。
    → 实现：只在**超过 `MAX_SCALE`(3)** 时回写（保住修死行程的原意），fitWidth 钳制场景不回写。
  - B **画面真的按 100% 铺**：放宽/去掉 `effectiveScale` 的 fitWidth 钳制 → 窄画布上轨道会超出可视宽（要不要横向滚动？要不要裁？），且这是 **ADR-0006 §1 Q4=A 的翻转**。
  - C 保持现状（88% 是诚实生效值）。
- **Q2**（选 A 时）数字显示 100%、画面被钳制时，点「−」会先吃一段无视觉变化的行程 —— 接受吗？
- **Q3** 双击数字「复原 100%」（`setScale(1)`）的语义是否保持？
- **Q4** 顺带确认：88% 是在什么窗口宽度 / 系统缩放下出现的？（决定要不要顺手调默认面板宽度。）

## 锁测（定案后填实）

- `tests/unit/chart/layout/*`、`tests/unit/chart/geometry/*`：`effectiveScale` 的钳制行为**不得**被 A 方案改动（A 只动 React 回写，不动几何）。若选 B，这里必须同步改并写明新口径。
- 回写条件本身在组件 effect 里、单测碰不到 → `tests/static/` 静态源码断言（照 `EditorAudioSessionRefactor.test.ts` / `SlideFlickDecorator.test.ts` 惯例）：
  锁「`setScale` 的回写被 `>` 上限的守卫包住 / 或不再无条件回写 effective」。
- 手工验收：窄窗口打开工作台 → 工具栏显示 100%；点 +/− 无死行程；切页回来数字不跳。
