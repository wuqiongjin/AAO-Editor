# 87 · 浏览器缩放时谱面画布"抢栏 / 外弹"再回弹

Type: bug
Status: resolved（2026-09-11 实测定位 + 修复，待你在页面验收）
Blocked by:

## 来源

用户 2026-09-11 报：工作台页**对网页本身缩放**（非谱面画布缩放）时出现问题，第二次复报给出准确症状：

> 在 100% 向更大的比例放大时，每执行一次放大，谱面画布的宽度会先抢占掉左侧栏和右侧栏的区域，
> 然后谱面画布的宽度会被迫回弹回来。

操作方式确认 = **Ctrl + 加号/减号**（用户 2026-09-11）。

## 症状

放大一步：画布宽度先"抢"进左右栏的空间，随后被挤回；缩小时相反（先留黑边再补上）。放大时最明显。

## 根因（Playwright 逐帧实测：两条独立缺陷）

### ① 面板的「视口夹取」被 200ms width 过渡拖慢 —— 用户看到的"抢栏 + 回弹"

面板宽度 = `min(用户宽度（持久化 px）, innerWidth × ratio)`（`Editor.tsx`），
而 `.ws-panel { transition: width 200ms }`（`AppShell.css`）—— **任何** width 变化都被拖成 200ms，
包括浏览器缩放导致的夹取生效。实测（在 chartArea 的 RO 回调内逐次采样）：

```
innerW=1160   leftW 380→379→372→359→352      rightW 300→…→281   areaW 428→429→441→463→474
              └──────── 面板在 200ms 里"慢慢让出空间" ────────┘
```

即：视口先把容器压掉 120px（画布瞬间变窄）→ 面板 200ms 后才让出空间 → 画布再长回 46px。
缩放本是"与视口同帧"的事，却被塞进了一条 200ms 动画。

### ② RO 回调 → React 异步渲染「晚一帧」（独立缺陷）

`canvas` 的 CSS 尺寸 = `surf.w`，而 `surf` 来自 RO 回调里的 `setSurface`。用**异步** setState 时，
React 要到下一帧才改到 canvas 尺寸 → 缩放瞬间"容器已变、画布仍停旧 surf"
（实测：容器 428 / 画布 548，差 **+120px**，下一帧才归零）。

## 修法

| 缺陷 | 修法 |
| --- | --- |
| ① | 视口夹取从 JS 挪到 **CSS `max-width`**：`.ws-panel-left { max-width: 30vw }` / `.ws-panel-right { max-width: 24vw }`（AppShell.css）。`max-width` **不在 transition 列表**（过渡只声明了 `width`）→ 视口驱动的夹取**瞬时生效、与缩放同帧**；折叠/展开（改 `width`）仍照常 200ms 过渡。`Editor.tsx` 只注入用户宽度，不再读 `window.innerWidth` |
| ② | `useSurfaceSize` 的提交改 **`flushSync(() => setSurface(v))`** —— RO 回调在 paint 之前，flushSync 让 React 在该回调内同步渲染完，画布尺寸与容器**同帧对齐**。安全性：画布在 `position: sticky` 的离屏包裹内、不参与 chartArea 的尺寸计算 → 不触发 RO 循环告警 |

保留：`src/chart/layout/zoomLiveTracker.ts`（dpr 变化 → 实时窗口期；连续缩放 / 触控板 pinch 时防 merger 冻结）。

## 锁测

1. `tests/unit/BrowserZoomLive.test.ts`（8 例）
   - 探针纯逻辑：首帧不布防 / dpr 不变（窗口拖拽）不布防 / dpr 变化 → 窗口期内 live 且过期失效 / 同 dpr 不续期；
   - 结构断言（防接线被拆）：`useSurfaceSize` 必须把探针并入 merger 的 live 探针、提交必须是 `flushSync`；
     **视口夹取必须是 CSS `max-width: 30vw/24vw`**，且 Editor **不得**再用 `innerWidth` 算面板宽度
     （夹取一旦回到 JS 就会重走 200ms width 过渡 → 症状复现）。
2. `tests/unit/SurfaceSizeMerger.test.ts`：`live()=true` 逐帧提交 / `live()=false` 尾随合并（原有用例保持绿）。
3. DOM 时序单测碰不到 → **Playwright 实测**（`scripts/measure-browser-zoom.mjs`，按仓库惯例不入库）：
   用 `Emulation.setDeviceMetricsOverride` 同时改 CSS 宽与 `deviceScaleFactor` 模拟浏览器缩放；
   **在 chartArea 的 RO 回调内**逐帧比 `canvas.getBoundingClientRect().width` 与容器宽。
   > 量测口径教训：在 **rAF** 里采样 `clientWidth` 会**预读**尚未提交的布局（rAF 在 layout / RO 之前），
   > 测出的"错位"有一部分从未被 paint —— 必须用 **RO 回调口径**。

### 实测结果

| | RO 回调次数 | 错位帧（\|canvas − area\| > 1.5px） |
| --- | --- | --- |
| ② 修前（异步 setState） | 74 | **56**（最差 +136px） |
| ② 修后（flushSync） | 61 / 65（两次） | **0**（≤0.5px，纯取整） |
| ① 修前（JS 夹取 + 200ms 过渡） | 39 | 每步一串中间态 |
| ① 修后（CSS max-width） | **4**（每步 1 次，一步到位） | **0** |

折叠/展开回归（RO 口径逐帧）：`34→40→64→116→193→258→303→332→353→366→374→379→380`
（21 档宽度 = 200ms 动画仍在），全程 **max |canvas − area| = 0.00px**。
