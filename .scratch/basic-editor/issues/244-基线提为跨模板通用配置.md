# 244 基线提为跨模板通用配置

- **Type**: grilling
- **Status**: resolved（定案于 2026-11-21 复核；2026-11-21 已实现）
- **关联**: [ADR-0009](../../../docs/adr/0009-SP绿条与段曲线模型.md) · [CONTEXT.md](../../../CONTEXT.md) · 前置 [240](./240-形状模板阶梯端点插值与专属配置项.md) · [243](./243-形状模板振荡基线偏移.md) · 后续 [245](./245-胶囊摘要默认值占位与居中撞词.md)

---

## 来源

用户复核曲线胶囊面板的配置项作用域（问题 1b）：243 把「振荡基线」做成了模板专属 `extraParams`，于是它按模板 ID 各记各的值，切模板就归零；而同一层的偏向 / 幅度 / 段密都是 `CurveConfig` 上的单值，切模板不归零。同一类参数两套记忆口径。

同批的 1a（偏向对部分模板无意义）用户确认**保留现状**，依据与结论见文末「范围外」。

---

## 现状与根因

1. **存储分叉**（`src/chart/editing/CurveTool.ts:37-41`）：`templateMirrored / templateScale / templateDensity` 是 `CurveConfig` 单值；`baseline` 落在 `templateExtras[模板 id].baseline`。
2. **落点三套口径**（同文件 `spanParamFromCurveConfig:100-124`）：前三个各有一条能力 gate（`templateSupportsMirror` / `templateSupportsAmplitude` / `adjustableDensity`）才写进 `SpanParam`；基线只能走 `stripDefaultTemplateExtra` 的 extra 白名单，没有 gate 可表达。
3. **声明是重复的**（`ShapeTemplates.ts:266-282`）：6 款模板引用同一个 `OSCILLATION_BASELINE_SPEC`，逐字段相同（−200…200 / step 5 / `%` / `贴左|居中|贴右` / `mirrorValue` 取反）；唯一差异 `oscillationHalf` 是**模板几何**，不是用户配置。
4. **数值语义本来就是共通量**：`±100%` 在每一款都等于「该模板峰值贴弦」，因为 `half` 就是按各款 `|off|` 峰值定义的（`relativeChordOffset`）。「贴右」跨模板是同一句话，只是绝对位移量随模板变。

结论：这是被 240 的 extra 机制顺手装进去的通用几何参数，语义该和偏向/幅度/段密同层。

---

## 定案（用户 2026-11-21 拍板）

1. `CurveConfig` 增加 **`templateBaseline?: number`** 单值，默认 `0`，范围 `-200…200`、步长 `5`，跨模板共享（切模板不归零）。
2. **段上仍写 `extra.baseline`**：`SpanParam` / 烘焙 / 旧谱读取路径零变化，不升 `schemaVersion`。
3. 面板行仍按模板声明渲染（只有 6 款有 `baseline`）；读写改走 `templateBaseline`，不再写 `templateExtras[].baseline`。
4. 旧记忆迁移：`normalizeCurveConfig` 把旧 `templateExtras[id].baseline` 提为 `templateBaseline`——优先当前 `templateId` 的记忆值，其次按对象键序取第一个非零值；迁移后从 extras 里删掉该键。
5. 摘要 / 迷你 SVG / 段参数三处都按「能力 gate + 单值」读取，与偏向/幅度/段密同构。

---

## 实现落点

1. **模型**（`CurveTool.ts`）：`CurveConfig` + `DEFAULT_CURVE_CONFIG` + `normalizeCurveConfig`（clamp 到 `TEMPLATE_BASELINE_RANGE`，步长 5，迁移逻辑见定案 4）；`spanParamFromCurveConfig` 在模板声明了 `baseline` 时把非默认值并入 `param.extra`（与其它 extra 合并，不覆盖）。
2. **能力判定**（`ShapeTemplates.ts`）：把「该模板是否声明 baseline」收敛成一个谓词（如 `templateSupportsBaseline`），供面板/摘要/段参数共用；`oscillationHalf` 保持模板自有。
3. **面板**（`CurveConfigPanel.tsx:296-308,455-463`）：`ExtraParamRow` 对 `key === 'baseline'` 的 range 项改读写 `config.templateBaseline`，其它 extra 路径不动。
4. **摘要 / 预览**（`curveLabels.ts:68`、`CurveConfigPanel.tsx:378`、`CurveOptionsCapsule.tsx:100`）：resolve 前把单值塞进 extra 视图，避免三处各写一套特判。
5. **ADR-0009**：追加一轮，记「基线是通用几何参数、跨模板共享；extra 只保留模板自有语义（如 `pulsePos`）」。

---

## 锁测

1. **配置（`CurveTool.test.ts`）**：`templateBaseline` 越界钳进 ±200、步长 5；切模板后值保留；默认 0 不写进 `SpanParam`；非 0 时 `param.extra.baseline` 正确；迁移——旧 extras 只有 A 模板有 `baseline` 且当前是 B 模板时，按键序取到 A 的值且 extras 中该键被清除。
2. **几何回归（`ShapeTemplates.test.ts` / `SpanCurve.test.ts`）**：同一 `templateBaseline = 100` 在 6 款上各自贴弦（该侧 `off` 等效 0）、峰峰值不变；与 243 已锁用例逐点对齐（此票不得改烘焙结果）。
3. **DOM（`CurveOptionsCapsule.test.tsx`）**：切模板后基线行显示同一值；摘要仍由 245 的口径输出。

## 范围外：偏向（1a，用户确认保留现状）

`templateSupportsMirror` 对 18 款中 17 款为 true（`step` 因端点插值显式 false，240 口径）。按各款 `sample()` 点列实测分两类：

- **高频交替型 6 款**（震动条、余震条、面筋·螺旋、面筋·斜纹、锁链·方波、锁链·拉链）：offsets 是 `±A` 交替，取反 = 齿换边 + 齿序平移半齿；画面差别集中在首颗齿朝哪边与首尾半齿。
- **连续型 11 款**：取反是真正的上下翻转（同一时刻由 `+1` 变 `−1`），形状明确不同。

所以「偏向对部分模板没意义」只在 6 款上成立，且是否在意起手方向取决于排谱习惯——用户 2026-11-21 确认**保留**，不改 `supportsMirror`、不隐藏该行。本票不动偏向。

## Comments

- **2026-11-21 复核与定案**：用户提出「基线做成独立配置项意味着每个模板的基线不互通」。核对后确认 `templateMirrored / templateScale / templateDensity` 均为 `CurveConfig` 单值且各有能力 gate，唯 `baseline` 走 `templateExtras`；6 款 `OSCILLATION_BASELINE_SPEC` 逐字段相同。用户选定「提为通用单值」，并要求旧谱与烘焙路径零变化。同批的偏向问题（1a）经量化后用户确认保留现状，记入「范围外」。
- **2026-11-21 实现**：
  - 模型：`CurveConfig.templateBaseline`（默认 `0`）+ `normalizeCurveConfig` 钳制/步长吸附；`resolveTemplateBaseline` 迁移旧 `templateExtras[id].baseline`（当前模板优先 → 对象键序首个非零值），迁移后从 extras 剔除。新增 `curveConfigExtraView` 统一「配置 → extra 视图」。
