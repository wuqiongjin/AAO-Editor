## 症状（2026-09-15 更正）

1. **画笔「回头」的语义是「冻结」，且方向不对称**：自下向上画时回头 → 预览末端取「最后一个采样点」（`FinalVirtualCanvas.tsx` L671），笔迹回不去；自上向下画时回头 → 预览末端取**实时光标**（L672-681），松手点越过起点还会走 `fwd` 分支把**降序采样**接在起点之后，**落出非单调点序**（L738-746）。
2. 原「症状 / 根因」把实机口径说成「忽略不单调的中间结点」，并据此规定「回头只停止追加」——**机理错**（见下），也与用户真实诉求（禁止回头、不让画笔产出非单调滑条）对不上。

## 根因

1. **落子分支按「松手点 vs 起点」两分，而不是按锁定方向收口**：`penAppendSamples` 回头返回空数组（`CanvasGesture.ts` L324-325），但提交侧只有 `fwd` / `bwd` 两条分支，于是「上→下 + 松手越过起点」从 `fwd` 漏出折返；`bwd` 分支的预览又拿实时光标当端点，回头期间预览出折返（预览与落子两套口径）。
2. **实机口径抄错了**：实机做的**不是「忽略中间结点」**，而是「**按 beat 稳定排序 + 掐掉首尾 hidden**」（仓内 vendored 参考实现 `docs/plans/external/sonolus-bandori-engine/lib/src/bestdori/convert.ts` L325-355 的 `repair()`），随后**按时间轴铺带**——带子永不回头。像素实测（三张截图，逐行统计绿色带分支数）：
   - **图1**：排序后中间结点全部早于起点 → 被首部裁掉 → 画布上是**一条直线**（看起来像「被忽略」）；我们＝数组序原样 → 折返。
   - **图2**：夹在中间的结点**保留并生效**，只表现为**横向折线/跳步**、全程无回头；我们＝折返。
   - **4 点判定实验**（`[1,L0] → [1.5,L2,h] → [1.25,L5,h] → [2,L6]`）：实机折点落在 bbox **25% / 50%** 高度，与「排序后渲染」逐点吻合（按 lane 映射预测 L2=37%、L5=68%，实测 38%、64%）——**「丢弃非法点」模型被排除**。
3. **导入比实机更严**：`validateChartCode`（`ChartConverter.ts` L444-469）对 `connections.length < 2`、首/尾 hidden **整份拒收**，而实机是**按可见结点退化**（1 个 → 当单键；0 个 → 渲染不出来、但代码里仍留着）——别人的谱我们直接打不开。

## 定案（用户 2026-09-15）

### 一、产出侧：画笔禁止回头（Q1 / Q10=甲）

- **回头不追加**（保留现状）：锁定方向后反向位移不产点。
- **回头不改变产出**：落子终点 = 「松手吸附拍位」与「锁定方向上最远采样点」中**沿锁定方向更远者**；`pen.last` 不再跟随光标，ADR 旧文「恢复同向时从折返点续采」**废止**。
- **预览 = 落子**：回头期间预览冻结在最远点、**永不画出折返**（删掉用实时光标当端点的构造）。
- 顺带消掉两个历史漏洞：①「上→下 松手越过起点 → 落出折返」；②「下→上 松手落在起点之下 → 整笔作废」。
- **不做回撤**（用户判定「行为怪、吃力不讨好」）：回头期间笔迹不跟手回收。代价（接受）：画过头不能靠退回收短——undo 重画，或落子后用指针拖端点/拖带整形。
- **倒画（从高拍向低拍）保留**；越界冻结、平滑开关、预览/命中同源规则不变。
- **跨倒流区/跨层跳变步「不补中间点」（原修法 6）+ 判据（2026-09-15 定，用户确认）**：判据 = **这一帧的 Δ 拍与 Δ 画布 y 不自洽**——按光标所在层的 BPM 算出「这段 y 位移最多能跨多少拍」，若 `|Δbeat|` 明显超出该上限 → **跨层**（beat 跳过了 y 上根本不存在的区间）→ **只把当前光标接为下一个采样点、跳过补点**；快速甩笔 Δy 同样大、上限也大 → 不会被误判，照常插值补点。

### 二、解释侧：只做「显示投影」（数据原样；无可见结点的滑条除外）（Q7 / Q13=乙 / Q14=乙 / Q15）

- **口径**：外部进来的非单调点序**代码原样保留**（代码弹窗、导出、往返全保真，不凭空产生 diff——回到 ADR-0010 §9 的既有精神），只有**画布**按实机口径显示。
- **唯一读取口径 = 显示投影**：新增纯函数 `displayConnections(connections)` ＝ **按 beat 稳定排序 + 掐掉首尾 hidden**（= `repair()` 的前两步）。**所有「读出来画 / 算带子」的地方都从它取点**：实绘（`renderSpanBands`）、选中·hover 描边（`collectSelectionOutlines`）、命中区（`hitTest.slideRegion`）；幽灵、瓦片缓存、以及今后的**完整谱面预览 / 播放模拟**都走这些入口，自动跟随。与 `slideBandGeometry` 同族「唯一定义处」（旁路另写一份连线实现会让单测变红）。
- **不动的部分**：数据层、段与参数、拖带权重、删结点、`planDragMove`、代码弹窗、导出 —— 仍按数组序（= 今天的契约）。**排序只改「怎么连」，不改点位置**：结点把手仍在数据真实位置、带子仍穿过全部把手；且外部导入的滑条必然是**自由段（无参数）**，所以「数据段 vs 显示段」的分叉只影响重烘焙，对它不适用。
- **可见结点不足的退化（Q14=乙；2026-09-15 再校正：一律不动数据）**：可见 **1 个** → **按单键形态显示**（数据仍是滑条，可选中、可删；`flick` / `skill` 标记照常画）；可见 **0 个** → **数据原样保留、画布上没有任何效果**（实机也只是显示不出来，**不会把它从谱面代码里删掉**）——改由**谱面状态图标**告知（明细计入「K 条无可见结点」），要清理请去代码编辑器改。据此**不再整份拒收**原先那两条（`connections.length < 2`、首/尾 hidden）——它们只在「可见 ≤1」时出现，正好由上面两条接住；我们自己仍**产不出**这种数据（删结点转 hidden / 拆条 / 组合 / 烘焙 / 画笔均保可见 ≥2）。**本票无任何一处修改用户数据。**
- **谱面状态图标 + 报错区搬迁 → 已移入 [107](./107-非单调点序规范化.md)**（2026-09-15 用户定：它是「规范化」的入口，跟规范化同一票；本票只负责把数据 / 画布口径做对）。
- **「规范化」动作（本期不做，另开 [107](./107-非单调点序规范化.md)）**：状态为「需按实机口径显示」时，在弹窗里一键**把同一套口径写回数据**（排序 + 掐首尾 hidden + 退化单键 + 丢弃，二次确认 + 一步 undo）。届时写回版与显示版共用同一个纯模块，本票的显示投影不动。
- **术语**：`非法结点` → **`非单调点序`**（判决词退出）。

### 三、不变的部分

- **折返的唯一合法来路仍是倒流区**（ADR-0010）；「先画后折」仍是主产图通道。
- `splitBandAtFolds` 保留，只服务**倒流区造成的布局折返**（非单调点序的显示改走投影，不再按数组序画折返）；ADR-0009 §5 依据不变。
- 同拍横向段（beat 相等）合法：实机（按时间轴铺）与我们（零面积不画不中）都不会把它画成有宽度的带子——两边一致，无动作。

## 锁测

- **单测（显示投影，锁表）**：图1 案例 → 投影后 = 2 个结点（直线）；图2 / 4 点实验 → 投影后 = **稳定排序**后的点序（同 beat 保持输入顺序）；首 / 尾 hidden 被投影掐掉；**投影不改输入数组**（纯函数、无副作用）。
- **单测（可见结点不足）**：`[{1,hidden},{2}]` / `[{2},{3,hidden}]` / `[{1,hidden},{2},{3,hidden}]` → 通过校验、渲染层判为「按单键显示」；`[{1,hidden},{2,hidden}]` → 判为「无可见结点 → 画布无效果」且**断言传入的 notes 数组逐元素不变**（本票不改用户数据）；beat 非有限数仍走校验拒收。
- **单测（跨层判据）**：Δbeat 超出「本帧 Δy 上限」→ 判为跨层（不补点）；Δy 与 Δbeat 自洽（快速甩笔）→ 正常插值补点。

## Comments

### 原文存档（2026-09-14 版；以下结论**已被上文推翻**，保留作事实存档）

> # 106 · SP 画笔点序回折废止（折返只能来自倒流区）
>
> Type: bug / Status: open / Blocked by: 104
>
> **来源**：issue 100 定案后的 Round 5 追问（2026-09-14，用户拍板 **Q13=A**）；连带修订 ADR-0009 §2.2 / §5。
>
> **症状**：ADR-0009 §2.2 允许「画笔方向锁定后中途折返 → 采样序列拍位回折」，并据此在 §5 做了回折自叠渲染（`splitBandAtFolds`）。但 **Bestdori 会忽略掉这些不单调的中间结点**，以「起点 → 单调的中间结点 → 终点」重建一条合法 Slide —— 即：我们编辑器里画出的这个折返**在实机根本不存在**。用例照着编辑器做，实机拿到的是一条被削平/少点的滑条。
> 数据佐证：仓内 11 份样本（社区 3 + 官方 8，合计 ≈**1943** 条 Slide/Long）**非单调点序 0 例**；`150030` 的 232 条滑条全部单调，折返纯粹来自负 BPM。
>
> **根因**：ADR-0009 §2.2 的实测只验证了「Bestdori 能导入这类代码」，未验证「Bestdori 会把这个折返渲染出来」——把一个**导入容错**误当成了**渲染能力**。
>
> **修法**（1~6 条原文）：① 画笔方向锁定后回头 → 只停止追加，不产生 beat 倒退；② 折返一律由倒流区产生；③ 曲线工具两击直放预览按折返几何显示；④ ADR-0009 修订；⑤ 折返产图通道 = 先画后折（+ 跨区段烘焙/模板）；⑥ 画笔跨层 = 直接接续、不补点。
>
> **锁测**（原文）：画笔折返不再出现 beat 倒退；`splitBandAtFolds` 在「点序单调 + 布局 y 折返」下正确；跨倒流区烘焙；光标跳变不补点；先画后折主通道；Playwright 像素实测；手工验收。
