## 症状

1. `FinalVirtualCanvas.tsx` 1048 行里内联着**整套操作编排**：
   `handleMouseDown:460` / `handlePointerMove:509` / `handlePointerUp:564` /
   `handleToolClick:599` / `handleDoubleClick:612` / `handleContextMenu:627` /
   `applyBoxAction:363` / `applyOps:275` / `beginDragCandidate:418` / `snapPos:268`。
   4px 阈值仲裁、单击/框选/拖拽三条通路的分派、Slide 锚点生命周期全在这一个组件里。
2. **编排层零测试**。`tests/` 里没有任何一个文件 import `FinalVirtualCanvas`、
   `handleToolClick`、`beginDragCandidate`、`applyOps`。被 ADR-0008 §9「规则表逐行落单测锁表」
   锁住的只有它们调用的**纯规则核心**（`ToolActionMatrix` / `NoteReplacementRules` / `SlideCombination`）。
   → 改编排 = 无网作业，只能凭手感验收。
3. **两条通路绕过分派矩阵**（leakage）：
   - `handleContextMenu:640` 右键删除直连 `deleteSelection`，不走 `ToolActionMatrix`；
   - 粘贴有两个入口：`ToolActionMatrix:184` 与 `EditingProvider:110`，各自调 `pasteChartNotes`。
4. **光标 / 视口 / 起点标记各有两份 state，双向同步**：
   - `hoverPos`（画布 px，`FinalVirtualCanvas:198`）↔ `UIProvider.mousePosition`（beat/lane，`UIProvider.tsx:50`）——
     每次 mousemove 各写一次（`:517`、`:521`）；
   - `viewport.scale` ↔ `ui.scale` —— 三个同步 effect（`:152` / `:841` / `:895`）+ wheel 回写（`:746`）；
   - `markerBeat`（`:200`）↔ `PlaybackProvider.markerBeat`（`:31`）—— 推过去后从未读回。
   `Editor.tsx:285-288` 已为此打了 workaround 注释（`mousePosition` 每次 move 换新引用 → 改走 ref），
   说明这是**已知并且被绕过**的问题，不是理论风险。
   历史上 issue 10 / 36 / 55 的漂移类缺陷全部出自这条缝。

## 根因

操作的**编排层**（手势状态机）与**宿主**（React 组件 + DOM 事件 + 绘制）没有 seam。
组件既当输入设备适配器，又当语义决策者，又当绘制发起者——于是：

- 语义决策无法脱离 DOM 测试（症状 2）；
- 同一个语义（粘贴 / 删除）因为"从哪进来"不同而有两条实现（症状 3）；
- 坐标需要在"画布 px"与"谱面 beat/lane"之间来回搬，搬的过程中长出三份互相同步的 state（症状 4）。

## 不变量（行为保持，逐条人工 + 单测覆盖）

> 用户明确要求"不能影响功能"。以下每一条在重构前后都必须成立。

**单击通路**
1. 单击语义矩阵（ADR-0008 §2）逐格不变：指针 / 键型 / BPM / Slide / 删除 / 镜像 / 粘贴 / 音符代码 八族行为一致。
2. §2 原则 6「非指针态单击画布即清选区」及其五条例外（镜像、粘贴、批量后、拖拽后、复制后、音符代码态）逐条一致。
3. BPM 判定次序恒定：音符 / 方向键 / 滑条结点 / 滑条段 → 最后 BPM 线（`findItemAt` 完全跳过 BPM）。

**框选通路**
4. 框选语义矩阵（ADR-0008 §2）逐格不变；BPM 的 X+Y 完整覆盖判据不变。
5. 框选矩形以虚拟坐标锚定（bug 32：滚动中起点不漂移）；越出画布钳进渲染面（issue 63）。

**拖拽通路**
6. 4px 阈值仲裁：<4px = 单击，≥4px = 拖拽（ADR-0008 §2 原则 1）。
7. 落点裁决表（ADR-0008 §6）逐格不变；任一件不可裁决 = 整体回弹。
8. 提交用按下时的锚点快照（issue 55 三轮修复：先清 `dragRef` 再算位移 = 恒回弹）。
9. 拖拽中光标 = `grabbing`；出界幽灵消失、松手回弹（issue 66 §4a：轨道外仍算位移）。

**Slide**
10. 两击直放 + 框选组合双路径；锚点取消边界（issue 65②）逐条一致——含「起手框选立即清锚点、拖拽音符不清」。
11. 形态归一表与 K 路保序归并（ADR-0008 §4）逐条一致（已有单测锁表，不得改）。

**执行键 / 键盘**
12. 执行键与鼠标**共用同一条通路**（§3：`Ctrl+F/G/A/S/D` 与单击共用 `clickOps`）。
13. Esc 四档链（弹窗 → Slide 锚点 → 清选区 → 落指针）顺序与"只吃一档"不变。

**其它**
14. 右键删除行为不变（收敛到矩阵后语义必须等价）。
15. 粘贴两入口合并后行为不变（锚点 = 包围盒左上角、越界钳制保持组宽）。
16. 撤销快照粒度不变（ADR-0001 §4 结构共享；`pushHistoryIfChanged` 的相等判据不变）。
17. 谱面代码弹窗（issue 59）与就地编辑（§5）不受影响。

## 切片 2：右键删除收敛进矩阵（2026-09-10，已实现）

`handleContextMenu` 原样直连 `deleteSelection`，与「删除工具点音符」是同一语义的两份实现。
现改为复用矩阵导出的 `actionOnItemOps('delete', notes, hit)`：

- `ToolActionMatrix.actionOnItemOps` 由私有改导出（语义不变，仅可见性）。
- 画布侧保留**只属于 UI 态**的两行清理（Slide 锚点 / BPM 就地编辑框）——它们悬垂在已消失对象上，
  不属于矩阵的谱面语义，不进 op。

**等价性**：原实现 `handleNotesChange(deleteSelection(notes,[hit])) + setSelectedItems([])`；
矩阵产出 `[{setNotes: deleteSelection(notes,[hit])}, {setSelection: []}]` → `applyOps` 执行同样两步。逐字等价。

**锁表**：`ToolActionMatrix.test.ts` 增 3 例，钉住「右键删除 ≡ 删除工具点音符」、
BPM 线可删、以及 delete/mirror 的 op **次序不可互换**（delete 先 notes 后 selection，mirror 反之）。

**验证**：`tsc -b` 0 错误；`vitest` **749 通过 / 47 文件**（746 + 3 新增，零回归）；
`eslint` 新增文件 0 error（5 条 `no-explicit-any` 在既有行 65/177/178/185/204，非本次引入）。

## 更正：原「粘贴两个入口」不是 leak，撤回

评审报告与切片 1 把「粘贴有 `ToolActionMatrix:184` 与 `EditingProvider:110` 两个入口」列为 leak。
**读码后撤回**：两者调用的是**同一个** `pasteChartNotes`（`NoteReplacementRules:544`），
覆写决策没有第二份拷贝，只有 `setNotes + setSelection` 两行 op 序列被写了两次。

且两条通路语义**按设计不同**（ADR-0008）：
- 粘贴**工具单击**：落点非法 / 空剪贴板 → `[clearSel]`（§2 原则 6）
- **Ctrl+V 执行键**：空剪贴板 → 直接 return，不清选区（§3「无事发生」）

强行合并会改变行为，与"不能影响功能"冲突。**不做**。

> 教训（记给后续评审）：「两个调用点」≠「两份实现」。判据应是**决策是否被复制**，不是入口有几个。
