# 78 · 轨道横线（虚线）右端比左端多出一段间隙

Type: bug（视觉）
Status: resolved（2026-09-10 实现 + 锁测，待你在页面目检）
Blocked by:

## 来源

用户 2026-09-10 清单 #10 + 截图。用户确认：**指的是横线（拍线 / 子拍线虚线）** ——
左侧最后一节虚线正好与轨道左缘衔接，右侧最后一节留了一段间隙。

## 症状

虚线横线左端贴住轨道左缘（`trackBgX`），右端在到达轨道右缘（`trackBgX + trackBgWidth`）前就断了，
缺一小段；缺多少随缩放 / 窗口宽度变化。

## 根因（已定位）

`src/visual/render.ts:164-181`：横线路径 = `moveTo(trackBgX, y) → lineTo(trackBgX + trackBgWidth, y)`，
再 `setLineDash(gridLineDash(tier, lineShapeTiers, es))`
（`src/visual/gridStyle.ts:109-114`：未开线形分层时非整拍统一 `[4, 6] * es`，即 dash 4·es + gap 6·es，**周期 p = 10·es**）。

虚线相位**从路径起点计**：

- 左端 `d = 0` 落在 dash 内 → 有墨，贴边；
- 右端 `d = L = trackBgWidth = 210·es`，而 `210·es mod 10·es = 0` → 恰好落在「下一段 dash 的起点」，
  于是末端之前的 `[L − gap, L)` 是空档 → **右端缺 gap（6·es）**。这就是截图里的间隙。

整拍线是实线（`dash === null`）不受影响；开了 `lineShapeTiers` 的档位同样按各自 dash 表受影响。

## 定案（用户 2026-09-10 选定）

**两端都贴边** —— 给虚线设 `lineDashOffset = dash[0] / 2`（半个 dash 长）。
因 `L ≡ 0 (mod p)`（210·es 恰好 21 个周期），该偏移使**左右端相位完全相同**：两端都有 dash 覆盖到边缘。

（未采纳备选：两端各内缩 `gap / 2` 且 `offset = 0` —— 两端各留半个空档。）

## 实现落点

| 文件 | 改动 |
| --- | --- |
| `src/visual/render.ts` | 横线绘制段：设 `ctx.lineDashOffset = dash[0] / 2`（实线档为 0），循环后复位；若走备选则同时把起终点 x 各内缩 `gap / 2` |

> 注意：`lineDashOffset` 是 ctx 状态，绘制完必须复位（与 `setLineDash([])` 处一起），
> 否则会污染后续 `renderBoundLines` 等虚线绘制。

## 锁测

`tests/unit/GridStyle.test.ts`（现有用例只断言横线**起点** x）：

- 新增：`lineDashOffset === dash[0] / 2`（虚线档；实线档为 0）；
- 新增：按 `offset` 推算，**左端点与右端点都落在 dash 覆盖内**（两端相位差为 0）——
  即"右端不再缺一段"的直接断言；
- 既有端点断言扩成左右两端（若走备选方案则断言两端各内缩 `gap / 2`）。

纯视觉差异单测只能锁参数，最终以你在页面上目检确认（左右端最后一个 dash 都贴住轨道边缘）。
