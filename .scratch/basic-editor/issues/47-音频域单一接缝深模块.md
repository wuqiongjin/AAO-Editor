# 47 音频域单一接缝·深模块

- **状态**：resolved（2026-08-29，架构深化评审候选 3 收口）

## 背景

承接架构深化评审 `/tmp/architecture-review-20260829-112731.html` 候选 3：
- **问题**："音频"是一个领域概念（`CONTEXT.md` 音频域），却拆成 4 份——设置（`ConfigContext.audio`）/ 时长（`PlaybackContext.duration`）/ 引擎+文件（`useAudioBridge`）/ 页面桥（`AudioPageContext`）。`AudioPageContext` 这条桥正是接缝错位的显形：工作台注册 api 字段、音频页通过 context 拿，桥上的 7 个字段跨 2 个 React 树。
- **目标**：建一个音频会话深模块（引擎 + 文件 + 时长 + 键音/SE + 页面契约），音频页与播放条都朝它调用，桥消失；引擎可 local-substitutable 注入假实现做单测。

## 既有铺垫（候选 1 / 2 已落地）

- 候选 1：`PlaybackScrollModel` 把秒↔scrollY 收敛到深模块（issue 45）。
- 候选 2：Editor 6 种会话流拆到 `useSurfaceSize` / `useScrollModel` / `useAudioBridge` / `usePlaybackCoordinator` / `useChartProjectPersistence` / `useLayoutPersistence` / `useShortcutDispatch` 7 个聚焦 hook（issue 46）。
- 但**音频桥本身**仍散——`useAudioBridge` 注册 7 字段 api 到 `AudioPageContext`，每次状态变化重注册。

## 接缝错位（旧形态）

```
AudioPageContext
  api: {
    audioName, duration, error,           ← 每次变化都重注册
    importAudio, clearAudio,
    dismissError, onDurationChange,
  }
  setApi(api)                              ← 桥反协议
```

`useAudioBridge` 在 Editor 端 `useEffect` 里 `registerAudioApi(api)` 反复调用；`AudioPage` 端 `useAudioPage()` 拿 `AudioPageApi | null`。
- 接口浅（7 个 setter/getter），实现散在 2 个组件 + 1 个 hook + 1 个 context；
- 理解"导入音频"要跳 4 个文件（Engine、useAudioBridge、AudioPageContext、AudioPage）。

## 收口方案（深模块 + 单一接缝）

**新形态**：
```
AudioSession（纯逻辑，node 环境可单测）
  ├ 状态：audioName / audioError / chartDuration / audioDuration / keySetId / seVolume
  ├ 行为：importAudio / clearAudio / dismissError / setChartDuration / setKeySetId / setSeVolume
  ├ 引擎：getEngine()（透出给 usePlaybackCoordinator RAF 用）
  ├ 持久化：setPersistNow / setSettingsPersist（外部注入，session 内部自动调）
  └ 订阅：subscribe(listener) → 单一 snapshot 推送

AudioSessionContext（React 入口）
  └ useAudioSession() → [snapshot, session]  // 工作台 / 音频页 共享同一单例
```

**接缝**：`useAudioSession()` 是**唯一入口**——返回 `AudioSessionSnapshot`（响应式状态）+ `AudioSession`（操作集合）。音频页不再 `useAudioPage()` 拿桥 api，而是直接 `session.importAudio(file)` / `session.setKeySetId(id)` / `session.setSeVolume(v)`。

**消失的桥**：
- `src/contexts/AudioPageContext.tsx`（**已删除**）
- `useAudioPage` / `useAudioPageRegister` / `AudioPageApi` 类型

**消失的 ref 环**（Editor.tsx 旧实现）：
- `audioMetaRef` / `persistRef` 手动时序耦合 → 改为 `session.setPersistNow(persistence.saveNow)` 一次性注入；`audioForPersist` 由 `useMemo` 从 session 派生。
- 旧 useAudioBridge 中"onPersistNow 外部传" + "audioName/audioError useState" 全消失。

## 接缝

- 唯一公开接缝：`useAudioSession()` → `[AudioSessionSnapshot, AudioSession]`
- 内部：纯 TypeScript class，可在 node 环境单测；引擎通过 `engineFactory` 注入（local-substitutable）
- 竞态保护：`inFlightToken` 单调递增，importAudio 的 .then/.catch 回调内 token 不匹配时早退
- NaN/Inf 拒绝：setChartDuration / setSeVolume / setVolume / 构造选项全部走 `Number.isFinite` 守卫，状态不被污染

## ADR 影响

- **ADR-0003 §7**：状态管理"Editor 只组装"原则进一步落实（音频域不再穿透到 Editor 内部 ref）。
- **ADR-0003 §12.2**：`settings.audio.{keySet, seVolume}` 字段位置**不变**（仍归 ConfigContext 段），仅 UI 呈现迁到音频页（已在 issue 29 切片 4 闭环）。本收口**只动"桥与归属的呈现"**，**字段定案不重开**——与架构评审 ADR callout 一致。
- **ADR-0004 §3 / §7**：有音频=音频时长（chartDuration clamp 到 MAX）/ 键音独立 SE 音量 / 持久化到 settings 三条不变量在 `AudioSession.importAudio` / `setSeVolume` / `setSettingsPersist` 中保留并可单测锁定。
