# 195 · 高倍暂停时鼠标移动导致整屏音符闪烁（瓦片缓存超额淘汰）

Type: bug
Status: resolved
Blocked by:
Related: [146](./146-播放中放置音符全谱闪烁.md), [188](./188-首次播放与长时静置后复播卡顿.md), [167](./167-首个音符抵线卡顿.md), [179](./179-冷启动首次播放首音符与BGM出声同刻卡顿.md)

## 来源

用户 2026-10-31 反馈（工作台画布）：缩放超过 200% 后暂停，鼠标一移动整屏音符开始闪烁；屏幕内存在 SP 绿条（含 hidden 结点）时必现，无 SP 则几乎看不到；播放中正常，停止移动也正常。用户提示“可能之前也遇到过”。

## 症状 / 复现

- 复现环境：1680×1000、deviceScaleFactor 2 → 画布 1550×906；缩放 240%；谱面 = BPM 120 + 每 0.5 拍单键 + 一条 beat 0→40 的 SP Slide（中间 hidden）；播放到 ~4.7s 暂停后在画布内持续移动鼠标。
- 闪烁帧主画布只剩静态层 2 次 `drawImage`，音符层 `blitted=0`；正常帧另有 1 次音符瓦片 blit。主画布非黑像素：正常 ~495k，闪烁帧 ~215k。
- 实测缩放阈值：180% 为 0/40 闪烁帧；200% 起为 10/40 —— 与 64MiB 预算可容纳的瓦片数由 5 降到 4 吻合。
- **SP 不是根因，只是可见性放大器**：普通 Slide（14/40）、无 Slide 但屏幕内有音符（15/40）同样出现 `blitted=0`；SP 带面积大，整块瓦片消失时肉眼非常明显，无 SP 时只丢稀疏音符，容易被忽略。

## 根因

`src/rendering/pipeline/noteLayerCache.ts`：

1. 瓦片位图 = 画布宽 × `TILE_PX(512)·es·TILE_DPR_CAP(1.5)`，单块字节随 es 线性增长。1550 宽画布下：180% ≈12.3MiB/块、200% ≈13.6MiB、240% ≈16.3MiB、300% ≈20.4MiB；`BYTES_BUDGET = 64MiB` 只能容 5.2 / 4.7 / 3.9 / 3.1 块。
2. 静止帧预取 `[lo, hi+2]`（视口本身含 ±200 virtual px padding，再向上 2 块）+ `[firstTile, firstTile+4]`（issue 167/179/188 首音符靶向预热）。高倍下非空瓦片需求 ≥5 块，超过预算 → `evictOverBudget()` 持续淘汰。
3. 暂停时鼠标移动触发重绘；`draw()` 在 `!rc.playing` 分支对 `lo..hi` 内缺失瓦片**同步重建**。某帧 padding 瓦片缺失时，重建它在同一帧内触发淘汰；Map 插入序中唯一覆盖视口的瓦片可能最旧 → 被淘汰 → 该帧 `blitted=0`，整个音符层消失。下一帧重建回来、再淘汰别的 → 移动鼠标时逐帧交替闪烁。
4. 播放中无此现象：`draw()` 跳过同步重建（`rc.playing` 分支），miss 交给异步队列；实测播放中 `rebuilt=0`、`blitted` 恒 ≥1。

实测账（240% 闪烁帧）：`lo..hi=3..5`，`startOrder=[4,5,2]`（仅 tile 4 覆盖视口），`pending=[3]`，建 tile 3 时 `evicted=[4]`，`blitted=0`。

## 修法（已实现 2026-10-31）

- `noteLayerCache` 新增预算规划：`tileBytesFor` / `maxTilesForBudget` / `tileIntersectsViewport` / `planPrefetchTiles`。预取顺序 = 视口覆盖块 → `hi+1/hi+2` 前瞻 → padding → 首音符窗口；总块数按 64MiB 容量封顶，高倍下远端 `firstTile..+4` 自动让位。
- `evictOverBudget` 保护本帧视口覆盖块：先淘汰非视口块；视口块即使让总量略超 64MiB 软上限也保留（正确性优先）。
- 非手势的静止帧同步重建只补**视口覆盖块**的 missing/stale；padding 块交给预取队列。打脏块仍保留同步语义（issue 146），basis 全量失效帧保持旧口径（一次性事件），手势帧口径不变（issue 173 轮转/公平性锁测不动）。
- 播放帧不重复做首音符扫描（沿用旧口径，静止期已预热），避免新增每帧成本。

## 锁测

1. `tests/unit/rendering/cache/HighZoomPausedHover.test.ts`（4 例）：
   - 240% 单块 ≈16.3MiB、预算只容 3 块；`tileIntersectsViewport` 不含 padding；
   - 预取规划受预算约束（视口块 + 向上 2 块，远端首音符让位）；
   - 低倍仍保留 `[firstTile, firstTile+4]`（issue 167/179/188 不回退）；
   - 手工摆出「预算超限 + padding 缺块 + 视口块最旧」临界态：旧实现 `blitted=0` / 视口块被淘汰，新实现 `blitted>0` 且视口块保留（实现前实测红）。
2. Playwright 像素实测（单测模拟不出真实帧调度）：240% + 暂停 + 连续 mousemove，40 帧主画布非黑像素稳定在 ~496–497k（修复前正常帧 ~495k / 闪烁帧 ~215k）。
3. 回归：`RendererPerf`（含 issue 167/179/188 首音符预热与 LRU）、`HighZoomBackflowSpCost`、`GestureRebuildFairness`、`PlaybackEditTileRefresh`、`HighZoomTiles` 全绿；`tsc -b` 0。
