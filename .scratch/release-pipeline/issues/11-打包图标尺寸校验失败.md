# 11-打包图标尺寸校验失败（icon.png 128x128 低于 mac ≥512 / linux ≥256 最低线）

Type: bug
Status: resolved
Blocked by: —

**来源**：tag v0.1.0 push 触发 `release.yml` 三平台矩阵；ubuntu / macos 两平台构建失败（windows 通过），失败点在 electron-builder 打包阶段的图标尺寸校验。

## 症状

electron-builder 24.13.3 直接失败：

- linux：`image public/icon.png must be at least 256x256`
- macOS：`image public/icon.png must be at least 512x512`

`public/icon.png` 实际为 128x128，低于两平台最低线。

## 根因

- `package.json` 的 `build.mac.icon` / `build.linux.icon` 均指向 `public/icon.png`；该文件自票 04（品牌整改）落位起就是 128x128。
- windows 走 `public/favicon.ico`（内嵌最大 256x256，恰好满足其 ≥256 要求），所以三平台只有它过。

## 修法

- `public/icon.png` 换 **512x512 全出血方图**（用户 2026-10-20 提供的图标集 `AAO-Editor-Icon-square-512.png`）。选方角不选 rounded：macOS Big Sur 起系统自行套 squircle 遮罩，预切圆角会双重圆角；Linux 按原样渲染，方图是通行规范。旧 128 版恰是预切圆角形态（顶行 61/256 像素全透明，半径约 24% 边长），本次一并修正。
- `src/assets/brand/app-logo.png`（应用内导航栏 mark 34px + 设置页关于 48px 两处渲染）同步换同设计 256x256 圆角版，消除 3x 屏拉伸发虚。属增强、非本 bug 修复必需（用户 2026-10-20 拍板保留）。
- `public/favicon.ico` 无需改动：用户提供的 `AAO-Editor-Icon.ico` 与仓内现有文件逐字节相同（MD5 一致）。

## 锁测

- `tests/static/ProductIdentityWiring.test.ts`：既有断言只锁三平台图标路径与文件存在、不锁像素尺寸——本修复未改路径，测试原样通过（8/8），兜底「图标资产路径不被误改」。
- 平台尺寸校验由 electron-builder 构建期执行，单测覆盖不到；替代验证 = 本地实跑 `electron-builder --linux --publish=never`：AppImage 正常产出（116MB），256x256 报错消除。macOS 用同一 PNG（512 ≥ 512 最低线），维度校验同构。
- 应用内 logo 换源：`tests/dom/pages/SettingsPageAbout.test.tsx` / `SettingsPageFlatSidebar.test.tsx` 渲染通过，资源导入链路无损。
