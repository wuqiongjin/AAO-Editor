# 13-发布展示层去重与流水线命名（release notes 文案重复；CNB pipeline 编号无名）

Type: chore
Status: resolved
Blocked by: —

**来源**：v0.1.0 发版验收（2026-10-20）一轮报出两个展示层问题：release notes 正文同一句文案出现两处；CNB 构建列表流水线名是 `push/pipeline-1` 这类编号，分不出谁是谁。同批处理，进一张批次票。

## Findings

### #1 release notes 文案重复

- 症状：草稿 release 顶部有一条 workflow 注入的「未签名告知」NOTICE（release.yml notes job 硬编码双语），RELEASE_NOTES.md「已知问题」第一条又是同一句话（中文单语）——页面正文里出现两遍。
- 根因：版本描述本有单一来源（RELEASE_NOTES.md，ADR-0021 §2：页面正文 + latest.yml → 产品内更新弹窗同一份），notes job 却在此基础上二次拼贴 NOTICE，两个载体各写一半必然腐烂。
- 修法：notes job 去掉 NOTICE 注入，直写单一来源 `gh release edit "$TAG" --notes-file RELEASE_NOTES.md`。未签名告知由 RELEASE_NOTES.md「已知问题」节统一承载（ADR-0022 §6 的「README 与 release notes 双落地」由 RELEASE_NOTES.md 与 README 各自承载，不靠 workflow 拼贴）。
- Status: resolved

### #2 CNB 流水线无名

- 症状：`.cnb.yml` 各 pipeline 未写 `name:`，CNB 按 `pipeline` / `pipeline-1` … 编号显示，构建列表里 `cnb/push/pipeline-1` 分不出是哪条。
- 根因：pipeline 级 `name:` 未显式声明（CNB 默认编号命名）。
- 修法：五个 pipeline 显式命名：门禁与镜像 / PR 门禁 / 国内副本镜像（每日）/ 国内副本镜像（手动）/ 发版门禁与镜像。命名后 `imports:` 不再是列表首键，缩进 4 → 6 空格，锁测同步。
- Status: resolved

## 锁测

- `tests/static/ReleasePipeline.test.ts`：notes job 断言改单一来源（`--notes-file RELEASE_NOTES.md`）；imports 断言随缩进调整（`^ {6}imports:` ×4）。19/19 通过。
- YAML 合法性：js-yaml 解析 .cnb.yml / release.yml，五条流水线 name 与 release.yml name/jobs 结构符合预期。
