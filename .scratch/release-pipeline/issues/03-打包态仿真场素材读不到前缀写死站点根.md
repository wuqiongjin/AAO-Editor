# 03-打包态（file://）仿真场素材读不到：素材前缀写死站点根

Type: bug
Status: resolved
Blocked by: —

**来源**：用户 2026-10-11 报「`npm run electron:dist` 打出来的包，动态预览喊『本地还没有仿真场素材… npm run assets:sync』」，dev 正常。

## 症状

打包产物进动态预览 = 空态 + 取件命令；重跑 `assets:sync` 毫无变化。音符皮肤（同树）在包里能显示，唯独仿真场不行。

## 根因

`src/preview/video/sim/simAssets.ts` 的 `SIM_ASSET_BASE` 写死**站点根绝对路径** `/assets/sim`。Electron 生产包是 `loadFile(dist/index.html)`，页面跑在 `file://` 下**没有站点根** → `/assets/sim/...` 解析成 `file:///D:/assets/sim/...`（磁盘根）→ 逐服探测全失败 → `emptySimAssets()` → 空态。**素材其实在包里**（asar 内 `dist/assets/sim/**` 9 文件齐全），是"取到了但读不到"。

判定要点：同树里音符皮肤走 `./assets/skins/...`（相对，跟 `base: './'`）—— 分界就是"绝对 vs 相对"。

## 本轮实现口径（待验收）

运行时素材 URL **一律跟构建 base**（`import.meta.env.BASE_URL`），不许写死站点根；判据是 `vite.config.ts` 的 `base` 与 `electron/main.cjs` 的 `loadFile`。

**修法**：`export const SIM_ASSET_BASE = `${import.meta.env.BASE_URL}assets/sim`;` —— dev `/` 行为不变；打包态 `./assets/sim` 相对当前文档解析。

## 锁测

- `tests/static/AssetsSync.test.ts`：① 仿真场前缀锁「跟 `BASE_URL` + 不许站点根绝对路径」；② 新增**全树锁** —— `src/` 下任何文件都不许出现 `['"`]/assets/`，把"一律跟 base"这条口径锁住（单条用例管不住整棵树）。
- `tests/static/SimRendererWiring.test.ts`：仿真场模块同一条口径，不再锁 `'/assets/sim'` 字面量。
- `tests/static/PreviewAssetAcquisition.test.ts`：新增「打包态的解析前提」—— 只锁环境前提（`loadFile` + `base: './'`），前缀怎么写不重复断言，避免两套正则各说各话。
- 单测测不到（jsdom 无 file:// 解析语义，`loadImage` 又是可注入替身，写死绝对路径在单测里全绿）。替代验证 = **headless Edge 真渲染**：`file:///…/dist/index.html` 下 `./assets/sim/...` 三图 OK（1160×610 / 2048×1024 / 150x41），`/assets/sim/...` FAIL 且解析为 `file:///D:/assets/sim/x.png`。脚本 `shots/verify-sim-assets.mjs`（`shots/` 被 .gitignore 忽略，故 `git status` 不显示）。

## 遗留（已拍板，2026-10-11）

空态文案原本断言"本地还没有素材…跑 `assets:sync`"，盖不住"路径解析不到"这一成因。用户拍板：**成因不区分，文案改中性，且不给开发者命令**。已落地，见 Comments。
