# 17-检查与本地包两轴

Type: grilling
Status: resolved
Blocked by: 06, 16

**来源**：用户 2026-10-25 验收应用更新：检查更新后点稍后，「立即重启」不出现；随后拍板可大改状态机。语义写入 [ADR-0021](../../../docs/adr/0021-应用更新.md) §2、`CONTEXT.md`「检查更新」。本票跟踪落地。

## 症状

包已经下完，再点检查更新、弹窗点稍后，关于里没有「立即重启」。检查、下载、能不能装被揉成一个 `status`，检查会把「已下完」踩碎。

## 根因

单轴状态把「远端有没有新发行」和「本机有没有能装的包」写成同一次赋值。`checking-for-update` 清掉 `ready`；稍后只关窗，界面却按「还没下」渲染。

## 为什么在 release-pipeline

接票 06 / 16 的应用更新产品面，不另开 effort。

## 定案（用户 2026-10-25）

- **远端**和**本地包**两轴，互不覆盖。检查只改远端；下载成功才改本地包。**稍后只关弹窗。**
- 关于：**检查更新**始终在；本地包就绪时其**左边**出**立即重启**（检查 / 稍后 / 切下载源都不拿掉）。
- 弹窗：没包 → 下载/稍后；刚下完或再检查同一版 → 立即重启/稍后（不再假装没下过）。点遮罩不关；走 Dialog `md`。
- 可装版本记本机 `app-state.json` 的 `readyVersion`（与下载源同类，不进设置对象）。没有 updater 安装包句柄不算就绪；立即重启只 `quitAndInstall`，不得先去下载。装不上不提示换源。

## 实现落点

- 主进程 `electron/appUpdate.cjs`：`remote` / `local`；下载成功才 `rememberReady`；检查到更新的正式版时 **不** 用新版本覆盖已下的 `readyVersion`；`install()` 只 `quitAndInstall`。
- 渲染：`AppUpdateHost` 按两轴弹窗；关于行立即重启在左、主按钮样式；点下载 toast 去关于看进度。
- ADR-0021 §2 / CONTEXT「检查更新」。

## 锁测

1. `tests/platform/electron/AppUpdate.test.ts`：下完再检查 `local` 仍 ready；只检查到新版本不算 ready；已下旧包、源上有更新版时 `readyVersion` 仍是旧版。
2. `tests/dom/pages/SettingsPageAbout.test.tsx`：稍后不掉立即重启；再检查弹重启不是下载；立即重启在左且 `button-primary`；点遮罩不关；`md` 宽。
3. `tests/unit/app/UpdateFailure.test.ts`：filepath / check-update-first 算 install，不提换源。
4. 真机：下过 → 再检查 → 稍后 → 关于仍有立即重启；点立即重启能装上（或装不上句不含换源）。

## Answer

检查与本地包拆成两轴。关于在包就绪时左边留立即重启；再检查同一版不再当成没下过。用户 2026-10-25「整体功能OK了」。

## Comments

### 2026-10-25 拍板存档

- 用户认两轴方案（检查不踩碎已下完；稍后什么都不改）。
- 立即重启在检查更新左边。
- 弹窗加宽、点遮罩不关。
- 立即重启曾误报「检查失败、换源」：是安装包句柄没接到 updater，不是网络。
- 2026-10-25 续：只检查到新版本时弹窗不得显示立即重启 / 「已就绪」；点立即重启不得开始下载。没有 updater 安装包句柄不算就绪。
- 2026-10-25 审查：票文落点与锁测对齐续拍板；已下旧包、源上有更新版时不得把新版标 ready。
