# 07-CI与发版链路（CNB 工作台 + GitHub 公开面孔）

Type: grilling
Status: resolved
Blocked by: —

**来源**：用户 2026-10-19 诉求「建立相关 CI，准备 release 出发布版本（计划 GitHub workflow + CNB CI）」。承接 01（拍板已毕 2026-10-07，CI / 发版链路待实现）与 06（应用更新已落地，发版 CI 不在其票）。本票把 01 剩余实现范围 + 本次新决策一次拍定；01 在本票实现完成时一并 resolved。拍板全记录 = ADR-0022。

## 症状

- 仓库无任何 CI（无 `.github/`、无 `.cnb.yml`）：发版全靠手动，质量无门禁。
- 发版目标（GitHub）与代码主仓（CNB）分裂：GitHub 仓停留在 24 commit 的 Vite 脚手架，双 README 的 clone / 下载 / 反馈入口却都指向它——名实不符。
- 06 落地了应用更新（updater 只认 GitHub 正式 Release），但发版链路不存在，更新源是空的。

## 根因

- 从未建 CI；01 拍定的「CI 构建期注入 + release 镜像」因仓库隔离未定而挂起。
- 代码在 CNB、发行在 GitHub 的分裂是既成事实（ADR-0021 更新源 + electron-builder `publish` 配置三处指向），缺一座桥；本票就是建桥。

## 已拍板（用户 2026-10-19）

1. **发布渠道 = public GitHub Releases**（Q1）：README 下载入口 / ADR-0021 更新源 / electron-builder `publish` 三处都已指向 `github.com/wuqiongjin/AAO-Editor`；issue 01 预留的「公开分发复审」随首个 release 一并完成（LICENSE 已声明仅覆盖代码、不覆盖素材）。
2. **代码通道 = CNB→GitHub 单向镜像，非 force**（Q2/Q13/Q17）：每次 `main` push、每次 `v*` tag push 执行；推送 `main` + tags，只允许 fast-forward；GitHub 侧出现未回流提交时镜像 job **响亮失败**，绝不静默覆盖。GitHub PR 回流 = GitHub merge → `git pull github main` → push CNB（纪律：回流早于下次 CNB push）。首次同步用户手动 `git push github main --force` 抹掉 24 commit 脚手架，此后永远快进。tag 只推不删不覆盖。
3. **职责划分**（Q3）：CNB = 质量门禁（push / MR）+ 镜像 job + 国内 release 副本；GitHub Actions = 三平台发版矩阵 + 发布 Release。CNB **不**出安装包（节点默认仅 Linux；单一构建真相放 GitHub Actions）。
4. **触发与版本**（Q4）：`v*` tag push 触发发版 + `workflow_dispatch` 手动；`npm version` 手动管理；CI 校验 tag 与 `package.json` version 一致，不一致即失败。
5. **门禁清单**（Q5）：`npm test`（3326 条全绿）+ `npm run build`（`tsc -b` + vite build，净）+ `npm run assets:check`。`npm run lint` / `npm run test:types` 存量错（HANDOFF 记录在案）不进门禁——「定义了就永远绿」；存量债另排 chore 票。
6. **素材注入 = GitHub Actions 直连 CNB**（Q6/Q16 终审改 ②）：GitHub 仓单 secret `ASSETS_SOURCE`（完整带只读 CNB 令牌的素材源 git 地址）取件；CNB 门禁 job **零 secret**——流水线内置 `CNB_TOKEN`，`assets-sync.mjs` 检测到即自动拼凭据；本地开发 export `CNB_TOKEN`（或 `ASSETS_SOURCE`）同理。**不建 GitHub assets 镜像仓**（少一仓一 job、素材少一份公网副本、token 过期可见失败）。**不 pin ref**（Q10/Q14，YAGNI）：clone main tip，接受「同版本重建可能换素材」（仅发生在故意换素材时）。
7. **发布语义**（Q7）：**正式 Release**（非 draft / 非 prerelease）；electron-builder `--publish always` 直发；`latest*.yml` 随包生成，发布那一刻已装用户即可经 electron-updater 收到（ADR-0021 口径）。
8. **签名 / 公证本期不做**（Q8）：mac Gatekeeper / win SmartScreen 代价写进 README 与 release notes；签名后续单开票。
9. **国内下载副本**（Q8）：CNB cron 流水线（`.cnb.yml` `crontab:`，Asia/Shanghai）轮询 GitHub latest release（public 匿名可读）→ 有新版本下载安装包 → `cnbcool/attachments` 插件 / Release API 传 CNB release（内置 `CNB_TOKEN`，无跨云 secret）；幂等跳过已镜像版本；**下载镜像，非更新源**（ADR-0021 不动）。

## 实现落点（拍板完成；按本仓约定实现写进本票，不另开）

- `scripts/ci/`（新增目录，入口被 `.cnb.yml` / release workflow 引用）：`common.sh`（仓库根前导）+ `ci-assets.sh`（取件）+ `ci-gate.sh`（门禁）+ `ci-mirror-github.sh`（非 force 镜像）+ `ci-mirror-installers.mjs`（cron 国内副本）。
- `.github/workflows/release.yml`：`push tags: v*` / `workflow_dispatch`（带 `tag` 输入，构建该 tag 的代码而非页面分支）→ 校验 tag↔version → 矩阵（windows-latest / macos-latest / ubuntu-latest）→ `npm ci` → 取素材（`CNB_TOKEN` + `ASSETS_REPO_SLUG` secret）→ `electron:build --publish=always`（`GH_TOKEN` 用默认 `GITHUB_TOKEN`）→ `notes` job 把未签名告知补进 release notes。缓存 npm + electron 二进制。
- `.cnb.yml`：main push / pull_request → 门禁；main push 与 `v*` tag_push 均挂镜像 job（非 force 推 main + tags）；`crontab: */30 * * * *`（CNB 固定 Asia/Shanghai）→ 国内副本轮询。**secret 走密钥仓库（Keystore）**：三条要 `GITHUB_TOKEN` 的流水线 `imports:` 引用 `AsterPicker/AAO-Editor-Keystore` 的 `env.yml`（改密钥仓名要同步三处 imports）。
- `scripts/assets-sync.mjs`：**无需改动**（已核实：`SOURCE` 直进 `git clone`，带凭据 URL 原生支持）。
- `.gitignore` 补 `/release/`（electron-builder `directories.output`，当前漏了，本地 `electron:dist` 会污染工作区）。
- 双 README：镜像与 PR 回流纪律声明（代码以 CNB 为准、GitHub 直推非快进拒绝）+ 下载双渠道（GitHub 主 / CNB 国内副本）+ 未签名打开方式。
- mac 构建 arch：首版 x64 + arm64 双架构 dmg（electron-builder 可在 arm64 runner 上交叉出 x64）；win nsis 先仅 x64；linux AppImage x64。后续按需扩。

  - `门禁三件套` / `门禁步骤与 package.json scripts 对齐，且 .cnb.yml 三种触发都真的调用门禁脚本`
  - `发布后补未签名告知进 release notes`
  - `发版链路无 Bestdori 引用`（01 既有口径延伸）/ `.gitignore 覆盖根目录 release/` / `.cnb.yml 四种触发俱全`
  - `取素材凭据走 secret，不写明文地址` / `素材快照仓名不出现在任何公开文档 / 配置里`

## 人工步骤（用户执行，配置写法由本票给出）

1. GitHub 仓 secret（一个）：`ASSETS_SOURCE` = `https://cnb:<只读令牌>@cnb.cool/<org>/<assets-repo>.git`（CNB 访问令牌只读、仅授权素材快照仓）。
2. CNB 侧（一个 secret）：建**密钥仓库** `AsterPicker/AAO-Editor-Keystore`（类型选「密钥仓库」，private）→ 其中建 `env.yml` 写 `GITHUB_TOKEN: "<GitHub fine-grained PAT，contents:写、仅代码仓>"` → 路径须与 `.cnb.yml` 三处 `imports:` 一致（改名字要同步改）。门禁取素材无需任何 secret（流水线内置 `CNB_TOKEN` 自动拼凭据）。
3. assets 快照仓设为 **private**（素材版权材料，不对外；此后本地 `assets:sync` 需 export `CNB_TOKEN`）。
4. 本地一次性：`git remote add github https://github.com/wuqiongjin/AAO-Editor.git` + `git push github main --force`（抹脚手架，此后永远快进）。
5. 冒烟（secret 就绪后）：CNB push tag → 镜像 → GH Actions 三平台 → 正式 Release → CNB cron 副本 → 已装 0.1.0 查到更新。`ci-mirror-installers.mjs` 的 CNB 上传两步（发起 → COS 直传）字段名 / 鉴权头按实际响应校准（脚本内有 TODO 标记）。

### 2026-10-19 secret 机制纠偏（用户提问「CNB 支持 secret 吗」引出）

查 CNB 官方文档确认：平台**没有** GitHub 式仓库级 secret——secret 机制是**密钥仓库（Keystore）**：独立 private 仓存 `env.yml`，`.cnb.yml` 各流水线 `imports:` 引用后注入为环境变量。首版 `.cnb.yml` 注释写的「仓库级 secrets 自动注入」不成立（照那样 `GITHUB_TOKEN` 不会出现，镜像 job 必红），已改为 imports。顺带减重：CNB 门禁侧删 `ASSETS_REPO_SLUG`（流水线内置 `CNB_TOKEN`，`assets-sync.mjs` 自动拼凭据 + 日志凭据打码）；GitHub 侧两 secret 合并为单个 `ASSETS_SOURCE`。终态 = 一边一个 secret。

### 2026-10-19 门禁首跑：素材取件「零 secret」设计被实测证伪

- 现象：三笔合并后的首笔 push 触发门禁，死在 `ci-assets.sh` 取件——clone 素材快照仓报 `Repository Not Found`（runner 日志实证）；gate 红 → 同流水线的镜像 stage 未跑。
- 排查：三种凭据（流水线内置 `CNB_TOKEN`、工作区 git token、CLI OAuth token）全部读不到素材快照仓，而同批凭据读同组织其他仓（CIF-Editor，git 与 API 两条路）正常 → 排除「仓不存在」，定位为**流水线内置 `CNB_TOKEN` 作用域仅限当前仓**，读不了私有快照仓。用户确认仓存在、个人只读令牌可访问。
- 处置（改 ADR-0022 §3 拍过的「门禁零 secret」，用户知情）：CNB 侧与 GitHub 侧同型——`ASSETS_SOURCE`（完整带只读令牌的素材源地址，仓名按既定口径不落文档）进密钥仓 `env.yml`，随 `imports:` 注入；`ci-assets.sh` 本就优先读 `ASSETS_SOURCE`，**脚本零改动**。`.cnb.yml` 头注 / `ci-assets.sh` 头注 / `scripts/README.md` / ADR §3 / 锁测同步回写。
- 待办（用户执行）：keystore `env.yml` 增加 `ASSETS_SOURCE: "<完整带只读令牌的素材源 git 地址，同 GitHub 侧 secret 口径>"`；本地工作区取件需 export 有快照仓读权限的个人访问令牌（IDE 自带 token 同样被挡，`export CNB_TOKEN=<个人只读令牌>` 后 `bash scripts/setup.sh`）。

### 2026-10-19 门禁转绿 + 镜像两连修（CNB 侧全链打通）

- **门禁全绿**（`cnb-eie` 起连续两轮）：keystore `ASSETS_SOURCE` → `ci-assets.sh` 取件 → 3411 测试 + build + assets:check 全过。用户已把只读令牌写进 keystore `env.yml`；本地经漫游文件 `~/.cnb/.env.local`（`06d890b5` 的 vscode 挂载）取件。
- **镜像 bug 1（fetch 目标）**：`ci-mirror-github.sh` 原本 `fetch origin refs/heads/main:refs/heads/main`——非 bare 仓不能 fetch 进已检出的 main，CNB runner 上必红（此前门禁一直红，没走到镜像这步所以没暴露）。改为 heads 进 `refs/remotes/origin/main`，push 从追踪 ref 出发；本地同条件复现通过。
- **镜像 bug 2（PAT scope）**：fetch 修好后镜像推到 GitHub 被拒——`refusing to allow a PAT to create or update workflow .github/workflows/release.yml without workflow scope`。fine-grained PAT 需 **contents + workflow 双写**（改权限即可，token 不变）。`.cnb.yml` 头注 / ADR-0022 §2 已回写。
- **本地事故（agent 环境）**：带 `CNB_TOKEN` 跑 `assets:sync` 时，`credential.helper=store` 把 URL 内嵌只读令牌存进 `.git/.git-credentials`，顶掉工作区可写 token（读 public 仓无恙、push 403）。修法：`assets-sync.mjs` clone 加 `-c credential.helper=`（`ea8df499`）；凭据已用工作区 token 还原。
- **剩余一步（用户）**：① PAT 加 workflow 写权限；② 本地一次性 `git remote add github … && git push github main --force` 抹脚手架（注意：本地推 GH 的凭据也要有 workflow scope）；③ 之后 CNB 每次 push 镜像自动快进，全链闭合。
