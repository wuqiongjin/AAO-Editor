## 定案（用户 2026-10-08 两次纠偏后）

**目标 = 应用仓与资源彻底解耦**：资源产物连同「抓取 / 构建 / 更新」能力一起住在**外部快照仓库**（私有，**地址不入库**）；
应用仓只**取件** —— 不存产物、不管哈希、不带产出工具。

```
[外部快照仓库]                                   [应用仓]
  原始包（不入库）
  抓取 / 构建 / 摆位脚本                          npm run assets:sync
  自更新入口（抓取 → 构建 → 摆位）        ──产出──▶   └ 拉取快照 → 按根拷回工作区
  payload = 应用仓工作区布局                          public/assets/**、src/assets/audio/keysounds/**
  （二进制 + 生成物注册表）                            src/{rendering/skin,audio}/**/gen/
```

**为什么生成物（注册表 `*.gen.ts`）也跟着走**：它是解析官方精灵坐标得到的生成物，与 PNG 二进制**必须同版本**；
留在应用仓 = 快照仓库单方面更新后注册表必然过期。生成器既然搬去快照仓库，生成物就跟着它一起分发（应用仓只消费、不生成）。

> 被本定案推翻的两版旧口径（不再保留）：① 应用仓存清单 + 哈希、用 `--pack/--sync` 管资源；② 归档从 `docs/` 搬去 `external/`。

## 落点

### 外部快照仓库（自更新；地址不入库）

| 路径 | 说明 |
| --- | --- |
| 抓取 / 构建 / 摆位脚本 | 从官方接口抓原始包 → 裁切 / 重组出二进制 → 生成注册表 → 摆成运行时目录树；另有手工覆写配置 |
| 更新入口 | 一键：抓取 → 构建 ×2 → 摆位；幂等，跑完 commit 即刷新 |
| `archive/`（**不入库**） | 抓来的原始包 |
| payload：`public/**` + `src/**` | 构建产物（二进制 + 注册表）—— 仓根 = 应用仓工作区布局，取件即拷贝 |

自更新在本仓流水线里跑那个入口脚本即可（定时 / 手动）；只抓应用实际要用的**构建选集**，不做全量归档。

### 应用仓（只消费）

- **取件** `scripts/assets-sync.mjs`（别名 `assets:sync` / `assets:check`）：默认来源以**编码常量**存在脚本里（不写明文、零配置；认证走机器 git 凭据）→ clone 到临时目录 → 按根整取到 `public/assets/skins`、`public/assets/sim`、`src/assets/audio/keysounds`、`src/rendering/skin/gen`、`src/audio/gen`；`ASSETS_SOURCE` 或 `--from <本地目录|git 地址>` 可换来源。
- **产出工具全部移出主仓**：抓取 / 构建脚本、覆写配置、清单、`docs/resource/` 下的归档目录全删（不再有 manifest / 哈希表）。
- **接线**：`setup.sh` [3/4] 取件（失败打印修复口径、不阻塞安装）；`dev.sh` 启动前预检，缺件先自动补齐，仍失败拒绝启动（键音注册表是 `?inline` 静态导入，缺件必挂）。
- **口径回写**：`.gitignore`（5 条产物目录）、`scripts/README.md`、`CONTEXT.md` 音符皮肤词条、`simAssets.ts` / `KeySound.ts` / `SpriteLocator.tsx` 头注、i18n 空态命令（→ `npm run assets:sync`）。
- **低调**：应用仓里**不出现**快照仓库的地址与名字，脚本里只留编码常量。
