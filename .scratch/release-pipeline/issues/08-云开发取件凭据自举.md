# 08-云开发取件凭据自举（shell 配置不漫游，改由脚本直读漫游文件）

Type: bug
Status: resolved
Blocked by: —

**来源**：用户 2026-10-20 报障——CNB 云开发 workspace 里 `scripts/setup.sh` [3/4] 取件失败（`Repository Not Found`），且担心"下次重建环境还犯"。

## 症状
新 workspace / 交互 shell 里 `npm run assets:sync` clone 外部素材源失败；URL 里拼的是平台注入的 AI-IDE 令牌，读不了素材源仓——与票 07 结论同源：内置 `CNB_TOKEN` 作用域仅限当前仓。

## 根因
- `/etc/profile` 每次环境重建都重新 export 平台 `CNB_TOKEN`，覆盖 shell rc 里加载的本地 PAT；`.zshenv` 等 rc 不在 CNB 默认漫游清单（默认只漫游 `~/.gitconfig`、code-server 配置、`~/.cnb/`），重建即丢——票 02「零配置」承诺在云开发环境不成立。
- 官方文档（`docs.cnb.cool/zh/workspaces/file-keeper.md`）：`~/.cnb/` 默认漫游，`~/.cnb/.env.local` 正是推荐存法。

## 修法
`scripts/assets-sync.mjs` 凭据链自举（按优先级，clone 失败自动换下一个）：`ASSETS_TOKEN`/`CNB_ASSETS_TOKEN` env > 本地漫游文件 `~/.cnb/.env.local`（`CNB_TOKEN_FILE` 可换路径）> 环境 `CNB_TOKEN`。不依赖任何 shell 配置；CI 路径（`ASSETS_SOURCE` secret 注入）不变。

## 锁测
`tests/static/AssetsSync.test.ts` 新增一条：脚本含 `ASSETS_TOKEN` / `.cnb` 凭据链与多候选重试；既有「来源不写明文」等断言不变。
