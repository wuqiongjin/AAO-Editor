# 37 · 详情页副行删掉曲目来源

Type: feature
Status: resolved (2026-10-13)

## 来源

用户 2026-10-13 验收（附详情页头部截图）：

> BanG Dream #804，BanG Dream 没啥必要提，因为用户大概率知道，然后 #804 和下面的音频名称也有重复。因此我认为可以删掉。

## 症状 / 根因

详情页头部副行渲染的是 `<歌手> · <曲目来源>`（`ProjectDetail.tsx`，`sourceLabel(sel.source)`），bandori 曲显示成「Poppin'Party · BanG Dream #804」。两处冗余：

- 站点名（BanG Dream）对用户是废话——用这个软件的人不会不知道自己在哪个站找谱；
- `#804` 与**下一行音频名**重复——票 35 之后音频名自带曲库 id（`official-804-…`）。

## 修法

- `ProjectDetail.tsx` 副行只留歌手（`{sel.artist ?? t('projects.artistMissing')}`）。
- `projectFormat.ts` 的 `sourceLabel()` 随之无人引用 → 删除。
- i18n 三键 `projects.sourceLabel.{custom,bandori,llsif}` 一并清掉（zh-CN / en 两份）。
- **`曲目来源` 字段本身保留**：发布时要按它填 `song`、工程信息弹窗里可改、换音频时还会回 `custom`（`ProjectAudioScope.test.ts` 已在守）。弹窗用的是另一组键 `projects.source{Custom,Bandori,Llsif}`，不动。

## 锁测

- 无既有测试断言那一行文案（`grep sourceLabel` / `BanG Dream #` 在 `tests/` 下零命中），所以本票补一条**静态源码断言**（照 `EditorAudioSessionRefactor.test.ts` 惯例）进
  `tests/static/ProjectDetailHeadLayout.test.ts`（详情页头部的事实本来就锁在这个文件）：
  1. `ProjectDetail.tsx` 不再出现 `sourceLabel`，且仍在渲染 `projects.artistMissing`（防「整行一起删掉」）；
  2. `projectFormat.ts` 不再导出 `sourceLabel`；
  3. 两份语言包里 `projects.sourceLabel.*` 一律为空集，而弹窗那组 `projects.source{Custom,Bandori,Llsif}` 必须还在（防误删）。
- 死引用另有一层保障：函数 / 键被删后若有残留引用，`npm run test:types` 直接编译失败。真正的观感（那一行只剩歌手）走人工验收，jsdom 验不了排版。
