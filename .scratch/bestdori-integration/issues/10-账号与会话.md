# 10 · 账号与会话

Type: feature
Status: resolved
Blocked by: 07

## 来源

ADR-0011 §3（内置登录直传、凭据红线）、issues/04、issues/06 的 grill Q3（2026-09-30 拍板）。

## 定案（用户 2026-09-30）

- **形态**：产品内置登录 `POST /api/user/login`；成功 Cookie 名 `token`（写路径实测）。**密码不落盘**，会话结束即弃。
- **Cookie 存放**：Electron `safeStorage` 加密；**不给**手动粘贴 Cookie 的入口（凭据红线要干净，调试走 Node 脚本）。
- **会话唯一真相**：能力层持**一个**会话对象；登录成功与启动时各查一次 `GET /api/user/me` 校验。
- **失效表现**：写能力变灰、**读能力保留**，不弹窗打断、不白屏。
- 登出 = 清除本机会话与被持久化的 Cookie。

## 实现落点

- `src/community/bestdori/account.ts`（能力 9–10）+ 能力 8 的「我自己的作品列表」（`post/list` 带 `username`）。
- 会话不属于「设置对象」（CONTEXT 明确设置对象是 chrome 偏好），不写 localStorage。
- **Cookie 只落在主进程**（与 ADR-0011 §2 一致 —— renderer 不碰凭据）。

## 锁测

1. `tests/unit/community/bestdori/account.test.ts`（新）：假出口 —— 登录成功置会话；失败（`{"result":false,"code":"CREDENTIALS_INVALID"}`）不写入任何凭据；`user/me` 401 → 会话失效且**读能力仍可用**.
2. 静态源码断言：新增一条「`password` 字面量不得出现在任何持久化写入路径」的断言，或等价 API untouched guard。
3. 单测覆盖不到的：`safeStorage` 真实加解密 / 跨进程取值 —— 照 `tests/platform/electron/` 惯例补平台测试 + 真机手工验收（含：退出再进是否仍在登录态，Fog 里 Cookie TTL 未测）。

### 2026-10-14 · 两轴评审（Standards / Spec）回修

评审报 13 条：落地 5 条，判断不改 8 条 —— **理由写在这里，免得下一轮再报一遍**。

改了的：

1. 测试文件名照 `tests/README.md` 的「PascalCase + 描述领域，不是被测文件名」：`account.test.ts` → `AccountSession.test.ts`。
2. **删掉 `communitySession:status`**（IPC 四条 → 三条）：无消费方，且凭据面的接口越小越好 ——「本机能不能加密」由 `persist()` 的返回值回答。顺带删掉 store 的 `exists()`（它只为 status 存在）。
3. `communitySession:clear` 回 `true`（原先 `{cleared:true}` 无人读），与 `backgroundSkin:clear` / `windowChrome:sync` / `i18n:setLanguage` 同形。
4. 静态断言：口径修正（原注释写「全仓」实际只扫 `src/`）+ 新增一条**结构性**断言 —— 凭据两个模块的 import 面只准相对路径（名字正则挡不住改名绕道，import 面拦得住）。
5. 平台测试补两条**走满全链**（真 `CREDENTIALS_INVALID` 原码 → 07 的真网关 → 10 的账号层 → jar / 磁盘；以及成功路径「登录 → 落盘密文 → 重启 restore 后请求自带 token」）。

判断不改的（逐条）：

- **`writeFileAtomic` 与 `main.cjs` 重复**：`projectStore.cjs` / `appState.cjs` / `assetCache.cjs` **各自都有**原子写（全仓 4 处），这是本仓主进程 CJS 模块的既有惯例；只抽本票这一份会变成「4 份里 1 份走共享件」，反而更不一致。整仓收敛该开 `chore` 票，不在本票顺手做。
- **平台测试的 `fakeIpcMain` / `okFetch` 与 `CommunityNetWiring.test.ts` 重复**：本仓口径是「假件就近声明」（`tests/support/communityTransport.ts` 头注同口径）。为 6 行替身去改一个与本票无关的测试文件，收益不抵。
- **`fetchMyPostsPage` 是 Middle Man**：它承载「不套纯数字 id 直查」的口径（那一套是搜索框的「跳转」语义），不是空转。
- **`Status: resolved` 与「本轮实现口径（票内未拍板的三处，待验收）」并存**：`docs/agents/issue-tracker.md` 明文规定 —— 「不得把实现口径冒充用户定案：……票里那一节写『本轮实现口径（待验收）』」。留着是照规矩，不是收口不一致。
- **静态断言 `persist\(\s*[^)]`「认不出 `persist(  )`」**：这条判反了 —— `\s*` 回溯之后，空格本身就会命中 `[^)]`，它反而把「带空白参数」也判成有参（偏严不偏松）。
- **`toHaveLength(3)` 靠条数兜底**：逐行身份 + 恰好 3 条，新增形参或新增用法都会红，够用。
- **`subscribe()` / `onRetry` / `retry` / `resetCommunityAccount()` 票面未提**：前三个是本仓既有的注入面（`withRetry` 的 `deps`、`rateLimit` 的「时间与随机数可注入」是明文惯例）；`resetCommunityAccount()` 与 `clearPostPageCache()` 同类 —— 会话单例的测试接缝。票 11 直接用。
