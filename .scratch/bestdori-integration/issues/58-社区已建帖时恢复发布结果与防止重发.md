# 58 · 社区已建帖时恢复发布结果与防止重发

Type: bug  
Status: resolved  
Blocked by: —

## 来源与症状

2026-11-22 用户反馈 AAO Editor 0.2.1 发布自定义曲目时报失败，但 Bestdori 已建帖。诊断包 `aao-diagnostics-20261122-212956` 的五条 `UNKNOWN` 与社区帖 `267296–267300` 创建时间按顺序相差约 2–4 秒。五帖有三个谱面版本，其中 `267296/267297`、`267299/267300` 各自完全相同。
五帖标签均为空。站点标签索引收录「韵律源点」，官网把 `BLOCKED` 解释为发帖过多；原始请求标签与各错误对应的请求阶段仍待确认。 [标签索引](https://bestdori.com/api/post/tag?type=text&data=%E9%9F%B5%E5%BE%8B%E6%BA%90%E7%82%B9&fuzzy=false) · [官网发布页代码](https://bestdori.com/js/CommunityChartsNew.b534f9a9.js)

## 根因

当前客户端只在发帖回包带合法帖子 ID 时写入上传记录。结果不明时会进入失败分支并重新开放发布。离线模拟「服务端已建帖、返回 `result: false`」可复现：再次发布会产生第二帖。现场回包与标签缺失原因待查。

## 定案（用户 2026-11-22）

- **Q1=A**。发帖结果待确认时禁用发布和重试，提供「重新核对」和「打开社区」。关窗、重启、暂未查到帖子或回查失败后仍保留待确认状态，确认本次未建帖后才恢复发布入口。
- **Q2=A**。进入待确认时自动回查一次。作者、时间、曲目和谱面内容均吻合且只有一个候选时，补写上传记录并显示「已上传」。多个匹配由用户选定，标签差异单独提示。脱敏诊断按尝试 ID 记录请求阶段、平台码、标签数量及已取得的帖子 ID。
- **Q3=A**。待确认期间暂锁该谱面本体和工程共享的音频、谱面时长，保留查看、播放和复制。
- **Q4=A**。提供「关联已有帖子」入口，支持 0.2.1 等旧版本遗留的已建帖案例。用户输入帖子 ID，校验作者账号、曲目与谱面内容后补写上传记录。

## 锁测

- `tests/unit/community/bestdori/publish.test.ts` 模拟已建帖后返回 `UNKNOWN`、超时或缺 ID，断言只发送一次 `POST /api/post`。`tests/unit/pages/usePublishEntry.test.ts` 覆盖唯一匹配补记、多匹配待选、未匹配与重开后继续待确认、按 ID 关联及校验失败。`tests/dom/pages/ProjectPublishConfirm.test.tsx` 验证待确认时无法触发发布与重试、补记后显示已上传。另在桌面端切页、重启验证谱面、音频及时长的编辑锁，覆盖弹窗单测观察不到的跨页和持久化行为。

## Answer

发帖已发出、回包不明时写入待确认并停二次发布；明确不会建帖的拒绝（含 `BLOCKED`）不当待确认。自动回查一次，唯一匹配或按帖子 ID 关联成功则补记上传记录。用户 2026-11-23 看过本地场景台：差不多，这类场景很少触发。词表见 CONTEXT「谱面状态 / 发布结果待确认 / 上传记录」，锁语义见 ADR-0015 §4。

## Comments

### 2026-11-23 · 本轮实现口径（用户看过场景台后关闭）

回查界面**不是** `BLOCKED`。官网把 `BLOCKED` 解释为发帖过多；本轮把它算作「明确不会建帖」的拒绝，映射成限流失败，**可以重试、不会进入待确认**。待确认只在 `POST /api/post` **已经发出**、回包却说不清有没有建帖时出现。

分界在 `src/community/bestdori/publish.ts`：`POST_REJECTION_CODES` = `POST_INVALID` / `POST_EMPTY` / `CHART_INVALID` / `TEMPORARY_FILE` / `BLOCKED`；再加上未授权、限流、`request-rejected`。其余在发帖请求开始之后都保持 `pendingPublish`（关窗、重启、暂未找到、回查失败都不解锁，Q1=A）。`UNKNOWN` **不是**平台文档里的「可能已建帖」码：`electron/community/communityNet.cjs` 在 `result:false` 且 `code` 空时兜底写成 `UNKNOWN`。现场诊断五条 UNKNOWN、超时、成功但缺合法 ID、发帖后断网，同属这一档。

回查结果在 `usePublishEntry.ts`，文案在 i18n `projects.publish.recovery.*`，弹窗在 `PublishRecoveryPanel.tsx`（待确认是正文警告条；「关联已有帖子」是底栏文本链接，展开后才出帖子 ID）。待确认期间主发布键隐藏，含核对中，避免变成「发布中…」。未匹配不解锁。

不新开 ADR：Q1–Q4 已是产品定案；错误码分档与下面场景表是本票验收口径。若验收保留「待确认也是锁、但还没有上传记录」，再改 CONTEXT「谱面状态」并给 ADR-0015 §4 补一句。research 只收可复用 API 事实（`UNKNOWN` 兜底、`BLOCKED` 官网含义），不收 11 档界面。

未发过帖也能看「底栏关联」：任意**未发布**谱面打开「发布谱面」。其余档需要工程里已有 `pendingPublish`（真机走到发帖结果不明，或验收时手工注入）。本地 `?prototype=publish-recovery` 场景台是抛件，未进提交。

### 场景对照

| 界面 | 真机怎么走进去 |
| --- | --- |
| 底栏关联 | 谱面没有本机上传记录。给 0.2.1 那种「社区已有帖、本机当没发过」：填帖子 ID，再核账号、曲目、谱面。 |
| 待确认 | 发帖请求已发出，回包不明（`UNKNOWN` / 超时 / 缺合法 ID / 发帖后断网）。禁用发布，锁谱面和工程共享的音频、时长，自动回查一次。 |
| 暂未找到 | 自动回查或「重新核对」在作品里找不到同时满足作者、曲目、谱面内容的帖。仍待确认。 |
| 核对失败 | 回查网络或请求失败，还没拿到可用结果。仍待确认。 |
| 账号不符 | 待确认记录是账号 A 发出的，当前是 B 或未登录。须换回当时那个社区账号。 |
| 帖子不匹配 | 「关联已有帖子」填了 ID，但这篇对不上当前账号、曲目或谱面（含用昵称冒充账号名）。不记账。 |
| 补记失败 | 社区帖已对上，本机把「已上传」写进工程时失败。帖在社区，本机记录仍空。 |
| 多帖待选 | 回查找到不止一篇都对得上（0.2.1 连点发布、两篇相同谱）。用户点其中一篇来补记。 |
| 核对中 | 自动回查或「重新核对」还在跑。主按钮不得以「发布中…」回来。 |
| 已补记 | 唯一匹配、用户选定的那一篇、或按 ID 关联成功，并且本机记录已写入。弹窗改「更新谱面」，关联入口消失；标签和原帖不一致时另 toast。 |
| 周围锁面 | 不是弹窗里的回查结果。待确认期间：详情行「发布结果待确认 / 重新核对」、不能改谱和删、音频页锁时长、工作台切换器带锁、编辑只读浮条。查看、播放、复制仍可用。 |
