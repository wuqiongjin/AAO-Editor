# 47 · 启动后账号行长时间显示「登录」

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-16 真机 #4：每次打开软件进工程详情，左下角登录态过好一阵子才变成「已登录」；期间无提示，会以为没登录。

## 症状

详情左栏 `AccountBar` 先画「登录」（人像 + 动作文案），若干秒后才切成头像 + 昵称。中间没有「确认中 / 恢复会话」一类字。

## 根因

1. **会话初始值就是未登录**（`account.ts`：`signedIn: false, account: null`）。`start()` 要先 `safeStorage` 恢复 Cookie，再 `GET /api/user/me`（`revalidate`，30s × 最多 3 次）。校验结束前订阅方只能看到「没登上」。
2. **账号行没有第三态**。票 39 明确否掉常驻状态行、否掉 availability 单例、不做网络预检；未登录文案是动作式「登录」。于是「正在确认上一份 Cookie」和「从来没登过」长得一模一样。
3. **`me` 走 API 档同一条单飞队列**。若用户先打开过官方/社区选曲，曲库那两发 `freshFirst`（票 44）会把 `me` 堵在后面——详情页左下角的等待被列表拉取放大。即便没开选曲，跨境 `me` 慢到十几秒也够让人以为没登录。
4. `start()` 挂在工程管理页挂载（`useCommunitySessionStart`），不是进详情才发；但 `AccountBar` **只在详情左栏渲染**，主页看不见校验过程。进详情时若 `me` 还没回来，就是这副样子。
5. `me` 若因超时/离线失败：`settleSignedOut()` 且 `expired=false`（凭据还在主进程 jar 里）。界面继续「登录」，跟「确认中」同一张脸。

## 定案（用户 2026-10-16）

有 Cookie 时先按已登录画头像/昵称，旁注「正在确认…」—— **2026-10-16 落点修订**：本机不缓存昵称，确认中只写「正在确认…」、不画头像。确认失败再回到「登录」或「登录状态已失效」。没有 Cookie 才画「登录」。`me` 尽量不要排在曲库大请求后面（身份校验优先）。

## 实现落点

会话加 `verifying`：Cookie 恢复后、`me` 回来前账号行写「正在确认…」。本机没有缓存昵称，所以这一态没有头像字母。

## 锁测

`tests/unit/community/bestdori/AccountSession.test.ts`（me 挂起时 verifying）；`CommunityNetGateway.test.ts`（me 插队）；`NewProjectSourceCopy.test.ts`（确认中发布不弹登录）。
