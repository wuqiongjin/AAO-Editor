# 09 · 社区帖浏览与导入

Type: feature
Status: resolved
Blocked by: 07

## 来源

issues/06 的 grill Q9 / Q10（2026-09-30 拍板）；落地 `chart-projects/issues/07` 里「Community 来源」那一支。

**2026-10-09 归位（用户拍板四项来源，见 [12](./12-导入入口四项归类.md)）**：本票 = 新建入口四支里的「**从社区谱面导入**」（`NewSource` 的 `'community'` 一支）。界面文案说「社区谱面」，不说「Bestdori 社区」——用户不关心数据从哪个站来，只关心官方 / 社区之分。

## 定案（用户 2026-09-30）

- 列表 / 搜索 / 分页走 `POST /api/post/list`；**等级与难度只能客户端过滤**（`docs/research/bestdori-api.md` §2.2）；**上拉加载**，不做页码。
  （撤销过一轮又加回来，最终口径见 Comments「验收反馈批次」#1 与「第二轮反馈」#1：**
  保留**客户端筛选，但**不自动补扫** —— 搜索是服务端的、典型结果很小，两者叠加才完整；筛选范围由列表尾明说）
- 详情 `GET /api/post/details?id=`。
- **谱面名称留空**（动态跟随工程名称，见 CONTEXT「谱面名称」）；原帖标题与**谱师**只在导入会话里显示，**不落进新谱面的 `title`** —— 避免「转手别人的谱，连名字一起转」。
- 曲目按帖子的 `song.type`：
  - 官方曲 → 记曲目来源 id 并下载音频与封面（复用 08 那条素材路径）；
  - 自定义曲 → 按帖内 URL 下载音频与封面，工程 `曲目来源` = `custom`。
- 导入的谱面代码一律走 Apply 闸门（ADR-0014）；官方 / 社区谱面代码与本编辑器格式一致（`basic-editor/issues/02`），不做格式重设计。
- 「广场」不新增应用页面（Q4）：浏览能力长在工程管理页的这个入口里。**且只长在「新建工程」这一层**（用户 2026-10-09 确认，见 12 票「边角口径」）——社区帖自带曲目素材，往已有工程里导入会撞上「一个工程一首歌」的音频归属，「工程详情 → 新增谱面」不接这条来源。

## 实现落点

- 导入的谱面代码走既有 `ChartConverter` 链路接受 Apply 闸门（ADR-0014），不新开一道入口。
- 文案进 `src/i18n/messages/{zh-CN,en}.json`。

2. 名称口径：新增一条锁「社区帖导入后 `ProjectChart.title` 为空」的用例（防止将来有人图省事预填帖子标题）。
3. 若新增测试大类需登记 `vitest.config.ts` 的 `include`；本票用既有 `tests/unit/` 即可。
4. 单测覆盖不到的：上拉加载时序、封面墙 / 预览窗 —— 走 `tests/dom/` + 手工验收清单。

### 2026-10-12 · 第二轮反馈（用户三条 → 定案与落地）

| # | 反馈 | 实测依据 | 定案与落地 |
| --- | --- | --- | --- |
| 1 | 「筛选是不是还是有点用的？搜索的时候筛选能不能起作用」 | ① 平台 `search` **是服务端搜索**，且实测**同时匹配标题与 `artists` 歌手**（`roki` 命中一篇标题不含 roki、歌手为 Tarokiki 的帖子）；**不匹配谱师账号**（`search=Envy09` → 0 条）。② 典型查询结果很小：`habit` **4** 条、`BLACK SHOUT` 22 条、`roki` 29 条（宽词如 `Roselia` 2222 条 = 45 页）。③ 但 `level` / `diff` **拼不进服务端请求**（§2.2 实测一律 `REQUEST_INVALID`） | **加回来**：筛选保留，口径 = **只作用于已加载的条目、不自动补扫**（补扫是首次成本大头，已撤）。搜索把范围缩小后，客户端筛选在常见查询下就是完整的 —— 这才是它重新有意义的理由。列表尾明说范围：`筛选只作用于已加载的 N 条（命中 M 条）· 加个关键字能缩小范围`；筛空时另有「已加载的 N 条里没有符合条件的」而不是假装全站没有 |
| 2 | 「官方谱面那边不需要刷新按钮吗？」+ 到底什么时候更新 | 官方曲库与社区列表**同一套**更新机制：网关 json 档 **24h 内直接回 → 过期先回旧的 + 后台补一枪（失败静默）**。但官方曲库**多一层**：`songs.ts` 的会话内模块缓存**不过期**，后台补的那一枪写的是磁盘，**当前会话仍用内存里的旧数组**（要下次启动才看见） | **官方面板补同一颗刷新钮**（社区那颗的兄弟，文案同为「刷新歌曲列表」）：`refreshSongCatalog` = 清模块缓存 + 两次请求都带 `revalidate`（跳过 24h 副本真打一发）；失败保留旧列表不弹错。两个面板的「刷新」语义就此一致：**点了就真拉，不点就吃缓存** |
| 3 | 「搜索帖子标题」改成「搜索歌曲标题」 | 同上：搜索其实也匹配歌手 | 占位符改为「**搜索歌曲标题**」/ "Search song titles"（用户口径）。**待定**：既然实测也匹配歌手、且官方面板写的是「搜索曲名或乐队」，是否改成「搜索标题或歌手」由用户定 |
