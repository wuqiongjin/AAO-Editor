# 19 · 存储与数据：加「打开数据目录」+ 缓存文案与行为对齐

Type: feature
Status: open
Blocked by: —

## 来源

用户 2026-10-10 真机验收意见 #2 a–f（针对票 18 的落地版）。

## 症状

设置 → 存储与数据（`SettingsPage.tsx:475-581`）只能看一行路径文本，没有打开目录的入口；且多处文案与真实行为不符：

| 现状文案 | 真实行为 / 问题 |
| --- | --- |
| 更改保存位置 | 实为**迁移**：`moveDataRoot`（`electron/dataRoot.cjs:144`）把旧数据根整包拷到新位置，成功后**删旧根** |
| 使用已有数据文件夹 | 实为**改指针**：`claimDataRoot`（`dataRoot.cjs:205`）不拷不删，只补建缺失子目录 |
| 占用 X · N 个文件 | N 是 `cache/community/index.json` 的**条目数**不是文件数（缩略图并入所属条目，`assetCache.cjs:416-432`）；分桶「索引与文本 / 封面与音频」是按 kind 的粗归类（`SettingsPage.tsx:56-64`），其余 kind 一律塞后者，不可靠 |
| 闲置超过（天）就清除 | 只作用于 `<数据根>/cache/community/`（`sweep()`，`assetCache.cjs:435-468`），不碰工程文件 / assets / 临时文件 |
| 占用上限（MB） | 同上（`enforceSize()`，`assetCache.cjs:202-217`） |
| 改了下次清扫就按新值算，不用重启 | 两个数字行共用同一条 hint（`:544` / `:552`），界面上**重复两遍**，且不解释词义 |

另：全仓没有 `shell.openPath` / `showItemInFolder`，`electron/main.cjs` 未 import `shell`，`preload.js` 的 8 个桥无一能打开目录。

## 定案（用户 2026-10-10 ~ 10-11，grill 三轮）

1. **新增「打开数据目录」按钮** —— `shell.openPath(dataRoot)`，需新建 IPC；
2. 按钮改名：`更改保存位置` → **更改数据目录位置**，`使用已有数据文件夹` → **使用已有数据目录**（保住「已有 / 接管」语义，避免用户混淆哪个会搬走并删除旧目录）；
3. 占用信息**只留总占用**，删掉条数与分桶两行；
4. 两个策略项改名：**缓存闲置天数** / **缓存上限（MB）**，hint 各写各的：
   - 闲置：`超过这个天数没被使用过的素材会被自动清理掉，默认30天。`
   - 上限：`超过缓存上限数值时，会自动清理缓存。默认 1024MB。`
5. 全文统一用「**素材**」（不用「资源」）。

## 修法

- 主进程：`electron/main.cjs` 引入 `shell`，新增 `dataRoot:open`；`preload.js` 加桥；`SettingsPage.tsx` 加按钮（无桥的静态演示版隐藏）；
- 文案：`zh-CN.json:256-275` 与 `en.json` 对应段重写 —— 删 `settings.cache.breakdown`，`settings.cache.usage` 去掉条数参数，新增两条独立 hint 键；
- **待确认**：UI 区间 1–365 天 / 64–65536MB（`AppSettings.ts:151-154`）与主进程硬夹 1–3650 天 / 1–64GB（`assetCache.cjs:34-37`）不一致，是否在同一次改动里统一。

## 锁测

1. `tests/dom/pages/SettingsCacheBlock.test.tsx`：两个数字行的 label / hint 文案；「占用」只出总量不再出条数与分桶；新增「打开数据目录」按钮在有桥时渲染、无桥时不渲染。
2. `shell.openPath` 属 Electron 侧，单测覆盖不到 → **真机验收**：点按钮系统文件管理器打开并定位到数据根；改两个数字后关设置页重启仍生效（票 18 既有行为不变）。
