# 20 · 重复点击已选曲目，封面消失且不再回来

Type: bug
Status: open
Blocked by: —

## 来源

用户 2026-10-11 在讨论 #4（预览栏折叠）时顺带实测发现，原话：

> 当再次点击已经「展开歌曲详情」的条目时，会导致已经加载好的封面图消失。

## 症状

官方选曲面板点某首歌 → 封面正常加载；**再次点击同一行** → 封面消失，且不会自己回来。同一次点击还伴随：试听播放器被重置、底部「创建并打开」按钮瞬间禁用再启用。

## 根因

`OfficialSongPanel.tsx:339-345` 的行点击没有去重，点谁都直接 `pick(song)`；而 `pick()`（`:97-104`）把封面与详情状态全部清零：

1. `setCoverReady(false)` → `<img>` 失去 `.is-in`，CSS 里 `.off-cover img { opacity: 0 }`（`ProjectsPage.css:512-520`）→ 封面**立刻变透明**；
2. 但 `<img>` 的 `src` 字符串没变（仍是缓存里的 `aao-asset://raw/...`，元素也没有 `key` 变化），图片已经 complete，**浏览器不会再触发一次 `onLoad`** → `coverReady` 永远回不到 `true` → 封面再也显示不出来；
3. `setDetail(null)` 连带 `CompactAudio` 的 `src` 变 `null`（`:316-322`）与 `onSelectionChange(null)`（`:116-118`）→ 另外两个症状同源。

不是加载失败，是**状态被重置后没有任何事件能把它恢复**。

## 修法

`pick()` 对同一首歌幂等：`song.id === selected?.id` 时直接返回（至少不重置 `coverReady` / `coverUseDirect` / `detail` / `detailError` / `loadingDetail`）。

## 锁测

1. `tests/dom/pages/OfficialPickerPreview.test.tsx`：新增「重复点击同一行 —— `<img>` 的 `is-in` class 保持、`src` 不变、`onSelectionChange` 不额外抛 `null`」。
2. jsdom 不发 `onLoad`、无法验证真实图片加载时序 → **真机验收**：连点同一行 3 次，封面始终在，试听不闪，按钮不闪禁。
