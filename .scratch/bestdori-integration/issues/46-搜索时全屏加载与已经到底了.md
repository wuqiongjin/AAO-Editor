# 46 · 社区搜索：整页「正在拉取」+ 短结果「已经到底了」

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-16 真机 #3：搜索时仍显示「正在拉取 xxx」；结果填不满一页时还显示「已经到底了」。问是否合理。

## 症状

社区 tab 改关键字（防抖 350ms）→ 列表被整块换成「正在拉取社区谱面…」→ 结果回来后，条数少于一屏时列表尾仍写「已经到底了」。

官方 tab 的搜索是**内存过滤**，不会因打字重拉曲库；若曲库还没下来，搜索框打字期间同样会一直停在「正在拉取官方曲库…」（跟票 44 叠在一起）。「已经到底了」这句只属于社区上拉列表。

## 根因

`CommunityPostPanel.loadFirst`：查询一变就把 `posts` 置 `null`，渲染分支是 `posts == null ? 正在拉取 : 列表`。上一页结果直接卸掉，没有「保留旧列表 + 角上转圈」。

翻完判定：`endReached = rawCount >= total || posts.length === 0`。搜索是服务端的、结果通常很小（票 09 实测 habit 4 / BLACK SHOUT 22），第一页经常就是全量 → `endReached` 为真 → 只要 `posts.length > 0` 就画「已经到底了」。这句是给**无限上拉**写的终点文案，套到「总共就这么几条」的搜索结果上会像嘲讽。

## 定案（用户 2026-10-16）

改关键字不要卸掉上一页列表 —— **2026-10-16 推翻**：正常搜索不留对不上关键字的上一页。换词 = 居中骨架 +「正在搜索…」；首屏仍是「正在拉取社区谱面…」。搜索短结果不写「已经到底了」/「没有更多了」；浏览翻完才写 A 的「没有更多了」。空结果继续「没有匹配的帖子」。

观感（用户 2026-10-16 对照原型）：**骨架用 B，文案用 C 的「正在拉取官方曲库」**；B 工具条右上那句「正在拉取曲库」多余，不要。短结果不写「已经到底了」。上拉加载更多 / 浏览翻完采用 A 的列表尾（spinner +「没有更多了」）。

## 实现落点

`OfficialSongPanel` / `CommunityPostPanel` 首次加载用 `.off-blank`（居中 spinner + `projects.*.loading`）。社区换词同样 `.off-blank`，文案 `projects.community.searching`（「正在搜索…」）。短结果不画 `noMore`；浏览翻完才画。不再渲染 `projects.community.end`。原型 B 去掉工具条旁提示。

`tests/static/NewProjectSourceCopy.test.ts`（off-blank / 不用 end 键）；`tests/unit/community/bestdori/posts.test.ts` inflight+force。
