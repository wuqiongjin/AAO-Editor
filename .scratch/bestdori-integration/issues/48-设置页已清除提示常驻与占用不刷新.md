# 48 · 设置页「已清除」提示常驻与缓存占用不刷新

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-18 真机反馈，原话：

> 社区素材缓存->清除缓存 后，怎么社区素材缓存下面的文本显示的就一直是"已清除（释放 96.8 MB）"，而不是当前的缓存大小情况了... (哪怕后续继续缓存了一些数据也不会更新)。这个 "已清除（释放 96.8 MB）" 应该是一次性的提示啊，不能作为文本常驻的。

## 症状

- 设置 → 存储与数据 →「社区素材缓存」：点「清除缓存」后，状态行**永久**显示「已清除（释放 96.8 MB）」。
- 后续继续缓存素材，占用数字也不更新（停在清除时的零值）。

## 根因

两个叠加问题，都在 `src/pages/settings/SettingsPage.tsx`：

1. **一次性提示成了常驻状态文本**：`cacheNote` 被放在渲染链 `cacheNote ?? (stats 文本)` 的**最优先位**（`:391-398`），而它只在**下一次再点清除**时被置回 null（`:166`）——没有计时器、没有关闭路径、stats 刷新也不重置它。加上页面是保活挂载（`src/layouts/AppShell.tsx:100-103`，所有 page 常驻仅切可见性），SettingsPage 从不重挂载，提示永不退场。票 14 / 18 / 19 从未把「已清除」定案为常驻状态，属实现偏离定案的 bug。
2. **占用数字本身冻结**：`loadCacheStats()` 只在挂载（`:155-160`）与切数据根（`:217`）时跑；清除后 stats 被硬编码为零（`:171`）。主进程侧无推送（`webContents.send` 全仓 0 次），渲染侧无轮询、无激活刷新——应用不重启，数字就停在挂载时那一帧。

## 定案（2026-10-18 grill，用户拍板）

- **Q1 提示落点 → 全局 toast**：复用 `showToast(msg, 'success')`（`src/ui/Toast.tsx`，2.6s 自动消失、可手动关）；状态行始终显示实时占用文本，`cacheNote` state 删除。
- **Q2 更新机制 → 激活时刷新**（本轮推荐、用户认可）：照票 38 的 `wasActiveRef` 边沿模式（先例 `src/pages/projects/ProjectsPage.tsx:100-111`）——切回设置页时重拉 stats。**不轮询**（保活页上定时 IPC 绝大多数读到同一个数，纯浪费）；**不加 push**（这会是全仓第一条 push 通道，为设置页数字引入全新事件契约，而精度收益为零——浏览社区时窗口被别的页占着，数字跳变无人观看）。
- **Q3 清除后初值 → 重拉真实 stats**（用户认可「硬编码不好」）：清除成功 → `loadCacheStats()`，删掉硬编码零值。`clear()` 返回时主进程内存索引已重置，同 tick 的 `stats()` 即真实结算；部分失败时 UI 不会嘴硬说「还没有缓存内容」。

## 实现落点

1. `src/pages/settings/SettingsPage.tsx`：
   - 删 `cacheNote` state（`:133`）及 `:166` / `:172` 两处 set；渲染链退回纯 stats 文本（reading / empty / usage）。
   - `handleClearCache` 成功分支：`showToast(t('settings.cache.cleared', { size: formatBytes(r.freedBytes) }), 'success')` + `loadCacheStats()`（撤掉 `:171` 的硬编码零值）。
   - 组件签名接 `{ active = true }`（PageSlot 本就传，`src/pages/PageRegistry.tsx:30-36`），照 ProjectsPage 加 `wasActiveRef` 边沿 effect：`active` false→true 时 `loadCacheStats()`。
2. i18n：`settings.cache.cleared` 值不变（从行内文本挪作 toast 文案）；无新键。
3. 主进程零改动。

## 锁测

- `tests/dom/pages/SettingsCacheBlock.test.tsx` 首条用例改写：清除后状态行回「还没有缓存内容」（不再有常驻「已清除」）；`statsFn` 清除后共 2 次（挂载 + 清除重拉）；toast 照既有惯例 `vi.spyOn(ToastModule, 'showToast')`（先例 `tests/dom/pages/ProjectNewSourceTabs.test.tsx:18,315`）锁 `success` 语气 + 释放量文案。
- 新增用例：`active` false→true（切回设置页）时重拉 stats——锁票 38 模式在本块的落地；首次挂载只拉 1 次（`wasActiveRef` 初值防重复）。
- 既有策略推送 / 空缓存文案两条用例预期仍绿（不受影响）。
