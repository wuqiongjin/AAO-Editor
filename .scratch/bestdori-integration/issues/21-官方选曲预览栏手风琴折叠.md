# 21 · 官方选曲预览栏改为手风琴折叠

Type: feature
Status: open
Blocked by: 20

## 来源

用户 2026-10-11 对 #4（空态文案「选一首曲子，看封面、难度与试听」）的答复，原话：

> 我觉得左侧的预览区，在没有预览的时候，是不是可以收起来？（就像手风琴模式一样）
> 只有在用户选择一个条目时，才展开，用户再次点击这个条目就是收起。

## 症状

左侧预览栏（`OfficialSongPanel.tsx:250` 的 `aside.off-preview`，`.off-split` 首列 240px）在未选曲时是一块空面板，只挂一句占位文案 `projects.official.pickHint`（`zh-CN.json:56`），白白占着 240px。

（更正前期描述：`.off-split` 是 `grid-template-columns: 240px minmax(0,1fr)`，DOM 顺序是预览在前、列表在后 —— **预览在左窄栏，列表在右宽栏**。）

## 定案（用户 2026-10-11）

1. 未选曲时预览区**收起**，`.off-split` 变单列 `minmax(0,1fr)`，列表占满宽度；
2. 选中某个条目 → 展开；
3. **再次点击已展开的条目 → 收起 = 取消选中**（`selected = null` → `onSelectionChange(null)`，底部「创建并打开」按钮随之禁用）。

## 修法

- `OfficialSongPanel.tsx:344` 行点击改为 toggle：同一首 → 清态并上抛 `null`；另一首 → `pick(song)`；
- `ProjectsPage.css:384-391` 无选中时收起首列（可加 `grid-template-columns` 过渡做手风琴观感）；窄屏断点（`:591-593`）下同步确认；
- `projects.official.pickHint` 随之没有渲染位置，确认删除（收起后不需要空态文案）；
- 依赖票 20：折叠后不应再存在「重复 `pick` 清掉封面」的路径，20 的幂等短路是这条 toggle 的安全网。

## 锁测

1. `tests/dom/pages/OfficialPickerPreview.test.tsx`（及 `ProjectListKeyboardNav` 族）：点选 → 展开且上抛 selection；再点 → 收起且 `onSelectionChange(null)`。
2. CSS 列数变化与过渡 jsdom 测不到 → **真机验收**：收起时列表占满、展开/收起不跳动；收起后底部按钮禁用；再点一次重新展开且封面正常显示。
