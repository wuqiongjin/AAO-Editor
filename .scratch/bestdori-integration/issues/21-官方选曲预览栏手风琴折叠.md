# 21 · 官方选曲预览栏改为手风琴折叠

Type: feature
Status: resolved
Blocked by: 20

## 来源

用户 2026-10-11 对 #4（空态文案「选一首曲子，看封面、难度与试听」）的答复，原话：

> 我觉得左侧的预览区，在没有预览的时候，是不是可以收起来？（就像手风琴模式一样）
> 只有在用户选择一个条目时，才展开，用户再次点击这个条目就是收起。

## 症状

左侧预览栏（`aside.off-preview`，`.off-split` 首列 240px）在未选曲时是一块空面板，只挂一句占位文案 `projects.official.pickHint`，白白占着 240px。

（`.off-split` 是 `grid-template-columns: 240px minmax(0,1fr)`，DOM 顺序预览在前、列表在后 —— **预览在左窄栏，列表在右宽栏**。）

## 定案（用户 2026-10-11）

1. 未选曲时预览区**收起**，列表占满宽度；
2. 选中某个条目 → 展开（带列宽过渡，观感是「揭开幕布」）；
3. **再次点击已展开的条目 → 收起 = 取消选中**（上抛 `null`，底部「创建」随之禁用）；
4. 展开全程**内容不得重排**（用户验收时明确要求「等布局到位再显示内容」）。

## 修法

### 结构：三层，裁切层与钉宽层分开

```
.off-split            首列轨道 var(--off-preview-w) ←→ 0，180ms 过渡
 └ aside.off-preview  宽度 = 轨道宽（跟着动画走）+ overflow:hidden   ← 裁切窗口
    └ .off-preview__inner   width: var(--off-preview-w)              ← 钉住最终宽度，永不重排
```

- 最终宽度只写一处：`--off-preview-w: 240px` 定义在 `.off-split`，首列轨道与内层共用。
- 收起态：`.off-split.is-collapsed { grid-template-columns: 0 minmax(0,1fr); gap: 0 }` —— **保持两轨**（轨道数变了 `grid-template-columns` 就不插值）。
- 裁切层必须是**纵向 flex + 交叉轴不拉伸**（`flex-direction: column; align-items: flex-start`），见下方踩坑 3。
- 窄屏单列（`@media max-width: 820px`）下没有相邻列，内层回到 `width: 100%`，不做「钉宽 + 揭开」。

### 交互（`OfficialSongPanel.tsx`）

- 新增 `expanded` 状态，与 `selected` 分开：**收起只是关窗**，不清 `selected` / `detail` / 封面状态。
  - 收起动画有东西可滑（否则内容瞬间消失、只剩空列在缩）；
  - 再展开同一首**不重取详情、不重建 `<img>`**，封面不会回到 `opacity: 0`（票 20 那条病根从根上被绕开）。
- 行点击 `toggleRow`：同一首在「展开 ↔ 收起」间切，换一首才 `pick(song)`。
- 语义不变：`onSelectionChange` 的条件加上 `expanded` → 收起即上抛 `null` → 弹窗 `confirmDisabled`（`!official`）禁用「创建」；`aria-selected` 与 `.is-active` 同样跟着 `expanded`。
- 副作用：
  - **试听**：收起时 `src` 传 `null` → `<audio>` 卸载 → 立刻停声（内容留着但不出声）；
  - **无障碍**：`.off-preview` 用**延迟 visibility** 收尾（`is-collapsed` → `visibility: hidden` + `transition: visibility 0s linear 180ms`），动画跑完才真的藏起来、退出无障碍树与 Tab 序。
- 依赖票 20：`pick()` 的同曲幂等守卫保留为防御性守卫（本票落地后行点击已不再产生「同曲重复 `pick`」）。

### detail 未到位时：等高骨架（`OfficialSongPanel.tsx` + `ui.css`）

- 不依赖 detail 的（封面 / 标题 / 歌手 / 难度 chip）立即真显示；
- 试听条：`detail == null` 时渲染 `.off-compact-audio.is-skeleton`（该类本身 `height: 32px` 定高），到位后**原地换成真 `CompactAudio`**，尺寸不变；
- 同步开关：保留真按钮的禁用态 + `is-loading` 微光 + `aria-busy`（按钮高度由内容撑，换成独立骨架反而要额外钉高度）；
- `ui.css`：`.off-compact-audio__time` 加 `min-width: 3em` + 右对齐，时长从 `0:00` 变真实长度时不再推动进度条；
- 微光复用既有的 `off-thumb-shimmer` 关键帧（与 `.off-row__thumb-ph` 同一套观感）。

**文案**：`projects.official.pickHint` 的 zh-CN / en 两条删除（收起后没有空态了）。

## 踩坑（防回潮，都是真机验出来的）

1. **裁切不能放在 `.off-split`**：容器级 `overflow: hidden` 只裁容器边缘、**不裁轨道边界**，过渡期间钉宽的预览栏会溢出轨道压到列表上。裁切必须放在「宽度 = 轨道宽」的那一层（`.off-preview`）。
2. **不要用 `opacity` 做收起态**：`opacity < 1` 会创建 stacking context，让预览栏盖到列表上面（配合坑 1 就是截图里那次叠影）。用延迟 `visibility`。
3. **`flex: 1` 会吃掉 `width`**：`flex: 1` = `flex-basis: 0%`，在横向主轴下覆盖 `width`，内层宽度就跟着轨道一起长 → 内容重排（等于坑都没修）。裁切层必须 `flex-direction: column` + `align-items: flex-start`，让 `flex: 1` 只作用于纵向。

## 锁测

1. `tests/dom/pages/OfficialPickerPreview.test.tsx`（9 条）：
   - 收起态（无预览内容 / 两个 `is-collapsed` / 「创建」禁用）；
   - 点选展开 → 再点收起（`aria-selected` 与按钮同步）；
   - 收起后 `aria-hidden` + 试听掐掉 `src`，再展开恢复；
   - detail 卡在闸门后（`installFakeBridge({ holdDetail: true })`）：骨架在位 + 真 `audio` 未挂载，放闸后原地替换；
   - 票 20 侧：收起再展开同一首 —— `/api/songs/29.json` 只请求 1 次、`<img>` 是同一个元素、`is-in` 不丢。
2. `tests/static/OfficialPickerAccordion.test.ts`（5 条静态源码断言）：裁切窗口是 `.off-preview` 自己；宽度变量只写一处；裁切层纵向 flex + 交叉轴不拉伸；列宽过渡与「首列归零」保留；**反向锁死** `.off-preview` 上出现 `opacity` 过渡。**为什么静态**：展开期间是否重排 / 是否叠影是 CSS 事实，jsdom 不加载外部 CSS 也没有布局引擎。
3. **真机验收**（代替像素实测）：展开时封面不从小到大生长、标题不换换行位置、chip 不重新折行、不压到列表上；再点收起时内容跟着一起滑走且试听立刻静音；再点原样回来。
