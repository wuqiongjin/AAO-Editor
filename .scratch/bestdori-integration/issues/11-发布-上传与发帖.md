# 11 · 发布（二进制上传 + 发帖）

Type: feature
Status: resolved
Blocked by: 07, 10

## 来源

issues/06 的 grill Q13（2026-09-30 拍板）；ADR-0015 §4（每张谱面至多一条上传记录、已上传只读）；`basic-editor/issues/156`（上传时静默 sanitize）。

现状：`src/upload/bestdori/sanitizeChart.ts` 已就绪但**零调用方**；`ChartProject.ts` 的 `ChartUploadRecord` 有展示（`ProjectDetail.tsx`）与只读闸门（`chartReadonlyGate.ts`），但**没有任何写入方** —— 本票是第一个。

## 定案（用户 2026-09-30）

- **上传 / 发布二分**（CONTEXT 新词条）：**上传** = 发字节（谱面代码 / 音频 / 封面），内容寻址可复用（`ALREADY_UPLOADED` 直接返回）；**发布** = 发帖，产生帖子 id。
- 三步二进制上传：`upload/prepare` → `upload`（multipart 字段 `file`）→ 轮询 `upload/status/{hash}`，引用于 `https://bestdori.com/api/upload/file/{hash}`。
- `POST /api/post` 前做**必填预检**，按字段名点名缺什么（CONTEXT「工程信息」已预告「缺的字段上传时再拦」）。
- 待发布的谱面字节先静默跑 `sanitizeChartForBestdoriUpload`（剥 `System` / `charge`），**不弹「谱面不合法」**（issue 156 定案）。
- 一次性确认「发布后谱面本体不可修改」（`post/edit` 没有 `chart` 字段），确认键按**危险键分寸**用实底红 —— 这是不可逆动作。
- **不做**本地草稿 / 发布队列：回旋余地已由「复制谱面」这条既有出路覆盖。
- 发布成功后**写 `upload` 记录**（`postId` + 时间），此后该谱面按既有闸门转只读。

## 实现落点

- `src/community/bestdori/publish.ts`（能力 11–13）。
- `src/upload/bestdori/sanitizeChart.ts` 按 issues/06 Q6 迁到 `src/community/bestdori/sanitizeChart.ts`（连带改 `tests/unit/upload/bestdori/sanitizeChart.test.ts` 一行 import；届时 `src/upload/` 空掉即删除该目录）。
- 发布对话框走既有**弹窗壳**（`src/ui/Dialog`），不自绘 scrim。
- 入口在工程管理页（ADR-0015 §4 后果：上传链路不归它管，但它展示上传记录并作入口）。

## 锁测

1. `tests/unit/community/bestdori/publish.test.ts`（新）：假出口 —— 三步上传遇 `ALREADY_UPLOADED` 跳过第二步；必填预检逐字段报错；**发帖成功后写入 `upload` 记录且只写一次**（重复调用被拒）。
2. `sanitizeChart` 既有三条用例随迁 `tests/unit/community/bestdori/`，行为不变。
3. 已上传只读是既有闸门行为，本票补一条「写入 `upload` 后编辑操作被拒」的用例（闸门此前只能靠手工注入记录测）。
4. 单测覆盖不到的：真实发帖会污染线上账号 —— **真机验收只许用测试曲 / 测试谱，并在 ADR-0011 §3 的自控速率约束内**。

### 2026-10-15 · 落地记录

**迁移（issues/06 Q6 收口）**：`src/upload/bestdori/sanitizeChart.ts` → `src/community/bestdori/sanitizeChart.ts`

**能力层 `src/community/bestdori/publish.ts`（新）**：
- `precheckPublish`（纯函数）：title / artists / level（缺或越 1–35）/ content（缺或超 5000）/
  chart（sanitize 后为空）/ audio（custom 且工程无音频）。弹窗与能力层共用同一份。
- `publishChart`：预检 →（custom）三步上传 → `POST /api/post` → 经注入的
  `writeUploadRecord` 接缝写记录。三个 POST 不套退避（07 写路径口径），status 轮询是幂等读照常退避。
- `uploadBinaryFile`：`prepare {ver:3,hash,size}` → 遇 `ALREADY_UPLOADED` **跳过上传与轮询**
  （内容寻址复用，平台码在能力层认，不上界面）→ multipart `upload` → 轮询 `status` 至
  `available`。文件引用回 `https://bestdori.com/api/upload/file/{hash}`。
- `publishFailureOf`：统一错误域 → 九档中立失败（与 `loginFailureOf` 同族，界面不认平台码）。

**字节不过 IPC 的两处落点**（票面未点，实现期定）：
1. `CommunityRequest.multipart`（`{field, filePath, fileName?}`）—— multipart 走**同一条**
   `communityNet:request` 通道，不为上传开第二条 IPC；主进程 `communityNet.cjs` 读文件拼体、
   自算 content-type（带 boundary）、字段名 / 文件名过安全字符、文件必须落在
   `uploadRoots`（main.cjs 注入**工程目录**，每次现取）内、64MB 防呆上限。
2. `project:uploadRefs` 桥（projectStore + preload + main）：回音频 / 封面的
   **路径 + 字节数 + SHA-1**。备选是 renderer 拿 `audioBlob` 自己算 —— 那会把 4MB 字节
   拉进渲染进程，且 multipart 总要主进程读文件，哈希在主进程一起算是顺路。

**写入与编排**：`recordChartUpload`（projectCatalog，纯函数）—— 已有记录 / 谱面不在工程里
一律回 null = 「只写一次」的把门；页面侧 `usePublishEntry.ts`（新，页面目录的 hook，
为 500 行拆解纪律让路）用 `mutateProject` 装配写入接缝。**帖子发出去而记录写不进来时
结果仍是 ok**（`recordWritten:false` + warn Toast）—— 平台上已有这一帖，再让用户按一次
只会多发一帖（ADR-0015 §4：社区没有作者自助下架）。

**界面**：`PublishDialog.tsx`（新，走 ui/Dialog 壳 + ConfirmDialog 实底红确认）——
缺失清单**实时**派生自预检（不用等点发布）；描述是唯一在此填的字段；阶段提示四档。
入口在工程详情谱面行（`ProjectDetail`，已上传的谱面没有它）；写能力被挡时按钮禁用 +
`CapabilityStatusLine` 就地一行（票 39 交下来的积木，文案仍只有那一处）。

**本轮实现口径（票内未拍板，待验收）**：
1. 上传引用经新桥 `project:uploadRefs`（主进程算 SHA-1），见上。
2. multipart 复用同一条网络通道（新请求字段），不为上传开第二条 IPC。
3. status 轮询 10 次 × 1s（wrapper 是 5 次；间隔未实测，用完明说不静默成功）。
4. custom 无封面时不发 `cover` 键（平台是否强制 custom 帖带封面未实测）。
5. 标题预检取「谱面名称 → 工程名称」的**原始值**，不拿「未命名工程」这个显示兜底去发帖。
6. 描述（`content`）必填（前端 `POST_EMPTY` 口径），≤5000 字。
7. 上传文件上限 64MB 是**防呆线不是平台政策**（15MB 仅见前端文案，§8 未实测）。
8. 缺字段清单实时展示（票面说「点名」，没说点出来后还是实时 —— 实时对用户更早）。

**与票面定案的两处对账（票不改写，记在这里）**：
1. 定案说「上传 = 发字节（谱面代码 / 音频 / 封面）」，但官网前端 `onPublish` 把
   `chart` 数组**内联**进发帖 body（bestdori-community-upload.md §3.1 / §4 的目标帖
   实证：865 对象随帖子发出，没走 `/api/upload`）—— 三步二进制上传只对**音频 / 封面**
   做，谱面代码随发布走。实现按事实站官网前端那边。
2. `song` / `diff` 预检只查**取值合法性**（bandori 曲库 id 正整数、diff 0..4），不查
   曲库成员关系：平台自己不校验曲 id（§3.2：`id: 999999` 照样建帖），而工程里的
   bandori id 按构造来自官方导入时的曲库选中（换音频即回 custom）—— 全量校验要拉
   曲库索引，代价与收益不成比例，留作已知缺口。
