# 11 · 发布（二进制上传 + 发帖）

Type: feature
Status: open
Blocked by: 07, 10

## 来源

issues/06 的 grill Q13（2026-09-30 拍板）；ADR-0015 §4（每张谱面至多一条上传记录、已上传只读）；`basic-editor/issues/156`（上传时静默 sanitize）。

现状：`src/upload/bestdori/sanitizeChart.ts` 已就绪但**零调用方**；`ChartProject.ts` 的 `ChartUploadRecord` 有展示（`ProjectDetail.tsx`）与只读闸门（`chartReadonlyGate.ts`），但**没有任何写入方** —— 本票是第一个。

## 定案（用户 2026-09-30）

- **上传 / 发布二分**（CONTEXT 新词条）：**上传** = 发字节（谱面代码 / 音频 / 封面），内容寻址可复用（`ALREADY_UPLOADED` 直接返回）；**发布** = 发帖，产生帖子 id。
- 三步二进制上传：`upload/prepare` → `upload`（multipart 字段 `file`）→ 轮询 `upload/status/{hash}`，引用于 `https://bestdori.com/api/upload/file/{hash}`。
- `POST /api/post` 前做**必填预检**，按字段名点名缺什么（CONTEXT「工程信息」已预告「缺的字段上传时再拦」）。
- 待发布的谱面字节先静默跑 `sanitizeChartForBestdoriUpload`（剥 `System` / `charge`），**不弹「谱面不合法」**（issue 156 定案）。
- 一次性确认「发布后谱面本体不可修改」（`post/edit` 没有 `chart` 字段），确认键按**危险键分寸**用实底红 —— 这是不可逆动作。
- **不做**本地草稿 / 发布队列：回旋余地已由「复制谱面」这条既有出路覆盖。
- 发布成功后**写 `upload` 记录**（`postId` + 时间），此后该谱面按既有闸门转只读。

## 实现落点

- `src/community/bestdori/publish.ts`（能力 11–13）。
- `src/upload/bestdori/sanitizeChart.ts` 按 issues/06 Q6 迁到 `src/community/bestdori/sanitizeChart.ts`（连带改 `tests/unit/upload/bestdori/sanitizeChart.test.ts` 一行 import；届时 `src/upload/` 空掉即删除该目录）。
- 发布对话框走既有**弹窗壳**（`src/ui/Dialog`），不自绘 scrim。
- 入口在工程管理页（ADR-0015 §4 后果：上传链路不归它管，但它展示上传记录并作入口）。

## 锁测

1. `tests/unit/community/bestdori/publish.test.ts`（新）：假出口 —— 三步上传遇 `ALREADY_UPLOADED` 跳过第二步；必填预检逐字段报错；**发帖成功后写入 `upload` 记录且只写一次**（重复调用被拒）。
2. `sanitizeChart` 既有三条用例随迁 `tests/unit/community/bestdori/`，行为不变。
3. 已上传只读是既有闸门行为，本票补一条「写入 `upload` 后编辑操作被拒」的用例（闸门此前只能靠手工注入记录测）。
4. 单测覆盖不到的：真实发帖会污染线上账号 —— **真机验收只许用测试曲 / 测试谱，并在 ADR-0011 §3 的自控速率约束内**。
