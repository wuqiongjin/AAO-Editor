# 61 · 发布弹窗体验：封面、描述生成与「关联已有帖子」

Type: grilling
Status: resolved（2026-11-27 用户验收通过）
Blocked by: —

## 来源

用户 2026-11-26（真机反馈，四条）：

1. 封面图没有提供可以设置的地方。
2. 没有封面图时没有明显缺失提醒；上传时不会本地报错，只等社区平台返错。
3. 自动生成的描述模板太鸡肋：
   - a) 没必要显示「标题」「谱师」——发到平台的帖子已经能看到；
   - b) 要增加 NPS 这类谱面信息；
   - c) 难度「Expert XXX」没必要，直接显示等级；
   - d) 还有哪些类似的有效信息可以加？
4. 左下角「关联已有帖子」的样式与交互都很诡异。

主线诉求：UI 布局、组件美化、交互逻辑的引导。

## 现状（代码事实）

### 封面

- 发布弹窗里的封面是只读视觉卡：`src/pages/projects/components/PublishDialog.tsx` 的 `.ppc-cover` 只渲染 `project.coverBlob` 或 `Music2` 占位，没有上传 / 替换 / 清除入口。
- 唯一设置入口在「编辑工程信息」弹窗：`src/pages/projects/components/ProjectDialogs.tsx` 的 `EditInfoDialog` 使用 `CoverField`；发布弹窗不知道 / 不引导这条路径。
- 无封面时只命中了 `.ppc-cover.is-optional`（虚线灰框）；`.ppc-cover.is-empty`（danger 虚线）在 CSS 里存在但从未接线。`title` 里的「暂无封面」还是硬编码中文，未走 i18n。
- 素材引用 `refs`（音频 / 封面路径 + hash）只在打开弹窗时加载一次（`useEffect` 依赖 `[custom, pending, published, project.id, loadUploadRefs]`），即使就地换了封面也不会刷新。

### 缺失提醒与平台回错

- `precheckPublish`（`src/community/bestdori/publish.ts`）的 `PublishMissingField` 没有 `cover` 这一档；custom 曲目只把 `audio` 当必填，`cover` 可以为 `null`。
- `PublishInput.song` 的 custom 分支允许 `cover: null`，能力层直接发不带 cover 的 `song`。
- 研究文档 `docs/research/bestdori-api.md` §9 的前端必填清单里没有封面；`docs/research/bestdori-community-upload.md` 写的是 custom「推荐自传封面/音频」。所以「没封面导致平台 POST 失败」目前没有文档证据，需要复现确认是否误判了别的字段。
- 界面侧无法区分「封面可选、只是没设置」和「封面是必填、现在缺了」——两种语义都表现为一个灰色占位图标。

### 自动生成

- `generatePublishDescription` 只接收 6 个事实：`title` / `diffName` / `level` / `noteCount` / `duration` / `charter`；输出「标题 / 难度 / 等级 / 音符 / 时长 / 谱师」六行。
- `charter` 传的是当前登录账号的 `nickname ?? username`（`displayName`），不是 `chart.charterCredit`；它和平台的帖子作者信息重复。
- 难度名与等级分两行；帖子头部本来就会显示 Expert / Special，用户只想要等级。
- 生成器是纯函数、无预览；点击立即覆盖当前描述（靠 `document.execCommand('insertText')` 进撤销栈）。
- 现有可复用数据：`countChartNotes`（音符数）、`formatDuration(project.durationSeconds)`（时长）、`getBpmEvents` + `bpmRangeText`（BPM 区间）、`maxNoteEndSeconds`（最后击打秒）。**没有 NPS / 密度 / 最大同时押的现成 helper**；需要新定义并新增纯函数。

### 「关联已有帖子」

- `PublishAssociateControl`（`src/pages/projects/components/PublishRecoveryPanel.tsx`）在 `!published && onRecover` 时**总是**渲染进底栏；而 `onRecover` 在工程页总是传入。于是任何未发布谱面（包括从未发过帖的新工程）都会看到它。
- 这是票 58 Q4 为「0.2.1 遗留：帖子已建、本机没记录」留的兼容入口；票 58 明确写了「未发过帖也能看底栏关联」。
- 形态：未展开是底栏左侧的无边框小字链（`.ppc-associate__toggle`，`--text-muted`）；点击后原地换成「帖子 ID 输入框 + 核对并关联按钮」的内联表单。底栏不换行（`.dialog__foot` 只有 `flex-wrap` 的 `--start` 变体才有），展开会挤压取消 / 发布。
- 语义没有解释：新用户不知道「关联已有帖子」是什么、什么时候该用；它和正文里「发布结果待确认」告警的「重新核对」在概念上重叠，却不是同一处。

### 跨条的信息架构问题

发布弹窗 = 票 11 的「必填表单」骨架 + 票 42 的「只读身份卡」拼接；之后票 51 加标签、票 52 加自动生成、票 58 加关联入口，都是往同一张窗上叠件。缺一个统一的「发布前检查 / 谱面概览」模型：

- 缺什么靠零散红字；
- 去哪儿补靠猜；
- 生成内容靠字段名，而不是「玩家关心的谱面数据」；
- 低频补救动作被放在最高权重的底栏动作区。

## 根因（分层）

1. **封面（#1）**：产品口径是「封面可选弱空位」（票 42 Q7），但实现只做了弱空位、没做「可设置」；设置入口留在工程信息弹窗，发布弹窗既不告知也不代理。CSS 里甚至有一条未接线的 `is-empty` 危险态，说明「缺失要顯眼」的意图曾存在、没落地。
2. **缺失提醒（#2）**：预检模型没有 cover 档，封面缺失不参与 `precheckPublish`，所以按钮不会禁用、也不会点名；`refs` 与 `project.coverBlob` 两套存在性判据还可能互相矛盾。
3. **自动生成（#3）**：票 52 Q5 的「事实块」按「弹窗里有什么字段」挑事实，而不是按「帖子看不到、但社区读者关心什么」挑。标题 / 谱师 / 难度名都是帖子头部已有的信息；NPS、BPM、密度这类只存在于谱面里的信息反而没有数据源。
4. **关联入口（#4）**：票 58 Q4 的兼容入口被当成正式动作放进底栏。它低频、有风险语义（校验作者 / 曲目 / 谱面内容），却用最轻的无边框文字链承载，展开后又变成表单，视觉权重与交互形态自相矛盾。
5. **跨条**：没有「发布前检查」这一层，所有缺项只能依赖每个字段自己的红框；用户看到的是一张需要逐项核对的表单，而不是「这张谱能不能发、还差什么」的检查结果。
