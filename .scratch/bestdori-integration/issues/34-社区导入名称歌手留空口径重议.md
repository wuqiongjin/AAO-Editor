## 来源

用户 2026-10-13：
> 社区谱面导入后，歌曲名称、歌手名称都没有成功导入。全都显示"未命名工程"、"未填歌手"。顺带改一下文本描述："未填歌手" -> "未知歌手"。

## 根因（重要：这不是 bug，是既有定案）

- **数据全程可用，是导入编排层刻意丢弃**：`communityImport.ts:145-151` 传 `name: ''` / `artist: null`。候选里 `PostCandidate.title`（原帖标题）、`artists`（自报歌手）、`charter`（谱师）齐全（`mapping.ts:205-220`），bandori 帖还有官方曲名/乐队。
- 依据是**票 09 落地前 grill Q2（2026-10-12 用户拍板）**：「工程名称 / 歌手预填 → **全留空**（防『转手名字』贯彻到工程级）」，且有防回潮锁测（`tests/unit/project/CommunityImport.test.ts` 名称全空用例）。
- 因此本票的实质是**推翻/修订既有定案**，不是修缺陷。官方导入不受影响（一直预填 `song.title` / 乐队名）。

## 顺带（无需拍板，随本票落地）

- i18n 文案：`projects.artistMissing` zh-CN「未填歌手」→「未知歌手」（`src/i18n/messages/zh-CN.json:28`）；en.json 同键 "No artist" 是否同步改 "Unknown artist" 一并处理。共 4 处使用点（ProjectHub/ProjectDetail/OfficialSongPanel×2），键不动只改值，无代码改动。

## 定案（用户 2026-10-13，**推翻票 09 Q2**）

1. **推翻「全留空」**，改为全部预填：
   - bandori 帖 = **官方曲名 + 官方乐队名**（与官方导入同口径）；
   - custom 帖 = **原帖标题 + 帖子自报歌手**（`post.artists`）。
2. `ProjectChart.title` 继续跟随工程名，不单独动；谱师署名维持只在导入会话展示。
3. 「防转手名字」约束就此放弃（对应防回潮锁测同步反转改写）。
4. 顺带文案照做：`projects.artistMissing` zh-CN「未填歌手」→「未知歌手」；en 同键 "No artist" → "Unknown artist"。
