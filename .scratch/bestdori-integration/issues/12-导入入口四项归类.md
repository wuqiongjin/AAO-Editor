# 12 · 新建工程的导入入口归类（四项）

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-09 原话：

> 关于在工程导入谱面的方式：1. 空白创建 2. 从本地谱面工程导入 3. 从官方谱面导入 4. 从社区谱面导入。
> 我觉得按照如上归类方式比较合适，因为**用户根本不关心 Bestdori**，它们在意的只有「官方谱」还是「社区谱」，而这两种虽然我们都是从 Bestdori 获取的，但是他们要区分出来。

取代的对象：`chart-projects/issues/01` 定案 11 的「新建来源 = 空白 / 复制工程 / 从 Bestdori」三条 + 定案 13 的「从 Bestdori 来源三种（BanG Dream / LLSIF / Community）」。

## 定案（用户 2026-10-09）

**分类轴 = 「谱面从哪来」，不是「数据从哪个站来」。** 四项并列为用户可见的来源：

| # | 入口名词 | 语义 | 落在哪张实现票 |
| --- | --- | --- | --- |
| 1 | **空白创建** | 定一张谱面的难度就开写（现状 `NewSource = 'blank'`） | 已落地（04 / 05） |
| 2 | **从本地谱面导入** | 以本机已有工程为源（= 现状「复制现有工程」改叫法） | 已落地（`duplicateProject`），本票只改名词与入口排布 |
| 3 | **从官方谱面导入** | 官方曲库选曲 → 曲目素材 + 可选官方谱面代码 | [08](./08-曲库浏览与官方曲导入.md) |
| 4 | **从社区谱面导入** | 社区帖选谱 → 谱面代码 + 帖内曲目素材 | [09](./09-社区帖浏览与导入.md) |

配套口径：

- **入口名词定稿**：第 2 项由「从本地谱面**工程**导入」缩短为「**从本地谱面导入**」（用户 2026-10-09 追加，与另两支同构：从 X 谱面导入）——语义不变，对象仍是**整份谱面工程**（连音频、封面、全部谱面一起照搬），不是单张谱面；名词短不等于语义变小。

- **「Bestdori」不进用户文案**。界面上说「官方谱面 / 社区谱面」；Bestdori 是实现细节（CONTEXT「社区平台」已定"当前只有 Bestdori"）。域名、站名、`post/list` 这类词一律不许出现在入口与选择界面。
- **官方 / 社区的区分是"用户视角的来源"，与 `曲目来源` 字段是两个维度**：前者说"这套东西是从哪拿来的"，后者是"发布时 `song` 怎么填"的指针（CONTEXT 已有口径：导入不锁本地编辑）。因此 **`曲目来源` 的显示名不跟着改**（仍是自定义 / BanG Dream / LLSIF）。
- **原「从 Bestdori」这个入口名词作废**：它是实现视角，用户看不出官方 / 社区之别。
- **原「BanG Dream / LLSIF / Community」三分作废**（只作实现内的分支）：游戏之分只在 `曲目来源` 里留痕；`song.type` 仍是 `bandori` / `llsif` / `custom` 三值，不动。
- **静态演示版**（ADR-0011 §1）只隐藏 3、4 两支，1、2 保留（判定口径 = `window.electronAPI` 缺失）。

## 实现落点

- `src/pages/projects/components/ProjectDialogs.tsx:13`：`export type NewSource = 'blank' | 'copy'` → 四值（建议 `'blank' | 'copy' | 'official' | 'community'`：值名只是内部接线，`copy` 就还是复制、不跟着界面名词改名，少一层无谓改动）。`NewProjectDialog` 的 `.dialog-tabs` 由两钮变四钮，四个来源共用一个弹窗壳（弹窗壳已定 `src/ui/Dialog`，尺寸档位沿用）。
- 两处入口同源改：`ProjectHub.tsx:154-159` 的 `.pb-tiles`（现两块 tile）与 `ProjectsPage.tsx:299-305` 的分裂按钮菜单（现两项）。tile 文案键参考现成的 `projects.newBlankDesc` / `projects.newCopyDesc` 配套写。
- 文案进 `src/i18n/messages/{zh-CN,en}.json`：`projects.newCopy`（"复制现有工程"）→ 「从本地谱面导入」及对应 desc；新增官方 / 社区两支的标题与 desc。**别处已提 Bestdori 的既有文案不动**（如 `projects.uploadsEmpty`「还没有谱面上传到 Bestdori」、`projects.chartNameHint`「这是上传到 Bestdori 的 title」）——那些是**上传链路**的话，不是导入来源的话；要不要一并去 Bestdori 化另开票。
- `ProjectsPage.tsx` 的 `newSource` state 与 `createBlank` / `copyProject` 回调按四值铺开（官方 / 社区两支本票只摆位与占位，实做在 08 / 09）。
- **落点口径不变**：四种来源走完都照 ADR-0015 §3 / issue 23 的既有定案——留在工程详情、新工程成为当前工程、不跳工作台（`enterWorkspace` 之外的 `setActivePage('workspace')` 仍被静态断言挡着）。官方 / 社区两支多了"下载素材"这一步，落盘时机与取消语义（用户在下载中途关弹窗）归 08 / 09 各自定。

## 锁测

1. `tests/dom/pages/` 新增／扩写：`NewProjectDialog` 渲染出**四个**来源钮，点官方 / 社区钮切到对应面板（08 / 09 落地前先锁"有这一格"）。既有 `ProjectCreateCopyLanding.test.tsx` 锁的三条（不跳工作台 / 成为当前工程 / 详情切过去）不动，本地导入这一支必须继续过它。
2. **文案守卫（静态源码断言，照 `tests/static/PreviewAssetAcquisition.test.ts` 读 i18n JSON 的惯例）**：新建入口用的 i18n 键（`projects.new*` 一族）**值里不得出现 `bestdori` / `Bestdori`**——这条是本票用户口径的唯一机器可验形态，也是防回潮总闸（人一图省事就会把"从 Bestdori 导入"写回文案）。
3. 单测覆盖不到的：四块 tile / 四钮在窄窗口的折行与选中态视觉 —— 走人工验收清单。

## 边角口径（2026-10-09 用户确认）

- **「从本地谱面导入」不含"工程文件导入"**：口径 = 以本机已有工程为源（选一个，照它建新的），**不做**从磁盘导入工程包 / 导入另一台机器的数据根。现状全仓也没有工程级导入导出 —— `electron/main.cjs` 那 14 个通道里只有 `chartCode:saveAs`（谱面代码 JSON）与 `preview:saveBinary`（图片）两种另存，工程的落盘形态是数据根下 `projects/<id>/` 三个文件，`project:list` 只是扫目录。将来若要文件级导入/导出，那是**新能力**（新 IPC + 新文件形态 + 校验），另开票。
- **官方 / 社区两支只做在「新建工程」这一层**，不进「工程详情 → 新增谱面」：这两个来源自带曲目素材（音频 + 封面属于**工程**），往已有工程里塞会撞上「一个工程一首歌」的音频归属（也撞上 `曲目来源` 的语义），不是加个入口就完事的事。将来要开，先解决与工程现有音频 / 曲目来源的冲突规则。
- **文案长度**（用户 2026-10-09 追加）：入口名短、desc 一句话封顶，**不许写成解释句** —— 表里第 2 项原来写成"以本机已有工程为源新建工程"，太长，已精简掉冗余的尾巴（整个弹窗本来就在"新建工程"语境里，尾巴是重复）。
- **落地文案**（初稿，实做时照此写）：`projects.newCopy` = 「从本地谱面导入」/ desc = 「拿已有工程当底子」；官方与社区两支同期补标题与 desc（实做在 08 / 09，同样一句封顶）。
