# 24 · 封面加载三态（微光 / 失败可重试 / 无封面）+ 可复用加载组件

Type: feature
Status: resolved 2026-10-12
Blocked by: —

## 来源

用户 2026-10-12 验收反馈 #5：加载中就显示一个「cover」，「不然都无法区分到底是在加载中，还是加载失败没有封面图。加载失败时，有办法重新让它加载吗？」并点名动态视频预览的加载态未来复用。

## 症状 / 根因

- **加载中**：`.off-cover__ph` 只有静态文字 `projects.official.coverPlaceholder`（=「封面」，`OfficialSongPanel.tsx:284`），实测 `animationName: none`；
- **失败与「曲目本身无封面」同显一个 `Music4` 裸图标**（`OfficialSongPanel.tsx:297-299`：`jacketImage === '' || coverFailed` 走同一支），三态不可区分，且失败后**没有就地重试**（唯一恢复途径 = 换首歌再换回来）；
- 动态预览加载态同样是静态文字（`PreviewVideoStage.tsx:399`「正在读取场地素材…」）—— 用户点名的复用点。

## 定案（用户 2026-10-12 诉求 + 复看反馈）

- 三态可区分：**加载中 = 微光 + 居中 spinner**（用户复看：「加载封面时，有加载动效吗？我貌似没看到」—— 原 7% 微光太淡，已加到 12% 并加 18px spinner，不保留文字；本机 cache 秒开看不到属预期，初次网络加载才走这条）；**失败 = 图标 + 「封面加载失败，点击重试」，整块可点**（文案为用户 2026-10-12 原句）；**无封面 = 裸图标**（重试无意义，不给）；
- 落成为 `src/ui/` 共享加载组件，动态预览那处**本票只预留口径、不改**（接入另开票）。

## 修法

- 抽 `src/ui/LoadingShimmer.tsx`（块级微光：绝对定位填满父级 + 100deg 渐变 + `off-thumb-shimmer` 关键帧上收 `ui.css`）；`.off-row__thumb-ph` 与 `.off-compact-audio.is-skeleton` 改复用它（行为等价，观感不变）；
- 封面加载态 = `LoadingShimmer` + 居中 spinner（复用 `off-spin` 关键帧，2px 边 + accent 顶边，18px）；
- **spinner 必须与微光层平级、各自绝对定位居中**（`inset:0 + margin:auto`），不许做微光层的子元素 —— 微光动画是整层 `translateX(-100%→100%)` 扫光，子元素会被带着横向漂移（用户实测「转圈圈会横向移动」；原型修复后 8 次采样中心点恒定、矩阵变化 = 原地转）；
- `OfficialSongPanel` 封面区改三态：加载中 → 上述组合；失败（`coverFailed`）→ 图标 + 重试按钮，点击 `setCoverFailed(false)` + `setCoverReady(false)` + `coverUseDirect` 打回 false + 给 `<img>` 上 nonce/key 强制重挂载（让「本机优先 → 直链」降级链重走一遍；此时请求已终态，重挂是安全的）；无封面维持裸图标；
- i18n 新增一条 zh/en：`projects.official.coverFailed`（「封面加载失败，点击重试」，用户 2026-10-12 原句，整行一句）；
- **重试只许在 onError（请求已结束）后触发**：本轮原型实测 —— 同 URL 重挂一个「飞行中」的 `<img>`，Chromium 会让新请求永久挂住（`naturalWidth=400` 但 `complete` 永远是 false）；生产的重试入口天然满足（onError 即请求终态），但别在加载中也去做「强制重挂」。

## 锁测

1. `tests/dom/pages/OfficialPickerPreview.test.tsx`：img onError 且直链也失败 → 出现重试按钮、微光消失；点重试 → `<img>` 是重新挂载的新元素；`jacketImage === ''` 的曲子只出裸图标、不出重试；
2. **缓存图竞态护栏**（票 20 一族）：img 在 onLoad 挂上前已 complete（重挂载 / 磁盘缓存）时 onLoad 永不来 —— 封面态需挂载后同步补判。本轮原型实测复现过该竞态（`naturalWidth=400` 但 `is-in` 丢失）；
3. 真机：断网点开一首歌 → 微光 → 失败态 → 点重试 → 恢复网络后封面回来。

### 2026-10-12 · 验收回修（缓存秒开也闪微光）

用户验收发现：重开弹窗后再点已缓存条目，封面仍闪一下。根因三段叠加：① 关弹窗 = `OfficialSongPanel` 整树卸载，`selected`/`coverReady` 全归零（票 20/21 守卫只防同一挂载实例内）；② `aao-asset://raw/` 零网络但**异步**（协议 handler → fs 往返），img ≥1 帧才 complete，微光必然出现一瞬 —— **「动效绑定 img 未 ready 而非网络慢」**，定案时「本机 cache 秒开看不到属预期」的口径实测不成立；③ `.off-cover img` 的 180ms 淡入。列表缩略图同理。

- 修法（用户拍板「延迟显示」档，否掉「去淡入」与「两者都做」）：动效只表示「真的慢」—— `useSlowLoading(ready, key)`（`LoadingShimmer.tsx`，150ms 阈值）挂微光与 spinner；ready = 已就绪或终态，换歌 / 直链降级 / 重试重置计时。缓存秒开全程零微光、只留柔和淡入；网络慢路径反馈保留（票 24 三态可区分性不丢）。
- 锁测：`OfficialPickerPreview.test.tsx` 假计时器用例 —— 100ms 无微光/spinner、200ms 出现、ready 撤掉（fake timers 下禁用 waitFor，同步断言 + act 驱动计时）。
