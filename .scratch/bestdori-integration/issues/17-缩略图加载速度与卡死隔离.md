# 17 · 缩略图加载速度（串行队列 × 跨境慢链路）

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-10 对票 15 落地版的**真机验收**意见 #1、#2，原话：

> 你这缩略图加载的速度非常非常慢... 平均 10s 能出来 1 首歌曲的图。（当前这个图片加载的策略是什么? 会对服务器造成压力吗？一次加载多少张？）
> black shout 还是没出图，我不知道要验证什么。主要是可能出图速度太慢，导致我很难观察这个现象。

## 症状

- 打开「从官方谱面导入」后，缩略图以 **~10s / 首** 的速度逐张出现；首屏（约 8–10 行）要一分钟量级。
- 有时整片**停住**：不是慢，是等 —— 单张卡住会把后面全部请求一起拖住。
- #2 已单独定位（见下），是验收样本被我下成半截文件，不是产品缺陷。

## 根因

1. **全应用只有一条串行网络队列**：票 07 定案「单飞 + 两次请求起点间隔 ≥400ms + 二进制单次超时 120s」。
   缩略图这一路是「行可见 → 经网关取整图（未命中才下）→ 再读本机缩略图」，N 行 = N 次**串行**跨境下载；
   且任何一张 stall，**队列后面的行图 / 详情 / 试听 / 导入一起等**。
2. **体感完全绑在跨境链路上**：2026-10-10 实测 —— 单张 98.5KB = 6.95s（≈14KB/s）；
   同一台机器另一次请求 32KB 卡到 120s 超时；4 张并行墙钟 38.9s。链路不只是慢，**会 stall**。
   原型之所以「感觉还行」，是因为它用浏览器直链（并发 ≈6 + 站点 HTTP 缓存 4h）。

## 已定位（不依赖拍板，随本票一起修）

- **产不出缩略图 → 行永远显示断图**：验收时我把一张**半截 PNG** 塞进缓存复现了整条链路 ——
  `nativeImage.createFromBuffer` 解出空图 → `ensureThumb` 回 null → 协议 404 → 行上一直是个断图图标，
  用户看到的是「还是没出图」而控制台没有任何提示。
  修法：缩略图取不到时**回退直链显示原图**（而不是断图）；同一份坏字节不要反复重下。
- **卡死没有隔离**：一条请求 stall 阻塞全局（根因 1），二进制下载不该把详情 / 导入一起拖住。

## 待拍板

见 Comments 的 grill：Q1 取图策略（选项 1/2/3）、Q2 对平台的客气程度。

## 选项（首屏体感 / 首轮流量）

| | 做法 | 首屏体感 | 首轮流量 |
| --- | --- | --- | --- |
| **1 · 只放宽队列** | 缩略图档单独并发 2–4 + 间隔收到 ~100–200ms + 单张超时收到 ~20s（失败静默） | ~15–30s（仍受跨境限制） | **最省**：每首歌只下一次整图（用于产 96px） |
| **2 · 直链即时显示 + 后台入缓存** | 行可见就挂 `<img src=直链原图>`（体感 = 原型），同时后台经网关把封面收进缓存 → 下一轮进列表读本机 96px、零网络 | 立刻 | 首轮每首歌**多下一次**整图（显示一次 + 入缓存一次） |
| **3 · 1+2 叠加** | 直链即时显示 + 网关并发填充 | 立刻，且后台填充也快 | 同 2 |

## 锁测（方向，拍板后写）

- 「每首歌只取一次」仍成立：命中不打网络；并发数与间隔是常数（改一处可调）。
- 缩略图产不出 → 回退直链（DOM：缩略图节点失败后 `src` 落到直链，不断图、不重下）。
- 卡死隔离：一条二进制请求 stall 时，详情 / 导入不被阻塞（假出口 + 可控时钟）。

  （产出 23683B 缩略图、协议 200）。

### 2026-10-10 · 落地记录（本轮）

**网关（对 07「单飞」口径的修订）**

- `electron/communityNet.cjs`：队列分档 —— `createLane({ concurrency, minIntervalMs })` = N 条独立串行链，
  链上两次「开始」至少隔 `minIntervalMs`；**并发 1 时与 07 的「单飞 + 最小间隔」逐字等价**（既有锁测原样通过）。
  API 档 = `MIN_REQUEST_INTERVAL_MS`(400) 不动；素材档 = `ASSET_CONCURRENCY`(4) / `ASSET_MIN_REQUEST_INTERVAL_MS`(100)。
  分档顺带把卡死隔离开：**素材档 stall 不再堵 API 档**（详情 / 导入照走）。
  口径说明：07 的「单飞 + 400ms」是照 API 设计的低速率，静态素材跟着一起串是票 15 踩到的坑（4 并发仍比站点自己的列表页 ≈6 客气）。

**渲染侧**

- `OfficialSongThumb.tsx` 重写为「**本机优先 → 直链兜底 → 图标**」：行可见即挂 `<img src=本机缩略图>`（上一轮已入缓存就
  零网络秒出），本机没有（协议 404）落回**直链原图**（浏览器并发 + 站点 4h HTTP 缓存 = 原型体感），两者都不成才降级；
  **后台**照旧经网关把封面收进缓存（这条路不再挡显示）。平台没有这张图（回退页 → ensure 回 null）画音符图标而不是「失败」。
- `endpoints.ts` / `songs.ts`：封面单独一档超时 `BESTDORI_COVER_TIMEOUT_MS = 30s`，**只给列表背景取图**用
  （卡住的链路尽快让出素材档队位，失败静默、下一轮再试）；导入路径仍 120s（用户主动发起，值得等）。

**锁测（全绿，`npx vitest run` = 231 文件 / 2584 条）**

- `CommunityNetGateway.test.ts` 新增 4 条：素材档最多 4 个同时在飞（原来 1）；API 档仍单飞；一张素材卡住不阻塞 API（卡死隔离）；档位常数。
- `OfficialPickerThumbs.test.tsx` 重写 6 条：没滚到既不发请求也不挂 img；本机优先 → 直链兜底 → 再失败才图标；
  平台没图 → 音符图标；后台取数失败不影响显示；行结构不破；无观察器直出。

**没做（明确留下）**

- 缓存里那份「产不出缩略图的坏字节」不主动重下（否则会变成反复下载）；显示路已有直链兜底，用户侧看到的就是一张正常图。
- 预览区大图 / 试听仍走直链 —— 那是 [16](./16-导入复用已取素材.md) 的 Q2，本票不动。

**真机待验（单测覆盖不到）**

1. 打开选曲台：首屏**立刻**出图（直链），不再是 10s 一首；滚到哪出哪。
2. 关掉弹窗再开（二次进列表）：缩略图**本机秒出**，devtools Network 里不再有该封面的跨境请求。
3. 数据根 `cache/community/` 能看到后台填进来的 `*-*.thumb.png`（素材档并发填充）。
4. 断网 / 平台抽风时：行要么显示直链图、要么显示图标，控制台无循环报错；详情 / 导入不被行图拖住。
