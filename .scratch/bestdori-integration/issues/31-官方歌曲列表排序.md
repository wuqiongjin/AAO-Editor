# 31 · 官方歌曲列表排序

Type: feature
Status: open

## 来源

用户 2026-10-13：「官方歌曲列表是否可以加个排序？（按发布时间/谱面ID/等等）」

## 现状与根因

- **没有排序功能**：`OfficialSongPanel.tsx` 只做过滤（`filterSongCandidates`），列表顺序由 `src/community/bestdori/mapping.ts:163-176` `toSongCandidates` 按 **song id 升序**写死。
- **发布时间数据在但不进候选**：曲库原始条目有 `publishedAt`（每服一个数组），当前只用于 `pickAssetServer` 选素材服，未映射进 `SongCandidate`（`mapping.ts:44-58` 只有 id/bandId/title/artist/jacketImage/server/difficulties）。
- 参考：工程列表已有排序先例（`src/project/projectSort.ts`，四键）。

## 修法

1. `SongCandidate` 增 `publishedAt`（映射层取主服或最早服时间，口径拍板后定）；
2. 面板加排序控件（与难度/等级筛选同一排）；排序键与默认排序待拍板。

## 定案（用户 2026-10-13）

- 排序键：**发布时间 / 谱面 ID / 曲名 / 乐队名** 四键；**默认 = 发布时间降序（最新在最上）**。
- 其他便捷键评估：难度/等级不进排序（语义已由筛选手风琴承担，两套难度语义并存收益低）；曲长等需额外拉详情，不做。
- publishedAt 各服口径：实现口径取**最早发布时间**（日服优先），待验收。

## 待拍板

- 排序键集合（发布时间 / 曲名 / 乐队 / ID）与默认排序是否维持「ID 升序」。

## 锁测

- 单测：`tests/unit/community/bestdori/`（songs 映射）新增 `publishedAt` 映射用例 + 排序函数用例（升/降序、同键稳定性、坏时间戳兜底）。
- DOM：排序控件切换后列表顺序断言（`tests/dom/pages/` 既有面板用例文件内补）。
