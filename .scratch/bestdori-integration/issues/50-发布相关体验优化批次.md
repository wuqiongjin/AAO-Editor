### #1 不可逆确认弹窗：标题行换行

**症状**：确认弹窗（`ConfirmDialog`）里说明文字与「确定发布「One Extra Large! Garupa☆Pico」？」
连排同一段，标题混在长句尾不易读。用户要求把问句挪到下一行。

**现状**：`zh-CN.json` `projects.publish.confirmMessage` 一句话内联 `{{title}}`；
`PublishDialog.tsx` 不可逆确认弹窗把整串交给 `ConfirmDialog` 的 `message`。

**Q**：
- Q1 拆法：拆两个文案键（`confirmMessage` 不可逆说明 + `confirmQuestion` 「确定发布「{{title}}」？」，
  弹窗里各自成段）还是 `ConfirmDialog` 支持多段 message？
- Q2 动不动 `ConfirmDialog` 本体：若改渲染层，扫一遍现有调用点防误伤。

### #2 发布失败信息展示优化

**症状**：失败后只在发布弹窗里塞一行红字（`pp-publish__error`，`role="alert"`），
如截图「社区平台拒绝了这次发布，请检查谱面与各项信息后重试。」——非常简陋。

**现状**：`PublishDialog.tsx` `FAILURE_KEYS: PublishFailure → 文案键`，失败 = 弹窗内一行红字；
平台码不上界面（票 11/49 口径：不猜失败成因）。49 落地预检后，谱面域外值会在发布前被点名，
但平台侧拒绝（rejected / 5xx 等）仍只有这一行。

**Q**：
- Q1 形态：保持一行红字但视觉加强（图标 / 定位到对应字段）？还是失败态改成一块
  可关闭的告警区（含「重试」动作）？
- Q2 rejected 档能指到多细：不改「不猜成因」口径的前提下，至少把「请检查谱面与各项信息」
  变成可操作的（例如高亮「谱面」摘要条目 / 引导去检查哪几项）？

### #3 工程详情的「音频与时长已锁定」说明占空间

**症状**：发布后工程详情音频行尾出现「已上传谱面 [Test] One Extra Large! Garupa☆Pico（Easy 1），
音频与时长已锁定」，文字很长；用户认为音频页已有同款锁定说明，详情页这份占空间。

**现状**：同一文案键 `projects.audioLockedNamed`（「已上传谱面 {{charts}}，音频与时长已锁定」）
用在两处：
- `ProjectDetail.tsx:128`：详情页音频行的行尾小字（`pp-lock-note`，锁图标 + 全文）；
- `AudioPage.tsx:204`：音频页顶部独立横幅（`audio-locked-banner`，锁图标 + 全文）。

**Q**：详情页这份收敛到什么程度——只留一枚锁图标（`title` 提示全文）？还是只留
「音频与时长已锁定」短语不点名谱面？还是整段删掉只靠音频页说明？
（注意详情页这行的职责：不出音频页也能看到锁定态，删掉是否丢信息要拍板。）

### #4 多谱面发布时，锁定说明会怎么变

**用户原问**：这种说明明确点名了特定谱面，一个工程发布多张谱面时会怎样？要不要优化？

**现状事实（2026-10-22 查证）**：会变——`lockedChartLabels`（`src/project/ui/projectUi.tsx`）
把工程里**所有**已上传谱面逐个拼进文案、顿号分隔（「谱面A（Easy 1）、谱面B（Expert 30）」），
`ProjectDetail` 传 `uploads` 全量、`AudioPage` 传 `view.lockedBy` 全量。
所以每多发一张，两处文案都变长一行；三张以上可读性会崩，#3 的占空间问题会被放大。

**Q**：多张时的形态——截断 + 「等 N 张」（tooltip 全量）？只计数不点名（「已上传谱面 3 张」）？
还是维持全量点名？（票 15 定案 6 的初衷是「点名才能判断能不能救」，全删点名与初衷冲突，
要重新权衡。）

## 实现落点（2026-10-24 落地，拍板与去向）

- **#1**：拆两键 + `\n` 拼接（AskUserQuestion 未获答复，按推荐项执行）。
  `confirmMessage`（后果说明）+ `confirmQuestion`（确定发布「{{title}}」？）两个键，
  `PublishDialog` 用 `\n` 拼接交给现有 `message` —— `.dialog__message` 已有 `pre-line`，
  问句独占一行；`ConfirmDialog` / `Dialog` 零改动，5 个调用点零风险。
- **#2**：失败展示升级为告警区块（`pp-publish__alert`，danger 左饰边 + soft 底，
  样式族照 `.audio-locked-banner`）+「重试」（重新走不可逆确认门，不直接发请求）+ 可关闭
  （`ui.dismiss`）。rejected 文案改为可操作表述（点出建议核对项：标题、歌手、难度与等级、
  谱面与描述），仍不猜平台拒绝成因。环境异常（读不到引用 / 已发布过）同壳但不挂动作；
  失败与常驻事实重复时不叠两条。code-review 后补两条口径：「重试」只给平台 / 网络 / 会话档
  （`RETRYABLE_FAILURES`；chart-invalid / local / unsupported 这类确定性拦截不给，重试必然原样再败）；
  重试与发布键都**不再先清告警**——确认门上取消告警仍在（信息仍然为真），真正发起发布（runPublish）才清。
- **#3**：详情页收敛为短语——新键 `projects.audioLockedShort`「音频与时长已锁定」，
  不点名谱面；锁定态仍不出音频页可见，点名职责归音频页横幅。
- **#4**：点名封顶——`lockedChartsSummary()` 返回 `{ text, fullList }`：≤3 张全量点名
  （`fullList` 为 null），更多时点名前 3 张 + 「等 N 张」（N = 总数，`projects.lockedChartsMore`；
  en 键带前导空格作分隔），`fullList` 供横幅挂 `title` 悬停提示。封顶的判断只活在 helper 里，
  调用方不自己数张数（code-review：收敛掉 maxShown 无人转的旋钮与两处重复截断判断）；
  票 15 定案 6 的「点名判断能不能救」保住（名单 hover 仍可见）。三张及以内不截断。

改动面：`zh-CN.json` / `en.json`（键增删）、`PublishDialog.tsx`、`ProjectsPage.css`
（`.pp-publish__error` → `.pp-publish__alert` 族）、`ProjectDetail.tsx`、`projectUi.tsx`
（`lockedChartsSummary` + `LOCKED_CHARTS_MAX_SHOWN`）、`AudioPage.tsx`；
锁测 `ProjectPublishConfirm` / `ProjectDetailAudioRow` / `AudioPageProjectScope` 已按新形态断言
（问句成行、告警块重试与关闭、详情短语、3 张边界 / 4 张截断 + title 全量）。
