# 18 · 缓存清理策略可设置 + 设置页文案收敛

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-10 对票 15 / 14 落地版的**真机验收**意见 #3，原话：

> 社区素材缓存，这个条目废话太多。用户根本不关心这些信息，它只关心占用了多大的磁盘空间、清理的策略吧？
> 清理策略最好可以设置。

## 症状

- 设置 → 存储与数据 → 「社区素材缓存」那段：口径说明比数字还长，扫一眼看不出「占了多少 / 什么时候会被清」。
- 回收参数是票 14 定死的常数（闲置 30 天、总量 1GB、写入后节流清扫），用户改不了。

## 根因

- 票 14 落地时把「口径说明」（缓存范围 / 不进分发物 / 回收规则）写进了界面 hint —— 本意是记账，实际是
  **内部行话上了界面**；界面上真正需要的只有「占了多少 + 会怎么清」。
- `electron/assetCache.cjs` 的 `MAX_AGE_MS` / `MAX_BYTES` 是模块常数，没有落成配置。

## 待拍板

见 Comments 的 grill：Q1 界面上留哪几个数、Q2 哪些策略可改（范围 / 默认）、Q3 生效时机。

## 实现落点（候选，拍板后细化）

- `src/pages/settings/SettingsPage.tsx`「存储与数据」分区里的那一块：占用（总量 + 条数）一行 + 策略控件；
  说明文案压到一行（细节收进 tooltip 或删）。
- 策略落 settings（ADR-0003 配置系统）→ 经 IPC 推给主进程；`assetCache` 的 `maxAgeMs` / `maxBytes`
  从常数改成可注入（既有 `stats` / `clear` 两条 IPC 旁边加一条「策略」）。
- i18n 键：那一块的文案键一并重写。

## 锁测（2026-10-10 已落地，见 Comments 落地记录）

- 占用数字仍来自主进程（既有 `SettingsCacheBlock` 那族）；策略改了之后下一次 `sweep()` 用新参数（假时钟）。
- 极端值（0 天 / 极小上限）不炸：夹取到安全范围；「清除缓存」行为不变。

## Comments

### 2026-10-10 · 拍板（用户答复）

- Q1（界面留什么）→ **占用（总量 + 文件数）一行 + 两个策略数字**，口径说明那句删掉。
- Q2（配什么）→ **可配「闲置天数 + 总量上限」**，默认 **30 天 / 1GB**（票 14 那两个常数变成默认值）。
- Q3（生效时机）→ 实现口径：**改了立即生效**（下一次清扫 / 写入容量兜底就按新值算，不用重启）。

### 2026-10-10 · 落地记录（本轮）

**设置层**

- `AppSettings`：`cachePolicy: { maxIdleDays, maxMegabytes }` —— additive 字段，不 bump schemaVersion；
  `CACHE_POLICY_RANGE`（1–365 天 / 64MB–64GB）+ `DEFAULT_CACHE_POLICY`（30 / 1024）+ `normalizeCachePolicy()`
  （界面输入与配置导入共用同一把尺）；`mergeSettings` / `updateSettings` 都接上。
- `ConfigProvider`：新增 `setCachePolicy(patch)`（段内浅合并 + 落盘 + 推主进程）；**启动时**也拨一次
  （照 `setActiveUiLanguage` 的既有写法），所以重启后仍是用户改过的值。

**通道**

- 新 `src/community/assetCachePolicy.ts`：设置里的两个数 → 主进程载荷（天 → ms、MB → 字节）；
  桥不在（静态演示版）静默跳过。
- `electron/assetCache.cjs`：`configure({ maxAgeMs, maxBytes })` —— 参数改成 `let`，**下一次清扫 / 容量兜底就按新值算**；
  renderer 递什么进来都再夹一次（硬边界：1 天–10 年 / 1MB–64GB，界面那把尺是软约束）。
- IPC 第三条：`assetCache:configure`（preload 同步加）。缓存内容照旧不暴露。

**界面**

- 「社区素材缓存」块：占用一行 + 分桶（有内容才显示）+「清除缓存」+ 两个数字行
  （「闲置超过（天）就清除」/「占用上限（MB）」）；那句口径说明（`settings.cache.hint`）删掉，
  只在数字行的 hint 位留一句「改了下次清扫就按新值算，不用重启」。

**锁测（全绿，`npx vitest run` = 232 文件 / 2594 条）**

- 新 `tests/unit/chart/config/CachePolicySettings.test.ts`（5 条）：默认 = 30 天 / 1GB、additive 不 bump、
  save→load 往返、缺段 / 脏值 / 越界回落与夹取、`normalizeCachePolicy` 与 `updateSettings` 同尺。
- `AssetCache.test.ts` 新增 3 条：闲置天数改后 31 天不清 / 61 天清；总量上限改后写入即按新上限回收；
  越界与非有限数都被夹住或保持原值。IPC 用例改为三条通道。
- `SettingsCacheBlock.test.tsx` 新增 2 条：默认 30 / 1024 且启动时先拨一次给主进程；改了就推送并落进 settings。
- `CommunityNetWiring.test.ts`：preload 的缓存通道锁改成三条（含 `assetCache:configure`）。

**真机待验（单测覆盖不到）**

1. 设置 → 存储与数据：占用 + 两个数字（30 / 1024）；改成「7 天 / 256MB」后关设置页、重启应用 —— 仍是 7 / 256。
2. 把上限改小（如 64MB）再浏览曲库，写满后按最久未用回收（占用不超上限）。
3. 极端值：输入框里敲 0 / 99999 → 被夹回区间，不会出现「0 天 = 什么都清掉」。
