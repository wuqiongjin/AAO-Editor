## 来源

用户 2026-10-16（票 42 落地后真机）：发布弹窗 7 条。一类问题收本票，不拆号。对照票 11 预检 + 票 42 原型 A。

## 症状

1. 无音频却仍有「时长」数字，且右下角「发布」可点（用户称特意构造、正常路径不该出现）。
2. 就地改难度后点弹窗外（关窗），窗关掉又自动再打开。
3. 点「发布」前到底拦什么（等级等）？
4. 右列条目：可输入值上下不齐；值与左侧标签也略不齐。
5. 难度原生 `<select>` 难看；空白创建 / 编辑谱面信息里还有同样的下拉。不确定要不要一起改。
6. 编辑谱面信息弹窗要不要加「描述」（与发布弹窗共享）？
7. 发布成功后现在是什么样？（不可逆，想先知道再真发）

## 根因（本轮实现口径待拍板）

### #1 无音频 + 有时长 + 发布可点

**时长本来就可以脱离音频存在**，不是发布弹窗独创的脏数据：

- `clearProjectAudio` / `AudioSession.clearAudio` 明确「时长保留当前值」；
- 无音频时 `setProjectAudioDuration` 允许手改时长（编辑器谱面长度，ADR-0005）；
- 空白工程默认 `durationSeconds = 30`。

发布弹窗里两套口径没对齐：

| | 显示 `audioMissing` | 预检 `precheckPublish` |
| --- | --- | --- |
| 依据 | `source==custom` 且（无 `refs.audio` **或** 无 `audioName`） | custom 只看 `song.audio == null`（即 `audio.bin` 的 uploadRefs） |
| 时长 | missing 时画「未填」，否则 `formatDuration(durationSeconds)` | **完全不看时长**（发帖 body 也没有 duration 字段） |
| bandori | `audioMissing` 恒为 false，永远画时长 | 不要求本机音频，只校验曲库 id |

因此：

- 预检**不会**因为「有时长无音频」就放行；custom 缺 `audio.bin` 应禁用「发布」。
- 若用户仍看到**数字时长且发布可点**，更像是 `source` 仍是 bandori（官方曲 id 足够发帖），或 `audio.bin` 还在而 `audioName` 已清（显示与预检各信一套）。
- 时长行在缺音频时改画「未填」，并没有把幽灵 `durationSeconds` 从工程里抹掉。

### #2 改难度后点外部 → 关了又开（不合理）

**不是「点外部应该重开」的产品行为。** 两段叠在一起：

1. **原生 `<select>` 点选项的 mousedown 打到 scrim。** `Dialog` 用 `dialog__scrim onMouseDown={onClose}`，面板 `stopPropagation`。Windows 下系统下拉画在面板 DOM 外，选 `Special` 的按下会先关窗。
2. **关窗后防抖写入把 `target` 设回来。** 改难度 → `syncChartMeta` 350ms 防抖 → `updateProject`。`closeDialog` 只 flush 描述草稿，**不清** chart/artist 定时器，也无 unmount 清理。`usePublishEntry.updateProject` 闭包里的旧 `target` 在 `saved` 后 `setTarget(...)` → 弹窗复活。改标题/歌手/等级同一条路径，难度只是最容易踩到。

### #3 发布前校验（事实，不改也能答）

`precheckPublish`（弹窗禁用键 + `publishChart` 入口各跑一次）+ 第二层红键确认。缺任一项则键禁用，确认窗不开。

拦：标题非空（谱面名，空则工程名原文，不用「未命名工程」兜底发帖）/ 歌手非空 / custom 必须有音频引用，bandori 曲 id 为正整数 / 难度 0–4 / **等级非空且 ∈ [1, 35]**（`POST_LEVEL_MIN/MAX`）/ 描述非空且 ≤5000 / sanitize 后还有可发音符 / 未发布过 / custom 的 uploadRefs 已读到且没失败。

不拦：封面（custom 可选）/ `durationSeconds` / 等级必须是整数（`28.5` 过 `parseLevel` 且落在 1–35 会过）/ 音符密度、等级与难度是否「合理」。

点「发布」之后还有「发布后谱面本体不可修改」确认，确认才真正 `publishChart`。

### #4 右列不对齐

`.ppc-a__id` 高 204px + `justify-content: space-between`，7×24px=168，余 36px 被均匀撑开，行距不稳。可编辑 `input` 有 1px 透明边框 + `padding: 0 6px`，只读 span（音符/音频/时长）没有，文字左缘与字号（标签 xs / 值 sm）对不齐。难度 select 高 22px vs 行 24px。

### #5 难度下拉

发布弹窗是带 `DIFF_COLORS` 的原生 `<select>`（option 列表跟系统走，和色块割裂）。空白创建、`ChartInfoDialog` 是 `.dialog-field select` 原生控件。详情谱面行的 `DiffLevelBadge` 已经是色块芯片，不走 select。

### #6 谱面信息要不要描述

描述是发帖 `content`，落在 `ProjectChart.publishDraft`，只在发布弹窗出现。谱面信息弹窗管标题/难度/等级（新建另加代码）。两边字段职责不同；加进去等于把发帖文案提前到日常改元数据。

### #7 成功后现状

无成功页。确认 → 上传/发帖 → `onClose` 卸弹窗 → Toast「已发布，帖子 #{{id}}」（记账失败则 warn：帖子已在平台、本机记录没写成）→ `reload`。该谱面变已上传只读，详情「上传记录」出外链 `postUrl(postId)`。不会打开浏览器帖子页。平台侧此后只能改难度/等级/标签，谱面本体不能改、不能自助下架（ADR-0015）。

## 定案（用户 2026-10-16）

- **Q1** 幽灵时长/无音频却可发布：**不管，保持现状**（用户已构造不出来）。
- **Q2** 点窗外：留下刚才的修改，窗保持关着。
- **Q3** 预检维持原字段；等级必须是整数（`28.5` 当缺项）。**2026-10-16 补**：三处改等级同一套——空可留（发布当缺项）；1–35 可存；0 / 负数 / 36+ / 非整数就地标红且不写工程。谱面信息越界时保存禁用、窗不关；徽标越界失焦/回车不提交。不 Toast、不夹逼。
- **Q4** 右列对齐按实现修，不出布局原型。
- **Q5** 本轮不整改全部难度下拉；发布弹窗那个带色原生 select 降噪成普通表单控件。空白创建 / 谱面信息不动。
- **Q6** 谱面信息不加描述。
- **Q7** 成功态维持关窗 + Toast，不自动打开帖子、不加成功弹窗。

## 实现落点

- `usePublishEntry.ts`：`setTarget(prev => prev == null ? null : …)`，关窗后在飞 mutate 不复活弹窗。
- `PublishDialog.tsx`：关窗冲刷难度/标题/等级/歌手防抖；难度 select 去掉 `DIFF_COLORS`。
- `PublishDialog.css`：右列固定 6px 行距，标签/值/输入同一条左缘与行高。
- `ChartInfoDialog.tsx`：`readChartLevelInput`（空→null，1–35 可写，其余不写）；谱面信息越界标红、保存禁用。
- `PublishDialog.tsx` / `ProjectBits.tsx`：越界标红且不防抖/不提交写入。
- `parseLevel` + `precheckPublish`：非整数与 1–35 外都算缺等级。
