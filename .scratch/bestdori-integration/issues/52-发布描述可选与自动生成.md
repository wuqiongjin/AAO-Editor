# 52 · 发布描述：可选与自动生成

Type: grilling
Status: resolved
Blocked by: —

## 来源与诉求

用户 2026-10-26：

3. 发布弹窗里的描述应该是可选的（Bestdori 貌似也是可选？）。
4. 描述支持按谱面信息自动生成。

弹窗生命周期 / 标签 / 发后改元数据见 [51](./51-发布弹窗标签与发后改元数据.md)。描述发后**不能**改（`post/edit` 无 `content`），所以本票只覆盖**第一次发布**。

## 现状

- 我们侧必填：`precheckPublish` 把 trim 后空串算 `missing: content`；placeholder「必填，不超过 5000 字」；空 textarea 标红，发布键禁用。
- 草稿记在 `chart.publishDraft`，发布成功后清掉（票 42 Q3）。
- 无自动生成。

## 根因

1. **「Bestdori 可选」不成立。** 官网前端 `userChartBody` 非空，否则 `POST_EMPTY`（`docs/research/bestdori-api.md` §9）。研究表把 `content` 标必填。API 是否接受空块数组**未测**，不能拿「貌似可选」当事实。
2. 我们把官网这条校验原样搬进预检，所以用户不填就发不了。
3. 自动生成不存在——描述是弹窗里唯一现场填写、又没有工程模型对应项的字段（草稿是后补的家，不是生成器）。

用户原以为平台可选；调查后否。第 1 轮推荐「对用户可选、提交时生成稿兜底」被否。

## 定案（用户 2026-10-26 · grill 第 1 轮）

- **Q4 否**：描述**仍必填**（平台不允许空就不允许空）。不想打字就用自动生成，不是把字段改成可选、也不是提交时偷偷填。
- **Q5** 生成稿只是事实块：标题、难度+等级、音符数、时长、谱师展示名；缺项跳过；不编歌词、不编玩法说明。

## 定案（用户 2026-10-26 · grill 第 2 轮）

- **Q12** 描述旁一颗「自动生成」；打开不预填；空仍不能发；框里已有字再点就直接覆盖。
- **Q13**（与 51 共用）发布成功后不再清空 `publishDraft`，发后只读展示。

## 待拍板（grilling）

无。已按定案落地。Q13 在票 51。

## 实现落点（预期，拍板后按实际调整）

- `precheckPublish`：**维持**空描述挡发布（与官网 `POST_EMPTY` 对齐）。
- 生成器纯函数（标题 / 难度+等级 / 音符数 / 时长 / 谱师）。
- `PublishDialog`：描述旁「自动生成」；点了才写入；空仍不能发。
- `publishDraft` 发布成功后保留，发后只读（51 已做）。

## 锁测

- `publish.test.ts`：空描述仍 missing；生成器缺时长 / 未登录 / 空标题 / 零音符跳过对应行。
- DOM：空描述不能发；点生成后可发；已有字再点覆盖；已发没有自动生成。

## Answer

描述仍必填。描述旁「自动生成」写事实块（标题 / 难度+等级 / 音符 / 时长 / 谱师），缺项跳过，打开不预填，已有字覆盖。Q13 发后不清草稿已在 51。
