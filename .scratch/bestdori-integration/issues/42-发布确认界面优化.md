# 42 · 发布确认界面：信息展示、缺项、描述草稿与正文能力

Type: grilling
Status: resolved
Blocked by: —

## 来源

用户 2026-10-15（真机截图 + 五条反馈）：发布确认弹窗「需要优化」。一类问题收本票，不拆号。

对照：票 11 落地（`PublishDialog`）+ 票 06 Q13（必填点名、不做草稿队列）+ 登录弹窗标题「?」先例（票 39 Q49 / `HelpHint`）。

## 症状

1. 六项只读摘要是「标签 + 纯文字」两列表格，视觉单调，缺项只靠值变红。
2. 「还缺以下信息，补齐后才能发布：」整块 inset 清单，与上方红字重复；描述缺了也再列一次（输入框就在下面）。
3. 描述只活在弹窗 `useState('')`：关弹窗 / 关软件即丢。
4. 站点正文是富文本块（实测至少 `text` / `br` / `emoji`）；我们发帖压成单块纯文本。用户问图片与内置表情要不要适配。
5. 标题下 hint「把这张谱面发布到社区平台。上传与发帖一次完成，中途取消不会留下半帖。」与标题同义 + 实现细节；用户建议收到标题旁「?」。

## 根因

**不是样式漏调，是票 11 把「预检点名」做成了第二份 UI，而描述没有工程里的家。**

1. **展示**：弹窗复用 `dialog-field` + `dialog-field-row`（表单标签/控件骨架），但六项全是只读，没有封面、难度色、音符量级以外的视觉锚。曲目行甚至把「无封面」写成括号说明，而不是露出封面空位。
2. **缺项盒**：票 11 / 06 Q13 要求「按字段点名缺什么」。实现把预检 `missing[]` **实时**渲成 `role="alert"` 清单（票 11 Comments 第 8 条：票面没要求实时盒，实现自作主张）。点名的真正价值是「去哪儿补」（工程信息 / 谱面信息 / 音频页），但这份信息叠在已经标红的格子上；描述缺项对空 textarea 是同义反复。
3. **描述丢失**：票 06 Q13 / 票 11 定案「**不做本地草稿 / 发布队列**」指的是失败上传的续传队列（回旋靠「复制谱面」）。描述是发布弹窗里**唯一现场填写**、且工程模型没有对应字段的东西（`ProjectChart` 无 content）。实现按字面没做任何持久化 → 关窗即卸挂载。这与「不做发布队列」不是同一决策。
4. **富文本**：研究文档已记录 `content` 为块数组，Fog 仍挂「完整语法 + 5000 字怎么计」。发帖路径写死 `[{ type: 'text', data: trim }]`，换行不会变成 `br`，emoji/图未接。图片块形状**未实测**（上传三步只对音频/封面）。`POST /api/post/edit` **没有 `content`**：发错不能改正文。
5. **hint**：`Dialog` 的 `hint` 是常驻一行；同壳的登录弹窗已把说明收进 `HelpHint`（`placement="down"`）。发布仍走旧 `hint` 槽。不可逆说明已经在第二层红键确认里（「发布后谱面本体不可修改」），常驻 hint 与确认窗职责重叠。

## 已拍板（用户 2026-10-15 / 2026-10-16 修订）

- **Q1** 摘要采用原型 A 身份卡视觉（左侧 1:1 封面，右侧 7 行元信息）；支持字段就地直接编辑（标题、歌手、难度、等级）并防抖写回工程。
- **Q3** 描述按谱面做草稿，记在该张谱面的工程记录里（复制一并带上），防抖写入；发布成功后清掉。不是发布队列。
- **Q4** 本轮不接表情盘和正文插图；纯文本 + 换行编成 `br`。图片块另开票（先实测）。
- **Q5** 常驻 hint 删掉，收到标题右侧「?」（`HelpHint`，与登录弹窗同款）；气泡只留「上传与发帖一次完成，中途取消不留半帖」。不可逆仍只在红键确认。
- **Q2** 缺口画在对应条目上：空槽就地标红与呈现，空槽代替伪值（不用「未知歌手 / 未命名工程 / —」）；灰盒删除；发布键不加「缺几项」`title`。无需接入点击条目弹窗或关窗跳转，缺项直接在就地输入框填写修改。
- **Q6** 取消条目点击跳转与叠窗联动，维持弹窗单一职责与轻量。
- **Q7** 自定义曲无封面是可选弱空位，不是挡发布的「未填」态。

## Comments

### 2026-10-15 · 设计迭代摘要

经三轮 grill 定案 Q1–Q7（见「已拍板」），随后在原型 A 上做了多轮视觉调整，最终定型：

- **曲目不是填写项**：发帖 `song` = 官曲 id 或自定义音频 URL；「缺音频」不映射成「曲目未填」。
- **账号**：右上角头像即可，不双写昵称/账号名。
- **难度 + 等级**：按用户定案，维持独立两行输入（难度 select 下拉框、等级 input 输入框），不合并为单行色块徽标。
- **音频**：文件名 + 时长分两行（文件名可能很长）；缺音频不画 `0:00`。
- **音符**：标签用「音符」；始终显示音符数，0 时出「谱面 未填」。
- **封面**：保持 1:1 正方形，边长跟右列高度走。
- **空槽**：必须带字段名（「歌手 未填」而非裸「未填」），不用虚线胶囊。
- **原型清理**：原型 A 已定型，`PublishConfirmPrototype` 等抛弃式原型及调试路由在定案后删除，不留生产主干。

### 2026-10-16 · 推翻「头像即可」（用户）

上方设计迭代摘要里「**账号**：右上角头像即可，不双写昵称/账号名」被用户推翻：「不双写」指昵称与账号名**不同时出现**（账号名称、昵称这两个一起写才叫双写），不是连昵称都不写；只放一个头像不合适。

**新定案**：发布弹窗右上角 = 头像 + **昵称**（展示名 `nickname ?? username`，与 `AccountBar` 的已登录行完全一致）；账号名不占可见版面，仍只在头像 `title` 提示里（「账号：envy09」）。长昵称省略、不挤标题（照 `.pc-account__text b` 口径）。

**落点**：`PublishDialog.tsx` 头部 `.ppc-who` 内加 `.ppc-who__name`；`PublishDialog.css` 补省略规则；锁测 `ProjectPublishConfirm.test.tsx`「有会话时画出昵称与头像」改断言昵称可见。
