# 59 · 社区谱面按谱师检索

Type: feature  
Status: resolved  
Blocked by: —

## 背景

用户提出「社区谱面搜索框支持输入谱师名称来搜索」。当前搜索框只发 `post/list` 的 `search`，平台侧只索引标题 + 歌手，谱师名永远搜不到。

## 平台事实（2026-11-26 直连实测）

| 请求 | 结果 | 含义 |
| --- | --- | --- |
| `search=Envy09` | 0 条 | `search` 不索引作者 |
| `username=Envy09` | 441 条 | 同一个人，按**账号名**过滤是通的 |
| `search=Envy`（他的昵称） | 18 条 | 全是别人标题含 Envy 的谱，不是他的 441 |
| `username=Envy`（昵称） | `REQUEST_INVALID` | 不认昵称 |
| `username=envy09` | 441 | 大小写不敏感 |
| `username=Envy0` / 中文昵称 | `REQUEST_INVALID` | 不支持前缀、不支持非 ASCII |
| `search=cosMo@暴走P` / `GUMI` | 250 / 341 | `search` 匹配标题 + 歌手 |
| `search=<某帖正文原句>` | 0 | 正文不索引 |

结论：

- 唯一的谱师字段 `username` 只接受**精确账号名**；账号不存在也回 `REQUEST_INVALID`（不是空结果）。
- 平台没有「昵称 → 账号名」的解析端点：`user/search`、`user/list` 等 404；`GET /api/user` 只认精确 `username`；站点自己的搜索框也只传 `search` —— 官方 Web 同样搜不到谱师。
- 界面展示的是 `charter = nickname || username`，用户手里的「谱师名」通常不是账号名 → **冷搜昵称在平台上做不到**。

## 定案（用户 2026-11-26，Q1=B）

1. **预览栏的谱师名可点** → 用该帖作者的账号名做服务端过滤（100% 命中）。
2. **搜索框并发一路 `username=<query>`**（`search` 那一路照旧）：知道账号名就能直接输。

## 落地口径

- 账号名探测只在**查询看起来像账号名**时发（可见 ASCII、无空格、含字母、2–32 字符）；中文 / 带空格 / 纯数字（那是帖 ID 直查那条路）不发 —— 省掉绝大多数白跑的请求。
- 探测**并发**在首页发出，零额外等待；失败（账号不存在 → `REQUEST_INVALID`）**静默丢弃**，不弹错、不影响关键字结果。
- 只有**关键字零命中、且账号名精确命中**时才把这一趟切成「只看该谱师」：列表切到 `search='' + username=<账号名>`，搜索框清空，bar 上出现「谱师：<昵称> ✕」。
  - 不在关键字有结果时也并入账号结果：账号名撞上歌名 / 歌手的概率不低（如 `roki`、`GUMI`），并进来会把真正要的歌挤到后面。
  - 切换后重新加载命中**会话页缓存**（探测那一发已经存过同一页），不闪白、不重复请求。
- 谱师筛选生效时，搜索框的关键字与账号名是 **AND** 关系（平台实测 `search` + `username` 同时给是交集）；翻页、刷新都带 `username`，游标与页缓存键都按「账号名 + 关键字 + offset」分桶。
- 账号名取 `author.username`（新增 `PostCandidate.charterUsername`）；`charterUsername` 为空时谱师名不可点（不猜）。
- 占位符改为「搜索标题 / 歌手，或精确账号名」。

## 不做

- 不做昵称索引 / 昵称→账号名映射：平台无端点，本地索引只能覆盖「本次会话见过的帖」，同一查询时灵时不灵，比不做更让人困惑。
- 不做「搜索框输入昵称自动提示账号名」：同上。

## 锁测

- `tests/unit/community/bestdori/posts.test.ts`：账号名探测的触发条件（ASCII / 无空格 / 含字母 / 纯数字不发）；`search` 有结果时丢弃探测结果；`search` 零命中 + 账号命中时回 `authorHit`；`REQUEST_INVALID` 静默。
- `tests/dom/pages/ProjectNewSourceTabs.test.tsx`：输入账号名 → 列表切成该谱师、bar 出芯片、清空芯片回到浏览态；关键字命中时不切；点预览栏谱师名 → 同一筛选。

## Comments

### 2026-11-26 · 落地

- 能力层 `src/community/bestdori/posts.ts`：`isAccountNameQuery`（触发闸）、`probeAuthorAccount`（首页并发探测，任何失败回 null）、`fetchPostSearchPage` 返回 `PostSearchPage.authorHit`；带 `username` 时不再探测、也不再走 id 直查。
- 映射层 `mapping.ts`：`PostCandidate.charterUsername`（`author.username`），展示名仍走 `charter`（nickname 优先）。
- 面板：`charterFilter` 状态 = `{ username, name }`；两个入口（搜索框探测命中、预览栏谱师名）+ bar 上的「谱师：xxx ✕」芯片；关键字与账号名是 AND（`loadFirst/loadMore/refresh/cancelToCache` 都带 `username`，页缓存键按「账号名 + 关键字 + offset」分桶）。
- **探测结果只在关键字零命中时采用**：`roki` / `GUMI` 这类账号名同时是歌名 / 歌手，并进来会把真正的搜索结果挤掉。
- 切换时清空搜索框：留着账号名会变成 `search=<账号名> AND username=<账号名>`，交集为空。探测那一发已把同一页写进会话页缓存，切换后的重载零请求、零白屏。
- 账号不存在（`REQUEST_INVALID`）静默：不弹错、不影响关键字结果（平台事实：不存在的账号也回这个码）。

锁测：`tests/unit/community/bestdori/posts.test.ts`（触发条件 / 零命中才认账号 / 关键字命中丢弃探测 / REQUEST_INVALID 静默 / 带 username 只发一路）；`tests/dom/pages/ProjectNewSourceTabs.test.tsx`（输入账号名切成该谱师 + 芯片可清；预览栏谱师名可点 → 请求带 `username`）。

### 2026-11-26 · 验收回修（文案 + 清芯片后再也搜不回来）

- **根因**：会话页缓存把「零命中」的页也存了。`loadFirst` 先 `peekPostPage(q, 0)`，命中即短路；而账号名探测的结论不在页缓存里 —— 清掉谱师芯片后再搜同一账号名，peek 拿到上次那张空页，探测不再发，直接回「没有匹配的帖子」（瞬时，连 loading 都没有）。
- **回修**：`fetchPostPage` 的零命中页不进会话缓存（账号名那一路有结果，照常缓存，切换仍零请求）；`loadFirst` 的短路因此只对「非空页」生效。补单测（零命中页 `peekPostPage` 为空、账号页仍命中）+ DOM 回归（清芯片 → 再搜 `Envy09` → 芯片重新出现）。
- **文案**：搜索框 placeholder 收敛为「搜索标题、歌手或帖 ID」；「精确账号名」从 placeholder 移到 hover 提示「也可输入谱师的账号名（需完全一致）」；谱师芯片 / 预览的 tooltip 改为「只看 {{name}} 的作品」；筛选态 placeholder 变「在 {{name}} 的作品中搜索」。
- **不做昵称检索的口径不变**：平台 `username` 只认账号名；展示名是昵称（200 条样本里 108 条两者不同）。账号名改为在预览栏的谱师行可见（票 60），不再靠 placeholder 解释。

### 2026-11-27 · 评审回修（双轴 code review）

- **空页闸收到唯一写入点** `commitPostPageCache`：此前只加在 `fetchPostPage` 那一处，`cancelToCache` 回落的磁盘空页仍会进会话缓存，清芯片后再搜同一账号名还是瞬时空 —— 「取消拉取」路径上原 bug 仍可复现。判定同时收紧为「**带 `username` 或账号名形态的关键字都不存空页**」：探测自己那一发（`query='' + username=<账号名>`）也可能是空页，存下来会让下一次探测命中它、永远拿不到 `authorHit`。
- **刷新增 `authorHit` 分支**：首屏与刷新共用组件里的 `adoptAuthorHit`，不再各写一套。此前在空结果态点刷新会把空结果再铺一遍，还报「加载成功」。
- **探测不再透传 `opts`**：只带 `query / offset / signal`。此前 `onRetry` / `force` 一起带进去，探测的网络抖动会点亮面板「重试中」，而它的结果本来就会被丢掉。
- 锁测：单测 +3（空页只放行「与谱师无关」的查询 / `commitPostPageCache` 闸含 `username` / 探测请求不带 `revalidate`）、DOM +1（空态刷新 → 切成该谱师）。
