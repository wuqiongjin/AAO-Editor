# 16 · 导入复用已取素材（封面 / 音频）

Type: grilling
Status: resolved
Blocked by: 14（实现；拍板可同轮）

## 来源

用户 2026-10-10 意见 #3，原话大意：

> 在真正的点击创建时（从官方谱面），为什么还会重新下载封面图、音频资源这些？
> 在预览详情内容的时候，也会加载谱面封面图、音频什么的，这些资源没办法直接用吗？

## 症状

预览已经加载过封面（完整图）与试听音频，点「创建」仍重新下载封面 / 音频。

## 根因（三条叠加，2026-10-10 走查）

1. **预览与导入是两条互不相通的通道**：预览走媒体标签直链（`songs.ts:192-206` 的
   `jacketPreviewUrl` / `audioPreviewUrl`，票 08 Q1 定案），字节只存在于渲染器 / Chromium
   HTTP 缓存里，**应用读不回来**；导入走主进程网关整文件下载（`officialImport.ts:87-99`）。
2. **网关显式不吃 HTTP 缓存**：`cache: 'no-store'`（`electron/communityNet.cjs:233-237`，07 定案，
   为防过期列表）——就算封面在 Chromium 缓存里（站点 `max-age=14400`），导入这条通道也不会命中。
3. **事实校正 —— 音频本来就没下过全量**：预览 `<audio preload="metadata">`
   （`src/ui/CompactAudio.tsx:44-52`）只取元数据 + 播放过的 Range；点创建是**第一次整包下载**
   （约 4MB），不是「重新下载」。真正重复的只有**封面**（预览一张整图 + 导入一张整图）。
   另外 08 已知未做：「暂存导入后不删，靠下次启动清」——同一首歌第二次导入仍会重下。

一句话：不是「缓存了没用上」，而是**从来没有一个「字节落点」能让预览与导入共用**（承接 14）。

## 定案

### 2026-10-10 · 首轮 grill（用户答复）

- **Q1 导入侧 = cache-first**：命中 0 网络；未命中下载并留在缓存（依赖 14 落地）。
- **Q2 预览侧 = 缓存优先**：选中歌曲时封面经网关收进缓存（预览仍即时直链显示）；导入零下载；
  已缓存的歌预览读本地（需自定义协议，音频含 Range）。首次浏览每首歌多约 97KB 缓存下载。
- **Q3（实现口径，待验收）**：07 的 `no-store` 暂不动 —— 复用全走应用级缓存（14），网关仍不吃
  Chromium HTTP 缓存；若实装中发现需要收窄（如仅 JSON 保留 `no-store`），在实现 Comments 里明示，
  不静默改 07 口径。

## 实现落点（候选，拍板后细化）

- `officialImport.ts` 的三个 fetch 前置缓存查询；命中时直接用缓存文件做 `staged` 来源。
- `projectStore.cjs:59-73` 的「暂存目录内」校验随缓存位置调整（或缓存即暂存，见 14 Q3）。
- 预览通道（若 Q2=是）：`jacketPreviewUrl` / `audioPreviewUrl` 换成本地 URL。

## 锁测

（2026-10-10 已落地，见 Comments 落地记录）

- 「命中缓存导入零网络 / 二次导入零网络」：14 的网关锁测已覆盖（binary 长复用），导入编排不感知缓存。
- 协议 raw 支：解析跨进程互锁与越界拒绝；200 全量带元数据；206 三种 Range 形态（`a-b` / `a-` / `-n`，
  终点越界收敛到末尾）；起点越界 416；回退页负缓存不外借（404）；坏缓存 / 越界请求 404 不抛。
- 能力层：`jacketLocalUrl` / `audioLocalUrl` 包住同一条直链（缓存按直链寻址）。
- 预览 DOM：封面「本机 → 直链 → 图标」、试听「本机 → 直链」（缓存缺失时落回直链 = 与现状一致的降级）；
  选中即经网关把封面收进缓存（预览显示本身不产生网关请求）。

### 2026-10-10 · 落地记录（Q2 本轮；无新增拍板）

**协议（`electron/assetProtocol.cjs` + `src/community/assetUrls.ts`）**

- 新 **raw 支**：`aao-asset://raw/?url=<素材原始 URL>`，只读素材缓存里的**原始字节**（kind: binary）；
  与 thumb 支共用一次解析与白名单（thumb / raw 两支按 host 分发）。
- 音频 Range（RFC 7233 单区间）：`bytes=a-b` / `a-` / `-n` → **206 + Content-Range**（终点越界收敛到
  末尾）；起点越界 / `bytes=-0` → **416 + `bytes */total`**；解不开的 Range 当没有 → 200 全量。
  响应带 `content-type`（缓存元数据，缺省 `application/octet-stream`）/ `accept-ranges` /
  `content-length` / `cache-control: no-store`（字节已在本地，别让 Chromium 再存一份）。
- **回退页负缓存不外借**：binary 桶里躺着的那份 `text/html`（平台对不存在素材的 200 回退页，网关
  照存作 1 小时负缓存）raw 一律 404 —— 一张网页递给 `<img>`/`<audio>` 只会换来注定失败的解码，
  直链降级照走。
- 206 按区间用文件句柄读（不整包读 4MB）；文件没了 / 读挂了 → 404，不把异常甩给协议层。

**渲染侧（`songs.ts` / `OfficialSongPanel` / `CompactAudio`）**

- 新 `jacketLocalUrl` / `audioLocalUrl`（= `assetRawUrl(直链)`）；`jacketPreviewUrl` /
  `audioPreviewUrl` 语义不变，注释改为「降级落点 + 缓存寻址 upstream」。
- 预览封面 **本机 → 直链 → 图标**、试听 **本机 → 直链**（与 15 的行内缩略图同一套降级模式：
  协议 404 走 `onError`）；`CompactAudio` 加可选 `onError` 出口。
- 实现加项：`pick()` 补一枪 `ensureOfficialCoverCached`（Q2 原话「选中歌曲时封面经网关收进缓存」）。
  通常行可见时 15/17 已收过（并发去重、命中零网络）；这一枪的实际意义是**之前那次后台取图失败了，
  选中时再试一把**，保「导入零下载」。

**口径重申（全部来自既有定案）**

- 音频不因预览进缓存：Q2 只承诺封面（首次浏览每首歌多约 97KB）；音频进缓存的唯一路径仍是导入。
  「已缓存的歌预览读本地」对音频 = **导入过的歌**。
