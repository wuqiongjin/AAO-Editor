# 22 · 试听播放条：音量可调 + 播放图标居中

Type: feature
Status: resolved 2026-10-12
Blocked by: —

## 来源

用户 2026-10-12 验收反馈（同批 6 条中的 #1 / #2）。

## 症状

1. 试听条右端喇叭图标点击没有任何反应 —— 它根本不是控件；
2. 播放钮里的 Play / Pause 图标都不在圆心（实测偏右 ~1px）。

## 根因

1. `CompactAudio.tsx:85` 的 `<Volume2>` 是纯装饰 svg：无 `onClick`、无音量 state、`aria-hidden`，`<audio>.volume` 恒为默认 1.0。该组件自票 13 #11e 落地起就没实现音量。
2. `.off-compact-audio__play`（`ui.css:791`）有 `display:grid; place-items:center`，但**没清 UA 默认 `padding: 1px 6px`**；全局 `box-sizing: border-box` 下按钮内容盒只剩 12px 宽（图标 13.7px）→ grid 隐式列撑不过 max-content → 图标贴内容盒左缘（距边框 6px、右侧仅 ~4px）。Playwright 实测：dx=+1px、dy=0（纵向因行能 stretch 到 22px 反而居中，故只有横向偏）。

## 定案（用户 2026-10-12）

- 音量形态 = **B · 内嵌小滑条**（用户初选 C，复看原型后改定 B：「选方案B」）：喇叭旁常驻 56px 小滑条，口径同 `PlayBar`（icon + range），音量为 0 时图标切 `VolumeX`；
- 音量存 = **A · 跟随 `settings.audio.volume`**（经 `setAudioVolume`，chart-preview 20 定案的「预览播放器是它的编辑入口」，本面板即预览播放器）；
- 播放钮 = `padding: 0` 拿回正圆与真居中；另 lucide 的 Play 三角在 viewBox 内偏右 1px（6..20，中心 13≠12），追加 -1px 光学校正（Pause 本身居中，不校正）。

## 修法

- `CompactAudio` props 化（照 `PlayBar.tsx:7-9`「数据入口全走 props」惯例）：入 `volume` / `onVolumeChange`；喇叭与滑条组成 `label`（`title`/`aria-label` 走 `play.volume`）；
- **必须同场加 `.off-compact-audio { min-width: 0 }`**：音量组把条的 min-content 从 ~154 抬到 ~218，flex 条默认 `min-width: auto` 会把它撑破栏宽（原型实测 318 > 300，顶出横向滚动条）；seek 本身 `flex:1 + min-width:0`，能吸收剩余空间；
- `OfficialSongPanel` 用 `useConfig()` 取 `settings.audio.volume` 与 `setAudioVolume` 接上（该组件当前不读 config；两处 DOM 测试均经 `ConfigProvider` 渲染页面，无裸渲染风险）；
- `ui.css`：`.off-compact-audio__play { padding: 0 }` + Play 图标 -1px 校正类 + 上述 `min-width: 0`。

## 音频加载/失败态（定案（用户 2026-10-12）：「我认可你这个音频加载的转圈圈效果」）

判断：**需要**。现状两处死角——

- **加载无反馈**：选歌后 `<audio preload="metadata">` 拉元数据（跨境 ~2s+）、点播放后缓冲（`waiting`）期间，按钮还挂着 Play 图标，点了像没反应；
- **失败是静默死角**：本机 404 → 自动落直链（这层已有）；直链也失败 → `onError` 无处理，`play()` 静默 reject，且票 20 的同曲守卫把恢复路径也短路——**没有任何重试途径**（与封面修复前同病）。

形态（条不变形，反馈全在按钮位）：

| 态 | 按钮位 | 条 |
| --- | --- | --- |
| 加载中（元数据未到 / `waiting` 缓冲） | 12px spinner（`off-spin` 复用）+ disabled | seek 维持既有 `duration<=0` disabled |
| 失败（直链也 onError，终态） | `RotateCcw` 重试图标 + title「试听加载失败，点击重试」，点击重挂 `<audio>` 重走「本机 → 直链」 | — |
| 正常 | Play / Pause | — |

红线（沿用票 24）：重试只许在 onError（请求终态）后触发；飞行中重挂 `<audio>` 同样会挂死。i18n 需新增 `projects.official.audioRetry`（「试听加载失败，点击重试」）zh/en。

## 锁测

1. `tests/dom/pages/OfficialPickerPreview.test.tsx`：拖 range → `setAudioVolume` 收到值；拖到 0 → 图标切 `VolumeX`；音频 onError（直链也败）→ 按钮切重试图标；点重试 → `<audio>` 重挂重走加载；
2. 几何居中是 CSS 事实、jsdom 无布局引擎 → **静态源码断言**（照 `OfficialPickerAccordion.test.ts` 惯例）：`.off-compact-audio__play` 含 `padding: 0`；`.off-compact-audio` 含 `min-width: 0`；
3. 原型已量（Playwright + Edge）：修复前 dx=+1px；`padding:0` + 校正后 dx≈0；音频加载窗（路由延迟 4s）按钮呈现 spinner + disabled。落地后同法复量。

### 2026-10-12 · 验收回修（折叠闪出 spinner）

用户验收发现：折叠预览栏时音频条按钮位闪出 loading spinner。根因：票 21 定案「收起掐 src 停声」使 `src → null`，而三态回零 effect 把它当成了新加载（`metaReady` 归零 → `spinning=true`）—— 没有东西在加载却在转圈。

- 修法：`spinning = src != null && !failed && (!metaReady || waiting)` —— 折叠态回落 Play 图标 + disabled；重展开重挂 `<audio>` 重拉元数据仍走 spinner（真实加载，几十 ms，保留）。
- 「重展开也零 spinner」档（记「这首已就绪」状态）评估过：与直链降级链 / 重试 / 换歌纠缠，为几十 ms 加一档状态不划算，真机验收后若仍显眼再升档。
- 锁测：`OfficialPickerPreview.test.tsx` —— 收起后无 `.off-compact-audio__spin`；再展开 spinner 出现。
