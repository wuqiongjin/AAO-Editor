### #1 `songs.ts` / `posts.ts` 三处同形逻辑各两份

- **症状**：`invalidResponse`（`songs.ts:40` / `posts.ts:41`）、`looksLikeMedia`（`songs.ts:180` / `posts.ts:240`）、`coverInflight` 并发去重（`songs.ts:257` / `posts.ts:340`）三对，形状相同。`posts.ts:339` 的注释已自陈「同 songs.ts 的 coverInflight 口径」。
- **根因**：官方（票 08）与社区（票 09）是**两条独立取数路径**，票 07/12 明确要求分开，竖切落地时各写了一份。
- **修法**：`invalidResponse` 与 `coverInflight` 可直接上收到 `src/community/`（两边完全相同、无差异）。**`looksLikeMedia` 不要硬合** —— 两边规则**故意不同**（官方侧 octet-stream 放行 vs 社区侧严判），抽公共会抹掉这个差异；若要抽，须把差异显式化为参数并保留两侧各自取值。
- **Status**: open

### #2 等级窗口归一化 `lo/hi` 近乎逐字重复

- **症状**：`songs.ts:329-336` 与 `posts.ts:379-386` 的 `hasLo/hasHi → lo/hi` 归一化**近乎逐字相同**（含 `?? filter.levelMax as number` 的断言写法），仅后续取 `filter.difficulty` 还是 `filter.diff` 不同。
- **根因**：同上，两条路径各写一份。
- **修法**：**最值得先抽的一条** —— 纯函数、两边零差异、无外部依赖。抽成 `src/community/` 下的 `normalizeLevelWindow(filter)` 返回 `{ lo, hi }`，两处调用。
- **Status**: open

### #3 两个选曲面板近乎同形

- **症状**：`OfficialSongPanel.tsx:265-576` 与 `CommunityPostPanel.tsx:414-644` 的筛选手风琴、`off-cover` 三态 + `retryCover` + `coverImgRef` 竞态护栏、`useSlowLoading`、列表行结构近乎同形；`chipLabel` 两份且**入参类型不一致**（`OfficialSongPanel.tsx:60` 收 `OfficialDifficulty`，`CommunityPostPanel.tsx:75` 收 `number`）。`CommunityPostPanel.tsx` 文件头注释自陈「骨架完全照 OfficialSongPanel」。
- **根因**：票 09 竖切时为赶进度显式复制票 08 的面板骨架，之后两边各自演化（难度类型一个用枚举、一个用数字）。
- **修法**：**风险最高、也最不该现在动的一条**。见「锁测」第 3 条 —— `tests/static/OfficialPickerPreviewBatch.test.ts` 等静态源码断言直接断言 `OfficialSongPanel` 里的字串，抽公共会让一批断言变红。要做就先统一难度类型、再抽面板骨架，并同步改锁测。
- **Status**: open

## 锁测

三条都是**行为等价**重构，锁测按「改了什么就锁什么」给：

1. **#1 / #2**：抽公共后，`tests/unit/community/bestdori/songs.test.ts`（457 行）与 `posts.test.ts`（443 行）**必须原样全绿、一字不改** —— 它们就是现有行为的看守。**若抽公共导致某条断言要改，说明抽错了**（把两边差异抹了）。
2. **#2 补一条**：新增 `tests/unit/community/levelWindow.test.ts`，逐条锁 `levelMin` / `levelMax` 的四种组合（都缺 / 只缺一边 / 都有但反序 / 含 NaN 与非有限值），断言 `lo` / `hi` 与重构前逐值相同。这是当前两份实现**都没有**直接覆盖的边界。
3. **#3 先补锁再动刀**：现状先加 `tests/static/OfficialPickerPreviewBatch.test.ts` 风格的静态断言，锁住两个面板当前的 `retryCover` / `coverImgRef` 竞态护栏与 `useSlowLoading` 延迟 150ms 口径；抽骨架后这批断言须仍全绿。
4. **全量门禁**：`npm test`（基线 2026-10-14：**256 文件 / 3027 用例**）、`npx tsc -b`、`npm run build` 全绿。
