# 28 · 「同步导入谱面」开关状态持久化记忆

Type: feature
Status: resolved (2026-10-12)

## 来源

用户 2026-10-12 反馈 #3：
> 同步导入谱面的 这个开关，不能记住吗？(官方谱面和社区谱面是否可以共用1个开关状态?)

## 症状

1. 每次打开新建工程弹窗（或在 Blank/Copy/Official/Community 间切换），「同步导入谱面」的开关状态都会重置为各自组件内置的硬编码默认值（官方曲默认 `false`，社区谱默认 `true`）。
2. 用户在官方曲面板中勾选了同步导入，下次打开又变回未勾选；反之亦然。无法记住用户的使用习惯。

## 根因

- `OfficialSongPanel.tsx` 与 `CommunityPostPanel.tsx` 各自内部使用本地 `useState`：
  - `OfficialSongPanel`: `const [withChart, setWithChart] = useState(selection?.withChart ?? false);`
  - `CommunityPostPanel`: `const [withChart, setWithChart] = useState(true);`
- 状态生命周期仅绑定在当前面板组件挂载周期内，弹窗关闭后组件卸载，状态丢失。
- 该开关未接入 `settings`（`AppSettings`）或任何本地持久化存储。

## 定案目标与方案建议（2026-10-12 用户拍板：3=OK）

1. **统一开关状态**：
   - 官方谱面导入与社区谱面导入**共用同一开关记忆**：放入 `settings.projects.importWithChart`，在两端面板间无缝同步。
2. **默认值基线**：
   - 首次未设置时的全局默认值统一为 `true`（默认勾选同步导入谱面代码）。
3. **响应式持久化**：
   - 在任一面板中切换该开关，立即更新持久化配置；跨面板、跨弹窗重开均自动继承。

## 实现细节（2026-10-12）

1. **设置模型拓展**：
   - `AppSettings.projects` 扩展 `importWithChart: boolean` 字段（additive，不 bump schemaVersion）；
   - `defaultSettings()` 默认值为 `true`；
   - `mergeSettings()` 归一化布尔类型并向后兼容缺失字段。
2. **Context Provider 接入**：
   - `ConfigProvider` 暴露 `setImportWithChart: (importWithChart: boolean) => void`，基于 `updateSettings` 字段级写回并 `saveSettings` 持久化到 `bangdream.settings.v1`。
3. **面板接入**：
   - `OfficialSongPanel` 和 `CommunityPostPanel` 移除局部 `withChart` 内部 state，直接读取 `settings.projects.importWithChart`；
   - 点击开关触发 `setImportWithChart(!withChart)`。

## 锁测

- 单测：`tests/unit/chart/config/ProjectSortSettings.test.ts` 覆盖默认值、additive 合并、字段覆盖与 save/load 往返测试。
- DOM 锁测：
  - `tests/dom/pages/ProjectNewSourceTabs.test.tsx` 新增「票 28 · 同步导入谱面开关状态官方与社区共用且持久保持」用例，全流程验证官方切关 -> 社区反映关 -> 社区切开 -> 官方反映开及 localStorage 落盘；
  - 修正历史测试关于官方导入默认开关状态的断言（对齐出厂默认 `true`）。
