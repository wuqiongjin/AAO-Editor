## 现状与根因

**ID 已经存在，不是"没有"，而是"不展示、不持久化、搜不到"**：

- 唯一 ID = Bestdori 帖子数字 id（`PostCandidate.postId`，`src/community/bestdori/mapping.ts:205-220`），列表接口原生携带，票 27 已修过详情缺 id 的坑。
- **展示**：列表行只显示 标题/谱师/难度/日期（`CommunityPostPanel.tsx`），预览栏不显示 postId。
- **持久化**：custom 帖导入后 `source = { type: 'custom' }`（`communityImport.ts:152`），**postId 不落进工程**；bandori 帖记的是官方 songId。全仓唯一 postId 落点是 `ProjectChart.upload.postId`（"我上传的帖"语义，且尚未接线，票 11）。
- **搜索**：服务端 `search` 关键字，实测匹配**标题与歌手**、不匹配谱师账号（票 09 第二轮反馈 #1）；**纯数字 postId 是否被服务端匹配未实测**。
- **"歌曲详情页"不存在**：没有独立详情页概念，只有新建弹窗里的内联预览栏（复用官方面板骨架）；`ChartInfoDialog` 是工程内谱面信息编辑，与此无关。

## 待拍板

1. **ID 搜索路径**：靠服务端 `search` 传数字（先实测是否命中，不可靠）vs 输入纯数字时改走 `GET /post/details?id=` 直查（可靠、一跳直达，但语义是"跳转"不是"搜索"）。倾向后者。
2. **ID 展示位置**：列表行 / 预览栏 / 两处都放。
3. **是否持久化到工程**：给 `SongSource.custom` 加 id（`{ type: 'custom'; postId: number }`）或新增工程字段；这会动 `SongSource` 形状（`ChartProject.ts:24-27`），需连带查 `projectAudio.ts` 换音频置 custom 的路径与旧数据兼容。
4. **"歌曲详情页"指什么**：在预览栏加 ID 即可，还是要新增独立详情视图？

## 定案（用户 2026-10-13）：ID 搜索路径

用户口径：输入纯数字时**并发两个请求**，id=xxx 匹配的那条优先展示，两路结果都展示。

- 路径 = 双请求：①服务端 `search=<数字>`（既有路径）；②`GET /post/details?id=<数字>` 直查。
- 合并规则：直查命中**置顶优先**；两路结果按 postId 去重；直查 404/不存在**静默忽略**、只留 search 结果，不报错。
- 直查命中那条并进面板会话缓存（key 含查询词），避免翻页/重开重发。
- AI 评估（已告知用户，无异议）：方案可行，details 单请求成本低。

## 落地（2026-10-13）

- `posts.ts` 新增一段「id 搜索」：
  - `numericPostIdQuery(query)`：trim 后全数字且是安全正整数才算一次 id 查询（`0` / 超安全整数 / 带别的字符都回 null）；
  - `fetchPostIdLookup(transport, query)`：走 `fetchPostDetail`（即 `post/details?id=`），
    **任何失败一律回 null**（不存在 / 形态不对 / 网络 / 超时都吞掉 —— 这条是加分项，它抖一下不该把搜索结果打翻）；
    命中结果进**会话内 id 缓存**（key = 查询词原文），并发去重；
  - `mergeIdLookupHit(hit, page)`：命中那条置顶、按 postId 去重；`total` / `rawCount` 仍取搜索那一路
    （直查命中不在服务端序列里，翻页游标不该被它带偏）；
  - `fetchPostSearchPage(transport, opts)`：**首页（offset === 0）**且纯数字时
    `Promise.all([直查, fetchPostPage])` 合并，其余情况 = 原样 `fetchPostPage`（直查那一路零请求）。
    直查**只挂首页**写在函数自己身上（不是靠调用方自觉）——深页是同一段搜索的翻页，
    每翻一页重问一次 id 是白发的请求。
- `clearPostPageCache()` 连 id 缓存一起清（测试与「刷新」都靠它）——所以点刷新会重问一次那个数字。
- `CommunityPostPanel.tsx`：首屏与「刷新」改用 `fetchPostSearchPage`；深页（上拉加载）仍走 `fetchPostPage`
  ——直查只挂在首页那个入口上。列表行常驻 `#postId`（右列小字 + `title` 提示，不进 `.off-row__levels` / 不落盘）。
  （预览栏那行 ID 已按下面的验收回修撤掉。）
- i18n：`projects.community.idLabel`（帖 ID / Post ID）+ `projects.community.searchPlaceholder`
  改为「搜索歌曲标题或帖 ID」（能力变了，placeholder 同步说清）。
- 持久化：**不动**（三轮定案：不落盘），`SongSource` 零改动。
