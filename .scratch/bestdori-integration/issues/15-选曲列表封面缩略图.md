# 15 · 选曲列表封面缩略图

Type: grilling
Status: resolved
Blocked by: 14（实现；拍板可同轮）

## 来源

用户 2026-10-10 意见 #2，原话大意：

> 关于歌曲的封面图，有办法让封面图直接显示到每个条目中吗？（光凭歌曲名字，可能无法完全辨识这首歌曲）
> 这样的话，就得考虑加载速度了吧？（这个封面图大小肯定得更小，得是那种缩略图的形式吧？）

## 症状

「从官方谱面导入」右列目录（`OfficialSongPanel.tsx:306-330` 的 `.off-row`）只有曲名 + 乐队 + 难度芯片，
没有封面；同名 / 记不清的曲子只能靠文字辨认。

## 根因

1. **界面从来没做**：13 #8 定案的行结构就是「曲名 + 完整乐队在左、难度芯片在右」，没提封面。
2. **站点没有缩略图端点**：13 #10 实测 —— jacket 是 400×400 PNG、39–98KB（song 1 = 97764 字节），
   非交错，跨境冷取实测 7.7s（CF 落 LAX），浏览器逐行扫刷。直接给目录每行挂 `<img src=原图>`
   = 滚动即跨境拉原图、浪费流量、可能撞站点限流。**「更小的图」没法从平台上要，只能本地生成。**
3. **本地缩略图没有落点**：没有缓存层（见 14），缩略图生成完也没处存、没法跨会话复用。
   → 本票实现依赖 14 的缓存层（缩略图与清除策略同属 14 Q1/Q2）。

## 定案 / 进行中

### 2026-10-10 · 首轮 grill（用户答复）

- **Q1 形态 = 先出原型对照**：`?prototype=official-picker-thumbs&variant=A|B|C`（40px 方块 / 48px 圆角 /
  56px 圆角），看完再拍；对照里同时展示未加载占位与无素材（合作曲）降级。
- **Q2 加载策略（拟口径，随对照确认）**：懒加载（滚到可见才取）→ 占位 → `load` 淡入 → 失败降级图标；
  本票只做行内缩略图，不动预览区大图。

### 2026-10-10 · 对照结果（用户拍板）

- **形态 = B（48px 圆角）**：方形缩略图 48×48、圆角 8px、行高略增（原型实测 ≈ 64px，无缩略图基线 ≈ 53px）。
- 缩略图生成规格（拟口径，随实装确认）：**96×96**（48 CSS px @2x，避免高分屏模糊），进缓存时由主进程顺手产出；
  缓存里同时保留原图（400×400）供预览区大图用。

### 锁测（方向）

- DOM：行内出现缩略图节点；`.off-row` 布局不破（标题 / 乐队 / 芯片仍在位）。
- 懒加载：jsdom 无 IntersectionObserver（实现时在测试里 stub）——锁「未入视口的行不发起图片请求」；
  替代验证：Playwright 像素实测（真实滚动，只有首屏行出图）。
- 降级：`jacketImage === ''` 的行不请求网络、渲染图标占位。

## 实现落点（候选，拍板后细化）

- 缩略图生成：封面进缓存时顺手产出（规格待定，如 64×64 PNG/WebP）；
  生成位置可选主进程 `nativeImage.resize` 或渲染侧 canvas（实现细节，票内定）。
- 行结构：`.off-row` 增缩略图位 + 占位块；懒加载走 IntersectionObserver。
- 媒体标签读缓存需要本地 URL 形态（自定义协议）——与 16 同一条通道。

## 锁测

（2026-10-10 已落地，见 Comments 落地记录）

- DOM（jsdom + IntersectionObserver 替身）：没滚到的行**一条封面请求都不发**；滚到才逐首收进缓存；
  `jacketImage === ''` 的曲子不请求网络、画图标降级；取数失败降级图标且只打一枪；无观察器环境直出。
- 行内节点：`<img src="tsugu-asset://thumb/?url=<原图地址>">`，`load` 才加淡入类；行结构（曲名 / 乐队 / 芯片）不破。
- 主进程：图片进缓存顺手产 96×96 方形 PNG；`ensureThumb` 给「本功能之前进的缓存」自愈；
  占用 / 回收 / 摘除都把缩略图算上；协议只认白名单主机、**只读**缓存、缺图回 404；
  scheme 特权在 app ready **之前**登记。
- 规格互锁：主进程 `THUMB_SIZE`(96) = CSS `--off-thumb-size`(48) × 2。
- **替代验证（本节原写的「Playwright 像素实测」按落地改为手工验收清单）**：「真实滚动到头、只有首屏附近
  的行出图」这条要**真实滚动 + 真实跨境网络 + Electron 桥**（浏览器静态演示版根本没有官方导入入口），
  单测的观察器是替身、jsdom 也没有布局，够不着 → 走真机待验 1 / 6（清单在 Comments 落地记录里）。
  要把它变成像素断言，得先给 Electron 侧开 e2e 基建（本票不开）。

### 2026-10-10 · 落地记录（本轮）

**主进程**

- 新 `electron/assetThumbnails.cjs`：`createThumbMaker`（**nativeImage 由装配处注入**，模块本身可在 node 下单测）——
  先居中裁方再 `resize({ 96, 96 })`，产 PNG；不是图片 / 解不开 / 空图一律回 null（失败只是「没有缩略图」，不报错）。
  选主进程 `nativeImage` 而不是渲染侧 canvas（票内定）：字节本来就落在主进程，不该为一张缩略图把图搬过 IPC。
- `electron/assetCache.cjs`：`store()` 顺手产缩略图（`<条目文件>.thumb.png`，挂在条目的 `thumb` 上，写失败只丢缩略图；
  重存同一条目而这次产不出缩略图时，旧的缩略图文件顺手删掉 —— 不留索引里没有的孤儿）；
  新增 `ensureThumb()` —— 条目在、缩略图不在（本功能之前进的缓存 / 上次产出失败）就现产一份写回索引，**老缓存自愈**；
  占用（`stats`）/ 回收（30 天、1GB LRU）/ `drop()` 都把缩略图算进它所属条目（缩略图不单列桶）。
  索引里缩略图记录的 `file` 同样只准是文件名（越界整条不认）。
- 新 `electron/assetProtocol.cjs`：`tsugu-asset://thumb/?url=<原图地址>` **只读协议** —— 只认白名单主机（与网关同口径）、
  只读缓存**不联网**（「什么该进缓存」仍归渲染侧经网关决定），命中即回字节；缺条目 / 产不出回 404，不抛。
  16 的预览大图 / 音频走同一条通道（再加 host 即可）。
- `electron/main.cjs`：`registerAssetSchemePrivileges(protocol)`（standard + secure，**ready 之前**）+
  `registerAssetProtocol(protocol, assetCache)`（ready 之后）+ `makeThumb: createThumbMaker(nativeImage)` 注入。
