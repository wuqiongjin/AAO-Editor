# 57 · 首次打开官方/社区导入面板有缓存时允许取消主动拉取

Type: grilling
Status: resolved
Blocked by: —

## 来源与诉求

用户 2026-11-14：

> 2. 首次打开软件时，从官方谱面导入、从社区谱面导入 是否允许取消主动拉取的操作？(因为经常会遇到网络不好+本来也不是想获取最新的，想用之前的缓存。注意，必须要有之前的缓存，没缓存禁止主动取消拉取吧)

## 现状

1. **首屏强制网络先行**：依据票 29 与票 44 定案，每次启动软件后首次打开「从官方谱面导入」（`OfficialSongPanel.tsx`）或「从社区谱面导入」（`CommunityPostPanel.tsx`）时，内存缓存为空，渲染层调用 `fetchSongCatalog` / `fetchPostPage`（`offset === 0`）均携带 `freshFirst: true`。
2. **弱网长时卡死**：主进程网关（`electron/community/communityNet.cjs`）遇到 `freshFirst: true` 时强制先发网络，必须等网络彻底失败后才回退读取磁盘缓存；叠加渲染层 `withRetry`（最多 3 次 × 单次 30s 超时 + 指数退避 + API 档 1 并发串行排队），弱网/挂起时用户会被卡在居中加载屏（`"正在拉取官方曲库"` / `"网络较慢，努力拉取中…"`）30 秒至数分钟。
3. **无取消切缓存机制**：
   - 加载态 `.off-blank` 中只有旋转指示器和文案，没有任何取消并切到上次结果的入口，且刷新按钮在拉取期间 `disabled`；
   - 弹窗「取消」/关窗只关闭整颗弹窗，既不能留在列表浏览旧结果，也无法中断在飞的请求与重试循环（`fetchSongCatalog` / `fetchPostPage` 无 `AbortSignal`，主进程也没有取消通道）；
   - 渲染层与能力层无法感知本地磁盘是否已有缓存（`readCache` 完全私有于 `communityNet.cjs`），无法判断「有缓存才允许取消，无缓存禁止取消」。

## 根因

1. **策略层只支持「网络失败自动回退」而不支持「用户主动中断并回退」**：票 44 为了避免「缓存先出 + 后台偷换列表打断浏览」而保留了首屏等网络，但未给有缓存的用户留出弱网逃生通道。
2. **缓存可见性与请求取消链路缺失**：跨进程契约（`src/community/transport.ts`、`electron/community/communityNet.cjs`）没有暴露「仅读缓存 / 查询是否有磁盘缓存」与「中止本次列表拉取」的能力。

## 定案（用户 2026-11-14 · grill 第 1–3 轮）

1. **Q5 + Q7 按钮设计、位置与无缓存限制**：
   - **位置**：居中加载区 `.off-blank` 内，紧贴在旋转圈与拉取文案正下方。
   - **出现条件与时机**：进加载态时检测本地磁盘是否已有上次拉取结果：
     - **有本地缓存**：进入加载态 **2 秒后** 显现按钮（正常网络 1 秒内出列表时不闪烁）；
     - **无本地缓存**：**不显示**该按钮（禁止主动取消拉取）。
   - **文案与反馈**：按钮文字只显示 **`取消`**（不把「缓存」等内部术语暴露给用户）；点击后立即切到上次结果列表，并弹出 `warn` Toast：**`已取消拉取，使用上次拉取结果`**。
2. **Q6 取消后的请求与会话行为**：
   - **真中止在飞请求**：渲染层通过 `AbortController` 立即停掉 `withRetry` 退避与当前拉取（并清理 `catalogInflight` / `pageInflight`，主进程如有进行中的请求也尽量 abort 或忽略其回包），绝不在后台偷换列表或延迟弹出 Toast；后续需要最新数据由用户主动点右上角「刷新」。
   - **同会话内复用**：点击 `取消` 加载出的上次结果写入会话内存缓存（`catalogCache` / `pageCache`），同一会话内关窗再重开弹窗秒开该列表，不再重新卡住（点右上角「刷新」再打网络）。
   - **缓存完整性与有效期**：
     - 官方导入：`songs/all.5.json` 与 `bands/all.1.json` 两份都有磁盘缓存才允许取消；
     - 社区导入：只要 `post/list` 第 1 页（`offset === 0`）有磁盘缓存就允许取消（关联官方曲库同步优先读缓存、有就用，不因曲库卡住社区面板）；
     - 只要磁盘缓存未被 30 天闲置 / 1GB 容量清理（仍存在于 `assetCache`）即算「有之前的缓存」。

## 实现落点（待实现）

- `electron/community/communityNet.cjs` & `src/community/transport.ts` / `electronTransport.ts`：
  - 支持只读缓存 / 探测缓存（如 `cacheOnly` 请求模式，或在 `CommunityRequest` 增加 `cacheOnly?: boolean` / 专用探测方式，注意同步维护 `preload.js` 与 `electronBridge.ts` 锁测）；
  - 支持主进程请求按 `requestId` 取消或渲染层 `AbortSignal` 立即截断等待并退出 `withRetry`。
- `src/community/bestdori/songs.ts` / `posts.ts`：
  - `fetchSongCatalog` / `fetchPostPage` 支持 `signal?: AbortSignal`；提供本地缓存可用性检查与 `cacheOnly` 回退加载原语；取消时正确清理 `catalogInflight` / `pageInflight`。
- `src/pages/projects/components/OfficialSongPanel.tsx` / `CommunityPostPanel.tsx` & `src/i18n/`：
  - 加载态探测是否有磁盘缓存；有缓存且等待满 2 秒显示 `取消` 按钮；点击触发 abort + 读本地缓存上屏 + `showToast(t(...), 'warn')`。
