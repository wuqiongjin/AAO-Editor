# 36 · bandori 帖工程名改帖标题（修订票 34 定案第 1 条）

Type: grilling
Status: resolved (2026-10-13)

## 来源

用户 2026-10-13 验收追问（承接票 34 的预填口径）：

> 社区谱面，如果是官方的曲子。此时导入后，工程名字为什么是官方曲子名字而不是 社区帖子的名字？
> （社区的曲子，一般都会自己起个别的名字，哪怕是官方的曲子。比如 [官方歌曲名称]-加强版 之类的。）

## 症状 / 根因

票 34 定案第 1 条把 bandori 帖的工程名定成「官方曲名（与官方导入同口径）」。真机上两个代价：

- **帖标题里的变体信息被抹掉**：官方曲的社区谱一般由谱师自己命名（fixture 里就是「BLACK SHOUT 谱师版」），那才是这只谱的名字；顶官方曲名等于**用歌名覆盖谱名**。
- **同一首歌的多篇社区谱撞名**：导两篇不同谱师的同一官方曲 → 列表里得到两个名字、歌手、曲目来源全一样的工程，只能靠难度分。

对照 CONTEXT：工程名是「**谱面工程**自己的名字」，且「没有独立的『歌名』字段——作的是谱面不是歌」。歌的身份并没丢——它在**歌手** + **曲目来源** + **音频名**（`official-804-…`）三处都记着。

## 定案（用户 2026-10-13，**修订票 34 定案第 1 条**）

1. **社区导入工程名一律取原帖标题**（bandori 与 custom 两支同一口径）：
   `post.title.trim() !== '' ? post.title : (song?.title ?? '')`。
2. **bandori 帖标题缺省时退回官方曲名**（空名不如歌名有用）；custom 帖缺省仍为「未命名工程」（`name: null`）。
3. 歌手口径不变（票 34）：bandori 帖 = 官方乐队名（乐队索引查不到则空）；custom 帖 = 帖子自报歌手。
4. 音频 / 封面落名不变（票 35）：bandori 帖的音频**就是**官方音频，`official-<songId>-<曲名>` 仍事实正确——本票只动工程名。
5. 票 34 的其余结论（预填取代「全留空」、谱师不落盘、`ProjectChart.title` 跟随工程名）全部继续有效。

## 与官方导入的分歧（刻意）

同一首歌的官方导入与社区导入会顶不同的名：前者是游戏自带的谱（工程名 = 官方曲名），后者是**某人的谱**（工程名 = 帖标题）。两者本来不是同一个东西，不同名才对。
