# ADR-0014：宽松谱面代码源数据与画布投影

- **状态**：Accepted
- **日期**：2026-09-23
- **范围**：谱面代码解析、工程保存、代码导出、画布渲染与画布编辑

## 背景

Bestdori 风格谱面代码的目标是最大兼容，而不是只接受编辑器内部能够严格建模的规范数据。未知字段、未知 `type`、已知字段的有限非法值和轨道外 lane 都可能出现在真实谱面中。若先把代码强制转换成严格的 `ChartNote[]`，再从内部模型重新生成代码，就会在解析、工程重载或导出时丢失用户数据。

同时，编辑器仍需要一个可操作的画布投影：无法理解的对象不能被伪造渲染或参与判定；可以安全计算的越界值则应尽量显示，编辑时再遵守编辑器自身的合法落点规则。

## 决策

### 1. 两层模型

谱面代码采用两层模型：

1. **源数据层**：保留合法 JSON 数组中的原始对象、字段和值。未知字段、未知 `type`、以及符合既有放行边界的有限非法值均不得因解析或序列化自动丢失。
2. **画布投影层**：把源数据中编辑器能够理解的部分投影成可渲染、可命中、可编辑的内部对象。投影失败不删除源数据。

JSON 语法错误仍拒绝应用。`type` 未知的对象作为 opaque 条目保留，但不渲染、不计数、不播放、不进入画布选区，只能通过谱面代码编辑器修改或删除。

现有 BPM 规则是独立硬边界：`bpm = 0` 仍拒绝，负数 BPM 继续放行；本 ADR 不把 `bpm = 0` 纳入宽松保留。

### 2. 坐标投影

- `beat < 0` 的音符和 Slide connection 在画布上统一显示于 `beat 0`；源数据仍保留原始 beat。
- `beat` 超过谱面工程的结束位置时，仍按真实 beat 渲染到 END 线之后；END 线的位置仍由谱面工程时长决定，END 不是渲染裁剪线。
- 有限越界 `lane` 按原值投影，因此音符和 Slide connection 都可以显示在轨道外。
- 修改 Slide connection 的 beat 导致点序变化时，沿用现有显示投影的稳定重排规则。

### 3. Directional 投影

- 渲染只把 `direction: "Left"` 解释为 Left，其它可序列化方向值（包括 `"Other"`）回落为 Right；源值保留。
- `width > 0` 时方向键本体数量为 `ceil(width)`，装饰位置使用原始 width 的小数位置。
- `width <= 0` 时不绘制本体，装饰仍按原始有符号 width 定位；负值使装饰向反方向移动。
- 例如 `width = 4.25` 渲染 5 个本体且装饰位于 4.25；`width = 0.25` 渲染 1 个本体且装饰位于 0.25。

### 4. 画布编辑与字段生命周期

- 拖拽、复制、剪切、镜像、粘贴等一对一操作保留未被直接编辑的源字段。
- 拖拽会把新的 lane 落点归入 `0..6`；新放置和粘贴也只能落入合法 lane。镜像不强制把结果 lane 归一化。
- 覆盖会删除旧对象及其字段，新对象只携带自己的字段。
- 拆条、增加 Slide connection、合并 Slide、增加 Directional 宽度等改变音符形态的操作对齐 Bestdori：重新生成标准对象，并丢弃编辑器不理解的未知字段和非法字段；可以明确映射的标准字段按既有编辑规则保留。
- **`Long` 身份（issue 154 grill）**：画布按 Slide 投影；本编辑器不放置 Long。无形态变化的往返必须保留 `"Long"`，不得改写成 `"Slide"`。一对一操作后若仍是两点且 beat 有序，即使换了 lane 仍为 Long。加结点、拆条、合并、弯/SP、变成单键则重建为 Slide。不得把几何像直 hold 的 Slide 自动改成 Long。
- **`System`**：Bestdori 一等类型，在本编辑器是 opaque 条目（§1），不是 BPM。官方 `data` 为 BGM 文件名或 `cmd_fever_*`；Fever 机制本编辑器不实现。
- **`charge`**：未知源字段（音符或 connection 上的 `true`），一对一操作保留，形态变化可丢；画布无 UI。不是独立音符类型。
- **Bestdori 社区上传清洗**不是 Apply / 工程保存 / 另存为的一部分。上传层（未来票）才按官网 `sanitizeAll` 丢掉 `System` 对象并剥掉 `charge` 键；`Long` 上传时保留。

### 5. 源文本与导出

- 应用后的代码文本是当前源文本，工程保存、重载和对外导出均以它为基础。
- 另存为不包含代码框中的未应用草稿。
- 没有画布编辑时，另存为尽量保存应用代码框的原始文本；画布编辑后允许必要的 JSON 重排，但遵守本 ADR 的字段生命周期规则。
- 编辑器内部字段（例如 `spanParams`）仍不属于用户谱面代码源数据，不直接导出。

## 后果

- 解析器和工程持久化不能再以严格 `ChartNote[]` 作为唯一真相源。
- 渲染、命中、选区、拖拽和导出必须明确区分“源值”和“投影值”。
- 用户可以打开、查看并导出编辑器不完全理解的谱面；代价是形态变化操作可能按 Bestdori 口径丢弃无法映射的字段。
- Auto Play 中 `beat < 0` 音符计入已完成 combo 的行为属于未来“谱面预览视频”能力，不由本 ADR 实现。
- Fever / `cmd_fever_*` / `charge` 累积进度不在本编辑器实现；源数据仍保真。
- 社区上传不可把官方谱原样 POST（见 `docs/research/bestdori-community-upload.md`）；清洗层独立于本 ADR 的源数据保真。
