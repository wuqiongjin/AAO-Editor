# ADR-0023: 片段收藏的载荷与存储边界

- **状态**：Accepted（basic-editor 164 的 grill，2026-10-30；用户逐问拍板 19 问，Q1 / Q9 两处由用户改写）
- **背景**：用户要"把喜欢的配置收藏起来，在任何可编辑的谱面画布粘贴"。剪贴板已经能搬一段音符，但它是一次性内存态；片段库要长期、跨工程、可分享。核心用例由用户点明：**复杂滑条，尤其是倒流区与特殊 BPM 段的**。这决定了片段不能只是"一组音符"。
- **结论**：片段 = **音符 + 速度语境**的快照；**收藏一律存速度语境，粘不粘在粘贴时决定**；片段库**独立存储、独立分享**，不进设置对象。
- **变更触发**：改载荷字段、改"含 BPM"的判定与行为、改片段库存储位置或分享格式，都要先改本文件并经用户确认。

---

## 1. 载荷：一律带速度语境

片段存 `{ id, name, createdAt, notes, bpmContext }`：

| 字段 | 口径 |
| --- | --- |
| `notes` | 收藏时选区的 `copySelection` 产物（与剪贴板同一套形态归一），**剥掉 `source`** |
| `bpmContext.startBpm` | 源谱面在 `minBeat` 处的**生效 BPM**：按 beat 稳定排序后最后一条 `beat ≤ minBeat` 的 BPM 值。谱面必有 beat 0 的 BPM，故恒有值 |
| `bpmContext.events` | 跨度内 `(minBeat, maxBeat]` 的 BPM 事件，相对 `minBeat` 记 `deltaBeat`（起拍那条即 `startBpm`，不重复） |

**为什么一律存**：只有存了，粘贴时才有得选。收藏是低频、可重做；粘贴是高频、当场有反馈——把"带不带"放在收藏侧等于要求用户为"以后也许想不带 BPM 粘"预先存两条，而选"不带"是不可逆的信息丢弃。此外缩略图对倒流区片段必须靠片段自身 BPM 才能按布局轴画对。

**为什么剥 `source`**：`source` 是 ADR-0014 的**原谱 overlay**（未知字段保真），它的语境是"这一份谱面代码"；片段是跨工程长期存活的纯音符，把别处的 overlay 带进新谱会变成幽灵字段。剪贴板是短途搬运，维持现状不动。

## 2. 粘贴：两个模式，数值绝对值

| 模式 | 行为 |
| --- | --- |
| **含 BPM（默认）** | 落点写 `startBpm`——**与目标该处生效 BPM 相同时不写**（同速粘贴不长出多余 BPM 横线）；`events` 按同一 `deltaBeat` 平移写入，同拍已有 BPM 按既有粘贴规则原位替换 |
| **不含 BPM** | 只按 beat 平移音符，速度完全跟目标谱面 |

落点语义与剪贴板 100% 同口径（ADR-0008 §2.1：beat 轴、包围盒左上角对齐、lane 夹取、越过谱面末端整组拒绝、覆盖按 ADR-0001）。

**显示口径**（2026-10-31 用户定案）：卡片徽标与胶囊都直接标**速度跨度** `120 → 180`（取与起点差值最大的那条事件作右值，`120 → 180 → 120` 也不会读成"没变化"）；负值只给那个数字上危险色，不再单设「倒流」徽标。胶囊两档措辞为 `含 BPM (120 → 180)` / `不含 BPM`。

**BPM 数值不按目标速度缩放**：源 200 BPM 的 `-120` 折返贴进 100 BPM 的谱面仍是 `-120`。理由是花活的形状由绝对数值决定，且比例缩放会产出 `-37.5` 这类非整数 BPM、让用户没法再手改对齐。

**不自动补"恢复 BPM"**：片段尾部若留下负值、而目标谱面其后没有 BPM 事件，整段后续都会进倒流区。但这正是 issue 142 已经定义过的错误态——**末条 BPM 为负**会被画成危险红 + `!`（导出后 Bestdori 打不开）。既有通道已经能把后果当场暴露，编辑器一贯**不拦**倒流（ADR-0010），自动塞一条用户没画的线反而违背该立场；而目标后文本来就有 BPM 事件时，负值天然被它收住，也不需要补。

## 3. 存储：独立，不进设置对象

| 项 | 口径 |
| --- | --- |
| 归属 | **应用级用户素材**，与谱面工程同级，不是"设置" |
| 位置 | Electron：数据根下独立文件（需新增数据根桥，现有只有 `projectStore` / `backgroundSkin`）；浏览器：IndexedDB 独立库 |
| 与设置的关系 | **不进 `settings`、不随设置 JSON 导入导出**。设置是"我的习惯"，片段是"我的素材"；混进去会让"导入别人的设置"顺手覆盖片段库，也会把上千音符塞进 localStorage 单键 |
| 容量 | 不设硬上限；v1 单文件全量载入，体量超阈值提示导出备份 |
| 分享 | 统一信封 `{ schemaVersion, exportedAt, patterns: [...] }`，单条也用同一信封；**合并导入、不做整库替换**；导入生成新 id；**允许重名**（名字是标签，不改写别人的命名——与「副本命名」那条**对象复制**规则区分）；坏条目跳过并报数。**(2026-10-31 补 189)** 导入按内容指纹（`notes + bpmContext` 的规范化 JSON，不含 id / name / createdAt / 本地视图偏好）判重，**只与本地片段库比对**：内容相同默认**跳过**；可选**覆盖**（保留本地 id / createdAt 等身份与收藏时间，只把名字换成导入名）或**保留两者**（各自新 id）。判重不按名字；同名不同内容照常两条都保留。**文件内部的同内容条目不做去重**——空库导入一份含多条同内容片段的文件时全部进来；冲突仅指「导入条目 ↔ 本地已有片段」。 |

## 4. 与既有模型的关系

- **剪贴板与片段并存**：点卡片不写剪贴板——片段粘贴态的负载来源是这个片段，退出后剪贴板仍是原来那份。
- **ADR-0008**：复用同一个粘贴持工具态（驻留 / 幽灵预览 / 单击即贴 / Esc 退出），只是负载来源多一个；此态下再点工具轨「粘贴」= 切回剪贴板来源。
- **ADR-0010**：倒流区片段照常允许，不拦、不补线。
- **ADR-0002**：收藏是新的 `FunctionId`（`execSavePattern`），进快捷键页、冲突拒绝。

## Considered Options

- **收藏时选含不含 BPM**：被否决 —— 选择发生在错误的时刻，且"不带"是不可逆的信息丢弃。
- **只对"特殊片段"含 BPM**（跨度内有 BPM 事件、或起点在倒流区）：看起来能避免"普通片段粘进异速谱面顺手改速度"，但判据不完整——整段落在正 BPM 特殊段内、区间无事件的片段会被判成普通片段而丢掉速度；而判据对用户不可见。改为"一律存 + 粘贴时选"后，规则可以一句话讲清：**含 = 按源速度还源，不含 = 按目标速度重排**。
- **按目标速度比例缩放 BPM**：被否决 —— 产出非整数 BPM，折返深度随目标曲速漂移，与"收藏这个形状"的意图相反。
- **自动在片段末端补恢复 BPM**：被否决 —— 粘贴会写入用户没画过的线；而未补的后果已有既有警示通道（issue 142）。
- **塞进 `settings.patterns`**：被否决 —— 见 §3。
- **整库替换式导入**：被否决 —— 危险键，误操作代价是毁掉别人积累的库。

## Consequences

- Electron 要新增一条数据根桥（当前只有工程与背景皮肤两条），并改动 `electron/dataRoot.cjs` / `preload.js`；浏览器要新增一个 IndexedDB 库。**两条路都要做**（在线版与桌面版同功能）。
- 收藏路径要能读到"源谱面在 minBeat 处的生效 BPM"，即需要按 beat 稳定排序取前驱事件——与导出排序同口径（`BpmTail.ts` 已有"末条"的先例）。
- 片段粘贴的执行路径必须与剪贴板共用 `pasteChartNotes` 的锚点 / 夹取 / 越界规则，否则"复制粘"与"收藏粘"会漂移成两套体感。
- 缩略图渲染要按**布局轴**取景（倒流折返），不能按 beat 跨度归一化——后者会把折返压平。
