# ADR-0019: 本地日志与诊断包

- **状态**：Accepted（2026-10-13 与用户拍板）
- **背景**：产品为本地 Electron 客户端、无服务器（ADR-0011 §1）。当前可观测性仅剩散装 `console.*`（`src/` 18 处，均带模块前缀）与约 30 处 try/catch 降级：打包态下这些输出普通用户不可见，且无 ErrorBoundary、无 `window.onerror` / `unhandledrejection` 兜底、无任何日志落盘。一旦发布，用户遇到白屏、导出失败、工程损坏、难复现的渲染/性能异常时，我们拿不到任何现场，只能听描述。需定案可观测性形态与信息通道。
- **结论**：见本文件全文。
- **变更触发**：任何远程遥测 / 错误自动上报 / 日志出境的提议与本文件冲突时，须先更新本文件并经用户确认。
- **关联**：[ADR-0011](./0011-Bestdori集成与本地客户端网络素材边界.md) §1（本地客户端唯一形态、无服务器）与 §3（凭据红线）；`.scratch/release-pipeline/`（发布渠道 = GitHub Releases，Issue 为用户反馈入口）；`.scratch/docs-site/`（「排障」章节指导用户导出诊断包附 Issue）。

---

## 1. 信息通道（定案：纯本地）

- **形态**：本地日志文件 + 应用内「导出诊断包」，用户附到 GitHub Issue。**不做远程遥测 / 自动错误上报**（Sentry 类）。
- 理由：① 桌面客户端 + GitHub Releases 分发，Issue 模板 + 诊断包可覆盖绝大多数场景；② 数据出境的隐私成本与「本地客户端」定位不成比例，与 ADR-0011 §3 凭据红线同源——用户数据不出本机；③ 引入第三方 SDK 会把网络面、隐私政策、数据共享全部拖进来。
- `feature/bestdori-integration` 合并后主进程将获得受控网络能力（ADR-0011 §2）——**不因此重开遥测议题**：该网络面是 Bestdori 数据通道，不是遥测通道。若将来自诊断包实践中出现大量不可复现 case、证明远程上报确有必要，须单开 ADR 并经用户确认。

## 2. 覆盖范围（定案：分阶段）

- 第一阶段：**静默故障 + 数据损坏**——白屏 / 渲染崩溃、导出（PNG/MP4/WebM）失败、谱面工程保存 / 加载失败。这些路径今天已有降级与 Toast，缺的是落盘与现场。Bestdori 合并后新增的网络 / 登录 / 上传失败路径同属本阶段。
- 第二阶段：**难复现问题**（性能 / 渲染异常）由操作轨迹 + 环境信息兜底。

## 3. 落盘与操作轨迹（定案：双轨）

- **错误日志**：`userData/logs/errors-YYYYMMDD.log`，纯文本，行格式 = 时间戳 + 级别 + 模块前缀（沿用现有 18 处 `console.*` 的模块命名），消费者是人——用户可直接当文本贴 Issue。
- **操作轨迹**：`userData/logs/trail-YYYYMMDD.jsonl`，结构化，模块级动作（页面导航、工程打开 / 保存、导入导出起止、设置变更），消费者是排查。内存 ring buffer 约 500 条，崩溃或导出诊断包时落盘。
- **轮转**：按天切文件、单文件 5MB 封顶、保留 7 天 / 总量 50MB。
- 渲染进程无文件写权限，日志经 IPC 汇聚到主进程统一落盘。

## 4. 诊断包（定案）

- **默认包含**：应用 / Electron / OS 版本、数据根路径、最近 7 天错误日志、最近一次操作轨迹、当前页面 / 模块、设置快照（凭据类字段一律剔除）。
- **「附带当前谱面数据」勾选框，默认不勾**——谱面是用户创作内容、可能含未发布作品，默认不附、让用户主动勾。
- 导出为带时间戳的 zip；入口 = 设置页 + 崩溃弹窗。

## 5. 崩溃兜底（定案：三层 + 全局）

- App 顶层 boundary + 每页面 route-level boundary + canvas 渲染区单独 boundary（崩了显示错误态 + 「重试」，不白屏）。
- `window.onerror` / `unhandledrejection` 接入 logger。
