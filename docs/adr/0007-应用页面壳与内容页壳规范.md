# ADR-0007: 应用页面壳与内容页壳规范

- **状态**：Accepted（定案于 grill-with-docs，2026-08-27）
- **背景**：应用 5 个页面（工作台 / 音频 / 素材 / 快捷键 / 设置）中，4 个非工作台页的布局壳形态各异——是否有次级索引、次级索引是顶部还是侧边、侧边在正文外还是正文内、整页滚还是内嵌滚、容器宽度——5 个维度都有差异，4 个页面写出 4 套微差 JSX。本轮目标：把这 5 维度的差异收敛为一个**可复用模板** `<AppPageShell>`，4 页一次性迁移，并沉淀"未来加新页"用的决策清单。
- **结论**：见本文件全文。
- **变更触发**：任何与"应用页面壳 / 内容页壳"形态相关行为与本文件冲突时，须先更新本文件并经用户确认。
- **关联**：与 [ADR-0003 工作台 UI 与配置系统](./0003-工作台UI与配置系统.md) §2 入口流程与 §11 信息架构配套；[issue 28 多页面管理](../.scratch/basic-editor/issues/28-多页面管理-页面Tab架构.md) 已闭环 5 页注册与切页快捷键；本 ADR 锁定 4 个非工作台页的**内容壳**。

---

## 1. 两层壳的边界

应用界面有两层壳，**职责正交、不能混**：

| 层 | 文件 | 职责 | 维护范围 |
|---|---|---|---|
| **应用壳** | `src/pages/AppShell.tsx` | 5 页注册 + 保活挂载 + 切页快捷键 + 可折叠应用导航 | 不在本 ADR 范围（issue 28 已闭环） |
| **内容壳** | `src/layouts/AppPageShell.tsx` | 4 个非工作台页（音频 / 素材 / 快捷键 / 设置）共用的"页面头 + 侧边索引 + 内容模式 + 自适应几何"模板 | 本 ADR 范围 |

工作台 `Editor` 因内部布局专属（issue 28 P1+P2 浮层重构），**不接入**内容壳。

## 2. 内容壳 API 形态

`<AppPageShell>` 采用 **compound component 形式**（namespace，不使用 React 19 `Children` API named children）：

```tsx
<AppPageShell>
  <AppPageShell.Header eyebrow="…" title="…" description="…" />

  {/* 可选；存在即渲染"独立于正文外"的侧边索引 */}
  <AppPageShell.Sidebar>
    {/* 平铺 */}
    <AppPageShell.SidebarItem icon={Music2} label="音频素材" />
    <AppPageShell.SidebarItem icon={Volume2} label="键音素材包" />

    {/* 或分组 */}
    <AppPageShell.SidebarGroup title="应用设置">
      <AppPageShell.SidebarItem icon={MonitorCog} label="外观" />
    </AppPageShell.SidebarGroup>
  </AppPageShell.Sidebar>

  <AppPageShell.Body mode="default" | "fill">
    {/* 页面正文；4 页自管（不强制包 surface-section）。body 宽自动填充剩余空间。 */}
  </AppPageShell.Body>
</AppPageShell>
```

**namespace 形式**而非 named children：心智负担最低（与 Radix UI / shadcn/ui 同风），调用方写错顺序编译通过但视觉错位——**靠代码 review 与本 ADR §6 决策清单自检**。

## 3. 4 个 prop / slot 的语义

| 维度 | API | 取值 | 默认 | 4 页现状映射 |
|---|---|---|---|---|
| **Header** | `Header` slot，props = `eyebrow / title / description` | 3 个字符串 | 必填 | 4 页 description 定稿见 issue 125 |
| **侧边索引** | `Sidebar` / `SidebarGroup` / `SidebarItem` slot | 可空；分组用 `SidebarGroup title` | 缺省 = 无侧边 | 设置 = 分组 / 音频 = 平铺 / 素材 = 平铺 2 项 / 快捷键 = 平铺索引筛选 |
| **内容模式** | `<Body mode="…">` | `"default"`（整页滚） / `"fill"`（整页不动 + 内部子元素自身滚） | `"default"` | 快捷键 = `fill`；其它 3 页 = `default` |
| **侧边宽度** | 模板自适应（无 prop） | `clamp(140px, 12.5% × W, 200px)`，见 §5 | — | 4 页统一自适应 |

## 4. 模板硬约束 3 处

其它全部由 design tokens + 页面作者自管——模板**不压平 4 页的"内容差异"**：

1. **Header 下间距** = `var(--space-8)`（32px）；
   > 修订（2026-09-05，issue 49 阶段 2 收口随附）：原定 `var(--space-md)`（旧 token 体系，当时 ≈16px）。2026-08-30 用户反馈"页头与卡片间距过窄"，上调至 32px（与卡片 24px padding 合计 ~56px 呼吸感）并经实机确认，本条按"变更触发"条款补记。
2. **Sidebar-Body 横向 gap** = `var(--space-6)`（24px，经 `--aps-gap` 落到 `__head`/`__main`）；
   > （2026-09-05 仅改 token 名：原写 `var(--space-lg)`，token 刻度重构后该名已不存在，24px 值未变。）
3. **Sidebar 内 padding** = `12px 10px`（与 `.app-nav` 一致，保证工作台与非工作台页图标位置统一）。

## 5. 几何自适应（issue 120：外侧间隙 + 正文封顶）

内容壳宽度 `W` = 窗口宽 − **应用导航**。一行：`L + 侧边索引 + gap(24) + 正文 + R = W`。实现：`src/layouts/contentShellGeometry.ts` 的 `layoutContentShell(W)`，由 `AppPageShell` 写入 `--aps-inset-l` / `--aps-inset-r` / `--aps-sidebar-w` / `--aps-body-w`。

- **侧栏** = `clamp(140px, 12.5% × W, 200px)`（不跟窗口 1:1 抢宽度）；
- **默认窗 1260×800**（折叠导航 → `W=1208`）：正文锚点 **920**；**L = 51**（不对称为左右相等）；R 吃剩余（默认档 **62**）；
- **再变窄**：L 与 R **一起减**；L 先到 **L_min = 16** 后只减 R，到 **R_min = 16** 之后才减正文；
- **再变宽**：间隙冻在默认窗那档，正文随侧栏吃完后的剩余变宽，直到 **`B_max = 1440`**；再宽则左右间隙一起加；**`L_max`**（令牌 `--aps-inset-l-max`，出厂 **96px**，可调，不锁死本文数字）之后只加 R；
- **gap** = `24px`（模板硬约束 #2）；
- **header / body 对齐**：`__head` 与 `__main` 同构 flex（同 L/R、同 gap、header 侧用 `__slot` 对侧栏）。当前四页都有真侧栏；无侧栏页仍可由 `__main` 渲染 `__slot`；
- **响应式断点 720px**：侧栏收为顶部水平条，L/R=16，`__slot` 隐藏，正文 `max-width: 100%`。

> 历史：issue 44 第四轮曾用固定 L=51 / R=32、正文 ≤1440 锁 920、更宽按 0.3/px 涨、无 `B_max`。issue 120 废 0.3 公式，改为外侧间隙可压缩 + 正文 1:1 至封顶。

## 6. 未来新页 4 题决策清单

> 加新应用页面（非工作台）时，按顺序答以下 4 题——答完即得模板调用骨架：

1. **有"页内子类别切换"吗？**
   - 没有 → 不写 `<Sidebar>` 整段；
   - 有且需分组（≥2 组）→ `<Sidebar>` + `<SidebarGroup title="…">`；
   - 有且单组 → `<Sidebar>` + 平铺 `<SidebarItem>`。
2. **页面内有"一直可见的头部（搜索/工具栏）"吗？**
   - 有 → `mode="fill"`（整页不动，搜索栏/工具栏固定，正文自滚）；
   - 没有 → `mode="default"`（整页滚）。
3. **详情区有几个 `surface-section`？**
   - 模板不限制，作者自管。
4. **页面头要写什么 eyebrow / title / description？**
   - 模板不规定，填 3 个字符串即可；4 个原页 eyebrow 文案语义对齐**单开 issue**（不归本 ADR）。

> **4 题答完 → 调用骨架自动出来**。新页作者无需再判断"该用顶部 tab 还是侧边"——本 ADR §3 + §6 已固化"侧边"为本规范唯一原语。body 宽 / sidebar 宽全部自适应，作者**不传 width prop**。

## 7. "顶部 tab"本轮废止

- 历史上素材页用过"页内顶部类别子 tab"（`.assets-tabs`）；
- 本轮收口：4 个非工作台页**全部侧边**，**顶部 tab 原语本轮废止**；
- 未来不复活，除非有强需求——届时另开 grill，并在本 ADR 增节登记回归原因。

## 8. 切子类别不写 URL

- 4 页"页内子类别"切换（音频 3 / 设置 4 / 素材 2）保持 `useState`，**不写 URL/hash、不进历史栈**；
- 与"切页 = 不写 URL"心智对称（应用壳 `AppShell` 切页用 `useState<PageId>`）；
- 未来"刷新后想恢复"的需求出现时单开 issue，**届时一并决定"切页本身要不要 URL"**，避免本 ADR 越界。

## 10. 边界（本 ADR 不覆盖）

- **`AppShell` 应用壳**（5 页注册 / 切页快捷键 / 折叠导航）：不在本 ADR 范围（issue 28 已闭环）；
- **工作台 Editor 内部布局**：不在本 ADR 范围（issue 28 P1+P2 浮层重构进行中）；
- **eyebrow 文案语义统一**：不在本 ADR 范围，单开 issue；
- **页面壳与 URL 路由**：不在本 ADR 范围，单开 issue；
- **顶部 tab 原语**：本 ADR §7 废止，未来回归需另开 grill；
- **每个页面内部"内容"**：不在本 ADR 范围，本轮纯壳迁移。
