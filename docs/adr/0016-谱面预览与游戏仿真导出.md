# 谱面预览与游戏仿真导出

## 1. 两种形态

### 1.1 静态预览 = **面板折行全景**（不是"导出一张长图"）

- **面板**：一处 `panelW × panelH` 的渲染目标，覆盖**布局轴**（ADR-0010：pos = 秒 × `virtualPxPerSecond`，`verticalRatio=1` 时 440 px/秒）上定长的一段。面板 `k` 覆盖 `[k·panelH/es, (k+1)·panelH/es)` 虚拟 px，其中 `es` 是生效缩放（经 `fitScale` 钳制）。
- **排布**：面板按序号**横向**排开 + 容器横向滚动；可见区间 = `[floor(scrollLeft/panelW), floor((scrollLeft+clientW)/panelW)]`；**只画可见且尚未画过的面板**（懒绘制 + 记账，滚出视口不销毁）。
- **面板内时间向上**：与既有渲染方向天然一致（判定线 = 画布底边，谱面在下、END 在上），不需要任何翻转。
- **默认档**：参考 Bestdori 模拟器的静态预览（`panelWidth = 13 × laneWidth`、`heightPerSecond = 150 × chartVertical`、每面板 ≈ 3.6 秒）——我们取 `panelW ≈ 130 CSS px`、`es ≈ 0.3`，每面板 ≈ 4.1 秒。
- **形态的理由**：谱师要**反复看**自己的谱面，"一次铺满一屏"比"一张几十万像素高的长图"可用得多；而长图导出只要复用同一份面板模型就能顺带拿到。
- 长图导出与尺寸上限见 §7。

### 1.2 动态预览 = **游戏仿真场**

- 画面 = 游戏式场地（设计面 **1334×750**；`laneWidth = 154 × W/1334`、`laneHeight = 0.82 × H`；原点 `(W/2, 0)`、`y = 1` 即场地判定线）+ 场地图 / 判定线图 / 背景图 + **per-lane 音符精灵** + 带体四边形 + 同时点击线 + 方向键 + **打击特效**（21 起照 Bestdori 自家 `particles` 精灵：命中特效 + **连按（带体按住）**的 `connectionRing` 与对转双环；缺这三张精灵时回落程序化自绘）+ **combo**（21 起用它的 `digits` / `combo` 精灵，不再用系统字体自绘）。
- **场地尺寸**：设计面 **contain** 进舞台（不拉伸、不满宽，两侧留白是预期），宽度钳制 `[320, 2560]` CSS px —— 上界由 1920 抬到 2560 是票 19 的定案（保持 contain、只把画面做大；位图 = 场地尺寸 × 密度，见 `SIM_FIELD_LIMITS`）。满宽两案（页面滚动 / 顶部裁切）**用户已否决**。
- **接近模型**：`A = 0.05 + 0.95 × 1.1^(50·(t_now − t_note)/T)`、`T = max(APPROACH_MIN_SECONDS, (12 − noteSpeed)/2)` 秒（档位 **1..12 步长 0.1** → 5.5s..0.1s；下限 `APPROACH_MIN_SECONDS = 0.1` 秒，票 24 定案 2026-10-08）；元素按 A 缩放（越小越靠上、越靠中 = 伪透视）。上界取 12 = **现代游戏自己的档位上限**（Bestdori 模拟器封在 11，因为同一个公式在 12 处退化成 `T = 0`）：给它一个 0.1s 的地板 ⇒ 12 是"极短但连续的接近窗口"而不是模型无定义，`n ≥ 11.8` 都是 0.1s。口径：**Bestdori 参照实现与游戏冲突时优先游戏**（1..11 是老版本游戏的档位）。_2026-10-18 修订（票 48）：T 换成**游戏同款分段映射** —— `n ≤ 11 → (12 − n)/2`、`n > 11 → (16 − n)/10`（口径来源 = sonolus-bandori-engine `note.duration`；两支在 n = 11 处连续，档位 1..12 → 5.5s..0.4s）。票 24 只接了第一支 + 0.1s 地板 ⇒ 12 档 0.1s 比游戏 0.4s 快 4x、11.5 档也快 1.8x；地板保留为**越界防御**，白名单内不再触达。"优先游戏"的口径本身不变（本次正是回到该口径）。_
- **首期不含**（原始拍板）：分数、技能 / fever 表现、自定义背景图 / 背景视频。判定文字（PERFECT）与 AP combo 变色自 chart-preview 51 起补上；_**2026-11-08 修订（票 71/72/73，推翻本条"不含分数"）**_：打歌画面增加 **AUTO 两档判定字**（`settings.preview.autoMode`，**2026-11-08 验收改默认关**；开 = `judge_auto` + `AUTO LIVE` 提示，关 = `judge_perfect`；**combo 的 AP 态只由 `apCombo` 决定，与 AUTO 无关**）与 **官方 HUD 顶栏**（左上分数框 6 档条 / 右上生命 `1000/1000` / 暂停钮 / 击打 `+增量`（每次命中各一条 `+inc`；2026-11-09 用户验收回退「限流合并」，实机没有该机制；**2026-11-14 用户定案两段运动：极快冲到最右侧，然后缓慢再右移一点点并同时淡出，那段缓移就是淡出时间**，冲刺占比 / 淡出位移 / 亮度等观感参数在原型里调） / SS+ 四芒星）。分数是**归一分**：满分 1,000,000、7 位定宽、`floor(满分 × 已命中数 / 可击打物总数)`、最后一音补齐满分 —— 这是本仓预览的归一上限，**不是**游戏官方分数（实机分数随总力 / 卡组 / 技能变化，官方无公开公式）。仍**不做**技能 / fever 表现、自定义背景图 / 视频。三个能力都画进仿真场帧 ⇒ 实时预览与导出同一份。参数与官方切图坐标见 `src/preview/video/sim/simHud.ts` 的 `SIM_HUD` / `HUD_SPRITES`。
- **口径一致**：`beat < 0` 不渲染 / 不键音 / 计 combo（[ADR-0014](./0014-宽松谱面代码源数据与画布投影.md)），倒流区元素位置取 `displayConnections` 同一显示投影（[ADR-0009 §2.2](./0009-SP绿条与段曲线模型.md)）——**不另立一套**。
- 参照实现：Bestdori `/tool/chartsimulator` 的 `MySongSimulator`（模型与素材清单见 research 笔记 §1.2）。它的"视频"是实时模拟器、**没有任何导出**（bundle 内 `MediaRecorder` / `captureStream` / `VideoEncoder` / `toBlob` 各 0 处）——视频导出在本项目里没有对标物。

## 2. 静态预览复用编辑器渲染 + 预览显示档

- 面板里画的**就是**编辑器画布那套渲染（`renderChart` / `RenderTarget`），不新写第二种平铺画笔：倒流区折返、SP 带、色觉辅助、皮肤全部照旧生效。
- **预览显示档** = 预览页自带的一组 `FrameView.display` 覆盖：默认**精简**（关掉网格细节 / 沟槽文字 / END 线这类"编辑器装饰"），可手动开回。首期优先用现有 display 字段表达；确需新开关时才在 `FrameView.display` 加字段。
- **被否**：为静态预览另写一份"干净平铺画笔"（Bestdori 那种黑底 + 轨道 + 音符）。观感更贴 Bestdori，但等于把带体 / SP / 倒流区的画法维护两份——本仓库已多次为"唯一绘制真相"付过代价（ADR-0009 §滑条带体几何）。
- hover 读数复用既有「实时显示线 + 分内时间（左）+ 已过音符数（右）」。

## 3. 落点与依赖方向

```
src/preview/            ← 新顶层域（不 import pages/）
  index.ts              ← barrel
  static/               ← 面板折行与长图导出
  video/sim/            ← 仿真场（几何 / 一帧绘制 / 实时回放）
  video/encode/         ← 离线逐帧、音轨、编码封装
src/pages/preview/      ← 应用页面（装配层，消费上面两者）
```

- 单向依赖：`preview → rendering / chart / audio / playback`；`chart` / `rendering` / `playback` **不得** import `preview`。
- 仿真场**不进** `src/rendering/`：它是预览专用画法（`src/rendering/` 的语义是"编辑器画布"）；它复用渲染域的皮肤原语（`rendering/skin/noteSkin` 的 `buildActiveNoteIcons`）与图集缓存。

## 4. 载体与作用域

- 预览是**独立应用页面**（应用壳第 7 页，紧随音频页；位次见下，键位 2026-10-28 起为 `Alt+4`，见 [ADR-0002](./0002-快捷键系统与自定义配置.md) 头部修订），**不**进程"进页面即确保当前工程"集合；无 scope 时回落「当前工程 + 当前谱面」，都没有 → 空态且**不新建工程**。
- **修订 [ADR-0015](./0015-歌曲级谱面工程与工程管理页入口.md) §6 的"只做工程一级"**：`pageScope` 的二级 `chartId` 由本 ADR 起落地（预览就是那个"第二个真实消费者"）；`chartId` 缺席时按工程的当前谱面取（`CurrentProjectSession`）。
- 作用域条复用 `src/ui/ScopePicker.tsx`（受控）；谱面级定位是预览页自己的事（作用域条只管工程，票 22 定案 7 不变）。

## 5. 视频导出 = **离线逐帧 + 含音频**

```
任意秒出帧（仿真场的同一函数，固定 surface / dpr）
  → 逐帧离屏出帧（t = k / fps）→ VideoEncoder（WebCodecs）→ 封装
音轨：OfflineAudioContext 渲染 BGM + 键音 → AudioEncoder → 同一容器
  → 二进制另存（Electron 通道；浏览器降级 <a download>）
```

- **不用实时录制作主路**（`canvas.captureStream()` + `MediaRecorder`）：掉帧与画质受实时性影响，且导出时长被"播一遍"绑死。对照数据仍会实测存档（票 06），供将来重新拍板时有据可查。
- **音轨口径**：**同一份事件表**（`AudioTiming.buildKeyEvents`）+ **同一份采样加载** + 同一份音量口径（`settings.audio`）；不新建第二套调度 / 音量。为此 `AudioEngine` 要交出解码结果 / 采样加载的接缝（现在全 private）。
- **【修订 2026-11-12，issue 231】同刻键音归并**：工作台实时（`AudioEngine.setChart`）、仿真场（`simPlayback` 经 `engine.setChart`）、视频导出（`exportVideo` → `renderAudioTrack`）**三处各自调用同一份 `AudioTiming.buildKeyEvents` 建自己的数组**，不是共享同一个数组实例；「同一份事件表」的口径 = 同一份建表函数 + 同一份发声计划语义。同刻（严格 `time` 相等）同一份采样的多次触发在**建表时**归并为一条、组内仍发声一次（语义见 ADR-0004 §7）；离线侧只保留原有的轨外过滤与 `+simStartSeconds`（票 74 起；原先是 `+openingSeconds`；票 75 起过滤右端点为 `D + tail`，末拍 `evt.time === D` 必发声），**不在渲染层另做去重 / 限幅**。归并条目 ≠ 删谱面音符，谱面数据层仍保真重叠音符。**【后续修订 2026-11-12】同刻响度归一**：归并后同刻仍有 N 份不同采样时，`buildKeyEvents` 给该组每条写 `gain = 1/√N`（单声省略 =1）；实时与离线都只把 `evt.gain` 透传给共享 `scheduleKeySample` / `scheduleKeyTone` 的 `gainScale`，不在渲染层另算系数、不挂总线限幅（理由与实测见 ADR-0004 §7）。
- 导出耗时 ≥ 歌曲时长：UI 必须给进度 + 取消；长谱导出不得阻塞页面交互。
- 视频编码与封装的具体 codec / 容器 / 库由实测（票 06）定；默认目标 1920×1080 / 60fps。
- **时间线 =（开场段，若开）+ 前导补偿段 + 谱面段 + 末击收尾段 +（结尾段，若开）**（开场 2026-10-10 追加见 §5.1；前导 2026-11-14 票 74 追加见 §5.1；末击尾段 2026-11-14 票 75 定案见 §5.2；结尾 2026-10-26 追加见 §5.2）：上面那条"任意秒出帧 → 逐帧"链条前后各可多一段，音轨同步拉长（**谱面 0 秒与 BGM / 键音一起落在 `simStartSeconds` = 开场 + 前导**、结尾留静音尾巴），绝不与谱面重叠。前导段按负秒取帧、音轨静音；末击尾段沿用同一条 `seconds = t − simStartSeconds`，让最后一击的打击特效 / 判定字自然播完再切结算。

### 5.1 视频开场：导出物最前面的一段（2026-10-10 用户拍板）

- **是什么**：导出物最前面一段**开场段**，四段 = ① **开场淡入**（第 0 帧纯黑 → 开场画面浮现，**1s**）→ ② **停留**（整屏静止读信息，**2.2s**）→ ③ **入场过渡**（开场画面淡出到只有**表演背景图**的场地上，**1.75s**）→ ④ **轨道淡入**（整块轨道 = 场地图的扇形车道 + 判定线浮现，**1.8s**）= 合计 **6.75s**（2026-10-27 原型回填；原先 1.0 / 1.5 / 1.0 / 1.5 = 5.0s）。四段过渡都是交叉淡入淡出，不做缩放 / 位移 / 倒计时。画面 = 黑底 + 程序化装饰（音符 + 配对五角星）+ 居中方形封面 + 难度徽章 + **标题条** + 艺人行。它服务"把谱面预览视频发到互联网上"这条用例——观众得先知道这是哪首曲子。
  _（四段时长 2026-10-10 由原型 `?prototype=opening-screen` 逐段拍板、**钉死常量、首期不可调**；初版是 1.0 / 1.5 / 0.5 = 3.0s，第四段为原型第五轮追加，第三、四段时长在第七轮各加 0.5s。）_
- **纯前置，绝不与歌曲前奏重叠**：视频总长 = **6.75 + 前导补偿 + 谱面时长 + 末击尾段（结尾段另加 7.5s，见 §5.2）**（票 74 追加，见下条）；BGM 与键音事件整体后移到 `simStartSeconds`（= 开场 + 前导），**开场段与前导段都无 BGM / 无键音**（人潮 SE 除外）。重叠方案被否：它吃掉谱面开头那段音符的接近窗口（默认 noteSpeed 9.5 时 ≈1.25s），开头就有音符的谱会漏掉可见期，"预览"本身失真。**过渡段的场地不按负秒取帧**（原型第六轮改）：负秒下 `drawSimFrameAt` 会画出正在接近的音符 / 带体，不是干净的场地 ⇒ ③ 只画 **bgskin 表演背景图**、④ 才加**整块轨道**（场地图 + 判定线），两段都不进 `drawSimFrameAt`；④ 之后的**前导段**才按负秒进 `drawSimFrameAt`，谱面 0 秒与音乐起点的对齐由 `simStartSeconds` 保证。
- **【2026-11-14 追加，票 74】开头前导补偿（lead-in）**：④ 轨道淡入结束后、谱面 0 秒之前补一段真实时长，让第 0 beat 的音符走完接近窗口（不再瞬间出现在判定线）。`leadIn = min(T, 2s)`，`T = chart.approachS`（与游戏 `note.duration` / 本仓 `approachSeconds` 同源），按 60fps 帧对齐；`LEAD_IN_CAP_SECONDS` 与 `leadInSeconds()` 只在 `exportSpec.ts` 定义一次，**成片验收后调参只改这一处**。`simStartSeconds = OPENING_SECONDS + leadIn` 是谱面 0 秒在成片里的绝对秒，`frameDriver` 统一取 `seconds = t − simStartSeconds`（前导段为负秒），BGM `start(simStartSeconds)`、键音 `+simStartSeconds`、轨长与视频总长同步；结尾 SE cue 也落在新 `endingAt`。**前导段保持静音**：开场人潮 `SE_RHYTHM_GAYA` 仍在开场段末尾截断淡出、不跟着延长。实时回放 `simPlayback` / 播放条时间码 `[0, D)` 不动。**【2026-11-15 成片验收回修】** 用户确认整体效果 OK，但慢速档（封顶生效）首帧仍能从 `A≈0.22` 直现看出「闪一下」；按「不再增长时长」的前提，只在前导头 `LEAD_IN_NOTE_FADE_FRAMES = 15` 帧（0.25s @60fps）给音符层 `1/15 → 1` 的线性淡入（初版 2 帧 = 33ms 用户反馈肉眼不可见，故加长）（`leadInNoteAlphaAt()` 与 `SimFrameLayers.noteAlpha`，只在 `leadIn < T` 时启用；`leadIn == T` 的默认 / 快速档零变化）。淡入只收边界突变，**不替代补时长**，也不进实时回放 / 音轨 / 结算段；用户描述的「移动遮罩」备选未采纳，留作后续若仍突兀再议。

- **图集不再进包体（2026-11-22 票 83）**：上面三张图集（`MenuAtlas.png` 2048² / 631 KB、`RhythmGameUI.png` 1024² / 135 KB、`tex_parSet_fever.png` 512² / 33 KB）运行时只用到十来格，像素利用率 1~2%，而 `public/` 是全量拷进 `dist/` 的。改为裁成 11 张单格派生件（合计 22.6 KB）；坐标对照表在 `docs/research/gbp-ui-assets.md` §12，是唯一事实源，生成器随快照仓（主仓不存放产出资源的工具），绘制侧一律整图 + `(0,0)` 取景。**派生件是官方原像素的无损裁切，画面零变化**；`atlas/` 与 `stageskin/normal/` 里那三张原图**必须从快照仓 payload 移出**（`assets-sync` 整根覆盖、无 exclude 机制），原图留在快照仓的非 payload 目录供 `--from` 再生成。缺派生件仍按「留空 / 纯字」降级。

- **稳定获取口径**（用户 2026-09-30 追问"是不是得有稳定的脚本能拿到"）：**唯一入口是归档脚本**
  `node scripts/fetch-bestdori-skins.mjs --category fieldskin,bgskin`
  —— 它幂等、可断点重跑、按 SHA-256 校验、失败写 `failures.json` 且非零退出；**README 与运行时空态文案都必须给出这条命令**。完整 manifest 照既有约定上传 release 渠道做镜像，供他人拉取。
- **授权边界不变**：素材"不得再分发、仅供本地研究"（`docs/resource/bestdori/README.md`）。
- **留后票**：打包进安装包 / 运行时从 Bestdori 拉取（前置是 [ADR-0011](./0011-Bestdori集成与本地客户端网络素材边界.md) 的网络层）/ 用户自备素材包；以及自定义背景图 / 背景视频。

## 7. 长图导出与落盘通道

- 长图导出 = 面板模型的**副产物**：离屏按同一参数逐面板出图 → 单行宽图（超上限才折行网格）单图（或每面板一张 PNG）。
- **不做单条超高长图**：3 分钟谱内容高 `180 × 440 = 79,200 px`，超 Chromium 单边上限 65,535 px（面积上限 2^28 ≈ 268M px²）；宽图网格（3,222 高档下 3 分钟 ≈ 19 面板，缓冲 `10,982 × 7,324`，含图文版 440 头带）仍在限内。
- **导出档 = 固定档，与预览解耦**（2026-10-05 加大宽 / 2026-10-06 乘 6 加高，两次用户定案）：面板 `289 × 3,222 CSS px`（`EXPORT_ES = 0.74`）、`dpr 2`、精简标注档；导出档常量各自钉死（`EXPORT_ES` / `EXPORT_PANEL_H` / `EXPORT_DPR` 在 `exportPanels.ts`，图文版头带的 `EXPORT_HEADER_H` 在 `sheetHeader.ts`），**不读**窗口与 `window.devicePixelRatio`，也不引用预览的缩放基准（`esForZoom` / `PREVIEW_ES_STANDARD`）——取的只是“定档当日的数”。加大宽的直接理由：旧值 `es = 1/3`（面板 130 px 宽）是 Bestdori 缩略档，导出图里音符的 CSS 尺寸（es 比）只有预览默认档的 45%，用户反馈“导出的图片感觉非常糊”（issue 13）；2026-10-06 格高再乘 6（537 → 3,222，issue 14）：537 时每列只装 ≈1.65 秒，3 分钟谱要 110 列（59:1 瘦条），加高后每列 ≈9.9 秒、19 列（1.7:1）——上限仍是画布上限，不是“越高越好”（复算见下条）。
- **上限通路不变**：先单行宽图（超宽折行、列数取满），再降密度 `dpr 2 → 1`，最后拒绝；真实语料实测（2026-10-06 格高 3,222 复跑，805 张谱面，末音符秒数口径）：**100% 单行、0 拒绝**（仅最长 715.3s / 73 面板一条降密度；图文版头带把 dpr 2 的面积边界自 72 前移到 **63 面板**——64 面板起先降到 dpr 1 再出图，余量足够，不产生拒绝；2026-10-07 头带 337 → 440 后由 65/66 再前移两位，**头带关掉**时回到旧的 72/73）；硬边界 ≈**226 面板**（≈37 分钟，面积 2^28 先于单边触顶）——折行在 3,222 高下**不可达**，旧档那条“110 列折行”通路实际已死。
- **默认图文版：封面区 + 信息区 + 谱面区**（2026-10-06 用户拍板，chart-preview 14；2026-10-07 版式整改 + 追加总开关，**取代本条旧口径「一律图文版、没有纯面板宽图这个产品档」**）：`settings.export.enabled`（默认开）决定要不要这条**头部横带** —— 开时宽图最上面是一条横带（`EXPORT_HEADER_H = 440 CSS px` = 392 封面 + 上下各 24），横带以下才是面板区，**横带计入高与面积上限**（`planSheetExport` 的 `headerH`，面板行整体下移）；**关掉时 `headerH = 0`，导出物就是纯面板区的宽图**（连封面都不解码）。没有封面也走**占位块**（工程 id 派生色相的深色渐变；hue 由页面算好传入——preview 域不 import 工程域）。封面方形裁切、短边居中取满、**贴左缘**（不让左边让白：与下面面板区左缘对齐成一条竖向内容边界）、无圆角；右侧信息区三槽位**整体垂直居中**（`layoutInfoStack`）：大字标题 120 / 副行 44（谱面标题未填回落工程名；工程名与标题重复自动去重）/ 指标 chips 32（难度等级 / 时长 / 音符数 / BPM / 导出时间；最多两行）——旧档是「标题顶部锚定 + chips 底对齐、中间留 ~136 px 空档 + 标题只占带高 14%」，缩略看整图时读不出东西（2026-10-06 用户验收「太丑」）。统一用一条无衬线链（含 chips）：等宽链在中文环境回落宋体更糟。每枚 chip 的**文字与描边带自己的重音色**（`CHIP_ACCENTS`：时长天蓝 / 音符淡紫 / BPM 琥珀 / 导出时间灰），**难度那枚用工程里那份难度色**（`DIFF_COLORS[diff]` 由页面传入 —— preview 域不 import 工程域，口径同 `coverHue`；缺省 / 非法回落默认字色）。头带底部有一道**由深渐暗的“缝”（10 px）+ 最底一条亮线（2 px）**与面板区分界（画在下 padding 区内，不额外占高）。7 项**信息区字段**开关与总开关同落 `settings.export`（additive 段、不 bump schemaVersion；字段默认 = 谱面标题 + 难度等级 + BPM），入口在预览页工具栏「导出」按钮弹出的「导出图片」浮层的「导出信息」组（2026-10-11 用户拍板，chart-preview 37：自「显示」面板迁移，对齐「导出视频」形态）：总开关挂组标题行右侧（2026-10-07 用户否决“另立一行”，由“关掉时七行置灰”自己说明管什么；增加 ? 帮助浮层解释横带作用），七行保留勾选但不可改；BPM 取绝对值 min–max、单条只写一个值；窄图（≤2 面板）封面自动缩到 ≤ 图宽一半、文字截断。复算：dpr 2 面积边界 63 过 / 64 降密度（头带关掉时 72 / 73），dpr 1 226 过 / 227 拒绝（reason `area`）；3 分钟谱 19 面板 → sheetH 3,662、缓冲 `10,982 × 7,324`。真机像素核对（Playwright 走真实导出通路，2026-10-06）：旧 337 档头带 / 面板区分界正好 `y = 674 = 337 × 2`，封面图贴左缘方形裁切、无封面为蓝紫占位块；2026-10-07 新档用真实画图代码渲染样本核对版式（整图缩到 1600 宽观看时标题 ≈35 px，旧档只有 ≈13 px）。
- **清晰度是像素事实**（单测画不出“糊”）：2026-10-06 真机实测（Playwright 走真实导出钮，量导出画布与落盘 PNG）同一孤立单键 —— 导出 `49 × 27 px`（`es 0.74 · dpr 2`）**与预览「标准档」（density 2）逐像素一致**；预览默认「高清档」（dsf 2 → density 4）为 `98 × 53`（2.00×）；旧档当量（`es 1/3` + density 2）为 `22 × 13`（0.449×）。
- **二进制另存通道**（preload + main：`Uint8Array` + 建议文件名 + mime）由本 effort 新建，PNG 与视频共用；浏览器降级 `Blob` + `<a download>`（照 `src/project/exportChartCode.ts` 先例）。

## 8. 否决（记录理由）

- **视频先做"编辑器观感"的过渡档**（用户否决）：最终一定要仿真场，先做一版编辑器观感的视频等于白做；导出链路与仿真场渲染器拆两条子线并行即可（前者与画面无关）。
- **静态预览 = 单条超高长图 / 把导出当主要形态**：尺寸上限之外，谱师要反复看，长图不方便。
- **静态预览另写"干净平铺"画笔**：两份绘制真相（见 §2）。
- **实时录制作主路**：见 §5。
- **素材打包进安装包 / 现在就做运行时拉取**：体积与授权问题都不该在首期解决；用户明确"未来再考虑，大不了改成素材不打包进去"。
- **不写本 ADR**：这族的决策（形态 / 域落点 / 依赖方向 / 素材边界 / 导出链路）跨 6 张票，落 ADR 才能让后续票不必各自重新论证。
