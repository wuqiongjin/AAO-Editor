# ADR-0016: 谱面预览与游戏仿真导出

- **状态**：Accepted（定案于 chart-preview 立项票 01 的七问，2026-09-30；用户逐问拍板）
- **背景**：谱面作者需要在编辑器画布之外**看到 / 导出**自己的谱面，重点服务"观赏性谱面"作者（诉求：流畅、可定制、便捷、快速）。当前仓库**没有任何预览 / 导出成图代码**：`src/preview/` 不存在，全仓无 `MediaRecorder` / `captureStream` / WebCodecs，落盘通道只有"谱面代码 JSON 另存为"与两处字节写。地基已就位：`architecture-refactor/03`（+ 08）把渲染收敛为 `src/rendering/` 唯一入口，`createRenderTarget` / `frameFor` / `renderFrame` 就是"任意片段出帧"的地基（文件头注释本就为"离屏导出 / 未来预览各建自己的 target"预留）；播放侧（[ADR-0004](./0004-播放预览交互.md) / [ADR-0006](./0006-画布动态渲染面与判定线贴底.md)）的时钟、滚动、键音、判定线贴底均已存在。Bestdori 侧的反编译事实与"我们有什么"见 [research 笔记](../research/chart-preview-technical-baseline.md)。
- **结论**：见全文。本 ADR 定"预览是什么形态、住哪、依赖怎么走、素材从哪来、导出走哪条链路"；实现由 `.scratch/chart-preview/` 的 02–07 票承载。
- **变更触发**：预览的**形态**（面板折行 / 仿真场 / 导出链路）若要与本文件冲突，须先改本文件并经用户确认。仿真场的**素材口径**（§6）单独一族，改动它不必重开本 ADR 的其余部分。

# 谱面预览与游戏仿真导出

## 1. 两种形态

### 1.1 静态预览 = **面板折行全景**（不是"导出一张长图"）

- **面板**：一处 `panelW × panelH` 的渲染目标，覆盖**布局轴**（ADR-0010：pos = 秒 × `virtualPxPerSecond`，`verticalRatio=1` 时 440 px/秒）上定长的一段。面板 `k` 覆盖 `[k·panelH/es, (k+1)·panelH/es)` 虚拟 px，其中 `es` 是生效缩放（经 `fitScale` 钳制）。
- **排布**：面板按序号**横向**排开 + 容器横向滚动；可见区间 = `[floor(scrollLeft/panelW), floor((scrollLeft+clientW)/panelW)]`；**只画可见且尚未画过的面板**（懒绘制 + 记账，滚出视口不销毁）。
- **面板内时间向上**：与既有渲染方向天然一致（判定线 = 画布底边，谱面在下、END 在上），不需要任何翻转。
- **默认档**：参考 Bestdori 模拟器的静态预览（`panelWidth = 13 × laneWidth`、`heightPerSecond = 150 × chartVertical`、每面板 ≈ 3.6 秒）——我们取 `panelW ≈ 130 CSS px`、`es ≈ 0.3`，每面板 ≈ 4.1 秒。
- **形态的理由**：谱师要**反复看**自己的谱面，"一次铺满一屏"比"一张几十万像素高的长图"可用得多；而长图导出只要复用同一份面板模型就能顺带拿到。
- 长图导出与尺寸上限见 §7。

### 1.2 动态预览 = **游戏仿真场**

- 画面 = 游戏式场地（设计面 **1334×750**；`laneWidth = 154 × W/1334`、`laneHeight = 0.82 × H`；原点 `(W/2, 0)`、`y = 1` 即场地判定线）+ 场地图 / 判定线图 / 背景图 + **per-lane 音符精灵** + 带体四边形 + 同时点击线 + 方向键 + **打击特效**（21 起照 Bestdori 自家 `particles` 精灵：命中特效 + **连按（带体按住）**的 `connectionRing` 与对转双环；缺这三张精灵时回落程序化自绘）+ **combo**（21 起用它的 `digits` / `combo` 精灵，不再用系统字体自绘）。
- **场地尺寸**：设计面 **contain** 进舞台（不拉伸、不满宽，两侧留白是预期），宽度钳制 `[320, 2560]` CSS px —— 上界由 1920 抬到 2560 是票 19 的定案（保持 contain、只把画面做大；位图 = 场地尺寸 × 密度，见 `SIM_FIELD_LIMITS`）。满宽两案（页面滚动 / 顶部裁切）**用户已否决**。
- **接近模型**：`A = 0.05 + 0.95 × 1.1^(50·(t_now − t_note)/T)`、`T = max(APPROACH_MIN_SECONDS, (12 − noteSpeed)/2)` 秒（档位 **1..12 步长 0.1** → 5.5s..0.1s；下限 `APPROACH_MIN_SECONDS = 0.1` 秒，票 24 定案 2026-10-08）；元素按 A 缩放（越小越靠上、越靠中 = 伪透视）。上界取 12 = **现代游戏自己的档位上限**（Bestdori 模拟器封在 11，因为同一个公式在 12 处退化成 `T = 0`）：给它一个 0.1s 的地板 ⇒ 12 是"极短但连续的接近窗口"而不是模型无定义，`n ≥ 11.8` 都是 0.1s。口径：**Bestdori 参照实现与游戏冲突时优先游戏**（1..11 是老版本游戏的档位）。
- **首期不含**：判定文字（PERFECT / …）、分数、技能 / fever 表现、自定义背景图 / 背景视频——登记为未来扩展（未开票，具体范围待定）。
- **口径一致**：`beat < 0` 不渲染 / 不键音 / 计 combo（[ADR-0014](./0014-宽松谱面代码源数据与画布投影.md)），倒流区元素位置取 `displayConnections` 同一显示投影（[ADR-0009 §2.2](./0009-SP绿条与段曲线模型.md)）——**不另立一套**。
- 参照实现：Bestdori `/tool/chartsimulator` 的 `MySongSimulator`（模型与素材清单见 research 笔记 §1.2）。它的"视频"是实时模拟器、**没有任何导出**（bundle 内 `MediaRecorder` / `captureStream` / `VideoEncoder` / `toBlob` 各 0 处）——视频导出在本项目里没有对标物。

## 2. 静态预览复用编辑器渲染 + 预览显示档

- 面板里画的**就是**编辑器画布那套渲染（`renderChart` / `RenderTarget`），不新写第二种平铺画笔：倒流区折返、SP 带、色觉辅助、皮肤全部照旧生效。
- **预览显示档** = 预览页自带的一组 `FrameView.display` 覆盖：默认**精简**（关掉网格细节 / 沟槽文字 / END 线这类"编辑器装饰"），可手动开回。首期优先用现有 display 字段表达；确需新开关时才在 `FrameView.display` 加字段。
- **被否**：为静态预览另写一份"干净平铺画笔"（Bestdori 那种黑底 + 轨道 + 音符）。观感更贴 Bestdori，但等于把带体 / SP / 倒流区的画法维护两份——本仓库已多次为"唯一绘制真相"付过代价（ADR-0009 §滑条带体几何）。
- hover 读数复用既有「实时显示线 + 分内时间（左）+ 已过音符数（右）」。

## 3. 落点与依赖方向

```
src/preview/            ← 新顶层域（不 import pages/）
  index.ts              ← barrel
  static/               ← 面板折行与长图导出
  video/sim/            ← 仿真场（几何 / 一帧绘制 / 实时回放）
  video/encode/         ← 离线逐帧、音轨、编码封装
src/pages/preview/      ← 应用页面（装配层，消费上面两者）
```

- 单向依赖：`preview → rendering / chart / audio / playback`；`chart` / `rendering` / `playback` **不得** import `preview`。
- 仿真场**不进** `src/rendering/`：它是预览专用画法（`src/rendering/` 的语义是"编辑器画布"）；它复用渲染域的皮肤原语（`rendering/skin/noteSkin` 的 `buildActiveNoteIcons`）与图集缓存。

## 4. 载体与作用域

- 预览是**独立应用页面**（应用壳第 7 页，`⇧⌘3` 紧随音频页），**不**进程"进页面即确保当前工程"集合；无 scope 时回落「当前工程 + 当前谱面」，都没有 → 空态且**不新建工程**。
- **修订 [ADR-0015](./0015-歌曲级谱面工程与工程管理页入口.md) §6 的"只做工程一级"**：`pageScope` 的二级 `chartId` 由本 ADR 起落地（预览就是那个"第二个真实消费者"）；`chartId` 缺席时按工程的当前谱面取（`CurrentProjectSession`）。
- 作用域条复用 `src/ui/ScopePicker.tsx`（受控）；谱面级定位是预览页自己的事（作用域条只管工程，票 22 定案 7 不变）。

## 5. 视频导出 = **离线逐帧 + 含音频**

```
任意秒出帧（仿真场的同一函数，固定 surface / dpr）
  → 逐帧离屏出帧（t = k / fps）→ VideoEncoder（WebCodecs）→ 封装
音轨：OfflineAudioContext 渲染 BGM + 键音 → AudioEncoder → 同一容器
  → 二进制另存（Electron 通道；浏览器降级 <a download>）
```

- **不用实时录制作主路**（`canvas.captureStream()` + `MediaRecorder`）：掉帧与画质受实时性影响，且导出时长被"播一遍"绑死。对照数据仍会实测存档（票 06），供将来重新拍板时有据可查。
- **音轨口径**：**同一份事件表**（`AudioTiming.buildKeyEvents`）+ **同一份采样加载** + 同一份音量口径（`settings.audio`）；不新建第二套调度 / 音量。为此 `AudioEngine` 要交出解码结果 / 采样加载的接缝（现在全 private）。
- 导出耗时 ≥ 歌曲时长：UI 必须给进度 + 取消；长谱导出不得阻塞页面交互。
- 视频编码与封装的具体 codec / 容器 / 库由实测（票 06）定；默认目标 1920×1080 / 60fps。

## 6. 仿真场素材：边界与获取

- **需要**：`ingameskin/fieldskin/*`（`bg_line_rhythm.png`、`game_play_line.png`）与 `ingameskin/bgskin/*`（`liveBG_normal.png`），当前归档脚本与运行时都**没有**这两类。
- **另需 Bestdori 自家的三张精灵**（chart-preview 21）：`/res/sprites/{digits,combo,particles}.png` —— combo HUD 与打击特效照它的实现搬（它不在游戏的资源树里，脚本按**直读 URL 清单**归类 `bestdori-sprites`）；缺这三张时 HUD 与特效**回落自绘**（不判空态、不影响场地）。
- **不需要**：判定资源（`judgeskin`）——Bestdori 模拟器没有判定文字，HUD 只有 combo（21 起用它的 `digits` / `combo` 精灵）。仓库里"保留给未来 Auto 预览判定显示"那条登记继续搁置。
- **不打包**：素材落 `docs/resource/bestdori/`（gitignore，不入仓库、不进安装包），开发期由 **dev-only 中间件**直读；生产构建没有这条通道 → 仿真场给**空态 + 命令提示**。
- **稳定获取口径**（用户 2026-09-30 追问"是不是得有稳定的脚本能拿到"）：**唯一入口是归档脚本**
  `node scripts/fetch-bestdori-skins.mjs --category fieldskin,bgskin`
  —— 它幂等、可断点重跑、按 SHA-256 校验、失败写 `failures.json` 且非零退出；**README 与运行时空态文案都必须给出这条命令**。完整 manifest 照既有约定上传 release 渠道做镜像，供他人拉取。
- **授权边界不变**：素材"不得再分发、仅供本地研究"（`docs/resource/bestdori/README.md`）。
- **留后票**：打包进安装包 / 运行时从 Bestdori 拉取（前置是 [ADR-0011](./0011-Bestdori集成与本地客户端网络素材边界.md) 的网络层）/ 用户自备素材包；以及自定义背景图 / 背景视频。

## 7. 长图导出与落盘通道

- 长图导出 = 面板模型的**副产物**：离屏按同一参数逐面板出图 → 单行宽图（超上限才折行网格）单图（或每面板一张 PNG）。
- **不做单条超高长图**：3 分钟谱内容高 `180 × 440 = 79,200 px`，超 Chromium 单边上限 65,535 px（面积上限 2^28 ≈ 268M px²）；宽图网格（3,222 高档下 3 分钟 ≈ 19 面板，缓冲 `10,982 × 7,324`，含图文版 440 头带）仍在限内。
- **导出档 = 固定档，与预览解耦**（2026-10-05 加大宽 / 2026-10-06 乘 6 加高，两次用户定案）：面板 `289 × 3,222 CSS px`（`EXPORT_ES = 0.74`）、`dpr 2`、精简标注档；导出档常量各自钉死（`EXPORT_ES` / `EXPORT_PANEL_H` / `EXPORT_DPR` 在 `exportPanels.ts`，图文版头带的 `EXPORT_HEADER_H` 在 `sheetHeader.ts`），**不读**窗口与 `window.devicePixelRatio`，也不引用预览的缩放基准（`esForZoom` / `PREVIEW_ES_STANDARD`）——取的只是“定档当日的数”。加大宽的直接理由：旧值 `es = 1/3`（面板 130 px 宽）是 Bestdori 缩略档，导出图里音符的 CSS 尺寸（es 比）只有预览默认档的 45%，用户反馈“导出的图片感觉非常糊”（issue 13）；2026-10-06 格高再乘 6（537 → 3,222，issue 14）：537 时每列只装 ≈1.65 秒，3 分钟谱要 110 列（59:1 瘦条），加高后每列 ≈9.9 秒、19 列（1.7:1）——上限仍是画布上限，不是“越高越好”（复算见下条）。
- **上限通路不变**：先单行宽图（超宽折行、列数取满），再降密度 `dpr 2 → 1`，最后拒绝；真实语料实测（2026-10-06 格高 3,222 复跑，805 张谱面，末音符秒数口径）：**100% 单行、0 拒绝**（仅最长 715.3s / 73 面板一条降密度；图文版头带把 dpr 2 的面积边界自 72 前移到 **63 面板**——64 面板起先降到 dpr 1 再出图，余量足够，不产生拒绝；2026-10-07 头带 337 → 440 后由 65/66 再前移两位，**头带关掉**时回到旧的 72/73）；硬边界 ≈**226 面板**（≈37 分钟，面积 2^28 先于单边触顶）——折行在 3,222 高下**不可达**，旧档那条“110 列折行”通路实际已死。
- **默认图文版：封面区 + 信息区 + 谱面区**（2026-10-06 用户拍板，chart-preview 14；2026-10-07 版式整改 + 追加总开关，**取代本条旧口径「一律图文版、没有纯面板宽图这个产品档」**）：`settings.export.enabled`（默认开）决定要不要这条**头部横带** —— 开时宽图最上面是一条横带（`EXPORT_HEADER_H = 440 CSS px` = 392 封面 + 上下各 24），横带以下才是面板区，**横带计入高与面积上限**（`planSheetExport` 的 `headerH`，面板行整体下移）；**关掉时 `headerH = 0`，导出物就是纯面板区的宽图**（连封面都不解码）。没有封面也走**占位块**（工程 id 派生色相的深色渐变；hue 由页面算好传入——preview 域不 import 工程域）。封面方形裁切、短边居中取满、**贴左缘**（不让左边让白：与下面面板区左缘对齐成一条竖向内容边界）、无圆角；右侧信息区三槽位**整体垂直居中**（`layoutInfoStack`）：大字标题 120 / 副行 44（谱面标题未填回落工程名；工程名与标题重复自动去重）/ 指标 chips 32（难度等级 / 时长 / 音符数 / BPM / 导出时间；最多两行）——旧档是「标题顶部锚定 + chips 底对齐、中间留 ~136 px 空档 + 标题只占带高 14%」，缩略看整图时读不出东西（2026-10-06 用户验收「太丑」）。统一用一条无衬线链（含 chips）：等宽链在中文环境回落宋体更糟。每枚 chip 的**文字与描边带自己的重音色**（`CHIP_ACCENTS`：时长天蓝 / 音符淡紫 / BPM 琥珀 / 导出时间灰），**难度那枚用工程里那份难度色**（`DIFF_COLORS[diff]` 由页面传入 —— preview 域不 import 工程域，口径同 `coverHue`；缺省 / 非法回落默认字色）。头带底部有一道**由深渐暗的“缝”（10 px）+ 最底一条亮线（2 px）**与面板区分界（画在下 padding 区内，不额外占高）。7 项**信息区字段**开关与总开关同落 `settings.export`（additive 段、不 bump schemaVersion；字段默认 = 谱面标题 + 难度等级 + BPM），入口在预览页「显示」面板的「导出信息」组：总开关挂组标题行右侧（2026-10-07 用户否决“另立一行”，由“关掉时七行置灰”自己说明管什么），七行保留勾选但不可改；BPM 取绝对值 min–max、单条只写一个值；窄图（≤2 面板）封面自动缩到 ≤ 图宽一半、文字截断。复算：dpr 2 面积边界 63 过 / 64 降密度（头带关掉时 72 / 73），dpr 1 226 过 / 227 拒绝（reason `area`）；3 分钟谱 19 面板 → sheetH 3,662、缓冲 `10,982 × 7,324`。真机像素核对（Playwright 走真实导出通路，2026-10-06）：旧 337 档头带 / 面板区分界正好 `y = 674 = 337 × 2`，封面图贴左缘方形裁切、无封面为蓝紫占位块；2026-10-07 新档用真实画图代码渲染样本核对版式（整图缩到 1600 宽观看时标题 ≈35 px，旧档只有 ≈13 px）。
- **清晰度是像素事实**（单测画不出“糊”）：2026-10-06 真机实测（Playwright 走真实导出钮，量导出画布与落盘 PNG）同一孤立单键 —— 导出 `49 × 27 px`（`es 0.74 · dpr 2`）**与预览「标准档」（density 2）逐像素一致**；预览默认「高清档」（dsf 2 → density 4）为 `98 × 53`（2.00×）；旧档当量（`es 1/3` + density 2）为 `22 × 13`（0.449×）。
- **二进制另存通道**（preload + main：`Uint8Array` + 建议文件名 + mime）由本 effort 新建，PNG 与视频共用；浏览器降级 `Blob` + `<a download>`（照 `src/project/exportChartCode.ts` 先例）。

## 8. 否决（记录理由）

- **视频先做"编辑器观感"的过渡档**（用户否决）：最终一定要仿真场，先做一版编辑器观感的视频等于白做；导出链路与仿真场渲染器拆两条子线并行即可（前者与画面无关）。
- **静态预览 = 单条超高长图 / 把导出当主要形态**：尺寸上限之外，谱师要反复看，长图不方便。
- **静态预览另写"干净平铺"画笔**：两份绘制真相（见 §2）。
- **实时录制作主路**：见 §5。
- **素材打包进安装包 / 现在就做运行时拉取**：体积与授权问题都不该在首期解决；用户明确"未来再考虑，大不了改成素材不打包进去"。
- **不写本 ADR**：这族的决策（形态 / 域落点 / 依赖方向 / 素材边界 / 导出链路）跨 6 张票，落 ADR 才能让后续票不必各自重新论证。
