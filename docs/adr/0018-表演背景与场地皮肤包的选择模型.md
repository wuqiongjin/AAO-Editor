# ADR-0018: 表演背景与场地皮肤包的选择模型（包清单由素材取件侧产出）

- **状态**：Accepted（chart-preview 41–44 的 grill，2026-10-11；用户逐问拍板 Q1–Q21，8/8 + 后续 3/3 采纳推荐，Q9 与 Q16 由用户改写）
- **修订**：2026-10-22 §1「显示名」口径 + 新增 §6（用户四问拍板；事实依据 `docs/research/skin-naming-sources.md`）——原「显示名 = 包 ID」改为**分层命名**：官方命名 API > 社区 fallback > 包 ID；中文取官方 cn 服条目优先；音符 TYPE 编号错位照官方显示。原 Considered Options 中「人工起中文名」的否决理由（编号包起不出名）对轨道皮肤已不成立——官方 API 恰好命名了 15 个编号轨道包（其中 8 个是乐队名）。**2026-10-22 二轮修订**（用户验收实现后提三点反馈）：§6 补「背景包本地化」行（官方背景名五服同值日文 → 6 个官方背景包的 zh/en 名走 i18n 消息表 `preview.display.bgName.*`，照键音先例；官方将来真本地化时以官方为准）与「网格 tooltip 与展示序」行（tooltip 只留显示名；编号包在前、主题包在后，默认 skin00 第一格）
- **背景**：动态预览（仿真场）的场地三图此前由 `src/preview/video/sim/simAssets.ts` **写死**：包固定 `skin00_rip`、文件名固定 `liveBG_normal.png` / `bg_line_rhythm.png` / `game_play_line.png`，唯一的"选择"是服务器探测 `jp → en → tw → cn → kr`（命中与否只看场地图）。用户诉求是「背景、轨道素材应该有更多种类」。上游实测（Bestdori `jp`，见 `docs/research/sim-asset-variants.md`）：场地（fieldskin）**33 个包**、表演背景（bgskin）**25 个真包**（另 ~19 个 `*preview` 变体）；但**主背景图命名不统一**（`skin00/02/03` 是 `liveBG_normal.png`，其余主题包是 `liveBG.png`），且大包里混着 `equalizer*` / `light_*` / `speaker*` 逐帧特效层与 `*.bundle`。
- **结论**：仿真场的**表演背景**与**场地皮肤包**各自独立、按**包 ID** 选择；**包清单由素材取件侧产出**，应用侧只消费、不再硬编码文件名。归属上刻意做成**混合层级**（内置包应用级 / 自定义图与视频工程级）。详见 §1–§6。
- **变更触发**：新增或删减可选包、改默认包、改任一归属层级、改"自定义"槽位规则，都要先改本文件并经用户确认。

## 1. 选择模型

| 项 | 口径 |
| --- | --- |
| 选择器 | **两个独立选择器**：「背景」（表演背景）/「轨道」（场地皮肤包）。不做成对整包预设 —— 上游两类包只同名配对 20 个，互不配对是常态（轨道独有 `skin01`/`skin04`–`skin14`/`collabo23_summer_g`，背景独有 `skin_5th`/`skin_collabo23_winter_d`/`skin_teamlivefestival`/`skinpractice`） |
| 默认 | 各为 `skin00` |
| 形态 | **缩略图网格**（轨道用该包 `bg_line_rhythm.png` 缩放、背景用 `liveBG*.png` 缩放，缩略从素材自身生成、不额外抓图）；**显示名 = 分层命名**（2026-10-22 修订，见 §6）：官方命名 API > 社区 fallback > 包 ID，辨识交给缩略图 |
| 入口 | **预览页「设置」面板**（挑背景要看着画面挑）；视觉素材页保持"管理 / 上传"场所 |
| 缺失 | **列表即真相**：清单只列**实际取到**的包；运行时加载失败兜底回落 `skin00`，不弹错误、不做"缺失"占位（常识不占行） |

## 2. 包清单由素材取件侧产出（取代硬编码）

- 应用侧**只按包 ID 查清单取文件名与 URL**，不再拼文件名 —— 上游 `liveBG_normal.png` / `liveBG.png` 两种命名并存，硬编码文件名在扩包的第一天就会碎。
- 取件范围（体积进安装包，故背景策展、轨道全量）：
  - 场地（fieldskin）：**全量 33 包**（场地图 1160×610 / 30–48 KB + 判定线 1800×38 / 2 KB，合计 ≈2 MB —— 便宜，差别全在观感）；
  - 表演背景（bgskin）：**策展约 20 个真包、每包只取主图**（2048×1024 / 280–523 KB，合计 ≈8–10 MB）；
  - **跳过**：`liveBG_fever`（我们不做 fever，将来做再补）、`liveBG_layer1/2`、`equalizer*` / `light_*` / `speaker*` 特效层、`*preview` 变体、`*.bundle`。
- **只同步 `jp` 一个服务器**（现状；多服 = 体积 ×5，留后）。
- 清单产出照 `noteSkinRegistry.gen.ts` 的先例（与二进制同版本、一起产出一起取件；**含皮肤显示名映射**，见 §6）；应用仓不自己生成。

## 3. 归属层级（混合，刻意的）

| 东西 | 层级 | 存哪 | 理由 |
| --- | --- | --- | --- |
| 表演背景 · **内置包**选择 | **应用级** | `settings.preview` | "我的默认口味"；新建工程**默认沿用上次选的那个包**（用户原话） |
| 表演背景 · **自定义图 / 视频** | **工程级** | 谱面工程（第 4 个工程二进制） | 它的主题属于这首歌；用户对画布那张的判断恰好相反 —— 画布「谱面背景皮肤」是"放一张自己喜欢的"观看偏好，保持应用级。**两张背景层级语义相反，勿统一** |
| 自定义图的 `fit`（cover / contain） | 工程级 | 同上 | 跟着那张图走 |
| 场地皮肤包（轨道） | **应用级** | `settings.preview` | 等同音符速度 / 镜向，是"我看着舒服" |
| 亮度（压暗） | **应用级** | `settings.preview` | 观看偏好 |

**优先级**：工程有自定义 → 用它；否则 → 应用级内置包。

**选中内置包 = 停用但保留**（不删除）：该工程切回内置包（`useCustom = false`），自定义图**留在工程里**，再点第一格即切回、**不用重传**。真正从工程删除只由「清除」触发。这样网格选中态自洽：第一格高亮 ⇔ 正在用自定义图。

## 4. 自定义槽位与存储

- **「自定义」是整个网格的第一格**，未上传时是「+ 自定义」上传入口，上传后是可点选的缩略（可清除）。"背景来源"只有一个选择器 —— 不存在"选了内置包却被自定义图盖住"的隐式优先级。
- **图片与视频共用同一个槽位**（一格只放一个，换格式 = 替换）。两个槽位会再引出一次"谁优先"的隐式优先级，而 §3 刚把它消灭掉。
- **视频背景只取画面**：自带音轨**一律丢弃**，不给开关 —— 导出音轨的来源已固定是 BGM + 键音，混入第三方音轨会和它们打架，而我们只有主音量 / SE 音量两个旋钮、没法单独调它。
- **视频开场第③段画视频首帧（静止，不播放）**，到第④段（谱面 0 秒）才随播放时钟走 —— 开场段是"纯前置、绝不与歌曲前奏重叠"，视频在这 1.0s 里动起来等于暗示歌曲已经开始。
- **视频的时长口径（比谱面短 / 长怎么办）待定**，要等离屏逐帧 `seek` 的可行性实测（"循环"意味着反复 seek，成本直接受 seek 开销影响）。
- 存储**照封面 / 音频加第 4 个工程二进制**：浏览器内联 Blob（IDB `bangdream.chartproject`）、Electron 落 `projects/<id>/` 下固定文件名；`xxxName` 记原始文件名供 UI 显示；**复制工程带走**（与封面同口径）；**清除 = 从工程删除**（不留空壳字段）。无工程 / 作用域失效时上传入口不可用（对齐音频页空态），入口复用预览页已有的 `ScopePicker`。
- 体积上限：图片沿用 **20 MiB**；视频**等 44 的实测报告再定**（先按 100 MiB 试）。否决"只存本机引用"（浏览器端跨刷新必然失效，拿不到 File 句柄）与"仅当前会话有效"（与"工程绑定"直接冲突）。
- 取景：**沿用内置同一取景矩形**（`BACKGROUND_RATIO`），给 `cover`（默认，铺满裁切）/ `contain`（完整显示，两侧露 `SIM_FALLBACK_BG` 兜底底色），与画布那套 `fit` 同名词同语义；不做"拉伸铺满"。

## 5. 应用范围与不覆盖范围

- **统一生效**：表演背景（内置包或自定义）对**实时预览 + 视频导出 + 视频开场第③段**一起换 —— "导出物应当和我在预览里看到的一致"。
- **亮度**：对所有背景来源统一（内置包 / 自定义图 / 视频）；**只压暗**（0–100% 黑罩，默认 0）、不做提亮（提亮会洗白画面，刚需是"亮背景压暗以便看清音符"）；**只压背景层**，不动轨道与音符（动轨道会让判定线一起糊掉）。
- **不覆盖**：画布「谱面背景皮肤」（仍是画布那一套、不进仿真场）、静态预览面板与谱面图（明确不画背景）、场地图 / 判定线的几何比例（`FIELD_IMAGE_RATIO` / `PLAY_LINE_RATIO` 不变）。

## 6. 皮肤显示名（2026-10-22 修订）

用户看不到有意义的名字（音符皮肤显示 "Skin 00"、轨道/背景直接显示包 ID `skin_maid` / `collabo23_summer_g`），本口径定显示名从哪来。事实依据：`docs/research/skin-naming-sources.md`（2026-10-22 实测）。

| 项 | 口径 |
| --- | --- |
| 命名源分层 | **官方命名 API > 社区 fallback > 包 ID**。官方 API = Bestdori `/api/skin/{notes,directionalFlicks,lanes,backgrounds}.all.3.json`（实测仅 v3 存在；结构 `{ "<序号>": { assetBundleName, skinName: [jp, en, tw, cn, kr] } }`；directionalFlicks 的 assetBundleName 不带前缀，消费方拼 `directionalflick`）；无官方名的主题包用 Sonolus 社区清洗规则（剥 `skin`/`skin_` 前缀 → 按 `_` 分词 → 首字母大写：`skin_maid`→Maid、`collabo23_summer_g`→Collabo23 Summer G） |
| 中文取名 | 官方 **cn 服条目优先**（`按键条皮肤00` / `Poppin'Party的按键条皮肤` / `MyGO!!!!!的按键条皮肤`），回退 en → jp；音符 TYPE1–7 五服一致，无需翻译 |
| 背景包本地化（2026-10-22 二轮修订） | 官方**背景名五服同值日文**（skin00–04 / skin_teamlivefestival 的 en/tw/cn 槽都是日文值，不出本地化条目）→ 按"不出原始日文"的用户反馈，这 6 个包的 zh/en 名走 **i18n 消息表** `preview.display.bgName.*`（照键音先例：无 API 本地化只能手写）；官方将来给出异于 jp 槽的本地化条目时**以官方为准**（无需改代码）；无官方名的主题包仍社区 fallback（Miku / Practice） |
| 网格 tooltip 与展示序（2026-10-22 二轮修订） | 缩略格 tooltip **只留显示名**（行标签已说明类别，包 ID 对用户无意义——原 `${full} · ${显示名}（${pack.id}）` 的三段式废止）；展示序 = **编号包（skin00–skin14）在前、主题包在后**，默认包 `skin00` 落在第一格（应用侧展示策略，取件侧清单仍只决定"有哪些包"） |
| 音符 TYPE 错位 | **照官方显示**（skin05=TYPE7、skin06=TYPE6，与游戏内一致，不按包号重排） |
| 产出形态 | 命名映射由**素材取件侧**拉 API、随 gen 注册表一起生成进快照（照 `noteSkinRegistry.gen.ts` / `simAssetPacks.gen.ts` 先例，与二进制同版本）；应用侧**只查表、不联网**（ADR-0011 §2） |
| 设置兼容 | 设置仍存**包 ID**，显示名纯查表 → 老设置零迁移；快照未带名字段时回落包 ID（灰度安全） |
| 键音 | **不在本口径内**：键音无官方命名 API，维持「官方键音 00」手写 i18n 名（用户 2026-10-22 定：三类皮肤先行） |
| 辨识分工 | 编号类官方名（TYPE1–7 / 按键条皮肤00–04）信息量≈编号，辨识主力仍是缩略图（§1 网格形态不变） |

## Considered Options

- **成对整包预设**（照音符皮肤「整包预设」）：否决 —— 上游两类包并非一一配对，成対意味着砍掉不配对的包或给它们硬凑搭档。
- **人工给每个包起中文显示名**：2026-10-11 否决（33 个包里 15 个是 `skin01`…`skin14` 编号包，起不出名；且要多维护一份清单）——**2026-10-22 部分重开**：官方命名 API 实测存在，且恰好命名了 15 个编号轨道包（8 个乐队名），“起不出名”的理由不再成立；重开后定案为 §6 分层命名，**仍不人工起名**——官方名 + 社区 fallback 已覆盖全部包，无需自维护映射。
- **自定义表演背景做成应用级单张**（照画布那张）：**被用户否决** —— 用户认为它是"与谱面工程绑定"的，主题属于这首歌。本 ADR §3 的混合模型是这一否决的结果。
- **多选服务器同步**：否决 —— 体积 ×5 而用户无感。
- **拆成"取件票"与"消费票"两张**：用户否决 —— 素材取件是内部实现细节，**不在票名与文档里点名那个仓**，一律说"素材取件 / 同步"。

## Consequences

- `tests/unit/preview/video/SimAssets.test.ts` 现有三条断言锁死了硬编码 URL，本 ADR 落地必然改红 → 改为"按包 ID 解析"并覆盖两种 `liveBG` 命名。
- 新增一个工程级二进制要动 6 处（`ChartProject` 字段 / `RECORD_FIELDS` / Blob+Present+Intent / wire payload / Electron backend / `electron/projectStore.cjs`），不是加一个字段的事。
- 安装包体积 +≈10 MB（背景策展 20 包主图）+ ≈2 MB（轨道全量）。
- 视频背景（票 44）排在静态自定义背景与亮度之后，**实现前先做离屏逐帧 `seek` 的可行性实测**；不过关的退路 = 导出只用首帧 / 禁止带视频背景导出。
