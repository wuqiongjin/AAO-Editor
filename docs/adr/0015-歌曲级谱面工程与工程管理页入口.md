# ADR-0015：歌曲级谱面工程与工程管理页入口

- **状态**：Accepted（定案于 grill-with-docs，2026-09-26）
- **范围**：谱面工程的数据单位、应用启动落点、页面与谱面工程的关系（当前工程 §3 / 作用域 §6）、已上传谱面的可编辑性
- **修订**：[ADR-0003 §2](./0003-工作台UI与配置系统.md)（入口直达工作台）、[ADR-0005 §2/§3](./0005-显式谱面长度与谱面工程持久化.md)（1 工程 = 1 份谱面代码；多谱面留后续）、本文 §3（2026-09-28 issue 20：当前工程跨刷新恢复；issue 15：音频页不再 ensure；issue 23：改写当前工程与进入工作台拆开、创建/复制落详情页）、**新增 §6**（2026-09-28 issue 22 / 15：页面作用域）、本文 §6 二级 `chartId` 落地（2026-09-30 chart-preview 02 / ADR-0016 §4）、本文 §4（2026-10-26 bestdori-integration 51：已上传只读切开谱面本体 vs diff / level / tags）、本文 §4（2026-10-28 bestdori-integration 54：已发谱面入口文案改动作词「更新」）
- **关联**：[chart-projects 01 定案票](../../.scratch/chart-projects/issues/01-谱面工程管理与启动流程定案.md)（逐问对话存档）、[ADR-0011 §3](./0011-Bestdori集成与本地客户端网络素材边界.md)（内置登录直传）、`docs/research/bestdori-community-upload.md`（帖子发后不能改谱、不能删）

## 背景

ADR-0003 §2 取消上传页后，应用一打开就是工作台；ADR-0005 把谱面工程定义为「一份谱面代码 + 谱面时长 + 音频」，并把多谱面留给 issue 26。实际创作里，同一首歌往往有多个难度共用一份音频，用户还需要一个地方看到自己的全部作品、它们做到哪一步、哪些已经发到 Bestdori。Bestdori 一帖只对应一个难度，帖子发出后不能改谱、不能删。

## 决策

### 1. 谱面工程是一首歌的容器

谱面工程 = 工程信息 + 音频 + 封面 + 谱面时长 + 1..n 张谱面。同一工程的谱面共享音频与谱面时长；音频不同就是两个工程。每张谱面带谱面名称、难度、等级、完成标记、上次修改时间和至多一条上传记录。同一工程内难度可重复。不单独存创建时间。

工程信息全部可选（工程名称、歌手、曲目来源、封面）。没有独立的「歌名」字段：Bestdori 的 `title` 就是谱面名称，未填时动态跟随工程名称。

**否决**：一张谱面一个工程、列表里按歌分组（B）。同曲多难度时音频会被复制多份，改音频要逐个工程改，而 Bestdori 的上传元数据（歌手、曲目来源、封面）本来就是歌曲级的。

### 2. 启动落在工程管理页

工程管理页是应用壳导航的第一项，也是启动默认落点，快捷键 `⇧⌘0`；其余页面快捷键不变。它是应用壳里的应用页面，不是应用壳之外的启动页。页内两层视图（2026-09-26 prototype 选定）：默认**工程启动台**（B），点进一个工程后是**工程详情**（C）。不拆成两个应用页面。

**否决**：应用壳之前的独立启动页（Unity Hub 式）。切工程要先「关闭工程」，也无法复用页面保活与切页快捷键。**否决**：只用列表（A）或只用主从（C）当启动首屏——C 信息密度适合详情，不适合刚打开软件。

### 3. 工作台只有一个当前工程

工作台同一时刻只打开一个当前工程，切工程回工程管理页。不做多工程标签页，CONTEXT「工程文档标签」废弃。

不经工程管理页直接进工作台时，打开**最近打开过的未完成工程**（工程未完成 = 至少一张谱面未完成）；一个未完成工程都没有时自动新建「未命名工程」并立即落盘。这样最多只会存在一个自动新建的空工程。

**修订（2026-09-28，issue 20）**：当前工程跨重启**记住**——`{ projectId, chartId }` 落在本机独立存储（不进设置对象、不随配置导入导出）；启动即恢复，进工作台**直接回到它**（即使已完成 / 只读）。只有没有可恢复项时（从未进过工作台，或记住的工程已不存在），才走上面「最近打开过的未完成工程 → 新建未命名」的规则。删除当前工程会连同记住项一起清掉。

**补充（2026-09-28，issue 15）**：进**音频页**不再 `ensure`——音频页无当前工程时音频区块空态（先去工程管理选一个），不因进页面而新建 / 打开工程；「最近未完成的工程 → 否则新建未命名」的规则只归工作台。

**补充（2026-09-28，issue 23）**：**改写当前工程**与**进入工作台**是两件事，不得再绑成一个动作。原 `openWorkspace` 把 `open(id)` 与 `setActivePage('workspace')` 写在一起，导致"新建工程"被迫"打开工作台"——而空白新建的谱面歌曲/等级/封面都没填，谱师被推进空工作台。现拆为：

- `setCurrent(id, chartId?)`：只改写当前工程（`flushPersist` → `open` → `notifyCatalogChanged`），**不跳页**；
- `enterWorkspace(id, chartId?)`：`setCurrent` + `setActivePage('workspace')`。hub 的 hero / 卡片播放 / 详情「在工作台打开」/ 谱面行「打开」/ 列表双击这 5 个**显式跳页**入口全走它。

**创建与复制工程统一落点**：留在**工程详情页**（视图切到新工程）+ 新工程成为**当前工程**，都不跳工作台。防回潮：`setActivePage('workspace')` 全仓只允许出现在 `enterWorkspace` 一处（静态断言看守）。

**工程详情左栏分栏**（同批）：宽度 `clamp(220, 300, 420)`、默认 300、双击复位，落 `settings.layout.projectList`。**不复用工作台的面板分栏机制**——工作台那套绑 `UIProvider`（Provider 级 state + Provider 内 mousemove effect + 内联 CSS 变量），详情页是 CSS Grid；且两者夹取范围本质不同（工作台左右对称、详情是导航列表不该占半屏）。出现第三个可拖拽分栏时再抽。

「当前工程」这个概念的**存在感**（到处是徽标、切换入口只在"进工作台"、四种文案并存）是否要让用户感知，留待 issue 24 单独 grill。


「抄」其他谱面的需求由剪贴板承担：切换工程 / 谱面时不清空剪贴板。长期复用的配置由片段收藏承担（basic-editor issue 164）。

**否决**：工程标签页（B）。Editor、音频会话、持久化、快捷键分发、播放编排现在都是单例，多开几乎要重写；每多开一个工程多占一份解码音频（3–4 分钟立体声约 60–85 MB）与瓦片缓存。「抄」只需要读和复制，不需要同时编辑两份。只读参考画布（A2）也被否决：看别人的谱不如直接上 Bestdori。

### 4. 已上传的谱面只读

谱面状态由完成标记与上传记录派生：有上传记录→已上传；否则标了完成→已完成；否则未完成。已上传的谱面**谱面本体**只读：可选中、复制、播放，不可改音符；每张谱面至多上传一次。要改谱或再传，就在同一工程内复制谱面（副本不带状态），改副本、传副本。

**修订（2026-10-26，bestdori-integration 51）**：只读切开「谱面本体」与「帖子还能改的元数据」。平台 `POST /api/post/edit` 只收 `diff` / `level` / `tags`；标题、歌手、曲目、描述、谱面代码发后都不能改。本地：难度徽标与谱面信息弹窗对已发谱面继续锁；难度 / 等级 / 标签只从工程详情的**更新**弹窗写，且 `post/edit` 成功后才对齐本地。内容警告 / `rating` 是社区故事字段，谱面帖不发、不做。

**修订（2026-10-28，bestdori-integration 54）**：已发谱面的**入口文案**从状态词改为动作词——谱面行按钮「更新」、弹窗标题「更新谱面」（未发态对应「发布」/「发布谱面」）。「已发布」这类状态由行内「已上传」徽标承担，不占按钮的语义位。语义本身（谱面本体只读 vs diff / level / tags 可改）不变。

工程里只要有一张已上传谱面，共享的音频与谱面时长就锁定；要换音频，复制工程（副本不带任何谱面状态）或新建工程。

**否决**：允许继续编辑谱面本体并显示「已上传 · 有改动」。Bestdori 上的帖子改不了谱，状态会与帖子脱节，用户也容易误改原件。

### 5. 不写旧数据迁移

产品未对外发布。新存储结构不读取、不删除旧的 `default` 工程；issue 25 的 IndexedDB → 文件后端迁移代码一并移除。需要保留当前谱面的，升级前导出谱面代码、升级后从谱面代码新建工程。

### 6. 页面作用域：页面可临时作用于非当前工程

（2026-09-28 新增，issue 22；修订 §3 与 §后果 的口径。）

**问题**：§3 定了工作台只有一个当前工程。但有些页面天然希望从**工程管理页**直接进去处理某一首歌的东西——音频页要能改任意工程的音频，未来的完整谱面预览 / 视频预览也要绑到某个工程上——而**不该切走工作台正在编辑的当前工程**。此前"页面作用于哪个工程"没有独立概念（隐含等于当前工程），于是只剩两条路：要么工程详情不能改（点进去也没用），要么跳过去就把当前工程切了（用户丢掉原来的编辑上下文）。

**决策**：引入**作用域（scope）**——某个页面此刻**作用于哪一个工程的临时指向**（数据上即 `projectId`，将来可扩第二级 `chartId`）。它与「当前工程」是**两个独立概念**，术语上不得混用（不得用「当前」表示作用域）。

- **入口决定 scope，不持久化**：应用壳左栏的页面入口（如「音频」`⇧⌘2`）**先清 scope 再激活**——语义 = 去当前工程的音频；带 scope 的跳转**先写 scope 再激活**。因此"回到当前工程" = 再点一次那个入口，**不需要**一个"回到当前工程"的按钮；也不"粘住上次访问"（那会让全局入口的含义随上次访问漂移）。
- **能力不缩水**：scope 指向任意工程都可**读**（工程名 / 音频名 / 时长 / 锁状态）与**播**；「换音频 / 清除 / 改时长」这类**改变共享资源的动作**按 `projectId` 参数化，并由 §4 的锁再挡一次（纵深防御）。锁定的工程**可以被选为作用域**——锁锁的是动作，不是看和听。
- **失效回落**：scope 指向的工程不存在（被删）→ 回落当前工程 + 一条提示；当前工程也没有 → 该页的"作用域空态"（与 §3 补充的"音频页不 ensure、无当前工程时空态"同源）。"无 scope"与"scope 失效"收敛为同一个态。
- **不写 URL**：与 [ADR-0007 §8](./0007-应用页面壳与内容页壳规范.md)「切子类别不写 URL」同源，不另立规则。
- **只做工程一级**：二级（工程 + 谱面）在 API 形状上留位，但要有第二个真实消费者才做出来。

**修订（2026-09-30，chart-preview 02 / [ADR-0016 §4](./0016-谱面预览与游戏仿真导出.md)）：二级 `chartId` 落地**。预览页就是上文要的"第二个真实消费者"，`pageScope.chartId` 由"只留形状"转正——带 `chartId` 的跳转精确到**哪一张谱面**：

- **解析**：`pickScopedChartId`（`src/layouts/pageScope.ts`）= 作用域二级（仍属于该工程时算数）?? 该工程就是当前工程则取其当前谱面 ?? 首张。
- **失效回落**：作用域二级指向的谱面被删 → **只清二级**、保留工程级作用域 + 一条提示（工程级失效仍照上文"整条清掉"）。
- 作用域条仍只管工程（上文"工程详情的音频行…带作用域的跳转入口"这一族口径不变）：**谱面级定位是预览页自己的事**，页面内自带谱面切换器。
- 两个入口都带 scope（照上文"先写 scope 再激活"）：工作台「预览当前谱面」带 `{ projectId, chartId: 当前谱面 }`；工程详情谱面行「预览」带 `{ projectId, chartId: 该行 }`。

**否决**：写进 [ADR-0007](./0007-应用页面壳与内容页壳规范.md)（应用页面壳）。0007 规范的是内容壳的**形态**——compound component API、侧边索引、几何自适应、3 条硬约束、新页 4 题决策清单；其 §10 边界明确把"每个页面内部的内容"划在范围外。作用域与布局无关，它是「页面与谱面工程的关系」，属 §3「工作台与当前工程的关系」的同族推广（从"工作台"推广到"任意页面"），放 0007 会逼它破自己的边界。
**否决**：作用域只读 + 一个「以此工程为当前工程并编辑」的按钮。省掉参数化写路径、语义最干净，但用户要的正是"不切当前工程也能改"。

## 后果

- 存储结构从「一个工程一份谱面代码」改为「一个工程多张谱面」；ADR-0005 §6 的「id → 工程记录」键值表保留，记录内部结构变化。
- 音频页是工程音频的**唯一管理入口**（换音频 / 清除只在音频页，工程管理页不另做导入）；它**默认作用于当前工程，可临时作用于其它工程**（§6 作用域），工程详情的音频行只读展示并给一个带作用域的跳转入口。谱面代码弹窗与导出作用于当前选中的那张谱面。
- 封面在工程信息里上传；启动台封面墙读它。上传流程只补缺字段和发帖专用项。
- 一个工程至少保留一张谱面，不能删掉最后一张。
- 上传链路（登录、清洗、发帖）仍归 bestdori-integration；工程管理页只展示上传记录并作为上传入口。
