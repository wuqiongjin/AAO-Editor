# ADR-0025: 伴生移动端模拟器 AAO Player 的架构选型与生态边界

- **状态**：Accepted（grill-with-docs，2026-11-26；用户逐问拍板 Q1–Q17；**方向与架构边界定案，尚未建仓实现**）
- **背景**：AAO Editor 的「仿真场」（ADR-0016）仅负责桌面端只读动态预览与视频导出，无法满足玩家在手机与平板上实机打歌、以及谱师改谱后即时真机测试的需求。社区主流工具 Sonolus 内置广告多、体验受限，且无法支持未来 AAO Editor 生态的扩展谱面规则。需要在立项前锁定伴生模拟器的产品边界、分发与版权合规策略、跨端技术栈、核心判定口径，以及与 AAO Editor（含未来移动端形态）的联动契约。
- **结论**：定名 **AAO Player**（中文领域称「**AAO 模拟器**」，独立仓库 `AAO-Player`）；同步覆盖 Android（直装 APK）与 iOS（未签名 IPA，暂不走应用商店/TestFlight），手机与平板一等适配；安装包零内置版权素材，走「原创默认包 + 用户外部**资源源**」模式；技术栈选定 **React Native（Expo Prebuild）UI 壳 + Rust 跨端打歌核（`wgpu` + `Oboe`/`CoreAudio` + 原生触控）**；底层引入**谱面编译管线**与解耦的**视觉流速轴**，承接滑条尾接方向键、基于音符自定义字段的变速/时停等未来 AAO 生态规则；V1 提供 Bestdori 官方/社区谱浏览与离线缓存、基础练习、本地成绩、延迟校准及与 AAO Editor 的**局域网测谱**联动，并预埋 Deep Link / 本地谱面工程包入口服务未来移动端编辑器互通。
- **变更触发**：改动产品/仓库边界、更换混合架构大路线（RN UI 壳或 Rust 打歌核）、调整版权素材零内置原则、修改与 AAO Editor 的联动契约或扩展规则兼容红线时，须先更新本文件并经用户确认。
- **关联**：[ADR-0001 音符覆盖与滑条规则](./0001-音符覆盖与滑条规则.md)、[ADR-0010 负数 BPM 与倒流区](./0010-负数BPM与倒流区.md)、[ADR-0011 Bestdori 集成与本地客户端网络素材边界](./0011-Bestdori集成与本地客户端网络素材边界.md)、[ADR-0014 宽松谱面代码源数据与画布投影](./0014-宽松谱面代码源数据与画布投影.md)、[ADR-0016 谱面预览与游戏仿真导出](./0016-谱面预览与游戏仿真导出.md)；配套技术调研与复用清单见 [docs/research/aao-player-architecture-and-reuse.md](../research/aao-player-architecture-and-reuse.md)。

## 1. 产品身份与仓库边界

- **独立伴生产品 + 独立仓库**：英文定名 **AAO Player**（应用标识建议 `com.aao.player`），中文领域术语统一为 **「AAO 模拟器」**，与编辑器内只读的「仿真场」严格区隔。独立仓库 `AAO-Player`。
- **不合并进本仓库（不转 Monorepo）**：编辑器的桌面发布链路与移动端的原生/Rust 工具链、发版节奏、受众群体完全不同；两仓通过协议契约协作，TS 协议代码初期按规范轻量同步，待协议稳定后再抽独立共享包（如 `@aao/protocol`）。

## 2. 目标平台、分发与平板适配

- **双端同步 + 平板一等公民**：同步覆盖 **Android + iOS**，并把 **iPad / 安卓平板** 视为核心使用场景（音游主力设备），而非手机界面简单拉大；**全应用锁定横屏（支持左右 180° 自动翻转）**，避免竖屏与横屏切换引起的原生视图重建闪烁。
- **社区免上架分发**：因音游社区形态与版权风险考虑，暂不上架 Google Play / App Store；Android 以直装 APK 分发，**iOS 现阶段优先提供未签名 IPA**（暂不走 TestFlight；经 macOS CI 无证书打包）。
- **画面与轨道适配（覆盖手机 20:9 与平板 4:3/3:2）**：表演背景铺满全屏（cover），核心轨道与判定线以画面高度为基准按比例居中，并提供**轨道宽度缩放、判定线纵移、音符大小**可调；否决「全机型强制 16:9 contain 留黑边」。

## 3. 版权素材与「资源源」策略（回应 ADR-0011 §4）

- **安装包零内置版权素材**：AAO Player 发布包内仅携带一套干净的 AAO 原创默认皮肤、舞台、判定字、特效数字与基础键音，彻底避免在面向大众分发的移动端安装包中直接捆绑官方版权图集与音效。
- **外部资源源协议（V1）**：用户可在 App 内输入外部**资源源** URL（`manifest.json` 清单，列出 **音符皮肤 / 场地 / 表演背景 / 判定字 / 特效与数字 / 键音** 6 类资产及 SHA-256 哈希，支持增量拉取与切换）或直接导入本地 `.zip` 资源包。AAO Editor 侧可提供导出脚本，将开发期 `assets-sync` 快照一键转为标准资源源用于开发测试。
- **Sonolus 格式兼容延后**：V1 只做简洁可控的 AAO 清单协议，V2 视社区需求评估 `.scp` 等外部格式转换/导入。

## 4. 核心技术栈：混合架构（React Native + Rust 跨端打歌核）

- **UI 壳层：React Native（Expo Prebuild / TypeScript）**
  - 承载选曲、Bestdori 官方/社区谱浏览、本地离线曲库、资源源管理、设置页、成绩结算与局域网测谱管理。
  - 直接承接 TypeScript 生态，可复用 AAO Editor 的 Bestdori 协议映射（`src/community/bestdori/`，替换原生 HTTP transport 即可无 CORS 直连）、谱面类型与 i18n 习惯，并与未来「AAO Editor 移动端」保持技术亲和性。
- **打歌引擎核：Rust（`wgpu` 渲染 + `Oboe`/`CoreAudio` 低延迟音频 + 原生多点触控）**
  - 进入打歌时切换至原生全屏视图（Android `SurfaceView` / iOS `MTKView`），由**同一份 Rust 核心**统一驱动 120Hz/144Hz 渲染、原生触控事件时间戳采集、判定状态机与低延迟音频混音。
  - **热路径零 JS、零 GC**：渲染与判定循环完全隔离在 Rust 线程，不经过 React Native JS 线程，保证 Android/iOS/平板判定 100% 一致，且未来可将同一 Rust 核心编译为 WASM 反哺 AAO Editor 桌面/Web 端试玩。
- **被否决路线**：
  - *纯 WebView / Capacitor 打歌*：Android WebView 触控延迟、JS GC 掉帧与碎片化无法达到替代 Sonolus 的硬核手感门槛。
  - *RN / Flutter 壳 + 嵌入式 Godot / Unity 视图*：双端原生生命周期销毁/重建、Metal/Surface 切换与音频焦点冲突风险极高，工程维护成本失控。
  - *纯 Unity / Godot 单引擎*：无法复用 TS 社区与规则层，外围社区列表/平板 UI 体验及与未来移动端编辑器的融合度弱于 RN 壳。

## 5. V1 功能范围与核心游玩口径

- **V1 必含闭环**：
  1. 标准 BanG Dream 7 轨多点触控打歌（Single / Flick / Skill / Slide / Long / Directional / SP 绿条）；
  2. 判定窗口严格对齐 `sonolus-bandori-engine` / 官方实机标准；滑条采用「轨道区域占领式」（允许换指/多指接力，左右留约半轨容错，SP 绿条按带体插值轨位连续追踪、隐藏点不计 combo）；
  3. 音画偏移校准（听拍点击自动测算 + 手动 ms 微调 + 独立打歌键音开关/音量，兼容蓝牙耳机场景）；
  4. 流速、音符大小、轨宽、镜像、表演背景与皮肤包切换；
  5. Bestdori 官方谱与社区谱在线浏览 + **本地持久化缓存曲库**（支持离线游玩、本地收藏、可调缓存上限与清理）；
  6. 基础练习模式（倍速、指定时间点起播、锁血/无敌开关）；
  7. 本地成绩存档与 FAST/SLOW 分布统计；
  8. AAO Editor **局域网测谱**一键推送。
- **极端自制谱边界口径**：
  - **倒流区（负 BPM，ADR-0010）**：播放时钟单调推进，音符按折返视觉轨迹运动并在真实秒位正常判定；
  - **越界轨（`lane < 0` 或 `lane > 6`，ADR-0014）**：触控判定区向外延伸至屏幕左右边缘，确保贴边可击打、不锁死 FC/AP；
  - **负 beat 击打物**：开局即过线，不渲染、不扣血、不强制判 MISS。
- **明确划出 V1**：游玩回放录像与成绩分享图（V2）、Bestdori 账号登录/点赞收藏同步（V2）、卡组技能/Fever/Live2D 养成演出（长期不做）。

## 6. 跨端联动边界（局域网测谱 & 未来移动端编辑器）

- **局域网测谱（V1）**：电脑端 AAO Editor 启本地局域网服务（二维码配对 + 同网段 mDNS 发现），通过局域网 HTTP + WebSocket 一键推送当前谱面、音频（按内容哈希去重缓存，改谱重推不重复传输音频）及可选的当前播放位置/标记点，手机秒载入试玩。底层保留 WebSocket 双向通道，为 V2 手机回传判定偏差/打标点到编辑器画布预留扩展。
- **移动端 App 间联动（V1 预埋）**：AAO Player 从 V1 起注册自定义 URL Scheme / Deep Link（如 `aaoplayer://`）并支持本地谱面工程压缩包（`.aaopkg` / `.zip`，含谱面 JSON + 音频 + 封面 + 元数据）导入，为未来「AAO Editor 移动端」离线一键拉起试玩并一键返回铺平通道。

## 7. 扩展音符规则与双规则集切换（滑条尾方向键与视觉变速）

- **双规则集切换**：AAO Player 支持在 **「AAO 规则」（默认）** 与 **「Bestdori 社区规则」** 之间切换（全局偏好 + 单谱切换）。切换为「Bestdori 社区规则」时关闭所有扩展解释，确保任何存量社区谱 100% 可回退兼容；未利用扩展机制的常规官方/社区谱在两套规则下表现一致。
- **架构原则**：不破坏常规 Bestdori 存量官方/社区谱面，不依赖破坏社区发帖校验的私有顶层 `type`。
- **谱面编译管线（Chart Compile Pass）**：原始 Bestdori JSON 按所选规则集经独立编译阶段转为引擎内部可判定实体表：
  - **滑条尾部方向键**：在「AAO 规则」下识别与 `Slide` 尾端点落在同一 `(beat, lane)` 的 `Directional` 音符，自动融合为「按住绿条至末尾顺势按方向划出」的复合判定（编辑器侧放宽覆盖规则归后续 ADR-0001 修订）。
  - **音符自定义扩展字段**：利用 Bestdori 保留合法音符（如 `BPM`、`Single`、`Slide` 等）额外自定义字段的特性，未来通过给既有音符附加 AAO 命名空间字段承载新规则（如 `BPM` 音符携带视觉流速倍率或时停语义），在「AAO 规则」下由编译管线按规则版本解释，旧版非 AAO 模拟器（或切至「Bestdori 社区规则」）自动无视并优雅降级。*（具体字段名与放行边界须在对应规则立项时经 Bestdori `POST /api/post` 实测确认。）*
- **视觉流速轴（`TimeScaleTimeline`）与拍-秒轴（`BpmTimeline`）解耦**：引擎渲染与接近计算基于积分后的视觉距离而非直接读拍-秒差；默认全谱恒定 `1.0×`，标准 BPM 变化不改变下落速度，显式携带扩展变速字段时支持任意倍率、突变与 `0.0` 真时停。
