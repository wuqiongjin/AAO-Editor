# ADR-0021: 应用更新

- **状态**：Accepted（2026-10-19 与用户拍板；2026-10-25 修订 §2 失败提示与 §3 下载源——grilling 定案，见 release-pipeline/16）
- **背景**：正式产品是已安装的 Electron 包，经 GitHub Releases 分发，但应用内看不到应用版本、也不能换掉当前二进制。设置页只有外观与存储。需要定「查」和「装」的边界，避免做成设置说明文字或国内第二源空壳。2026-10-25：国内副本已存在，国内网络检查 GitHub 经常失败，第二源不再是空壳。
- **结论**：已安装的正式产品做应用更新；关于页展示应用版本；自动检查进设置对象；下完请重启。发版原址仍是 GitHub 正式 Release；关于里可选 **下载源** GitHub（默认）或 CNB（同一 tag 的可达副本）。界面不出现「更新源」。
- **变更触发**：改下载源（含默认、是否静默 fallback、CNB 是否必须同一 tag 字节副本）、把自动检查挪出设置对象、静默换掉正在跑的进程、或做强制/永不更新，须先改本文件并经用户确认。
- **关联**：[CONTEXT.md](../../CONTEXT.md)（应用版本 / 应用更新 / 关于 / 检查更新 / 自动检查 / 下载源）；[ADR-0022](./0022-发布链路拓扑.md)（CNB 副本须提供匿名 generic feed）；[ADR-0011](./0011-Bestdori集成与本地客户端网络素材边界.md) §1（Electron 为正式产品）；[ADR-0019](./0019-本地日志与诊断包.md)（诊断包含应用版本；发布渠道 GitHub Releases）。

## 1. 能力与落点

- **应用更新** = 用更新的发行替换当前已安装应用。只属于已安装的正式产品。
- **应用版本** = 用户可见的产品 semver，不是设置对象的 `schemaVersion`。
- 设置内容页新增侧边 **关于**：展示产品名与**应用版本**。**检查更新**、**自动检查**与**下载源**只在已安装包出现；浏览器、静态演示、未打包 Electron 只展示应用版本（导语不承诺下载/重启）。
- 不用「版本更新」（会和 schema、发行说明搅在一起）。界面与 toast 不用「更新源」（开发者文档可写 update source）。

## 2. 检查与安装

- **检查更新**从关于发起。**自动检查**默认开，只在启动做一次，一次运行不轮询；关掉只停启动那一次，不拿掉检查更新。
- 自动检查**写入设置对象**，导入/导出带走。应用版本、已下载的安装包、**下载源**不进 JSON（下载源是本机网络约束，见 §3）。
- 没有「永不更新」，没有「跳过此版本」。
- 发现新发行后后台下载；进度只写在关于，不另开进度窗。下完用弹窗壳请重启（写清新版本与当前；有发行说明则附上）。可**稍后**（关弹窗继续用，自己关窗口不会装上）。包已就绪时，关于该行变成**立即重启**，不再并排留检查更新。
- **稍后不是跳过下次检查。** 下次启动若自动检查仍开，仍会再查一次发行：还是已下的那一版就再请重启；其间又发了更新的正式版，就改下新的再请重启。关掉自动检查则启动不查、不弹；关于里仍可手动检查。
- 手动检查失败或已是最新：toast，不在关于行里写终态。网络 / HTTP 类失败（含启动自动检查、手动检查、下载中断）每次 toast 带一句换源提示，不断因「换源就能好」。文案：「检查失败，可能是网络问题，可以尝试将下载源替换为 {另一个源}。」校验失败、磁盘满、权限错误只说该原因，不提换源。

## 3. 下载源

- **发版原址**仍是 `github.com/wuqiongjin/AAO-Editor` 的正式 Release（electron-builder `publish`、忽略预发布）。CNB 不是第二条发版线：只允许更新到 GitHub 已 Publish 的同一 tag、同一字节副本（sha512 仍以 GitHub 构建产物为准）。
- 已安装包关于里一行 **下载源**：互斥选项 **GitHub**（旁标默认）/ **CNB**；短名；单色站点识别标（GitHub = lucide `Github`；CNB = 其公开品牌标的单色简化 SVG，与行内 lucide 同色同尺寸）。说明：「检查更新时从这里获取安装包。CNB 是国内副本，可能稍晚。」
- **默认 GitHub**（全体新构建同一默认，不按地区、不按「从哪下的包」）。可信优先；国内打不开 GitHub 用本行切换 + 失败提示，不把默认改成 CNB、不静默 fallback。
- 偏好只留本机：`userData/app-state.json` 字段 `updateSource: 'github' | 'cnb'`（缺省 / 非法 = `github`）。不进设置对象、导入导出带不走。浏览器无此字段。
- 改源只写本机，不立刻检查；下次手动检查或下次启动自动检查才走新源。**下载中禁止改源。** 已下完待重启时允许改（下次检查走新源；这次包与「立即重启」不动——同一 tag 字节）。
- 停在 CNB 且副本尚未跟上 GitHub 已 Publish 的版本：检查结果按「已是最新」，不每次解释时差（人不赶着更新；时差写在关于说明里）。
- 连不上 GitHub 的已装用户，应用内更新不到带本选择器的那一版：去 CNB 发行页手下一遍。README / 发行说明写一句。
- **选择器与 CNB generic feed 同一张票**：CNB 必须提供可匿名 GET 的 electron-updater generic 目录（`latest.yml` + 安装包 + 校验）。做不到 feed 就不合选择器——空壳正是 2026-10-19 否决第二源的原因。客户端按本机字段 `setFeedURL`；打包配置仍 `publish.provider: github`。

## 4. 否决

- 只显示版本 / 只打开浏览器到 Releases 页 / 应用内 changelog 阅读器。
- 自动检查留本机状态、不进设置对象（它是可搬运的工作习惯，与主题同类）。下载源相反：不进设置对象。
- 启动静默换包、强制更新、跳过此版本。
- 未打包开发态或浏览器上露出检查更新 / 下载源。
- 静默把失败的源换成另一个再查。
- CNB 独发或抢先发 GitHub 没有的版本。
- 界面文案写「更新源」。
