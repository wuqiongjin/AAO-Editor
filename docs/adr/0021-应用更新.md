# ADR-0021: 应用更新

- **状态**：Accepted（2026-10-19 与用户拍板）
- **背景**：正式产品是已安装的 Electron 包，经 GitHub Releases 分发，但应用内看不到应用版本、也不能换掉当前二进制。设置页只有外观与存储。需要定「查」和「装」的边界，避免做成设置说明文字或国内第二源空壳。
- **结论**：已安装的正式产品做应用更新；关于页展示应用版本；自动检查进设置对象；下完请重启。权威源这一期只有 GitHub 正式 Release。
- **变更触发**：改更新源、把自动检查挪出设置对象、静默换掉正在跑的进程、或做强制/永不更新，须先改本文件并经用户确认。
- **关联**：[CONTEXT.md](../../CONTEXT.md)（应用版本 / 应用更新 / 关于 / 检查更新 / 自动检查）；[ADR-0011](./0011-Bestdori集成与本地客户端网络素材边界.md) §1（Electron 为正式产品）；[ADR-0019](./0019-本地日志与诊断包.md)（诊断包含应用版本；发布渠道 GitHub Releases）。

---

## 1. 能力与落点

- **应用更新** = 用更新的发行替换当前已安装应用。只属于已安装的正式产品。
- **应用版本** = 用户可见的产品 semver，不是设置对象的 `schemaVersion`。
- 设置内容页新增侧边 **关于**：展示产品名与**应用版本**。**检查更新**与**自动检查**只在已安装包出现；浏览器、静态演示、未打包 Electron 只展示应用版本（导语不承诺下载/重启）。
- 不用「版本更新」（会和 schema、发行说明搅在一起）。

## 2. 检查与安装

- **检查更新**从关于发起。**自动检查**默认开，只在启动做一次，一次运行不轮询；关掉只停启动那一次，不拿掉检查更新。
- 自动检查**写入设置对象**，导入/导出带走。应用版本、已下载的安装包不进 JSON。
- 没有「永不更新」，没有「跳过此版本」。
- 发现新发行后后台下载；进度只写在关于，不另开进度窗。下完用弹窗壳请重启（写清新版本与当前；有发行说明则附上）。可**稍后**（关弹窗继续用，自己关窗口不会装上）。包已就绪时，关于该行变成**立即重启**，不再并排留检查更新。
- **稍后不是跳过下次检查。** 下次启动若自动检查仍开，仍会再查一次发行：还是已下的那一版就再请重启；其间又发了更新的正式版，就改下新的再请重启。关掉自动检查则启动不查、不弹；关于里仍可手动检查。
- 启动检查失败保持安静。手动检查失败或已是最新：toast，不在关于行里写终态。

## 3. 更新源

- 这一期只认 `github.com/wuqiongjin/AAO-Editor` 的正式 Release（与 README 安装包入口同一处），忽略预发布。
- **不做第二源、不做关于里的更新源选择器。** 国内打不开 GitHub 是真问题，但第二源必须是同一份发行的另一处可达副本。仓库当时还没有发版 CI，客户端双源会是空壳，镜像漂移或被投毒比「检查失败」更糟。

## 4. 否决

- 只显示版本 / 只打开浏览器到 Releases 页 / 应用内 changelog 阅读器。
- 自动检查留本机状态、不进设置对象（它是可搬运的工作习惯，与主题同类）。
- 启动静默换包、强制更新、跳过此版本。
- 未打包开发态或浏览器上露出检查更新。
