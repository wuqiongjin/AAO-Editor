# ADR-0024: 曲目署名与谱师署名的字段边界

- **状态**：Accepted（grill-with-docs，2026-11-15；用户逐问拍板 Q1–Q18；**已实现**，Canvas 成片待用户验收，见 `.scratch/chart-preview/issues/79-导出署名字段与谱师署名.md`）
- **背景**：用户要完善动态预览导出视频的**曲目信息片头**（游戏夹克画面 = 乐队 + 作词 / 作曲 / 编曲），并加「谱师」名称；静态预览也希望带谱师；且每一项都要像既有「乐队」一样能单独开关。票 39 已在绘制层预留 4 行 credits 与方案 B 版式，但工程 / 谱面数据层没有字段，`PreviewPage.tsx` 的 `credits` 恒 `null`；票 14 把「谱师姓名」明确留给后续票，该票一直未开。本 ADR 定这 5 项的术语、归属、来源、开关与文案。
- **结论**：「曲目署名」拆成**工程级 4 项**（乐队 / 作词 / 作曲 / 编曲）+ **谱面级 1 项**（谱师署名）；谱师只在**新建谱面时**取登录账号名落值、可手填；导入帖的 charter **不落盘**（票 32 保留）；动态片头 4 枚 + 静态头带 1 枚逐项开关、两组互不跟随；全部标签走 i18n。
- **变更触发**：改字段层级、默认来源、导入 / 发布边界、开关分组或导出物文案语言，都要先改本文件并经用户确认。

---

## 1. 术语：把「谱师」拆成两个概念

| 术语 | 定义 |
| --- | --- |
| **曲目署名**（Song credits） | 用户手填、只服务导出画面的一组创作者署名：乐队 / 作词 / 作曲 / 编曲 / 谱师署名。它不是一个配置项，也不是歌曲元数据或谱面统计信息。 |
| **谱师署名**（Charter credit） | 曲目署名里的一行：作者为本地谱面填写的展示名，可含多位谱师；随谱面走，不进上传 / 发布。 |
| **谱师**（Charter，既有词条） | 词义不变 = 谱面的创作者，Bestdori 侧 = 社区帖作者（`username`，展示用 `nickname`）。界面标签仍写「谱师」。 |

**为什么拆**：发布时 `generatePublishDescription` 已经会写一行「谱师：账号昵称」，`chart.upload.username` 也记账号；本地导出署名与平台身份同名不同物，联合创作时更不可能等同于单个账号。拆词只发生在词汇表与代码命名，界面文案不动。

## 2. 层级与填写入口

| 字段 | 层级 | 入口 |
| --- | --- | --- |
| 乐队（= 既有 `ChartProject.artist`） | 工程 | 「编辑工程信息」弹窗 |
| 作词 / 作曲 / 编曲 | 工程 | 「编辑工程信息」弹窗的「曲目署名」分区 |
| 谱师署名 | **谱面** | 「谱面信息」弹窗，单独一行 |

- **谱师为什么在谱面级**：一个谱面工程可含多张谱面，合作时各带自己的谱师；与「同一首歌可以有多篇社区帖、各带自己的谱师」同口径。
- 官方曲导入创建的工程署自己的名不与「官方曲只有歌手，不讲谱师」冲突 —— 那句说的是**官方谱本身**没有谱师。
- 复制谱面 / 复制工程**带走**署名；署名是工程数据，不进 `settings`、不随设置 JSON 导入导出。

## 3. 默认值：只在新建谱面时落值

优先级（**创建时**）：**手动填写 > 当时登录账号名 > 空**。

- 账号名取 `getCommunityAccount().getSession().account` 的 `nickname ?? username`（与发布描述、`toCharter` 同口径）。
- **落值而非动态回落**：会话在未登录、失效、离线校验没过、启动 `user/me` 未返回（`verifying`）时都是 `null`，登出会清；导出物必须可复现，不能把署名绑在网络 / 登录状态上。
- **升级前已有的谱面不补默认值，只能手填**；导出阶段绝不现取账号名。
- **从社区谱导入不带入 `PostCandidate.charter`**：导入是为了自己重新创作，署自己名。`.scratch/bestdori-integration/issues/32` 的「谱师名称同理不落盘」定案**保留、不翻案**（曾提议翻案，被用户否决）。
- 发布描述里的「谱师：账号昵称」与 `chart.upload.username` **本次不动**，与导出署名互不影响。
- 值形状 = **一个自由文本框**：联合创作由作者自己写分隔符（「A、B」/「A / B」），绘制层原样输出、不解析、不拆行；超长沿用既有截断。

## 4. 开关与绘制范围

- `settings.export.opening.items` 由 3 项扩到 **7 项**；`EXPORT_FIELD_KEYS` 由 7 项扩到 **8 项**（静态**只加谱师**）。两组继续**互不跟随**（ADR-0016 §5.1 / §7）。
- 动态新增 4 枚默认**全开**、缺字段回落 `true`（延续定案 5）；静态新增 1 枚默认**关**（不改动老用户既有的出图版式）。开关开但值为空 ⇒ 不画、不占位（票 39 口径）。
- 每枚开关必须**真正 gate 自己那一行** —— 现状 `extractCreditLines` 完全无视开关，只要有 `credits` 就 4 行全画。
- **动态只改曲目信息片头**；结尾结算卡、实时预览舞台不加署名。
- **静态只在「导出谱面图」头带信息区加一枚「谱师」chip**；静态预览舞台 / 全屏画面不加任何文字层（只读全景、全屏时工具栏整排退场），作词 / 作曲 / 编曲不进静态图。
- 该 chip 排 **chips 行末位**（与「导出信息」开关顺序一致），只对它做文本截断加省略号、保证不超 `textW`；不改 `packChipRows` 的通用策略（它现在会把超宽 chip 整枚跳过），两行放满沿用既有截尾。

## 5. 文案

- **片头 4 行 / 长图 chip / 两处开关标签全部走 i18n** ⇒ 导出物文字随界面语言变；这是用户拍板 Q13=B 时接受的可复现代价。
- zh-CN：`作词` / `作曲` / `编曲` / `谱师` + 全角「：」；en：`Lyricist` / `Composer` / `Arranger` / `Charter` + 半角「: 」。四个词统一为**角色名**，与既有 `projects.publish.field.charter = "Charter"` 一致；`Lyrics / Composer / Arranger` 那种作品名与人名混排不采用。
- **乐队行维持只有名字、无标签**（照游戏截图），不动票 39 已定档的方案 B 版式。`artist` 只作内部字段名与界面标签：导出面板 en = `Band`、工程信息 en = `Artist`、Bestdori 帖子 `artists` 中文 = 「歌手」。

## 6. 数据与兼容

- 全部 **additive**：`ChartProject` 加 3 个可选字符串、`ProjectChart` 加 1 个；缺字段在记录 `read` 里回落空；`PROJECT_SCHEMA_VERSION` **不 bump**、不写迁移。`RECORD_FIELDS` 由实体派生且带 `satisfies`，加字段必须同步改字段表。
- **已上传谱面的谱师署名可改**：视作元数据，与难度 / 等级 / 标签同档，不碰音符、不改谱面本体只读规则。

## 7. 曾考虑（否决）

- **动态回落账号名** —— 导出物不可复现、绑登录 / 网络状态。
- **导入帖 charter 自动带入** —— 与「导入是为了自己重作」相反，且要翻票 32（用户明确否决）。
- **谱师署名进设置对象** —— 把谱面级语义拉回应用级。
- **结构化多值 / 每人一行 / 多枚 chip** —— 突破票 39 按 0~4 行定档的片头版式，还要另定分隔符、顺序、去重。
- **静态预览舞台常驻署名浮层** —— 与只读全景、全屏「整排退场」、面板折行 / 懒绘制打架。
- **把 5 项做成一个「曲目署名」总开关** —— 与「乐队」既有逐项开关口径、声明式列表设计相悖。
- **片头标签保持硬编码中文** —— 用户选 Q13=B 要本地化。
